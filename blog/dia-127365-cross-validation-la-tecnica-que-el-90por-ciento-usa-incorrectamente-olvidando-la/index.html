Cross-Validation - La técnica que el 90% usa incorrectamente olvidando la dependencia temporal

07 de april de 2026
sklearn

Hola, parcero. Llegamos al Día 127 y hoy vamos con Cross-Validation. Este tema es crítico porque el 90% de los practitioners que conozco lo usa mal — y lo peor es que ni siquiera lo saben. Me toca ver en producción modelos que supuestamente tenían "85% de accuracy" pero que en realidad estaban sobreajustados al conjunto de validación por culpa de un CV mal hecho. Así que quédate atento que esto va bien detallado.

📐 Fundamentos Teóricos

Cross-Validation (CV) es una técnica de remuestreo que nos permite estimar qué tan bien generalizará un modelo a datos unseen. La idea central es sencilla: dividimos los datos en $k$ pliegues (folds), entrenamos $k$ veces, y promediamos las métricas. Pero aquí es donde la mayoría falla — la forma de dividir los datos no puede ser aleatoria cuando existe estructura en ellos.

El estimador de k-Fold

Dado un conjunto de datos $\mathcal{D} = \{(\mathbf{x}_i, y_i)\}_{i=1}^{n}$, el estimador de k-fold CV se define como:

$$\widehat{E}_{k\text{-fold}} = \frac{1}{k} \sum_{j=1}^{k} \mathcal{L}\left( y_j, f_j(\mathbf{x}_j) \right)$$

donde $f_j$ es el modelo entrenado usando todos los datos excepto el fold $j$ como conjunto de entrenamiento, y $\mathcal{L}$ es la función de pérdida (típicamente log-loss para clasificación o MSE para regresión).

Bias-Variance Tradeoff en k-Fold

El valor de $k$ controla el tradeoff sesgo-varianza:

  • k pequeño (2-3): Training sets grandes → bajo sesgo, alta varianza en la estimación. El estimador es ruidoso porque solo promediamos 2-3 modelos muy diferentes entre sí.
  • k grande (10-20): Training sets más pequeños → sesgo ligeramente mayor (el modelo ve menos datos), pero la varianza del estimador baja porque promediamos muchas realizaciones del modelo.
  • k = n (Leave-One-Out): Sesgo mínimo, pero varianza máxima y costo computacional prohibitivo ($n$ modelos).

La regla práctica: k = 10 es un buen default para la mayoría de casos. Menos es sospechoso, más es overkill computacional sin mejora significativa.

¿Por qué Stratified?

En clasificación, cuando las clases están desbalanceadas, un k-fold aleatorio puede producir folds donde algunas clases tienen cero representantes. Stratified k-fold mantiene la proporción de clases en cada fold:

$$\hat{p}_j^c = \frac{1}{|\mathcal{D}_j|} \sum_{i \in \mathcal{D}_j} \mathbb{1}[y_i = c] \approx \frac{n_c}{n} \quad \forall c$$

donde $\hat{p}_j^c$ es la proporción estimado de la clase $c$ en el fold $j$, que debe ser aproximadamente igual a la proporción real $n_c/n$ en el dataset completo.

💻 Implementación Práctica

Vamos con PyTorch + sklearn para implementar cada variante desde cero. Esto te va a servir para entender exactamente qué está pasando por debajo antes de usar las funciones de alto nivel.

import numpy as np
import torch
import torch.nn as nn
import torch.optim as optim
from sklearn.model_selection import KFold, StratifiedKFold, GroupKFold, TimeSeriesSplit, cross_val_score
from sklearn.datasets import make_classification, make_regression
from sklearn.preprocessing import StandardScaler
from sklearn.metrics import accuracy_score, mean_squared_error
import warnings
warnings.filterwarnings('ignore')

# ============================================================
# Setup: Dataset de clasificación con desbalance y grouping
# ============================================================
print("=" * 60)
print("CROSS-VALIDATION EN PYTORCH — DESDE CERO")
print("=" * 60)

# Dataset sintético: binary classification, 30% clase positiva, 1000 samples
X, y = make_classification(
    n_samples=1000, n_features=20, n_informative=15,
    n_redundant=5, n_classes=2, weights=[0.70, 0.30],
    random_state=42, flip_y=0.05
)
X = StandardScaler().fit_transform(X)

# Groups: 50 grupos de 20 samples cada uno (datos agrupados por sujeto/experimento)
groups = np.repeat(np.arange(50), 20)

print(f"\nDataset: {X.shape[0]} samples, {X.shape[1]} features")
print(f"Clases: {np.bincount(y)} (ratio: {np.bincount(y)[1]/len(y):.1%} positiva)")
print(f"Grupos: {len(np.unique(groups))} grupos de ~20 samples c/u")

# ============================================================
# Red neuronal simple en PyTorch
# ============================================================
class SimpleNN(nn.Module):
    def __init__(self, input_dim, hidden_dim=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(hidden_dim, hidden_dim // 2),
            nn.ReLU(),
            nn.Dropout(0.2),
            nn.Linear(hidden_dim // 2, 1),
            nn.Sigmoid()
        )

    def forward(self, x):
        return self.net(x).squeeze()

def train_model(model, X_train, y_train, epochs=50, lr=0.001):
    """Entrena el modelo y retorna el accuracy en el conjunto de entrenamiento."""
    model.train()
    optimizer = optim.Adam(model.parameters(), lr=lr, weight_decay=1e-4)
    criterion = nn.BCELoss()

    X_t = torch.FloatTensor(X_train)
    y_t = torch.FloatTensor(y_train)

    for epoch in range(epochs):
        optimizer.zero_grad()
        outputs = model(X_t)
        loss = criterion(outputs, y_t)
        loss.backward()
        optimizer.step()

    # Evaluar al final del entrenamiento
    model.eval()
    with torch.no_grad():
        preds = (model(X_t) > 0.5).float()
        acc = (preds == y_t).float().mean().item()
    return acc

def evaluate_model(model, X_test, y_test):
    """Evalúa el modelo en el conjunto de test."""
    model.eval()
    with torch.no_grad():
        X_t = torch.FloatTensor(X_test)
        preds = (model(X_t) > 0.5).float().numpy()
    return accuracy_score(y_test, preds)

# ============================================================
# 1) K-FOLD CV desde cero (NO stratificado — MUY MAL para este caso)
# ============================================================
print("\n" + "-" * 60)
print("1) K-FOLD CV DESDE CERO (NO estratificado)")
print("-" * 60)

kfold = KFold(n_splits=5, shuffle=True, random_state=42)
fold_accuracies = []

for fold, (train_idx, val_idx) in enumerate(kfold.split(X)):
    X_train, X_val = X[train_idx], X[val_idx]
    y_train, y_val = y[train_idx], y[val_idx]

    model = SimpleNN(input_dim=X.shape[1])
    train_model(model, X_train, y_train, epochs=50)
    acc = evaluate_model(model, X_val, y_val)

    fold_accuracies.append(acc)
    print(f"  Fold {fold+1}: accuracy = {acc:.4f} | "
          f"val_pos_ratio = {y_val.mean():.2%} (dataset: {y.mean():.2%})")

print(f"\n  K-Fold Accuracy: {np.mean(fold_accuracies):.4f} ± {np.std(fold_accuracies):.4f}")
print(f"  ⚠️  NOTE: Los folds NO estratificados pueden tener proporciones de clase muy diferentes.")

# ============================================================
# 2) STRATIFIED K-FOLD CV — la forma correcta para classification
# ============================================================
print("\n" + "-" * 60)
print("2) STRATIFIED K-FOLD CV (la forma CORRECTA)")
print("-" * 60)

skfold = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
strat_fold_accuracies = []

for fold, (train_idx, val_idx) in enumerate(skfold.split(X, y)):
    X_train, X_val = X[train_idx], X[val_idx]
    y_train, y_val = y[train_idx], y[val_idx]

    model = SimpleNN(input_dim=X.shape[1])
    train_model(model, X_train, y_train, epochs=50)
    acc = evaluate_model(model, X_val, y_val)

    strat_fold_accuracies.append(acc)
    print(f"  Fold {fold+1}: accuracy = {acc:.4f} | "
          f"val_pos_ratio = {y_val.mean():.2%} (dataset: {y.mean():.2%})")

print(f"\n  Stratified K-Fold Accuracy: {np.mean(strat_fold_accuracies):.4f} ± {np.std(strat_fold_accuracies):.4f}")
print(f"  ✅ Los folds estratificados mantienen ~{y.mean():.0%} de clase positiva en cada fold.")

# ============================================================
# 3) GROUP K-FOLD — cuando los datos tienen estructura de grupo
# ============================================================
print("\n" + "-" * 60)
print("3) GROUP K-FOLD (datos agrupados por sujeto/experimento)")
print("-" * 60)

gkfold = GroupKFold(n_splits=5)
group_fold_accuracies = []

for fold, (train_idx, val_idx) in enumerate(gkfold.split(X, y, groups)):
    X_train, X_val = X[train_idx], X[val_idx]
    y_train, y_val = y[train_idx], y[val_idx]

    # Verificar que NO hay overlap de grupos entre train y val
    train_groups = set(groups[train_idx])
    val_groups = set(groups[val_idx])
    overlap = train_groups & val_groups

    model = SimpleNN(input_dim=X.shape[1])
    train_model(model, X_train, y_train, epochs=50)
    acc = evaluate_model(model, X_val, y_val)

    group_fold_accuracies.append(acc)
    print(f"  Fold {fold+1}: accuracy = {acc:.4f} | "
          f"train_groups={len(train_groups)}, val_groups={len(val_groups)}, overlap={len(overlap)}")

print(f"\n  Group K-Fold Accuracy: {np.mean(group_fold_accuracies):.4f} ± {np.std(group_fold_accuracies):.4f}")
print(f"  ✅ GroupKFold evita data leakage entre grupos — cada grupo está entero en train O en val.")

# ============================================================
# 4) TIME SERIES CV con sliding window — para datos temporales
# ============================================================
print("\n" + "-" * 60)
print("4) TIME SERIES CV — Sliding Window (NO aleatorio)")
print("-" * 60)

# Simular serie temporal: tendencia + estacionalidad + ruido
np.random.seed(42)
n_ts = 300
time_X = np.linspace(0, 30, n_ts)
time_y = 2 * time_X + 10 * np.sin(2 * np.pi * time_X / 12) + np.random.randn(n_ts) * 3
time_X = time_X.reshape(-1, 1)

tscv = TimeSeriesSplit(n_splits=5, gap=5)  # gap=5: no usar últimos 5 para train
ts_fold_scores = []

for fold, (train_idx, val_idx) in enumerate(tscv.split(time_X)):
    X_train, X_val = time_X[train_idx], time_X[val_idx]
    y_train, y_val = time_y[train_idx], time_y[val_idx]

    # Verificar que train es ANTES de val en el tiempo
    assert train_idx[-1] < val_idx[0], "Data leakage temporal!"

    model = SimpleNN(input_dim=1, hidden_dim=32)
    optimizer = optim.Adam(model.parameters(), lr=0.01)
    criterion = nn.MSELoss()

    X_t = torch.FloatTensor(X_train)
    y_t = torch.FloatTensor(y_train)
    X_v = torch.FloatTensor(X_val)
    y_v = torch.FloatTensor(y_val)

    model.train()
    for epoch in range(100):
        optimizer.zero_grad()
        loss = criterion(model(X_t).squeeze(), y_t)
        loss.backward()
        optimizer.step()

    model.eval()
    with torch.no_grad():
        preds = model(X_v).squeeze().numpy()

    mse = mean_squared_error(y_val, preds)
    ts_fold_scores.append(mse)
    print(f"  Fold {fold+1}: MSE = {mse:.4f} | "
          f"train=[0:{train_idx[-1]}], val=[{val_idx[0]}:{val_idx[-1]}]")

print(f"\n  TimeSeries CV MSE: {np.mean(ts_fold_scores):.4f} ± {np.std(ts_fold_scores):.4f}")
print(f"  ✅ TimeSeriesSplit avanza en el tiempo: train siempre ANTES de val.")

# ============================================================
# 5) cross_val_score de sklearn con pipeline
# ============================================================
print("\n" + "-" * 60)
print("5) cross_val_score CON SKLEARN (alto nivel)")
print("-" * 60)

from sklearn.base import BaseEstimator, ClassifierMixin
from sklearn.pipeline import Pipeline

class PyTorchClassifier(BaseEstimator, ClassifierMixin):
    """Wrapper para usar cualquier modelo PyTorch con sklearn."""
    def __init__(self, input_dim=20, hidden_dim=64, epochs=50, lr=0.001):
        self.input_dim = input_dim
        self.hidden_dim = hidden_dim
        self.epochs = epochs
        self.lr = lr
        self.model = None

    def fit(self, X, y):
        self.model = SimpleNN(self.input_dim, self.hidden_dim)
        train_model(self.model, X, y, epochs=self.epochs, lr=self.lr)
        return self

    def predict(self, X):
        self.model.eval()
        with torch.no_grad():
            X_t = torch.FloatTensor(X)
            return (self.model(X_t) > 0.5).long().numpy()

    def score(self, X, y):
        return accuracy_score(y, self.predict(X))

clf = PyTorchClassifier(input_dim=X.shape[1])

# Usar cross_val_score directamente
cv_scores = cross_val_score(clf, X, y, cv=StratifiedKFold(n_splits=5, shuffle=True, random_state=42), scoring='accuracy')
print(f"  cross_val_score accuracies: {cv_scores}")
print(f"  Mean: {cv_scores.mean():.4f} ± {cv_scores.std():.4f}")
print(f"  ✅ sklearn maneja el CV internamente — muy conveniente para comparar modelos.")

print("\n" + "=" * 60)
print("RESUMEN: ¿Cuándo usar cada variante?")
print("=" * 60)
print("""
  • KFold básico        → Solo para regresión con datos independientes y sin estructura.
  • StratifiedKFold     → SIEMPRE en clasificación, especialmente con clases desbalanceadas.
  • GroupKFold          → Cuando cada grupo (sujeto, experimento, paciente) es independiente.
  • TimeSeriesSplit     → Para series temporales. Train es SIEMPRE anterior a val.
  • LeaveOneOut         → Muy costoso; solo para datasets muy pequeños (< 200 samples).
""")




🚨 Los 3 Errores Más Comunes



Error 1: Random Split en Time Series Data — Data Leakage Temporal



Este es el error más grave que veo en la industria. Si tienes datos temporales (precios, demanda, sensores) y haces train_test_split(shuffle=True), estás filtrando información del futuro al pasado. El modelo ve datos que no debería haber visto cuando hace predicciones.



La matemática es simple: si tus datos tienen dependencia temporal, cualquier división aleatoria viola la asumción de exchangeabilidad. El estimador de error se vuelve sesgado — te dice que el modelo funciona mejor de lo que realmente funciona.



Fix: Usa TimeSeriesSplit de sklearn o implementa sliding window manual. Asegúrate de que todos los datos de entrenamiento sean estrictamente anteriores a los de validación:



# MAL: shuffle=True causa data leakage temporal
# train_test_split(X, y, test_size=0.2, shuffle=True)  # ¡NO HACER ESTO!

# BIEN: TimeSeriesSplit
tscv = TimeSeriesSplit(n_splits=5, gap=5)
for train_idx, val_idx in tscv.split(time_X):
    assert train_idx[-1] < val_idx[0]  # Train es siempre antes que val




Error 2: No Usar Stratified K-Fold con Class Imbalance



En un dataset con 95% clase negativa y 5% clase positiva, un KFold aleatorio puede producir folds donde la clase positiva tiene 0 o 1 ejemplos. El modelo aprende a predecir siempre la clase mayoritaria y el CV te dice que tienes "90% de accuracy" — lo cual es básicamente inútil.



La proporción de clase en cada fold debería ser aproximadamente igual a la proporción global. Esto es lo que StratifiedKFold garantiza matemáticamente:


$$\hat{p}_j^c \approx \frac{n_c}{n} \quad \forall j \in \{1, \ldots, k\}, \forall c \in \{1, \ldots, C\}$$


Fix: SIEMPRE usa StratifiedKFold en clasificación. Es una línea y puede cambiar completamente tu estimación de performance:



# MAL
kfold = KFold(n_splits=5, shuffle=True, random_state=42)

# BIEN — una línea que cambia todo
skfold = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)




Error 3: Usar k-fold con k=2 o k=3 — Alta Varianza en la Estimación



Con k=2, cada fold de validación contiene solo el 50% de los datos. La estimación tiene alta varianza porque cada fold es muy diferente del otro. Estás esencialmente comparando dos modelos entrenados con datasets muy distintos.



La varianza del estimador de k-fold CV es aproximadamente $\frac{\sigma^2}{k}$ donde $\sigma^2$ es la varianza de los errores individuales. Con k=2, la varianza es el doble que con k=4, y 5 veces mayor que con k=10.



Fix: Usa k=10 como default. Si el dataset es pequeño (n < 1000), considera k=5. Para datasets grandes (n > 100k), k=5 es suficiente porque cada fold ya tiene suficientes ejemplos para ser representativo.



# MAL: k=2 da estimadores de alta varianza
kfold_bad = KFold(n_splits=2, shuffle=True, random_state=42)

# BIEN: k=10 es el standard de la industria
kfold_good = KFold(n_splits=10, shuffle=True, random_state=42)






✅ Resumen y Cierre



Bueno parcero, vamos cerrando. Lo más importante de hoy:



    

  • StratifiedKFold para clasificación, siempre. Es la forma de garantizar que la distribución de clases se mantiene en cada fold.
    • 

  • GroupKFold cuando hay estructura de grupo — pacientes, sujetos, experimentos. Lo que NO quieres es que el modelo vea datos del mismo grupo en train y val.
    • 

  • TimeSeriesSplit para series temporales. El tiempo no se puede barajar.
    • 

  • k=10 es el sweet spot entre sesgo y varianza para la mayoría de casos.
    • 




El mayor enemigo de un buen CV es el data leakage — meter información de test en train por cualquier medio. Ya sea por shuffle en series temporales, por no separar grupos, o por usar el validation set para seleccionar hiperparámetros sin un holdout separado. Sé riguroso con las fronteras de tus datos.
