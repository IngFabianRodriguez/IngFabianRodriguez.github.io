Re-Ranking - Mejorando Resultados de Busqueda

02 de septiembre de 2026

Introduccion: El Problema con la Busqueda Vectorial

Hagale pues, parcero. Dia 245 y hoy nos metemos con un tema que el 80% de los desarrolladores de RAG ignoran: re-ranking. Ese paso adicional que convierte resultados "meh" en resultados utiles. Ya sabemos que la busqueda vectorial es poderosa, pero por si sola tiene limitaciones serias. Despues de este articulo va a saber exactamente que es re-ranking, por que lo necesita, y como implementarlo. Vamos con tune.

Por Que la Busqueda Vectorial No Es Suficiente

La busqueda vectorial (semantic search) funciona bien en general, pero tiene problemas especificos:

  • 太子Problem de recall: Los vectores capturan similitud semántica global, pero no consideran relevancia contextual para la query especifica
  • 太子Problem de precision: Los primeros resultados pueden ser semanticamente similares a la query pero no responder lo que el usuario realmente necesita
  • 太子Problem de length mismatch: Un documento largo puede tener un vector similar a la query aunque solo una pequena seccion sea relevante

La formulacion matematica del retrieval vectorial es:

score = cosine_similarity(embeddings(query), embeddings(document))

Esto mide solo la similitud geometrica en el espacio vectorial, no la relevancia real para la tarea.

Que Es Re-Ranking?

Re-ranking es un segundo paso despues del retrieval inicial que reordena los documentos usando un modelo mas sofisticado. La idea es:

  1. Fase 1 - Retrieval: Obtener los top-K documentos usando busqueda vectorial (rapido, alto recall)
  2. Fase 2 - Re-ranking: Reordenar esos K documentos usando un modelo cross-encoder (mayor precision)

Intuicion Visual

Imagine que busca "como cocinar arroz" en un sistema de retrieval. La busqueda vectorial le da documentos sobre cocina en general. Re-ranking toma esos documentos y evalua: ¿cual de estos realmente responde la pregunta especifica?

Cross-Encoder vs Bi-Encoder

Bi-Encoder (Retrieval Estandar)

El bi-encoder codifica query y documento por separado en el mismo espacio vectorial:

from sentence_transformers import SentenceTransformer
import numpy as np

# Bi-encoder
model = SentenceTransformer('all-MiniLM-L6-v2')

# Query y documentos se codifican por separado
query_emb = model.encode("como cocinar arroz")
doc_emb = model.encode("Para cocinar arroz, primero lave el arroz...")

# Similitud coseno
score = np.dot(query_emb, doc_emb) / (np.linalg.norm(query_emb) * np.linalg.norm(doc_emb))
print(f"Similitud: {score:.4f}")

Cross-Encoder (Re-Ranking)

El cross-encoder toma query y documento juntos y produce un score de relevancia:

from sentence_transformers import CrossEncoder

# Cross-encoder para re-ranking
model = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')

# Query y documento JUNTOS - el modelo puede atender a ambos simultaneously
pairs = [
    ("como cocinar arroz", "Para cocinar arroz, primero lave el arroz..."),
    ("como cocinar arroz", "El cambio climatico afecta la produccion de arroz en Asia..."),
    ("como cocinar arroz", "Receta de paella valenciana con arroz."),
]

scores = model.predict(pairs)
for pair, score in zip(pairs, scores):
    print(f"Query: '{pair[0]}' | Doc: '{pair[1][:50]}...' | Score: {score:.4f}")

Pipeline Completo de Retrieval + Re-Ranking

from sentence_transformers import SentenceTransformer, CrossEncoder
import numpy as np

class HybridSearchReranker:
    """
    Pipeline completo: retrieval vectorial + re-ranking.
    """
    
    def __init__(self, embedding_model='sentence-transformers/all-MiniLM-L6-v2',
                 reranker_model='cross-encoder/ms-marco-MiniLM-L-6-v2',
                 top_k_retrieval=50,
                 top_k_rerank=10):
        
        self.embedding_model = SentenceTransformer(embedding_model)
        self.reranker_model = CrossEncoder(reranker_model)
        self.top_k_retrieval = top_k_retrieval
        self.top_k_rerank = top_k_rerank
    
    def retrieve(self, query, documents):
        """
        Fase 1: Retrieval vectorial.
        """
        # Codificar query
        query_emb = self.embedding_model.encode(query, convert_to_tensor=True)
        
        # Codificar documentos
        doc_embs = self.embedding_model.encode(documents, convert_to_tensor=True)
        
        # Calcular similitud coseno
        scores = np.dot(query_emb.cpu(), doc_embs.cpu().T)
        
        # Obtener top-k
        top_indices = np.argsort(scores)[::-1][:self.top_k_retrieval]
        
        return [(idx, scores[idx]) for idx in top_indices]
    
    def rerank(self, query, documents, retrieval_results):
        """
        Fase 2: Re-ranking con cross-encoder.
        """
        # Obtener documentos del retrieval
        retrieved_docs = [documents[idx] for idx, _ in retrieval_results]
        
        # Crear pares query-documento
        pairs = [[query, doc] for doc in retrieved_docs]
        
        # Obtener scores del reranker
        rerank_scores = self.reranker_model.predict(pairs)
        
        # Combinar scores (opcional: fusionar retrieval + rerank)
        # Aqui solo usamos el score del reranker
        reranked = sorted(
            zip(retrieved_docs, rerank_scores),
            key=lambda x: x[1],
            reverse=True
        )[:self.top_k_rerank]
        
        return reranked
    
    def search(self, query, documents):
        """
        Busqueda completa: retrieval + re-ranking.
        """
        # Fase 1: Retrieval
        retrieval_results = self.retrieve(query, documents)
        
        # Fase 2: Re-ranking
        reranked_results = self.rerank(query, documents, retrieval_results)
        
        return reranked_results


# Uso
documents = [
    "Paris es la capital de Francia.",
    "Londres es la capital del Reino Unido.",
    "Berlín es la capital de Alemania.",
    "Madrid es la capital de España.",
    "Roma es la capital de Italia.",
]

searcher = HybridSearchReranker(top_k_retrieval=5, top_k_rerank=3)
results = searcher.search("capital de Francia", documents)

print("Resultados re-rankeados:")
for i, (doc, score) in enumerate(results, 1):
    print(f"{i}. [{score:.4f}] {doc}")

Fusion de Scores: Retrievers Multiples

En sistemas production-grade, se usan multiples retrievers y se fusionan los scores antes de re-ranking:

import numpy as np
from sklearn.preprocessing import MinMaxScaler

class ReciprocalRankFusion:
    """
    Reciprocal Rank Fusion (RRF) para combinar multiples retrievers.
    """
    
    @staticmethod
    def fuse(retriever_results_list, k=60):
        """
        Combina resultados de multiples retrievers usando RRF.
        
        RRF_score(d) = sum(1 / (k + rank_i(d)) for i in retrievers)
        """
        fused_scores = {}
        
        for results in retriever_results_list:
            for rank, (doc_id, score) in enumerate(results, 1):
                if doc_id not in fused_scores:
                    fused_scores[doc_id] = 0
                fused_scores[doc_id] += 1 / (k + rank)
        
        # Ordenar por score fusionado
        sorted_results = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        
        return sorted_results


class ScoreLevelFusion:
    """
    Fusion a nivel de scores (requiere normalizacion).
    """
    
    @staticmethod
    def normalize_scores(scores):
        """Normaliza scores al rango [0, 1]."""
        min_s = min(scores)
        max_s = max(scores)
        if max_s == min_s:
            return [0.5] * len(scores)
        return [(s - min_s) / (max_s - min_s) for s in scores]
    
    @staticmethod
    def fuse_weighted(retriever_results_with_weights):
        """
        Fusion ponderada de retrievers.
        
        Args:
            retriever_results_with_weights: [(results_dict, weight), ...]
                donde results_dict = {doc_id: score}
        """
        fused_scores = {}
        
        for results, weight in retriever_results_with_weights:
            normalized = ScoreLevelFusion.normalize_scores(list(results.values()))
            doc_ids = list(results.keys())
            
            for doc_id, norm_score in zip(doc_ids, normalized):
                if doc_id not in fused_scores:
                    fused_scores[doc_id] = 0
                fused_scores[doc_id] += norm_score * weight
        
        return sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)


# Ejemplo de uso con BM25 + Vector search
def example_fusion():
    # Simular resultados de BM25
    bm25_results = {
        "doc1": 0.95,
        "doc2": 0.80,
        "doc3": 0.75,
        "doc4": 0.60,
    }
    
    # Simular resultados de busqueda vectorial
    vector_results = {
        "doc1": 0.85,
        "doc3": 0.90,
        "doc5": 0.88,
        "doc2": 0.70,
    }
    
    # Fusion ponderada (BM25 y vector igual de importantes)
    fused = ScoreLevelFusion.fuse_weighted([
        (bm25_results, 0.5),
        (vector_results, 0.5),
    ])
    
    print("Resultados fusionados:")
    for doc_id, score in fused:
        print(f"  {doc_id}: {score:.4f}")

BM25: El Retriever Lexico

BM25 es el algoritmo de retrieval lexico clasico que sigue siendo relevante hoy:

from rank_bm25 import BM25Okapi
import re

def tokenize(text):
    """Tokenizacion simple en minusculas."""
    return re.findall(r'\w+', text.lower())

# Corpus de ejemplo
corpus = [
    "Paris es la capital de Francia y una ciudad romantica.",
    "Londres es la capital del Reino Unido en Europa.",
    "Francia es conocido por su gastronomia y vinos.",
    "El cambio climatico afecta a Europa y el mundo.",
    "Paris tiene mas de dos millones de habitantes.",
]

tokenized_corpus = [tokenize(doc) for doc in corpus]

# Crear BM25
bm25 = BM25Okapi(tokenized_corpus)

# Query
query = "capital Francia"
tokenized_query = tokenize(query)

# Obtener scores
scores = bm25.get_scores(tokenized_query)

# Ordenar documentos
doc_scores = sorted(zip(corpus, scores), key=lambda x: x[1], reverse=True)

print(f"Query: '{query}'")
print("\nResultados BM25:")
for doc, score in doc_scores:
    print(f"  Score: {score:.4f} - {doc[:60]}...")

Evaluacion de Re-Ranking

from sklearn.metrics import ndcg_score
import numpy as np

def evaluate_retrieval(query_ids, retrieved_docs, relevance_scores, k=10):
    """
    Evalua el sistema de retrieval/re-ranking con NDCG.
    
    Args:
        query_ids: Lista de queries
        retrieved_docs: Dict {query_id: [(doc_id, score), ...]}
        relevance_scores: Dict {query_id: {doc_id: relevance_score}}
        k: Numero de documentos a evaluar
    """
    ndcg_scores = []
    
    for qid in query_ids:
        # Obtener docs retrievalados para esta query
        retrieved = retrieved_docs[qid][:k]
        doc_ids = [doc_id for doc_id, _ in retrieved]
        
        # Obtener relevance scores en el orden de retrieval
        actual_relevance = [relevance_scores[qid].get(doc_id, 0) for doc_id in doc_ids]
        
        # Crear ideal relevance (ordenado por relevancia real)
        ideal_relevance = sorted(actual_relevance, reverse=True)
        
        # Calcular NDCG
        if sum(ideal_relevance) > 0:
            # Para una sola query, NDCG se calcula manualmente
            actual_dcg = sum(rel / np.log2(idx + 2) for idx, rel in enumerate(actual_relevance))
            ideal_dcg = sum(rel / np.log2(idx + 2) for idx, rel in enumerate(ideal_relevance))
            ndcg = actual_dcg / ideal_dcg if ideal_dcg > 0 else 0
            ndcg_scores.append(ndcg)
    
    return np.mean(ndcg_scores)


# Ejemplo de evaluacion
relevance_scores = {
    "q1": {"d1": 3, "d2": 2, "d3": 1, "d4": 0, "d5": 0},
}

retrieved_docs = {
    "q1": [("d1", 0.9), ("d3", 0.8), ("d2", 0.7), ("d4", 0.5), ("d5", 0.3)],
}

ndcg = evaluate_retrieval(["q1"], retrieved_docs, relevance_scores)
print(f"NDCG@5: {ndcg:.4f}")

Resumen y Cierre Colombiano

Hagale pues, Parcero. Hoy cubrimos re-ranking a fondo y espero que ahora entienda por que la busqueda vectorial por si sola no es suficiente para un sistema RAG production-grade.

Los puntos clave:

  • La busqueda vectorial tiene alto recall pero baja precision para queries especificas
  • Re-ranking usa un segundo paso con cross-encoder para mejorar la relevancia
  • Bi-encoder codifica por separado, cross-encoder evalua juntos query y documento
  • Modelos como Cohere reranker y MS MARCO son referencias en el campo
  • La fusion de scores (RRF, weighted) combina multiples retrievers efectivamente
  • BM25 sigue siendo util como retrieval lexico complementario
  • Siempre evalue con metricas como NDCG antes de desplegar
