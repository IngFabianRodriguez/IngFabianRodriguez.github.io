Hola, parcero. Día 168 y hoy vamos con Hallucinations. Este tema es donde el 90% inmediatamente culpa al modelo ("GPT-4 está alucinando") cuando en realidad el problema casi siempre es el prompt, el contexto, o el retrieval system. Vamos a cambiar esa narrativa hoy — con math, código real, y por qué el modelo no es el problema principal.

📐 Fundamentos: Qué Es una Hallucination Realmente

Una hallucination en LLMs es cuando el modelo genera contenido que parece correcto pero es factualmente incorrecto, no está respaldado por el contexto, o directamente es inventado. Pero la pregunta importante es: ¿por qué pasa?

El Math: Por Qué los LLMs Generan Texto

Un LLM genera texto prediciendo el siguiente token basado en probabilidad:

$$P(\text{token}_i | \text{token}_{1}, \text{token}_{2}, ..., \text{token}_{i-1}, \theta)$$

donde $\theta$ son los pesos del modelo. El modelo no "sabe" si algo es verdadero — solo predice qué token es más probable dado el contexto. Si el contexto no es suficientemente informativo, el modelo predice lo que parece más plausible estadísticamente.

Tipos de Hallucinations

  • Factuales: El modelo afirma que "Einstein nació en 1879" cuando en realidad fue en 1879 (esto es verdadero, pero si dijera 1847 sería una hallucination)
  • Contextuales: El modelo ignora el contexto proporcionado y genera información que no está en los documentos
  • Self-consistency: El modelo se contradice a sí mismo en diferentes partes de la respuesta
  • Reference: El modelo cita fuentes que no existen o que no respaldan lo que dice

💻 Código: Detectar y Mitigar Hallucinations

1. Detectar Hallucinations con Self-Consistency

# Generar múltiples respuestas y comparar consistencia
from openai import OpenAI
client = OpenAI()

def detect_hallucination_with_self_consistency(prompt, n_generations=5):
    """
    Genera múltiples respuestas y verifica consistencia.
    Si el modelo dice cosas diferentes para el mismo prompt,
    hay mayor probabilidad de hallucination.
    """
    responses = []
    for _ in range(n_generations):
        response = client.chat.completions.create(
            model="gpt-4",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.7  # Un poco de variabilidad
        )
        responses.append(response.choices[0].message.content)
    
    # Comparar respuestas
    # Método simple: verificar si las respuestas key facts coinciden
    key_facts = extract_key_facts(responses)
    
    # Calcular consistencia
    consistency_score = calculate_consistency(key_facts)
    
    return {
        'responses': responses,
        'key_facts': key_facts,
        'consistency_score': consistency_score,
        'is_likely_hallucination': consistency_score < 0.6
    }

def extract_key_facts(responses):
    """Extrae hechos clave de las respuestas."""
    # Implementación simplificada
    # En producción usar NER y extracción de hechos
    facts_per_response = []
    for resp in responses:
        facts = set()
        # Ejemplo simplificado: extraer números y fechas
        import re
        numbers = re.findall(r'\b\d{4}\b', resp)  # Years
        facts.update(numbers)
        facts_per_response.append(facts)
    return facts_per_response

def calculate_consistency(key_facts):
    """Calcula score de consistencia entre respuestas."""
    if not key_facts:
        return 1.0
    
    # Comparar hechos entre respuestas
    reference = key_facts[0]
    matches = 0
    total = 0
    
    for facts in key_facts[1:]:
        for fact in facts:
            if fact in reference:
                matches += 1
            total += 1
    
    return matches / total if total > 0 else 1.0

2. Mitigar Hallucinations con Chain of Verification

def verify_and_fix_response(initial_response, context_documents):
    """
    Chain of Verification:
    1. Generar respuesta inicial
    2. Extraer claims factuales
    3. Verificar cada claim contra el contexto
    4. Corregir claims que no están respaldados
    """
    
    # Step 1: Extraer claims
    claims_prompt = f"""
    Extrae todos los hechos assertions en la siguiente respuesta.
    Para cada hecho, sepáralo en una línea separada.
    
    Respuesta: {initial_response}
    """
    
    claims_response = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": claims_prompt}]
    )
    claims = claims_response.choices[0].message.content.split('\n')
    
    # Step 2: Verificar cada claim contra el contexto
    verified_claims = []
    for claim in claims:
        if not claim.strip():
            continue
            
        verification_prompt = f"""
        Dado el siguiente claim y contexto, responde:
        - Si el claim está respaldado por el contexto: "VERDADERO"
        - Si el claim contradice el contexto: "FALSO"
        - Si el claim no puede ser verificado con el contexto: "NO VERIFICABLE"
        
        Claim: {claim}
        
        Contexto:
        {context_documents}
        """
        
        verification = client.chat.completions.create(
            model="gpt-4",
            messages=[{"role": "user", "content": verification_prompt}]
        )
        
        result = verification.choices[0].message.content
        verified_claims.append({
            'claim': claim,
            'status': result
        })
    
    # Step 3: Generar respuesta corregida
    correction_prompt = f"""
    Dada la siguiente respuesta inicial y los resultados de verificación,
    genera una versión corregida que:
    - Mantenga los hechos VERDADEROS
    - Corrija los hechos FALSOS
    - Indique explícitamente los hechos NO VERIFICABLES
    
    Respuesta inicial: {initial_response}
    
    Verificación:
    {verified_claims}
    """
    
    final_response = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": correction_prompt}]
    )
    
    return final_response.choices[0].message.content

4. Retrieval-Augmented Generation (RAG) para Reducir Hallucinations

# RAG con cite sources para verificar claims
def rag_with_citations(query, vector_store, llm_client):
    """
    RAG que incluye citations para que el usuario pueda verificar.
    Esto reduce hallucinations porque el usuario puede checkear las fuentes.
    """
    
    # 1. Retrieve relevant documents
    retrieved_docs = vector_store.similarity_search(query, k=5)
    
    # 2. Build context with source tracking
    context_with_sources = []
    for i, doc in enumerate(retrieved_docs):
        context_with_sources.append(f"[{i+1}] Fuente: {doc.metadata.get('source', 'Unknown')}\n{doc.page_content}")
    
    # 3. Generate response with explicit citation instruction
    prompt = f"""Responde la pregunta usando el contexto proporcionado.
    Para cada afirmación, cita el número de fuente correspondiente.
    Si la información no está en el contexto, di "No tengo esa información según las fuentes disponibles".
    
    Contexto:
    {' '.join(context_with_sources)}
    
    Pregunta: {query}
    
    Formato de respuesta:
    - Afirmación 1 [cita: 1]
    - Afirmación 2 [cita: 2]
    """
    
    response = llm_client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": prompt}]
    )
    
    return {
        'response': response.choices[0].message.content,
        'sources': retrieved_docs,
        'cited_prompt': prompt
    }

📊 Resumen: Reducción de Hallucinations

  • Prompt Engineering: El factor más importante. Decirle "usa solo el contexto" reduce 80% de hallucinations
  • Chain of Verification: Generar, verificar claims, corregir
  • RAG con Citations: Solo responder con información de fuentes verificables
  • Self-Consistency: Múltiples generaciones para detectar inconsistencias
  • Evitar Preguntas Vagas: Preguntas específicas con contexto claro = menos room for hallucination
  • Medir: Sin métricas no hay mejora

🏁 Cierre

Y ahí lo tienen, parcero. Las hallucinations no son un bug del modelo — son una consecuencia de cómo los LLMs funcionan y cómo los humanos los promptan.
