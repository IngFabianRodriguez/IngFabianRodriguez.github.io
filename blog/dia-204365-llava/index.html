Object Detection — YOLO, Faster R-CNN y el Detector que Necesitas

23 de julio de 2026
object-detectionyolofaster-r-cnnssdcomputer-vision

Hagale pues, parcero. Día 204 y hoy hablamos de un problema que está en todas partes: cómo hacer que una computadora vea objetos en una imagen y diga dónde están. Esto lo usas cuando Netflix te muestra thumbnails con caras, cuando Tesla detecta peatones, o cuando tu celular organiza fotos por contenido. No es magia — son dos filosofías distintas de detección que conviene entender. Café listo.

One-Stage vs Two-Stage Detectors

Antes de ver código, hay que entender la diferencia fundamental entre los dos enfoques:

  • Two-Stage Detectors (Faster R-CNN, R-CNN): Primero encuentran regiones candidatas (Stage 1), luego clasifican cada región y refinan el bounding box (Stage 2). Más precisos pero más lentos.
  • One-Stage Detectors (YOLO, SSD): Predicen clases y bounding boxes directamente en una sola pasada por la red. Más rápidos pero pueden struggle con objetos pequeños.

La elección depende de tu caso de uso: ¿prioridad en accuracy o en velocidad?

YOLO con Ultralytics — Detección en Tiempo Real

YOLO (You Only Look Once) revolucionó la detección de objetos haciendo predicción directa de bounding boxes y clases en una sola pasada. Ultralytics tiene una implementación muy pulida que puedes usar en 5 líneas.

from ultralytics import YOLO
import cv2

# Cargar modelo pre-entrenado (yolov8n = nano, el mas pequeno)
# Otros: yolov8s, yolov8m, yolov8l, yolov8x
model = YOLO('yolov8n.pt')

# Inference en una imagen
image_path = 'street_scene.jpg'
results = model(image_path, conf=0.25, iou=0.45)

# results es una lista de Results objects
for result in results:
    # result.boxes contiene los bounding boxes
    boxes = result.boxes
    
    # Acceder a datos de cada deteccion
    for box in boxes:
        # Coordenadas (xyxy format)
        x1, y1, x2, y2 = box.xyxy[0].tolist()
        # Confianza
        conf = box.conf[0].item()
        # Clase predicha
        cls_id = int(box.cls[0].item())
        class_name = result.names[cls_id]
        
        print(f"Objeto: {class_name}, Confianza: {conf:.2f}")
        print(f"  Bounding box: [{x1:.0f}, {y1:.0f}, {x2:.0f}, {y2:.0f}]")

# Visualizar y guardar
annotated_frame = results[0].plot()
cv2.imwrite('output.jpg', annotated_frame)

Faster R-CNN con TorchVision

Faster R-CNN es el estándar two-stage. La región de interés (RoI) se propone con una RPN (Region Proposal Network) y luego se clasifica y refina en el segundo stage.

Non-Maximum Suppression (NMS)

Cuando tu detector produce múltiples boxes superpuestos para el mismo objeto, NMS se encarga de quedarse con el mejor y descartar los demás. Esto es crítico para YOLO que genera muchos anchors.

Algoritmo:

  1. Ordenar detecciones por confidence score
  2. Elegir la deteccion con mayor score
  3. Descartar todas las detecciones que overlapuan demasiado (IoU > threshold) con esta
  4. Repetir hasta que no queden cajas
import torch
import torchvision.ops as ops

# Boxes en formato xyxy, scores de confianza
boxes = torch.tensor([
    [100, 100, 200, 200],   # box 1
    [105, 105, 205, 205],   # box 2 — alto overlap con box 1
    [300, 300, 400, 400],   # box 3 — diferente objeto
    [310, 310, 410, 410],   # box 4 — alto overlap con box 3
], dtype=torch.float32)

scores = torch.tensor([0.9, 0.85, 0.92, 0.78], dtype=torch.float32)

# NMS standard
iou_threshold = 0.5
keep_indices = ops.nms(boxes, scores, iou_threshold)
print(f"Boxes mantenidos: {keep_indices}")  # [2, 0] — mantiene mejores de cada grupo

# NMS con soft-NMS (penaliza boxes que overlapuan en vez de descartarlos)
keep_soft = ops.soft_nms(boxes, scores, iou_threshold, sigma=0.5)
print(f"Boxes con soft-NMS: {keep_soft}")

Parámetros clave de NMS:

  • iou_threshold: Cuánto overlap (IoU) se acepta antes de descartar. Típicamente 0.45-0.5.
  • score_threshold: Descartar detecciones muy bajas antes de NMS. Esto salva tiempo computacional.

Entendiendo mAP — Mean Average Precision

mAP es la métrica estándar para object detection, pero es commonly misunderstood. No es un solo número — es un promedio sobre IoU thresholds.

Cómo se calcula:

  1. Para cada clase, calculas Average Precision (AP) en la curva Precision-Recall
  2. mAP = mean(AP) sobre todas las clases
  3. En COCO, se calcula para IoU thresholds de 0.5 a 0.95 en pasos de 0.05 y se promedia

mAP@0.5: IoU threshold fijo de 0.5 (más laxo)

mAP@0.5:0.95: Promedio sobre IoU 0.5, 0.55, 0.6, ..., 0.95 (estándar COCO)

# En ultralytics YOLO, validation retorna mAPs
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
metrics = model.val(data='coco.yaml', split='val')

# Metricas disponibles:
print(f"mAP50-95: {metrics.box.map:.4f}")      # Standard COCO mAP
print(f"mAP50: {metrics.box.map50:.4f}")       # Solo IoU=0.5
print(f"mAP75: {metrics.box.map75:.4f}")       # Solo IoU=0.75
print(f"mAP por clase: {metrics.box.ap50}")     # AP por clase

Errores Comunes

Error 1: No Saber Cuándo Usar One-Stage vs Two-Stage

El problema: Escoger YOLO para todo porque "es el más popular" cuando tu caso requiere alta precisión en objetos pequeños (medicina, vigilancia) y Faster R-CNN sería mejor. O al revés — usar Faster R-CNN para detección en tiempo real donde YOLO sería suficiente.

La solución: Analiza tus requerimientos. Para tiempo real (30+ FPS), YOLO/SSD son necesarios. Para máxima accuracy en objetos pequeños con tiempo de inference no crítico, Faster R-CNN con Feature Pyramid Network (FPN) es superior. Una regla: YOLO para producción/embedded, Faster R-CNN para investigación/benchmark accuracy.

Error 2: No Tunear Non-Maximum Suppression Thresholds

El problema: Dejar NMS con valores por defecto (iou_threshold=0.45) sin entender el impacto. En escenas densas (multitud, estantes de supermercado), un threshold muy bajo descarta detecciones válidas que se overlapuan; uno muy alto mantiene duplicates.

La solución: Experimenta con iou_threshold entre 0.3 y 0.7 según tu escena. También usa score_threshold para filtrar detecciones junk antes de NMS — esto mejora la calidad de las_supresión. Para YOLO, prueba diferentes valores de conf y iou hasta que veas el tradeoff optimal entre recalls y precision en tu validation set.

Error 3: mAP Sin Entender Que Es Promedio Sobre IoU Thresholds

El problema: Ver "mAP = 0.65" y pensar que significa 65% de objetos detectados correctamente con IoU cualquiera. En realidad, mAP@0.5:0.95 es un promedio de 10 valores de IoU diferentes (0.5, 0.55, 0.6, ..., 0.95). Un modelo puede tener mAP50=0.80 y mAP95=0.35 — alto en lo laxo, bajo en lo estricto.

La solución: Reporta ambas métricas. mAP@0.5 es más fácil de lograr y te dice qué tan bien detecta el modelo en general; mAP@0.5:0.95 te dice la calidad del localization. ParaPapers With Code, es el mAP@0.5:0.95. En producción,往往是 mAP@0.5 porque threshold de IoU 0.5 es lo mínimo aceptable.

Resumen

  • Two-Stage (Faster R-CNN): Más preciso, más lento — para máxima accuracy
  • One-Stage (YOLO, SSD): Más rápido, okay accuracy — para tiempo real
  • YOLO: Ultralytics hace trivial entrenar y deployar
  • Faster R-CNN: torchvision tiene implementación sólida para fine-tuning
  • NMS: Elimina duplicates — tunea iou_threshold y score_threshold
  • mAP@0.5:0.95: Estándar COCO — promedio sobre IoU thresholds
  • mAP@0.5: Métrica más laxa — baseline rápido
