🎯 La Matemática del Latency

Antes de optimizar, hay que entender la anatomía de una request a un LLM:

Latencia Total = Latencia Prefill + Latencia Decode

Donde:

  • Prefill: Procesa el prompt de entrada — paralelo, rápido, pero limitado por memoria GPU
  • Decode: Genera tokens uno por uno — secuencial, lento, el verdadero bottleneck

💡 Regla del 80/20: El decode típicamente representa el 80% de la latencia total en requests largas. Pero en prompts cortos, el prefill puede dominar.

La formula de latencia para decode es:

Latencia Decode = (tokens_generados) × (tiempo_por_token)

Y el tiempo por token depende de:

  • Throughput de la GPU (tokens/segundo)
  • Tamaño del KV cache
  • Grado de ocupación de la GPU (utilization)

📊 Benchmarking: Midiendo para No Adivinar

El error #1 de la gente es optimizar sin medir. Vamos a hacer benchmarking serio:

import time
import numpy as np
from typing import Dict, List

class LatencyBenchmark:
    """Benchmark para medir latencia de LLM inference por componente."""

    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer

    def measure_prefill(self, prompt: str) -> Dict[str, float]:
        """Mide latencia de la fase de prefill."""
        inputs = self.tokenizer(prompt, return_tensors="pt")

        # Warm-up
        _ = self.model.generate(**inputs, max_new_tokens=1,
                                do_sample=False, pad_token_id=0)

        # Medir prefill
        start = time.perf_counter()
        with torch.no_grad():
            _ = self.model(**inputs)
        prefill_time = (time.perf_counter() - start) * 1000  # ms

        num_tokens = inputs["input_ids"].shape[1]

        return {
            "prefill_time_ms": prefill_time,
            "prompt_tokens": num_tokens,
            "prefill_per_token_ms": prefill_time / num_tokens
        }

    def measure_decode(self, prompt: str, max_new_tokens: int = 100) -> Dict[str, float]:
        """Mide latencia de la fase de decode."""
        inputs = self.tokenizer(prompt, return_tensors="pt")

        # Warm-up
        _ = self.model.generate(**inputs, max_new_tokens=1,
                                do_sample=False, pad_token_id=0)

        # Medir decode token por token
        start = time.perf_counter()
        with torch.no_grad():
            outputs = self.model.generate(
                **inputs,
                max_new_tokens=max_new_tokens,
                do_sample=False,
                pad_token_id=0
            )
        decode_time = (time.perf_counter() - start) * 1000

        generated_tokens = outputs.shape[1] - inputs["input_ids"].shape[1]

        return {
            "decode_time_ms": decode_time,
            "generated_tokens": generated_tokens,
            "time_per_token_ms": decode_time / generated_tokens,
            "throughput_tokens_per_sec": (generated_tokens / decode_time) * 1000
        }

    def full_benchmark(self, prompt: str, max_new_tokens: int = 100) -> Dict:
        """Benchmark completo: prefill + decode."""
        prefill = self.measure_prefill(prompt)
        decode = self.measure_decode(prompt, max_new_tokens)

        total_time = prefill["prefill_time_ms"] + decode["decode_time_ms"]

        return {
            "total_latency_ms": total_time,
            "prefill": prefill,
            "decode": decode,
            "prefill_pct": (prefill["prefill_time_ms"] / total_time) * 100,
            "decode_pct": (decode["decode_time_ms"] / total_time) * 100
        }

🚀 Continuous Batching: El Game Changer

Si no estás usando continuous batching, estás dejando dinero en la mesa. Esta técnica puede darte 10x en throughput:

from vllm import LLM, SamplingParams

# vLLM implementa continuous batching nativamente
llm = LLM(
    model="meta-llama/Llama-2-70b-hf",
    tensor_parallel_size=4,  # 4 GPUs
    gpu_memory_utilization=0.90,
    max_num_batched_tokens=8192,
    max_num_seqs=256
)

sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.95,
    max_tokens=512
)

# Requests llegan en batches dinámicos automáticamente
# El scheduler de vLLM va metiendo requests conforme hay espacio
def generate_batch(prompts: List[str]) -> List[List[str]]:
    outputs = llm.generate(prompts, sampling_params)

    # El batching es transparente para el usuario
    return [out.outputs[0].text for out in outputs]

# Esto recibe requests de múltiples usuarios y las batchea automáticamente
prompts_batch = [
    "Escribe un email de disculpa",
    "Explica relatividad general",
    "Código Python para fibonacci",
    # ... hasta 256 requests en paralelo
]
results = generate_batch(prompts_batch)

Por qué funciona?

  • Los LLMs usan la misma GPU para todos los requests
  • Cuando un request termina, otro empieza inmediatamente
  • No hay "burbujas" de GPU sin trabajar

🔮 Speculative Decoding: Prediciendo el Futuro

Speculative decoding usa un modelo "draft" pequeño para predecir los siguientes tokens, y el modelo grande solo verifica:

class SpeculativeDecoder:
    """Speculative decoding con draft model."""

    def __init__(self, large_model, draft_model, tokenizer, gamma=4):
        self.large = large_model
        self.draft = draft_model
        self.tokenizer = tokenizer
        self.gamma = gamma  # Número de tokens a predecir

    def generate(self, prompt: str, max_new_tokens: int = 100) -> str:
        inputs = self.tokenizer(prompt, return_tensors="pt")

        # Fase 1: Draft genera gamma tokens
        draft_outputs = self.draft.generate(
            **inputs,
            max_new_tokens=self.gamma,
            do_sample=True,
            temperature=0.7
        )

        draft_tokens = draft_outputs[0, inputs["input_ids"].shape[1]:]

        # Fase 2: Large model verifica en paralelo
        large_inputs = torch.cat([inputs["input_ids"], draft_tokens.unsqueeze(0)], dim=1)

        with torch.no_grad():
            large_logits = self.large(large_inputs).logits

        # Aceptar tokens donde el large está de acuerdo con draft
        accepted = []
        for i, draft_tok in enumerate(draft_tokens):
            large_tok = large_logits[0, inputs["input_ids"].shape[1] + i - 1].argmax()
            if draft_tok == large_tok:
                accepted.append(draft_tok.item())
            else:
                # Primera diferencia: usar el del large y parar
                accepted.append(large_tok.item())
                break

        return self.tokenizer.decode(accepted)

# Speedup típico: 2-3x con 85%+ acceptance rate
# 4 tokens predecidos, 3.4 aceptados en promedio = 3.4x speedup

💾 KV Cache Optimization

El KV cache crece con el contexto. Optimízalo:

# Cuantización del KV cache de 16-bit float a 8-bit int
from transformers import AutoModelForCausalLM, BitsAndBytesConfig

quantization_config = BitsAndBytesConfig(
    load_in_8bit=True,
    llm_int8_skip_modules=["lm_head"],  # No cuantizar el output
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-70b-hf",
    quantization_config=quantization_config,
    device_map="auto"
)

#另另一个优化: PagedAttention (vLLM)
# El KV cache se maneja en "páginas" de 16 tokens
# En vez de allocated 8192 tokens連続, usa solo lo necesario
# Esto permite manejar contextos más largos con menos memoria

# Configuración оптимальная para long context
llm = LLM(

    gpu_memory_utilization=0.90,
    max_model_len=8192,  # Soporta hasta 8k tokens
    enable_prefix_caching=True  # Cache para prefijos comunes (system prompts!)

⚠️ Los 3 Errores Clásicos (y sus fixes)

Error 1: No medir latencia por componente

Síntoma: "Mi sistema está lento" sin saber por qué. Optimizas prefill cuando el problema es decode, o viceversa.

Fix: Implementa benchmarking granular desde día 1.

# инструмент для identificar el bottleneck
def diagnose_bottleneck(prompt: str, max_tokens: int = 100):
    benchmark = LatencyBenchmark(model, tokenizer)
    result = benchmark.full_benchmark(prompt, max_tokens)

    if result['prefill_pct'] > 60:
        return "🔴 BOTTLENECK: Prefill (prompt muy largo)"
    elif result['decode_pct'] > 70:
        return "🔴 BOTTLENECK: Decode (generación muy larga)"
    else:
        return "🟡 BALANCED (revisar otras optimizaciones)"

# Usage
print(diagnose_bottleneck("Prompt corto"))  # Likely decode
print(diagnose_bottleneck("A" * 4000 + "??"))  # Likely prefill

Error 2: Hacer focus en la optimización equivocada

Síntoma: Optimizas prefill (usando flash attention) cuando el problema real es decode. O optimizas el modelo cuando el problema es el batching.

Fix: Mide primero. Después optimiza lo que el data dice que está lento.

💡 La mayoría de sistemas LLM en producción son decode-bound, no prefill-bound. Si mides y resulta ser prefill, algo raro tienes.

Error 3: No usar continuous batching

Síntoma: Tienes 8 GPUs y usas solo 2. El throughput es可怜的. Las GPUs están idle esperando.

Fix: Migra a vLLM o TensorRT-LLM con continuous batching.

# Antes: iteration-level batching (lento)
results = []
for prompt in prompts:  # Procesa uno por uno!
    results.append(model.generate(prompt))

# Después: continuous batching (10x faster)
from vllm import LLM, SamplingParams
llm = LLM(model="meta-llama/Llama-2-70b-hf")
outputs = llm.generate(prompts, SamplingParams(max_tokens=512))

📈 Dashboard de Latency

# Dashboard para monitorear latencia en producción
import json
from dataclasses import dataclass, asdict
from datetime import datetime

@dataclass
class LatencyMetrics:
    timestamp: str
    prefill_ms: float
    decode_ms: float
    total_ms: float
    throughput: float  # tokens/segundo
    num_requests: int

    def to_json(self):
        return json.dumps(asdict(self))

class LatencyDashboard:
    def __init__(self):
        self.metrics = []

    def log(self, prefill_ms: float, decode_ms: float, throughput: float, num_requests=1):
        self.metrics.append(LatencyMetrics(
            timestamp=datetime.now().isoformat(),
            prefill_ms=prefill_ms,
            decode_ms=decode_ms,
            total_ms=prefill_ms + decode_ms,
            throughput=throughput,
            num_requests=num_requests
        ))

    def summary(self) -> dict:
        if not self.metrics:
            return {}

        totals = [m.total_ms for m in self.metrics]
        return {
            "p50_latency_ms": sorted(totals)[len(totals)//2],
            "p95_latency_ms": sorted(totals)[int(len(totals)*0.95)],
            "p99_latency_ms": sorted(totals)[int(len(totals)*0.99)],
            "avg_throughput": sum(m.throughput for m in self.metrics) / len(self.metrics)
        }

# Usage: después de cada request
dashboard.log(
    prefill_ms=result['prefill']['prefill_time_ms'],
    decode_ms=result['decode']['decode_time_ms'],
    throughput=result['decode']['throughput_tokens_per_sec']
)

print(dashboard.summary())

🏁 Resumen

Así que ahí lo tienes, parcero. Latency optimization para LLMs:

  • Mide primero: Sin datos estás ciega, optimizando al azar
  • Identifica el bottleneck: ¿Prefill o decode?
  • Continuous batching es obligatorio: 10x throughput, no es opcional
  • Speculative decoding: 2-3x speedup con acceptance rate del 85%+
  • KV cache optimization: Cuantización + prefix caching

La próxima vez que alguien se queje de que "el LLM está lento", ya sabes qué hacer: medir, diagnosticar, optimizar. Con método, no con prayers. 🙏
