1. Que es GPT-4o? (Y por que deberia importarte)

1.1 La analogia cotidiana: el interprete simultaneo de la ONU

GPT-4o es como un interprete simultaneo en una cabina de las Naciones Unidas, pero con un superpoder extra: le puedes tirar un paper tecnico en aleman, una radiografia medica, y un audio en portugues al mismo tiempo, y el responde todo en espanol, sin cambiar de energia entre modalidades, cobrandote por minuto de su atencion. La "o" viene de "omni" y no es marketing vacio: significa que las tres modalidades (texto, vision, audio) se proyectan al mismo espacio latente antes de pasar por el decoder autoregresivo.

Para ti como practitioner, lo que importa es esto: GPT-4o no "entiende" imagenes por separado y luego las pega con texto. Las procesa como una secuencia unica de tokens donde algunos tokens son parches de pixel y otros son sub-palabras de texto. Eso permite que la atencion cruzada entre modalidades funcione sin trucos, y por eso el modelo puede razonar sobre "que hay en la esquina superior izquierda de la imagen" con la misma fluidez con que razona sobre tu prompt.

1.2 La matematica formal, simbolo por simbolo

GPT-4o es una red transformer decoder-only autoregresiva. Su corazon es self-attention:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

Donde cada simbolo significa:

  • $Q \in \mathbb{R}^{n \times d_k}$: matriz de queries, una fila por cada uno de los $n$ tokens del contexto
  • $K \in \mathbb{R}^{n \times d_k}$: matriz de keys (la "etiqueta" de cada token para ser buscado)
  • $V \in \mathbb{R}^{n \times d_v}$: matriz de values (el contenido que cada token aporta si es atendido)
  • $d_k$: dimensionalidad de las keys ($d_k = 128$ en las cabezas de GPT-4o)
  • $QK^\top \in \mathbb{R}^{n \times n}$: matriz de similitud entre cada par de tokens, producto punto
  • $\sqrt{d_k}$: factor de escala para que los productos punto no exploten cuando $d_k$ crece; sin esto, los gradientes son numericamente inutiles
  • $\text{softmax}(\cdot)$ aplicado por filas: convierte cada fila en una distribucion de probabilidad que suma 1
  • Output $\in \mathbb{R}^{n \times d_v}$: cada fila es una combinacion ponderada de values, donde los pesos vienen de la matriz de atencion

El modelo apila multiples cabezas y concatena sus salidas:

$$\text{MHA}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) W^O$$

donde $\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$ y $h$ es el numero de cabezas (96 en GPT-4o).

En el paso final, el hidden state $h_t \in \mathbb{R}^{d_{\text{model}}}$ se proyecta al vocabulario:

$$P(y_t \mid y_{donde $W_o \in \mathbb{R}^{|V| \times d_{\text{model}}}$ es la unembedding matrix, $|V| \approx 200{,}000$ para el tokenizador BPE multilingue de GPT-4o, y $x$ es el prompt (que puede incluir vision).

Para multimodalidad, los parches visuales se proyectan al espacio comun:

$$z_{\text{mm}} = W_{\text{proj}} \cdot E_v + b_{\text{proj}}$$

donde $E_v \in \mathbb{R}^{p \times d_v}$ son embeddings de los $p$ parches de la imagen (ViT-like) y $W_{\text{proj}}$ los proyecta a $d_{\text{model}}$.

El entrenamiento minimiza cross-entropy sobre toda la secuencia:

$$L(\theta) = -\frac{1}{N}\sum_{i=1}^{N}\sum_{t=1}^{T_i} \log P_\theta(y_t^{(i)} \mid y_{donde $N$ es el tamano del batch, $T_i$ la longitud de la secuencia $i$, y $x^{(i)}$ el prompt.

El sampling con temperatura $\tau$ modifica la distribucion de salida:

$$P_\tau(y_t = v) = \frac{\exp(z_v / \tau)}{\sum_{j=1}^{|V|} \exp(z_j / \tau)}$$

Cuando $\tau \to 0$, argmax puro (greedy, determinista). Cuando $\tau = 1$, distribucion cruda del modelo. Cuando $\tau > 1$, mas creativo pero menos factual y propenso a alucinar.

2. Como la API de OpenAI resuelve esto por vos

Cuando llamas client.chat.completions.create(), pasan estas cosas en orden:

Tu codigo
    │
    │  HTTPS POST (JSON serializado)
    ▼
api.openai.com:443
    │
    │  TLS 1.3 → Cloudflare WAF → Auth check → Rate limiter
    ▼
Load balancer (8 PoPs globales, HTTP/2)
    │
    │  SSE si stream=True
    ▼
Inference cluster (H100s en containers, autoscaling)
    │
    │  Tokenizer (BPE multilingue) → Forward pass → Sampler
    ▼
Tokens generados (uno por chunk de SSE si stream=True)

Cuatro puntos que te muerden:

  1. El sampler corre en el servidor, no en tu maquina. temperature=0.7 viaja en el JSON hasta el cluster y se aplica ahi.
  2. El streaming usa Server-Sent Events (SSE) sobre HTTP/2. Cada token llega como chunk JSON separado. Latencia tipica time-to-first-token: 250-450ms para GPT-4o.
  3. El rate limit es por organization, no por API key. Si tienes 5 keys bajo la misma org, comparten el mismo bucket.
  4. El cobro es por tokens consumidos. max_tokens no usados tambien aparecen en el response como completion_tokens facturables.

3. OpenAI: Uso Directo y Casos de Control Fino

La API cruda te sirve cuando:

  • Llamadas unicas, sin estado entre requests.
  • Latencia objetivo sub-segundo sin capa de abstraccion.
  • Caso de uso claro (vision + JSON, function calling simple, embeddings).

Donde la API cruda se queda corta:

  • Agentes multi-step: necesitas loop persistente con memoria y tool execution. Ahi mira el Agents SDK de OpenAI o LangGraph.
  • RAG pesado: si tu retrieval retorna 50k tokens de contexto, la API no te ayuda a rankear ni comprimir. Tu codigo lo hace.
  • Cost guardrails estrictos: la API te cobra lo que pides; no hay circuit breaker magico. Eso lo programas tu.

# types.py
"""Tipos y protocolos del cliente GPT-4o."""

from __future__ import annotations

from dataclasses import dataclass
from typing import Protocol

from pydantic import BaseModel, Field


# Precios USD por 1M tokens. Verificar antes de cada deploy.
# https://openai.com/api/pricing/
PRICING: dict[str, dict[str, float]] = {
    "gpt-4o":      {"input": 2.50, "output": 10.00},
    "gpt-4o-mini": {"input": 0.15, "output":  0.60},
}


@dataclass
class UsageStats:
    """Acumulador thread-safe de uso y costo."""

    prompt_tokens: int = 0
    completion_tokens: int = 0
    total_tokens: int = 0
    cost_usd: float = 0.0
    request_count: int = 0

    def add(self, usage: "SupportsUsage", model: str) -> None:
        self.prompt_tokens += usage.prompt_tokens
        self.completion_tokens += usage.completion_tokens
        self.total_tokens += usage.total_tokens
        self.request_count += 1
        p = PRICING.get(model, PRICING["gpt-4o"])
        # Verificacion manual: 1000 prompt + 500 completion en gpt-4o
        # = 1000*2.50/1e6 + 500*10.00/1e6 = 0.0075 USD
        self.cost_usd += (
            usage.prompt_tokens * p["input"] / 1_000_000
            + usage.completion_tokens * p["output"] / 1_000_000
        )


class SupportsUsage(Protocol):
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int


class InvoiceData(BaseModel):
    """Schema estructurado para extraccion de facturas."""

    vendor: str = Field(description="Nombre del proveedor como aparece en la factura")
    total: float = Field(description="Monto total en la moneda original, sin separadores de miles")
    currency: str = Field(description="Codigo ISO 4217: COP, USD, EUR, MXN, etc.")
    due_date: str = Field(description="Fecha de vencimiento en formato ISO 8601 YYYY-MM-DD")

4.2 El motor principal

# client.py
"""Cliente production-ready para GPT-4o."""

from __future__ import annotations

import logging
import os
from typing import Any, Iterator, Type

import backoff
from openai import APIConnectionError, OpenAI, RateLimitError
from pydantic import BaseModel

from types import InvoiceData, SupportsUsage, UsageStats

logger = logging.getLogger(__name__)


class GPT4oClient:
    """Cliente con reintentos, tracking de costo y soporte multimodal."""

    def __init__(
        self,
        api_key: str | None = None,
        default_model: str = "gpt-4o",
    ) -> None:
        self.client = OpenAI(api_key=api_key or os.environ["OPENAI_API_KEY"])
        self.default_model = default_model
        self.stats = UsageStats()

    @backoff.on_exception(
        backoff.expo,
        (RateLimitError, APIConnectionError),
        max_tries=5,
        max_time=60,
        jitter=backoff.full_jitter,
    )
    def chat(
        self,
        messages: list[dict[str, Any]],
        model: str | None = None,
        temperature: float = 1.0,
        max_tokens: int = 1024,
        response_format: Type[BaseModel] | None = None,
    ) -> str | BaseModel:
        """Llamada no-streaming con reintentos exponenciales."""
        model = model or self.default_model
        kwargs: dict[str, Any] = {
            "model": model,
            "messages": messages,
            "temperature": temperature,
            "max_tokens": max_tokens,
        }
        if response_format is not None:
            kwargs["response_format"] = response_format

        resp = self.client.chat.completions.create(**kwargs)
        usage: SupportsUsage = resp.usage  # type: ignore[assignment]
        self.stats.add(usage, model)

        if response_format is not None:
            # parsed es una instancia de response_format gracias al modo json_schema
            return resp.choices[0].message.parsed  # type: ignore[return-value]
        return resp.choices[0].message.content or ""

    def stream(
        self,
        messages: list[dict[str, Any]],
        model: str | None = None,
        temperature: float = 1.0,
        max_tokens: int = 1024,
    ) -> Iterator[str]:
        """Streaming via SSE; usage llega en el ultimo chunk."""
        model = model or self.default_model
        stream = self.client.chat.completions.create(
            model=model,
            messages=messages,
            temperature=temperature,
            max_tokens=max_tokens,
            stream=True,
            stream_options={"include_usage": True},
        )
        for chunk in stream:
            if chunk.choices and chunk.choices[0].delta.content:
                yield chunk.choices[0].delta.content
            if chunk.usage is not None:
                self.stats.add(chunk.usage, model)

    def extract_invoice(self, image_b64: str, mime: str = "image/png") -> InvoiceData:
        """Vision: extraccion estructurada desde una imagen en base64."""
        messages = [{
            "role": "user",
            "content": [
                {"type": "text", "text": (
                    "Extrae vendor, total, currency (ISO 4217) y due_date "
                    "(YYYY-MM-DD). Si un campo no aparece, devuelve null."
                )},
                {
                    "type": "image_url",
                    "image_url": {"url": f"data:{mime};base64,{image_b64}"},
                },
            ],
        }]
        result = self.chat(
            messages,
            model="gpt-4o",
            response_format=InvoiceData,
        )
        assert isinstance(result, InvoiceData)
        return result

    def report(self) -> dict[str, Any]:
        """Snapshot actual de uso y costo para Prometheus."""
        return {
            "prompt_tokens": self.stats.prompt_tokens,
            "completion_tokens": self.stats.completion_tokens,
            "total_tokens": self.stats.total_tokens,
            "requests": self.stats.request_count,
            "cost_usd": round(self.stats.cost_usd, 6),
        }

4.3 Utilidades de analisis y verificacion

# analysis.py
"""Utilidades para auditar respuestas de GPT-4o en produccion."""

from __future__ import annotations

import math
from collections import Counter
from typing import Any, Iterable


def shannon_entropy(distribution: Iterable[float]) -> float:
    """Entropia H = -sum(p * ln p) en nats.

    Verificacion: uniforme sobre 4 items = ln(4) ≈ 1.3863.
    Concentrada (1,0,0,0) = 0.
    """
    return -sum(p * math.log(p) for p in distribution if p > 0)


def repetition_score(tokens: list[str]) -> float:
    """Ratio de tokens unicos vs total.

    Verificacion: ["a","b","c","a","b","c"] -> 3/6 = 0.5
    """
    if not tokens:
        return 1.0
    return len(set(tokens)) / len(tokens)


def detect_degeneration(text: str, window: int = 50) -> dict[str, Any]:
    """Detecta repeticion patologica tipica de temperature mal calibrada.

    Caso real: con temperature=0.0 y prompt ambiguo, GPT-4o puede loopear
    la misma frase 20 veces. Eso es degeneration, no creatividad.
    """
    tokens = text.split()
    if len(tokens) < window:
        return {"degenerated": False, "repetition_ratio": 1.0}

    chunks = [
        " ".join(tokens[i : i + window])
        for i in range(0, len(tokens) - window, max(1, window // 2))
    ]
    counter = Counter(chunks)
    most_common_count = counter.most_common(1)[0][1]
    ratio = repetition_score(tokens)
    return {
        "degenerated": most_common_count >= 3 or ratio < 0.3,
        "repetition_ratio": round(ratio, 4),
        "most_repeated_chunk_count": most_common_count,
    }


def estimate_cost(
    prompt_tokens: int,
    completion_tokens: int,
    model: str = "gpt-4o",
) -> float:
    """Coste estimado en USD.

    Verificacion manual: 1000 input + 500 output en gpt-4o
    = 1000*2.50/1e6 + 500*10.00/1e6 = 0.0075 USD
    """
    pricing = {"gpt-4o": (2.50, 10.00), "gpt-4o-mini": (0.15, 0.60)}
    in_price, out_price = pricing.get(model, pricing["gpt-4o"])
    return prompt_tokens * in_price / 1_000_000 + completion_tokens * out_price / 1_000_000

Caso 3: Model cascading para reducir costos

# caso_3_cascade.py
"""Usa gpt-4o-mini como filtro; solo escala a gpt-4o si hay duda."""
from pydantic import BaseModel, Field

from client import GPT4oClient


class Classification(BaseModel):
    needs_gpt4o: bool = Field(description="True solo si requiere razonamiento profundo")
    confidence: float = Field(ge=0, le=1)


def answer(question: str, client: GPT4oClient) -> str:
    """Primero clasifica con mini; solo escala si confianza es alta."""
    classification = client.chat(
        [{"role": "user", "content": (
            "¿Esta pregunta requiere razonamiento matematico o tecnico profundo?\n\n"
            f"{question}\n\nResponde needs_gpt4o (bool) y confidence (0-1)."
        )}],
        model="gpt-4o-mini",
        response_format=Classification,
        temperature=0.0,
    )
    assert isinstance(classification, Classification)

    chosen = "gpt-4o" if (
        classification.needs_gpt4o and classification.confidence > 0.7
    ) else "gpt-4o-mini"

    return str(client.chat(
        [{"role": "user", "content": question}],
        model=chosen,
        temperature=0.3,
    ))


if __name__ == "__main__":
    c = GPT4oClient()
    print(answer("Cuanto es 2+2?", c))
    print(answer("Deriva la ELBO de un VAE y muestra por que colapsa el KL", c))
    # Pregunta trivial: ~0.0001 USD (mini)
    # Pregunta profunda: ~0.005 USD (gpt-4o)
    print(c.report())

6. Debugging: Cuando Todo se Va a la Mierda

Problema 1: HTTP 429 (rate limit) sin backoff

Si mandas 1000 requests paralelos a GPT-4o desde un script de migracion, te tumbo el bucket en 30 segundos. No hay fiesta con eso.

Deteccion numerica: el header x-ratelimit-remaining-requests baja por cada llamada; cuando llega a 0, el siguiente request retorna 429 con header retry-after en segundos.

# fix_rate_limit.py
"""Cliente que respeta Retry-After del header."""
import time

from openai import RateLimitError

from client import GPT4oClient


def chat_resilient(
    client: GPT4oClient,
    messages: list,
    max_retries: int = 5,
) -> str:
    backoff_s = 1.0
    for attempt in range(max_retries):
        try:
            return str(client.chat(messages))
        except RateLimitError as e:
            # OpenAI envia Retry-After en segundos
            retry_after = float(e.response.headers.get("retry-after", backoff_s))
            print(f"[429] esperando {retry_after}s (intento {attempt + 1}/{max_retries})")
            time.sleep(retry_after)
            backoff_s = min(backoff_s * 2, 60)
    raise RuntimeError("Rate limit persistio tras todos los reintentos")

Soluciones reales mas alla del backoff:

  1. Token bucket por organization, no por key. Con 3 keys bajo la misma org, solo escalas si distribuyes bien el trafico.
  2. Pre-filtrar con gpt-4o-mini (caso 3). Reduce trafico al endpoint premium entre 70% y 90%.
  3. Batch API para workloads nocturnos: 50% de descuento y ventana de 24h. No sirve para tiempo real, pero para reportes batch es perfecto.

Problema 2: Context window overflow (128k)

GPT-4o tiene 128k tokens de contexto. Suena mucho hasta que metes 50 paginas de PDF en una sola llamada.

Deteccion: BadRequestError con mensaje context_length_exceeded. Tu codigo debe medir tokens ANTES de mandar, no despues.

# fix_context_overflow.py
"""Cuenta tokens con tiktoken antes de mandar."""
import tiktoken

from client import GPT4oClient


def safe_chat(
    client: GPT4oClient,
    messages: list,
    max_input_tokens: int = 120_000,
) -> str:
    enc = tiktoken.encoding_for_model("gpt-4o")
    n_tokens = sum(
        len(enc.encode(m["content"])) if isinstance(m.get("content"), str) else 0
        for m in messages
    )
    if n_tokens > max_input_tokens:
        raise ValueError(
            f"Prompt tiene {n_tokens} tokens, maximo permitido {max_input_tokens}. "
            "Trunca o resume antes de enviar."
        )
    return str(client.chat(messages))


# Verificacion: encode("Hola mundo") -> 2 tokens
enc = tiktoken.encoding_for_model("gpt-4o")
assert len(enc.encode("Hola mundo")) == 2

Soluciones reales:

  1. Truncar inteligente: conserva system prompt completo + ultimo turno del usuario + resumen del medio (generado por gpt-4o-mini).
  2. Retrieval en vez de full context: si tu RAG retorna 50k tokens, el retrieval esta mal calibrado. Top-5, no top-50.
  3. Compression prompt-side: usa gpt-4o-mini para resumir la entrada antes de mandarla al modelo grande. Cuesta una llamada extra pero mantiene el costo predecible.

Problema 3: JSON malformado en structured outputs

Antes de response_format=pydantic_class, la unica forma era pedir JSON en el prompt y rezar. Ahora OpenAI garantiza JSON valido, pero solo si:

  1. Usas response_format={"type": "json_schema", ...} o pasas una clase Pydantic.
  2. Tu schema no tiene referencias circulares ni uniones que JSON Schema no soporte.

Deteccion: la respuesta llega como string vacio, o parsed retorna None cuando no deberia.

# fix_json.py
"""Validacion estricta con reintentos y feedback al modelo."""
from pydantic import BaseModel, Field, ValidationError

from client import GPT4oClient


class Diagnosis(BaseModel):
    disease_code: str = Field(pattern=r"^[A-Z]\d{2}$")  # ICD-10
    confidence: float = Field(ge=0, le=1)


def diagnose(client: GPT4oClient, symptoms: str) -> Diagnosis | None:
    messages = [
        {"role": "user", "content": f"Sintomas: {symptoms}\nDevuelve ICD-10 y confianza."},
    ]
    try:
        result = client.chat(messages, response_format=Diagnosis)
        assert isinstance(result, Diagnosis)
        return result
    except ValidationError as e:
        # Feedback loop: mandale el error al modelo para que se autocorrija
        messages.append({"role": "assistant", "content": "<respuesta invalida>"})
        messages.append({
            "role": "user",
            "content": f"Tu respuesta fallo por: {e}. Intenta de nuevo con el schema correcto.",
        })
        try:
            retry = client.chat(messages, response_format=Diagnosis)
            assert isinstance(retry, Diagnosis)
            return retry
        except ValidationError:
            return None

Soluciones reales:

  1. Pydantic > dict: siempre pide clases Pydantic, nunca dicts sueltos. Pydantic valida tipos, regex y rangos sin codigo extra.
  2. Reintentos con feedback: como en el codigo de arriba. El modelo se autocorrige el 80% de las veces si le devuelves el error exacto.
  3. strict=True en campos: para enums y strings, evita coercion automatica ("3.14" → 3.14 cuando esperas str).

7. Optimizaciones de Produccion

Optimizacion 1: Prompt caching automatico

OpenAI introdujo caching automatico para prompts > 1024 tokens. Si tu system prompt + contexto se mantiene igual entre requests, los tokens cacheados cuestan 50% menos.

# opt_caching.py
"""Prompt caching: system prompt fijo + variabilidad solo en user msg."""
from client import GPT4oClient

# Verificacion numerica:
# 100k input tokens sin cache = 100k * 2.50/1e6 = 0.250 USD
# 100k input tokens con cache = (1024*2.50 + 98976*1.25)/1e6 ≈ 0.126 USD
# Ahorro: ~50% sobre el tramo cacheado


SYSTEM_PROMPT = """
Eres un asistente medico que diagnostica segun ICD-10. Responde unicamente
con JSON que cumpla el schema {disease_code, confidence}. [texto fijo largo
de ~3000 tokens con ejemplos y reglas - aqui iria tu prompt real]
"""


def query(client: GPT4oClient, user_msg: str) -> str:
    return str(client.chat([
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_msg},
    ]))

Trade-off: el caching solo aplica si el prefijo de tokens es IDENTICO entre requests. Si tu system prompt cambia por usuario (ej. incluyes el nombre), pierdes el cache. Solucion: deja el system prompt canonico estable y pasa la variabilidad por el mensaje del usuario.

Optimizacion 2: Model cascading

Ya lo vimos en el caso 3, pero vale repetir: una cascada gpt-4o-mini → gpt-4o bien calibrada reduce el costo por query entre 60% y 85% sin perder calidad perceptible.

# opt_cascade.py
"""Cascada mini -> 4o basada en decision estructurada del mini."""
from pydantic import BaseModel, Field

from client import GPT4oClient


class RouterDecision(BaseModel):
    use_gpt4o: bool
    reason: str = Field(max_length=120)


def answer_cascade(question: str, client: GPT4oClient) -> tuple[str, str]:
    decision = client.chat(
        [{"role": "user", "content": (
            f"¿Esta pregunta requiere un modelo avanzado?\n\nQ: {question}"
        )}],
        model="gpt-4o-mini",
        response_format=RouterDecision,
        temperature=0.0,
    )
    assert isinstance(decision, RouterDecision)
    chosen = "gpt-4o" if decision.use_gpt4o else "gpt-4o-mini"
    answer = str(client.chat(
        [{"role": "user", "content": question}],
        model=chosen,
        temperature=0.3,
    ))
    return answer, chosen

Trade-off: la cascada introduce una llamada extra en el camino lento. Si tu latencia objetivo es <500ms p99, no te sirve. Si tu volumen es alto y la latencia objetivo es 1-2s, te ahorras una fortuna.

8. Conclusion: Por Que Esto te Salva el Pellejo en Produccion

  • GPT-4o es un transformer autoregresivo multimodal, no magia. La temperatura y el sampling son parametros del servidor, no tuyos. Optimiza desde el prompt, no desde el sampler.
  • El costo se te va de las manos si no mides tokens en cada request. Wrappea el cliente con un UsageStats y exponlo como /metrics para Prometheus; pon alertas cuando el costo por hora supere tu umbral.
  • El reintento no es opcional. backoff con jitter es la diferencia entre un sistema que escala y uno que se cae cuando OpenAI tiene un bad day.
  • Structured outputs con Pydantic matan el 95% de los bugs de parsing. Dejate de pedir JSON en el prompt como si fueras junior.
  • Cascada + caching es donde se gana dinero. La diferencia entre una factura de $400 USD y una de $4,000 USD al mes es solo eso.

Mini-checklist antes de mandar GPT-4o a produccion

  • [ ] Tienes backoff con jitter en cada llamada?
  • [ ] Tienes timeout explicito (no infinito)?
  • [ ] Estas midiendo tokens por request y exponiendolos como metricas?
  • [ ] Tienes un cap de costo diario con circuit breaker?
  • [ ] Tu system prompt es cacheable (no varia por request)?
  • [ ] Estas usando gpt-4o-mini para pre-filtrar donde puedas?
  • [ ] Tus structured outputs usan Pydantic, no dicts?

Si marcaste todas, de una puedes dormir tranquilo. Si no, el CFO te va a escribir un Slack tarde o temprano. No hay fiesta con eso. 🔥
