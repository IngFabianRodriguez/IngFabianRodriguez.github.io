Function Calling — Por qué el 80% hace ChatGPT plugins incorrectamente

13 de may de 2026
openaifunction-callingtool-use

Hola, parcero. Llegamos al Día 163 y hoy vamos con Function Calling. Si pensabas que los plugins de ChatGPT eran magia o que basta con囲む una API, esta vaina te va a volar la cabeza. El 80% implementa function calling incorrectamente — y hoy te explico por qué, con código real.

📐 Fundamentos Teóricos

Function Calling (también conocido como tool use o tool calling) es la capacidad de un LLM para identificar cuándo necesita ejecutar una función externa y generar los parámetros correctos para invocarla. En lugar de solo generar texto, el modelo puede pedir ejecutar acciones.

¿Cómo funciona por debajo?

El proceso tiene tres componentes críticos:

  • Function Schema: JSON Schema que define la función disponible, sus parámetros y tipos
  • Prompt Engineering: Se le dice al modelo cuándo y cómo usar funciones
  • Parsing y validación: La salida del modelo se parsea para extraer el llamada a función

La matemática detrás es interesante: el modelo no "ejecuta" la función — solo genera una estructura que representa la llamada. La ejecución real ocurre fuera del modelo.

Arquitectura de una llamada a función

La anatomía de una function call es:

# Estructura de una function call
function_call = {
    "name": "get_weather",           # Nombre de la función
    "arguments": {                     # Argumentos en JSON
        "location": "Bogotá",
        "unit": "celsius"
    }
}

# El modelo NO ejecuta esto — solo lo GENERA
# La ejecución real ocurre en tu código

💻 Implementación Práctica

Vamos con código real. Usaremos la API de OpenAI, pero el patrón aplica a cualquier proveedor.

import openai
import json
from datetime import datetime

# 1. Definir las funciones disponibles
functions = [
    {
        "name": "get_weather",
        "description": "Obtiene el clima actual para una ubicación",
        "parameters": {
            "type": "object",
            "properties": {
                "location": {
                    "type": "string",
                    "description": "Ciudad y país, ej: Bogotá, Colombia"
                },
                "unit": {
                    "type": "string",
                    "enum": ["celsius", "fahrenheit"],
                    "description": "Unidad de temperatura"
                }
            },
            "required": ["location"]
        }
    },
    {
        "name": "send_email",
        "description": "Envía un email",
        "parameters": {
            "type": "object",
            "properties": {
                "to": {
                    "type": "string",
                    "description": "Email del destinatario"
                },
                "subject": {
                    "type": "string",
                    "description": "Asunto del email"
                },
                "body": {
                    "type": "string",
                    "description": "Cuerpo del email"
                }
            },
            "required": ["to", "subject", "body"]
        }
    }
]

# 2. Función para ejecutar la llamada
def execute_function(function_name, arguments):
    """Ejecuta la función seleccionada con los argumentos"""
    if function_name == "get_weather":
        # Simulación — en producción harías el llamado real
        return {"temperature": 22, "condition": "Parcialmente nublado", "humidity": 65}
    elif function_name == "send_email":
        # Simulación
        return {"status": "sent", "message_id": "abc123"}
    else:
        return {"error": "Función desconocida"}

# 3. Conversation loop
def chat_with_functions(messages, functions):
    """Loop principal de conversation con function calling"""
    response = openai.ChatCompletion.create(
        model="gpt-4o",
        messages=messages,
        functions=functions,
        function_call="auto"  # El modelo decide cuándo llamar
    )
    
    message = response["choices"][0]["message"]
    
    # Si el modelo quiere llamar una función
    if message.get("function_call"):
        function_name = message["function_call"]["name"]
        arguments = json.loads(message["function_call"]["arguments"])
        
        # Ejecutar la función
        result = execute_function(function_name, arguments)
        
        # Agregar la respuesta de la función al conversation
        messages.append({
            "role": "function",
            "name": function_name,
            "content": json.dumps(result)
        })
        
        # Llamada final para generar la respuesta
        response = openai.ChatCompletion.create(
            model="gpt-4o",
            messages=messages,
            functions=functions
        )
    
    return response["choices"][0]["message"]["content"]

# 4. Uso
messages = [
    {"role": "system", "content": "Eres un asistente útil"},
    {"role": "user", "content": "¿Cómo está el clima en Bogotá?"}
]

response = chat_with_functions(messages, functions)
print(response)
# "El clima en Bogotá está parcialmente nublado con 22°C y 65% de humedad."

🔍 Tipos de Function Calling

Hay tres modos principales:

1. Auto (recomendado)

El modelo decide si llamar una función o responder normalmente:

# El modelo puede o no llamar una función
response = openai.ChatCompletion.create(
    model="gpt-4o",
    messages=messages,
    functions=functions,
    function_call="auto"
)

2. Forced

Fuerza al modelo a llamar una función específica:

# Siempre llama get_weather, aunque no tenga sentido
response = openai.ChatCompletion.create(
    model="gpt-4o",
    messages=messages,
    functions=functions,
    function_call={"name": "get_weather"}
)

3. None

Desactiva function calling — útil para conversaciones normales:

# Sin function calling
response = openai.ChatCompletion.create(
    model="gpt-4o",
    messages=messages,
    function_call="none"
)

🚨 Errores Comunes y Fixes

Error 1: No definir bien los JSON Schemas

Síntoma: El modelo inventa parámetros o genera llamadas incorrectas.

Causa: Los schemas son vagos o incompletos. Sin constraints claros, el modelo improvisa.

Fix: Define todos los campos posibles con tipos específicos, descriptions claras, y enums cuando hay opciones fijas. Un buen schema es la diferencia entre function calling que funciona y caos.

Error 2: No manejar errores de función

Síntoma: La aplicación crashea cuando una función falla.

Causa: Asumes que todas las llamadas a función van a succeed. En el mundo real, APIs fallan, servicios se caen, timeout pasan.

Fix: Implementa try/catch, timeouts, y fallback values. Cuando una función falla, regresa un mensaje claro al modelo para que pueda responder apropiadamente.

Error 3: Loop infinito de function calls

Síntoma: El modelo sigue llamando funciones en loop.

Causa: No hay límite de recursion o el prompt no indica cuándo parar.

Fix: Implementa un max_iterations counter y un stop condition claro. También mejora el system prompt para indicar cuándo el objetivo está logrado y no necesita más llamadas.

✅ Mejores Prácticas

  • Schemas precisos: Cada parámetro necesita description, tipo, y constraints claras.
  • Una función por propósito: No hagas funciones catch-all. Mejor muchas específicas que una gigante.
  • Validación de inputs: Nunca confíes ciegamente en los argumentos del modelo — valida siempre antes de ejecutar.
  • Manejo de errores robusto: Prepared para failures en cualquier llamada externa.
  • Contexto de sesión: Mantén el conversation history completo para que el modelo pueda razonar sobre múltiples llamadas.
