Hola, parcero. Vamos al Día 132 y hoy toca MLflow, el framework de experiment tracking que el 70% de los equipos de ML en Colombia todavía no usa bien — o no usa del todo. Y cuando no trackeas tus experimentos desde el día uno, pierdes información que luego no puedes recuperar. ¿Cuántas veces has vuelto a un proyecto después de dos semanas y no recuerdas cuál era la configuración que te dio el mejor resultado? Eso no debería pasar. Vamos a ver cómo hacerlo bien, con código real de PyTorch y comparándolo con Weights & Biases para que sepas cuándo usar cada uno.

📐 Fundamentos Teóricos

MLflow es una plataforma open source para el ciclo de vida completo de ML: desde experiment tracking hasta model registry y deployment. Desarrollada por Databricks, es hoy el estándar de facto en la industria para organizar experimentos de ML.

Los cuatro componentes de MLflow

  • MLflow Tracking: Registra parameters, metrics, metadata y artifacts durante el entrenamiento. Cada run es un исполнений del código con su propio timestamp y UUID.
  • MLflow Projects: Formato empaquetado para código ML reproducible, con dependencias yentry points definidos.
  • MLflow Models: Formato estándar para empaquetar modelos para deployment en distintos serving frameworks.
  • MLflow Model Registry: Centralized model store para versionar modelos, hacer stage transitions (Staging → Production → Archived), y trackear lineage.

¿Cómo funciona el Tracking?

Cada experimento en MLflow se organiza así:

$$\text{Experiment} \rightarrow \{\text{Run}_1, \text{Run}_2, \ldots, \text{Run}_n\}$$

Cada Run contiene:

  • Parameters: {"learning_rate": 0.001, "batch_size": 32, "optimizer": "adam"}
  • Metrics: {"accuracy": 0.92, "loss": 0.23, "f1": 0.89} — registrados en timestamps, permitiendo trackear la evolución durante el entrenamiento.
  • Artifacts: Archivos arbitrarios: modelos guardados, plots, JSONs, imágenes.
  • Tags y metadata: {"user": "fabian", "dataset": "mnist_v2", "git_sha": "a3f2c1d"}

Comparación: MLflow vs Weights & Biases

Esta es una сравнение que me preguntan mucho en consulting. Aquí va la diferencia prática:

Aspecto MLflow Weights & Biases
Costo Gratis (self-hosted) SaaS con tiers gratis/pagos
Setup Más complejo inicial Muy fácil (wandb.init())
UI Funcional pero básica Superior, más interactiva
Artifacts Ilimitados (disco propio) 100GB gratis en SaaS

Recomendación prática: para equipos pequeños o individuales, W&B es más rápido de adoptar. Para equipos grandes que necesitan control total, compliance, o model registryenterprise-grade, MLflow self-hosted es mejor.

# Generar datos realistas (simulando historial colombiano)
def generate_transaction_data(n_samples, seed_offset=0):
    np.random.seed(42 + seed_offset)
    
    # Features: monto, frecuencia, antigüedad, categoría, hora, días inactivo
    data = {
        'monto': np.random.lognormal(6.5, 1.5, n_samples),  # skewed hacia montos bajos
        'frecuencia_mensual': np.random.randint(1, 60, n_samples),
        'antiguedad_dias': np.random.randint(30, 2000, n_samples),
        'categoria': np.random.randint(0, 8, n_samples),  # 8 categorías de comercio
        'hora_transaccion': np.random.randint(0, 24, n_samples),
        'dias_inactivo': np.random.randint(0, 120, n_samples),
    }
    
    # Target: fraude (1) o legítimo (0)
    # Distribución realista: menos del 2% son fraudulentas
    log_probs = (
        -3.0 +
        0.7 * (data['monto'] > 2000).astype(float) +
        -0.3 * np.log1p(data['frecuencia_mensual']) +
        -0.2 * np.log1p(data['antiguedad_dias']) +
        0.4 * (data['hora_transaccion'] < 6).astype(float) +  # madrugada = sospechoso
        0.5 * (data['dias_inactivo'] > 30).astype(float)
    )
    fraud_probs = 1 / (1 + np.exp(-log_probs))
    data['fraude'] = (np.random.random(n_samples) < fraud_probs).astype(int)
    
    return pd.DataFrame(data)

train_df = generate_transaction_data(n_train, seed_offset=0)
test_df = generate_transaction_data(n_test, seed_offset=999)

X_train = torch.FloatTensor(train_df.drop('fraude', axis=1).values)
y_train = torch.LongTensor(train_df['fraude'].values)
X_test = torch.FloatTensor(test_df.drop('fraude', axis=1).values)
y_test = torch.LongTensor(test_df['fraude'].values)

print(f"Train: {X_train.shape}, Test: {X_test.shape}")

print(f"Test fraud rate: {y_test.mean()*100:.2f}%")

# DEFINICIÓN DEL MODELO
# ============================================================
class FraudClassifier(nn.Module):
    def __init__(self, input_size, hidden_sizes=[64, 32], dropout=0.3):
        super().__init__()
        layers = []
        in_feat = input_size
        
        for h_size in hidden_sizes:
            layers.append(nn.Linear(in_feat, h_size))
            layers.append(nn.ReLU())
            layers.append(nn.Dropout(dropout))
            in_feat = h_size
        
        layers.append(nn.Linear(in_feat, 2))  # 2 classes: legítimo, fraude
        self.network = nn.Sequential(*layers)
    
    def forward(self, x):
        return self.network(x)

# ============================================================
# FUNCIÓN DE ENTRENAMIENTO CON MLFLOW TRACKING
# ============================================================
def train_with_mlflow(
    model, train_loader, test_loader, 
    optimizer, criterion, n_epochs,
    experiment_name, run_name, params
):
    """
    Training loop completo con MLflow tracking.
    Registra: params, metrics por epoch, artifacts (modelo, plots).
    """
    with mlflow.start_run(run_name=run_name) as run:
        run_id = run.info.run_id
        print(f"\n🔍 MLflow Run ID: {run_id}")
        
        # --- Loggear parámetros ---
        mlflow.log_params({
            'n_epochs': n_epochs,
            'batch_size': params.get('batch_size'),
            'learning_rate': params.get('lr'),
            'optimizer': params.get('optimizer'),
            'hidden_layers': str(params.get('hidden_layers')),
            'dropout': params.get('dropout'),
            'n_features': X_train.shape[1],
        })
        
        best_val_acc = 0.0
        best_model_state = None
        
        for epoch in range(n_epochs):
            # --- Training ---
            model.train()
            train_loss = 0.0
            train_correct = 0
            train_total = 0
            
            for batch_X, batch_y in train_loader:
                optimizer.zero_grad()
                outputs = model(batch_X)
                loss = criterion(outputs, batch_y)
                loss.backward()
                optimizer.step()
                
                train_loss += loss.item() * batch_X.size(0)
                _, predicted = torch.max(outputs.data, 1)
                train_total += batch_y.size(0)
                train_correct += (predicted == batch_y).sum().item()
            
            train_loss /= train_total
            train_acc = train_correct / train_total
            
            # --- Validation ---
            model.eval()
            val_loss = 0.0
            val_correct = 0
            val_total = 0
            
            with torch.no_grad():
                for batch_X, batch_y in test_loader:
                    outputs = model(batch_X)
                    loss = criterion(outputs, batch_y)
                    val_loss += loss.item() * batch_X.size(0)
                    _, predicted = torch.max(outputs.data, 1)
                    val_total += batch_y.size(0)
                    val_correct += (predicted == batch_y).sum().item()
            
            val_loss /= val_total
            val_acc = val_correct / val_total
            
            # --- Loggear metrics a MLflow ---
            mlflow.log_metrics({
                'train_loss': train_loss,
                'train_acc': train_acc,
                'val_loss': val_loss,
                'val_acc': val_acc,
            }, step=epoch)
            
            # Guardar mejor modelo
            if val_acc > best_val_acc:
                best_val_acc = val_acc
                best_model_state = model.state_dict().copy()
            
            if (epoch + 1) % 10 == 0 or epoch == 0:
                print(f"  Epoch {epoch+1:3d} | "
                      f"Train Loss: {train_loss:.4f} Acc: {train_acc:.4f} | "
                      f"Val Loss: {val_loss:.4f} Acc: {val_acc:.4f}")
        
        # Cargar mejor modelo
        model.load_state_dict(best_model_state)
        
        # --- Guardar modelo como artifact ---
        mlflow.pytorch.log_model(
            model, 
            artifact_path="best_model",
            registered_model_name=params.get('registered_name', None)
        )
        
        # --- Generar y guardar artifact: matriz de confusión ---
        model.eval()
        all_preds = []
        all_labels = []
        with torch.no_grad():
            for batch_X, batch_y in test_loader:
                outputs = model(batch_X)
                _, preds = torch.max(outputs.data, 1)
                all_preds.extend(preds.numpy())
                all_labels.extend(batch_y.numpy())
        
        cm = confusion_matrix(all_labels, all_preds)
        
        fig, ax = plt.subplots(figsize=(6, 5))
        im = ax.imshow(cm, interpolation='nearest', cmap=plt.cm.Blues)
        ax.figure.colorbar(im, ax=ax)
        ax.set(xticks=[0, 1], yticks=[0, 1],
               xticklabels=['Legítimo', 'Fraude'],
               yticklabels=['Legítimo', 'Fraude'],
               ylabel='True label',
               xlabel='Predicted label',
               title=f'Confusion Matrix\nBest Val Acc: {best_val_acc:.4f}')
        
        # Añadir texto en cada celda
        thresh = cm.max() / 2.
        for i in range(cm.shape[0]):
            for j in range(cm.shape[1]):
                ax.text(j, i, format(cm[i, j], 'd'),
                        ha="center", va="center",
                        color="white" if cm[i, j] > thresh else "black")
        
        fig.tight_layout()
        confusion_path = "/tmp/confusion_matrix.png"
        plt.savefig(confusion_path, dpi=150, bbox_inches='tight')
        mlflow.log_artifact(confusion_path)
        plt.close()
        
        # --- Guardar classification report ---
        report = classification_report(all_labels, all_preds, target_names=['Legítimo', 'Fraude'])
        report_path = "/tmp/classification_report.txt"
        with open(report_path, 'w') as f:
            f.write(report)
        mlflow.log_artifact(report_path)
        
        print(f"\n✅ Run completado. Best Val Accuracy: {best_val_acc:.4f}")
        
        return best_val_acc, run_id

🚨 Errores Comunes + Fixes

Error 1: No usar experiment tracking desde el día 1 del proyecto

Este es el error más crítico. Empiezas un proyecto de ML, entrenas 20 versiones del modelo en dos semanas, y cuando finalmente encuentras una buena configuración, no tienes registro de qué exactamente te dio ese resultado. Los parameters, las seeds, el preprocessing exacto — todo perdido porque lo hiciste en scripts de Jupyter que reiniciaste sin guardar outputs. Peor aún: cuando el modelo falla en producción dos meses después, no tienes cómo reproducir el experimento exacto que deployaste.

Fix:

# Desde el día 1, envolvé TODO en mlflow.start_run()
import mlflow

mlflow.set_experiment("mi_proyecto_v1")

# Incluso para el más mínimo experimento
with mlflow.start_run(run_name="quick_baseline_test"):
    mlflow.log_params({"lr": 0.001, "epochs": 5})
    # ... tu código de entrenamiento ...
    mlflow.log_metrics({"accuracy": 0.85})

# No importa si el experimento es "solo para probar"
# Si no lo trackeás, no existe para vos en dos semanas.

Error 2: Loggear todo sin filtro lo que hace difícil encontrar experimentos relevantes

El extremo opuesto también es problemático. Algunos equipos loguean absolutamente todo — cada batch, cada loss por capa, cada gradient norm, cada prediction — lo que resulta en miles de métricas por run y hace imposible encontrar las realmente importantes en la UI. En dos semanas tienes un experimento con 50,000 métricas y no sabes cuáles importan.

Fix:

# Loggear SOLO lo que necesitás para decision-making
with mlflow.start_run(run_name="production_model_v3"):
    # Params: configuración del experimento (solo los importantes)
    mlflow.log_params({
        "model_type": "transformer",
        "learning_rate": 0.0001,
        "batch_size": 32,
        "n_layers": 6,  # No loggear cada batch_size tested, solo el final
    })
    
    # Metrics: solo los que te importan para comparar
    # Si son muchos, agrupalos en un dict significativo
    mlflow.log_metrics({
        "epoch_loss": epoch_loss,      # Por epoch (no por batch)
        "epoch_acc": epoch_acc,
        "val_f1": val_f1,
        "training_time_secs": elapsed,
    })
    
    # Para debugging interno, guardá plots como artifacts
    # No como métricas individuales
    mlflow.log_artifact("debug_gradient_flow.png")
    mlflow.log_artifact("debug_predictions.csv")

# Si necesitás logging por batch para debugging,
# hacelo a archivo local y solo guardá el resumen como metric.

Error 3: No usar model registry para versionar modelos en producción

Muchas empresas guardan modelos como model_v1.pkl, model_v1_final.pkl, model_v1_final_v2.pkl — un desastre de versionado. Cuando necesitas hacer rollback a la versión de hace tres semanas porque la nueva está fallando, no sabes cuál archivo era. MLflow Model Registry resuelve esto con un sistema de versions y stages干干净净.

Fix:

from mlflow.tracking import MlflowClient

client = MlflowClient()

# Registrar modelo después del entrenamiento
model_uri = f"runs:/{run_id}/best_model"
registered = mlflow.register_model(model_uri, "MyModel")

# Transitoned a Staging para validar
client.transition_model_version_stage(
    name="MyModel",
    version=registered.version,
    stage="Staging"
)

# Después de validar en Staging, promover a Production
client.transition_model_version_stage(
    name="MyModel",
    version=registered.version,
    stage="Production"
)

# Para rollback: simplemente transicionar la versión anterior de vuelta
# client.transition_model_version_stage(
#     name="MyModel",
#     version=2,  # la versión anterior
#     stage="Production"
# )

# Listar todas las versiones y sus stages
for mv in client.search_model_versions("name='MyModel'"):
    print(f"Version {mv.version}: {mv.current_stage}")

📊 Resumen y Cierre

Resumen del día, parcero:

  • MLflow Tracking registra parameters, metrics y artifacts por cada run de experimento
  • MLflow Model Registry es tu sistema de versionado de modelos en producción — úsalo desde el día uno
  • Los stages (Staging, Production, Archived) te dan un workflow limpo para promoción y rollback
  • Para proyectos pequeños, W&B es más rápido de adoptar. Para equipos grandes, MLflow self-hosted da más control
  • NUNCA empieces un proyecto de ML sin tracking — aunque sea "solo un prototype"
  • Loggea lo que necesitas para decision-making, no todo lo que puedes loggear
  • El Model Registry es la diferencia entre "dónde está mi modelo de producción?" y "模型 v3.2 está en Production desde ayer"

MLflow no es glamour. Es la disciplina de registrar todo desde el principio para que cuando algo falle o cuando necesites comparar lo que hiciste hace dos meses con lo que estás haciendo ahora, tengas los datos. En equipos donde el caos de experimentos es la norma, MLflow es tu tabla de salvación. Implementalo desde el primer día, aunque sea en modo local sin server. Después me vas a agradecer cuando puedas hacer mlflow.search_runs() y encontrar exactamente el experimento que necesitás.
