28 de junio de 2026

🎯 Batch Size: Conceptos Fundamentales

Batch Size es el número de samples que procesas antes de actualizar los pesos de tu red. Es uno de los hiperparámetros más importantes y el 85% de practitioners loconfigura incorrectamente sin entender las consecuencias.

Los tres escenarios:

  • Batch Gradient Descent: Todo el dataset → preciso pero lento
  • Mini-Batch SGD: 32-512 samples → el sweet spot
  • Stochastic (batch=1): 1 sample → ruido, no converge bien

📐 La Matemática Detrás

El gradiente se calcula como el promedio sobre el batch:

$$\\nabla L_{batch} = \\frac{1}{B} \\sum_{i=1}^{B} \\nabla L_i(x_i, y_i)$$

donde B es el batch size. Varianza del gradiente escala como $O(1/\\sqrt{B})$.

La intuición práctica:

  • Batch pequeño → gradiente ruidoso → escapa mínimos locales
  • Batch grande → gradiente preciso → converge mejor pero puede atascarse
  • Batch size óptimo depende de GPU memory y la naturaleza del problema

⚠️ Errores Comunes

Error 1: Batch Size Fijo Sin Ajustar Learning Rate

El problema: El learning rate óptimo escala con batch size. Si duplicas el batch size pero mantienes el mismo LR, la red converge más lento o no converge.

La regla empírica: LR_scaled = LR_base × (batch_size / batch_size_base)^0.5

# Escalar learning rate con batch size
def scale_lr(initial_lr, current_batch, base_batch=32):
    scale = (current_batch / base_batch) ** 0.5
    return initial_lr * scale

# Uso
lr = scale_lr(1e-3, current_batch=128)  # ≈ 2e-3

Error 2: Ignorar el Impacto en Batch Normalization

El problema: BatchNorm calcula media/varianza sobre el batch. Con batch size pequeño (≤8), las estadísticas se vuelven muy ruidosas y el modelo degrada.

# Solución: usar Ghost BatchNorm o LayerNorm
from torch.nn import LayerNorm

class GhostBatchNorm(torch.nn.Module):
    """Variance reduction across virtual sub-batches."""
    def __init__(self, num_features, num_splits=8):
        super().__init__()
        self.bn = torch.nn.BatchNorm1d(num_features)
        self.num_splits = num_splits
    
    def forward(self, x):
        chunks = x.chunk(self.num_splits, dim=0)
        mean = torch.stack([c.mean(dim=0) for c in chunks]).mean(dim=0)
        var = torch.stack([c.var(dim=0, unbiased=False) for c in chunks]).mean(dim=0)
        # Normalize
        x_norm = (x - mean.unsqueeze(0)) / (var.unsqueeze(0) + 1e-5)
        return self.bn(x_norm)

Error 3: No Usar Gradient Accumulation Para Batch Sizes Grandes

El problema: GPU memory limita batch size, especialmente en LLMs. Sin gradient accumulation, no puedes simular batches grandes.

# Gradient accumulation parabatch sizes virtuales grandes
accumulation_steps = 4
effective_batch = batch_size * accumulation_steps

model.zero_grad()
for i, (data, target) in enumerate(dataloader):
    data, target = data.cuda(), target.cuda()
    output = model(data)
    loss = criterion(output, target)
    loss = loss / accumulation_steps  # Normalize loss
    loss.backward()
    
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        model.zero_grad()

✅ Resumen y Recomendaciones

  • Vision tasks: 32-128 es el sweet spot
  • NLP/LLMs: 8-32 (limitado por memoria)
  • Embedding models: 128-512 (puede ser mayor)
  • Siempre escala LR si cambias batch size
  • Gradient accumulation para simular batches grandes
  • Usa drop_last=True para evitar batches asimétricos

Hágale que batch size no es "set and forget". Ajusta LR, considera memory constraints, y usa gradient accumulation cuando necesites batches virtuales grandes. El 15% que hace esto bien tiene modelos que convergen 30% más rápido, parcero.
