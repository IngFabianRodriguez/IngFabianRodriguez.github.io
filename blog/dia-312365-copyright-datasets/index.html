📐 La Matemática del Task Planning con LLMs

Antes de código, la teoría. Una tarea compleja puede formalizarse como un Goal-Oriented Action Planning (GOAP) o como un Hierarchical Task Network (HTN). Vamos con GOAP que es más intuitivo.

Formalización del Problema

Una tarea se define como una tupla:

(G, S, A, T, C)

  • G = Goal state (estado objetivo)
  • S = Current state (estado actual)
  • A = Set of actions posibles
  • T = Action effects: T(a) = (preconditions, effects)
  • C = Cost function para cada acción

El problema es encontrar un plan — una secuencia de acciones — tal que:

∃(a_1, ..., a_n) : S_0 --a_1--> S_1 --a_2--> ... --a_n--> G

donde S_i es el estado después de aplicar la acción a_i.

Plan Score Function

Para comparar planes candidatos, usamos una función de score:

Score(plan) = α × Completeness - β × Cost - γ × Risk

  • Completeness: Qué tan cerca llega al goal (0-1)
  • Cost: Costo total de ejecutar el plan (tokens, tiempo, dinero)
  • Risk: Probabilidad de failure basada en acciones complejas

El LLM como planner genera candidatos y nosotros elegimos el de mayor score.

Task Decomposition con Chain-of-Thought

Para descomponer tareas complejas, usamos un approach de recursive decomposition:

Task(x) → if complex(x) then decompose(x) = [subtask_1, ..., subtask_n] else [x]

La recursión para cuando todos los subtasks son "atómicos" (acciones directas o herramientas).

class TaskStatus(Enum):
    """Estados posibles de una tarea"""
    PENDING = "pending"
    IN_PROGRESS = "in_progress"
    COMPLETED = "completed"
    FAILED = "failed"
    RETRYING = "retrying"
    CANCELLED = "cancelled"


class ActionType(Enum):
    """Tipos de acciones atómicas disponibles"""
    LLM_QUERY = "llm_query"           # Consulta a LLM
    SEARCH = "search"                 # Búsqueda web
    CALCULATE = "calculate"           # Cálculo
    READ_FILE = "read_file"           # Leer archivo
    WRITE_FILE = "write_file"         # Escribir archivo
    EXTERNAL_API = "external_api"     # Llamada a API externa
    USER_CONFIRM = "user_confirm"     # Confirmación de usuario
    WAIT = "wait"                     # Esperar


@dataclass
class Action:
    """Una acción atómica ejecutable"""
    action_type: ActionType
    description: str
    parameters: dict = field(default_factory=dict)
    retry_count: int = 0
    max_retries: int = 3
    timeout: float = 30.0
    dependencies: list[str] = field(default_factory=list)  # IDs de acciones dependientes
    
    def can_execute(self, completed_actions: set[str]) -> bool:
        """Verifica si las dependencias están cumplidas"""
        return all(dep in completed_actions for dep in self.dependencies)


@dataclass
class TaskResult:
    """Resultado de ejecutar una acción"""
    success: bool
    output: any = None
    error: str = None
    execution_time: float = 0.0
    retries_used: int = 0


@dataclass
class ExecutableTask:
    """Una tarea descompuesta y lista para ejecutar"""
    task_id: str
    description: str
    actions: list[Action]
    status: TaskStatus = TaskStatus.PENDING
    results: dict[str, TaskResult] = field(default_factory=dict)
    created_at: float = field(default_factory=time.time)
    
    @property
    def completed_actions(self) -> set[str]:
        return {aid for aid, res in self.results.items() if res.success}
    
    @property
    def is_complete(self) -> bool:
        return all(res.success for res in self.results.values())
    
    @property
    def failed_actions(self) -> list[str]:
        return [aid for aid, res in self.results.items() if not res.success]

class ExecutionEngine:
    """
    Motor de ejecución de tareas con retry y recovery.
    Implementa retry exponencial con jitter.
    """
    
    def __init__(self, llm_client=None, search_client=None):
        self.llm_client = llm_client
        self.search_client = search_client
        
    def execute_action(self, action: Action) -> TaskResult:
        """
        Ejecuta una acción individual con retry logic.
        
        Retry strategy: exponential backoff con jitter
        wait_time = base_wait * (2 ** retry_count) + random_jitter
        """
        start_time = time.time()
        last_error = None
        
        for attempt in range(action.max_retries + 1):
            try:
                # Verificar timeout
                if time.time() - start_time > action.timeout:
                    return TaskResult(
                        success=False,
                        error=f"Timeout after {action.timeout}s",
                        execution_time=time.time() - start_time
                    )
                
                # Ejecutar según tipo de acción
                result = self._dispatch(action)
                
                if result.success:
                    result.retries_used = attempt
                    return result
                else:
                    last_error = result.error
                    
            except Exception as e:
                last_error = str(e)
                
            # Retry con exponential backoff si no es el último intento
            if attempt < action.max_retries:
                wait_time = self._calculate_backoff(attempt)
                time.sleep(wait_time)
                action.retry_count = attempt + 1
        
        return TaskResult(
            success=False,
            error=last_error or "Max retries exceeded",
            execution_time=time.time() - start_time,
            retries_used=action.max_retries
        )
    
    def _calculate_backoff(self, retry_count: int, base: float = 1.0) -> float:
        """Calcula wait time con exponential backoff + jitter"""
        import random
        exp_wait = base * (2 ** retry_count)
        jitter = random.uniform(0, 0.5)  # 0-500ms de jitter
        return min(exp_wait + jitter, 30.0)  # Cap a 30 segundos
    
    def _dispatch(self, action: Action) -> TaskResult:
        """Dispatch a la función correcta según tipo de acción"""
        start = time.time()
        
        if action.action_type == ActionType.LLM_QUERY:
            return self._execute_llm_query(action)
        elif action.action_type == ActionType.SEARCH:
            return self._execute_search(action)
        elif action.action_type == ActionType.CALCULATE:
            return self._execute_calculate(action)
        elif action.action_type == ActionType.READ_FILE:
            return self._execute_read_file(action)
        elif action.action_type == ActionType.WRITE_FILE:
            return self._execute_write_file(action)
        elif action.action_type == ActionType.USER_CONFIRM:
            return self._execute_user_confirm(action)
        elif action.action_type == ActionType.WAIT:
            time.sleep(action.parameters.get("seconds", 1))
            return TaskResult(success=True, output="Waited", execution_time=time.time() - start)
        else:
            return TaskResult(success=False, error=f"Unknown action type: {action.action_type}")
    
    def _execute_llm_query(self, action: Action) -> TaskResult:
        """Ejecuta query a LLM"""
        query = action.parameters.get("query", "")
        # En producción: response = self.llm_client.generate(query)
        return TaskResult(success=True, output=f"LLM response to: {query}", execution_time=time.time() - time.time())
    
    def _execute_search(self, action: Action) -> TaskResult:
        """Ejecuta búsqueda web"""
        query = action.parameters.get("query", "")
        # En producción: results = self.search_client.search(query)
        return TaskResult(success=True, output=[f"Result 1 for {query}", f"Result 2 for {query}"], execution_time=0.5)
    
    def _execute_calculate(self, action: Action) -> TaskResult:
        """Ejecuta cálculo"""
        operation = action.parameters.get("operation", "aggregate")
        data = action.parameters.get("data", [])
        # Simular cálculo
        result = sum(d for d in data) if data else 0
        return TaskResult(success=True, output=result, execution_time=0.1)
    
    def _execute_read_file(self, action: Action) -> TaskResult:
        """Lee archivo"""
        filepath = action.parameters.get("path", "")
        try:
            with open(filepath, 'r') as f:
                content = f.read()
            return TaskResult(success=True, output=content, execution_time=0.2)
        except FileNotFoundError:
            return TaskResult(success=False, error=f"File not found: {filepath}", execution_time=0.1)
    
    def _execute_write_file(self, action: Action) -> TaskResult:
        """Escribe archivo"""
        filepath = action.parameters.get("path", "")
        content = action.parameters.get("content", "")
        try:
            with open(filepath, 'w') as f:
                f.write(content)
            return TaskResult(success=True, output=f"Wrote {len(content)} bytes", execution_time=0.2)
        except Exception as e:
            return TaskResult(success=False, error=str(e), execution_time=0.1)
    
    def _execute_user_confirm(self, action: Action) -> TaskResult:
        """
        Solicita confirmación al usuario.
        En producción, esto sería async y bloquearía hasta recibir respuesta.
        """
        message = action.parameters.get("message", "¿Confirmar?")
        # Placeholder: en producción, pending until user responds
        return TaskResult(success=True, output={"confirmed": True, "message": message}, execution_time=0.0)


class RecoveryManager:
    """
    Maneja recovery cuando una acción falla.
    Implementa varios strategies de recovery.
    """
    
    def __init__(self):
        self.recovery_strategies = {
            "retry": self._retry_strategy,
            "skip": self._skip_strategy,
            "alternative": self._alternative_strategy,
            "rollback": self._rollback_strategy,
            "escalate": self._escalate_strategy,
        }
    
    def attempt_recovery(self, failed_action: Action, 
                        context: dict,
                        available_strategies: list[str] = None) -> Optional[Action]:
        """
        Intenta recuperar de un failure.
        Retorna una nueva acción para reintentar, o None si no hay recovery posible.
        """
        strategies_to_try = available_strategies or ["retry", "alternative", "escalate"]
        
        for strategy_name in strategies_to_try:
            strategy = self.recovery_strategies.get(strategy_name)
            if strategy:
                new_action = strategy(failed_action, context)
                if new_action:
                    return new_action
                    
        return None  # No recovery possible
    
    def _retry_strategy(self, action: Action, context: dict) -> Optional[Action]:
        """Retry con parámetros modificados"""
        if action.retry_count >= action.max_retries:
            return None
            
        # Modificar parámetros para el retry
        new_params = action.parameters.copy()
        if "query" in new_params:
            # Hacer query más específica
            new_params["query"] = f"{new_params['query']} (retry {action.retry_count + 1})"
            
        return Action(
            action_type=action.action_type,
            description=f"RETRY: {action.description}",
            parameters=new_params,
            retry_count=action.retry_count + 1,
            max_retries=action.max_retries,
            timeout=action.timeout * 1.5  # Aumentar timeout
        )
    
    def _skip_strategy(self, action: Action, context: dict) -> Optional[Action]:
        """Skip la acción y marcar como completada (solo para no-críticas)"""
        non_critical = context.get("non_critical_actions", [])
        if action.description in non_critical:
            # Crear acción dummy que "falla" pero se marca como success
            return Action(
                action_type=ActionType.WAIT,
                description=f"SKIPPED (non-critical): {action.description}",
                parameters={"seconds": 0}
            )
        return None
    
    def _alternative_strategy(self, action: Action, context: dict) -> Optional[Action]:
        """Buscar alternativa para la acción"""
        alternatives = context.get("alternative_actions", {})
        
        if action.action_type in alternatives:
            alt = alternatives[action.action_type]
            return Action(
                action_type=alt["type"],
                description=f"ALTERNATIVE: {action.description}",
                parameters=alt.get("parameters", {})
            )
        return None
    
    def _rollback_strategy(self, action: Action, context: dict) -> Optional[Action]:
        """
        Rollback de acciones previamente completadas.
        Útil para operaciones con side effects.
        """
        completed = context.get("completed_with_side_effects", [])
        
        rollback_action = Action(
            action_type=ActionType.WRITE_FILE,
            description=f"ROLLBACK: revert {action.description}",
            parameters={"operation": "rollback", "original_action": action.description}
        )
        return rollback_action
    
    def _escalate_strategy(self, action: Action, context: dict) -> Optional[Action]:
        """
        Escalar a usuario cuando no hay recovery automático.
        """
        escalate_action = Action(
            action_type=ActionType.USER_CONFIRM,
            description=f"ESCALATE: {action.description} requiere intervención manual",
            parameters={
                "message": f"La acción '{action.description}' falló. ¿Cómo deseas proceder?",
                "require_response": True
            }
        )
        return escalate_action


class TaskAutomationEngine:
    """
    Motor principal de task automation.
    Orchestrates decomposition, planning, execution, y recovery.
    """
    
    def __init__(self, llm_client=None):
        self.decomposer = TaskDecomposer(llm_client)
        self.executor = ExecutionEngine(llm_client)
        self.recovery_manager = RecoveryManager()
        self.current_task: Optional[ExecutableTask] = None
        self.execution_callbacks: list[Callable] = []
        
    def execute_task(self, task_description: str, 
                     allow_recovery: bool = True) -> ExecutableTask:
        """
        Ejecuta una tarea completa con planning, execution, y recovery.
        
        Flujo:
        1. Decompose - descompón en acciones atómicas
        2. Plan - ordena acciones considerando dependencias
        3. Execute - ejecuta en orden topológico
        4. Recover - maneja failures con strategies configurables
        5. Report - resume resultados
        """
        # ===== PASO 1: Decompose =====
        print(f"[Planning] Descompiniendo tarea: {task_description}")
        actions = self.decomposer.decompose(task_description)
        
        # ===== PASO 2: Crear task executable =====
        task = ExecutableTask(
            task_id=f"task_{int(time.time())}",
            description=task_description,
            actions=actions
        )
        self.current_task = task
        
        # ===== PASO 3: Execute en orden =====
        print(f"[Execution] Ejecutando {len(actions)} acciones")
        task.status = TaskStatus.IN_PROGRESS
        
        for action in actions:
            # Verificar dependencias
            if not action.can_execute(task.completed_actions):
                print(f"[Skipping] {action.description} - dependencias no cumplidas")
                continue
            
            print(f"[Executing] {action.action_type.value}: {action.description}")
            result = self.executor.execute_action(action)
            task.results[action.description] = result
            
            if not result.success:
                print(f"[Failed] {action.description}: {result.error}")
                
                if allow_recovery:
                    # Intentar recovery
                    recovery_context = {
                        "non_critical_actions": ["wait", "log"],
                        "alternative_actions": {},
                        "completed_with_side_effects": []
                    }
                    
                    new_action = self.recovery_manager.attempt_recovery(
                        action, recovery_context
                    )
                    
                    if new_action:
                        print(f"[Recovery] Intentando: {new_action.description}")
                        recovery_result = self.executor.execute_action(new_action)
                        task.results[new_action.description] = recovery_result
                        
                        if not recovery_result.success:
                            task.status = TaskStatus.FAILED
                            break
                    else:
                        task.status = TaskStatus.FAILED
                        break
                else:
                    task.status = TaskStatus.FAILED
                    break
        
        # Verificar si completó exitosamente
        if task.is_complete:
            task.status = TaskStatus.COMPLETED
            
        return task
    
    def add_execution_callback(self, callback: Callable):
        """Agrega callback para eventos de ejecución"""
        self.execution_callbacks.append(callback)


# ===== EJEMPLO DE USO =====
if __name__ == "__main__":
    # Inicializar engine
    engine = TaskAutomationEngine()
    
    # Task de ejemplo
    task_description = """
    Investigar competidores de nuestro producto de SaaS,
    analizar sus precios, y generar un reporte con recomendaciones.
    """
    
    print("=== TASK AUTOMATION DEMO ===")
    print(f"Tarea: {task_description}\n")
    
    # Ejecutar
    result = engine.execute_task(task_description)
    
    # Reporte
    print(f"\n=== RESULTADO ===")
    print(f"Status: {result.status.value}")
    print(f"Acciones completadas: {len(result.completed_actions)}")
    print(f"Acciones fallidas: {len(result.failed_actions)}")
    
    for action_desc, res in result.results.items():
        status = "✅" if res.success else "❌"
        print(f"  {status} {action_desc} ({res.execution_time:.2f}s)")

⚠️ Los 3 Errores Comunes que Arruinan la Automatización

Error 1: No descomponer las tareas

El error más básico y más común. La gente le da una tarea compleja al LLM en un solo prompt y espera que mágicamente sepa qué hacer. No funciona así.

# ❌ CÓDIGO EQUIVOCADO - Prompt único para tarea compleja
response = openai.ChatCompletion.create(
    messages=[{
        "role": "user", 
        "content": "Hazme un reporte competitivo completo de mi startup"
    }]
)
# El LLM puede dar un reporte genérico, no sabe:
# - Qué competidores buscar
# - Qué fuentes usar
# - Cómo estructurar el análisis
# - Qué métricas comparar

Un LLM no puede ejecutar múltiples pasos de forma confiable sin decompose explícita. Necesita que le digas:

  • Step 1: Identificar 5 competidores principales
  • Step 2: Buscar información de precios de cada uno
  • Step 3: Comparar features
  • Step 4: Generar análisis con insights
  • Step 5: Crear reporte

Fix correcto — Task Decomposition:

# ✅ CÓDIGO CORRECTO - Descomposición explícita
class TaskPlanner:
    def create_execution_plan(self, goal: str) -> list[Step]:
        # 1. Análisis del goal
        goal_analysis = self.analyze_goal(goal)
        
        # 2. Identificar subtasks
        subtasks = self.identify_subtasks(goal_analysis)
        
        # 3. Ordenar por dependencias
        execution_order = self.topological_sort(subtasks)
        
        # 4. Generar prompts específicos para cada paso
        plan = []
        for step in execution_order:
            plan.append(Step(
                description=step,
                prompt=self.generate_step_prompt(step, context),
                expected_output=self.define_output_schema(step)
            ))
            
        return plan
    
    def execute_plan(self, plan: list[Step]) -> ExecutionResult:
        results = []
        for step in plan:
            # Contexto acumulado de pasos anteriores
            context = self.build_context(results)
            
            # Ejecutar con prompt específico
            result = self.execute_step(step, context)
            results.append(result)
            
            # Verificar before de continuar
            if not self.validate_output(result, step.expected_output):
                return ExecutionResult(partial=results, failed_at=step)
                
        return ExecutionResult(complete=results)

Error 2: No planificar con consideration de failures

El segundo error es asumir que todo va a salir bien. En producción, las cosas fallan: APIs no responden, searches no dan resultados, cálculos fallan. Si tu plan no considera failures, todo se cae.

Fix correcto — Plan con branches de failure:

# ✅ CÓDIGO CORRECTO - Plan con consideration de fallos
class RobustPlanner:
    def create_robust_plan(self, goal: str) -> ExecutionPlan:
        base_plan = self.create_base_plan(goal)
        
        # Agregar branches de failure a cada paso crítico
        enhanced_plan = []
        for step in base_plan.steps:
            enhanced_plan.append(step)
            
            # Si el paso es crítico, agregar alternativas
            if step.is_critical:
                # Alternative path 1: retry con parámetros distintos
                enhanced_plan.append(Step(
                    action="retry",
                    trigger="step.failed",
                    prompt=step.get_retry_prompt()
                ))
                
                # Alternative path 2: usar fuente alternativa
                if step.has_alternative_source:
                    enhanced_plan.append(Step(
                        action="use_alternative",
                        trigger="step.failed",
                        prompt=step.get_alternative_prompt()
                    ))
                    
        return ExecutionPlan(steps=enhanced_plan)
    
    def should_continue_on_failure(self, step: Step, error: Error) -> bool:
        """
        Decide si continuar o abortar based en el error.
        """
        # Categorías de errores recuperables vs no-recuperables
        recoverable = ["timeout", "rate_limit", "temporary_unavailable"]
        non_recoverable = ["auth_failed", "permission_denied", "not_found"]
        
        if error.type in non_recoverable:
            return False  # Abortar
            
        if step.is_optional and error.type in recoverable:
            return True   # Continuar saltando el paso opcional
            
        # Por defecto, abortar en errores desconocidos
        return False

Error 3: No tener error recovery

El tercer error — y quizás el más importante en producción — es no tener ningún mecanismo de recovery. Cuando algo falla, el sistema simplemente se detiene y hay que empezar de nuevo manualmente.

Fix correcto — Recovery strategies:

# ✅ CÓDIGO CORRECTO - Recovery automático
class AutomatedRecoverySystem:
    def __init__(self):
        self.strategies = {
            ActionType.SEARCH: [
                RetryStrategy(max_retries=3, backoff="exponential"),
                AlternativeSourceStrategy(fallback_engines=["bing", "duckduckgo"]),
            ],
            ActionType.LLM_QUERY: [
                RetryStrategy(max_retries=2, backoff="linear"),
                SimplifyQueryStrategy(),  # Hacer query más simple
                HumanEscalationStrategy(),  # Último recurso
            ],
            ActionType.FILE_OPERATION: [
                RetryStrategy(max_retries=3, backoff="fixed"),
                CheckPermissionsStrategy(),
                AlternativeLocationStrategy(),
            ]
        }
    
    def handle_failure(self, action: Action, error: Error) -> RecoveryAction:
        """Determina qué hacer cuando una acción falla"""
        
        strategies = self.strategies.get(action.action_type, [])
        
        for strategy in strategies:
            if strategy.can_handle(error):
                recovery = strategy.generate_recovery_action(action, error)
                
                if recovery:
                    # Verificar que el recovery tiene sentido
                    if self.validate_recovery(recovery, action):
                        return recovery
                        
        # Si ninguna strategy funciona, escalate to human
        return HumanInterventionAction(
            original_action=action,
            error=error,
            context=self.capture_context()
        )
    
    def capture_context(self) -> dict:
        """Captura contexto para debugging humano"""
        return {
            "task_state": self.get_current_task_state(),
            "completed_steps": self.get_completed_steps(),
            "failed_step": self.get_current_step(),
            "error_history": self.get_error_history(),
            "system_state": self.get_relevant_system_state()
        }

📊 Métricas para Task Automation

Para evaluar qué tan bien está funcionando tu sistema:

  • Task Completion Rate (TCR): Porcentaje de tareas que completan exitosamente
  • Recovery Success Rate (RSR): Porcentaje de failures que se recoveran automáticamente
  • Average Execution Time (AET): Tiempo promedio de ejecución
  • Step Success Rate (SSR): Éxito por tipo de acción
  • Escalation Rate (ER): Cuántas tareas requieren intervención humana

TCR = (tareas_completadas / total_tareas) × 100

RSR = (fallas_recuperadas / total_fallas) × 100

🔄 Resumen y Cierre

Hagamos el resumen parce:

  • Task decomposition es fundamental. No puedes darle una tarea compleja a un LLM sin descompásla primero.
  • El planning debe considerar failures. No asumas que todo va a salir bien — planifica el failure path también.
  • Error recovery no es opcional en producción. Sin recovery automático, tu sistema va a fallar en el momento más inoportuno.
  • El recovery hierarchy importa. Retry → Alternative → Skip (si no-crítico) → Escalate to human.
  • Mide todo. Sin métricas no sabes si tu sistema está mejorando o empeorando.

Lo que separa un sistema de automatización robusto de uno frágil no es que no tenga errores — es cómo maneja los errores cuando ocurren. Los mejores sistemas que conozco tienen recovery automático para el 90% de los casos, y cuando no pueden recoverar, escalan gracefulmente a intervención humana con todo el contexto capturado.
