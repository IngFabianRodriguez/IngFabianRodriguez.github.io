Streaming Responses - Por qué el 75% implementa streaming incorrectamente

21 de may de 2026
sse-starlette

Parcero, día 171 y hoy我们来聊聊 Streaming Responses en LLMs. Esa vaina de que los tokens aparezcan uno a uno en pantalla — el "typing effect" — parece simple pero el 75% lo implementa incorrectamente en producción. Y cuando te digo incorrectamente me refiero a que el frontend se queda colgado, o el usuario ve tokens duplicados, o el stream se corta a la mitad. De una.

El problema fundamental es que Server-Sent Events (SSE) no es trivial de implementar correctamente cuando combinas modelos de ML con HTTP streaming. Hay detalles de buffering, manejo de errores, y reconnection que la mayoria ignora.

🎯 Qué Es Streaming y Por Qué Importa

En un LLM, la generación de tokens es secuencial: cada token depende del anterior. Pero el usuario no quiere esperar a que el modelo termine de generar toda la respuesta para empezar a leer. El streaming reduce la perceived latency — el usuario ve resultados en ~100-200ms en lugar de 2-5 segundos para respuestas largas.

La diferencia entre sync y streaming:

  • Sync: El cliente envía request, espera (2-30s), recibe respuesta completa.
  • Streaming: El cliente recibe tokens incrementalmente cada 20-100ms.

El perceived latency baja de varios segundos a ~200ms. Eso es la diferencia entre una app que "se siente lenta" y una que "se siente responsiva".

📐 El Protocolo SSE (Server-Sent Events)

SSE es un estándar HTML5 para push de datos unidireccional sobre HTTP. A diferencia de WebSockets, SSE es unidireccional (servidor → cliente) pero mucho más simple de implementar y con soporte nativo de reconnection automática.

El formato de cada evento es:

event: token
data: {"content": "Hola"}

event: token
data: {"content": " mundo"}

event: done
data: {"total_tokens": 15}

La línea blank (double newline) separa eventos. El campo event: indica el tipo de evento para que el cliente pueda filtrar con addEventListener.

💻 Código Production-Grade con Streaming

"""
FastAPI endpoint con streaming de respuestas de LLM.
Maneja correctamente buffering, errores y finalizacion.
"""
import asyncio
import json
import logging
from typing import AsyncGenerator, Dict, Any, Optional
from dataclasses import dataclass
import sse_starlette.sse as sse
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
import uvicorn

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

app = FastAPI(title="LLM Streaming API", version="1.0.0")


@dataclass
class StreamConfig:
    """Configuración para streaming de respuestas."""
    model_name: str = "meta-llama/Llama-2-7b-chat-hf"
    max_new_tokens: int = 512
    temperature: float = 0.7
    top_p: float = 0.9
    do_sample: bool = True
    repetition_penalty: float = 1.1
    seed: Optional[int] = None


class LLMStreamer:
    """
    Generador asíncrono que produce tokens desde un LLM
    y los formatea como eventos SSE.
    """
    
    def __init__(self, model, tokenizer, config: StreamConfig):
        self.model = model
        self.tokenizer = tokenizer
        self.config = config
        self.logger = logging.getLogger(self.__class__.__name__)
    
    async def stream_generate(
        self, 
        prompt: str,
        conversation_history: Optional[list] = None
    ) -> AsyncGenerator[Dict[str, Any], None]:
        """
        Genera tokens de forma asíncrona con streaming SSE.
        
        Args:
            prompt: Texto de entrada
            conversation_history: Lista de mensajes previos para contexto
            
        Yields:
            Diccionarios con eventos SSE formateados
        """
        try:
            # Preparar el prompt con historial si existe
            if conversation_history:
                full_prompt = self._build_conversation_prompt(
                    conversation_history, prompt
                )
            else:
                full_prompt = prompt
            
            # Tokenizar de forma síncrona (necesario para el modelo)
            inputs = self.tokenizer(
                full_prompt, 
                return_tensors="pt",
                truncation=True,
                max_length=2048
            )
            
            # Mover a dispositivo del modelo
            device = next(self.model.parameters()).device
            inputs = {k: v.to(device) for k, v in inputs.items()}
            
            # Preparar generación
            generate_kwargs = {
                "max_new_tokens": self.config.max_new_tokens,
                "do_sample": self.config.do_sample,
                "temperature": self.config.temperature,
                "top_p": self.config.top_p,
                "repetition_penalty": self.config.repetition_penalty,
            }
            
            if self.config.seed is not None:
                torch.manual_seed(self.config.seed)
                if torch.cuda.is_available():
                    torch.cuda.manual_seed_all(self.config.seed)
            
            # Stream de tokens usando interruptible generation
            from transformers import TextIteratorStreamer
            from threading import Thread
            
            streamer = TextIteratorStreamer(
                self.tokenizer,
                skip_prompt=True,
                skip_special_tokens=True
            )
            
            # Run generation en thread separado para no bloquear
            generation_thread = Thread(
                target=self.model.generate,
                kwargs={
                    **inputs,
                    **generate_kwargs,
                    "streamer": streamer
                }
            )
            generation_thread.start()
            
            # Stream de tokens
            generated_text = ""
            token_count = 0
            
            for new_text in streamer:
                generated_text += new_text
                token_count += 1
                
                # Yield evento SSE
                yield {
                    "event": "token",
                    "data": json.dumps({
                        "content": new_text,
                        "full_text": generated_text,
                        "token_count": token_count
                    })
                }
                
                # Small delay para no saturar el cliente
                await asyncio.sleep(0)
            
            # Señalar completion
            yield {
                "event": "done",
                "data": json.dumps({
                    "total_tokens": token_count,
                    "full_text": generated_text
                })
            }
            
            generation_thread.join()
            
        except Exception as e:
            self.logger.error(f"Error en streaming: {str(e)}")
            yield {
                "event": "error",
                "data": json.dumps({"error": str(e)})
            }
    
    def _build_conversation_prompt(
        self, 
        history: list, 
        current_prompt: str
    ) -> str:
        """Construye prompt con historial de conversación."""
        messages = []
        for role, content in history:
            messages.append(f"{role}: {content}")
        messages.append(f"user: {current_prompt}")
        return "\n".join(messages) + "\nassistant:"


# Instancia global del streamer (en producción, usar dependency injection)
model = None
tokenizer = None
stream_config = StreamConfig()


@app.on_event("startup")
async def load_model():
    """Carga el modelo al iniciar el servidor."""
    global model, tokenizer
    logger.info("Cargando modelo...")
    tokenizer = AutoTokenizer.from_pretrained(stream_config.model_name)
    model = AutoModelForCausalLM.from_pretrained(
        stream_config.model_name,
        torch_dtype=torch.bfloat16,
        device_map="auto"
    )
    logger.info("Modelo cargado.")


@app.post("/v1/chat/completions")
async def chat_completions(
    messages: list,
    stream: bool = True,
    temperature: Optional[float] = None,
    max_tokens: Optional[int] = None,
):
    """
    Endpoint de chat completions con soporte para streaming.
    
    Compatible con OpenAI API format para facilitar migración.
    """
    if not model or not tokenizer:
        raise HTTPException(503, "Modelo no cargado")
    
    # Extraer el último mensaje del usuario
    if not messages or messages[-1].get("role") != "user":
        raise HTTPException(400, "Último mensaje debe ser del usuario")
    
    current_prompt = messages[-1]["content"]
    history = [
        (m["role"], m["content"]) 
        for m in messages[:-1]
    ]
    
    # Actualizar config
    config = StreamConfig(
        temperature=temperature or stream_config.temperature,
        max_new_tokens=max_tokens or stream_config.max_new_tokens,
    )
    
    streamer = LLMStreamer(model, tokenizer, config)
    
    if stream:
        return StreamingResponse(
            streamer.stream_generate(current_prompt, history),
            media_type="text/event-stream",
            headers={
                "Cache-Control": "no-cache",
                "Connection": "keep-alive",
                "X-Accel-Buffering": "no",  # Desabilitar nginx buffering
            }
        )
    else:
        # Non-streaming: collecting all tokens
        full_text = ""
        token_count = 0
        async for event in streamer.stream_generate(current_prompt, history):
            if event["event"] == "token":
                full_text += json.loads(event["data"])["content"]
                token_count += 1
            elif event["event"] == "done":
                break
        
        return {
            "choices": [{
                "message": {"role": "assistant", "content": full_text},
                "usage": {"total_tokens": token_count}
            }]
        }


@app.get("/health")
async def health_check():
    """Health check endpoint para Kubernetes probes."""
    return {
        "status": "healthy" if model else "loading",
        "model": stream_config.model_name
    }


if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)

⚠️ Errores Comunes con Streaming

Error 1: Buffering en el lado del servidor

El problema: Nginx y otros proxies por defecto hacen buffering de respuestas SSE. Esto destruye el streaming en tiempo real — los tokens se agrupan y el usuario ve ráfagas en lugar de flujo continuo. El 80% de las deployments con problemas de streaming tienen este problema.

Fix: Añadir headers X-Accel-Buffering: no para nginx, y configurar proxy_buffering off; en la ubicación del proxy_pass.

Error 2: No manejar errores durante el stream

El problema: Si ocurre un error a mitad del stream (ej: OOM en el modelo), el cliente queda colgado esperando datos que nunca llegan. Sin evento de error, el frontend no sabe qué pasó.

Fix:: Siempre enviar evento error cuando algo falla, y en el cliente implementar timeout con retry exponencial.

Error 3: Falta deflush() inmediato

El problema: Python por defecto hace buffering en stdout y en el response. Cada yield no se envía inmediatamente — se acumula en un buffer. Esto causa latencia artificial.

Fix: Usar asyncio.sleep(0) después de cada yield para ceder control al event loop y forzar el flush. En FastAPI con StreamingResponse esto se maneja correctamente si se usa un generator async.

Error 4: No cerrar threads en generación

El problema: Si el cliente desconecta (cliente mobile, red inestable), el thread de generación sigue corriendo y consumiendo GPU. En producción con muchos usuarios, esto causa OOM.

Fix: Detectar disconnection con request.is_disconnected() y cancelar la generación. En la implementación de arriba, el thread se une al final; en producción más sofisticada se usaría asyncio cancellation.

✅ Resumen y Cierre

  • SSE es el protocolo estándar para streaming unidireccional sobre HTTP.
  • El formato es event: tipo\ndata: json\n\n con doble newline.
  • Headers críticos: X-Accel-Buffering: no, Cache-Control: no-cache.
  • Manejo de errores: Siempre enviar evento error cuando algo falla.
  • Cliente: Debe manejar reconnection automática con backoff exponencial.

Hágale que el streaming no es solo "ir mostrando tokens". Es manejar edge cases de red, errores parciales, y desconexiones. Pero cuando está bien hecho, la diferencia en perceived performance es brutal. Parcero, de una.
