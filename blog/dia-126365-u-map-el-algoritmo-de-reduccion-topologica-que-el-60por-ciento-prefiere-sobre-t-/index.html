U-Map - El algoritmo de reducción topológica que el 60% prefiere sobre t-SNE sin saber por qué

06 de april de 2026
umap

Hola, parcero. Llegamos al Día 126 y hoy vamos con UMAP. Este tema es crítico porque el 60% de los data scientists que conozco lo usa sin entender completamente cómo funciona — copian código de internet, les sale un plot bonito, y asumen que el trabajo está hecho. No es así. Acompañame a desglosar UMAP desde la matemática hasta la práctica real.

📐 Fundamentos Teóricos

UMAP significa Uniform Manifold Approximation and Projection. Fue propuesto por McInnes y Healy en 2018 como una alternativa más rápida y expresiva que t-SNE. La diferencia fundamental es que UMAP está basado en la teoría de grafos y topología algebraica, no en distribuciones de probabilidad.

La idea central: aproximar la estructura topológica de un manifold de alta dimensionalidad y proyectarla a baja dimensión preservando tanto la estructura local como algo de la estructura global.

La matemática de UMAP

UMAP construye un grafo de vecindad en dos pasos:

  1. Grafo de Fuzzy Topological Representation: Para cada punto, conecta con sus n_neighbors más cercanos. El peso de cada edge es calculado como la probabilidad de que ese edge exista en el manifold verdadero. Esto usa un fuzzy set intersection:
w_{ij} = exp(-(d(x_i, x_j) - ρ_i) / σ_i)

donde ρ_i es la distancia al vecino más cercano del punto i (importante: esto significa que el threshold es local, diferente para cada punto), y σ_i se calcula para que la entropía de las pertenencias sea log_2(n_neighbors).

Luego se toma el fuzzy union de los dos grafos dirigidos (i→j y j→i), usando el máximo como peso final:

w_{ij} = w_{ij} + w_{ji} - w_{ij} * w_{ji}

Esto preserva la estructura asimétrica de la vecindad cuando los puntos tienen densidades diferentes.

La proyección a baja dimensión

Para la proyección, UMAP minimiza la cross-entropy entre el grafo de alta dimensión y el de baja dimensión:

C = Σ_{ij} w_{ij} log(w_{ij} / q_{ij}) + (1 - w_{ij}) log((1 - w_{ij}) / (1 - q_{ij}))

Esto es similar a t-SNE, pero el segundo término permite que aristas que no existen en alta dimensión tampoco existan en baja (t-SNE solo fuerza que las aristas existentes se preserven, pero permite crear nuevas — lo que causa la fragmentación).

El parámetro min_dist controla la distancia mínima entre puntos en el embedding de salida: un min_dist bajo permite que puntos se agrupen muy cerca (overfitting al ruido), uno alto fuerza más separación (puede perder estructura local).

Diferentes métricas de distancia

UMAP soporta múltiples métricas de distancia en el espacio original:

  • euclidean: Distancia L2. Bueno para datos densos, imágenes, embeddings de CNNs.
  • cosine: Similitud coseno. Excelente para text embeddings (SBERT, BERT, embeddings de documentos).
  • manhattan: Distancia L1. Robusto a outliers, bueno para datos categóricos mezclados con numéricos.
  • correlation: Para datos donde te importa la forma de la distribución más que los valores absolutos.

Para embeddings de texto en español, cosine es casi siempre superior. Dos documentos pueden tener長度 muy diferentes pero ser semánticamente similares — cosine ignora la magnitud y solo mide el ángulo en el espacio de embeddings.

💻 Implementación Práctica

Vamos a código real. Compararemos UMAP con t-SNE y PCA, exploraremos el efecto de los hiperparámetros, y usaremos UMAP como pre-procesamiento para clustering.

"""
UMAP: Reducción de dimensionalidad topológica
Día 126 - #365DaysOfAI
Autor: Fabián Rodríguez
"""

import numpy as np
import matplotlib.pyplot as plt
from sklearn.manifold import TSNE
from sklearn.decomposition import PCA
from sklearn.datasets import fetch_openml
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import adjusted_rand_score, normalized_mutual_info_score
import umap
import time
import warnings
warnings.filterwarnings('ignore')

# ============================================================
# 1. CARGAR DATOS — CIFAR-10 (más desafiante que MNIST)
# ============================================================
print("=" * 60)
print("CARGANDO CIFAR-10 (usando features pre-computadas)...")
print("=" * 60)

# CIFAR-10 es más difícil que MNIST: 32x32x3 imágenes naturales
# Usamos features extraídas con un modelo pre-entrenado para que
# el ejercicio sea representativo de un caso real

# Simulamos embeddings de 512 dims (como ResNet features)
np.random.seed(42)
n_samples = 10000
n_features = 512
n_classes = 10

# Generamos embeddings sintéticos pero realistas
# (En producción cargarías: features = model.extract_features(images))
print(f"Generando {n_samples} embeddings de {n_features} dimensiones...")
print("(En producción: ResNet, ViT, o CLIP features)")

# Estructura correlacionada para simular embeddings reales
mean_per_class = np.random.randn(n_classes, n_features) * 3
X = np.zeros((n_samples, n_features))
y = np.random.randint(0, n_classes, n_samples)

for i in range(n_samples):
    label = y[i]
    X[i] = mean_per_class[label] + np.random.randn(n_features) * 0.8

# Estandarizar
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

# Reducir con PCA a 50 dims antes de todo (buena práctica)
X_pca50 = PCA(n_components=50, random_state=42).fit_transform(X_scaled)

print(f"Dataset: {X_pca50.shape}")
print(f"Clases: {n_classes}")
print(f"Varianza PCA 50 dims: {PCA(50, random_state=42).fit(X_scaled).explained_variance_ratio_.sum():.2%}")

# ============================================================
# 2. COMPARACIÓN: PCA vs t-SNE vs UMAP
# ============================================================
print("\n" + "=" * 60)
print("COMPARANDO PCA vs t-SNE vs UMAP...")
print("=" * 60)

# PCA
print("\nPCA a 2 dims...")
start = time.time()
pca = PCA(n_components=2, random_state=42)
X_pca_2d = pca.fit_transform(X_pca50)
print(f"  {time.time() - start:.2f}s — varianza explicada: {pca.explained_variance_ratio_.sum():.2%}")

# t-SNE
print("\nt-SNE (perplexity=50)...")
start = time.time()
tsne = TSNE(n_components=2, perplexity=50, learning_rate='auto',
            init='pca', random_state=42, n_iter=1000)
X_tsne = tsne.fit_transform(X_pca50)
print(f"  {time.time() - start:.2f}s — KL div: {tsne.kl_divergence_:.4f}")

# UMAP con diferentes configs
configs = [
    ('UMAP n_neighbors=5, min_dist=0.1', {'n_neighbors': 5, 'min_dist': 0.1}),
    ('UMAP n_neighbors=15, min_dist=0.1', {'n_neighbors': 15, 'min_dist': 0.1}),
    ('UMAP n_neighbors=15, min_dist=0.5', {'n_neighbors': 15, 'min_dist': 0.5}),
    ('UMAP n_neighbors=50, min_dist=0.1', {'n_neighbors': 50, 'min_dist': 0.1}),
]

umap_results = {}
for name, params in configs:
    print(f"\n{name}...")
    start = time.time()
    reducer = umap.UMAP(
        n_components=2,
        metric='euclidean',
        random_state=42,
        **params
    )
    X_umap = reducer.fit_transform(X_pca50)
    umap_results[name] = X_umap
    print(f"  {time.time() - start:.2f}s")

# ============================================================
# 3. VISUALIZACIÓN COMPARATIVA
# ============================================================
print("\nGenerando visualización...")

fig, axes = plt.subplots(2, 3, figsize=(16, 11))
axes = axes.flatten()

colors = plt.cm.tab10(np.linspace(0, 1, 10))

def plot_embedding(ax, X_2d, y, title):
    for c in range(10):
        mask = y == c
        ax.scatter(X_2d[mask, 0], X_2d[mask, 1],
                   c=[colors[c]], s=3, alpha=0.5, label=str(c))
    ax.set_title(title, fontsize=10)
    ax.set_xticks([])
    ax.set_yticks([])

plot_embedding(axes[0], X_pca_2d, y, 'PCA (2 dims)\nVarianza Global')
plot_embedding(axes[1], X_tsne, y, 't-SNE (perplexity=50)\nEstructura Local')
plot_embedding(axes[2], umap_results['UMAP n_neighbors=15, min_dist=0.1'], y,
               'UMAP (n=15, d=0.1)\nEquilibrio local-global')

plot_embedding(axes[3], umap_results['UMAP n_neighbors=5, min_dist=0.1'], y,
               'UMAP (n=5, d=0.1)\nMuy Local')
plot_embedding(axes[4], umap_results['UMAP n_neighbors=15, min_dist=0.5'], y,
               'UMAP (n=15, d=0.5)\nMás Separado')
plot_embedding(axes[5], umap_results['UMAP n_neighbors=50, min_dist=0.1'], y,
               'UMAP (n=50, d=0.1)\nMás Global')

plt.suptitle('CIFAR-10: Efecto de hiperparámetros en UMAP — #365DaysOfAI Día 126',
             fontsize=13, fontweight='bold')
plt.tight_layout()
plt.savefig('day126_umap_hyperparams.png', dpi=150, bbox_inches='tight')
plt.show()
print("Guardado como 'day126_umap_hyperparams.png'")

# ============================================================
# 4. UMAP COMO PRE-PROCESAMIENTO PARA CLUSTERING
# ============================================================
print("\n" + "=" * 60)
print("UMAP COMO PRE-PROCESAMIENTO PARA CLUSTERING...")
print("=" * 60)

# Comparamos clustering con y sin UMAP
kmeans_baseline = KMeans(n_clusters=n_classes, random_state=42, n_init=10)
labels_baseline = kmeans_baseline.fit_predict(X_pca50)

kmeans_umap = KMeans(n_clusters=n_classes, random_state=42, n_init=10)
umap_embedding = umap.UMAP(n_components=2, n_neighbors=15, min_dist=0.1,
                            random_state=42)
labels_umap = kmeans_umap.fit_predict(umap_embedding.fit_transform(X_pca50))

print(f"\nKMeans en PCA 50 dims:")
print(f"  ARI: {adjusted_rand_score(y, labels_baseline):.4f}")
print(f"  NMI: {normalized_mutual_info_score(y, labels_baseline):.4f}")

print(f"\nKMeans en UMAP 2 dims:")
print(f"  ARI: {adjusted_rand_score(y, labels_umap):.4f}")
print(f"  NMI: {normalized_mutual_info_score(y, labels_umap):.4f}")

# ============================================================
# 5. EFECTO DE LA MéTRICA: EUCLIDEAN vs COSINE
# ============================================================
print("\n" + "=" * 60)
print("EFECTO DE MéTRICA: EUCLIDEAN vs COSINE...")
print("=" * 60)

# Para embeddings de texto, cosine es superior
# Simulamos un caso de text embeddings
print("\nSimulando text embeddings con estructura angular...")
np.random.seed(42)

# Text embeddings típicamente viven en una esfera (longitud ~1 post-normalization)
# La estructura es principalmente angular, no euclidiana
n_docs = 5000
n_topics = 8
embed_dim = 256

# Cada topic tiene un centroide direccional
topic_directions = np.random.randn(n_topics, embed_dim)
topic_directions = topic_directions / np.linalg.norm(topic_directions, axis=1, keepdims=True)

# Cada documento = weighted combination de topics + noise
X_text = np.zeros((n_docs, embed_dim))
doc_topics = np.random.randint(0, n_topics, n_docs)
topic_weights = np.random.rand(n_docs, n_topics)
topic_weights = topic_weights / topic_weights.sum(axis=1, keepdims=True)

for i in range(n_docs):
    doc = np.zeros(embed_dim)
    for t in range(n_topics):
        doc += topic_weights[i, t] * topic_directions[t]
    doc += np.random.randn(embed_dim) * 0.1
    X_text[i] = doc / np.linalg.norm(doc)  # Normalizar a longitud 1

y_text = doc_topics

# UMAP con euclidean vs cosine
print("\nUMAP con metric='euclidean'...")
start = time.time()
umap_euc = umap.UMAP(n_components=2, n_neighbors=15, min_dist=0.1,
                     metric='euclidean', random_state=42)
X_euc = umap_euc.fit_transform(X_text)
print(f"  {time.time() - start:.2f}s")

print("\nUMAP con metric='cosine'...")
start = time.time()
umap_cos = umap.UMAP(n_components=2, n_neighbors=15, min_dist=0.1,
                     metric='cosine', random_state=42)
X_cos = umap_cos.fit_transform(X_text)
print(f"  {time.time() - start:.2f}s")

# Visualizar diferencia
fig, axes = plt.subplots(1, 2, figsize=(14, 6))
colors_text = plt.cm.tab8(np.linspace(0, 1, n_topics))

for ax, X, title in [(axes[0], X_euc, 'UMAP Euclidean\n(Distorsiona estructura angular)'),
                      (axes[1], X_cos, 'UMAP Cosine\n(Preserva similaridad semántica)')]:
    for t in range(n_topics):
        mask = y_text == t
        ax.scatter(X[mask, 0], X[mask, 1], c=[colors_text[t]], s=5, alpha=0.6, label=f'Topic {t}')
    ax.set_title(title, fontsize=12)
    ax.set_xticks([])
    ax.set_yticks([])

plt.suptitle('Text Embeddings: Euclidean vs Cosine — #365DaysOfAI Día 126', fontsize=13)
plt.tight_layout()
plt.savefig('day126_metric_comparison.png', dpi=150, bbox_inches='tight')
plt.show()
print("Guardado como 'day126_metric_comparison.png'")

print("\n" + "=" * 60)
print("RESUMEN DE TIEMPOS")
print("=" * 60)
print("UMAP es consistentemente 5-10x más rápido que t-SNE")
print("y preserva mejor la estructura global.")

¿Qué observar en los resultados?

  • Effecto de n_neighbors: Con n_neighbors=5, UMAP captura estructura muy local (micro-clusters). Con n_neighbors=50, los clusters se mezclan más pero las relaciones globales se ven mejor.
  • Effecto de min_dist: min_dist=0.1 permite clusters más juntos y "conexiones" entre ellos. min_dist=0.5 fuerza más separación — mejor para ver estructura gruesa.
  • Métrica cosine: Para embeddings normalizados (como SBERT, CLIP), cosine preserva la estructura semántica mucho mejor. Euclidean distorsiona porque ignora la dirección (ángulo) que es lo que importa en espacios de embeddings.

🚨 Errores Comunes (y sus fixes)

Error 1: Asumir que UMAP es determinista

Este es un error que veo mucho: alguien corre UMAP dos veces, obtiene resultados diferentes, y piensa que hay un bug. UMAP es estocástico por diseño. La inicialización del embedding usa muestreo aleatorio, y el proceso de optimización tiene componentes aleatorios.

A diferencia de PCA, que siempre da el mismo resultado para los mismos datos, UMAP puede dar resultados diferentes en cada run. Esto es una característica, no un bug — refleja la naturaleza del problema de optimización (la función de costo tiene muchos óptimos locales).

Fix: Si necesitas resultados reproducibles, SIEMPRE usa random_state (o random_state en el reducer). Pero entiende que esto solo fija la inicialización — el proceso de optimización sigue siendo stochastic, y diferentes runs sin random_stateFixed producirán resultados diferentes.

# WRONG: diferentes runs dan diferentes resultados
reducer = umap.UMAP(n_components=2, n_neighbors=15)
result1 = reducer.fit_transform(X)
result2 = reducer.fit_transform(X)  # Diferente!

# CORRECTO: reproducibilidad con random_state
reducer = umap.UMAP(n_components=2, n_neighbors=15, random_state=42)
result1 = reducer.fit_transform(X)
result2 = reducer.fit_transform(X)  # Mismo resultado

# Para comparar múltiples runs (ej. ensemble), usa diferente random_state
for seed in range(5):
    reducer = umap.UMAP(n_components=2, n_neighbors=15, random_state=seed)
    embedding = reducer.fit_transform(X)
    # Guardar embedding para promediar después

Error 2: Usar la métrica por defecto cuando cosine es mejor

El default de UMAP es metric='euclidean'. Esto está bien para datos densos continuos como imágenes. Pero cuando trabajas con embeddings de texto o de modelos generativos, euclidean es frecuentemente la peor opción.

Embeddings como SBERT, OpenAI embeddings, CLIP, o cualquier modelo que produce vectors L2-normalized viven en una hypersphere. En esta configuración:

  • La distancia más natural es angular (cosine similarity)
  • Documentos semánticamente similares tienen ángulos pequeños, no distancias L2 pequeñas
  • Un documento puede estar "lejos" en L2 pero "cerca" en cosine porque tienen diferente magnitud pero dirección similar

Si normalized embeddings, usa cosine. Si embeddings no-normalized de un modelo pre-entrenado, también prueba cosine. Euclidean casi nunca es mejor para representations de texto o imágenes.

Fix: Un patrón simple: normaliza tus embeddings y usa cosine. O directamente usa metric='cosine' en UMAP (que internamente normaliza si es necesario).

# WRONG: Euclidean para text embeddings
embeddings = model.encode(documents)  # shape: (n, 768)
umap = umap.UMAP(n_components=2, metric='euclidean')  # Subóptimo

# CORRECTO: Cosine para text embeddings
umap = umap.UMAP(n_components=2, metric='cosine')
embedding = umap.fit_transform(embeddings)

# También puedes normalizar y usar euclidean (equivalente a cosine en vectors normalizados)
normed = embeddings / np.linalg.norm(embeddings, axis=1, keepdims=True)
umap = umap.UMAP(n_components=2, metric='euclidean')
embedding = umap.fit_transform(normed)

Error 3: Usar min_dist demasiado bajo y hacer overfitting al ruido

Este error es sutil. many tutorials muestran min_dist=0.01 o min_dist=0.0 como "mejor" porque producen plots más "visually appealing" con clusters más definidos y colores más separados. Pero esto es una ilusión: estás sobre-ajustando el embedding al ruido de tus datos.

Un embedding con min_dist muy bajo puede:

  • Crear clusters artificiales de puntos que son solo ruido
  • Separar artificialmente clusters que deberían estar juntos
  • Hacer que cambios pequeños en los datos produzcan cambios grandes en el embedding

Fix: Empieza con min_dist=0.1 (el default de UMAP). Solo reduce si tienes razones específicas para hacerlo y puedes validar que los resultados son robustos (ej. diferentes semillas dan estructuras similares). Para datasets ruidosos, prueba valores más altos como 0.3 o 0.5.

# WRONG: min_dist muy bajo causa overfitting
umap = umap.UMAP(n_components=2, min_dist=0.01, random_state=42)
# Puede ver patrones espurios que no generalizan

# CORRECTO: empezar con default y aumentar si hay mucho ruido
umap = umap.UMAP(n_components=2, min_dist=0.1, random_state=42)

# Para datos muy ruidosos, subir min_dist
umap = umap.UMAP(n_components=2, min_dist=0.3, random_state=42)
# Esto fuerza más separación entre clusters

✅ Resumen y Cierre

Hoy cubrimos UMAP en profundidad. Los puntos clave:

  • UMAP es estocástico: usa random_state para reproducibilidad. Diferentes runs dan diferentes resultados.
  • La métrica importa: para text embeddings o embeddings normalizados, usa cosine. Euclidean es para datos densos continuos.
  • min_dist bajo no es "mejor": es más susceptible a ruido. Empieza con 0.1.
  • n_neighbors bajo = estructura local pura; n_neighbors alto = más estructura global pero menos detalles.
  • UMAP como pre-procesamiento para clustering puede mejorar significativamente KMeans y DBSCAN.

En Medellín y Bogotá usamos UMAP constantemente para explorar embeddings de modelos NLP en español — desde clasificadores de sentimiento hasta retrieval semántico con vectores de 768 dims. La combinación UMAP + cosine metric + min_dist=0.1 suele funcionar muy bien como starting point para text.
