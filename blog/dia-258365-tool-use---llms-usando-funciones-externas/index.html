RAG Optimization Avanzado

Hagale pues, parcero. Día 258 y hoy vamos a lo que el 75% no sabe: RAG Optimization Avanzado. Query expansion, HyDE, reranking y self-RAG. Esto es lo que separa un RAG básico de uno que mejora los resultados 5x. Deje que le cuente.

🎯 Por Qué el RAG Básico Falla

El RAG básico tiene un problema fundamental: el vocabulary mismatch. Tu query dice "equipo médico" pero el documento dice "instrumental hospitalario". El embedding del documento nunca se recuperará porque vive en una región diferente del espacio vectorial. La solución no es buscar más documentos — es buscar mejor.

📐 HyDE: Hypothetical Document Embeddings

HyDE resuelve el vocabulary mismatch de forma elegante: en lugar de buscar con tu query original, le pides al LLM que genere un documento hipotético que responda la pregunta, y buscas con ese documento generado:

from openai import OpenAI

client = OpenAI()

def hyde_search(query, collection, k=5):
    """
    HyDE: Genera documento hipotético y busca con él
    """
    # Paso 1: Generar documento hipotético
    hypothetical_prompt = f"""
    Escribe un documento breve y denso que responda la siguiente pregunta.
    El documento debe estar en español y ser factual.
    
    Pregunta: {query}
    
    Documento:"""
    
    response = client.chat.completions.create(
        model="gpt-4-turbo",
        messages=[{"role": "user", "content": hypothetical_prompt}],
        max_tokens=500,
        temperature=0.7
    )
    
    hypothetical_doc = response.choices[0].message.content
    
    # Paso 2: Buscar con el documento hipotético
    results = collection.query(
        query_texts=[hypothetical_doc],
        n_results=k
    )
    
    return {
        "hypothetical_doc": hypothetical_doc,
        "results": results
    }

# Uso
result = hyde_search(
    "¿Cómo funciona la fotosíntesis en plantas tropicales?",
    collection,
    k=5
)
print(f"Doc hipotético:\n{result['hypothetical_doc']}")

La matemática detrás de HyDE: El LLM tiene conocimiento latente que proyecta en lenguaje natural. Al generar un documento respondiendo la pregunta, captura la semántica de lo que busca en un embedding que coincide mejor con los documentos de tu base de conocimiento.

🚀 Query Expansion con Subqueries

Otra técnica poderosa: expandir una query en múltiples subqueries especializadas y luego fusionar resultados:

def query_expansion(query, collection, k=3):
    """
    Query expansion: divide y vencerás
    """
    # Generar subqueries
    expansion_prompt = f"""
    Divide la siguiente pregunta en 2-4 subpreguntas más específicas
    que juntos cubran todos los aspectos de la pregunta original.
    
    Pregunta: {query}
    
    Formato: Una subpregunta por línea, sin numeración.
    """
    
    response = client.chat.completions.create(
        model="gpt-4-turbo",
        messages=[{"role": "user", "content": expansion_prompt}],
        max_tokens=200
    )
    
    subqueries = [q.strip() for q in response.choices[0].message.content.split('\n') if q.strip()]
    subqueries.append(query)  # Incluir query original
    
    # Buscar con cada subquery
    all_results = []
    seen_ids = set()
    
    for sq in subqueries:
        results = collection.query(query_texts=[sq], n_results=k)
        for i, doc_id in enumerate(results['ids'][0]):
            if doc_id not in seen_ids:
                seen_ids.add(doc_id)
                all_results.append({
                    'id': doc_id,
                    'document': results['documents'][0][i],
                    'distance': results['distances'][0][i],
                    'subquery': sq
                })
    
    # Re-ordenar por score combinado
    all_results.sort(key=lambda x: x['distance'])
    return all_results[:k*2]

# Ejemplo
query = "¿Cuáles son los beneficios del café colombiano?"
results = query_expansion(query, collection)

🔄 Reranking con Cross-Encoder

Después de la búsqueda vectorial, el reranking mejora dramáticamente la relevancia usando un cross-encoder que evalúa query-document juntos:

from sentence_transformers import CrossEncoder

# Inicializar cross-encoder
cross_encoder = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')

def rerank_results(query, documents, top_n=10):
    """
    Rerank usando cross-encoder para mejor precisión
    """
    # Crear pares query-document para el cross-encoder
    pairs = [(query, doc) for doc in documents]
    
    # Obtener scores de relevancia
    scores = cross_encoder.predict(pairs)
    
    # Ordenar por score
    ranked_indices = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)
    
    return [
        {
            'document': documents[i],
            'original_rank': i,
            'rerank_score': scores[i],
            'rerank_position': rank + 1
        }
        for rank, i in enumerate(ranked_indices[:top_n])
    ]

def hybrid_search_with_rerank(query, collection, initial_k=20, final_k=5):
    """
    Búsqueda híbrida: vector + rerank
    """
    # 1. Búsqueda vectorial inicial (over-retrieve)
    vector_results = collection.query(
        query_texts=[query],
        n_results=initial_k
    )
    
    documents = vector_results['documents'][0]
    
    # 2. Reranking con cross-encoder
    reranked = rerank_results(query, documents, top_n=final_k)
    
    return reranked

# Uso
results = hybrid_search_with_rerank(
    "beneficios del café de altura colombiano",
    collection,
    initial_k=20,
    final_k=5
)
for r in results:
    print(f"[Rank {r['rerank_position']}] Score: {r['rerank_score']:.3f}")

🧠 Self-RAG: Auto-Evaluación

Self-RAG añade un paso de reflexión donde el LLM evalúa si los documentos recuperados son relevantes antes de generar la respuesta:

def self_rag_query(query, collection, llm_client):
    """
    Self-RAG: El LLM decide si la recuperación fue útil
    """
    # 1. Recuperar documentos
    retrieved = collection.query(query_texts=[query], n_results=5)
    documents = retrieved['documents'][0]
    
    # 2. Evaluación de cada documento
    evaluation_prompt = f"""
    Evalúa si cada documento es relevante para responder la pregunta.
    Para cada documento, responde en una línea con:
    [RELEVANT] si es directamente útil para responder
    [PARTIAL] si es tangencialmente relacionado
    [IRRELEVANT] si no ayuda a responder
    
    Pregunta: {query}
    
    Documento 1: {documents[0]}
    Evaluación:"""
    
    evaluations = []
    for i, doc in enumerate(documents):
        eval_response = llm_client.chat.completions.create(
            model="gpt-4-turbo",
            messages=[{
                "role": "user", 
                "content": evaluation_prompt.replace(f"Documento 1:", f"Documento {i+1}:")
            }],
            max_tokens=50
        )
        evaluations.append(eval_response.choices[0].message.content)
    
    # 3. Filtrar solo documentos relevantes
    relevant_docs = []
    for doc, eval_result in zip(documents, evaluations):
        if "[RELEVANT]" in eval_result or "[PARTIAL]" in eval_result:
            relevant_docs.append(doc)
    
    # 4. Generar respuesta solo con docs relevantes
    if not relevant_docs:
        return {
            "answer": "No encontré información relevante para responder tu pregunta.",
            "retrieval_success": False,
            "docs_used": []
        }
    
    context = "\n\n".join([f"Documento: {d}" for d in relevant_docs])
    
    answer_prompt = f"""
    Based ONLY on the provided documents, answer the question.
    If the documents don't contain enough information, say so.
    
    Documents:
    {context}
    
    Question: {query}
    
    Answer:"""
    
    answer_response = llm_client.chat.completions.create(
        model="gpt-4-turbo",
        messages=[{"role": "user", "content": answer_prompt}],
        max_tokens=500
    )
    
    return {
        "answer": answer_response.choices[0].message.content,
        "retrieval_success": True,
        "docs_used": relevant_docs,
        "evaluations": evaluations
    }

📊 Métricas de RAG

| Métrica | Qué Mide | Target | |---------|----------|--------| | Recall@K | Documentos relevantes recuperados | > 0.8 | | MRR | Posición del primer documento relevante | > 0.6 | | Rerank Improvement | Gain en relevance post-rerank | > 15% | | Context Precision | Relevancia del contexto usado | > 0.7 | | Answer Faithfulness | Qué tan fiel es la respuesta al contexto | > 0.9 |

⚠️ Los 3 Errores Más Comunes

Error 1: Basic RAG Sin Optimization en Vocabulary Mismatch

El problema: Tu query usa "vehículo eléctrico" pero los docs hablan de "automóvil battery-powered". El embedding space los separa y nunca recuperas nada relevante. Pones top_k=10 y todos son ruido.

La solución: Implementa HyDE o query expansion. La diferencia es dramática:

# El 70% hace esto y se pregunta por qué no funciona
results = collection.query(query_texts=["vehículo eléctrico"], n_results=10)
# → Recuperaste 2 docs relevantes de 10

# La solución: HyDE
results = hyde_search("vehículo eléctrico", collection, k=10)
# → Recuperaste 8 docs relevantes de 10
# El documento hipotético "carro que usa batería recargable" 
# coincide mejor con el embedding de los docs existentes

Error 2: No Usar Reranking, Degradando Relevance

El problema: La búsqueda vectorial optimiza para similitud semántica, no para relevancia específica a la query. El documento más similar semánticamente puede no ser el más útil para responder.

La matemática: La búsqueda vectorial maximiza $\cos(q, d)$ pero la relevancia real es $P(rel|q, d)$. Son distribuciones diferentes.

La solución: Reranking con cross-encoder que aprende $P(rel|q, d)$ directamente:

# Reranking típicamente mejora:
# - MRR: +15-30%
# - NDCG@10: +20-40%
# - Precision@5: +10-25%

# Sin reranking
base_results = collection.query(query_texts=[query], n_results=20)
# → MRR = 0.45

# Con reranking
reranked = hybrid_search_with_rerank(query, collection, initial_k=20, final_k=5)
# → MRR = 0.72 (59% mejora!)

Error 3: Too Much Context Que Overwhelms el LLM

El problema: Pones 20 documentos en el contexto esperando mejor coverage. El resultado: el LLM se pierde, genera respuestas genéricas, o empieza a contradecirse porque partes del contexto compiten.

La matemática: Cada LLM tiene una ventana de atención limitada. Más contexto no linealmente significa mejor respuestas. Hay un punto de dimishing returns:

$$P(\text{respuesta buena} | \text{contexto}) \propto \frac{1}{\text{longitud\_contexto}^{0.3}} \times \text{relevancia\_promedio}$$

La solución: Menos docs pero más relevantes, con reranking:

# NO hacer esto
all_docs = collection.query(query_texts=[query], n_results=20)
context = "\n\n".join(all_docs['documents'][0])  # 8000 tokens de ruido

# SÍ hacer esto
reranked = hybrid_search_with_rerank(query, collection, initial_k=20, final_k=5)
context = "\n\n".join([d['document'] for d in reranked])  # ~1500 tokens de precisión

# El sweet spot: 3-7 documentos rerankeados
# - Context window usado óptimamente
# - Alta relevancia promedio
# - LLM puede enfocarse en generar, no en filtrar

📝 Resumen

  • El vocabulary mismatch es el problema fundamental del RAG básico
  • HyDE genera documentos hipotéticos para mejorar la recuperación
  • Query expansion descompone preguntas complejas en subpreguntas
  • Reranking con cross-encoder mejora dramáticamente la relevancia
  • Self-RAG añade auto-evaluación de relevancia antes de generar
  • Menos contexto relevante > más contexto ruidoso
  • HyDE + Reranking pueden mejorar un RAG básico 5x o más
