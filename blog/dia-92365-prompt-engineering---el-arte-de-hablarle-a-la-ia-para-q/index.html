Prompt Engineering - El Arte de Hablarle a la IA para que Haga lo que Necesitas

18 de marzo de 2026

¿Qué es Prompt Engineering y Por Qué es tu Superpoder?

En Colombia tenemos un dicho: "Del dicho al hecho hay mucho trecho". Con los LLMs pasa igual — del modelo al output hay una distancia enorme que se llama prompt engineering. No es magia ni cheat code; es la disciplina de estructurar tu comunicación con el modelo para obtener exactamente lo que necesitas.

Un prompt no es solo "escribe un poema". Es el contexto completo: qué espera el modelo que hagas, cómo debe razonar, qué tono usar, qué evitar. Piénsalo como darle las instrucciones precisas a un practicante nuevo en tu empresa — mientras mejores las instrucciones, mejor el resultado.

Zero-Shot, Few-Shot y Chain-of-Thought: Los Tres Niveles

Zero-Shot: Sin Ejemplos, Solo Instrucciones

Zero-shot es lo más simple: le das al modelo una instrucción directa y esperas que la cumpla. "Clasifica esta reseña como positivo o negativo". El modelo usa su conocimiento pre-entrenado para responder.

messages = [
    {"role": "system", "content": "Eres un asistente que clasifica reseñas."},
    {"role": "user", "content": "Clasifica: 'El producto llegó dañado y el soporte no respondió'"},
]
# Output esperado: "Negativo"

Zero-shot funciona bien cuando:

  • La tarea es simple y el modelo tiene capacidad suficiente
  • No tienes ejemplos etiquetados
  • Quieres velocidad máxima

Few-Shot: Dale Ejemplos, Obtén Patrones

Few-shot es el siguiente nivel: le das al modelo 2-5 ejemplos de la tarea resuelta. Esto le permite inferir el patrón sin necesidad de fine-tuning. El modelo aprende de la estructura de los ejemplos más que del contenido específico.

messages = [
    {"role": "system", "content": "Clasifica cada reseña en positivo, negativo o neutral."},
    {"role": "user", "content": "Ejemplo 1: '¡Me encantó! Excelente calidad' → Positivo"},
    {"role": "user", "content": "Ejemplo 2: 'No recomiendo, se rompió en una semana' → Negativo"},
    {"role": "user", "content": "Ejemplo 3: 'El producto llegó a tiempo' → Neutral"},
    {"role": "user", "content": "Ahora clasifica: 'La batería dura poco pero el diseño es bonito'"},
]
# El modelo infiere que hay un elemento positivo y uno negativo → probablemente "Neutral" o clasifica mixto

Few-shot es poderoso porque:

  • Enseña formato sin fine-tuning
  • Reduce alucinaciones en tareas específicas
  • Permite que el modelo maneje casos edge via ejemplos

Chain-of-Thought: El Modelo que Razonaa

Chain-of-Thought (CoT) es la técnica que cambió el juego en 2022. En lugar de pedir la respuesta directa, le pides al modelo que muestre su razonamiento primero. Esto produce respuestas dramáticamente mejores en tareas de lógica, matemáticas y análisis multi-paso.

# Sin CoT — directo a la respuesta (propenso a errores)
messages = [
    {"role": "user", "content": "Si un tren sale de Bogotá a 80 km/h y otro de Medellín a 120 km/h, "
                               "y la distancia es 400km, ¿cuándo se encuentran?"},
]

# Con CoT — razonamiento paso a paso
messages = [
    {"role": "system", "content": "Resuelve problemas paso a paso, mostrando tu razonamiento."},
    {"role": "user", "content": "Si un tren sale de Bogotá a 80 km/h y otro de Medellín a 120 km/h, "
                               "y la distancia es 400km, ¿cuándo se encuentran?"},
]
# El modelo responde con:
# 1. Velocidad relativa = 80 + 120 = 200 km/h
# 2. Tiempo = distancia / velocidad = 400 / 200 = 2 horas
# 3. Se encuentran en 2 horas
💡 Descubrimiento clave: No cualquier razonamiento funciona. Estudios muestran que el CoT mejora drásticamente solo cuando el razonamiento se pide explícitamente ("razona paso a paso") y cuando el modelo es suficientemente grande (típicamente 70B+). Modelos pequeños tienden a seguir patrones de razonamiento incorrectos.

System, User, Assistant: La Arquitectura de Conversación

Los LLMs conversacionales operan con roles diferenciados:

  • System: Instrucciones globales — define el comportamiento, tono, límites. Es el más poderoso pero a veces ignorado.
  • User: Tus mensajes. Pueden ser preguntas, instrucciones, o feedback.
  • Assistant: Las respuestas del modelo. También se usa para few-shot ejemplos de comportamiento.
messages = [
    # System: quién es el modelo y cómo debe comportarse
    {
        "role": "system",
        "content": (
            "Eres un asistente técnico especializado en redes. "
            "Respondes de forma concisa, técnicas, sin jerga innecesaria. "
            "Siempre preguntás por el contexto antes de dar soluciones."
        )
    },
    # User: tu pregunta
    {
        "role": "user",
        "content": "Tengo un servidor que no responde en el puerto 443"
    },
    # Assistant: la respuesta del modelo (o ejemplo en few-shot)
    {
        "role": "assistant",
        "content": "¿Puedes confirmarme si el servicio está corriendo? "
                   "Ejecuta: systemctl status nginx"
    },
    # User: seguís la conversación
    {
        "role": "user",
        "content": "Sí, el servicio está activo y escuchando en el puerto"
    },
]

El rol system es subestimado. Pocos aprovechan que puedes:

  • Definir formato de salida (JSON, markdown, texto plano)
  • Establecer limitaciones (no dar consejos médicos, no generar código peligroso)
  • Dar contexto de dominio (actuar como experto en tu industria)
  • Definir personalidad y tono del modelo

ChatML Templates: El Formato que los Modelos Entienden

Cada modelo tiene su propio formato de conversación. ChatML es el formato de OpenAI (usado también por muchos otros), pero cada modelo puede variar. Usar el template correcto es crítico para que el modelo entienda la estructura de la conversación.

from transformers import AutoTokenizer

model_name = "meta-llama/Llama-3-8b-Instruct"

tokenizer = AutoTokenizer.from_pretrained(model_name)

# ChatML template de Llama 3
messages = [
    {"role": "system", "content": "Eres un asistente útil."},
    {"role": "user", "content": "¿Qué es Python?"},
]

# apply_chat_template convierte automáticamente al formato del modelo
# Llama 3 usa: <|begin_of_text|><|start_header_id|>system<|end_header_id|>\n\nprompt = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,  # Añade el header del assistant para generación
)

print(prompt)
# Output:
# <|begin_of_text|><|start_header_id|>system<|end_header_id|>
#
# Eres un asistente útil.<|eot_id|><|start_header_id|>user<|end_header_id|>
#
# ¿Qué es Python?<|eot_id|><|start_header_id|>assistant<|end_header_id|>
⚠️ Error común: hardcodear formatos como System: ...\nUser: ...\nAssistant: ... funciona a veces, pero es frágil. Cada modelo interpreta esto diferente. Usa siempre tokenizer.apply_chat_template() que garantiza el formato correcto.

Retrieval-Augmented Prompting: El Mejor de Dos Mundos

Retrieval-Augmented Generation (RAG) no es solo para fine-tuning. En el nivel de prompting, puedes hacer retrieval-augmented prompting: construir dinámicamente el contexto con información recuperada de documentos.

from typing import List, Dict
import numpy as np

def retrieval_augmented_prompt(
    query: str,
    documents: List[Dict[str, str]],
    top_k: int = 3,
) -> str:
    """
    Construye un prompt con contexto recuperado dinámicamente.
    
    Args:
        query: la pregunta del usuario
        documents: lista de dicts con 'text' y opcionalmente 'source'
        top_k: número de documentos a recuperar
    """
    # Simulación de retrieval — en producción usa embeddings + cosine similarity
    # Aquí usamos longitud como proxy para "relevancia" (demo)
    scored = []
    for doc in documents:
        # Score simple: qué tan largo es el documento (proxy de contenido)
        score = len(doc["text"])
        scored.append((score, doc))
    
    # Ordenar por score y tomar top_k
    top_docs = sorted(scored, reverse=True)[:top_k]
    
    # Construir contexto
    context_parts = []
    for i, (score, doc) in enumerate(top_docs, 1):
        context_parts.append(f"[Documento {i}]\n{doc['text']}")
    
    context = "\n\n".join(context_parts)
    
    # Prompt con contexto recuperado
    full_prompt = f"""Usa el siguiente contexto para responder la pregunta.
Si la respuesta no está en el contexto, indica que no tienes suficiente información.

--- CONTEXTO ---
{context}
--- FIN CONTEXTO ---

Pregunta: {query}
Respuesta:"""

    return full_prompt


# Ejemplo de uso
documents = [
    {"text": "Python es un lenguaje de programación de alto nivel creado por Guido van Rossum en 1991. "
             "Es conocido por su sintaxis legible y su filosofía de 'batteries included'."},
    {"text": "Colombia es el tercer país más grande de Sudamérica. Su capital es Bogotá. "
             "El país tiene costa tanto en el Caribe como en el Pacífico."},
    {"text": "Las redes neuronales transformer fueron introducidas en el paper 'Attention Is All You Need' "
             "de Google en 2017. Son la arquitectura base de los LLMs modernos."},
]

query = "¿Qué es Python y quién lo creó?"
full_prompt = retrieval_augmented_prompt(query, documents, top_k=2)

print(full_prompt)
# Output: prompt con los 2 documentos más relevantes (Python y Transformer)
# El de Colombia se descarta porque no es relevante para la pregunta

Este enfoque tiene ventajas sobre fine-tuning para conocimiento:

  • ✅ Siempre tienes información actualizada
  • ✅ Puedes citar fuentes específicas
  • ✅ No necesitas re-entrenar para actualizar conocimiento
  • ✅ Más controlable — el modelo solo usa el contexto dado

Pipeline Completo: Few-Shot + CoT + Chat Templates

"""
Prompt Engineering Pipeline — Día 92 #365DaysOfAI
Combina few-shot, chain-of-thought y chat templates en un pipeline production-ready
"""
from transformers import AutoModelForCausalLM, AutoTokenizer
from typing import List, Dict, Optional, Tuple
import torch


# ─── 1. FEW-SHOT EXAMPLE SELECTOR ─────────────────────────────────────────
def select_few_shot_examples(
    query: str,
    examples: List[Dict[str, str]],
    tokenizer: AutoTokenizer,
    max_tokens: int = 1500,
) -> List[Dict[str, str]]:
    """
    Selecciona los mejores ejemplos few-shot basado en similaridad de tokens.
    
   策略: Ordenar ejemplos por posición y truncar si excede max_tokens.
    En producción, usar embeddings y similaridad coseno para selección semántica.
    """
    selected = []
    total_tokens = 0
    
    # Prompt system no cuenta para el límite de ejemplos
    system_prompt = (
        "Eres un asistente que clasifica textos en categorías. "
        "Razona paso a paso antes de dar la respuesta final."
    )
    system_tokens = len(tokenizer.encode(system_prompt))
    max_tokens -= system_tokens
    
    # Simple: tomar ejemplos del inicio (los más estables)
    # Mejor aproximación: embedding similarity
    for ex in examples:
        # Calcular tokens del ejemplo
        ex_text = f"Texto: {ex['input']}\nCategoría: {ex['output']}"
        ex_tokens = len(tokenizer.encode(ex_text))
        
        if total_tokens + ex_tokens <= max_tokens:
            selected.append(ex)
            total_tokens += ex_tokens
        else:
            break  # No caben más ejemplos
    
    return selected


def build_cot_prompt(
    query: str,
    examples: List[Dict[str, str]],
    include_reasoning: bool = True,
) -> List[Dict[str, str]]:
    """
    Construye un prompt con few-shot + chain-of-thought.
    
    El formato CoT usa un separador para distinguir razonamiento de respuesta.
    """
    system_content = (
        "Eres un asistente que clasifica textos en categorías. "
        "Siempre razona paso a paso antes de dar la respuesta."
    )
    
    messages = [{"role": "system", "content": system_content}]
    
    # Few-shot examples con CoT
    for ex in examples:
        # User message con el ejemplo de entrada
        messages.append({
            "role": "user",
            "content": f"Clasifica el siguiente texto y explica tu razonamiento:\n\n{ex['input']}"
        })
        
        # Assistant message con razonamiento + respuesta
        reasoning = ex.get("reasoning", "")
        if not reasoning:
            # Generar razonamiento simple si no existe
            reasoning = f"El texto {'menciona' if 'positivo' in ex['output'] else 'contiene'} "
            reasoning += f"elementos {ex['output'].lower()}"
        
        messages.append({
            "role": "assistant",
            "content": f"Razonamiento: {reasoning}\n\nCategoría: {ex['output']}"
        })
    
    # Query final
    messages.append({
        "role": "user",
        "content": f"Clasifica el siguiente texto y explica tu razonamiento:\n\n{query}"
    })
    
    return messages


# ─── 2. GENERACIÓN CON TEMPERATURE Y TOP-P ────────────────────────────────
@torch.no_grad()
def generate_response(
    model: AutoModelForCausalLM,
    tokenizer: AutoTokenizer,
    messages: List[Dict[str, str]],
    max_new_tokens: int = 256,
    temperature: float = 0.7,
    top_p: float = 0.9,
    top_k: int = 50,
) -> str:
    """
    Genera respuesta usando chat template y sampling.
    
    Args:
        model: modelo causal (Llama, Mistral, etc.)
        tokenizer: tokenizer compatible con el modelo
        messages: mensajes en formato {role, content}
        max_new_tokens: máximo de tokens a generar
        temperature: controla aleatoriedad (0 = determinista, ~0.7 = balance, >1 = caótico)
        top_p: nucleus sampling — muestrea del top_p% de distribución de probabilidad
        top_k: limita a los top_k tokens más probables
    """
    # Aplicar chat template del modelo
    input_text = tokenizer.apply_chat_template(
        messages,
        tokenize=False,
        add_generation_prompt=True,
    )
    
    # Tokenizar
    input_ids = tokenizer(
        input_text,
        return_tensors="pt",
        padding=True,
    ).to(model.device)
    
    # Generación con sampling
    outputs = model.generate(
        **input_ids,
        max_new_tokens=max_new_tokens,
        temperature=temperature,
        top_p=top_p,
        top_k=top_k,
        do_sample=True,
        pad_token_id=tokenizer.pad_token_id,
        eos_token_id=tokenizer.eos_token_id,
        repetition_penalty=1.1,  # Penalizar repeticiones
    )
    
    # Decodificar solo la respuesta nueva (sin el prompt)
    response_ids = outputs[0][input_ids["input_ids"].size(1):]
    response = tokenizer.decode(response_ids, skip_special_tokens=True)
    
    return response


def extract_category(response: str) -> str:
    """
    Extrae la categoría de una respuesta CoT.
    Busca patrones como 'Categoría: X' o 'Respuesta: X'.
    """
    import re
    
    # Patrones comunes de extracción
    patterns = [
        r"Categoría:\s*(\w+)",
        r"Respuesta:\s*(\w+)",
        r"Categoría final:\s*(\w+)",
        r"^(\w+)$",  # Último token si todo falla
    ]
    
    for pattern in patterns:
        match = re.search(pattern, response, re.IGNORECASE | re.MULTILINE)
        if match:
            return match.group(1)
    
    return "unknown"


# ─── 3. PIPELINE COMPLETO ──────────────────────────────────────────────────
class PromptEngineeringPipeline:
    """
    Pipeline completo de prompt engineering.
    
    Combina:
    - Few-shot learning con selección de ejemplos
    - Chain-of-thought para razonamiento
    - Chat templates para formato correcto
    - Temperature y top-p para control de diversidad
    """
    
    def __init__(
        self,
        model_name: str = "meta-llama/Llama-3-8b-Instruct",
        device: str = "auto",
    ):
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModelForCausalLM.from_pretrained(
            model_name,
            torch_dtype=torch.bfloat16,
            device_map=device,
        )
        self.model.eval()
    
    def classify(
        self,
        query: str,
        examples: List[Dict[str, str]],
        categories: List[str],
        use_cot: bool = True,
        temperature: float = 0.5,
    ) -> Tuple[str, str]:
        """
        Clasifica un texto usando few-shot + optional CoT.
        
        Returns:
            Tupla de (categoría, razonamiento)
        """
        # Seleccionar ejemplos relevantes
        selected = select_few_shot_examples(query, examples, self.tokenizer)
        
        if use_cot:
            # Few-shot + CoT
            messages = build_cot_prompt(query, selected)
            response = generate_response(
                self.model,
                self.tokenizer,
                messages,
                temperature=temperature,
            )
        else:
            # Few-shot simple
            messages = [{"role": "system", "content": "Clasifica en una categoría."}]
            for ex in selected:
                messages.append({"role": "user", "content": ex["input"]})
                messages.append({"role": "assistant", "content": ex["output"]})
            messages.append({"role": "user", "content": query})
            response = generate_response(
                self.model,
                self.tokenizer,
                messages,
                temperature=temperature,
            )
        
        category = extract_category(response)
        
        # Validar que la categoría sea válida
        if category not in categories:
            category = categories[0]  # Default a la primera si no se reconoce
        
        return category, response

Errores Comunes y sus Soluciones

Error 1: Prompts demasiado vagos que producen respuestas genéricas

# ❌ MAL: prompt genérico
messages = [{"role": "user", "content": "Explica machine learning."}]

# ✅ BIEN: específico con formato y restricciones
messages = [
    {"role": "system", "content": (
        "Explica conceptos técnicos de ML a una audiencia de estudiantes de ingeniería. "
        "Usa analogías de la vida cotidiana en Colombia. "
        "Estructura: definición → ejemplo → limitación. "
        "Máximo 3 párrafos."
    )},
    {"role": "user", "content": "Explica qué es un transformer en ML."}
]

Error 2: Few-shot con ejemplos inconsistentesconfunde al modelo

# ❌ MAL: ejemplos con formatos contradictorios
examples = [
    {"input": "Texto positivo", "output": "Positivo"},  # mayúscula
    {"input": "Texto negativo", "output": "negativo"},  # minúscula
    {"input": "Otro positivo", "output": "+++positivo+++"},  # con símbolos
]

# ✅ BIEN: formato consistente en todos los ejemplos
examples = [
    {"input": "Texto positivo", "output": "positivo"},
    {"input": "Texto negativo", "output": "negativo"},
    {"input": "Otro positivo", "output": "positivo"},
]

Error 3: Pedir razonamiento a modelos muy pequeños = alucinaciones estructuradas

# ❌ MAL: CoT en modelo pequeño (1B-3B) puede empeorar resultados
# Modelos pequeños copian el formato de razonamiento sin capacidad real

# ✅ BIEN: CoT solo en modelos >= 7B, o usar zero-shot con modelo pequeño
# En modelos pequeños, mejor dar instrucciones directas:
messages = [
    {"role": "system", "content": (
        "Responde SOLO con la categoría: positivo, neutral o negativo. "
        "Sin explicaciones."
    )},
    {"role": "user", "content": "¿Es esto positivo o negativo? El café está bueno."}
]

Resumen: Hablarle Bien a la Máquina

Prompt engineering no es un arte vago — es una disciplina con técnicas concretas, estudiado formalmente y con resultados medibles. Zero-shot, few-shot y chain-of-thought no son estrategias intercambiables; cada una tiene su contexto óptimo:

  • Zero-shot: tareas simples, modelos grandes, cuando necesitas velocidad
  • Few-shot: necesitas formato específico o el modelo no entiende la tarea por contexto
  • Chain-of-thought: lógica, matemáticas, análisis multi-paso, modelos grandes

El system prompt es tu mayor palanca pero la más ignorada. Un buen system prompt define comportamiento, tono, formato y limitaciones — todo antes de que el usuario diga una palabra.

Y recuerda: en Colombia tenemos una riqueza lingüística increíble. Un modelo que responde en caldense, que entiende el humor paisa, que sabe que "es que eso es" significa algo diferente según el contexto — eso no se logra con prompting alone. Pero un buen prompt engineering es el primer paso para que la tecnología nos habla como gente, no como manuales de usuario.
