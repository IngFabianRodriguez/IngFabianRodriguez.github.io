La Matematica de Semantic Search

La busqueda semantica representa textos como vectores en un espacio de alta dimension donde documentos similares quedan cerca. La similaridad se mide con coseno:

similarity(a, b) = cos(theta) = (a . b) / (||a|| ||b||)

Para embeddings de dimension d=1536 (OpenAI text-embedding-3-small), el espacio tiene 2^1536 posibles vectores. La clave: embeddings capturan significado semantico, no solo palabras exactas.

La busqueda en este espacio es un problema de nearest neighbor aproximado (ANN). FAISS usa IVF-PQ (Inverted File Index + Product Quantization) para indexar millones de vectores en milisegundos.

El Framework de Semantic Search con FAISS

import numpy as np
from sentence_transformers import SentenceTransformer
import faiss

class SemanticSearchEngine:
    def __init__(self, model_name="all-MiniLM-L6-v2", dimension=384):
        self.model = SentenceTransformer(model_name)
        self.dimension = dimension
        self.index = None
        self.documents = []
        
    def build_index(self, documents, batch_size=32):
        """Construir indice FAISS con embeddings de documentos."""
        self.documents = documents
        
        # Generar embeddings por batches
        embeddings = self.model.encode(
            documents, 
            batch_size=batch_size,
            show_progress_bar=True
        )
        
        # Normalizar para similaridad coseno
        embeddings = embeddings / np.linalg.norm(embeddings, axis=1, keepdims=True)
        
        # Indice FAISS: IVF-PQ para ANN a escala
        nlist = min(100, len(documents) // 10)
        quantizer = faiss.IndexFlatIP(dimension)
        self.index = faiss.IndexIVFFlat(quantizer, dimension, nlist, faiss.METRIC_INNER_PRODUCT)
        self.index.train(embeddings.astype(np.float32))
        self.index.add(embeddings.astype(np.float32))
        self.index.nprobe = 10  # Numero de clusters a explorar
        
        return self
    
    def search(self, query, top_k=10):
        """Busqueda semantica pura."""
        query_embedding = self.model.encode([query])
        query_embedding = query_embedding / np.linalg.norm(query_embedding, axis=1, keepdims=True)
        
        distances, indices = self.index.search(
            query_embedding.astype(np.float32), 
            top_k
        )
        
        return [
            {"document": self.documents[idx], "score": float(dist)}
            for dist, idx in zip(distances[0], indices[0])
        ]

# Uso:
engine = SemanticSearchEngine()
engine.build_index(documents)
results = engine.search("consultas SQL con JOIN", top_k=5)

Hybrid Search: Combinando Lexical + Semantic

El error comun: usar solo busqueda semantica o solo BM25. La solucion: hybrid search con Reciprocal Rank Fusion (RRF).

from rank_bm25 import BM25Okapi
import numpy as np

class HybridSearchEngine:
    def __init__(self, semantic_engine: SemanticSearchEngine):
        self.semantic_engine = semantic_engine
        self.bm25 = None
        self.tokenized_docs = []
        
    def build_bm25_index(self, documents):
        """Construir indice BM25 para busqueda lexica."""
        self.tokenized_docs = [doc.lower().split() for doc in documents]
        self.bm25 = BM25Okapi(self.tokenized_docs)
        return self
    
    def search(self, query, top_k=20, alpha=0.5):
        """
        Busqueda hibrida con RRF.
        
        alpha: peso para busqueda semantica (0.5 = igual peso)
        RRF formula: 1 / (k + rank) donde k=60 y rank=posicion en lista
        """
        # Busqueda semantica
        semantic_results = self.semantic_engine.search(query, top_k=top_k * 2)
        
        # Busqueda lexica BM25
        tokenized_query = query.lower().split()
        bm25_scores = self.bm25.get_scores(tokenized_query)
        top_bm25_indices = np.argsort(bm25_scores)[::-1][:top_k * 2]
        lexical_results = [
            {"document": self.semantic_engine.documents[idx], "score": float(bm25_scores[idx])}
            for idx in top_bm25_indices
        ]
        
        # Reciprocal Rank Fusion
        fused_scores = {}
        k = 60  # Constante RRF
        
        for rank, result in enumerate(semantic_results):
            doc_id = result["document"]
            fused_scores[doc_id] = fused_scores.get(doc_id, 0) + alpha * (1 / (k + rank + 1))
            
        for rank, result in enumerate(lexical_results):
            doc_id = result["document"]
            fused_scores[doc_id] = fused_scores.get(doc_id, 0) + (1 - alpha) * (1 / (k + rank + 1))
        
        # Ordenar por score fusionado
        ranked = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        return [{"document": doc, "score": score} for doc, score in ranked[:top_k]]

# Uso:
hybrid = HybridSearchEngine(engine)
hybrid.build_bm25_index(documents)
results = hybrid.search("optimizacion queries PostgreSQL", top_k=10, alpha=0.6)

Reranking con Cross-Encoders

Despues del retrieval inicial, usamos cross-encoders para reranquear con mejor precision. El error del 70%: saltarse este paso.

from sentence_transformers import CrossEncoder

class Reranker:
    def __init__(self, model="cross-encoder/ms-marco-MiniLM-L-6-v2"):
        self.model = CrossEncoder(model)
    
    def rerank(self, query, documents, top_k=10):
        """
        Rerankea documentos usando cross-encoder.
        Cross-encoder: mas preciso pero mas lento que bi-encoder.
        """
        # Crear pares query-document para el cross-encoder
        pairs = [(query, doc) for doc in documents]
        
        # Obtener scores de relevancia
        scores = self.model.predict(pairs)
        
        # Ordenar por score
        doc_scores = sorted(
            zip(documents, scores),
            key=lambda x: x[1],
            reverse=True
        )
        
        return [
            {"document": doc, "score": float(score)}
            for doc, score in doc_scores[:top_k]
        ]

# Pipeline completo: retrieval + reranking
class SemanticSearchPipeline:
    def __init__(self):
        self.retriever = None
        self.reranker = Reranker()
    
    def search(self, query, initial_k=50, final_k=10):
        # 1. Retrieval hibrido
        candidates = self.retriever.search(query, top_k=initial_k)
        
        # 2. Extraer documentos
        docs = [c["document"] for c in candidates]
        
        # 3. Reranking con cross-encoder
        reranked = self.reranker.rerank(query, docs, top_k=final_k)
        
        return reranked

pipeline = SemanticSearchPipeline()
pipeline.retriever = hybrid
results = pipeline.search("patrones de diseno en microservices", initial_k=30, final_k=5)

Evaluando Search Quality: Recall@K y MRR

def evaluate_search(pipeline, queries, relevant_docs, k_values=[5, 10, 20, 50]):
    """
    Evaluar con Recall@K y Mean Reciprocal Rank (MRR).
    
    Recall@K: fraccion de documentos relevantes encontrados en top K
    MRR: 1/rank promedio donde r es el rank del primer resultado relevante
    """
    results = {"recall": {}, "mrr": {}}
    
    for k in k_values:
        recalls = []
        mrrs = []
        
        for query, relevant in zip(queries, relevant_docs):
            # Obtener resultados del pipeline
            search_results = pipeline.search(query, initial_k=k, final_k=k)
            retrieved = [r["document"] for r in search_results]
            
            # Recall@K
            relevant_set = set(relevant)
            retrieved_set = set(retrieved)
            recall = len(relevant_set & retrieved_set) / len(relevant_set)
            recalls.append(recall)
            
            # MRR
            for rank, doc in enumerate(retrieved, 1):
                if doc in relevant_set:
                    mrrs.append(1 / rank)
                    break
            else:
                mrrs.append(0)
        
        results["recall"][f"@{k}"] = np.mean(recalls)
        results["mrr"][f"@{k}"] = np.mean(mrrs)
    
    return results

# Ejemplo de evaluacion
queries = [
    "SQL JOIN performance optimization",
    "React useEffect cleanup",
    "Docker multi-stage builds"
]

relevant_docs = [
    ["doc1", "doc5", "doc12"],
    ["doc3", "doc7"],
    ["doc2", "doc9", "doc15"]
]

metrics = evaluate_search(pipeline, queries, relevant_docs)
print(f"Recall@10: {metrics['recall']['@10']:.3f}")
print(f"MRR@10: {metrics['mrr']['@10']:.3f}")

Los 3 Errores Comunes y Sus Arreglos

Error 1: Usar Solo Busqueda Lexica (BM25 Solo)

El problema: BM25 solo encuentra documentos con palabras exactas. "Terapia cognitiva" no encuentra "tratamiento psicologico para la mente".

La solucion: Hybrid search que combine BM25 + semantico con RRF.

# Wrong: solo BM25
results = bm25.search(query)

# Correct: hybrid search
results = hybrid.search(query, alpha=0.5)  # 50% semantico, 50% lexico

Error 2: No Usar Reranking

El problema: El retrieval inicial prioriza velocidad sobre precision. Un documento relevante puede quedar en posicion 15.

La solucion: Post-fetch reranking con cross-encoder para afinar el orden.

# Wrong: solo retrieval, sin reranking
results = hybrid.search(query, top_k=10)

# Correct: retrieval + reranking
results = pipeline.search(query, initial_k=50, final_k=10)

Error 3: No Evaluar Recall

El problema: Sin metricas, no sabes有多少 relevantes estas perdiendo. Un sistema puede tener 95% precision pero 30% recall.

La solucion: Evaluar siempre Recall@K y MRR con ground truth.

# Wrong: evaluar sin ground truth
print(f"Found {len(results)} results")

# Correct: evaluar con recall y MRR
metrics = evaluate_search(pipeline, queries, relevant_docs)
print(f"Recall@10: {metrics['recall']['@10']:.3f} — target: >0.8")

Resumen y Cierre Colombiano

Pues ahi lo tiene, parcero. Semantic search no es solo poner embeddings en FAISS. Es un pipeline completo:

  • Embeddings con bi-encoders para retrieval rapido
  • Hybrid search combinando BM25 + semantico con RRF
  • Reranking con cross-encoders para precision
  • Evaluacion con Recall@K y MRR

El 80% de los que implementan RAG solo usan busqueda lexica. Usted ya sabe como hacerlo bien. Practique en sus proyectos, mida siempre, y cuando el recall este bajo 0.7, anada reranking.
