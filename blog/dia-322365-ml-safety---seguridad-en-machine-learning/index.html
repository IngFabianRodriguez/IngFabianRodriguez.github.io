🎯 LLM Fairness y Bias: Lo Que El 85% No Considera

Qué tal parcero, hoy 18 de noviembre de 2026, Día 322. Ya ayer hablamos de privacy-preserving en LLMs, y hoy le metemos el otro lado de la moneda: fairness y bias. Porque acá nadie se salva — todos los modelos tienen sesgos de algún tipo. La pregunta no es si tienen bias, sino qué tan severe es y qué estamos haciendo al respecto. Eso es lo que hojeamos hoy.

⚖️ Por Qué Importa El Fairness En LLMs

Un LLM que genera texto con sesgos de género, racial o cultural no es solo problemático éticamente — puede causar damage real. Imaginen un sistema de contratación automatizada que rechaza candidatos por su nombre, o un modelo de crédito que niega préstamos basándose en la dirección de residencia. Eso no es ciencia ficción — eso passa todos los días con modelos en producción.

En Colombia específicamente, la Ley 1098 del Código de Infancia y Adolescencia y demás normas de igualdad exigen que los sistemas automatizados no discriminen. Así que si están deployando LLMs en productos que afectan decisiones a personas, tienen obligación legal de considerar fairness. No es solo buena práctica — es requirement legal.

📊 Tipos De Sesgo En LLMs

Antes de medir, hay que entender qué estamos midiendo. Los sesgos en LLMs vienen de muchas formas:

  • Historical Bias: El training data refleja sesgos históricos de la sociedad. Si en los datos los doctores son mayormente hombres, el modelo asocia "doctor" con género masculino.
  • Representation Bias: Algunos grupos están subrepresentados en el training data. Pocas mujeres en datasets de STEM, pocos hombres en datasets de enfermería.
  • Measurement Bias: Cómo se miden y labels los datos. Un label "successful" puede significar cosas diferentes según el contexto cultural.
  • Aggregation Bias: Un modelo que funciona bien promediando puede fallar para subgrupos específicos.
  • Deployment Bias: El modelo se usa de formas no previstas durante el entrenamiento.

📐 Métricas De Fairness

La matemática del fairness tiene varias métricas, y ninguna es perfecta. Siempe hay trade-offs. Las principales:

Demographic Parity: La proporción de predicciones positivas debe ser igual entre grupos.

P(Ŷ=1 | A=0) = P(Ŷ=1 | A=1)

donde A es el grupo protegido (ej: género).

Equalized Odds: Las tasas de verdadero positivo y falso positivo deben ser iguales entre grupos.

P(Ŷ=1 | A=0, Y=y) = P(Ŷ=1 | A=1, Y=y)

Calibration: Si el modelo dice 70% probabilidad, esa probabilidad debe ser correcta para todos los grupos.

import numpy as np
from sklearn.metrics import confusion_matrix

def demographic_parity_difference(y_true, y_pred, sensitive_attribute):
    """Calcula diferencia de paridad demográfica entre grupos"""
    group_0 = sensitive_attribute == 0
    group_1 = sensitive_attribute == 1
    
    rate_0 = y_pred[group_0].mean()
    rate_1 = y_pred[group_1].mean()
    
    return rate_1 - rate_0  # 0 es ideal

def equalized_odds_difference(y_true, y_pred, sensitive_attribute):
    """Calcula diferencia de equalized odds (TPR y FPR)"""
    group_0 = sensitive_attribute == 0
    group_1 = sensitive_attribute == 1
    
    # True Positive Rates
    tpr_0 = y_pred[(group_0) & (y_true == 1)].mean() if (group_0 & (y_true == 1)).any() else 0
    tpr_1 = y_pred[(group_1) & (y_true == 1)].mean() if (group_1 & (y_true == 1)).any() else 0
    
    # False Positive Rates
    fpr_0 = y_pred[(group_0) & (y_true == 0)].mean() if (group_0 & (y_true == 0)).any() else 0
    fpr_1 = y_pred[(group_1) & (y_true == 0)].mean() if (group_1 & (y_true == 0)).any() else 0
    
    tpr_diff = abs(tpr_1 - tpr_0)
    fpr_diff = abs(fpr_1 - fpr_0)
    
    return max(tpr_diff, fpr_diff)

def calibration_by_group(y_true, y_prob, sensitive_attribute, n_bins=10):
    """Evalúa calibración por grupo (ska-learn style)"""
    results = {}
    for group in np.unique(sensitive_attribute):
        mask = sensitive_attribute == group
        y_t = y_true[mask]
        y_p = y_prob[mask]
        
        bins = np.linspace(0, 1, n_bins + 1)
        bin_means = []
        bin_true = []
        
        for i in range(n_bins):
            bin_mask = (y_p >= bins[i]) & (y_p < bins[i+1])
            if bin_mask.any():
                bin_means.append(y_p[bin_mask].mean())
                bin_true.append(y_t[bin_mask].mean())
        
        results[f"group_{group}"] = {
            "predicted": bin_means,
            "actual": bin_true,
            "calibration_error": np.mean(np.abs(np.array(bin_means) - np.array(bin_true)))
        }
    
    return results

class BiasReport:
    """Genera reportes de sesgos detectados"""
    
    SEVERITY_THRESHOLDS = {
        "low": 0.1,
        "medium": 0.3,
        "high": 0.5
    }
    
    def __init__(self, evaluation_results):
        self.results = evaluation_results
    
    def classify_severity(self, bias_score):
        for severity, threshold in self.SEVERITY_THRESHOLDS.items():
            if bias_score < threshold:
                return severity
        return "critical"
    
    def generate_report(self):
        report = []
        for item in self.results:
            severity = self.classify_severity(item.get("bias_score", 0))
            report.append(f"{item['occupation']}: {severity}")
        return "\n".join(report)

🔧 Debiasing Techniques

Encontraste los sesgos. Ahora qué? Hay tres categorías principales de debiasing:

1. Data-Level Debiasing

Modificar el training data para balancear representación:

class DataDebiaser:
    """Técnicas de debiasing a nivel de datos"""
    
    def resample_undersample(self, dataset, sensitive_attr, target_col):

        balanced = groups.apply(lambda x: x.sample(min_group_size))

class CounterfactualDataAugmenter:
    """Augmentación counterfactual específica para NLP"""
    
    GENDER_SUBSTITUTIONS = {
        "hombre": "mujer", "mujer": "hombre",
        "él": "ella", "ella": "él",
        "rey": "reina", "reina": "rey",
        "sr": "sra", "sra": "sr",

    }
    
    def augment(self, texts):
        """Genera versiones counterfactual de textos"""
        augmented = []
        for text in texts:
            aug_texts = self._substitute_gender(text)
            augmented.extend(aug_texts)
        return augmented
    
    def _substitute_gender(self, text):
        """Sustituye términos de género en un texto"""
        results = []
        for male, female in self.GENDER_SUBSTITUTIONS.items():
            if male.lower() in text.lower():
                results.append(text.lower().replace(male.lower(), female))
        return results

2. Training-Level Debiasing

Modificar el proceso de entrenamiento con regularización adversarial o constraints de fairness:

class AdversarialDebiaser:
    """Debiasing mediante entrenamiento adversarial"""
    
    def __init__(self, main_model, adversary_model, lambda_fair=0.1):
        self.main_model = main_model
        self.adversary_model = adversary_model
        self.lambda_fair = lambda_fair  # Weight del término adversarial
    
    def train_step(self, batch, sensitive_attributes):
        """
        Paso de entrenamiento con debiasing adversarial.
        El modelo principal predice la tarea.
        El adversary predice el atributo protegido desde las representations.
        El main model intenta foolear al adversary.
        """
        # 1. Forward pass del modelo principal
        features = self.main_model.get_representation(batch)
        predictions = self.main_model.predict(batch)
        
        # 2. El adversary intenta predecir el atributo sensible
        adversary_pred = self.adversary_model(features)
        adversary_loss = self._adversary_loss(adversary_pred, sensitive_attributes)
        
        # 3. El main model quiere minimizar la capacidad del adversary
        # (maximizar la pérdida del adversary = remover información del atributo)
        main_loss = self._task_loss(predictions, batch['labels'])
        adversarial_penalty = -adversary_loss  # Neg because we want to maximize it
        
        # 4. Loss total: task loss + λ * adversarial penalty
        total_loss = main_loss + self.lambda_fair * adversarial_penalty
        
        # 5. Backprop
        self.main_model.backward(total_loss)
        
        return {
            "task_loss": main_loss.item(),
            "adversary_loss": adversary_loss.item(),
            "fairness_penalty": adversarial_penalty.item()
        }


class In-ProcessingFairness:
    """Debiasing durante el entrenamiento con constraints de fairness"""
    
    def __init__(self, model, fairness_constraint="demographic_parity"):
        self.model = model
        self.constraint = fairness_constraint
    
    def train_with_constraint(self, train_loader, val_loader, epochs=10):
        """Entrena con constraint de fairness"""
        for epoch in range(epochs):
            for batch in train_loader:
                # Loss regular de la tarea
                task_loss = self.model.compute_loss(batch)
                
                # Gradient descent en el espacio de hipótesis
                # para optimizar task loss subject a fairness constraint
                constrained_loss = self._apply_fairness_constraint(
                    task_loss, 
                    batch, 
                    self.constraint
                )
                
                self.model.optimizer.step(constrained_loss)
    
    def _apply_fairness_constraint(self, loss, batch, constraint):
        """Aplica constraint de fairness como regularización"""
        if constraint == "demographic_parity":
            # Añade penalty si las predicciones están correlacionadas
            # con el atributo protegido
            sensitive_attr = batch['sensitive_attribute']
            pred_corr = self._correlation(batch['predictions'], sensitive_attr)
            penalty = self.lambda_fair * torch.abs(pred_corr)
            return loss + penalty
        
        elif constraint == "equalized_odds":
            # Igualar TPR y FPR entre grupos
            tpr_diff, fpr_diff = self._compute_odds_differences(batch)
            penalty = self.lambda_fair * (tpr_diff + fpr_diff)
            return loss + penalty
        
        return loss

3. Output-Level Debiasing

Post-procesar las outputs del modelo para remover sesgos detectados:

class OutputDebiaser:
    """Técnicas de debiasing a nivel de output"""
    
    def calibration_around_threshold(self, probs, sensitive_attr, target_fairness=0.5):
        """Ajusta umbrales de decisión por grupo para igualar tasas"""
        adjusted_probs = probs.copy()
        
        groups = np.unique(sensitive_attr)
        thresholds = {}
        
        for group in groups:
            mask = sensitive_attr == group
            group_probs = probs[mask]
            
            # Encuentra threshold que iguala la tasa de positivos
            threshold = np.percentile(group_probs, (1 - target_fairness) * 100)
            thresholds[group] = threshold
        
        # Ajusta probabilidades según el threshold del grupo
        for group in groups:
            mask = sensitive_attr == group
            adjusted_probs[mask] = (probs[mask] >= thresholds[group]).astype(float)
        
        return adjusted_probs
    
    def context_aware_neutralization(self, text, demographic_terms):
        """Neutraliza términos demográficos en texto generado"""
        neutralized = text
        for term in demographic_terms:
            # Reemplaza con placeholder neutral
            neutralized = neutralized.replace(term, "[PERSONA]")
        return neutralized
    
    def beam_search_with_diversity(self, model, prompt, beam_width=5, lambda_diversity=0.1):
        """Beam search que penaliza generaciones con sesgos estereotípicos"""
        # Implementación simplificada de diverse beam search
        beams = [(prompt, 0.0, [])]  # (sequence, score, history)
        
        for step in range(50):  # Max length
            candidates = []
            for beam in beams:
                seq, score, history = beam
                next_tokens = model.get_top_k_tokens(seq, k=beam_width)
                
                for token, token_prob in next_tokens:
                    new_seq = seq + token
                    # Score base + penalty por estereotipos
                    diversity_bonus = self._stereotype_penalty(token, history)
                    new_score = score + np.log(token_prob) + lambda_diversity * diversity_bonus
                    candidates.append((new_seq, new_score, history + [token]))
            
            beams = sorted(candidates, key=lambda x: x[1], reverse=True)[:beam_width]
        
        return beams[0][0]  # Best beam
    
    def _stereotype_penalty(self, token, history):
        """Calcula penalty por reforzar estereotipos"""
        # Placeholder - en producción usar lexicon de estereotipos
        return np.random.random() if history else 0

⚠️ Error 1: No Considerar Bias En Primer Lugar

El error más básico y más común. Mucha gente asume que porque "no fueron intencionales con los sesgos", el modelo no los tiene. FALSO. Todo training data tiene sesgos implícitos de la sociedad que lo generó.

❌ Mal: Deployar un chatbot de atención al cliente sin haber testeado cómo responde a запросы de personas de diferentes géneros, edades, o regiones de Colombia.

Fix: Siempre hacer bias evaluation antes de deployment. Usar los frameworks que mostré arriba. Si no tienen recursos para un análisis completo, al menos hacer probe tests con occupation-gender stereotypes y ver cómo responde el modelo.

⚠️ Error 2: No Medir Fairness

Medir fairness no es opcional y no es "nice to have". Si están tomando decisiones automáticas que afectan personas, necesitan métricas de fairness documentadas.

❌ Mal: Usar accuracy general como única métrica de un modelo de clasificación de risk crediticio, sin disaggregated metrics por grupo demográfico.

Fix: Implementar métricas de fairness desde el inicio. Demographic parity, equalized odds, calibration by group. Si una de estas muestra disparidades grandes ( > 0.1 para diferencias, o > 5% para tasas), hay que actuar.

⚠️ Error 3: Debiasing Sin Entender Tipos De Bias

El debiasing no es magic. Aplicar counterfactual augmentation sin entender qué tipo de sesgo estás atacando puede empeorar las cosas o crear nuevos problemas.

❌ Mal: Hacer undersampling brute force sin considerar que talvez el issue no es representación sino cómo se miden los labels (measurement bias).

Fix: Antes de aplicar cualquier debiasing, hacer un bias audit completo para identificar el tipo de sesgo. Si el problema es measurement bias, necesitas re-etiquetar datos, no resampling. Si es historical bias, necesitas data augmentation + possibly adversarial training. Si es deployment bias, necesitas cambiar cómo se usa el modelo, no el modelo mismo.

# Framework completo de evaluación y mitigación de bias
class FairnessFramework:
    def __init__(self, model):
        self.model = model
        self.evaluator = LLMBiasEvaluator(model, None)
        self.bias_report = None
    
    def full_audit(self, test_data, sensitive_attributes):
        """Auditoría completa de fairness"""
        print("[AUDIT] Iniciando auditoría de sesgos...")
        
        # 1. Medir disparities en diferentes métricas
        metrics = {
            "demographic_parity": demographic_parity_difference(
                test_data['labels'], test_data['predictions'], sensitive_attributes
            ),
            "equalized_odds": equalized_odds_difference(
                test_data['labels'], test_data['predictions'], sensitive_attributes
            ),
        }
        
        print("\n[MÉTRICAS DE FAIRNESS]")
        for metric, value in metrics.items():
            status = "✓ OK" if abs(value) < 0.1 else "⚠ ALERTA"
            print(f"  {metric}: {value:.3f} {status}")
        
        # 2. Probe para estereotipos específicos
        print("\n[STEREOTYPE PROBE]")
        stereotype_results = self.evaluator.probe_stereotypes(
            [("hombre", "mujer")], 
            ["ingeniero", "enfermero", "doctor"]
        )
        for r in stereotype_results:
            print(f"  {r['occupation']}: sesgo hacia {r['bias_direction']}")
        
        self.bias_report = metrics
        return metrics
    
    def recommend_interventions(self):
        """Recomienda intervenciones basadas en el audit"""
        if not self.bias_report:
            print("Primero ejecutar full_audit()")
            return
        
        interventions = []
        
        if abs(self.bias_report['demographic_parity']) > 0.1:
            interventions.append({
                "type": "in-processing",
                "technique": "adversarial_debiasing",
                "priority": "high"
            })
        
        if abs(self.bias_report['equalized_odds']) > 0.1:
            interventions.append({
                "type": "post-processing",
                "technique": "threshold_calibration",
                "priority": "high"
            })
        
        return interventions

📊 Resumen y Cierre

Bueno Ahí Vamos parcero. Fairness y bias en LLMs no es un problema que se resuelva una vez — es un proceso continuo. Los tres errores principales:

  1. No considerar bias → Fix: bias evaluation es prerequisite para deployment
  2. No medir fairness → Fix: métricas quantitativas desde el inicio (demographic parity, equalized odds, calibration)
  3. Debiasing sin entender tipos de sesgo → Fix: hacer bias audit completo antes de elegir técnica de mitigación

La matemática — demographic parity, equalized odds, la teoría de constraints de fairness — les da un framework para pensar el problema de manera rigurosa. No es solo "ser buenos". Es medir, auditar, mitigar, y volver a medir.
