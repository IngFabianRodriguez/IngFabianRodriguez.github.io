🎯 ¿Qué es un AI Agent?

Qué tal, Colombia 🇮🇩 Hoy vamos a hablar de algo que está redefiniendo por completo cómo pensamos la inteligencia artificial: los AI Agents. Si los LLMs fueron la revolución del 2022-2023, los agents son la del 2024 en adelante. No es solo un chatbot que responde preguntas — es un sistema que puede actuar, usar herramientas, y completar tareas complejas de forma autónoma.

Un AI Agent es un sistema donde un modelo de lenguaje no solo genera texto, sino que:

  1. Razona sobre qué hacer con una pregunta compleja
  2. Elige y ejecuta acciones (llamar herramientas, buscar info, ejecutar código)
  3. Observa los resultados de esas acciones y los incorpora a su razonamiento
  4. Repite hasta completar la tarea o decidir que no puede

La diferencia con un chatbot tradicional es crucial: un chatbot recibe un input y produce un output. Un agent recibe un input, produce acciones, y el mundo real (o una simulación) le devuelve observaciones que alimentan el siguiente ciclo de razonamiento.

📐 ReAct: Reasoning + Acting

El patrón más influyente es ReAct (Reason + Act), propuesto por Yao et al. en 2022. La idea central es entrelazar el razonamiento explícito con las acciones externas en un loop:

  • Thought: El modelo razona sobre la situación actual y decide qué hacer
  • Action: Ejecuta una acción (llamar una función, buscar, calcular)
  • Observation: Recibe el resultado de la acción y lo incorpora a su estado mental
  • Repite hasta que decide que tiene suficiente para responder

Este ciclo es análogo a cómo nosotros resolvemos problemas: "veamos, si hago X debería pasar Y, pero no estoy seguro, mejor busco más info primero".

Código: ReAct Agent con Tool Calling

import json
import re
from dataclasses import dataclass, field
from typing import Callable

@dataclass
class Tool:
    """Definición de una herramienta que el agent puede usar.

    Attributes:
        name: Nombre único de la herramienta (ej: "search", "calculate")
        description: Descripción para el LLM de qué hace la herramienta
        function: Función Python que ejecuta la lógica real
        input_schema: Schema JSON que describe los parámetros esperados
    """
    name: str
    description: str
    function: Callable
    input_schema: dict

    def to_function_schema(self) -> dict:
        """Convierte la tool a schema para structured output del LLM."""
        return {
            "name": self.name,
            "description": self.description,
            "parameters": self.input_schema
        }


@dataclass
class Message:
    """Un mensaje en el conversation history del agent."""
    role: str  # "user", "assistant", "tool_result"
    content: str


@dataclass
class ConversationMemory:
    """Memory del agent con buffer + summary hybrid approach.

    El problema con un conversation buffer puro es que se vuelve enorme.
    El problema con summary puro es que pierdes detalle granular.
    Solution: mantener buffer para últimos N mensajes, resumir lo más antiguo.
    """
    buffer_size: int = 10
    messages: list = field(default_factory=list)

    def add(self, role: str, content: str):
        self.messages.append(Message(role=role, content=content))

    def get_context(self) -> str:
        """Retorna el contexto completo para mandar al LLM."""
        if len(self.messages) <= self.buffer_size:
            return self._format_messages(self.messages)

        # Mantener últimos N, resumir los más antiguos
        recent = self.messages[-self.buffer_size:]
        older = self.messages[:-self.buffer_size]
        summary = self._summarize(older)

        return f"[Resumen de conversación anterior]: {summary}\n\n" + \
               self._format_messages(recent)

    def _format_messages(self, messages: list) -> str:
        return "\n".join(f"{m.role}: {m.content}" for m in messages)

    def _summarize(self, older: list) -> str:
        """Resume mensajes antiguos. En producción usar otro LLM call."""
        if not older:
            return ""
        total = len(older)
        return f"({total} mensajes previos sobre: {older[0].content[:50]}...)"


class ReActAgent:
    """ReAct agent con tool calling y conversation memory.

    El loop principal:
    1. Recibir input del usuario
    2. Construir context con conversation memory
    3. Llamar al LLM con el prompt de ReAct + tools disponibles
    4. Parsear la respuesta: extraer thought/action/action_input
    5. Si hay action → ejecutar la tool, guardar resultado como observation
    6. Si no hay action → retornar la respuesta final
    7. Si iteraciones > max_iterations → parar (prevenir loops infinitos)
    """
    def __init__(
        self,
        llm_callable,  # Función que llama el LLM (ej: openai.ChatCompletion.create)
        tools: list[Tool],
        max_iterations: int = 10
    ):
        self.llm = llm_callable
        self.tools = {t.name: t for t in tools}
        self.max_iterations = max_iterations
        self.memory = ConversationMemory()

    def _build_system_prompt(self) -> str:
        """Construye el system prompt con las tools disponibles."""
        tool_schemas = [t.to_function_schema() for t in self.tools]
        tools_text = json.dumps(tool_schemas, indent=2, ensure_ascii=False)

        return f"""Eres un AI assistant con acceso a herramientas.

Cuando necesites información o necesites ejecutar acciones, usa el siguiente formato:

Thought: [tu razonamiento aquí]
Action: [nombre de la herramienta]
Action Input: [parámetros en JSON]

Después de cada acción recibirás una observación con el resultado.

Cuando hayas completado la tarea, responde con:

Final Answer: [tu respuesta final]

## Herramientas disponibles:
{tools_text}"""

    def _parse_llm_response(self, response: str) -> dict:
        """Parsea la respuesta del LLM para extraer thought/action/observation.

        Retorna dict con keys: has_action (bool), thought, action, action_input
        """
        result = {"has_action": False, "thought": "", "action": None, "action_input": None}

        # Buscar patrón Thought: ...
        thought_match = re.search(r"Thought:\s*(.+?)(?=\nAction:|$)", response, re.DOTALL)
        if thought_match:
            result["thought"] = thought_match.group(1).strip()

        # Buscar patrón Action: ...
        action_match = re.search(r"Action:\s*(\w+)", response)
        if action_match:
            result["has_action"] = True
            result["action"] = action_match.group(1).strip()

        # Buscar patrón Action Input: ...
        input_match = re.search(r"Action Input:\s*({.*?})\s*(?=\n|Final Answer:|$)", response, re.DOTALL)
        if input_match and result["has_action"]:
            try:
                result["action_input"] = json.loads(input_match.group(1))
            except json.JSONDecodeError:
                result["action_input"] = {"raw": input_match.group(1).strip()}

        # Buscar si es respuesta final
        final_match = re.search(r"Final Answer:\s*(.+)", response, re.DOTALL)
        if final_match:
            result["is_final"] = True
            result["final_content"] = final_match.group(1).strip()

        return result

    def run(self, user_input: str) -> str:
        """Ejecuta el agent loop completo hasta producir respuesta final."""
        self.memory.add("user", user_input)

        system_prompt = self._build_system_prompt()

        for iteration in range(self.max_iterations):
            # Construir el prompt completo
            context = self.memory.get_context()
            full_prompt = f"{system_prompt}\n\n## Conversación:\n{context}"

            # Llamar al LLM
            llm_response = self.llm(full_prompt)
            self.memory.add("assistant", llm_response)

            # Parsear respuesta
            parsed = self._parse_llm_response(llm_response)

            # Si es respuesta final, retornar
            if parsed.get("is_final"):
                return parsed["final_content"]

            # Si hay acción, ejecutarla
            if parsed["has_action"]:
                tool_name = parsed["action"]
                tool_input = parsed.get("action_input", {})

                if tool_name not in self.tools:
                    obs = f"Error: herramienta '{tool_name}' no encontrada. Available: {list(self.tools.keys())}"
                else:
                    try:
                        obs = self.tools[tool_name].function(**tool_input)
                    except Exception as e:
                        obs = f"Error ejecutando {tool_name}: {str(e)}"

                self.memory.add("tool_result", f"[{tool_name}] → {obs}")
            else:
                # No action, no final answer — forzar siguiente iteración
                self.memory.add("tool_result", "(Sin acción detectada, continuando reasoning...)")

        # Si llegamos aquí, se agotaron las iteraciones
        return f"[Agent] Se alcanzó el límite de {self.max_iterations} iteraciones. " \
               f"Último contexto: {self.memory.get_context()[-500:]}"


# --- Ejemplo de uso ---
def demo_llm(prompt: str) -> str:
    """Demo LLM que simula respuestas de ReAct.
    En producción, esto sería openai.ChatCompletion.create o similar."""
    if "search" in prompt.lower():
        return """Thought: El usuario quiere saber sobre Machine Learning. Debo buscar información.
Action: search
Action Input: {"query": "machine learning introduction"}

Final Answer: Machine Learning es una rama de la inteligencia artificial..."""
    return """Thought: El usuario hace una pregunta directa. Puedo responder sin herramientas.
Final Answer: ¡Hola! Soy un ReAct agent de demostración."""

# Definir tools
def search(query: str) -> str:
    """Simula búsqueda en la web."""
    return f"Resultados para '{query}': 1) Wikipedia: ML article, 2) Nature: Deep Learning survey..."

def calculate(expression: str) -> str:
    """Evalúa una expresión matemática."""
    try:
        result = eval(expression)
        return str(result)
    except Exception as e:
        return f"Error: {e}"

tools = [
    Tool(
        name="search",
        description="Busca información en la web dado un query",
        function=search,
        input_schema={"type": "object", "properties": {"query": {"type": "string"}}, "required": ["query"]}
    ),
    Tool(
        name="calculate",
        description="Evalúa una expresión matemática",
        function=calculate,
        input_schema={"type": "object", "properties": {"expression": {"type": "string"}}, "required": ["expression"]}
    ),
]

agent = ReActAgent(llm_callable=demo_llm, tools=tools, max_iterations=5)
result = agent.run("¿Qué es machine learning?")
print(result)
print("\nAgent run completado ✓")

📐 Structured Output para Tool Calls

El parsing de texto libre como en el ejemplo anterior es frágil. La forma robusta de hacer tool calling es usar structured output — forzar al LLM a devolver JSON válido que matchée un schema predefinido.

Esto es lo que implementan OpenAI function calling, Anthropic tool use, y otros. El LLM no elige entre texto libre y JSON: elige qué tool llamar y qué parámetros, y devuelve todo en un objeto JSON bien formado.

from enum import Enum
from typing import Optional, Union
from pydantic import BaseModel, Field

class ToolChoice(str, Enum):
    """Enum de las herramientas disponibles para el agent."""
    SEARCH = "search"
    CALCULATE = "calculate"
    RETRIEVE = "retrieve_documents"
    CODE_INTERPRETER = "execute_python"

class SearchInput(BaseModel):
    """Schema para la herramienta de búsqueda."""
    query: str = Field(description="Query de búsqueda")
    max_results: int = Field(default=5, description="Máximo de resultados")

class CalculateInput(BaseModel):
    """Schema para la herramienta de cálculo."""
    expression: str = Field(description="Expresión matemática a evaluar")

class AgentAction(BaseModel):
    """Acción estructurada devuelta por el LLM.

    En vez de parsear texto libre, el LLM llena este schema directamente.
    Esto elimina la fragilidad del regex parsing.
    """
    thought: str = Field(description="Razonamiento del agent sobre qué hacer")
    action: ToolChoice = Field(description="Nombre de la herramienta a llamar")
    action_input: Union[SearchInput, CalculateInput, dict] = Field(
        description="Parámetros para la herramienta"
    )

class AgentResponse(BaseModel):
    """Respuesta final del agent cuando no necesita más acciones."""
    is_final: bool = Field(default=True)
    final_answer: Optional[str] = Field(default=None, description="Respuesta final al usuario")

def parse_llm_structured_response(raw_output: dict) -> Union[AgentAction, AgentResponse]:
    """Convierte el output estructurado del LLM a objetos tipados.

    Con structured output (JSON mode en OpenAI, tool use en Anthropic),
    el LLM devuelve directamente un dict que matchée el schema.
    Esto es 100x más confiable que parsear texto libre.
    """
    if raw_output.get("is_final"):
        return AgentResponse(is_final=True, final_answer=raw_output.get("final_answer"))
    return AgentAction(
        thought=raw_output.get("thought", ""),
        action=ToolChoice(raw_output.get("action")),
        action_input=raw_output.get("action_input", {})
    )

# Ejemplo de uso con structured output
if __name__ == "__main__":
    raw_response = {
        "thought": "El usuario quiere información sobre python. Voy a buscar.",
        "action": "search",
        "action_input": {"query": "python programming language", "max_results": 3}
    }

    parsed = parse_llm_structured_response(raw_response)
    print(f"Tipo: {type(parsed).__name__}")
    print(f"Thought: {parsed.thought}")
    print(f"Action: {parsed.action}")
    print("Structured output parsing exitoso ✓")

📐 Memory: Conversation Buffer, Summary y Vector Store

Un agent sin memory es inútil: cada vez que el usuario hace una pregunta relacionada con la anterior, no tiene contexto. Pero guardar toda la conversación es impráctico — el context window se agota.

La solución real combina tres estrategias:

  • Conversation Buffer: Los últimos N mensajes se guardan tal cual
  • Summary: Mensajes más antiguos se resumen periódicamente (cada N mensajes)
  • Vector Store: Para retrieval de información relevante de conversaciones antiguas o documentos externos
class VectorMemory:
    """Vector memory para retrieval de información relevante.

    En vez de guardar todo en el context window, guardamos embeddings
    de cada chunk de información. Cuando el usuario pregunta, buscamos
    los chunks más similares vectorialmente y los injectamos al prompt.
    """
    def __init__(self, embedder, vector_store=None):
        self.embedder = embedder  # Función que devuelve embeddings (ej: OpenAI embeddings)
        self.vector_store = vector_store or {}
        self.chunks = []

    def add(self, text: str, metadata: dict = None):
        """Añade un chunk de texto al vector store."""
        embedding = self.embedder(text)
        chunk_id = len(self.chunks)
        self.chunks.append({
            "id": chunk_id,
            "text": text,
            "metadata": metadata or {},
            "embedding": embedding
        })
        self.vector_store[chunk_id] = embedding

    def retrieve(self, query: str, top_k: int = 5) -> list[dict]:
        """Busca los chunks más relevantes para la query."""
        query_emb = self.embedder(query)

        # Simple cosine similarity (en producción usar FAISS o similar)
        scores = []
        for chunk in self.chunks:
            sim = self._cosine_similarity(query_emb, chunk["embedding"])
            scores.append((chunk, sim))

        scores.sort(key=lambda x: x[1], reverse=True)
        return [chunk for chunk, _ in scores[:top_k]]

    def _cosine_similarity(self, a: list, b: list) -> float:
        dot = sum(x * y for x, y in zip(a, b))
        norm_a = sum(x * x for x in a) ** 0.5
        norm_b = sum(x * x for x in b) ** 0.5
        return dot / (norm_a * norm_b + 1e-8)


class HybridMemory:
    """Combina conversation buffer + summary + vector retrieval.

    Estrategia:
    - Últimos 10 mensajes → buffer directo
    - Mensajes 10-50 → summary
    - Más de 50 → vector store + retrieval
    """
    def __init__(self, embedder=None, vector_store=None):
        self.buffer = []  # Lista de Message
        self.summary = ""
        self.vector_memory = VectorMemory(embedder, vector_store) if embedder else None
        self.summary_threshold = 10
        self.vector_threshold = 50

    def add_message(self, role: str, content: str):
        self.buffer.append(Message(role=role, content=content))
        self._maybe_summarize()

    def _maybe_summarize(self):
        """Cada summary_threshold mensajes, resumir los más antiguos."""
        if len(self.buffer) > self.summary_threshold:
            to_summarize = self.buffer[:-self.summary_threshold]
            self.summary = f"[Resumen]: {', '.join(m.content[:30] for m in to_summarize)}..."
            self.buffer = self.buffer[-self.summary_threshold:]

    def get_context(self, current_query: str = "") -> str:
        """Retorna el contexto completo para el prompt."""
        parts = []

        if self.summary:
            parts.append(self.summary)

        if self.vector_memory and current_query:
            relevant = self.vector_memory.retrieve(current_query, top_k=3)
            if relevant:
                parts.append("[Info relevante de memoria vectorial]:")
                parts.extend(c["text"] for c in relevant)

        if self.buffer:
            parts.append("[Conversación reciente]:")
            parts.extend(f"{m.role}: {m.content}" for m in self.buffer)

        return "\n\n".join(parts)


# --- Ejemplo ---
if __name__ == "__main__":
    def dummy_embed(text: str) -> list:
        return [0.1 * len(text)] * 10

    memory = HybridMemory(embedder=dummy_embed)

    for i in range(60):
        memory.add_message("user", f"Mensaje {i} del usuario")

    context = memory.get_context("consulta sobre mensaje 30")
    print(f"Contexto generado ({len(context)} chars):")
    print(context[:300])
    print("Hybrid memory funcionando ✓")

📐 Code Interpreter Agent

Uno de los agents más útiles es el Code Interpreter: recibe una pregunta que requiere cálculo o procesamiento de datos, genera código Python, lo ejecuta, y usa el resultado para formular la respuesta. Es como darle un cerebro que puede realmente hacer cuentas y procesar archivos.

import io
import sys
from contextlib import redirect_stdout

class CodeInterpreterAgent:
    """Agent que ejecuta código Python generado por el LLM.

    El flujo:
    1. LLM recibe la pregunta y decide "necesito calcular algo"
    2. LLM genera código Python para resolverlo
    3. Este agente ejecuta el código en un entorno seguro
    4. El output se devuelve al LLM para formular la respuesta final

    IMPORTANTE: En producción, ejecutar en sandbox (Docker, E2B, etc.)
    para evitar código malicioso.
    """
    def __init__(self, llm_callable, max_execution_time: int = 30):
        self.llm = llm_callable
        self.max_execution_time = max_execution_time

    def execute_code(self, code: str) -> dict:
        """Ejecuta código Python y retorna resultado o error."""
        output = io.StringIO()
        error_output = io.StringIO()

        try:
            with redirect_stdout(output):
                exec_globals = {"__builtins__": __builtins__}
                exec(code, exec_globals)

            return {
                "success": True,
                "output": output.getvalue(),
                "error": None
            }
        except Exception as e:
            return {
                "success": False,
                "output": output.getvalue(),
                "error": f"{type(e).__name__}: {str(e)}"
            }

    def run(self, user_question: str) -> str:
        """Loop del code interpreter agent."""
        system_prompt = """Eres un code interpreter agent. Si la pregunta requiere
cálculos, procesamiento de datos, o manipulación de información numérica,
genera código Python y responde con:

Code: [código python]
Sin código: [explicación si no necesitas código]"""

        response = self.llm(f"{system_prompt}\n\nPregunta: {user_question}")

        if "Code:" in response:
            code = response.split("Code:")[1].split("Sin código:")[0].strip()
            result = self.execute_code(code)

            if result["success"]:
                return f"El código se ejecutó correctamente.\n\nOutput:\n{result['output']}\n\nCódigo usado:\n{code}"
            else:
                return f"Error en ejecución:\n{result['error']}\n\nCódigo usado:\n{code}"
        else:
            return response


# --- Ejemplo ---
def demo_llm(prompt: str) -> str:
    return "Code:\nprint(sum(range(1, 101)))\nSin código: No necesito ejecutar código."

interpreter = CodeInterpreterAgent(llm_callable=demo_llm)
result = interpreter.run("¿Cuál es la suma de los números del 1 al 100?")
print(result)
print("\nCode interpreter completado ✓")

🚨 Errores Comunes en AI Agents

Error 1: Agents en Loops Infinitos sin max_iterations

El error más básico y peligroso. Si el agent no tiene un límite de iteraciones, puede entrar en un loop donde sigue tomando acciones sin llegar nunca a una conclusión. Puede volver a llamar la misma tool una y otra vez, o ping-pong entre dos tools sin resolver nada.

Fix:

  • SIEMPRE definir max_iterations y verificar que se respeta
  • Trackear las acciones ya ejecutadas: si la misma secuencia se repite 2-3 veces, parar
  • Implementar un cost/latency budget que corte la ejecución si se pasa de tiempo
  • Considerar un timeout global por request

Error 2: No Tener Fallback Cuando una Tool Falla

Si una tool falla (API down, bad parameters, timeout) y el agent no tiene fallback, toda la ejecución puede colapsar. El usuario recibe un error críptico en lugar de una respuesta parcial o una explicación de qué pasó.

Fix:

  • Wrappear cada tool call con try/except y devolver un mensaje de error estruturado
  • Implementar retry con exponential backoff (1s, 2s, 4s) para errores transitorios
  • Si una tool falla 2+ veces, marcar como unavailable y continuar con alternativas
  • Devolver siempre algo útil al usuario: "No pude calcular X, pero puedo decirte que..."

Error 3: No Usar Structured Output para Tool Calls

Parsear tool calls desde texto libre con regex es una receta para problemas. Un LLM puede devolver "I will use the search tool" en vez de Action: search, o puede inventar parameters que no existen, o puede escribir JSON malformado.

Fix:

  • Usar structured output (JSON mode en OpenAI, tool use en Anthropic,guided generation en open-source)
  • Si usas regex parsing, al menos validar que el output cumple el schema antes de ejecutar
  • Tener un parser fallback: si el JSON parsing falla, intentar extraer info del texto libre
  • Considerar usar un schema más permisivo (string parameters en vez de enums estrictos) para reducir edge cases

🎯 Resumen

Los AI Agents representan un cambio de paradigma: de modelos que generan texto a sistemas que pueden actuar. El patrón ReAct (thought-action-observation) es la base sobre la que se construyen la mayoría de implementaciones modernas. La combinación de tool calling con structured output, conversation memory híbrida (buffer + summary + vector), y code interpreter permite resolver tareas que un chatbot simple jamás podría.

Los tres errores principales — loops infinitos, falta de fallback, y parsing fragile — son prevenibles con disciplina de engineering. Un agent sin max_iterations es un bug esperando pasar; un agent sin fallback ante tool failures es una liability; un agent sin structured output es una time bomb de edge cases.

En Colombia 🇨🇴 decimos que "el que no tiene de ding, tiene de dong". Para agents significa: ten un plan B para todo. La próxima vez que un agent te sorprenda respondiendo preguntas sobre datos que claramente no estaban en su training, date cuenta de que probablemente está recuperando información de un vector store o ejecutando código Python en un sandbox.

Nos vemos mañana. ¡Abrazo! 🇨🇴
