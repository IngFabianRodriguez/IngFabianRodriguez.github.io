Pooling (MaxPool, AvgPool) - Cómo Reducir Dimensionalidad sin Perder Información Relevante

7 de marzo de 2026
nn.MaxPool2dnn.AvgPool2dadaptive poolingspatial reduction

Hágale pues Parcero, ¿sabes cuál es el error más común cuando alguien implementa su primera CNN? Poner capas de Pooling sin entender qué están descartando.-maximizar o promediar — esa es la decisión. Y el 90% no sabe que está destruyendo información cuando usa AvgPool donde debería usar MaxPool, o viceversa. Lo descubrí de la manera más dolorosa: mi modelo de detección de bordes fallaba exactamente en los casos más difíciles porque el AvgPool promediaba la señal y el ruido juntos. Hoy destapamos Pooling: la matemática real de por qué reduce dimensionalidad, qué información preserva cada tipo, y cómo implementarlo correctamente en PyTorch.

## 🎯 ¿Por Qué Reducir Dimensionalidad sin Perder lo que Importa? **Definición técnica (sin rodeos):** Pooling es una operación de down-sampling que reduce el spatial size (alto × ancho) de los feature maps mientras preserva la información más importante. A diferencia de la convolución, que aprende filtros, Pooling es una operación fija — no tiene pesos que aprender. **Tipos:** - **MaxPool2d**: Toma el valor máximo en cada ventana. Conserva la activación más fuerte — ideal para detectar features como bordes, esquinas, blobs. - **AvgPool2d**: Promedia todos los valores en la ventana. Suaviza la señal — útil para clasificación cuando todas las features contribuyen por igual. - **Global Pooling**: Reduce CADA canal a un solo valor (1×1 spatial). Reemplaza flatten + dense en arquitecturas modernas. - **Adaptive Pooling**: Garantiza output size fijo sin importar el input size — esencial para transfer learning. **Mirá**: Es como cuando ves una foto desde lejos — automáticamente ignoras los detalles ruidosos y solo captas las formas grandes. MaxPool es como "quédate con lo más brillante"; AvgPool es como "quédate con el promedio de lo que ves". ## 📐 La Ecuación del Pooling — LA JOYA Esta ecuación parece simple pero tiene TODO el poder de reducir computación mientras preserva invariancia espacial: $$y_{c,i,j} = \frac{1}{k_h \cdot k_w} \sum_{m=0}^{k_h-1} \sum_{n=0}^{k_w-1} x_{c, i \cdot s_h + m, j \cdot s_w + n}$$ "Output $y$ del canal $c$ en posición $(i,j)$ es el promedio (o máximo) de la ventana $k_h \times k_w$ del input,Starting en $x$ con stride $s$." **$k_h, k_w$** = tamaño del kernel de pooling (típicamente 2×2) **$s_h, s_w$** = stride — cuánto se mueve la ventana (típicamente 2, reduce dimensiones a la mitad) **$c$** = índice del canal (el pooling se aplicaindependientemente por canal) ### MaxPool — La Ecuación del Máximo $$\max(x_{c,i,j}) = \max_{\substack{0 \leq m < k_h \\ 0 \leq n < k_w}} \left\{ x_{c, i \cdot s_h + m, j \cdot s_w + n} \right\}$$ "Para cada ventana, solo el valor máximo sobrevive. Esto le da a la red invariancia a translaciones pequeñas — si el feature más importante se mueve un poco, sigue siendo capturado." **Ventaja**: Preserva features estructurales (bordes, esquinas) incluso con ruido. **Desventaja**: Puede perder información si el feature importante no es el máximo. ### AvgPool — La Ecuación del Promedio $$\text{avg}(x_{c,i,j}) = \frac{1}{k_h \cdot k_w} \sum_{m=0}^{k_h-1} \sum_{n=0}^{k_w-1} x_{c, i \cdot s_h + m, j \cdot s_w + n}$$ "Cada valor contribuye por igual al output. Suaviza activaciones ruidosas." **Ventaja**: Suaviza features, útil para clasificación robusta. **Desventaja**: Diluye features fuertes con ruido circundante. ### Output Size After Pooling $$H_{out} = \left\lfloor \frac{H_{in} - k_h}{s_h} \right\rfloor + 1$$ Con $k=2, s=2$: cada dimensión se reduce a la mitad. Ejemplo numérico concreto: ```python import torch import torch.nn as nn # Simular feature map 4x4 (ej: después de una conv) x = torch.arange(16, dtype=torch.float32).reshape(1, 1, 4, 4) print("Input:\n", x.squeeze()) # MaxPool 2x2 con stride 2 maxpool = nn.MaxPool2d(kernel_size=2, stride=2) out_max = maxpool(x) print("\nMaxPool output:\n", out_max.squeeze()) # [[ 5, 7] # [13, 15]] # AvgPool 2x2 con stride 2 avgpool = nn.AvgPool2d(kernel_size=2, stride=2) out_avg = avgpool(x) print("\nAvgPool output:\n", out_avg.squeeze()) # [[ 2.5, 4.5] # [10.5, 12.5]] # Global Average Pooling — cada canal se reduce a 1 valor gap = nn.AdaptiveAvgPool2d((1, 1)) out_gap = gap(x) print("\nGlobal AvgPool output shape:", out_gap.shape) # [1, 1, 1, 1] # Adaptive Pooling — output size fijo sin importar input adaptive = nn.AdaptiveAvgPool2d((2, 2)) x_large = torch.randn(1, 1, 8, 8) # input más grande out_adaptive = adaptive(x_large) print("Adaptive AvgPool output shape:", out_adaptive.shape) # [1, 1, 2, 2] ``` ## 🚨 Errores Comunes (y Cómo No Cagarla) **Error 1: Usar AvgPool donde MaxPool preservaría mejor los features** **El problema**: AvgPool promedia todos los valores en la ventana, incluyendo ruido. Para tasks de detección (bordes, objetos, esquinas), el máximo preserva la señal más fuerte mientras suprime el ruido. ❌ ```python # Detección de bordes con AvgPool — destruye la señal class EdgeDetectorAvg(nn.Module): def __init__(self): super().__init__() self.conv = nn.Conv2d(3, 16, 3, padding=1) self.pool = nn.AvgPool2d(2, 2) # Promedia el borde con el fondo! self.fc = nn.Linear(..., 10) ``` **Por qué falla**: Un borde con intensidad 0.9 rodeado de fondo 0.1, pooleado con AvgPool 2×2, resulta en (0.9 + 0.1×3)/4 = 0.3 — casi indistinguible del fondo. ✓ ```python # Detección de bordes con MaxPool — preserva la señal fuerte class EdgeDetectorMax(nn.Module): def __init__(self): super().__init__() self.conv = nn.Conv2d(3, 16, 3, padding=1) self.pool = nn.MaxPool2d(2, 2) # Toma el máximo = 0.9 self.fc = nn.Linear(..., 10) ``` **Error 2: Olvidar que Global Pooling reemplaza flatten + dense** **El problema**: Muchos practitioners usan Flatten + Dense para conectar capas convolucionales al clasificador. Esto introduce millones de parámetros innecesarios. Global Pooling reduce cada canal a un solo valor — dramáticamente más eficiente. ❌ ```python # Arquitectura ineficiente: flatten + dense class InefficientNet(nn.Module): def __init__(self): super().__init__() self.features = nn.Sequential( nn.Conv2d(3, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), # 224->112 nn.Conv2d(64, 128, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), # 112->56 ) # flatten: 56*56*128 = 401,408 valores self.fc = nn.Linear(56*56*128, 10) # ~4M parámetros solo aquí! ``` **Por qué falla**: Los 4M parámetros en la primera capa Dense son innecesarios. La red está sobre-parametrizada y sobreajusta. ✓ ```python # Arquitectura eficiente: Global Average Pooling class EfficientNet(nn.Module): def __init__(self): super().__init__() self.features = nn.Sequential( nn.Conv2d(3, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), nn.Conv2d(64, 128, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), ) # Global Average Pooling: cada canal -> 1 valor self.gap = nn.AdaptiveAvgPool2d((1, 1)) # Output: 128 valores self.fc = nn.Linear(128, 10) # Solo 1,280 parámetros! ``` **Error 3: No usar Adaptive Pooling cuando haces transfer learning** **El problema**: Modelos pre-entrenados en ImageNet esperan input de 224×224. Si tus imágenes son de otro tamaño y no usas transforms correctas, tienes que elegir entre resize deformante o crop parcial. Adaptive Pooling resuelve esto: garantiza output size fijo sin importar input size. ❌ ```python # Sin adaptive pooling: fallan con inputs de diferente tamaño model = MyCNN() # Input de 300x300 falla porque la conv reduce a tamaño inesperado x = torch.randn(1, 3, 300, 300) out = model(x) # Shape mismatch en la capa fully connected ``` **Por qué falla**: Convocional Pooling stride 2 reduce 300→150→75→38... el feature map final no tiene tamaño fijo para la capa Dense. ✓ ```python # Con adaptive pooling: cualquier input -> tamaño fijo class CNNWithAdaptivePool(nn.Module): def __init__(self): super().__init__() self.features = nn.Sequential( nn.Conv2d(3, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), nn.Conv2d(64, 128, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), ) # Adaptive pool: SIEMPRE produce 7x7 sin importar input self.adaptive_pool = nn.AdaptiveAvgPool2d((7, 7)) self.fc = nn.Linear(128 * 7 * 7, 10) # Ahora funciona con CUALQUIER tamaño >= 14x14 x_300 = torch.randn(1, 3, 300, 300) # Funciona x_224 = torch.randn(1, 3, 224, 224) # Funciona x_150 = torch.randn(1, 3, 150, 150) # Funciona ``` --- ## 🎯 Resumen Ejecutivo Pooling no es "reducir la imagen para que sea más pequeña". Es resolver: $$y_{c,i,j} = \text{pool}\left(x_{c, i \cdot s:i \cdot s+k, j \cdot s:j \cdot s+k}\right)$$ Mediante la reducción espacial que mantiene invariancia a translaciones pequeñas. Con todas las implicaciones que eso conlleva: - **MaxPool**: Preserva features máximos — ideal para detección de bordes, esquinas, objetos. Invarianza a ruido. - **AvgPool**: Suaviza features — útil para clasificación cuando todas las activaciones contribuyen igual. - **Global Pooling**: Reemplaza flatten+dense, dramáticamente más parámetros-efficient. Estándar en arquitecturas modernas. - **Adaptive Pooling**: Garantiza output size fijo sin importar input size — esencial para transfer learning. - **Stride vs Kernel**: Con stride=2 y kernel=2, las ventanas no se solapan (down-sampling puro). Con stride=1 y kernel=2, hay solape. Parcero, Pooling es de las operaciones más simples y efectivas en CNNs. Y precisamente por eso el 90% la subestima — la ven como "reducir la imagen". Pero como con todo en deep learning, el diablo está en los detalles: MaxPool preserva features, AvgPool los suaviza, Global Pooling elimina la necesidad de flatten+dense, y Adaptive Pooling hace tu modelo robusto a cualquier input size. Recuerda: "promediar siempre es mejor que maximizar" es mentira — depende del task. ¡Nos vemos en el día 82!
