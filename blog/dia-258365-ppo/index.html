Tool Use - LLMs Usando Funciones Externas

15 de septiembre de 2026
tool-usefunction-callingllmintegration

Por Qué Tool Use Cambia Todo

Hagale pues, parcero. Día 258 y hoy vamos a lo que el 70% no sabe implementar bien: Tool Use y Function Calling. Esto es lo que separa un LLM que solo genera texto de uno que de verdad puede actuar en el mundo. Un LLM con tools puede buscar información real, ejecutar código, manipular archivos, hacer cálculos. Póngame atención que esto vale gold.

Qué Es Function Calling

Function Calling es la capacidad de un LLM para invocar funciones externas definidas por el usuario. En lugar de solo responder con texto, el modelo puede pedir explícitamente que se ejecute una función con parámetros específicos.

La diferencia clave con un RAG tradicional:

  • Sin Function Calling: El LLM genera texto basándose en su conocimiento. Si necesita info actualizada, inventa (hallucinate).
  • Con Function Calling: El LLM identifica qué información necesita, pide que se ejecute una función específica, y usa el resultado para generar una respuesta grounded.

Cómo Funciona la Arquitectura

El flujo completo de function calling tiene 5 pasos:

# Paso 1: Definir las funciones disponibles
functions = [
    {
        "name": "get_weather",
        "description": "Obtiene el clima actual de una ciudad",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {
                    "type": "string",
                    "description": "Nombre de la ciudad"
                },
                "unit": {
                    "type": "string",
                    "enum": ["celsius", "fahrenheit"],
                    "description": "Unidad de temperatura"
                }
            },
            "required": ["city"]
        }
    },
    {
        "name": "search_web",
        "description": "Busca información en la web",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {
                    "type": "string",
                    "description": "Query de búsqueda"
                }
            },
            "required": ["query"]
        }
    }
]

# Paso 2: Enviar functions al LLM
response = client.chat.completions.create(
    model="gpt-4-turbo",
    messages=[{"role": "user", "content": "Cómo está el clima en Bogotá?"}],
    tools=[{"type": "function", "function": f} for f in functions],
    tool_choice="auto"
)

# Paso 3: El LLM decide qué función llamar
# response.choices[0].message.tool_calls contendrá la solicitud

# Paso 4: Ejecutar la función localmente
tool_call = response.choices[0].message.tool_calls[0]
if tool_call.function.name == "get_weather":
    args = json.loads(tool_call.function.arguments)
    weather = get_weather_sync(args["city"], args.get("unit", "celsius"))
    
# Paso 5: Enviar el resultado de vuelta al LLM
response2 = client.chat.completions.create(
    model="gpt-4-turbo",
    messages=[
        {"role": "user", "content": "Cómo está el clima en Bogotá?"},
        response.choices[0].message,
        {
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": json.dumps(weather)
        }
    ]
)

Estructura del JSON de Funciones

El JSON schema de las funciones sigue el estándar OpenAI. Debe ser preciso para que el LLM llame las funciones correctamente:

# Estructura completa de una función bien definida
function_schema = {
    "name": "consultar_saldo_bancario",
    "description": "Consulta el saldo actual de una cuenta bancaria",
    "parameters": {
        "type": "object",
        "properties": {
            "numero_cuenta": {
                "type": "string",
                "pattern": "^[0-9]{10,20}$",  # Regex para validación
                "description": "Número de cuenta de 10 a 20 dígitos"
            },
            "tipo_moneda": {
                "type": "string",
                "enum": ["COP", "USD", "EUR"],
                "description": "Moneda del saldo a consultar"
            },
            "incluir_detalles": {
                "type": "boolean",
                "description": "Si true, incluye últimos 5 movimientos"
            }
        },
        "required": ["numero_cuenta"]
    }
}

# Errores comunes en definiciones:
# 1. Description vaga: "Gets user info" vs "Returns user name, email, and subscription tier"
# 2. Sin required fields: El LLM puede omitir parámetros críticos
# 3. Types incorrectos: string para IDs numéricos en lugar de integer
# 4. Sin ejemplos en description para casos complejos

Patrones de Implementación

Patrón 1: Búsqueda + Síntesis

El patrón más común: el LLM identifica qué info necesita, la busca, y sintetiza:

def search_and_synthesize(query, vector_store):
    """
    Patrón clásico: buscar información y sintetizar respuesta
    """
    # El LLM pide búsqueda con query optimizada
    search_function = {
        "name": "semantic_search",
        "description": "Busca documentos relevantes en la base de conocimiento",
        "parameters": {
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "top_k": {"type": "integer", "default": 5}
            },
            "required": ["query"]
        }
    }
    
    # Loop de tool use hasta que el LLM tenga toda la info
    messages = [{"role": "user", "content": query}]
    
    while True:
        response = client.chat.completions.create(
            model="gpt-4-turbo",
            messages=messages,
            tools=[{"type": "function", "function": search_function}]
        )
        
        if not response.choices[0].message.tool_calls:
            break  # El LLM tiene lo que necesita
        
        # Ejecutar cada tool call
        for tool_call in response.choices[0].message.tool_calls:
            if tool_call.function.name == "semantic_search":
                args = json.loads(tool_call.function.arguments)
                results = vector_store.search(args["query"], top_k=args.get("top_k", 5))
                
                messages.append(response.choices[0].message)  # El tool call del LLM
                messages.append({
                    "role": "tool",
                    "tool_call_id": tool_call.id,
                    "content": json.dumps(results)
                })
    
    return response.choices[0].message.content

Patrón 2: Código + Ejecución

El LLM genera código y pide ejecutarlo:

def code_execution_pattern(query):
    """
    El LLM genera código Python y pide ejecutarlo
    """
    code_interpreter_tool = {
        "name": "execute_python",
        "description": "Ejecuta código Python y retorna el output",
        "parameters": {
            "type": "object",
            "properties": {
                "code": {"type": "string", "description": "Código Python a ejecutar"},
                "timeout": {"type": "integer", "default": 30}
            },
            "required": ["code"]
        }
    }
    
    messages = [
        {"role": "system", "content": "You can execute Python code to help answer questions."},
        {"role": "user", "content": query}
    ]
    
    max_iterations = 5
    for _ in range(max_iterations):
        response = client.chat.completions.create(
            model="gpt-4-turbo",
            messages=messages,
            tools=[{"type": "function", "function": code_interpreter_tool}]
        )
        
        if not response.choices[0].message.tool_calls:
            return response.choices[0].message.content
        
        tool_call = response.choices[0].message.tool_calls[0]
        args = json.loads(tool_call.function.arguments)
        
        result = execute_python(args["code"], timeout=args.get("timeout", 30))
        
        messages.append(response.choices[0].message)
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": str(result)
        })

# Ejemplo: "Calcula los primeros 20 números primos y súmalos"
result = code_execution_pattern("Calcula los primeros 20 primos y su suma")

Patrón 3: Multi-Tool Chaining

Múltiples herramientas encadenadas donde cada resultado alimenta la siguiente:

def multi_tool_chain(query):
    """
    Encadenar múltiples tools: buscar -> filtrar -> calcular -> reportar
    """
    tools = [
        {
            "name": "get_stock_data",
            "description": "Obtiene datos de acciones",
            "parameters": {
                "type": "object",
                "properties": {
                    "symbol": {"type": "string"},
                    "period": {"type": "string", "enum": ["1d", "1w", "1m", "1y"]}
                },
                "required": ["symbol"]
            }
        },
        {
            "name": "calculate_returns",
            "description": "Calcula retornos financieros",
            "parameters": {
                "type": "object",
                "properties": {
                    "prices": {"type": "array", "items": {"type": "number"}},
                    "periods": {"type": "integer"}
                },
                "required": ["prices"]
            }
        },
        {
            "name": "send_email",
            "description": "Envía un email",
            "parameters": {
                "type": "object",
                "properties": {
                    "to": {"type": "string", "format": "email"},
                    "subject": {"type": "string"},
                    "body": {"type": "string"}
                },
                "required": ["to", "subject", "body"]
            }
        }
    ]
    
    messages = [{"role": "user", "content": query}]
    
    while True:
        response = client.chat.completions.create(
            model="gpt-4-turbo",
            messages=messages,
            tools=[{"type": "function", "function": t} for t in tools]
        )
        
        if not response.choices[0].message.tool_calls:
            return response.choices[0].message.content
        
        for tool_call in response.choices[0].message.tool_calls:
            func_name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            
            # Ejecutar según la función
            if func_name == "get_stock_data":
                result = yf.download(args["symbol"], period=args.get("period", "1mo"))
            elif func_name == "calculate_returns":
                result = calculate_returns(**args)
            elif func_name == "send_email":
                result = smtp_client.send(**args)
            
            messages.append(response.choices[0].message)
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": json.dumps(result)
            })

Errores Comunes

Error 1: Funciones Mal Definidas

El problema: La description de la función es vaga. El LLM no sabe cuándo o cómo llamar la función.

La solución: Descriptions específicas con ejemplos. Incluir qué retorna y en qué formato:

# MAL
{
    "name": "search",
    "description": "Busca cosas",
    "parameters": {"type": "object", "properties": {"q": {"type": "string"}}}
}

# BIEN
{
    "name": "search_restaurants",
    "description": "Busca restaurantes por nombre, cuisine, o ubicación. "
                   "Retorna lista de dicts con keys: name, cuisine, rating, address, price_level. "
                   "Usa esta función cuando el usuario pregunte por restaurantes, comida, o dónde comer.",
    "parameters": {
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "Término de búsqueda: puede ser nombre, tipo de comida (e.g., 'italiano'), o ubicación ('Cartagena')"
            },
            "limit": {
                "type": "integer",
                "description": "Número máximo de resultados (default: 5, max: 20)",
                "default": 5
            }
        },
        "required": ["query"]
    }
}

Error 2: No Manejar Límite de Tool Calls

El problema: El LLM puede entrar en loop llamando tools infinitamente.

La solución: Implementar max_iterations y validar que cada llamada sea progresiva:

def safe_tool_execution(messages, tools, max_iterations=10):
    for i in range(max_iterations):
        response = client.chat.completions.create(
            model="gpt-4-turbo",
            messages=messages,
            tools=[{"type": "function", "function": t} for t in tools]
        )
        
        if not response.choices[0].message.tool_calls:
            return response.choices[0].message.content
        
        # Verificar que cada tool call sea único y progresivo
        tool_call_ids = [tc.id for tc in response.choices[0].message.tool_calls]
        if len(set(tool_call_ids)) != len(tool_call_ids):
            # Mismo tool llamado múltiples veces - alto!
            return "Error: Loop detectado"
        
        # Ejecutar tools
        for tc in response.choices[0].message.tool_calls:
            result = execute_tool(tc.function.name, json.loads(tc.function.arguments))
            messages.append(response.choices[0].message)
            messages.append({
                "role": "tool",
                "tool_call_id": tc.id,
                "content": str(result)
            })
    
    return "Error: Límite de iteraciones alcanzado"

Error 3: No Validar Parámetros

El problema: Confías ciegamente en los parámetros que el LLM envía. Pueden ser inválidos o maliciosos.

La solución: Validar siempre los parámetros antes de ejecutar:

def safe_execute_tool(func_name, args, allowed_functions):
    if func_name not in allowed_functions:
        return {"error": f"Función {func_name} no permitida"}
    
    # Validar según el tipo de función
    if func_name == "send_email":
        if not validate_email(args.get("to")):
            return {"error": "Email inválido"}
        if len(args.get("body", "")) > 10000:
            return {"error": "Email muy largo"}
        # Sanitizar
        args["body"] = sanitize_html(args["body"])
    
    elif func_name == "execute_sql":
        # NUNCA ejecutar SQL directo sin validación
        if not is_safe_query(args["query"]):
            return {"error": "SQL potencialmente peligroso"}
    
    return execute_function(func_name, args)
