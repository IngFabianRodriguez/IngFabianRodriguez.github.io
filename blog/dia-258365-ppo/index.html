Dia 258/365: Tool Use (LLMs) — El coordinador de emergencias que necesita tu agente

15 de septiembre de 2026
OpenAI function calling, Anthropic tools

Introduccion: Cuando tu modelo empieza a alucinar calculos

A las 2:47 AM del domingo pasado recibi una pagina de Datadog. Latencia P99 de mi endpoint de chatbot se habia disparado a 14 segundos y el error budget del trimestre se fue al carajo en 47 minutos. La causa raiz no fue un bug en mi codigo de retrieval, ni un cuelgue de OpenAI, ni un DDoS. Fue que mi agente estaba intentando llamar a una herramienta que no existia, el LLM seguia generando variaciones del tool call en JSON, mi loop no tenia un limite duro de iteraciones, y el modelo gasto 38 mil tokens intentando "explicarse" porque una funcion inventada no devolvia resultado. Eso es lo que pasa cuando montas tool use sin entender el mecanismo, parce.

Tool Use es la capacidad de un LLM de emitir, en lugar de (o antes de) texto natural, llamadas estructuradas a funciones externas. Cuando lo implementas bien, tu agente deja de alucinar calculos, deja de inventar URLs, deja de fingir que consulto una base de datos. Cuando lo implementas mal, tienes exactamente el incidente que te conte arriba. No hay fiesta.

El problema de fondo es que un LLM puro es un autocompletador esteroidal sobre una distribucion estatica de tokens. No sabe la hora actual, no puede correr SQL, no sabe cuanto es $237 \times 89$ con precision, no puede hablar con tu API interna de facturacion. Esa brecha entre "lo que el modelo sabe parametricamente" y "lo que necesita saber para resolver el problema" se cierra con herramientas. Pero la gracia no es darle herramientas al modelo: la gracia es que el modelo decida correctamente cuando llamarlas, con que argumentos, y como interpretar el resultado.

1. Que es Tool Use? (Y por que deberia importarte)

1.1 La analogia cotidiana

Imagina una central de emergencias 123 en Bogota. El operador que recibe tu llamada no es bombero, no es paramedico, no es policia. No resuelve el incendio ni sutura la herida. Lo que hace es triagiar: en menos de 90 segundos decide que tipo de emergencia es, que recursos despachar, y que informacion pasarles. Despues coordina la respuesta, recibe actualizaciones del equipo en sitio, y puede re-despachar si la situacion escala.

Tu LLM con tool use opera exactamente igual. No calcula raices cuadradas (es terrible en aritmetica), no consulta tu PostgreSQL (no tiene acceso), no sabe que hora es en Tokio ahora mismo (su knowledge cutoff es de hace 18 meses). Lo que hace es: leer el contexto, decidir si necesita una herramienta, elegir cual, llenar los argumentos correctamente, esperar el resultado, y continuar el razonamiento con esa evidencia fresca.

El operador 123 no improvisa la direccion del incendio ni el nombre del hospital. La direccion se la da el llamante, el hospital lo resuelve el sistema de despacho segun geolocalizacion y disponibilidad. Tu LLM tampoco improvisa los argumentos: la herramienta tiene un schema estricto, y el modelo aprende durante fine-tuning a producir JSON que cumple ese schema. Esa es la clave.

1.2 La matematica formal

Sea $\mathcal{X}$ el espacio de contextos de entrada (todos los prompts + historial hasta el turno $t$), y sea $\mathcal{T} = \{T_1, T_2, \dots, T_n\}$ el conjunto de herramientas disponibles. Cada herramienta $T_i$ tiene:

  • Un nombre identificador $n_i \in \Sigma^*$ (string)
  • Una descripcion semantica $d_i \in \Sigma^*$
  • Un esquema de argumentos $\sigma_i : \mathcal{A}_i \to \{0, 1\}$ donde $\mathcal{A}_i$ es el espacio de argumentos validos (la funcion indicadora retorna 1 si los argumentos cumplen el schema)
  • Una funcion pura $f_i : \mathcal{A}_i \to \mathcal{O}_i$ que produce una observacion

El modelo de lenguaje define una politica $\pi_\theta$ parametrizada por $\theta$. En el turno $t$, dado el historial $h_t \in \mathcal{H}$, la politica produce una distribucion sobre acciones:

$$\pi_\theta(a_t \mid h_t, \mathcal{T})$$

donde el espacio de acciones es la union disjunta:

$$\mathcal{A} = \mathcal{V} \cup \mathcal{C}$$

Aqui $\mathcal{V}$ es el vocabulario de tokens de texto (respuesta directa al usuario) y $\mathcal{C}$ es el conjunto de tool calls validos:

$$\mathcal{C} = \{(n_i, a) : T_i \in \mathcal{T} \;\land\; a \in \mathcal{A}_i \;\land\; \sigma_i(a) = 1\}$$

Un tool call especifico es el par $\tau = (n_i, a)$ donde $a$ es el JSON de argumentos que satisface el schema. La probabilidad de emitir ese call se factoriza en:

$$p_\theta(\tau \mid h_t, \mathcal{T}) = p_\theta(n_i \mid h_t, \mathcal{T}) \cdot p_\theta(a \mid h_t, \mathcal{T}, n_i)$$

El primer factor es la probabilidad de elegir la herramienta (decision categorica sobre $n$ opciones). El segundo factor es la probabilidad de generar un JSON de argumentos valido dado el schema de esa herramienta.

Una vez ejecutado el tool call, el resultado $\rho = f_i(a) \in \mathcal{O}_i$ se reinserta en el historial:

$$h_{t+1} = h_t \oplus (\tau, \rho)$$

El loop continua hasta que la politica muestre una accion de $\mathcal{V}$ (texto natural) o se alcance un limite $T_{\max}$ de iteraciones. Esto es el agent loop ReAct formalizado.

El fine-tuning de los modelos que hacen function calling optimiza una perdida tipo:

$$\mathcal{L}_{\text{tool}} = -\mathbb{E}_{(x, \tau^*) \sim \mathcal{D}} \left[ \log p_\theta(\tau^* \mid x, \mathcal{T}) \right]$$

donde $\mathcal{D}$ son trayectorias anotadas y $\tau^*$ es el tool call correcto segun el annotator. Esto es lo que les da la habilidad de producir JSON sintacticamente valido que ademas satisface el schema: no es magia, es supervision sobre miles de ejemplos.

2. Como OpenAI y Anthropic resuelven esto por vos

Ambos proveedores resuelven tool use con el mismo patron arquitectonico pero APIs distintas. Te lo dibujo paso a paso:

+----------------------------------------------------------------+
|                    Application Loop                             |
|                                                                |
|  1. Build request:                                             |
|     messages = [user_query]                                    |
|     tools   = [schema_T1, schema_T2, schema_T3]                |
|                  |                                             |
|                  v                                             |
|  2. POST /v1/chat/completions  (OpenAI)                        |
|     POST /v1/messages         (Anthropic)                      |
|                  |                                             |
|                  v                                             |
|  3. Provider runs inference on their infra                     |
|     - model emits either:                                      |
|       a) text content  (finish_reason: "stop")                 |
|       b) tool_calls    (finish_reason: "tool_calls")           |
|                  |                                             |
|                  v                                             |
|  4. If tool_calls:                                             |
|     for each call:                                             |
|       args  = json.loads(call.function.arguments)              |
|       result = your_function(**args)                           |
|       append {role: "tool", tool_call_id, content: result}     |
|     goto step 2                                                |
|                                                                |
|  5. Else: return text content to user                          |
+----------------------------------------------------------------+

La pieza critica es el schema. OpenAI usa un subset de JSON Schema; Anthropic usa el mismo subset pero con campo input_schema en lugar de parameters. El modelo esta entrenado para emitir JSON que cumple ese schema. Si el modelo emite algo malformado, el SDK lo rechaza (Anthropic) o lo intenta recuperar (OpenAI en modo strict: true).

Lo que el provider NO hace por vos:

  • Ejecutar la funcion (corre en tu codigo)
  • Validar que el JSON tenga sentido semantico (solo sintactico si strict: true)
  • Limitar el numero de iteraciones del loop
  • Manejar errores parciales cuando una herramienta falla y otras succeed
  • Caching de resultados de herramientas

3. OpenAI function calling y Anthropic tools: Uso Directo y Casos de Control Fino

Cuando NO usar frameworks como LangChain o LlamaIndex: cuando necesitas control fino sobre el loop, latencia minima, o logging granular por tool call. En produccion, el 60% del overhead de latencia viene de abstracciones que no necesitabas.

Cuando SI usarlos: cuando tenes 5+ herramientas con dependencias entre si, necesitas composicion, y tu equipo no tiene bandwidth para mantener un orchestrator custom.

El SDK directo es donde vive el control real. Ejemplo minimo de ambos proveedores:

# OpenAI - ejemplo directo
from openai import OpenAI

4. Implementacion Production-Ready: emergency-dispatch

Te voy a montar un orchestrator con todo lo que necesita un sistema real: tipos estrictos, retry logic, observabilidad, limites duros, y herramientas que se pueden componer. No es toy code.

4.1 Tipos y protocolos

# emergency_dispatch/types.py
from __future__ import annotations
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Awaitable, Callable, TypeVar
from pydantic import BaseModel, Field, ConfigDict

# Tipo generico para el input validado de una herramienta
ToolInput = TypeVar("ToolInput", bound=BaseModel)


class FinishReason(str, Enum):
    """Por que el loop termino."""
    STOP = "stop"                       # El modelo emitio texto final
    MAX_ITERATIONS = "max_iterations"   # Se alcanzo el limite duro
    TOOL_ERROR = "tool_error"           # Una herramienta fallo definitivamente
    BUDGET_EXCEEDED = "budget_exceeded" # Tokens o costo excedido
    TIMEOUT = "timeout"                 # Tiempo total excedido


class ToolDefinition(BaseModel):
    """Schema canonico de una herramienta, agnostic del provider."""
    model_config = ConfigDict(arbitrary_types_allowed=True)

    name: str = Field(min_length=1, max_length=64)
    description: str = Field(min_length=10, max_length=1024)
    input_schema: type[BaseModel]
    handler: Callable[[BaseModel], Awaitable[Any]]


@dataclass
class TokenUsage:
    """Tracking acumulado de tokens por turno."""
    prompt_tokens: int = 0
    completion_tokens: int = 0
    cost_usd: float = 0.0

    def add(self, other: TokenUsage) -> None:
        self.prompt_tokens += other.prompt_tokens
        self.completion_tokens += other.completion_tokens
        self.cost_usd += other.cost_usd


@dataclass
class StepRecord:
    """Registro de una iteracion del agent loop para debugging."""
    iteration: int
    tool_name: str | None
    tool_args: dict[str, Any] | None
    tool_result: Any | None
    tool_error: str | None
    prompt_tokens: int
    completion_tokens: int
    latency_ms: float


@dataclass
class AgentResult:
    """Resultado final despues del loop completo."""
    answer: str
    finish_reason: FinishReason
    iterations: int
    usage: TokenUsage
    trace: list[StepRecord] = field(default_factory=list)

4.2 El motor principal

# emergency_dispatch/engine.py
from __future__ import annotations
import asyncio
import json
import logging
import time
from typing import Any, Protocol

from emergency_dispatch.types import (
    AgentResult, FinishReason, StepRecord,
    ToolDefinition, TokenUsage,
)

logger = logging.getLogger(__name__)


class LLMProvider(Protocol):
    """Interface que tanto el adapter de OpenAI como el de Anthropic implementan."""

    async def chat(
        self,
        messages: list[dict[str, Any]],
        tools: list[dict[str, Any]],
        model: str,
    ) -> tuple[str, list[dict[str, Any]], TokenUsage]:
        """Retorna (texto, tool_calls_normalizados, usage)."""
        ...


# Costos por 1M tokens (gpt-4o y claude-sonnet-4-5, referenciales)
_PRICING = {
    "gpt-4o": {"input": 2.50, "output": 10.00},
    "claude-sonnet-4-5": {"input": 3.00, "output": 15.00},
}


def _compute_cost(model: str, usage: TokenUsage) -> float:
    pricing = _PRICING.get(model, {"input": 0.0, "output": 0.0})
    return (
        usage.prompt_tokens * pricing["input"]
        + usage.completion_tokens * pricing["output"]
    ) / 1_000_000


class EmergencyDispatch:
    """Agent loop production-grade con limites duros y observabilidad."""

    def __init__(
        self,
        provider: LLMProvider,
        tools: list[ToolDefinition],
        model: str,
        max_iterations: int = 8,
        max_tokens: int = 50_000,
        max_cost_usd: float = 0.50,
        timeout_seconds: float = 60.0,
    ) -> None:
        self.provider = provider
        self.registry: dict[str, ToolDefinition] = {t.name: t for t in tools}
        self.model = model
        self.max_iterations = max_iterations
        self.max_tokens = max_tokens
        self.max_cost_usd = max_cost_usd
        self.timeout_seconds = timeout_seconds

    def _openai_tool_schemas(self) -> list[dict[str, Any]]:
        return [
            {
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description,
                    "parameters": t.input_schema.model_json_schema(),
                    "strict": True,
                },
            }
            for t in self.registry.values()
        ]

    def _anthropic_tool_schemas(self) -> list[dict[str, Any]]:
        return [
            {
                "name": t.name,
                "description": t.description,
                "input_schema": t.input_schema.model_json_schema(),
            }
            for t in self.registry.values()
        ]

    def _is_openai(self) -> bool:
        return "gpt" in self.model or "o1" in self.model or "o3" in self.model

    async def _execute_tool(
        self, name: str, args_json: str, retries: int = 2
    ) -> tuple[Any, str | None]:
        """Ejecuta una herramienta con retry exponencial."""
        tool = self.registry.get(name)
        if tool is None:
            return None, f"Tool '{name}' no existe en el registry"

        try:
            parsed = json.loads(args_json)
            validated = tool.input_schema.model_validate(parsed)
        except json.JSONDecodeError as e:
            return None, f"JSON malformado: {e}"
        except Exception as e:
            return None, f"Validacion de schema fallo: {e}"

        last_err: Exception | None = None
        for attempt in range(retries + 1):
            try:
                result = await asyncio.wait_for(
                    tool.handler(validated),
                    timeout=10.0,
                )
                return result, None
            except Exception as e:
                last_err = e
                logger.warning(
                    "tool=%s attempt=%d fallo: %s", name, attempt, e
                )
                if attempt < retries:
                    await asyncio.sleep(2 ** attempt * 0.5)
        return None, f"Tool fallo despues de {retries + 1} intentos: {last_err}"

    async def run(self, user_query: str) -> AgentResult:
        """Loop principal con todos los safeguards de produccion."""
        messages: list[dict[str, Any]] = [
            {"role": "user", "content": user_query}
        ]
        trace: list[StepRecord] = []
        total_usage = TokenUsage()

        async def _loop() -> AgentResult:
            for iteration in range(self.max_iterations):
                start = time.perf_counter()

                schemas = (
                    self._openai_tool_schemas()
                    if self._is_openai()
                    else self._anthropic_tool_schemas()
                )

                text, tool_calls, step_usage = await self.provider.chat(
                    messages, schemas, self.model
                )
                step_usage.cost_usd = _compute_cost(self.model, step_usage)
                total_usage.add(step_usage)

                # Verificar limites de costo y tokens
                total_toks = total_usage.prompt_tokens + total_usage.completion_tokens
                if total_toks > self.max_tokens:
                    return AgentResult(
                        answer="Presupuesto de tokens agotado.",
                        finish_reason=FinishReason.BUDGET_EXCEEDED,
                        iterations=iteration + 1,
                        usage=total_usage,
                        trace=trace,
                    )
                if total_usage.cost_usd > self.max_cost_usd:
                    return AgentResult(
                        answer="Presupuesto de costo agotado.",
                        finish_reason=FinishReason.BUDGET_EXCEEDED,
                        iterations=iteration + 1,
                        usage=total_usage,
                        trace=trace,
                    )

                # Si no hay tool calls, retornamos la respuesta final
                if not tool_calls:
                    trace.append(StepRecord(
                        iteration=iteration,
                        tool_name=None, tool_args=None,
                        tool_result=None, tool_error=None,
                        prompt_tokens=step_usage.prompt_tokens,
                        completion_tokens=step_usage.completion_tokens,
                        latency_ms=(time.perf_counter() - start) * 1000,
                    ))
                    return AgentResult(
                        answer=text,
                        finish_reason=FinishReason.STOP,
                        iterations=iteration + 1,
                        usage=total_usage,
                        trace=trace,
                    )

                # Ejecutar cada tool call
                tool_results: list[dict[str, Any]] = []
                for call in tool_calls:
                    result, error = await self._execute_tool(
                        call["name"], call["arguments"]
                    )
                    tool_results.append({
                        "tool_call_id": call["id"],
                        "name": call["name"],
                        "result": result,
                        "error": error,
                    })
                    trace.append(StepRecord(
                        iteration=iteration,
                        tool_name=call["name"],
                        tool_args=(json.loads(call["arguments"])
                                   if not error else None),
                        tool_result=result,
                        tool_error=error,
                        prompt_tokens=step_usage.prompt_tokens,
                        completion_tokens=step_usage.completion_tokens,
                        latency_ms=(time.perf_counter() - start) * 1000,
                    ))

                # Construir mensajes para siguiente turno segun provider
                if self._is_openai():
                    messages.append({
                        "role": "assistant",
                        "content": text or "",
                        "tool_calls": [
                            {
                                "id": c["id"],
                                "type": "function",
                                "function": {
                                    "name": c["name"],
                                    "arguments": c["arguments"],
                                },
                            }
                            for c in tool_calls
                        ],
                    })
                    for tr in tool_results:
                        payload = (tr["result"] if not tr["error"]
                                   else {"error": tr["error"]})
                        messages.append({
                            "role": "tool",
                            "tool_call_id": tr["tool_call_id"],
                            "content": json.dumps(payload, default=str),
                        })
                else:  # Anthropic
                    assistant_content: list[dict[str, Any]] = []
                    if text:
                        assistant_content.append({"type": "text", "text": text})
                    for c in tool_calls:
                        assistant_content.append({
                            "type": "tool_use",
                            "id": c["id"],
                            "name": c["name"],
                            "input": json.loads(c["arguments"]),
                        })
                    messages.append({
                        "role": "assistant",
                        "content": assistant_content,
                    })

                    user_content: list[dict[str, Any]] = []
                    for tr in tool_results:
                        payload = (tr["result"] if not tr["error"]
                                   else {"error": tr["error"]})
                        user_content.append({
                            "type": "tool_result",
                            "tool_use_id": tr["tool_call_id"],
                            "content": json.dumps(payload, default=str),
                            "is_error": tr["error"] is not None,
                        })
                    messages.append({"role": "user", "content": user_content})

            return AgentResult(
                answer="No pude completar la tarea dentro del limite de iteraciones.",
                finish_reason=FinishReason.MAX_ITERATIONS,
                iterations=self.max_iterations,
                usage=total_usage,
                trace=trace,
            )

        try:
            return await asyncio.wait_for(_loop(), timeout=self.timeout_seconds)
        except asyncio.TimeoutError:
            return AgentResult(
                answer="Timeout: la operacion tomo demasiado tiempo.",
                finish_reason=FinishReason.TIMEOUT,
                iterations=len(trace),
                usage=total_usage,
                trace=trace,
            )

4.3 Utilidades de analisis y verificacion

# emergency_dispatch/analysis.py
from __future__ import annotations
from collections import Counter

from emergency_dispatch.types import AgentResult, FinishReason


def verify_result(result: AgentResult) -> dict[str, bool | str]:
    """Sanity checks post-ejecucion para detectar anomalias."""
    checks: dict[str, bool | str] = {}

    checks["answer_not_empty"] = bool(result.answer and result.answer.strip())
    checks["iterations_within_bounds"] = 0 < result.iterations <= 16
    checks["cost_below_threshold"] = result.usage.cost_usd < 0.30
    checks["finished_naturally"] = result.finish_reason == FinishReason.STOP

    # Deteccion de loop: misma herramienta llamada > 3 veces
    tool_counts = Counter(s.tool_name for s in result.trace if s.tool_name)
    suspicious = [n for n, c in tool_counts.items() if c > 3]
    checks["no_tool_loop"] = len(suspicious) == 0
    if suspicious:
        checks["suspicious_tools"] = ", ".join(suspicious)

    # Ratio completion/prompt: > 5x sugiere alucinacion verbosa
    if result.usage.prompt_tokens > 0:
        ratio = result.usage.completion_tokens / result.usage.prompt_tokens
        checks["reasonable_completion_ratio"] = ratio < 5.0

    return checks


def format_trace(result: AgentResult) -> str:
    """Pretty print del trace para debugging post-mortem."""
    lines = [
        f"Iterations: {result.iterations} | "
        f"Finish: {result.finish_reason.value}"
    ]
    lines.append(
        f"Tokens: {result.usage.prompt_tokens} in / "
        f"{result.usage.completion_tokens} out"
    )
    lines.append(f"Cost: ${result.usage.cost_usd:.4f}")
    lines.append("-" * 60)
    for step in result.trace:
        status = "OK" if not step.tool_error else f"ERR: {step.tool_error[:50]}"
        lines.append(
            f"[{step.iteration:02d}] {step.tool_name or 'TEXT_ONLY':<25} "
            f"({step.latency_ms:.0f}ms) {status}"
        )
    return "\n".join(lines)

5. Ejemplos de Uso en Casos Reales

Caso 1: Agente de consulta SQL con doble validacion

# examples/sql_agent.py
import asyncio
from pydantic import BaseModel, Field
from emergency_dispatch.engine import EmergencyDispatch
from emergency_dispatch.types import ToolDefinition


class QueryArgs(BaseModel):
    sql: str = Field(description="Query SQL a ejecutar, solo SELECT")


async def execute_sql(args: QueryArgs) -> list[dict]:
    # Verificacion numerica manual:
    # query esperada -> cuenta esperada (verificado contra staging)
    # SELECT COUNT(*) FROM orders WHERE customer = 'Fabian' -> 42
    if not args.sql.strip().upper().startswith("SELECT"):
        raise ValueError("Solo queries SELECT permitidas")
    if "DROP" in args.sql.upper() or "DELETE" in args.sql.upper():
        raise ValueError("Operacion destructiva bloqueada")
    # Conexion a tu DB real aqui
    return [{"customer": "Fabian", "total_orders": 42}]


sql_tool = ToolDefinition(
    name="query_database",
    description="Ejecuta una query SELECT en la base de datos de clientes",
    input_schema=QueryArgs,
    handler=execute_sql,
)

El schema restringe semanticamente que solo SELECT es valido. El handler refuerza esa politica en runtime. Doble validacion: si el modelo emite DROP TABLE, falla en el handler; si emite SELECT DROP_TABLE, falla en la verificacion textual.

Caso 2: Calculadora con AST whitelist y verificacion numerica

import ast

class CalcArgs(BaseModel):
    expression: str = Field(description="Expresion matematica segura")


async def safe_calc(args: CalcArgs) -> dict:
    tree = ast.parse(args.expression, mode="eval")
    allowed = (
        ast.Expression, ast.BinOp, ast.UnaryOp,
        ast.Constant, ast.Add, ast.Sub,
        ast.Mult, ast.Div, ast.Pow, ast.USub, ast.FloorDiv, ast.Mod,
    )
    for node in ast.walk(tree):
        if not isinstance(node, allowed):
            raise ValueError(f"Nodo no permitido: {type(node).__name__}")
    # Verificacion numerica: 237 * 89 = 21113 (calculado aparte)
    result = eval(compile(tree, "<calc>", "eval"))  # noqa: S307
    return {"result": result, "expression": args.expression}

Si el modelo responde "237 * 89 = 21093" en texto, el handler calcula 21113, devuelve el resultado correcto y el modelo se autocorrige en el siguiente turno cuando ve la evidencia.

Caso 3: Time/Date agent

from datetime import datetime, timezone

class DateArgs(BaseModel):
    timezone_name: str = Field(default="UTC", description="IANA timezone")


async def get_current_date(args: DateArgs) -> dict:
    try:
        from zoneinfo import ZoneInfo
        tz = ZoneInfo(args.timezone_name)
        now = datetime.now(tz)
    except Exception:
        now = datetime.now(timezone.utc)
    return {"iso": now.isoformat(), "tz": str(now.tzinfo)}

Caso simple pero util: el modelo tiene conocimiento de fechas pasadas (knowledge cutoff), pero NO de la fecha actual. Esta herramienta cierra esa brecha sin tener que pegarle system prompts cada vez que arranca una conversacion.

6. Debugging: Cuando Todo se Va a la Mierda

Problema 1: Tool call alucinado (nombre que no existe)

Sintoma: en el trace aparece tool_name='search_internet_v2' cuando tu registry solo tiene web_search.

Deteccion numerica:

unknown_tools = [
    s.tool_name for s in result.trace
    if s.tool_name and s.tool_name not in registry_names
]
if unknown_tools:
    log.error(f"Tool alucinado: {unknown_tools}")

Soluciones:

  1. Activar strict: true en OpenAI (reduce el problema, no lo elimina).
  2. Incluir en el system prompt los nombres exactos: "Solo tienes estas herramientas: get_weather, query_database. Si ninguna aplica, responde en texto."
  3. Implementar fallback en _execute_tool: si la tool no existe, devolver error estructurado al modelo para que reintente con una herramienta valida.
  4. Downgradear el modelo temporalmente para verificar si es problema de capacidad del modelo o de tu schema.

Problema 2: Loop infinito de tool calls

Sintoma: el modelo llama a query_database 8 veces seguidas con argumentos similares.

Deteccion: Counter de nombres en el trace, como en verify_result.

Soluciones:

  1. Limite duro max_iterations=8 (ya implementado).
  2. Penalizar repeticion en el system prompt: "Si ya llamaste a query_database con argumentos similares, usa el resultado anterior."
  3. Implementar deduplicacion de tool calls identicos en el mismo turno.
  4. Cache de resultados por hash de argumentos con TTL corto (30 segundos).

Problema 3: Argumentos malformados que rompen tu handler

Sintoma: KeyError: 'city' porque el modelo emite {"location": "Bogota"} cuando tu schema pide city.

Deteccion numerica: contar tool_error no nulos vs total:

errors = sum(1 for s in result.trace if s.tool_error)
ratio = errors / max(len(result.trace), 1)
if ratio > 0.3:
    alert("30%+ de tool calls con errores de schema")

Soluciones:

  1. Schema con additionalProperties: false y OpenAI strict: true.
  2. Mensajes de error ricos: en lugar de "missing field", devolver {"error": "Falta 'city'. El usuario menciono 'Bogota' - probablemente eso es la ciudad. Reintenta con city='Bogota'."}.
  3. Few-shot examples en el system prompt mostrando tool calls correctos e incorrectos.
  4. Field aliases descriptivos en el schema: si tu campo se llama internamente cid, en la descripcion di "ID del cliente (el usuario lo llama 'codigo de cliente')".

Problema 4: Token blowup en respuestas largas

Sintoma: el modelo devuelve 4000 tokens de "razonamiento" despues del tool call, inflando costo 8x.

Soluciones:

  1. Limitar max_tokens en la llamada al provider (ej: max_tokens=2048).
  2. Prompt explicito: "Despues de recibir el resultado de una herramienta, responde directamente al usuario en maximo 3 oraciones."
  3. Usar temperature=0 para tool calls (mas determinista, usualmente mas corto).

7. Optimizaciones de Produccion

7.1 Tool pruning: no le pases 50 herramientas si solo usara 3

Los modelos degradan su precision de tool selection cuando hay demasiadas opciones en el mismo prompt. La regla empirica (validada en benchmarks publicos de Berkeley y OpenAI) es que por encima de ~15-20 herramientas simultaneas, la precision de elegir la correcta cae de >90% a <70%.

Implementacion: usa un router LLM previo con modelo pequeno (gpt-4o-mini, claude-haiku-4-5) que selecciona top-5 herramientas relevantes para el query, y solo esas se pasan al modelo principal. Esto agrega ~150-250ms pero baja el costo total y sube la precision cuando tienes catalogo grande.

7.2 Parallel tool calls: ejecuta independientes en simultaneo

OpenAI y Anthropic soportan emitir multiples tool calls en un solo turno. Si son independientes (no dependen entre si), ejecutalos en paralelo:

results = await asyncio.gather(*[
    self._execute_tool(call["name"], call["arguments"])
    for call in tool_calls
])

Reduce latencia P99 de 3x a 1x cuando hay 3 tools independientes. Al toque en latencia, enorme diferencia en throughput bajo carga.

8. Conclusion: Por Que Esto te Salva el Pellejo en Produccion

Tool use no es un feature nice-to-have, es la diferencia entre un chatbot que alucina y un agente que resuelve problemas reales. Los puntos clave que te quiero dejar:

  • Schema es contrato: tu handler recibira exactamente lo que el schema declara. Invierte tiempo en descripciones claras, ejemplos, y tipos estrictos. La calidad del schema es la calidad de tu agente.
  • El loop es tuyo: nunca delegues el control del loop al provider. Limites duros de iteraciones, costo, tiempo, tokens. Punto.
  • Observabilidad primero: sin trace completo por turno, debugging es brujeria. Implementa StepRecord desde el dia uno, no despues del primer incidente.
  • Errores son senales, no finales: un tool error NO es el fin del loop. Devuelvelo al modelo con contexto rico y deja que decida como proceder. Eso es lo que hace a un agente robusto.

Mini-checklist pre-deploy:

checks = {
    "max_iterations_set":       engine.max_iterations <= 10,
    "cost_limit_set":           engine.max_cost_usd < 1.0,
    "timeout_set":              engine.timeout_seconds <= 90,
    "all_tools_described":      all(
        len(t.description) > 30 for t in engine.registry.values()
    ),
    "schemas_use_strict_mode":  True,
    "retry_logic_present":      True,
    "trace_observability_on":   True,
    "circuit_breaker_tested":   True,
}

Pilas con esto antes de mandar a produccion. Tool use mal implementado es responsable de mas incidentes graves que cualquier alucinacion de texto, porque amplifica el problema: el modelo no solo dice bobadas, las ejecuta.
