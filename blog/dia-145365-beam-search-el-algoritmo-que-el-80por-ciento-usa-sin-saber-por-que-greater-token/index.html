Beam Search - El algoritmo que el 80% usa sin saber por qué greater tokens no siempre es mejor

25 de april de 2026
torch

Hola, parcero. Llegamos al Día 145 y hoy vamos con Beam Search. Este algoritmo es el pan de cada día en traducción automática, resumen de textos y cualquier tarea seq2seq. El problema es que el 80% lo usa con beam_width=1 — eso no es Beam Search, es greedy search disfrazado. Acompañame que esto va detallado.

📐 Fundamentos Teóricos

Beam Search es un algoritmo de búsqueda aproximada que balancea calidad vs. compute. En lugar de explorar TODAS las secuencias posibles (exponencial), solo mantiene las K mejores candidatos — las beams.

La matemática detrás

En cada paso t, tenemos K secuencias parciales. Para cada una, calculamos el score:

score(y_1, ..., y_t) = \sum_{i=1}^{t} \log P(y_i | y_1, ..., y_{i-1})

Luego seleccionamos las K con mayor score acumulado. El truco está en que se trabaja en log-space para evitar underflow numérico.

Beam Width: el trade-off silencioso

  • beam=1: Greedy — solo explora un camino. Rápido pero suboptimal.
  • beam=3-5: Balance típico para traducción. Mejora notable sobre greedy.
  • beam=10+: Para tareas que requieren diversidad. Cuidado con la calidad vs. diversidad.

Length Normalization

Sin normalization, Beam Search prefiere secuencias cortas porque acumulan menos penalización de log-probabilidad negativa:

score_{norm}(y) = \frac{score(y)}{|y|^\alpha}

Donde α ∈ [0.6, 0.7] es el estándar según Google Neural Machine Translation. Esto evita que "the" gane sobre "the cat sat on the mat" solo porque tiene menos tokens.

Coverage Penalty

Para tareas donde cada token de entrada debe ser "cubierto" (e.g., resumen), se añade:

score_{final} = score_{norm}(y) + \beta \cdot \sum_{i=1}^{|x|} \log(\max(c_i, \epsilon))

Donde c_i es la cobertura del token i de entrada. Esto reduce la repetición y mejora la cobertura.

class SimpleDecoder(torch.nn.Module):
    """Decoder simulado para demostrar beam search.
    En producción usarías tu modelo real (LLaMA, T5, etc.)
    """
    def __init__(self, vocab_size: int, embed_dim: int = 128, hidden_dim: int = 256):
        super().__init__()
        self.vocab_size = vocab_size
        self.embed = torch.nn.Embedding(vocab_size, embed_dim)
        self.lstm = torch.nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.fc = torch.nn.Linear(hidden_dim, vocab_size)
        
    def forward(self, x: torch.Tensor, hidden=None) -> Tuple[torch.Tensor, tuple]:
        emb = self.embed(x)
        out, hidden = self.lstm(emb, hidden)
        logits = self.fc(out)
        return logits, hidden
    
    def get_log_probs(self, token_ids: torch.Tensor, hidden=None) -> Tuple[torch.Tensor, tuple]:
        """Retorna log-probabilidades del próximo token."""
        logits, hidden = self.forward(token_ids, hidden)
        log_probs = F.log_softmax(logits[:, -1:], dim=-1)
        return log_probs, hidden


def beam_search(
    model: torch.nn.Module,
    start_token: int,
    end_token: int,
    beam_width: int = 5,
    max_len: int = 50,
    length_penalty: float = 0.6,
    device: str = "cpu"
) -> List[Tuple[List[int], float]]:
    """
    Beam Search con length normalization.
    
    Args:
        model: Decoder con get_log_probs()
        start_token: Token de inicio (e.g., 2)
        end_token: Token de fin (e.g., 3)
        beam_width: Número de beams a mantener
        max_len: Longitud máxima de generación
        length_penalty: α para length normalization (0.6-0.7 típico)
        device: cpu o cuda
    
    Returns:
        Lista de (secuencia_tokens, score_normalizado)
    """
    model.eval()
    
    # Estado inicial: una sola beam con solo el start_token
    # beams: list of (token_sequence, log_prob_sum, hidden_state)
    beams = [(start_token,), 0.0, None]
    completed = []
    
    with torch.no_grad():
        for step in range(max_len):
            all_candidates = []
            
            for seq, score, hidden in beams:
                # Si ya terminó, agregar a completados
                if seq[-1] == end_token:
                    completed.append((seq, score))
                    continue
                    
                # Preparar input para el modelo
                seq_tensor = torch.tensor([[seq[-1]]], dtype=torch.long).to(device)
                
                # Obtener log-probs del próximo token
                if hidden is not None:
                    hidden = tuple(h.to(device) for h in hidden)
                    
                log_probs, new_hidden = model.get_log_probs(seq_tensor, hidden)
                log_probs = log_probs.squeeze(0)  # (vocab_size,)
                
                # Top-k tokens para esta beam
                topk_log_probs, topk_indices = log_probs.topk(beam_width * 2)
                
                for log_p, token_id in zip(topk_log_probs, topk_indices):
                    new_seq = seq + (token_id.item(),)
                    new_score = score + log_p.item()
                    all_candidates.append((new_seq, new_score, new_hidden))
            
            if not all_candidates:
                break
                
            # ORDENAR por score normalizado (length normalized)
            # Esto es LO QUE DIFERENCIA beam search de greedy
            normalized = [
                (seq, score / (len(seq) ** length_penalty), hidden)
                for seq, score, hidden in all_candidates
            ]
            normalized.sort(key=lambda x: x[1], reverse=True)
            
            # Mantener solo las top-K beams
            beams = normalized[:beam_width]
            
            # Si todas las beams terminaron, parar
            if all(seq[-1] == end_token for seq, _, _ in beams):
                break
    
    # Agregar beams incompletas a completados
    for seq, score, _ in beams:
        if seq[-1] != end_token:
            completed.append((seq, score / (len(seq) ** length_penalty)))
    
    # Ordenar por score normalizado
    completed.sort(key=lambda x: x[1], reverse=True)
    return completed


def greedy_search(
    model: torch.nn.Module,
    start_token: int,
    end_token: int,
    max_len: int = 50,
    device: str = "cpu"
) -> Tuple[List[int], float]:
    """Greedy search: siempre toma el token con mayor probabilidad."""
    model.eval()
    seq = [start_token]
    total_log_prob = 0.0
    
    with torch.no_grad():
        hidden = None
        for _ in range(max_len):
            seq_tensor = torch.tensor([[seq[-1]]], dtype=torch.long).to(device)
            log_probs, hidden = model.get_log_probs(seq_tensor, hidden)
            log_probs = log_probs.squeeze(0)
            
            top_idx = log_probs.argmax().item()
            top_log_prob = log_probs[top_idx].item()
            
            if top_idx == end_token:
                total_log_prob += top_log_prob
                break
                
            seq.append(top_idx)
            total_log_prob += top_log_prob
    
    return seq, total_log_prob / (len(seq) ** 0.6)


def nucleus_sampling(
    model: torch.nn.Module,
    start_token: int,
    end_token: int,
    p: float = 0.9,
    max_len: int = 50,
    temperature: float = 1.0,
    device: str = "cpu"
) -> Tuple[List[int], float]:
    """Nucleus Sampling (Top-P) — alternatica a beam search para generación abierta."""
    model.eval()
    seq = [start_token]
    total_log_prob = 0.0
    
    with torch.no_grad():
        hidden = None
        for _ in range(max_len):
            seq_tensor = torch.tensor([[seq[-1]]], dtype=torch.long).to(device)
            logits, hidden = model.get_log_probs(seq_tensor, hidden)
            logits = logits.squeeze(0) / temperature
            
            # Softmax para obtener probabilidades
            probs = F.softmax(logits, dim=-1)
            
            # Nucleus: ordenar y acumular hasta llegar a p
            sorted_probs, sorted_indices = torch.sort(probs, descending=True)
            cumsum = torch.cumsum(sorted_probs, dim=-1)
            
            # Masks: incluir tokens hasta que cumsum > p
            nucleus_mask = cumsum <= p
            nucleus_mask = torch.cat([nucleus_mask[:-1], torch.tensor([True]).to(device)])
            
            # Aplicar mask y renormalizar
            filtered_probs = probs * nucleus_mask.float()
            filtered_probs = filtered_probs / filtered_probs.sum()
            
            # Sample del núcleo
            next_token = torch.multinomial(filtered_probs, 1).item()
            
            if next_token == end_token:
                break
                
            seq.append(next_token)
    
    return seq, 0.0  # Score no aplica para sampling


def compare_strategies(
    model: torch.nn.Module,
    start_token: int,
    end_token: int,
    device: str = "cpu"
):
    """Compara greedy, beam search y nucleus sampling."""
    print("\n" + "="*60)
    print("COMPARACIÓN DE ESTRATEGIAS DE DECODIFICACIÓN")
    print("="*60)
    
    # Greedy
    greedy_seq, greedy_score = greedy_search(model, start_token, end_token, device=device)
    print(f"\n📍 GREEDY (beam=1):")
    print(f"   Secuencia: {greedy_seq}")
    print(f"   Score norm: {greedy_score:.4f}")
    
    # Beam Search con diferentes widths
    for bw in [3, 5, 10]:
        beams = beam_search(model, start_token, end_token, beam_width=bw, device=device)
        if beams:
            best_seq, best_score = beams[0]
            print(f"\n📍 BEAM SEARCH (width={bw}):")
            print(f"   Mejor: {best_seq}")
            print(f"   Score norm: {best_score:.4f}")
            print(f"   Total candidates: {len(beams)}")
    
    # Nucleus Sampling
    nucleus_seq, _ = nucleus_sampling(model, start_token, end_token, p=0.9, device=device)
    print(f"\n📍 NUCLEUS SAMPLING (p=0.9):")
    print(f"   Secuencia: {nucleus_seq}")


def demo_length_normalization():
    """Demuestra por qué length normalization es crítica."""
    print("\n" + "="*60)
    print("LENGTH NORMALIZATION: EL PROBLEMA DE SECUENCIAS CORTAS")
    print("="*60)
    
    # Scores crudos (sin normalizar) — preferirá secuencias cortas
    scores_raw = [
        ([1, 2, 3], -2.5),      # Secuencia corta
        ([1, 2, 3, 4, 5, 6], -5.0),  # Secuencia larga
    ]
    
    print("\n❌ SIN LENGTH NORMALIZATION:")
    for seq, score in scores_raw:
        print(f"   Seq {seq}: score={score:.4f} → gana {[s for s, _ in scores_raw if _ == max(scores_raw, key=lambda x: x[1])[1]]}")
    
    # Scores normalizados — balance apropiado
    alpha = 0.6
    scores_norm = [(seq, score / (len(seq) ** alpha)) for seq, score in scores_raw]
    
    print("\n✅ CON LENGTH NORMALIZATION (α=0.6):")
    for seq, score in scores_norm:
        print(f"   Seq {seq}: score_norm={score:.4f}")
    
    winner = max(scores_norm, key=lambda x: x[1])
    print(f"   → Ganador: {winner[0]} con score {winner[1]:.4f}")

📊 Beam Width: Efecto Práctico

La siguiente tabla resume el impacto del beam width:

Beam Width Calidad Velocidad Uso Recomendado
1 (Greedy) Baja Muy rápida Solo para debugging
3-5 Buena Rápida Traducción, resumen
10-20 Muy buena Media Generación estructurada
50+ Excelente Lenta Solo si necesitas coverage

🚨 Errores Comunes y Sus Fallas

Error 1: Usar beam_width=1 y creer que es Beam Search

El problema: La mayoría de tutoriales usan num_beams=1 "para ser más rápidos" — eso NO es beam search, es greedy search con otro nombre. Perdés toda la ventaja del algoritmo.

# ❌ MAL: esto es GREEDY, no beam search
outputs = model.generate(input_ids, num_beams=1, max_length=50)

# ✅ BIEN: beam search real con width=5
outputs = model.generate(input_ids, num_beams=5, max_length=50)

El fix: Usa num_beams >= 3 mínimo. Si tu modelo tarda 100ms en greedy, beam=5 tarda ~500ms pero la calidad mejora significativamente en tareas de seq2seq.

Error 2: No usar Length Normalization

El problema: Sin normalization, beam search produce secuencias sistemáticamente más cortas de lo óptimo porque acumula menos penalización negativa.

# ❌ MAL: sin length normalization
# El modelo prefiere "the" sobre "the cat sat on the mat"

# ✅ BIEN: con length normalization
outputs = model.generate(
    input_ids,
    num_beams=5,
    max_length=50,
    length_penalty=0.6  # Google NMT usa 0.6-0.7
)

El fix: Siempre usa length_penalty entre 0.6 y 0.7. Esto normaliza por |y|^α y balancea la preferencia por longitud.

Error 3: Usar Beam Search para Generación Abierta

El problema: Beam search es determinista y explora pocas trayectorias. Para chat, storytelling o code completion abierto, esto resulta en texto repetitivo y falta de diversidad.

# ❌ MAL: beam search para generación abierta
# Vas a obtener texto repetitivo tipo "el el el el..."
outputs = model.generate(input_ids, num_beams=10, max_length=200)

# ✅ BIEN: nucleus sampling para generación abierta
outputs = model.generate(
    input_ids,
    do_sample=True,
    top_p=0.9,
    temperature=0.8,
    max_length=200
)

El fix: Para tareas open-ended, usa nucleus sampling (top_p) o temperature sampling. Beam search brilla en tareas con目标和是正确的输出 (traducción, resumen, QA estructurado).

✅ Resumen y Cierre

Hoy aprendimos que Beam Search no es solo "poner num_beams > 1". Es entender:

  • El beam width controla el trade-off calidad vs. compute
  • La length normalization evita el sesgo hacia secuencias cortas
  • El coverage penalty mejora la cobertura en tareas de resumen
  • Beam Search NO es para generación abierta — para eso está nucleus sampling

La próxima vez que tu modelo de traducción produzca "the the the", ya sabés qué hacer: length_penalty=0.6 y num_beams=5.
