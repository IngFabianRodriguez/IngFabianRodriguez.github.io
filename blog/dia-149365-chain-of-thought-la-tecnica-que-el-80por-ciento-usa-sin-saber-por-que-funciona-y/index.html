Chain of Thought - La técnica que el 80% usa sin saber por qué funciona y cuándo aplicarla

29 de april de 2026
transformers

Hola, parcero. Llegamos al Día 149 y hoy vamos con Chain-of-Thought, o como le digo yo, la técnica de "pensar en voz alta". Esto lo implementan muchos pero muy pocos saben por qué funciona — y más importante, cuándo no funciona. Aquí te cuento todo con código real en PyTorch para que te lleves algo útil, no solo teoría.

📐 Fundamentos: ¿Qué es Chain-of-Thought?

Chain-of-Thought (CoT) es una técnica de prompting que induce al modelo a generar una secuencia de pasos de razonamiento intermedios antes de dar la respuesta final. En términos matemáticos:

Dado un input x, en lugar de generar directamente f(x), CoT elicita:

z₁, z₂, ..., zₙ ~ p(·|x) donde cada zᵢ es un paso de razonamiento, y la respuesta final es y ~ p(·|x, z₁,...,zₙ)

La intuición: al exponer el espacio de razonamiento, el modelo puede "ver" su trabajo y corregir errores antes decommitear la respuesta.

¿Cuándo funciona CoT?

  • Aritmética multi-dígito: "Tengo 15 naranjas, le doy 3 a María y 4 a Juan, ¿cuántas me quedan?" — CoT ayuda porque fuerza verificar cada operación.
  • Problemas lógicos en cadena: Preguntas que requieren composición de reglas (si A entonces B, si B entonces C...)
  • Sentido común complejo: Preguntas donde se necesita considerar múltiples aspectos antes de responder.
  • Codificación: Bugs que requieren buscar en múltiples lugares del código para encontrar la causa raíz.

¿Cuándo NO funciona CoT?

  • Factual recall simple: "¿Capital de Francia?" — forzar razonamiento aquí solo agrega latencia.
  • Operaciones aritméticas triviales: "2+2=?" — el modelo ya sabe esto, CoT es overhead innecesario.
  • Tareas donde el modelo es already perfect: Si el accuracy es 99%+ sin CoT, añadirlo solo slow things down.

💻 Implementación Completa en PyTorch

Vamos a implementar desde cero: CoT prompting, self-consistency decoding, y comparación directa vs CoT. Esto es código que puedes correr directamente.

"""
Chain-of-Thought Implementation in PyTorch
Implementación completa: direct prompting vs CoT vs CoT + self-consistency
"""
import torch
import torch.nn as nn
from transformers import AutoModelForCausalLM, AutoTokenizer
from typing import List, Dict, Tuple
import numpy as np


class ChainOfThoughtPrompting:
    """
    Implementación de CoT prompting con soporte para:
    - Direct prompting (baseline)
    - Zero-shot CoT
    - Few-shot CoT con exemplars
    - Self-consistency decoding
    """

    def __init__(self, model_name: str = "gpt2"):
        self.device = "cuda" if torch.cuda.is_available() else "cpu"
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModelForCausalLM.from_pretrained(model_name)
        self.model.to(self.device)
        # GPT-2 no tiene pad token por defecto
        self.tokenizer.pad_token = self.tokenizer.eos_token

    def direct_prompt(self, question: str) -> str:
        """
        Baseline: prompting directo sin razonamiento intermedio.
        Útil para comparar contra CoT.
        """
        prompt = f"Q: {question}\nA:"
        inputs = self.tokenizer(prompt, return_tensors="pt").to(self.device)

        with torch.no_grad():
            outputs = self.model.generate(
                **inputs,
                max_new_tokens=100,
                temperature=0.7,
                do_sample=True,
                pad_token_id=self.tokenizer.pad_token_id
            )

        response = self.tokenizer.decode(outputs[0], skip_special_tokens=True)
        # Extraer solo la respuesta después de "A:"
        return response.split("A:")[-1].strip()

    def zero_shot_cot(self, question: str) -> Tuple[str, str]:
        """
        Zero-shot Chain-of-Thought: elicita razonamiento con "Let's think step by step"
        Retorna (razonamiento, respuesta)
        """
        # Paso 1: Generar el razonamiento
        cot_prompt = f"Q: {question}\nLet's think step by step:"
        inputs = self.tokenizer(cot_prompt, return_tensors="pt").to(self.device)

        with torch.no_grad():
            reasoning_output = self.model.generate(
                **inputs,
                max_new_tokens=200,
                temperature=0.7,
                do_sample=True,
                pad_token_id=self.tokenizer.pad_token_id
            )

        reasoning = self.tokenizer.decode(reasoning_output[0], skip_special_tokens=True)
        reasoning_steps = reasoning.split("Let's think step by step:")[-1].strip()

        # Paso 2: Extraer respuesta usando el razonamiento como contexto
        answer_prompt = f"{reasoning_steps}\nTherefore, the answer is:"
        answer_inputs = self.tokenizer(answer_prompt, return_tensors="pt").to(self.device)

        with torch.no_grad():
            answer_output = self.model.generate(
                **answer_inputs,
                max_new_tokens=50,
                temperature=0.1,
                do_sample=False,
                pad_token_id=self.tokenizer.pad_token_id
            )

        answer = self.tokenizer.decode(answer_output[0], skip_special_tokens=True)
        return reasoning_steps, answer.split("the answer is:")[-1].strip()

    def few_shot_cot(
        self, question: str, exemplars: List[Dict[str, str]]
    ) -> Tuple[str, str]:
        """
        Few-shot CoT: provee ejemplos de calidad (reasoning + answer) como contexto.
        ¡OJO! Los exemplars DEBEN ser de alta calidad — garbage in, garbage out.
        """
        # Construir prompt con exemplars
        prompt_parts = []
        for ex in exemplars:
            prompt_parts.append(f"Q: {ex['question']}")
            prompt_parts.append(f"Reasoning: {ex['reasoning']}")
            prompt_parts.append(f"Answer: {ex['answer']}\n")

        prompt_parts.append(f"Q: {question}")
        prompt_parts.append("Reasoning:")

        full_prompt = "\n".join(prompt_parts)
        inputs = self.tokenizer(full_prompt, return_tensors="pt").to(self.device)

        with torch.no_grad():
            output = self.model.generate(
                **inputs,
                max_new_tokens=250,
                temperature=0.7,
                do_sample=True,
                pad_token_id=self.tokenizer.pad_token_id
            )

        response = self.tokenizer.decode(output[0], skip_special_tokens=True)

        # Extraer reasoning y answer
        parts = response.split("Reasoning:")
        if len(parts) > 1:
            reasoning_and_answer = parts[-1].split("Answer:")
            reasoning = reasoning_and_answer[0].strip() if reasoning_and_answer else ""
            answer = reasoning_and_answer[-1].strip() if len(reasoning_and_answer) > 1 else ""
        else:
            reasoning, answer = "", response

        return reasoning, answer

    def self_consistency_decoding(
        self, question: str, n_samples: int = 10
    ) -> Tuple[str, str, Dict]:
        """
        Self-consistency: genera múltiples reasoning paths y selecciona
        la respuesta más común. Mejora significativamente CoT.

        Math: argmax_y ∑ᵢ p(y | reasoning_path_i) donde reasoning_path_i ~ p(·|x)
        """
        reasoning_paths = []
        answers = []

        # Generar n_samples reasoning paths
        for _ in range(n_samples):
            reasoning, answer = self.zero_shot_cot(question)
            reasoning_paths.append(reasoning)
            answers.append(answer.lower().strip())

        # Contar frecuencia de respuestas
        answer_counts: Dict[str, int] = {}
        for ans in answers:
            answer_counts[ans] = answer_counts.get(ans, 0) + 1

        # Respuesta más consistente
        consistent_answer = max(answer_counts, key=answer_counts.get)
        confidence = answer_counts[consistent_answer] / n_samples

        # El reasoning path más común
        most_common_reasoning = reasoning_paths[answers.index(consistent_answer)]

        return most_common_reasoning, consistent_answer, {
            "confidence": confidence,
            "answer_distribution": answer_counts,
            "total_samples": n_samples
        }

    def compare_direct_vs_cot(self, questions: List[str]) -> Dict:
        """
        Compara performance de direct prompting vs CoT vs CoT + self-consistency.
        Retorna métricas agregadas.
        """
        results = {
            "direct": {"correct": 0, "total": len(questions), "answers": []},
            "cot": {"correct": 0, "total": len(questions), "answers": []},
            "cot_sc": {"correct": 0, "total": len(questions), "answers": []},
        }

        for q in questions:
            # Direct
            direct_ans = self.direct_prompt(q)
            results["direct"]["answers"].append(direct_ans)

            # Zero-shot CoT
            _, cot_ans = self.zero_shot_cot(q)
            results["cot"]["answers"].append(cot_ans)

            # CoT + Self-consistency
            _, sc_ans, _ = self.self_consistency_decoding(q, n_samples=5)
            results["cot_sc"]["answers"].append(sc_ans)

        return results


# --- Exemplars de ALTA calidad para few-shot CoT ---
HIGH_QUALITY_EXEMPLARS = [
    {
        "question": "María tiene 5 manzanas. Compra 3 cajas de 4 manzanas cada una. ¿Cuántas manzanas tiene ahora?",
        "reasoning": "Primero calculo las manzanas de las cajas: 3 cajas × 4 manzanas = 12 manzanas. Luego sumo las que ya tenía: 5 + 12 = 17 manzanas. Entonces María tiene 17 manzanas en total.",
        "answer": "17"
    },
    {
        "question": "Un tren sale de Bogotá a las 8am hacia Medellín a 60 km/h. Otro sale de Medellín a las 9am hacia Bogotá a 80 km/h. Si la distancia es 400km, ¿a qué hora se encuentran?",
        "reasoning": "A las 9am, el tren de Bogotá ya ha recorrido 60km. Quedan 340km entre ellos. La velocidad relativa combinada es 60+80=140 km/h. Tiempo hasta encuentro desde las 9am: 340/140 ≈ 2.43 horas = 2 horas 26 minutos. Se encuentran a las 11:26am aproximadamente.",
        "answer": "11:26 AM"
    }
]

# --- Demo ---
if __name__ == "__main__":
    print("=" * 60)
    print("Chain-of-Thought: Direct vs CoT vs Self-Consistency")
    print("=" * 60)

    cot = ChainOfThoughtPrompting("gpt2")

    test_question = "Si tengo 1000 pesos y compro 3 galletas de 150 pesos cada una, ¿cuánto me queda?"

    print(f"\n📝 Pregunta: {test_question}")

    print("\n--- Direct Prompting ---")

    print(f"Respuesta: {direct}")

    print(f"Razonamiento: {reasoning}")

🚨 Los 3 Errores que el 80% Commete con CoT

Error 1: Usar CoT para aritmética simple — ¡Overkill!

Error típico:

# ❌ MAL: usando CoT para algo trivial
prompt = """Problema: 2 + 2 = ?
Pensemos paso a paso:"""
# Esto solo agrega latencia para algo que el modelo ya sabe perfectamente

Fix: Aplica CoT selectivamente. Si el problema requiere 1-2 operaciones mentales simples, no lo uses. Mira la complejidad del reasoning antes de aplicar CoT. Regla práctica: si el error rate sin CoT es bajo (<5%), CoT probablemente no ayuda.

Error 2: CoT sin exemplars de calidad — Garbage in, garbage out

El ejemplo más común que veo en producción:

# ❌ MAL: exemplars de baja calidad
exemplars = [
    {"question": "calc", "reasoning": "hmm let me think...", "answer": "42"},
    # El reasoning es vago, no estructura el pensamiento
]
# Resultado: CoT falla porque los ejemplos no enseñan la estructura correcta

Fix: Los exemplars deben mostrar el FORMATO del razonamiento, no solo la respuesta correcta. Cada paso debe ser explícito y justificado. Si tu exemplar dice "porque sí", estás enseñando al modelo a responder sin fundamento.

Error 3: No usar self-consistency — Dejando performance sobre la mesa

Error:

# ❌ MAL: Solo usando CoT sin self-consistency
reasoning, answer = cot.zero_shot_cot(question)
# Una sola muestra = una sola chance de error

Self-consistency típicamente mejora CoT en 10-30% en benchmarks de razonamiento. El paper original muestra que con 40 samples, CoT+SC alcanza state-of-the-art en GSM8K (matemáticas de escuela).

Fix: Para tareas críticas, usa self-consistency con 5-10 samples. Para tareas menos críticas, al menos 3 samples te dan mejor señal que 1.

# ✅ BIEN: usando self-consistency
reasoning, answer, stats = cot.self_consistency_decoding(question, n_samples=7)
print(f"Confidence: {stats['confidence']:.2%}")  # 85.7% de las samples concuerdan

📊 Comparación: Direct vs CoT vs CoT+SC

Método: Direct

  • Latencia: ⭐ (mínima)
  • Accuracy Típico: Baseline
  • Cuando usarlo: Factual recall, arithmetic trivial

Método: Zero-shot CoT

  • Latencia: ⭐⭐⭐
  • Accuracy Típico: +5-15%
  • Cuando usarlo: Razonamiento lógico complejo

Método: Few-shot CoT

  • Latencia: ⭐⭐⭐⭐
  • Accuracy Típico: +10-20%
  • Cuando usarlo: Dominios especializados

Método: CoT + Self-consistency

  • Latencia: ⭐⭐⭐⭐⭐ (alta)
  • Accuracy Típico: +15-30%
  • Cuando usarlo: Tareas críticas, math benchmarks

✅ Resumen y Cierre

Hoy cubrimos Chain-of-Thought desde los fundamentos hasta la implementación completa. Puntos clave para llevarse:

  • CoT no es magia: funciona cuando el reasoning es la pieza faltante, no cuando el modelo simplemente no sabe.
  • La calidad de los exemplars determina el ceiling: invierte tiempo en crear buenos ejemplos.
  • Self-consistency es el upgrade más impactful: si ya usas CoT, agrégale SC — el improvement vale la latencia extra.
  • Selecciona cuándo aplicar CoT: no todo problema necesita razonamiento explícito.

En Bogotá我们都习惯了 resolver problemas complejos paso a paso — CoT simplemente le enseña eso mismo a los transformers. La diferencia entre alguien que aplica CoT ciegamente y alguien que sabe cuándo y cómo usarlo es la diferencia entre un chatbot que responde y uno que razona.
