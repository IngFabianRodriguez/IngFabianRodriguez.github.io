Dia 199/365: TTS — El imitador de voces del mercado que vive en tu servidor

Introduccion: El fantasma que te contesta el telefono

Hace dos meses, una marca con la que trabajo sufrio una caida del canal de voz un viernes a las 7pm. El proveedor de TTS empezo a devolver 429 en hora pico y el fallback de Azure tenia una cola de 30 segundos. Los usuarios escucharon "Por favor espere" en loop durante 4 minutos antes de que pudieramos matar el servicio y enrutar a un operador humano. Cuatro dias despues teniamos tres ingenieros dedicados full-time a reconstruir el stack de sintesis.

Esa es la razon por la que ya no delego el TTS critico a un unico proveedor. Lo que vas a leer aca no es un tutorial de "hola mundo TTS": es una arquitectura battle-tested para correr coqui-ai XTTS-v2 (modelo local, clonacion de voz) y edge-tts (wrapper del servicio de Azure que usa Microsoft Edge, cero costo) en paralelo, con verificacion numerica del audio, fallback automatico, y manejo de los tres puntos donde se rompe todo: cold-start del modelo, referencias de voz contaminadas, y rate-limits rotativos. Si llevas sistemas de voz a produccion o estas por implementar un agente conversacional serio, esto te va a ahorrar el telefono a las 2am.

1. Que es TTS? (Y por que deberia importarte)

1.1 La analogia cotidiana: El imitador de voces de la plaza de mercado

En cada pueblo colombiano hay uno. Llega a la reunion familiar, escucha tres segundos al viejo de la tienda, y le clava la voz pidiendo "...a ver mijita, me regala tres panes y un tinto". Esa persona agarra una frase cualquiera y la hace sonar como si la dijera otra persona. Eso mismo es Text-to-Speech moderno: agarras texto plano y produces un waveform que suena como una persona real hablando.

Detras del truco hay tres etapas que casi nadie te explica. (1) Convertir el texto crudo en una representacion intermedia (los mel-spectrogramas, que son como una "huella digital" del sonido en una escala perceptual). (2) Pasar esa representacion por un modelo acustico que predice el espectrograma completo a partir del texto y un embedding del hablante. (3) Un vocoder convierte el espectrograma en audio crudo que tus parlantes puedan reproducir. Si cualquiera de las tres falla, lo escuchas: sale metalico (vocoder pobre), monótono (acustico debil), o desentonado (referencia mala).

1.2 La matematica formal

Paso 0: la escala Mel. El oido humano no procesa frecuencias linealmente: percibe 2000Hz como casi el doble de 1000Hz, no como el doble exacto. TTS usa la escala Mel para comprimir el espectro:

$$m = 2595 \cdot \log_{10}\left(1 + \frac{f}{700}\right)$$

Donde $f$ es la frecuencia en Hz y $m$ es la coordenada Mel. La inversa para volver a Hz es $f = 700 \cdot (10^{m/2595} - 1)$. Esto explica por que los extractores usan siempre 80 mels (no 513 bins lineales): ahorran dimensionalidad sin perder lo que el oido distingue. TTS modernos consumen $y \in \mathbb{R}^{80 \times T}$ donde $T$ son los frames temporales.

Paso 1: el modelo acustico. Tacotron-2 modela la sintesis como una distribucion autorregresiva sobre frames de mel:

$$p_\theta(y_{1:T} \mid x) = \prod_{t=1}^{T} p_\theta(y_t \mid y_{Donde $x$ es la secuencia de caracteres, $y_t$ es el frame de mel en el timestep $t$, y $p_\theta$ es la salida del decoder (LSTM con location-sensitive attention). XTTS-v2 de coqui-ai abandona la autorregresividad: usa un transformer no-autoregresivo condicionado a latentes de speaker. Esto cambia el juego porque la latencia pasa de O(T) a O(1) en el decoder.

Paso 2: VITS como caso moderno. VITS unifica modelo acustico y vocoder en una sola red adversarial:

$$p_\theta(y \mid c) = \int\!\!\!\int p_\theta(y \mid z, v) \cdot p_\theta(z \mid v, c) \cdot p_\theta(v) \; dz \; dv$$

Donde $c$ es el texto, $v$ es la variable latente de speaker, $z$ es el latent phonetic, y $y$ es el waveform de audio. El truco esta en el decoder iSTFT: en vez de generar 22050 samples por segundo, genera coeficientes complejos de la STFT ($\approx 96$ frames por segundo) y reconstruye via Short-Time Fourier inversa. Resultado: 200x menos pasos de generacion y XTTS-v2 corre en CPU con latencia razonable.

Paso 3: HiFi-GAN como vocoder. Cuando el modelo no es end-to-end, usa un vocoder separado. HiFi-GAN entrena un generador con perdida mixta:

$$\mathcal{L}_G = \mathcal{L}_{adv}(G; D) + \lambda_{fm}\mathcal{L}_{fm} + \lambda_{mel}\mathcal{L}_{mel}$$

Donde $\mathcal{L}_{adv}$ es la perdida adversarial, $\mathcal{L}_{fm}$ es el feature matching (distancia L1 entre features intermedias de $G$ y $D$), y $\mathcal{L}_{mel}$ es la distancia L1 entre el mel-espectrograma real y el sintetizado. Los hiperparametros $\lambda_{fm} \approx 2$ y $\lambda_{mel} \approx 45$ son los que vuelven un HiFi-GAN "natural" en vez de "metalico".

4. Implementacion Production-Ready: tts_engine

4.1 Tipos y protocolos

"""
tts_engine.py - Motor unificado TTS con backends plugables.
Production-grade: retries, verificacion de audio, metrica de RTF.
"""
from __future__ import annotations

import logging
import time
from dataclasses import dataclass, field
from enum import Enum
from pathlib import Path
from typing import Protocol, runtime_checkable

import numpy as np
import soundfile as sf

logger = logging.getLogger(__name__)


class Backend(str, Enum):
    EDGE = "edge"
    COQUI = "coqui"


@dataclass(frozen=True, slots=True)
class SynthesisRequest:
    text: str
    voice: str
    language: str = "es"
    backend: Backend = Backend.EDGE
    reference_audio: Path | None = None
    speaking_rate: float = 1.0
    pitch_shift_semitones: float = 0.0
    temperature: float = 0.65
    output_path: Path = field(default_factory=lambda: Path("output.wav"))


@dataclass(frozen=True, slots=True)
class SynthesisResult:
    output_path: Path
    sample_rate: int
    duration_seconds: float
    synthesis_seconds: float
    realtime_factor: float
    backend: Backend
    voice: str

    def __str__(self) -> str:
        return (
            f"[{self.backend.value}:{self.voice}] {self.duration_seconds:.2f}s "
            f"audio en {self.synthesis_seconds:.2f}s (RTF={self.realtime_factor:.2f})"
        )


@runtime_checkable
class TTSBackend(Protocol):
    async def synthesize(self, request: SynthesisRequest) -> SynthesisResult: ...
    async def list_voices(self, language: str) -> list[str]: ...

SynthesisRequest separa el "que quiero decir" del "quien lo dice y como". SynthesisResult incluye el RTF (real-time factor): si $RTF < 1.0$, el motor es mas rapido que el tiempo real, que es el KPI que te importa en produccion.

4.2 El motor principal

"""
tts_edge.py - Implementacion del backend edge-tts con retry y verificacion.
"""
from __future__ import annotations

import asyncio
import logging
import time
from pathlib import Path

import edge_tts
import soundfile as sf

from tts_engine import Backend, SynthesisRequest, SynthesisResult

logger = logging.getLogger(__name__)


class EdgeTTSBackend:
    """Wrapper async de edge-tts con retry exponencial."""

    MAX_RETRIES = 3
    BACKOFF_BASE_SECONDS = 0.5

    def __init__(self) -> None:
        self._client_cls = edge_tts.Communicate  # alias para inyeccion en tests

    async def list_voices(self, language: str) -> list[str]:
        voices = await edge_tts.list_voices()
        prefix = language.lower()
        return [v["ShortName"] for v in voices if v["Locale"].lower().startswith(prefix)]

    async def synthesize(self, request: SynthesisRequest) -> SynthesisResult:
        if request.backend is not Backend.EDGE:
            raise ValueError(f"EdgeTTSBackend llamado con backend={request.backend}")

        rate_pct = int(round((request.speaking_rate - 1.0) * 100))
        pitch_hz = int(round(request.pitch_shift_semitones * 5))  # 5Hz ~= 1 semitono aprox

        start = time.perf_counter()
        for attempt in range(1, self.MAX_RETRIES + 1):
            try:
                comm = self._client_cls(
                    text=request.text,
                    voice=request.voice,
                    rate=f"{rate_pct:+d}%",
                    pitch=f"{pitch_hz:+d}Hz",
                )
                await comm.save(str(request.output_path))
                break
            except (edge_tts.exceptions.NoAudioReceived, ConnectionError) as exc:
                wait = self.BACKOFF_BASE_SECONDS * (2 ** (attempt - 1))
                logger.warning(
                    "edge-tts intento %s/%s fallo (%s); retry en %.2fs",
                    attempt, self.MAX_RETRIES, exc.__class__.__name__, wait,
                )
                if attempt == self.MAX_RETRIES:
                    raise
                await asyncio.sleep(wait)

        elapsed = time.perf_counter() - start
        info = sf.info(str(request.output_path))
        duration = info.frames / info.samplerate
        return SynthesisResult(
            output_path=request.output_path,
            sample_rate=info.samplerate,
            duration_seconds=duration,
            synthesis_seconds=elapsed,
            realtime_factor=elapsed / duration,
            backend=Backend.EDGE,
            voice=request.voice,
        )

MAX_RETRIES = 3 con backoff exponencial $t_k = 0.5 \cdot 2^{k-1}$ aguanta rate-limits puntuales sin tumbar la peticion. La conversion pitch_semitones \rightarrow Hz usa $\Delta f \approx 5 \cdot \Delta s$, suficientemente buena para TTS donde el oido no distingue 2Hz de diferencia.

4.3 Utilidades de analisis y verificacion

"""
tts_verify.py - Verificacion numerica del audio sintetizado.
"""
from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path

import numpy as np
import soundfile as sf


@dataclass(frozen=True, slots=True)
class AudioReport:
    duration_seconds: float
    sample_rate: int
    rms_amplitude: float
    peak_amplitude: float
    snr_db: float
    is_valid: bool
    issues: list[str]


class AudioVerifier:
    """Validaciones numericas que un oido humano no percibe pero importan en pipeline."""

    MIN_RMS = 0.015
    MAX_PEAK = 0.97
    SNR_MIN_DB = 18.0
    MIN_DURATION_SECONDS = 0.3

    @classmethod
    def analyze(cls, audio_path: Path) -> AudioReport:
        audio, sr = sf.read(str(audio_path))
        if audio.ndim > 1:
            audio = audio.mean(axis=1)
        audio_f64 = audio.astype(np.float64)

        rms = float(np.sqrt(np.mean(audio_f64 ** 2)))
        peak = float(np.max(np.abs(audio_f64)))
        duration = len(audio_f64) / sr

        # SNR estimado: percentil 90 (senal) contra percentil 10 (piso de ruido).
        frame_size = 2048
        n_frames = len(audio_f64) // frame_size
        if n_frames > 1:
            frame_rms = np.array([
                np.sqrt(np.mean(audio_f64[i * frame_size:(i + 1) * frame_size] ** 2))
                for i in range(n_frames)
            ])
            noise_floor = float(np.quantile(frame_rms, 0.10))
            snr_db = float(20 * np.log10(rms / max(noise_floor, 1e-9)))
        else:
            snr_db = 0.0

        issues: list[str] = []
        if rms < cls.MIN_RMS:
            issues.append(f"RMS={rms:.4f} debajo del piso {cls.MIN_RMS}")
        if peak > cls.MAX_PEAK:
            issues.append(f"Pico={peak:.4f} cerca del clipping")
        if 0 < snr_db < cls.SNR_MIN_DB:
            issues.append(f"SNR={snr_db:.1f}dB debajo del umbral {cls.SNR_MIN_DB}dB")
        if duration < cls.MIN_DURATION_SECONDS:
            issues.append(f"Duracion={duration:.2f}s muy corta")

        return AudioReport(
            duration_seconds=duration,
            sample_rate=sr,
            rms_amplitude=rms,
            peak_amplitude=peak,
            snr_db=snr_db,
            is_valid=not issues,
            issues=issues,
        )

El SNR estimado divide el audio en frames de 2048 samples, calcula el RMS por frame, y compara el percentil 90 contra el percentil 10. Es estimacion, pero sirve para detectar audios "medio sordos" que pasan la escucha casual pero rompen ASR downstream.

5. Ejemplos de Uso en Casos Reales

Caso 1: locucion diaria de resumen de noticias (edge-tts). Cada noticia se sintetiza en un MP3 separado para edicion posterior.

import asyncio
import json
from datetime import UTC, datetime
from pathlib import Path

from tts_edge import EdgeTTSBackend
from tts_engine import Backend, SynthesisRequest
from tts_verify import AudioVerifier

BACKEND = EdgeTTSBackend()


async def narrar_resumen(noticias: list[dict]) -> list[Path]:
    date_str = datetime.now(UTC).strftime("%Y-%m-%d")
    out_dir = Path(f"output/resumen_{date_str}")
    out_dir.mkdir(parents=True, exist_ok=True)
    outputs: list[Path] = []

    for i, n in enumerate(noticias, start=1):
        script = f"{n['titulo']}. {n['resumen']}"
        target = out_dir / f"noticia_{i:03d}.mp3"
        req = SynthesisRequest(
            text=script,
            voice="es-CO-GonzaloNeural",
            language="es-CO",
            backend=Backend.EDGE,
            speaking_rate=0.98,
            output_path=target,
        )
        result = await BACKEND.synthesize(req)
        report = AudioVerifier.analyze(target)
        if not report.is_valid:
            raise RuntimeError(f"Audio invalido en {target}: {report.issues}")
        print(f"OK {result}")
        outputs.append(target)
    return outputs


if __name__ == "__main__":
    muestra = json.loads(Path("noticias_hoy.json").read_text())
    asyncio.run(narrar_resumen(muestra))

Verificacion inline: cualquier noticia con RMS $< 0.015$ o duracion $< 300$ms aborta el lote. Preferible a producir 50 audios y descubrirlos rotos a las 11pm.

Caso 2: clonacion de voz para asistente de marca (coqui-ai). XTTS clona una voz a partir de una referencia corta.

from pathlib import Path

from TTS.api import TTS

tts = TTS("tts_models/multilingual/multi-dataset/xtts_v2").to("cuda")
REFERENCE = Path("assets/voice_ceo_30s.wav")  # 30s limpios, sin ruido
ASSETS = Path("assets/scripts")

for script in sorted(ASSETS.glob("*.txt")):

    if not text:
        continue
    target = script.with_suffix(".wav")
    tts.tts_to_file(
        text=text,
        file_path=str(target),
        speaker_wav=str(REFERENCE),
        language="es",
        temperature=0.55,           # mas bajo = mas "serio" para CEO

Pilas con esto: XTTS necesita minimo 6 segundos de referencia limpia, pero con 30 segundos el modelo captura mejor el timbre y la prosodia habitual. Si la referencia tiene ruido, la voz clonada sale "lechosa". Recorta silencios largos mayores a 800ms y aplica denoise (RNNoise) al WAV antes de pasarlo como speaker_wav.

Caso 3: doblaje en lote con control SSML (edge-tts). SSML permite inyectar pausas y enfasis palabra por palabra.

import asyncio
from pathlib import Path

import edge_tts

SSML_TEMPLATE = """<speak version="1.0" xmlns="http://www.w3.org/2001/10/synthesis" xml:lang="es-CO">
  <voice name="es-CO-GonzaloNeural">
    <prosody rate="{rate}" pitch="{pitch}">
      <break time="{pre}s"/>
      {text}
      <break time="{post}s"/>
    </prosody>
  </voice>
</speak>"""


async def doblar_clip(text: str, target: Path, emphasize_words: list[str]) -> None:
    marked = " ".join(
        f"<emphasis level='strong'>{w}</emphasis>" if w in emphasize_words else w
        for w in text.split()
    )
    ssml = SSML_TEMPLATE.format(
        rate="+0%", pitch="+0Hz", pre="0.5", post="0.4", text=marked,
    )
    comm = edge_tts.Communicate(ssml, voice="es-CO-GonzaloNeural")
    await comm.save(str(target))


async def main() -> None:
    await doblar_clip(
        "Oferta valida solo hoy, no hay fiesta con esta promocion.",
        target=Path("oferta.mp3"),
        emphasize_words=["valida", "hoy"],
    )


asyncio.run(main())

La diferencia entre "Oferta valida solo hoy" y "Oferta VALIDA solo HOY" la percibe el oido aunque midan el mismo RMS. Para voice-overs publicitarios esto importa mas que cualquier truco de modelo.

6. Debugging: Cuando Todo se Va a la Mierda

Problema A: audio sale "lechoso" / con ruido de fondo en XTTS. Causa habitual: referencia contaminada por ruido ambiente.

"""
Repro y deteccion: XTTS clonacion con referencia ruidosa.
"""
from pathlib import Path

import numpy as np
import soundfile as sf

referencia = Path("assets/voice_con_ruido.wav")
audio, sr = sf.read(str(referencia))
rms_global = np.sqrt(np.mean(audio.astype(np.float64) ** 2))
print(f"RMS global: {rms_global:.4f}")  # tipicamente > 0.05 si hay ruido

Deteccion numerica: un audio limpio para XTTS debe tener RMS global entre $0.05$ y $0.20$. Si supera $0.30$, hay ruido. Si esta por debajo de $0.03$, la voz queda lejos del mic y el clon sale opaco.

Soluciones (en orden de esfuerzo):

  1. Pasada rapida: aplica un high-pass filter a 80Hz para cortar ruido de aire acondicionado. SciPy: scipy.signal.butter(4, 80, btype='high', fs=sr).
  2. Mejor: corre RNNoise (pip install rnnoise) sobre la referencia. Quita ruido sin destruir la voz.
  3. Definitivo: graba la referencia en una boompole con muerta acustica. 30 segundos limpios valen mas que 5 minutos post-procesados.

Problema B: latencia de cold-start mata el SLA (coqui-ai). Cuando cargas XTTS por primera vez, la inferencia tarda 4-6s extra mientras compila el grafo CUDA y carga el tokenizer.

Deteccion numerica: instrumenta el endpoint y mide $t_{first\_byte} - t_{request\_arrived}$. Si supera 3s en mas del 5% de las peticiones, tienes cold start.

"""
Warmup deterministico para coqui-ai al arrancar el servicio.
"""
import logging
from pathlib import Path

from TTS.api import TTS

logger = logging.getLogger(__name__)
WARMUP_TEXT = "Calibrando motor de sintesis, espere por favor."


def warm_up(model: TTS, reference: Path) -> None:
    logger.info("Iniciando warmup de XTTS-v2")
    model.tts_to_file(
        text=WARMUP_TEXT,
        file_path="/tmp/_warmup.wav",
        speaker_wav=str(reference),
        language="es",
        speed=1.0,
    )
    logger.info("Warmup terminado")

Otras soluciones:

  1. Cache de modelo: carga XTTS una sola vez al arrancar el proceso (no en cada request). En FastAPI, en app.on_event("startup").
  2. Precomputed embeddings: si tu voz de marca es fija, extrae el embedding del speaker una vez con tts.synthesizer.tts_model.get_conditioning_latents(...) y serializalo a disco. Pasarlo precomputado salta el encoder y baja la latencia $\approx 40\%$.
  3. CUDA graphs: captura el grafo con torch.cuda.graph para frases de longitud fija. Para latencias sub-50ms en GPU es la unica salida.

Problema C: edge-tts devuelve 403 / WebSocket cierra antes de tiempo. Esto pasa cuando Microsoft rota el endpoint o tu IP acumula demasiadas conexiones concurrentes. Deteccion: busca en logs el patron WebSocketException o NoAudioReceived. Si pasa mas de 3 veces por hora, te rate-limitearon. Soluciones:

  1. Pool de IPs: rota entre 3-5 IPs de salida (VPN corporativa, peering dedicado) para distribuir el rate limit. Cada IP maneja $\approx 5$ conexiones concurrentes.
  2. Fallback local: combina edge-tts con coqui-ai. Usa edge como primario y coqui como respaldo cuando edge falle 3 veces seguidas.
  3. Cache de frases: las locuciones de tu IVR ("Presione 1 para ventas") se repiten literalmente. Hashea el texto y sirve desde disco un MP3 precomputado.

7. Optimizaciones de Produccion

Optimizacion 1: streaming por chunks para latencia sub-300ms. edge-tts soporta Communicate.stream() que entrega chunks MP3 a medida que llegan del servidor.

import edge_tts
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


async def stream_audio(text: str, voice: str):
    comm = edge_tts.Communicate(text, voice)
    async for chunk in comm.stream():
        if chunk["type"] == "audio":
            yield chunk["data"]  # bytes MP3, listos para pipe al response


@app.get("/tts/stream")
async def tts_stream(text: str, voice: str = "es-CO-GonzaloNeural"):
    return StreamingResponse(stream_audio(text, voice), media_type="audio/mpeg")

Pipelinea esto con un cliente que espera el primer chunk y lo envia al usuario mientras el resto sigue generando. Trade-off honesto: streaming reduce el "time-to-first-byte" pero NO el tiempo total. Si tu usuario no reproduce el audio hasta que llega el chunk final, no has ganado nada. Solo vale la pena si el cliente es Web Audio API o un player que arranca al primer chunk.

Optimizacion 2: cuantizacion INT8 del modelo coqui-ai. Cargar XTTS-v2 en FP16 ya baja VRAM de 4GB a 2GB. Cuantizar a INT8 con bitsandbytes lo lleva a $\approx 1$GB, suficiente para correr en una T4 sin pedir una A100.

import torch
from TTS.api import TTS

tts = TTS("tts_models/multilingual/multi-dataset/xtts_v2").to("cuda")
tts.synthesizer.tts_model = torch.quantization.quantize_dynamic(
    tts.synthesizer.tts_model, {torch.nn.Linear}, dtype=torch.qint8,
)

Cuidado: la cuantizacion INT8 degrada entre un 3-8% en la metrica MOS (Mean Opinion Score) de naturalidad. Para voice-overs publicitarios donde cada matiz cuenta, usa FP16. Para IVR o bots, INT8 va perfecto.

8. Conclusion: Por Que Esto te Salva el Pellejo en Produccion

  • Latencia deterministica. Midiendo RTF en cada peticion sabes inmediatamente cuando el backend degrada. $RTF < 1.0$ significa que el motor genera mas rapido que el tiempo real; $RTF > 1.0$ es tu primera alerta de saturacion.
  • Fallback graceful entre edge-tts (rapido, cero costo, voces preconstruidas) y coqui-ai (privado, voz clonada, costoso en GPU). Si uno falla, el otro absorbe.
  • Calidad verificable con AudioVerifier: SNR $> 18$dB, RMS $> 0.015$, duracion $> 300$ms. Cualquier audio que rompa estos topes se descarta antes de salir al cliente.
  • Resiliencia ante rate-limits con el patron retry $t_k = 0.5 \cdot 2^{k-1}$ y cacheo de frases repetitivas. Aguanta picos del 300% sin tumbar el servicio.
  • Audio escalable sin regalarle data a terceros. coqui-ai corre local y edge-tts no requiere contrato enterprise para empezar.

Checklist rapido antes de salir a produccion:

  1. [ ] Decide backend por caso de uso: edge-tts para IVR/contenido, coqui-ai para branding/privacidad.
  2. [ ] Mide RTF en condiciones reales (no en tu laptop de desarrollo).
  3. [ ] Warm-up del modelo coqui-ai al arrancar el proceso, no al primer request.
  4. [ ] Verificador de audio (AudioVerifier) en el pipeline, no al final.
  5. [ ] Cache de frases repetidas: cualquier texto con hash recurrente va a disco.
  6. [ ] Metrica de RTF por voz (algunas voces de Azure son mas lentas que otras por idioma).
  7. [ ] Fallback automatico: si edge-tts falla 3 veces seguidas, enruta a coqui-ai.

Mete este motor en tu pipeline, mide los numeros, y el viernes a las 6pm tu canal de voz sigue arriba mientras los demas estan peleandose con tickets. 🔥
