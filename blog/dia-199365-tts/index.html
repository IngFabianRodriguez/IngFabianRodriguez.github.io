Anomaly Detection — El Arte de Encontrar Lo Que No Debería Existir

18 de julio de 2026
anomaly-detectionautoencoderisolation-forestpytorch

Hagámosle pues, parcero. Día 199 y hoy nos metemos en un tema que parece sencillo pero es pura ciencia: cómo encontrar las cosas raras, las anomalías, eso que no debería estar ahí. Imagínese que usted tiene una fábrica de arepas en Bogotá y de repente una mañana el sistema detecta que una arepa salió con 500 grados centígrados de temperatura — eso es una anomalía. Eso es lo que vamos a aprender a detectar con código real en PyTorch.

¿Qué Es Anomaly Detection?

El detection de anomalías es la técnica de identificar patrones que no concuerdan con el comportamiento esperado de un sistema. A diferencia de la clasificación tradicional donde tenemos etiquetas de "normal" y "anormal", aquí generalmente solo tenemos datos normales para entrenar. El modelo aprende qué es "normal" y todo lo que se desvíe demasiado lo marca como anomalía.

Esto es inmensamente útil en:

  • Detección de fraude: Transacciones que no siguen el patrón habitual de un usuario
  • Monitoreo industrial: Sensores que detectan maquinaria funcionando fuera de parámetros
  • Seguridad informática: Tráfico de red sospechoso que indica un ataque
  • Control de calidad: Productos defectuosos en una línea de producción
  • Salud: Detectar enfermedades raras o condiciones anormales en exámenes

La matemática detrás es elegante: capturamos la distribución de los datos normales y medimos qué tan improbable es un nuevo dato bajo esa distribución. Si la probabilidad es muy baja, temos una anomalía.

Los Tres Grandes Métodos

1. Isolation Forest — El Más Sencillo y Efectivo

Funciona con un principio elegante: es más fácil aislar anomalías que datos normales. Imagine que tiene una lista de números [2, 3, 4, 5, 6, 100]. El 100 se aísla mucho más rápido con splits aleatorios que los demás. Por eso se llama "isolation" — aísla las anomalías.

import numpy as np
from sklearn.ensemble import IsolationForest
import torch

# Ejemplo: datos normales de sensores industriales
np.random.seed(42)
normal_data = np.random.randn(1000, 4) * np.array([10, 5, 2, 8]) + np.array([50, 30, 15, 100])
# Añadir algunas anomalías (outliers)
anomalies = np.random.randn(20, 4) * np.array([50, 30, 20, 40]) + np.array([50, 30, 15, 100])

# Combinar datos
X = np.vstack([normal_data, anomalies])
y_true = np.hstack([np.zeros(1000), np.ones(20)])  # 0=normal, 1=anomalía

# Entrenar Isolation Forest
iso_forest = IsolationForest(
    n_estimators=200,
    contamination=0.02,  # esperamos ~2% de anomalías
    random_state=42
)
iso_forest.fit(X)

# Predecir: -1 = anomalía, 1 = normal
predictions = iso_forest.predict(X)
scores = iso_forest.decision_function(X)  # entre más bajo, más anómalo

print(f"Anomalías detectadas: {np.sum(predictions == -1)}")
print(f"Score ejemplo (normal alto, anómalo bajo): {scores[:5]}")

Encuentra el hiperplano que separa los datos normales del origen en un espacio de alta dimensión. Funciona bien cuando los datos tienen formas no elípticas.

3. Autoencoder — El Deep Learning para Anomalías

Aquí es donde entra PyTorch. El autoencoder aprende a comprimir y reconstruir datos normales. Si el error de reconstrucción es alto, significa que el dato es anómalo — porque el autoencoder no fue entrenado para reconstruir ese tipo de datos.

La idea es simple pero poderosa:

  • Encoder: comprime los datos a una representación latente pequeña
  • Decoder: reconstruye los datos desde esa representación
  • Entrenamiento: solo con datos normales, minimizando error de reconstrucción
  • Inferencia: si Reconstruction Error > threshold → anomalía
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

class AnomalyAutoencoder(nn.Module):
    """
    Autoencoder para detección de anomalías.
    Entrenamos solo con datos normales.
    """
    def __init__(self, input_dim, latent_dim=8):
        super().__init__()
        
        # Encoder: comprime input_dim -> latent_dim
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 32),
            nn.ReLU(),
            nn.BatchNorm1d(32),
            nn.Linear(32, 16),
            nn.ReLU(),
            nn.BatchNorm1d(16),
            nn.Linear(16, latent_dim),
            nn.ReLU()
        )
        
        # Decoder: reconstruye latent_dim -> input_dim
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 16),
            nn.ReLU(),
            nn.BatchNorm1d(16),
            nn.Linear(16, 32),
            nn.ReLU(),
            nn.BatchNorm1d(32),
            nn.Linear(32, input_dim)
        )
    
    def forward(self, x):
        z = self.encoder(x)
        x_recon = self.decoder(z)
        return x_recon, z
    
    def get_reconstruction_error(self, x):
        """MSE entre input y reconstrucción"""
        x_recon, _ = self.forward(x)
        return torch.mean((x - x_recon) ** 2, dim=1)


def train_anomaly_detector(X_normal, epochs=100, batch_size=64, latent_dim=8, threshold=None):
    """
    Entrena autoencoder para detección de anomalías.
    X_normal: datos de entrenamiento SOLO con observaciones normales.
    """
    device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
    print(f"Entrenando en: {device}")
    
    # Convertir a tensores
    X_tensor = torch.FloatTensor(X_normal).to(device)
    dataset = TensorDataset(X_tensor)
    dataloader = DataLoader(dataset, batch_size=batch_size, shuffle=True)
    
    input_dim = X_normal.shape[1]
    model = AnomalyAutoencoder(input_dim, latent_dim).to(device)
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-5)
    scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, patience=10, factor=0.5)
    
    model.train()
    for epoch in range(epochs):
        total_loss = 0
        for batch in dataloader:
            x = batch[0]
            x_recon, _ = model(x)
            
            # Error de reconstrucción
            loss = nn.MSELoss()(x_recon, x)
            
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            total_loss += loss.item()
        
        avg_loss = total_loss / len(dataloader)
        scheduler.step(avg_loss)
        
        if epoch % 20 == 0:
            print(f"Epoch {epoch:3d} | Loss: {avg_loss:.6f}")
    
    # Calcular threshold usando datos normales
    model.eval()
    with torch.no_grad():
        X_device = X_tensor.to(device)
        reconstruction_errors = model.get_reconstruction_error(X_device).cpu().numpy()
    
    if threshold is None:
        # Threshold: percentil 95 de errores de reconstrucción en datos normales
        threshold = np.percentile(reconstruction_errors, 95)
    
    print(f"\nThreshold calculado (percentil 95): {threshold:.6f}")
    print(f"Rango de errores normales: [{reconstruction_errors.min():.6f}, {reconstruction_errors.max():.6f}]")
    
    return model, threshold


def detect_anomalies(model, X, threshold):
    """Detecta anomalías en nuevos datos."""
    device = next(model.parameters()).device
    model.eval()
    
    with torch.no_grad():
        X_tensor = torch.FloatTensor(X).to(device)
        errors = model.get_reconstruction_error(X_tensor).cpu().numpy()
    
    predictions = (errors > threshold).astype(int)
    scores = errors  # entre más alto, más anómalo
    
    return predictions, scores

from sklearn.metrics import roc_auc_score, average_precision_score
import matplotlib.pyplot as plt

def compare_methods(normal_data, test_data, y_true):
    """Compara Isolation Forest, One-Class SVM y Autoencoder."""
    
    # 1. Isolation Forest
    iso_forest = IsolationForest(contamination=0.02, random_state=42)
    iso_forest.fit(normal_data)
    scores_iso = -iso_forest.decision_function(test_data)  # negate para que alto = anomalía
    
    # 2. One-Class SVM
    scaler = StandardScaler()
    normal_scaled = scaler.fit_transform(normal_data)
    test_scaled = scaler.transform(test_data)
    
    ocsvm = OneClassSVM(kernel='rbf', nu=0.02)
    ocsvm.fit(normal_scaled)
    scores_svm = -ocsvm.decision_function(test_scaled)  # negate
    
    # 3. Autoencoder (entrenado ya)
    _, ae_threshold = train_anomaly_detector(normal_data, epochs=50)
    _, scores_ae = detect_anomalies(model, test_data, ae_threshold)
    
    # Calcular métricas AUC
    results = {
        'Isolation Forest': roc_auc_score(y_true, scores_iso),
        'One-Class SVM': roc_auc_score(y_true, scores_svm),
        'Autoencoder': roc_auc_score(y_true, scores_ae)
    }
    
    print("\nAUC-ROC Comparison:")
    print("-" * 40)
    for name, auc in sorted(results.items(), key=lambda x: x[1], reverse=True):
        print(f"  {name:20s}: {auc:.4f}")
    
    return results

Los 3 Errores Más Comunes

Error 1: Entrenar con Datos Contaminados con Outliers

El problema: Uno de los errores más graves es entrenar el modelo de anomaly detection incluyendo anomalías en los datos de entrenamiento. Si el autoencoder ve anomalías durante el entrenamiento, aprenderá a reconstruirlas también, y después no las detectará. Es como enseñarle a un perro a no ladrar incluyéndole el ladrido en el entrenamiento — no sirve.

En Isolation Forest pasa lo mismo: si hay anomalías en los datos de entrenamiento, el modelo las considera "normales" porque aprende de todo lo que le das.

La solución: Limpiar los datos de entrenamiento rigurosamente. Si no puede garantizar datos 100% limpios, use métodos robustos a contaminación como IsolationForest con contamination='auto' o técnicas de robust covariance estimation.

# MAL: entrenar con datos contaminados
all_data = np.vstack([normal_data, anomalies])  # NO HACER ESTO
iso_forest_bad = IsolationForest()
iso_forest_bad.fit(all_data)  # El modelo aprende las anomalías como normales

# BIEN: entrenar SOLO con datos normales
iso_forest_good = IsolationForest()
iso_forest_good.fit(normal_data)  # Solo datos normales

Error 2: No Definir el Threshold Correctamente

El problema: Muchos practitioners usan threshold fijo sin analizar la distribución de errores de reconstrucción. Un threshold muy bajo causa muchos false positives (datos normales marcados como anomalías) y uno muy alto causa muchos false negatives (anomalías que no se detectan).

Imagine que su sistema de detección de fraude tiene 50% de false positives — sus clientes estarían Furiosos cada vez que su tarjeta válida es rechazada.

La solución: Analice la distribución de scores en datos normales. Métodos estadísticos robustos:

def calculate_optimal_threshold(scores_normal, percentile=95, method='percentile'):
    """
    Calcula threshold óptimo para detección de anomalías.
    
    methods:
    - percentile: usa el percentil especificado de scores normales
    - gaussian: asume distribución normal y usa mean + 3*std
    - iqr: usa 1.5 * IQR (robust a outliers)
    """
    if method == 'percentile':
        threshold = np.percentile(scores_normal, percentile)
    elif method == 'gaussian':
        mean = np.mean(scores_normal)
        std = np.std(scores_normal)
        threshold = mean + 3 * std  # 3-sigma rule
    elif method == 'iqr':
        q1 = np.percentile(scores_normal, 25)
        q3 = np.percentile(scores_normal, 75)
        iqr = q3 - q1
        threshold = q3 + 1.5 * iqr
    else:
        raise ValueError(f"Método desconocido: {method}")
    
    return threshold

# Analizar diferentes thresholds
print("Comparación de métodos de threshold:")
for method in ['percentile', 'gaussian', 'iqr']:
    thresh = calculate_optimal_threshold(reconstruction_errors, method=method)
    preds = (reconstruction_errors > thresh).astype(int)
    tp = np.sum((preds == 1) & (y_true == 1))
    fp = np.sum((preds == 1) & (y_true == 0))
    print(f"  {method:12s}: threshold={thresh:.4f}, TP={tp}, FP={fp}")

Error 3: Usar Supervised Classification Cuando es Unsupervised

El problema: El error más conceptual. Muchos proyectos de anomaly detection comienzan recopilando datos etiquetadas: "esta transacción es fraude", "este equipo falló". Y entonces usan un clasificador supervisado (Random Forest, XGBoost, red neuronal con softmax) para predecir fraude vs. no-fraude. Esto está mal en muchos escenarios reales porque:

  • Las anomalías son raras por definición: imbalance extremo (1:1000 o peor)
  • Nuevos tipos de anomalías: un modelo supervisado solo detecta lo que ya vio
  • Costo de etiquetas: etiquetar anomalías es difícil y costoso

La solución: Usar métodos específicamente diseñados para anomaly detection. Si tiene algunas etiquetas, use semi-supervised o weakly-supervised approaches. Methods como Isolation Forest y Autoencoders no necesitan etiquetas — solo aprenden la distribución de lo normal.

# MAL: supervised classification con imbalance severo
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split

# 1000 normales, solo 10 anomalías etiquetadas
X_train, X_test, y_train, y_test = train_test_split(test_data, y_true, test_size=0.3, random_state=42)

clf = RandomForestClassifier(n_estimators=100)
clf.fit(X_train, y_train)  # El modelo estará sesgado hacia "normal"
y_pred = clf.predict(X_test)

# Reporte muestra el problema: no detecta anomalías
print(classification_report(y_test, y_pred))

# BIEN: unsupervised anomaly detection
predictions, scores = detect_anomalies(model, X_test, threshold)
print(classification_report(y_test, predictions))

Resumen y Cierre

Hoy aprendimos a detectar lo que no debería existir. Vimos tres métodos poderosos:

  • Isolation Forest: rápido, escalable, excelente para datos de alta dimensión
  • One-Class SVM: buen rendimiento, pero más lento en datasets grandes
  • Autoencoder: captura patrones complejos, ideal para datos no estructurados

Recuerde siempre:

  1. Entrenar solo con datos normales
  2. Calcular el threshold correctamente usando la distribución real
  3. Elegir el método adecuado al problema — no todo es classification supervisada
