🎯 ¿Qué Es Tokenization Y Por Qué Es El Primer Paso Crítico?

Tokenization es el proceso de convertir texto plano en secuencias de números enteros (tokens) que un modelo puede procesar. No es simplemente "dividir por espacios" — es el arte de representar el lenguaje de manera que preserva información semántica mientras maneja eficientemente el vocabulario.

Existen tres categorías fundamentales de tokenization:

  • Word-level tokenization: Cada palabra es un token. Problema: vocabulario enorme y OOV (out-of-vocabulary) guaranteed.
  • Character-level tokenization: Cada carácter es un token. Funciona para cualquier texto pero genera secuencias larguísimas.
  • Subword tokenization: La mayoría de las palabras se dividen en subpartes lógicas. Balanced approach.

Los modelos modernos como BERT, GPT-2, GPT-3, LLaMA todos usan subword tokenization. Específicamente:

  • BPE (Byte Pair Encoding): Usado por GPT-2, RoBERTa, y la mayoría de modelos degenerativos.
  • WordPiece: Usado por BERT y sus variantes.
  • SentencePiece: Usado por T5, XLNet, MarianMT. Unificado y entrenado directamente sobre texto raw sin pre-tokenization.

📐 La Matemática Detrás De BPE — El Algoritmo

BPE es elegante en su simplicidad. Parte de un vocabulario donde cada carácter es un token individual, y va fusionando iterativamente el par más frecuente. La función de merge se selecciona maximizando:

score(c1, c2) = freq(c1c2) / (freq(c1) * freq(c2))

Esta fórmula evita fusionar pares que involucran tokens ya muy frecuentes (como espacios). En código PyTorch:

import torch
from collections import defaultdict
import re

def get_stats(vocab):
    """Cuenta frecuencia de pares de tokens adyacentes."""
    pairs = defaultdict(int)
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[(symbols[i], symbols[i+1])] += freq
    return pairs

def merge_vocab(pair, v_in):
    """Fusiona el par más frecuente en el vocabulario."""
    v_out = {}
    bigram = re.escape(pair[0] + ' ' + pair[1])
    p = re.compile(r'(?<!\S)' + bigram + r'(?!\S)')
    for word in v_in:
        w_out = p.sub(''.join(pair), word)
        v_out[w_out] = v_in[word]
    return v_out

def bpe_train(corpus, num_merges=100):
    """
    Entrena un tokenizador BPE desde cero.
    
    Args:
        corpus: Lista de textos para entrenar
        num_merges: Número de fusiones a realizar
    
    Returns:
        vocab: Vocabulario entrenado con merges aplicados
        merges: Lista de tuplas (token1, token2) que fueron fusionadas
    """
    # Inicializar vocabulario con caracteres individuales
    vocab = defaultdict(int)
    for text in corpus:
        # Añadir marker de fin de palabra
        words = text.lower().split()
        for word in words:
            word = ' '.join(list(word) + ['</w>'])
            vocab[word] += 1
    
    # Proceso de fusión iterativa
    merges = []
    for i in range(num_merges):
        pairs = get_stats(vocab)
        if not pairs:
            break
        # Encontrar el par más frecuente
        best_pair = max(pairs, key=pairs.get)
        if pairs[best_pair] < 2:  # Stop si frecuencia es muy baja
            break
        # Fusionar
        vocab = merge_vocab(best_pair, vocab)
        merges.append(best_pair)
        if (i + 1) % 20 == 0:
            print(f"[BPE] Merge {i+1}/{num_merges}: {best_pair} "
                  f"(freq={pairs[best_pair]})")
    
    return vocab, merges

def tokenize_text(text, vocab, merges):
    """Tokeniza texto usando vocabulario BPE entrenado."""
    # Tokenización básica a caracteres
    tokens = []
    for word in text.lower().split():
        word_tokens = list(word) + ['</w>']
        tokens.extend(word_tokens)
    
    # Aplicar merges en orden
    for merge in merges:
        merge_str = merge[0] + merge[1]
        new_tokens = []
        i = 0
        while i < len(tokens):
            if i < len(tokens) - 1 and tokens[i] == merge[0] and tokens[i+1] == merge[1]:
                new_tokens.append(merge_str)
                i += 2
            else:
                new_tokens.append(tokens[i])
                i += 1
        tokens = new_tokens
    
    return tokens

# Ejemplo de entrenamiento
corpus = [
    "el gato come pescado",
    "el perro come carne", 
    "el gato duerme mucho",
    "el perro duerme en la casa",
    "mucho tiempo juntos",
]

print("=== Entrenando BPE ===")
vocab, merges = bpe_train(corpus, num_merges=50)

print(f"\n=== Vocabulario final ({len(vocab)} palabras) ===")
print("Sample:", list(vocab.items())[:5])

print(f"\n=== Merges realizados ({len(merges)} fusiones) ===")
for m in merges[:10]:
    print(f"  {m}")

# Tokenización de ejemplo
test_text = "el gato duerme"
result = tokenize_text(test_text, vocab, merges)
print(f"\n=== Tokenización ===")
print(f"Input: '{test_text}'")
print(f"Tokens: {result}")
print(f"Número de tokens: {len(result)}")

⚠️ Los 3 Errores Que El 85% De Los Practitioners Cometen

❌ Error 1: No Usar Subword Tokenization — OOV Garantizado

El problema: Usar tokenization por palabras completas causa que cualquier palabra fuera del vocabulario (OOV) sea convertida a [UNK]. Si tu vocabulario tiene 50,000 palabras y encuentras "neuronavigatión", se convierte en token desconocido.

El impacto: Modelos con word-level tokenization tienen accuracy terrible en datasets con palabras fuera del training set. En benchmarks como FLUD (Few-shot Language Understanding Dataset) esto puede significar 40% menos accuracy.

La solución:

# ❌ WRONG: Word-level tokenization con OOV
def bad_tokenize(text):
    words = text.lower().split()
    return [word_to_id.get(w, UNK_ID) for w in words]

# ✅ CORRECT: Subword tokenization
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
tokens = tokenizer.encode(text, add_special_tokens=False)
# "neuronavigation" → ['ne', '##uro', '##nav', '##igation']

❌ Error 2: Vocabulary Muy Pequeño — Fragmentación Excesiva

El problema: Elegir un vocabulary size muy pequeño (ej: 10,000 tokens cuando el dataset tiene alta diversidad léxica) causa que palabras comunes se fragmenten en múltiples subwords, aumentando la longitud de secuencias 3-4x.

El impacto:

  • Secuencias 3-4x más largas = 3-4x más costo computacional
  • Mayor uso de memoria GPU
  • Inferencia más lenta
  • Modelos más difíciles de entrenar (gradient propagation más largo)

La solución:

# Fórmula empírica para vocabulary size mínimo:
# vocab_size ≈ sqrt(total_unique_subwords_in_corpus) * 1.5

# O usar rule of thumb:
# - English general purpose: 30,000-50,000
# - Domain-specific (medical, legal): 50,000-100,000  
# - Multilingual: 100,000+

# Si entrenas desde cero:
from tokenizers import Tokenizer
from tokenizers.models import BPE

tokenizer = Tokenizer(BPE(unk_token="[UNK]"))
trainer = Tokenizer.trainers.BpeTrainer(
    vocab_size=30000,  # ← Ajusta según tu corpus
    min_frequency=2,
    special_tokens=["[PAD]", "[UNK]", "[CLS]", "[SEP]", "[MASK]"]
)

❌ Error 3: Tokenizer/Model Mismatch — El Error Silencioso

El problema: Entrenar un modelo con un tokenizer y luego cargar los pesos con otro tokenizer diferente. Esto pasa frecuentemente cuando:

  • Copias la configuración del modelo pero no el tokenizer
  • Usas fine-tuning sin guardar el tokenizer junto con el modelo
  • Intercambias tokenizers entre modelos de arquitecturas similares

El impacto: El modelo genera garbage porque los IDs de los tokens no corresponden a las mismas piezas de texto.

La solución:

# ✅ SIEMPRE guarda tokenizer y modelo juntos
model.save_pretrained("./my_model")
tokenizer.save_pretrained("./my_model")

# ✅ Cargar ambos juntos
from transformers import AutoModel, AutoTokenizer
model = AutoModel.from_pretrained("./my_model")
tokenizer = AutoTokenizer.from_pretrained("./my_model")

# ❌ WRONG: Cargar modelo sin tokenizer
model = AutoModel.from_pretrained("./my_model")  # Sin tokenizer!
outputs = model(**tokenizer("Hello world"))  # ❌ IDs mal mapeados

# ✅ CORRECT: Siempre verificar match
assert model.config.vocab_size == tokenizer.vocab_size, "Vocab mismatch!"

💡 Tips Para Producción

  • Cachea tokenizaciones: Si tokenizas el mismo texto múltiples veces (ej: durante validación), cachea los resultados. Esto puede reducir tiempo de inferencia 10x.
  • Usa fast tokenizer: Los tokenizadores basados en Rust (fast tokenizers) son 10-20x más rápidos que los de Python puro.
  • Configura truncation: Siempre define max_length y truncation=True explícitamente. El default behavior varía entre tokenizadores.
  • Benchmark en tu dominio: Un tokenizer que funciona bien en English puede ser terrible en Spanish. Evalúa siempre con datos de tu dominio.
  • Considera el padding strategy: Longest vs. max_length. Para batched inference, max_length con padding reduce variaciones.

📊 Resumen — Lo Que Debes Llevarte

  • Subword > Word-level: Siempre usa BPE, WordPiece o SentencePiece. El OOV problem te va a explotar.
  • Vocab size importa: Ni muy pequeño (fragmentación) ni muy grande (memoria). 30k-50k es buen punto de partida para English.
  • Special tokens no son opcionales: [PAD], [UNK], [CLS], [SEP], [MASK] existen por razones específicas. Respétalos.
  • Tokenizer y modelo son un par: Nunca los separes. Siempre guardalos y precargalos juntos.
  • Mide comprensión: Antes de entrenar, analiza la distribución de longitud de tokens en tu dataset. Esto te dice mucho sobre qué tan bien tu tokenizer representa tu dominio.
