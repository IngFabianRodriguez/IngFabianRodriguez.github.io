Active Learning y Human-in-the-Loop — La técnica que el 70% salta y que ahorra labeling costs del 80%

03 de octubre de 2026

Etiqutar datos es como el peyeo en Bogotá — todos saben que hay que hacerlo, nadie quiere hacerlo. 10,000 imágenes para labeling, un equipo de 3 annotators, semanas de trabajo y al final tu modelo apenas supera el baseline. Lo que el 70% de los equipos no sabe es que con active learning puedes lograr el mismo performance labeleando el 20% de los datos. En este artículo te explico cómo.

Qué es Active Learning?

Active learning es un paradigma de ML donde el modelo pide explícitamente más labels para las muestras que más lo van a ayudar. En lugar de labelar datos al azar, el modelo identifica las instances donde su incertidumbre es más alta y las manda a un humano.

La idea central: no todas las muestras son iguales. Una foto de un perro obvious le enseña poco al modelo. Pero una donde hay un perro medio tapado por una sombra, eso es gold.

Formalmente, dado un pool de datos no etiquetados \( U \) y un conjunto pequeño inicial etiquetado \( L \), el ciclo de active learning es:

  1. Entrenar modelo \( f \) con \( L \)
  2. Evaluar incertidumbre en \( U \)
  3. Seleccionar las \( k \) samples más informativas
  4. Obtener labels humanos para esas \( k \) samples
  5. Agregar a \( L \), repetir

La matemática de la incertidumbre

Cómo medimos "cuánto va a ayudar esta muestra"? Tres métricas principales:

1. Least Confidence (LC)

La más simple: para cada sample, tomamos la clase con mayor probabilidad:

$$ LC(x) = 1 - P_\theta(\hat{y} | x) $$ Donde \( \hat{y} = \arg\max_y P(y|x) \). Muestras con LC alto son las que el modelo menos confía.

2. Margin Sampling

Para problemas multi-clase, la diferencia entre las dos clases más probables:

$$ Margin(x) = P_\theta(y_1|x) - P_\theta(y_2|x) $$ Donde \( y_1 \) y \( y_2 \) son las clases top. Un margin pequeño = el modelo está entre dos clases = alta incertidumbre.

3. Entropy

La más completa — mide incertidumbre en toda la distribución:

$$ H(x) = -\sum_y P_\theta(y|x) \log P_\theta(y|x) $$ Alta entropía = el modelo está evenly split entre varias clases.

import numpy as np
from scipy.stats import entropy

def uncertainty_scores(model, X_pool, method="entropy"):
    """Calcula scores de incertidumbre para un pool de datos no etiquetados."""
    probs = model.predict_proba(X_pool)
    
    if method == "least_confidence":
        # 1 - max probability
        scores = 1 - probs.max(axis=1)
    elif method == "margin":
        # Diferencia entre top 2 clases
        sorted_probs = np.sort(probs, axis=1)
        scores = sorted_probs[:, -1] - sorted_probs[:, -2]
    elif method == "entropy":
        # Entropy de la distribución
        scores = entropy(probs.T)
    else:
        raise ValueError(f"Unknown method: {method}")
    
    return scores

def select_samples(X_pool, scores, n_select, strategy="top"):
    """Selecciona las samples más informativas."""
    if strategy == "top":
        # Top-k por score
        indices = np.argsort(scores)[-n_select:]
    elif strategy == "random":
        # Baseline random para comparar
        indices = np.random.choice(len(X_pool), n_select, replace=False)
    elif strategy == "threshold":
        # Todas sobre un threshold
        indices = np.where(scores > np.percentile(scores, 90))[0][:n_select]
    return indices

El loop completo de Active Learning

class ActiveLearningLoop:
    def __init__(self, model, X_init, y_init, X_pool, 
                 query_strategy="entropy", n_iterations=10, batch_size=100):
        self.model = model
        self.X_labeled = X_init.copy()
        self.y_labeled = y_init.copy()
        self.X_pool = X_pool.copy()
        self.query_strategy = query_strategy
        self.n_iterations = n_iterations
        self.batch_size = batch_size
        self.history = {"iteration": [], "accuracy": [], "n_labeled": []}
    
    def query(self):
        """Selecciona samples para labeling usando la estrategia elegida."""
        scores = uncertainty_scores(self.model, self.X_pool, self.query_strategy)
        indices = select_samples(self.X_pool, scores, self.batch_size, strategy="top")
        return indices
    
    def update(self, indices, labels):
        """Agrega las nuevas samples etiquetadas al training set."""
        self.X_labeled = np.vstack([self.X_labeled, self.X_pool[indices]])
        self.y_labeled = np.concatenate([self.y_labeled, labels])
        self.X_pool = np.delete(self.X_pool, indices, axis=0)
    
    def evaluate(self, X_test, y_test):
        """Evalúa el modelo actual."""
        acc = self.model.score(X_test, y_test)
        return acc
    
    def run(self, X_test, y_test, human_labeler):
        """Corre el loop completo de active learning."""
        for i in range(self.n_iterations):
            # 1. Entrenar
            self.model.fit(self.X_labeled, self.y_labeled)
            
            # 2. Evaluar
            acc = self.evaluate(X_test, y_test)
            self.history["iteration"].append(i)
            self.history["accuracy"].append(acc)
            self.history["n_labeled"].append(len(self.y_labeled))
            
            print(f"Iter {i}: acc={acc:.4f}, labeled={len(self.y_labeled)}")
            
            # 3. Query
            indices = self.query()
            
            # 4. Human labeling
            new_labels = human_labeler.label(self.X_pool[indices])
            
            # 5. Update
            self.update(indices, new_labels)
            
            if len(self.X_pool) == 0:
                break
        
        return self.history

Cost-effective Labeling: la estrategia importa

No todos los labels cuestan igual. Un caso edge en医学 imaging puede necesitar un especialista. Una review de producto la puede labelar cualquiera. El costo de labeling debe influir en qué samples seleccionas:

def expected_error_reduction(model, X_candidate, cost=1.0):
    """
    Expected Error Reduction: 
    Estima la reducción esperada en error si labelamos esta sample.
    
    Más costoso computacionalmente pero más preciso.
    """
    probs = model.predict_proba(X_candidate.reshape(1, -1))[0]
    current_entropy = entropy(probs)
    
    # Simular ambos labels posibles y ver cuánto reducen incertidumbre
    reductions = []
    for label in range(len(probs)):
        # Asumimos este label y vemos cuánto baja la entropía
        new_probs = probs.copy()
        new_probs *= 0  # Reset
        new_probs[label] = 1.0  # Confianza total
        reduction = current_entropy - entropy(new_probs)
        reductions.append(reduction * probs[label])  # Pondera por probabilidad del label
    
    expected_reduction = sum(reductions)
    utility = expected_reduction / cost
    return utility

def cost_aware_query(model, X_pool, costs, n_select=100):
    """
    Query aware de costos: maximiza utility = información / costo.
    """
    scores = []
    for i, x in enumerate(X_pool):
        info_score = uncertainty_scores(model, x.reshape(1,-1), method="entropy")[0]
        utility = info_score / costs[i]
        scores.append(utility)
    
    scores = np.array(scores)
    top_indices = np.argsort(scores)[-n_select:]
    return top_indices

Human-in-the-Loop: más que solo labeling

Active learning es labeling selectivo, pero human-in-the-loop (HITL) es más amplio. Incluye:

  • Data verification: humanos verifican predicciones del modelo en producción
  • Error analysis: humanos analizan failure modes sistemáticamente
  • Feature feedback: humanos sugieren features o corrigen cómo se extraen
  • Curriculum design: humanos ordenan qué conceptos aprender primero
class HumanInTheLoop:
    def __init__(self, model, db_connection):
        self.model = model
        self.db = db_connection
        self.pending_reviews = []
    
    def flag_low_confidence(self, X, threshold=0.6):
        """Flag predicciones de baja confianza para revisión humana."""
        probs = self.model.predict_proba(X)
        max_probs = probs.max(axis=1)
        low_conf_mask = max_probs < threshold
        return np.where(low_conf_mask)[0]
    
    def log_review(self, sample_idx, predicted_label, human_label, 
                   feedback_type="correction"):
        """Loguea el feedback humano para análisis posterior."""
        query = """
        INSERT INTO human_feedback (sample_idx, predicted_label, 
                                    human_label, feedback_type, timestamp)
        VALUES (?, ?, ?, ?, datetime('now'))
        """
        self.db.execute(query, (sample_idx, predicted_label, 
                                human_label, feedback_type))
    
    def retrain_with_feedback(self, X_all, y_all, n_epochs=5):
        """
        Re-entrena el modelo incorporando feedback humano.
        Las samples con feedback tienen weight mayor.
        """
        # Pesos: más para las que humanos corrigieron
        feedback_samples = self.get_high_impact_feedback()
        
        # Fine-tune con las correcciones
        self.model.fit(X_all, y_all)  # baseline
        self.model.fit(
            feedback_samples["X"], 
            feedback_samples["y"],
            sample_weight=feedback_samples["weights"]
        )
        return self.model

Los 3 errores que mandan tu proyecto al piso

Error 1: Labelar todo manualmente sin active learning

El problema: Labelas 50,000 imágenes al dope cuando con active learning labelando 10,000 ibas a llegar al mismo performance. Gastaste 5x más en labeling y llegaste igual.

El fix: Siempre corre un análisis de "cuántos labels necesitas" antes de empezar. Compara random sampling vs uncertainty sampling vs expected error reduction. Si la diferencia es 3x o más, usa active learning.

Error 2: Usar random sampling en vez de uncertainty sampling

El problema: Labelas samples que no le enseñan nada al modelo — la foto obvia del perro, el texto que ya clasifica bien. Estás desperdiciando el tiempo del annotator.

El fix: Implementa uncertainty sampling desde el día 1. Para texto, usa entropy. Para imágenes, usa least confidence o margin. Solo usa random si no tienes modelo entrenado todavía (cold start).

# Cold start: sin modelo, usar diversidad
from sklearn.cluster import KMeans

def cold_start_selection(X_pool, n_select, n_clusters=10):
    """
    Cold start: sin modelo, selecciona samples diversas usando clustering.
    """
    # Cluster los datos
    kmeans = KMeans(n_clusters=n_clusters, random_state=42)
    labels = kmeans.fit_predict(X_pool)
    
    # Selecciona los samples más cercanas al centroid de cada cluster
    selected = []
    for c in range(n_clusters):
        cluster_mask = labels == c
        cluster_points = X_pool[cluster_mask]
        centroid = kmeans.cluster_centers_[c]
        distances = np.linalg.norm(cluster_points - centroid, axis=1)
        # La más cercana al centroid
        selected.append(np.where(cluster_mask)[0][np.argmin(distances)])
    
    return np.array(selected)[:n_select]

Error 3: HITL sin integración sistemática de feedback

El problema: Los annotators corrigen cosas, pero esas correcciones no llegan al modelo. El sistema sigue cometiendo los mismos errores en producción.

El fix: Cada corrección humana debe ser: (1) logged, (2) analyzed por tipo de error, (3) incorporated al training con peso mayor. Sin este pipeline, HITL es solo theater — se siente bien pero no mejora nada.

# Pipeline completo de feedback integration
def systematic_feedback_pipeline(model, feedback_df, X_train, y_train):
    """
    Integra feedback de manera sistemática:
    1. Analiza patterns en errores
    2. Weight samples por impacto
    3. Re-entrena con weights
    """
    # 1. Analiza qué tipo de errores son
    error_types = feedback_df.groupby("feedback_type").size()
    print("Error types:", error_types)
    
    # 2. Calcula weights: más para errores recientes y frecuentes
    feedback_df["weight"] = (
        feedback_df.groupby("sample_idx")["timestamp"]
        .transform("count")  # Frecuencia
        * feedback_df["timestamp"].rank(ascending=False)  # Recencia
    )
    feedback_df["weight"] = feedback_df["weight"] / feedback_df["weight"].max()
    
    # 3. Si es corrección, aumenta weight
    feedback_df.loc[
        feedback_df["feedback_type"] == "correction", "weight"
    ] *= 2.0
    
    # 4. Re-entrena con weights
    # Necesitas las features para las samples con feedback
    feedback_indices = feedback_df["sample_idx"].unique()
    weights = feedback_df.groupby("sample_idx")["weight"].mean()
    
    # Fine-tune
    model.fit(X_train, y_train)
    model.fit(
        X_train[feedback_indices],
        y_train[feedback_indices],
        sample_weight=weights.values
    )
    
    return model

Resumen: etiqueta menos, aprende mejor

Active learning y human-in-the-loop son complementarios. Active learning decide qué labelear. HITL asegura que esos labels se usen bien. Juntos pueden reducir costs de labeling en 80% sin sacrificar performance.

La clave es treating labeling como una inversión, no como un costo. Cada label humano debe comprar la máxima información posible para tu modelo. Si estás labelando al azar, estás desperdiciando plata y tiempo.

Y aquí viene lo clave: el mejor labeling no es el que más samples tiene — es el que más diversity cubre con el mínimo de samples. Un modelo entrenado con 1,000 samples bien elegidas puede ganarle a uno entrenado con 50,000 picked at random. Así de duro es el juego.
