Mechanistic Interpretability - Desmontando Redes Neuronales

26 de septiembre de 2026

Introduction

Hagale pues, parcero. Aqui en Medellin cuando hablamos de modelos grandes, el 90% de la gente los trata como cajas negras: le metes texto, sale texto, punto. Pero hay un campo emergente que esta cambiando eso: Mechanistic Interpretability. La idea es simple pero poderosa: reverse-engineer las redes neuronales para entender exactamente que computo esta haciendo, a nivel de circuitos y features individuales.

Anthropic, Google DeepMind, y otros equipos pequenos de researchers estan usando estas tecnicas para entender desde que exactamente hace un transformer cuando responde una pregunta, hasta por que ciertos prompts causan comportamientos inesperado. Vamos paso a paso.

Que Es Mechanistic Interpretability?

La interpretability mecanistica busca descomponer una red neuronal en sus componentes fundamentales y entender como interactuan. No es solo ver que activaciones ocurren, sino entender el circuito computacional subyacente.

La intuicion central viene de la neuroscience: si queremos entender el cerebro, no solo medimos actividad neuronal. Estudiamos circuitos, pathways, y mecanismos. Mechanistic interpretability aplica lo mismo a redes artificiales.

El concepto clave es que una red neuronal no es una funcion continua incomprensible. Es una composicion de modulos discretos que implementan algoritmos especificos. Si podemos identificar esos modulos y esos algoritmos, podemos explicar el comportamiento del modelo.

Features como Direcciones en Activation Space

El primer concepto fundamental: las activaciones de una red neuronal viven en espacios de alta dimensionalidad. Cada token en una secuencia tiene un vector de activacion asociado.

$$a(x) \in \mathbb{R}^d$$

Donde $d$ es la dimension del modelo (puede ser miles o millones). Un feature es una direccion especifica en ese espacio que corresponde a un concepto interpretable.

La hipotesis de superposition dice que los modelos representan mas features de los que tienen dimensiones. Esto es posible porque features pueden ser quase-orthogonales: correlacionados pero no exactamente iguales.

Para detectar features, usamos tecnicas como:

  • Probing: entrenar un clasificador lineal sobre las activaciones para predecir una propiedad deseada
  • Activation patching: cambiar activaciones especificas y observar el efecto en el output
  • SAE (Sparse Autoencoders): descomponer activaciones en features mas sparse y interpretables

Circuit Analysis

Un circuito es un subgrafo de la red que implementa un computo especifico. Por ejemplo, un circuito podria ser el pathway que detecta si una palabra es un verbo y lo согласует con el sujeto.

Los circuitos se identifican mediante:

  1. Activation analysis: identificar que componentes se activan para ciertos patrones
  2. Gradient analysis: ver como el loss cambia cuando modificamos ciertas activaciones
  3. ablation studies: remover componentes y ver como degrada el rendimiento

El Problema de Superposition

Uno de los descubrimientos mas sorprendente de mechanistic interpretability es el fenomeno de superposition: los modelos representan mas features interpretables de las dimensiones que tienen.

Esto es eficiente pero problematico para interpretability. Si cada neurona representara exactamente un feature, seria facil. Pero en la practica, las neuronas representan combinaciones de features, y un solo feature puede estar distribuido en muchas neuronas.

La formula matematica de superposition:

$$\text{Superposition Hypothesis}: \exists F \text{ features t.q. } |F| \gg d \text{ y } \forall f \in F, \cos^2(\theta_f, \theta_{f'}) \approx 0$$

Esto explica por que el probing directo often fails: no puedes simplemente entrenar un clasificador en una capa y esperar que las neuronas correspondan a conceptos claros.

SAE: Sparse Autoencoders para Descomponer Superposition

Una solucion emergente es usar Sparse Autoencoders (SAE). La idea es entrenar un autoencoder que descomponga las activaciones en una representacion mas sparse donde cada feature es mas independiente.

class SparseAutoencoder(torch.nn.Module):
    def __init__(self, d_model: int, d_hidden: int, sparsity: float = 0.01):
        super().__init__()
        self.W_encoder = torch.nn.Linear(d_model, d_hidden, bias=True)
        self.W_decoder = torch.nn.Linear(d_hidden, d_model, bias=False)
        self.sparsity = sparsity
        
    def encode(self, x):
        z = self.W_encoder(x)
        z = torch.relu(z)  # Solo valores positivos
        return z
    
    def decode(self, z):
        return self.W_decoder(z)
    
    def forward(self, x, l1_lambda: float = 1e-3):
        z = self.encode(x)
        x_reconstructed = self.decode(z)
        
        # Loss = reconstruction + sparsity penalty
        recon_loss = torch.nn.functional.mse_loss(x_reconstructed, x)
        sparsity_loss = z.abs().mean()  # L1 promotes sparsity
        
        return recon_loss + l1_lambda * sparsity_loss, z

Attention Heads y Sus Roles

Dentro de un transformer, los attention heads son componentes fundamentales. Cada head aprende a asistir a diferentes tipos de informacion.

En modelos de lenguaje, algunos patrones comunes de attention heads:

  • Duplicate token heads: detectan tokens repetidos en el contexto
  • Induction heads: copian patrones de un token a otro (ej: "First... Then" -> "Then...")
  • Previous token heads: asisten al token anterior
  • Semantic similarity heads: asisten a tokens semanticamente relacionados

Los induction heads son particularmente importantes: son un circuito simple que permite al modelo hacer few-shot learning pattern completion.

Herramientas Practicas para Interpretability

Para hacer mechanistic interpretability en la practica, hay varias herramientas disponibles:

  • TransformerLens: library de Neel Nanda para cargar modelos y hacer analysis de activaciones
  • Circuits.overfit.com: blog de Neel Nanda con analisis detallados de circuitos
  • SAE Vis: herramienta para visualizar features aprendidas por SAEs
  • PySvelte: visualizacion de circuitos neuronales
# Ejemplo completo con TransformerLens
import transformer_lens
import sae_lens

# Cargar modelo y SAE asociado
model = transformer_lens.HookedTransformer.from_pretrained("gpt2-small")
sae, cfg, sparsity = sae_lens.get_sae("gpt2-small-resid-post")

# Obtener features para un prompt
prompt = "The meaning of life is"
tokens = model.tokenizer(prompt, return_tensors="pt")

# Run model y obtener sparse features
_, cache = model.run_with_cache(tokens.input_ids)
resid_post = cache["blocks.0.hook_resid_post"]

# Encode a features
features = sae.encode(resid_post)

# Ver top features activas
top_features = features[0, 0].topk(10)
print("Top active features:")
for idx, val in zip(top_features.indices, top_features.values):
    feature_desc = sae_lens.get_feature_description(idx.item())
    print(f"  Feature {idx}: {val:.3f} - {feature_desc}")

Por Que Importa

Mechanistic interpretability no es solo curiosidad academic. Tiene implicaciones practicas profundas:

  • Safety: si entendemos como un modelo causa ciertos comportamientos, podemos detect y mitigating riesgos
  • Debugging: cuando un modelo falla, podemos entender por que a nivel de circuito
  • Alignment: si queremos que modelos hagan lo que queremos, entender como piensan es fundamental
  • Improvement: conocimiento de circuitos puede guiar arquitectura y training improvements

El objetivo ultimo es双向: poder explicar el comportamiento de modelos complejos en terminos de mecanismos interpretables, y usar ese conocimiento para hacer modelos mejores y mas seguros.

Resumen y Cierre

Pues alla lo tiene, parcero. Mechanistic interpretability es el intento mas serio de desmontar redes neuronales y entender que exactamente esta pasando dentro. Features como direcciones, circuitos como algoritmos, superposition como problema fundamental, y SAE como una solucion emergente.

No es magia ni filosofia. Es ciencia empirica aplicada a sistemas complejos. Cada semana hay nuevos descubrimientos sobre como los modelos implementan computos especificos. El que entiende los circuitos, entiende el modelo.
