🎯 LLM Evaluation: Lo Que El 80% Hace Mal

Qué tal parcero, hoy 20 de noviembre de 2026, Día 324 del #365DaysOfAI. Ayer aprendimos a entender los modelos internamente con interpretability. Hoy nos enfocamos en algo más práctico pero igual de importante: cómo evaluar LLMs de manera sistemática. Y no, no es solo "le pongo un prompt y veo si responde bien". Eso lo hace el 80%. El 20% usa frameworks como lm-evaluation-harness, designa evaluation suites rigurosas, y compara modelos justamente. Hoy nous vamos a ese lado. Eso es lo que hojeamos hoy.

📊 Por Qué La Evaluación Sistemática Importa

Imaginen que tienen dos modelos: uno saca 75% en MMLU y otro saca 72%.Cuál es mejor? La respuesta obvia parece ser el primero. Pero qué pasa si:

  • El 75% es solo porque el modelo tiene más parameters pero está memorizando
  • El 72% generaliza mejor a tareas no vistas
  • El modelo con 75% falla en tareas de reasoning paso a paso
  • El de 72% es 10x más rápido y eficiente

Sin una evaluación sistemática, no pueden tomar esa decisión informadamente. Y en producción, la diferencia entre un modelo que "parece bueno" y uno que realmente es adecuado para su caso de uso puede ser la diferencia entre éxito y fracaso.

Además, en Colombia la Ley 1585 del 2023 sobre sistemas de inteligencia artificial exige que los sistemas automatizados demuestren suitabilidad para su propósito. Eso requiere metrics quantificables, no intuiciones.

🔧 lm-evaluation-harness: El Estándar De Facto

lm-evaluation-harness (lm-eval) es una library open-source de EleutherAI que permite evaluar LLMs en más de 60 benchmarks estándar de manera consistente y reproducible. Es lo que usa la comunidad de investigación para comparar modelos.

"""

import lm_eval
from lm_eval.api.model import LM
from lm_eval.api.tasks import TaskManager
from lm_eval.api.registry import ALL_TASKS
import json

class LM_Evaluator:
    """Wrapper para lm-evaluation-harness"""
    
    def __init__(self, model_name, device="cuda"):
        self.model_name = model_name
        self.device = device
        self.task_manager = TaskManager()
    
    def list_available_tasks(self):
        """Lista todas las tasks disponibles"""
        return list(ALL_TASKS.keys())
    
    def evaluate(self, tasks, batch_size=8, num_fewshot=None):
        """
        Evalúa el modelo en las tasks especificadas.
        
        math:
        Para cada task, lm-eval computa:
        - Exact match (EM) o ROUGE depending de la task
        - F1 score sobre tokens
        - Accuracy para multiple choice
        
        Para few-shot, se proveen ejemplos de in-context:
        prompt = [example1, example2, ..., example_k, target]
        donde k = num_fewshot
        """
        results = lm_eval.simple_evaluate(
            model="hf",
            model_args=f"pretrained={self.model_name},device={self.device}",
            tasks=tasks,
            batch_size=batch_size,
            num_fewshot=num_fewshot,
            limit=None  # None = todos los ejemplos
        )
        return results
    
    def parse_results(self, results):
        """Parsea resultados de lm-eval a un formato legible"""
        parsed = {}
        for task_name, task_results in results["results"].items():
            parsed[task_name] = {
                "accuracy": task_results.get("acc", None),
                "accuracy_stderr": task_results.get("acc_stderr", None),
                "f1": task_results.get("f1", None),
                "perplexity": task_results.get("perplexity", None),
            }
        return parsed
    
    def compare_models(self, model_names, tasks, num_fewshot=5):
        """
        Compara múltiples modelos en las mismas tasks.
        
        math:
        Para comparar justamente, usamos:
        - win rate: % de tasks donde modelo A > modelo B
        - average score: promedio ponderado por difficulty
        - statistical significance: t-test sobre resultados
        
        Para fair comparison, todos los modelos se evalúan
        con los mismos hyperparameters (temperature=0, etc.)
        """
        comparison = {}
        
        for model_name in model_names:
            print(f"Evaluando {model_name}...")
            evaluator = LM_Evaluator(model_name, self.device)
            results = evaluator.evaluate(tasks, num_fewshot=num_fewshot)
            comparison[model_name] = evaluator.parse_results(results)
        
        # Calcular rankings
        rankings = {model: {} for model in model_names}
        
        for task in tasks:
            scores = {
                model: comparison[model].get(task, {}).get("accuracy", 0) or 0
                for model in model_names
            }
            sorted_models = sorted(scores.items(), key=lambda x: -x[1])
            
            for rank, (model, score) in enumerate(sorted_models):
                rankings[model][task] = rank + 1
        
        return comparison, rankings


# Ejemplo de uso

    print(f"{task}: {metrics}")

📐 Diseño De Evaluation Suites

Un benchmark individual no les dice todo. Necesitan una evaluation suite que cubra múltiples dimensiones del modelo. Esto es lo que diferencia una evaluación seria de un simple accuracy number.

from dataclasses import dataclass
from typing import List, Dict, Optional
import json

@dataclass
class EvaluationTask:
    """Define una task individual en la evaluation suite"""
    name: str
    benchmark: str  # hellaswag, mmlu, gsm8k, etc.
    metric: str  # accuracy, f1, em (exact match)
    weight: float  # peso en el score final
    description: str
    category: str  # reasoning, knowledge, safety, etc.

class EvaluationSuite:
    """
    Define una evaluation suite completa.
    
    math:
    El overall score es un weighted average:
    
    Score = sum_i (weight_i * metric_i) / sum_i weight_i
    
    donde i indexa las tasks. Los weights reflejan
    la importancia relativa para su use case específico.
    """
    
    def __init__(self, name: str):
        self.name = name
        self.tasks: List[EvaluationTask] = []
    
    def add_task(self, task: EvaluationTask):
        self.tasks.append(task)
    
    def get_tasks_by_category(self, category: str) -> List[EvaluationTask]:
        return [t for t in self.tasks if t.category == category]
    
    def compute_overall_score(self, results: Dict) -> float:
        """
        Computa overall weighted score.
        
        math:
        Score_total = Σ(w_i * score_i) / Σ(w_i)
        """
        total_weight = 0
        weighted_sum = 0
        
        for task in self.tasks:
            if task.name in results and results[task.name] is not None:
                score = results[task.name].get(task.metric, 0) or 0
                weighted_sum += task.weight * score
                total_weight += task.weight
        
        return weighted_sum / total_weight if total_weight > 0 else 0
    
    def generate_report(self, results: Dict) -> str:
        """Genera un reporte textual de resultados"""
        report = f"=== EVALUATION SUITE: {self.name} ===\n\n"
        
        # Results por categoría
        categories = set(t.category for t in self.tasks)
        
        for category in categories:
            cat_tasks = self.get_tasks_by_category(category)
            report += f"\n## {category.upper()}\n"
            
            for task in cat_tasks:
                if task.name in results:
                    score = results[task.name].get(task.metric, 0) or 0
                    status = "✅" if score > 0.7 else "⚠️" if score > 0.5 else "❌"
                    report += f"  {status} {task.name}: {score:.3f} (weight: {task.weight})\n"
                    report += f"      {task.description}\n"
        
        report += f"\n## OVERALL SCORE: {self.compute_overall_score(results):.3f}\n"
        
        return report

📈 Análisis De Resultados Y Comparación Justa

Evaluar no es solo obtener números. Es analizar qué significan esos números, comparar modelos justamente, y entender las limitaciones de cada benchmark.

import numpy as np
from scipy import stats
from typing import List, Dict, Tuple
import matplotlib.pyplot as plt

class EvaluationAnalyzer:
    """
    Análisis estadístico de resultados de evaluación.
    
    math:
    Para comparación justa de modelos:
    
    1. Statistical significance: t-test pareado
       H0: los modelos tienen el mismo performance
       Si p < 0.05, rechazamos H0 (diferencia significativa)
    
    2. Effect size: Cohen's d
       d = (mean_A - mean_B) / pooled_std
       small: d ≈ 0.2, medium: d ≈ 0.5, large: d ≈ 0.8
    
    3. Win rate: % de tasks donde A > B
       Importante: no solo el promedio
    """
    
    def __init__(self, results_dict: Dict[str, Dict]):
        """
        results_dict: {
            "model_name": {
                "task1": score1,
                "task2": score2,
                ...
            },
            ...
        }
        """
        self.results = results_dict
        self.models = list(results_dict.keys())
        self.tasks = list(next(iter(results_dict.values())).keys())
    
    def paired_ttest(self, model_a: str, model_b: str) -> Tuple[float, float]:
        """
        T-test pareado entre dos modelos.
        
        math:
        t = Σ(d_i) / (s * sqrt(n))
        donde d_i = score_A_i - score_B_i
        y s = desviación estándar de las diferencias
        """
        scores_a = [self.results[model_a][t] for t in self.tasks]
        scores_b = [self.results[model_b][t] for t in self.tasks]
        
        t_stat, p_value = stats.ttest_rel(scores_a, scores_b)
        
        return t_stat, p_value
    
    def cohens_d(self, model_a: str, model_b: str) -> float:
        """
        Calcula Cohen's d entre dos modelos.
        
        math:
        d = (mean_A - mean_B) / pooled_std
        pooled_std = sqrt((std_A^2 + std_B^2) / 2)
        """
        scores_a = np.array([self.results[model_a][t] for t in self.tasks])
        scores_b = np.array([self.results[model_b][t] for t in self.tasks])
        
        mean_diff = np.mean(scores_a - scores_b)
        pooled_std = np.sqrt((np.std(scores_a)**2 + np.std(scores_b)**2) / 2)
        
        return mean_diff / pooled_std if pooled_std > 0 else 0
    
    def win_rate(self, model_a: str, model_b: str) -> float:
        """Calcula win rate de A sobre B"""
        wins = sum(
            self.results[model_a][t] > self.results[model_b][t]
            for t in self.tasks
        )
        return wins / len(self.tasks)
    
    def tie_rate(self, model_a: str, model_b: str, threshold=0.01) -> float:
        """Calcula tie rate (diferencia < threshold)"""
        ties = sum(
            abs(self.results[model_a][t] - self.results[model_b][t]) < threshold
            for t in self.tasks
        )
        return ties / len(self.tasks)
    
    def compare_models(self, model_a: str, model_b: str) -> Dict:
        """
        Comparación completa entre dos modelos.
        """
        t_stat, p_value = self.paired_ttest(model_a, model_b)
        d = self.cohens_d(model_a, model_b)
        win_r = self.win_rate(model_a, model_b)
        tie_r = self.tie_rate(model_a, model_b)
        
        # Determinar effect size
        if abs(d) < 0.2:
            effect = "negligible"
        elif abs(d) < 0.5:
            effect = "small"
        elif abs(d) < 0.8:
            effect = "medium"
        else:
            effect = "large"
        
        # Determinar ganador
        if p_value < 0.05:
            if win_r > 0.5:
                winner = model_a
            elif win_r < 0.5:
                winner = model_b
            else:
                winner = "tie"
        else:
            winner = "no_significant_difference"
        
        return {
            "model_a": model_a,
            "model_b": model_b,
            "t_statistic": t_stat,
            "p_value": p_value,
            "significant": p_value < 0.05,
            "cohens_d": d,
            "effect_size": effect,
            "win_rate_a_over_b": win_r,
            "tie_rate": tie_r,
            "winner": winner
        }
    
    def full_comparison_matrix(self) -> Dict:
        """Matriz de comparación entre todos los modelos"""
        n = len(self.models)
        matrix = np.zeros((n, n))
        comparisons = {}
        
        for i, model_a in enumerate(self.models):
            for j, model_b in enumerate(self.models):
                if i != j:
                    comp = self.compare_models(model_a, model_b)
                    matrix[i, j] = comp["win_rate_a_over_b"]
                    comparisons[(model_a, model_b)] = comp
        
        return {
            "win_rate_matrix": matrix,
            "model_names": self.models,
            "task_names": self.tasks,
            "comparisons": comparisons
        }
    
    def plot_radar_chart(self, model_name: str, save_path="radar.png"):
        """Gráfico radar de un modelo por categoría de task"""
        categories = list(set(t.split("_")[0] for t in self.tasks))
        
        # Calcular score promedio por categoría (simplificado)
        model_scores = self.results[model_name]
        
        angles = np.linspace(0, 2 * np.pi, len(categories), endpoint=False).tolist()
        values = [np.mean([model_scores[t] for t in self.tasks if t.startswith(cat)])
                  for cat in categories]
        values += values[:1]  # Cerrar el polígono
        angles += angles[:1]
        
        fig, ax = plt.subplots(figsize=(8, 8), subplot_kw=dict(polar=True))
        ax.plot(angles, values, 'o-', linewidth=2)
        ax.fill(angles, values, alpha=0.25)
        ax.set_xticks(angles[:-1])
        ax.set_xticklabels(categories)
        ax.set_title(f"Performance Profile: {model_name}")
        plt.savefig(save_path)
        plt.close()
        return save_path
    
    def generate_report(self) -> str:
        """Genera reporte de análisis completo"""
        report = "=== EVALUATION ANALYSIS REPORT ===\n\n"
        
        # Summary stats por modelo
        report += "## Summary por Modelo\n"
        for model in self.models:
            scores = list(self.results[model].values())
            report += f"\n### {model}\n"
            report += f"  Mean: {np.mean(scores):.3f}\n"
            report += f"  Std: {np.std(scores):.3f}\n"
            report += f"  Min: {np.min(scores):.3f}\n"
            report += f"  Max: {np.max(scores):.3f}\n"
        
        # Pairwise comparisons
        report += "\n## Pairwise Comparisons\n"
        for i, model_a in enumerate(self.models):
            for j, model_b in enumerate(self.models):
                if i < j:
                    comp = self.compare_models(model_a, model_b)
                    report += f"\n### {model_a} vs {model_b}\n"
                    report += f"  Winner: {comp['winner']}\n"
                    report += f"  Significant (p<0.05): {comp['significant']}\n"
                    report += f"  p-value: {comp['p_value']:.4f}\n"
                    report += f"  Cohen's d: {comp['cohens_d']:.3f} ({comp['effect_size']})\n"
                    report += f"  Win rate: {comp['win_rate_a_over_b']:.1%}\n"
        
        return report

🔧 Custom Tasks En lm-evaluation-harness

lm-eval permite crear custom tasks para benchmarks específicos de su caso de uso:

import os
import json

class CustomTaskCreator:
    """
    Crea custom tasks para lm-evaluation-harness.
    
    Estructura de una task:
    task_name/
    ├── task.yaml      # Metadata y configuración
    └── dataset.json   # Datos (prompts y targets)
    """
    
    @staticmethod
    def create_choice_task(name: str, description: str, dataset: List[Dict]):
        """
        Crea una task de multiple choice.
        
        math:
        Para multiple choice, lm-eval computa accuracy como:
        accuracy = 1/N * Σ( argmax(model_probs(choices)) == correct_answer )
        """
        task_dir = f"./tasks/{name}"
        os.makedirs(task_dir, exist_ok=True)
        
        # Dataset JSON
        dataset_formatted = []
        for item in dataset:
            dataset_formatted.append({
                "prompt": item["prompt"],
                "choices": item["choices"],  # ["A", "B", "C", "D"]
                "gold": item["gold"]  # índice de la respuesta correcta
            })
        
        with open(f"{task_dir}/dataset.jsonl", "w") as f:
            for item in dataset_formatted:
                f.write(json.dumps(item) + "\n")
        
        # Task YAML
        yaml_content = f"""
task: {name}
dataset_path: {name}
dataset_name: null
test_split: test

num_fewshot: 0

dataset_kwargs:
  databricks: null

output_type: multiple_choice

training_split: null
validation_split: null

metric_list:
  - metric: acc
    aggregation:
      - mean
    higher_is_better: true

metadata:
  description: {description}
  tags:
    - custom
    - {name}
"""
        with open(f"{task_dir}/task.yaml", "w") as f:
            f.write(yaml_content)
        
        return task_dir
    
    @staticmethod
    def create_generation_task(name: str, description: str, dataset: List[Dict]):
        """
        Crea una task de generación de texto.
        
        math:
        Para generación, lm-eval computa:
        - ROUGE: overlap entre generated y reference
        - BLEU: n-gram precision
        - Exact Match: generated == reference
        """
        task_dir = f"./tasks/{name}"
        os.makedirs(task_dir, exist_ok=True)
        
        # Dataset JSONL
        with open(f"{task_dir}/dataset.jsonl", "w") as f:
            for item in dataset:
                f.write(json.dumps(item) + "\n")
        
        # Task YAML
        yaml_content = f"""
task: {name}
dataset_path: {name}
output_type: gen_task

metric_list:
  - metric: rouge
    aggregation:
      - mean
    higher_is_better: true
  - metric: bleu
    aggregation:
      - mean
    higher_is_better: true
  - metric: exact_match
    aggregation:
      - mean
    higher_is_better: true

metadata:
  description: {description}
"""
        with open(f"{task_dir}/task.yaml", "w") as f:
            f.write(yaml_content)
        
        return task_dir
    
    @staticmethod
    def create_colombian_legal_task():
        """

        """
        dataset = [
            {

⚠️ Los 3 Errores Principales

Error 1: No Usar Evaluación Estandarizada

El Error: Evaluar el modelo "a ojo" — le mando 5 prompts y si me gustan las respuestas, el modelo está listo. No hay reproducibilidad, no hay comparación cuantitativa, no hay manera de trackear progreso.

El Fix: Usar lm-evaluation-harness o similar para tener métricas consistentes y reproducibles. Incluso una evaluación simple con lm-eval ya les da números comparables con la literatura y con otros modelos.

def quick_benchmark(model_name, tasks=["hellaswag", "mmlu"]):
    """
    Benchmark rápido para comparar modelos.
    """
    from lm_eval import simple_evaluate
    
    results = simple_evaluate(
        model="hf",
        model_args=f"pretrained={model_name}",
        tasks=tasks,
        num_fewshot=5,
    )
    
    return {
        task: results["results"][task]["acc"]
        for task in tasks
    }

Error 2: Evaluar En Tasks Que No Importan Para Su Caso De Uso

El Error:-optimizar para MMLU cuando su caso de uso es generación de código, o viceversa. O usar benchmarks que no reflejan la realidad de su deployment (ej: evaluar en inglés cuando el modelo se usa en español).

El Fix: Diseñar una evaluation suite específica para su caso de uso. Evaluar en tasks que importan, en el idioma que importa, con las constraints que importan (latencia, longitud de contexto, etc.).

def design_use_case_suite(use_case: str) -> EvaluationSuite:
    """

Error 3: No Comparar De Manera Justa

El Error: Comparar modelos con diferentes temperatures, different number of shots, o different prompt formats, y concluir que uno es mejor. O comparar un modelo pequeño optimizado contra uno grande sin optimizar.

El Fix: Usar la misma configuración para todos los modelos (same temperature=0, same num_fewshot, same prompt format). Hacer análisis estadístico (t-test, effect size) para determinar si las diferencias son significativas.

def fair_model_comparison(model_names: List[str], tasks: List[str]):
    """
    Compara modelos de manera justa.
    
    Importante:
    - Misma temperatura (0 = determinista)
    - Mismo num_fewshot
    - Mismo prompt format
    - Mismo hardware
    """
    # Config fixed para todos
    config = {
        "temperature": 0,
        "num_fewshot": 5,
        "batch_size": 8,
        "device": "cuda:0"
    }
    
    results = {}
    for model in model_names:
        print(f"Evaluando {model}...")
        
        evaluator = LM_Evaluator(model, device=config["device"])
        raw_results = evaluator.evaluate(
            tasks,
            num_fewshot=config["num_fewshot"],
            batch_size=config["batch_size"]
        )
        
        # Extraer solo accuracy
        results[model] = {
            task: raw_results["results"][task].get("acc", 0) or 0
            for task in tasks
        }
    
    # Análisis estadístico
    analyzer = EvaluationAnalyzer(results)
    comparison = analyzer.full_comparison_matrix()
    
    # Report
    print("\n=== COMPARISON SUMMARY ===")
    for (model_a, model_b), comp in comparison["comparisons"].items():
        print(f"\n{model_a} vs {model_b}:")
        print(f"  Winner: {comp['winner']}")
        print(f"  Significant: {comp['significant']} (p={comp['p_value']:.4f})")
        print(f"  Effect size: {comp['cohens_d']:.2f} ({comp['effect_size']})")
    
    return comparison

📐 La Matemática Detrás

La evaluación de LLMs tiene fundamentos matemáticos importantes:

Exact Match (EM) — La métrica más simple para generación:

$$EM = \frac{1}{N} \sum_{i=1}^{N} \mathbb{1}[y_{pred}^{(i)} = y_{true}^{(i)}]$$

Es 1 si la predicción es exactamente igual al target, 0 si no.

ROUGE-L — Longest Common Subsequence entre pred y reference:

$$ROUGE-L = \frac{LCS(pred, ref)}{len(ref)}$$

Mide overlap normalizado por la longitud del reference.

F1 Score para Multiple Choice:

$$F1 = 2 \cdot \frac{precision \cdot recall}{precision + recall}$$

Para multiple choice con una sola respuesta correcta, esto se reduce a accuracy.

Statistical Significance con t-test pareado:

$$t = \frac{\bar{d}}{s_d / \sqrt{n}}$$

donde $\bar{d}$ es la media de las diferencias entre scores pareados, $s_d$ es la desviación estándar de esas diferencias, y $n$ es el número de tasks.

📊 Resumen y Cierre

Bueno Ahí Vamos parcero. LLM Evaluation Harness no es opcional — es prerequisite para tomar decisiones informadas sobre qué modelo usar, cómo mejorarlo, y cuándo está listo para producción. Los tres errores principales:

  1. No usar evaluación estandarizada → Fix: adoptar lm-evaluation-harness como baseline para toda evaluación
  2. Evaluar en tasks que no importan → Fix: diseñar evaluation suite específica para su caso de uso (español, código, legal, etc.)
  3. No comparar de manera justa → Fix: misma configuración para todos los modelos + análisis estadístico (t-test, effect size)

La matemática — exact match, ROUGE, t-test pareado, Cohen's d — les da el framework para evaluar rigurosamente. No es solo "le echo un vistazo al output". Es tener números reproducibles, comparables, y estadísticamente significativos.
