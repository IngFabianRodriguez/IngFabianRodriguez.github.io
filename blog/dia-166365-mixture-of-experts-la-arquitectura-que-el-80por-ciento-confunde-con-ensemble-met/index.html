📐 Fundamentos: Qué Es la Cuantización

La cuantización es el proceso de convertir valores de precisión completa (típicamente FP32 o FP16) a representacioens de menor precisión (INT8, INT4, etc.) para reducir memoria y computación. La matemática es simple pero las implicaciones son profundas:

El Math de la Cuantización

Dado un peso original $W$ en FP16, la cuantización proceso:

$$W_q = \text{clamp}\left(\text{round}\left(\frac{W}{s} + z\right), 0, 255\right)$$

Donde:

  • $s$ es el scale factor (un valor por grupo de pesos)
  • $z$ es el zero point (para cuantización asimétrica)
  • $W_q$ es el peso cuantizado en UINT8

La dectructuración (usar el peso cuantizado) es:

$$\hat{W} = s \cdot (W_q - z)$$

El error de cuantización (diferencia entre $W$ original y $\hat{W}$) depende de:

$$\text{Error} = |W - \hat{W}|^2 \propto \frac{1}{n_{\text{bits}}}$$

Más bits = menos error, pero más memoria. El arte está en minimizar error sin perder accuracy.

🔬 GPTQ: Post-Training Quantization via Hessian

GPTQ (Generative Pre-trained Transformer Quantization) usa un enfoque de quantización post-training basado en el Hessian de la función de pérdida. Fue propuesto por Frantar et al. en 2022 y se convirtió en el estándar para cuantizar LLMs a 4 bits.

Cómo Funciona GPTQ

GPTQ quantiza capa por capa. Para cada capa, resuelve:

$$\min_{\hat{W}} \|W - \hat{W}\|_F^2 \quad \text{sujeto a} \quad \hat{W} \in \mathbb{B}^n$$

donde $\mathbb{B}^n$ es el códigobook de valores cuantizados. Usa una aproximación de segundo orden (Hessian) para guiar qué pesos cuantizar primero:

$$\Delta w_i = -\frac{(H^{-1})_{ii}}{\text{diag}(H)^{-1}_i} \cdot (w_i - \hat{w}_i)$$

# Implementación con auto-gptq
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig
from transformers import AutoTokenizer
import torch

model_name = "meta-llama/Llama-2-7b-chat-hf"
quantize_config = BaseQuantizeConfig(
    bits=4,                    # 4 bits (GPTQ es excelente en 4-bit)
    group_size=128,            # Cuantizar por grupos de 128 pesos
    desc_act=True,             # Activation order - mejor accuracy pero más lento
)

tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoGPTQForCausalLM.from_pretrained(
    model_name,
    quantize_config=quantize_config,
    torch_dtype=torch.float16,
)

# Calibración con dataset representativo (¡NO con training data!)
# El error aquí es usar datos irrelevantes
calibration_dataset = [
    tokenizer("Qué es la fotosíntesis?", return_tensors="pt")
    for _ in range(512)
]

print("Cuantizando modelo...")
model.quantize(calibration_dataset)

# Guardar modelo cuantizado
model.save_pretrained("llama-2-7b-chat-gptq-4bit")
tokenizer.save_pretrained("llama-2-7b-chat-gptq-4bit")

# Carga y usa
model = AutoGPTQForCausalLM.from_pretrained(
    "llama-2-7b-chat-gptq-4bit",
    device_map="auto",
)

🔬 AWQ: Activation-Aware Weight Quantization

AWQ (Activation-Aware Weight Quantization) es más nuevo y se basa en la observación de que no todos los pesos son igual de importantes. Los pesos que interactúan con activaciones de alta magnitud deben ser cuantizados con menos error.

Cómo Funciona AWQ

AWQ usa una heurística simple pero efectiva: los pesos que tienen productos grandes con las activaciones (i.e., $|W| \cdot |X|$ alto) deben preservarse mejor:

$$\text{importance}(w_i) = |w_i| \cdot \mathbb{E}[|x_i|]$$

AWQ busca el factor de escala óptimo $s$ minimizando:

$$\min_s \|W - \hat{W}_s\|_F^2 \quad \text{donde} \quad \hat{W}_s = \text{quantize}(W / s) \cdot s$$

# Implementación con awq
from transformers import AutoTokenizer, AutoModelForCausalLM
from awq import AutoAWQForCausalLM
from awq.utils.lite_utils import get_best_device

model_name = "meta-llama/Llama-2-7b-chat-hf"
tokenizer = AutoTokenizer.from_pretrained(model_name)

# Cuantización AWQ
quant_config = {
    "zero_point": True,         # Cuantización asimétrica
    "q_group_size": 128,        # Tamaño del grupo
    "w_bit": 4,                 # Bits para los pesos
    "version": "gemm",          # GEMM vs GEMV - gemm es más rápido
}

model = AutoAWQForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16)
datasets = ["tatsu-lab/alpaca", "yahma/alpaca-cleaned"]  # ¡Data de calibración!

print("Buscando scaling factors óptimos...")
model.quantize(tokenizer, quant_config=quant_config)

# Guardar
model.save_quantized("llama-2-7b-chat-awq-4bit")
tokenizer.save_pretrained("llama-2-7b-chat-awq-4bit")

# Carga

Cuándo Usar Cuál

  • Usa GPTQ cuando:
    • Quieres estabilidad y reproducibilidad
    • El modelo será served en edge devices (GPTQ tiene mejor soporte para HW específico)
    • Estás cuantizando a 4 bits (el caso de uso principal de GPTQ)
    • Quieres usar exllama o exllamav2 para inference rápida
  • Usa AWQ cuando:
    • Necesitas la mejor accuracy posible para el mismo bit-width
    • Tienes outliers significativos en los pesos (AWQ los maneja mejor)
    • Estás cuantizando a 3 bits (AWQ degrada menos que GPTQ)
    • Usas vLLM (soporte nativo para AWQ)
  • Usa bitsandbytes solo para:
    • Prototyping rápido donde la accuracy no importa mucho
    • Cuando la convenience > calidad (NF4 con transformers es muy easy)
    • Fine-tuning (bnb funciona mejor para training que para inference)

📊 Resumen: GPTQ vs AWQ vs bitsandbytes

  • GPTQ: Basado en Hessian, excelente para 4-bit, más tutorials y tooling
  • AWQ: Activation-aware, mejor accuracy en 3-4 bits, mejor para outliers
  • bitsandbytes NF4: Convenient para prototyping, worse accuracy que GPTQ/AWQ
  • Weight-only quantization: Solo cuantiza pesos, las activaciones se mantienen en FP16
  • Calibration dataset: Debe ser representativo de producción, NO training data
  • Siempre verificar: Perplexity + sanity checks + semantic similarity antes de deploy

🏁 Cierre

Y ahí lo tienen, parcero. Cuantización no es solo "poner el modelo en 4 bits y ya". Es entender qué método funciona mejor para tu caso, calibrar con datos que representen lo que vas a servir, y verificar que después de cuantizar el modelo sigue siendo útil. El 90% que no hace esto es por qué ves tantos modelos cuantizados que generan basura en producción.
