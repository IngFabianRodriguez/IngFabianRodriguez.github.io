Padding - El Héroe Silencioso Que Evita Pérdida de Información

24 de March de 2026

🎯 Intro: ¿Por Qué Importa El Padding?

Hágale pues, parcero. Vamos al Día 98 y hoy hablamos de algo que parece trivial pero cuando no lo haces bien te causa pérdidas de información en los bordes, data leakage en language modeling, y errores de dimensión en tus batches. Sí, hablo del padding.

En NLP los textos tienen longitud variable. En CV las imágenes tienen bordes. Sin padding, las convoluciones descartan información en los bordes y los batches se rompen cuando mezclas secuencias de diferentes tamaños. El padding es el héroe silencioso que evita que todo eso se vaya al piso.

La pregunta no es si usar padding — es cuál tipo usar y dónde. Eso es lo que vamos a ver.

📐 La Matemática Del Padding En Convoluciones

Para una convolución 1D con stride=1, el output size es:

$$H_{out} = H_{in} + 2 \cdot pad - (kernel - 1)$$

Para mantener el tamaño espacial (padding='same'):

$$pad = \lfloor (kernel - 1) / 2 \rfloor$$

Para kernel=3, pad=1. Para kernel=5, pad=2. Para kernel=7, pad=3.

En 2D es igual pero en ambas dimensiones. Y aquí es donde muchos cometen el primer error.

🚀 Implementación Completa En PyTorch

import torch
import torch.nn as nn
import torch.nn.functional as F

# ─── 1. Tipos De Padding En PyTorch ───────────────────────────────────────────

def demo_padding_types():
    """Compara ConstantPad2d, ReflectionPad2d, ReplicationPad2d."""
    x = torch.arange(9, dtype=torch.float).reshape(1, 1, 3, 3)
    print("Input (3x3):")
    print(x)

    # Constant padding (zeros por defecto)
    const_pad = nn.ConstantPad2d(padding=1, value=0)
    print("\nConstantPad2d(padding=1, value=0):")
    print(const_pad(x))

    # Reflection padding — refleja los valores de borde
    refl_pad = nn.ReflectionPad2d(padding=1)
    print("\nReflectionPad2d(padding=1):")
    print(refl_pad(x))

    # Replication padding — replica el borde
    repl_pad = nn.ReplicationPad2d(padding=1)
    print("\nReplicationPad2d(padding=1):")
    print(repl_pad(x))


# ─── 2. Same Padding En Convoluciones (No Existe En PyTorch Nativamente) ────────

def same_padding_1d(kernel_size, stride):
    """Calcula el padding necesario para mantener el tamaño en conv1d."""
    p = (kernel_size - 1) // 2
    return p

def conv1d_same(x, weight, bias=None, stride=1):
    """
    Convolución 1D con 'same' padding.
    x: (batch, channels, length)
    """
    kernel_size = weight.shape[2]
    pad = same_padding_1d(kernel_size, stride)
    return F.conv1d(x, weight, bias, stride=stride, padding=pad)


# ─── 3. Causal Padding Para Autoregressive Models ──────────────────────────────

class CausalConv1D(nn.Module):
    """
    Convolución 1D causal: el output en tiempo t solo depende de
    inputs en tiempos <= t. Implementado con padding derecho (no izquierdo).
    """
    def __init__(self, in_channels, out_channels, kernel_size, dilation=1):
        super().__init__()
        self.pad = (kernel_size - 1) * dilation  # Padding SOLO a la derecha
        self.conv = nn.Conv1d(in_channels, out_channels, kernel_size,
                             dilation=dilation)

    def forward(self, x):
        # Pad a la derecha antes de la conv
        x = F.pad(x, (self.pad, 0))  # (left_pad, right_pad)
        return self.conv(x)


class TransformerBlockWithCausalMask(nn.Module):
    """
    Transformer decoder block con causal masking + causal padding.
    Garantiza que position i solo atienda a positions <= i.
    """
    def __init__(self, d_model=256, num_heads=8):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, num_heads, batch_first=True)
        self.ln1 = nn.LayerNorm(d_model)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_model * 4),
            nn.GELU(),
            nn.Linear(d_model * 4, d_model)
        )
        # Causal mask — triangulo inferior
        self.register_buffer(
            'causal_mask',
            torch.tril(torch.ones(1024, 1024))
        )

    def forward(self, x):
        """
        x: (batch, seq_len, d_model)
        """
        seq_len = x.size(1)
        # Crear causal mask para atención (下行)
        causal_mask = self.causal_mask[:seq_len, :seq_len]

        # Auto-atención causal
        attn_out, _ = self.attn(
            self.ln1(x), self.ln1(x), self.ln1(x),
            attn_mask=causal_mask,
            need_weights=False
        )
        x = x + attn_out
        x = x + self.ffn(self.ln2(x))
        return x


# ─── 4. Causal Padding En LSTM/GRU Para Language Modeling ────────────────────

class CausalLSTM(nn.Module):
    """
    LSTM con causal padding: cada timestep solo ve los anteriores.
    Sin esto, habría data leakage en language modeling.
    """
    def __init__(self, vocab_size, embed_dim=256, hidden_dim=512):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True)
        self.output = nn.Linear(hidden_dim, vocab_size)

    def forward(self, x):
        """
        x: (batch, seq_len) — token IDs
        Retorna: (batch, seq_len, vocab_size) — logits para cada posición
        """
        embed = self.embedding(x)  # (batch, seq_len, embed_dim)

        # LSTM normal con batch_first=True
        # El "causal" viene del objetivo: predecimos siguiente token
        # usando solo tokens anteriores (teacher forcing)
        lstm_out, _ = self.lstm(embed)  # (batch, seq_len, hidden_dim)

        logits = self.output(lstm_out)  # (batch, seq_len, vocab_size)
        return logits

    def generate_causal(self, start_tokens, max_new_tokens):
        """
        Generación autoregresiva con causal masking.
        """
        self.eval()
        generated = start_tokens.clone()
        for _ in range(max_new_tokens):
            # Siempre usar solo los últimos tokens (los nuevos se generan)
            logits = self.forward(generated[:, -1024:])
            next_token = logits[:, -1, :].argmax(dim=-1, keepdim=True)
            generated = torch.cat([generated, next_token], dim=1)
        return generated


# ─── 5. Padding-Aware Architecture: Handling Variable Length Sequences ───────

class PadAwareBatchNorm1d(nn.Module):
    """
    BatchNorm que ignora positions de padding.
    Necesario cuando truncation deja tokens de padding en medio del batch.
    """
    def __init__(self, num_features):
        super().__init__()
        self.bn = nn.BatchNorm1d(num_features)

    def forward(self, x, padding_mask=None):
        """
        x: (batch, seq_len, features)
        padding_mask: (batch, seq_len) — True donde hay padding
        """
        if padding_mask is None:
            return self.bn(x.reshape(-1, x.size(-1))).reshape(x.shape)

        # Zero out padded positions antes de BatchNorm
        x_masked = x.clone()
        x_masked[padding_mask] = 0
        x_flat = x_masked.reshape(-1, x.size(-1))

        # Calcular stats ignorando padding
        out = self.bn(x_flat).reshape(x.shape)
        return out


def collate_with_padding(batch, pad_token_id=0, max_length=None):
    """
    Combina sequences de diferente longitud en un batch con padding.
    Retorna: (padded_tensor, attention_mask)
    """
    # batch: lista de (input_ids, labels)
    input_ids = [item[0] for item in batch]
    labels = [item[1] for item in batch]

    if max_length is None:
        max_length = max(len(ids) for ids in input_ids)

    batch_size = len(batch)
    padded_ids = torch.full((batch_size, max_length), pad_token_id, dtype=torch.long)
    attention_mask = torch.zeros((batch_size, max_length), dtype=torch.long)

    for i, ids in enumerate(input_ids):
        length = len(ids)
        padded_ids[i, :length] = ids
        attention_mask[i, :length] = 1  # 1 = real token, 0 = padding

    return padded_ids, attention_mask

⚠️ Tres Errores Comunes (Y Sus Fx)

❌ Error 1: No Usar Causal Padding En Language Modeling (Data Leakage)

El problema: Si implementas un Transformer decoder o LSTM de language modeling sin causal masking/padding, durante el training el modelo puede "ver" tokens futuros y aprender a predecir el pasado usando información que no debería tener. Esto es data leakage — el modelo hace trampa. En la práctica esto se manifiesta como:

  • Métricas de training que se ven increíbles pero inference que falla
  • Perplexity que no mejora o empeora con más epochs
  • El modelo generando texto sin sentido porque aprendió a depender de tokens futuros

El fix: Implementa causal masking en la atención Y causal padding en las convoluciones. Los Transformers modernos usan torch.tril() para crear la máscara causal. Los LSTM deben usar teacher forcing donde cada input es el token anterior, no el siguiente.

# MAL: Atención sin máscara causal — permite ver el futuro
class BadTransformerDecoder(nn.Module):
    def forward(self, x):
        # x: (batch, seq, d_model)
        return self.attn(self.ln1(x), self.ln1(x), self.ln1(x))[0]  # ❌ Sin mask


# BIEN: Atención con causal mask
class GoodTransformerDecoder(nn.Module):
    def __init__(self):
        super().__init__()
        self.register_buffer(
            'causal_mask',
            torch.tril(torch.ones(1024, 1024))  # Triangulo inferior = solo pasado
        )

    def forward(self, x):
        seq_len = x.size(1)
        mask = self.causal_mask[:seq_len, :seq_len]
        # Attn mask es -inf donde hay 0s (futuro), 0 donde hay 1s (pasado)
        attn_mask = (mask == 0).to(x.device)
        return self.attn(
            self.ln1(x), self.ln1(x), self.ln1(x),
            attn_mask=attn_mask
        )[0]

❌ Error 2: Padding Con Zeros No Siempre Es Óptimo

El problema: El padding por defecto es zero-padding. Pero para imágenes con bordes bien definidos (texturas, objetos en el borde), el padding con zeros crea discontinuidades que la convolución amplifica. En lugar de eso, los valores de borde reflejados o replicados mantienen la continuidad de los features maps.

El fix: Para tareas de imagen donde los bordes importan (object detection, segmentation), usa ReflectionPad2d o ReplicationPad2d. Para NLP con embeddings densos, zero-padding está bien porque el embedding de padding es learnable y el modelo aprende a ignorarlo si entrenas con attention masks correctos.

# Zero padding en NLP: OK si tienes attention mask
x = torch.randint(0, 1000, (4, 20))
embed = nn.Embedding(1000, 128, padding_idx=0)(x)  # Embedding de padding = 0
# El attention mask dice dónde están los tokens reales
attention_mask = (x != 0).long()

# Zero padding en CV: puede ser problemático en bordes
# Para una imagen de 224x224 con objetos en el borde:
# ConstantPad2d(2, 0) crea un borde negro de 2px
# ReflectionPad2d(2) extiende los bordes naturalmente
img = torch.randn(1, 3, 224, 224)
img_padded_zeros = F.pad(img, (2, 2, 2, 2), mode='constant', value=0)
img_padded_refl  = F.pad(img, (2, 2, 2, 2), mode='reflect')
print(f"Zero padding en bordes: {img_padded_zeros[:, :, :5, :5].mean().item():.4f} (debería ser ~0)")
print(f"Reflection padding preserva estructura: {img_padded_refl[:, :, :5, :5].std().item():.4f}")

❌ Error 3: Truncar Sequences Sin Padding Causa Batch Dimension Mismatches

El problema: Cuando procesas batches de secuencias de diferente longitud y truncas al máximo en lugar de padear al máximo, terminas con batches donde las secuencias cortas tienen garbage en las posiciones "truncadas" que no son padding real. Esto causa:

  • Dimensiones inconsistentes cuando intentas stackear tensors
  • Attention mask que no corresponde a los tokens reales
  • Métricas sesgadas porque el modelo procesa tokens de padding como si fueran reales

El fix: SIEMPRE haz padding al máximo en el batch y usa attention masks. Si el texto es muy largo, trunca pero asegura que el truncamiento sea consistente (siempre del lado derecho o izquierdo, nunca ambos). Usa collate_with_padding como función de DataLoader collate_fn.

# MAL: Truncar sin padding — batch mismatch
def bad_batch_processing(sequences):
    max_len = max(len(s) for s in sequences)
    batch = []
    for s in sequences:
        if len(s) < max_len:
            # NO hacer esto: zeros sin attention mask
            s = s + [0] * (max_len - len(s))
        batch.append(s)
    return torch.tensor(batch)  # ¿Cómo区分 cuáles son padding?


# BIEN: Padding con attention mask
def good_batch_processing(sequences, pad_token_id=0):
    max_len = max(len(s) for s in sequences)
    batch_size = len(sequences)
    batch = torch.full((batch_size, max_len), pad_token_id, dtype=torch.long)
    mask = torch.zeros((batch_size, max_len), dtype=torch.bool)

    for i, s in enumerate(sequences):
        length = min(len(s), max_len)
        batch[i, :length] = torch.tensor(s[:length])
        mask[i, :length] = True  # True = real token, False = padding

    return batch, mask  # Retornar mask junto con batch


# Si necesitas truncar, trunca de forma consistente
def truncate_right(sequence, max_length):
    """Trunca desde la izquierda (keep right) para NLP."""
    return sequence[-max_length:] if len(sequence) > max_length else sequence

def truncate_left(sequence, max_length):
    """Trunca desde la derecha (keep left) para NLP."""
    return sequence[:max_length] if len(sequence) > max_length else sequence

# Nunca hagas esto: truncate en ambos lados
def bad_truncate_both(sequence, max_length):
    """Esto rompe la estructura del texto."""
    if len(sequence) <= max_length:
        return sequence
    # Corta ambos lados — destruye contexto
    left_cut  = (len(sequence) - max_length) // 2
    return sequence[left_cut:left_cut + max_length]

💡 Resumen y Guía Rápida

Aquí va lo que necesitas para no perder información en los bordes:

  • Usa causal padding en cualquier modelo autoregresivo (LSTM, Transformer decoder). Sin esto, tienes data leakage y tu modelo hace trampa.
  • Usa same padding (o calcula el padding manualmente) cuando quieras mantener el tamaño espacial en las convoluciones. Para kernel 3, padding=1. Para kernel 5, padding=2.
  • Usa reflection/replication padding en imágenes cuando los bordes contengan información relevante. Zero padding está bien para NLP donde los embeddings de padding aprenden a ser ignorados.
  • Siempre usa attention masks cuando hagas padding. No dependas de que el modelo "aprenda" a ignorar el padding — el attention mask hace el trabajo explícito.
  • Trunca consistentemente: siempre del mismo lado (izquierda o derecha), nunca de ambos.

Y ahí lo tienes, parcero. El padding es el héroe silencioso que evita que la información se pierda en los bordes y que el data leakage arruine tu training. Ya sabes cuándo y cómo usarlo sin que te dé rabia.
