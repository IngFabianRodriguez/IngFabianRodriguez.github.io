Hola, parcero. Día 158 y hoy vamos con un tema que me duele cada vez que lo veo mal implementado: **Evaluation de LLMs**. Me ha tocado revisar dashboards donde alguien muestra "perplexity = 42.3" como métrica de calidad y me da comezón. ¿Por qué? Porque el 90% de la industria mide perplexity cuando debería medir cosas completamente distintas. Acompañame a entender qué funciona y qué no cuando de evaluar modelos de lenguaje se trata.

📊 Por Qué la Evaluación de LLMs es Difícil

Evaluación de LLMs es un problema fundamentalmente diferente a evaluación de modelos discriminativos (clasificación, regression). Cuando tienes un modelo que predice si un email es spam o no, puedes medir accuracy, F1, AUC con ground truth claro. Con LLMs, estás generando texto — y "¿qué tan buena es esta respuesta?" no tiene una sola respuesta correcta.

Además, las métricas tradicionales de NLP no capturan lo que importa para uso real:

  • Fluidez vs Factuality: Una oración puede ser gramaticalmente perfecta y completamente falsa.
  • Helpfulness vs Safety: El modelo puede ser útil para tareas dañinas.
  • Specificity vs Coverage: Respuestas cortas y precisas pueden perder contexto importante.

📐 Fundamentos Teóricos

La Métricas Tradicionales y Sus Limitaciones

Perplexity

Definición formal:

PP(W) = \sqrt[N]{\prod_{i=1}^{N} \frac{1}{P(w_i|w_1,...,w_{i-1})}} = 2^{-\frac{1}{N}\sum_{i=1}^{N} \log_2 P(w_i|w_1,...,w_{i-1})}

La perplexity mide qué tan sorprendendido está el modelo por el texto. **Problema**: Baja perplexity no implica alta calidad. Un modelo que simplemente memorizó Wikipedia tendrá baja perplexity en textos de Wikipedia pero será inútil para preguntas de sentido común.

BLEU Score

BLEU (Bilingual Evaluation Understudy) mide n-gram overlap entre candidato y referencia:

BLEU = BP \cdot \exp\left(\sum_{n=1}^{N} w_n \log p_n\right)

Donde BP es el brevity penalty, p_n es la precisión de n-gramas, y w_n son pesos (típicamente uniformes).

**Problema con BLEU**: Mide overlap léxico, no semántico. "El gato está en la mesa" y "La mesa tiene un gato encima" tienen BLEU = 0 si no comparten n-gramas.

ROUGE Score

ROUGE mide recall de n-gramas entre candidato y referencia. Variantes:

  • ROUGE-N: Overlap de N-gramas (típicamente ROUGE-1, ROUGE-2)
  • ROUGE-L: Longest Common Subsequence
  • ROUGE-S: Skip-bigram co-occurrence
ROUGE-N = \frac{\sum_{S \in \text{Reference}} \sum_{\text{gram}_n \in S} \min(\text{Count}_{match}(\text{gram}_n), \text{Count}_{ref}(\text{gram}_n))}{\sum_{S \in \text{Reference}} \sum_{\text{gram}_n \in S} \text{Count}_{ref}(\text{gram}_n)}

**Problema**: ROUGE funciona para summarization donde hay una referencia "correcta", pero para preguntas abiertas, múltiples respuestas son válidas.

METEOR

METEOR buscaalignment explícito entre candidato y referencia, considerando stemming y sinónimos:

METEOR = F_{mean} \cdot (1 - \text{penalty})

donde F_{mean} es la media armónica de precisión y recall, y penalty penaliza fragmentos descontinuos.

LLM-as-a-Judge: El Enfoque Moderno

La técnica más usada actualmente: usar un LLM (ej. GPT-4) para evaluar生成的 respuestas. El prompt típico:

JUDGE_PROMPT = """
Eres un evaluador experto de respuestas de IA.

Tarea: Evaluar la siguiente respuesta del asistente a la pregunta del usuario.

Pregunta: {question}

Respuesta del asistente: {response}

Evalúa en una escala de 1-5 en las siguientes dimensiones:
1. Relevancia: ¿La respuesta aborda lo que se preguntó?
2. Exactitud: ¿La información es correcta y verificable?
3. Completitud: ¿Cubre todos los aspectos de la pregunta?
4. Claridad: ¿Es fácil de entender?
5. Seguridad: ¿La respuesta es segura y no dañina?

Responde en JSON:
{{
  "scores": {{
    "relevance": <1-5>,
    "accuracy": <1-5>,
    "completeness": <1-5>,
    "clarity": <1-5>,
    "safety": <1-5>
  }},
  "overall": <1-5>,
  "reasoning": "<breve explicación de tu evaluación>"
}}
"""

**Ventajas**: Captura preferencias humanas, escala bien, no requiere ground truth.

**Desventajas**: Sesgo de autoreferencia (GPT-4 puede preferir respuestas estilo GPT-4), costo, no determinístico.

1. BLEU/ROUGE Scoring con NLTK

from nltk.translate.bleu_score import sentence_bleu, SmoothingFunction
from nltk.translate.ROUGE_score import rouge_n
from nltk.tokenize import word_tokenize
import numpy as np

class NLPMetrics:
    """Métricas tradicionales de NLP para generación de texto."""
    
    def __init__(self):
        self.smoother = SmoothingFunction().method1
    
    def bleu_score(self, reference: str, candidate: str, n: int = 4) -> float:
        """Calcula BLEU score para oraciones individuales."""
        ref_tokens = word_tokenize(reference.lower())
        cand_tokens = word_tokenize(candidate.lower())
        
        weights = [1/n] * n + [0] * (4 - n)
        try:
            score = sentence_bleu(
                [ref_tokens], 
                cand_tokens, 
                weights=weights[:n],
                smoothing_function=self.smoother
            )
        except:
            score = 0.0
        
        return score
    
    def rouge_n_score(self, reference: str, candidate: str, n: int = 1) -> float:
        """Calcula ROUGE-N score."""
        ref_tokens = word_tokenize(reference.lower())
        cand_tokens = word_tokenize(candidate.lower())
        
        ref_ngrams = self._get_ngrams(ref_tokens, n)
        cand_ngrams = self._get_ngrams(cand_tokens, n)
        
        if not ref_ngrams:
            return 0.0
        
        overlap = sum((ref_ngrams & cand_ngrams).values())
        total_ref = sum(ref_ngrams.values())
        
        return overlap / total_ref if total_ref > 0 else 0.0
    
    def _get_ngrams(self, tokens: list, n: int) -> dict:
        """Genera n-gramas y sus conteos."""
        ngrams = {}
        for i in range(len(tokens) - n + 1):
            ngram = tuple(tokens[i:i+n])
            ngrams[ngram] = ngrams.get(ngram, 0) + 1
        return ngrams
    
    def batch_evaluate(self, references: list, candidates: list) -> dict:
        """Evalúa múltiples pares referencia-candidato."""
        bleu_scores = []
        rouge1_scores = []
        rouge2_scores = []
        rougel_scores = []
        
        for ref, cand in zip(references, candidates):
            bleu_scores.append(self.bleu_score(ref, cand))
            rouge1_scores.append(self.rouge_n_score(ref, cand, 1))
            rouge2_scores.append(self.rouge_n_score(ref, cand, 2))
            rougel_scores.append(self.rouge_n_score(ref, cand, 3))
        
        return {
            "bleu": np.mean(bleu_scores),
            "rouge_1": np.mean(rouge1_scores),
            "rouge_2": np.mean(rouge2_scores),
            "rouge_l": np.mean(rougel_scores),
        }

# Uso
evaluator = NLPMetrics()

references = [
    "The quick brown fox jumps over the lazy dog",
    "Machine learning is a subset of artificial intelligence"
]

candidates = [
    "The quick brown fox jumps over the lazy dog",  # Perfect match
    "ML is part of AI",  # Semantic equivalent, different words
]

for ref, cand in zip(references, candidates):
    scores = {
        "bleu": evaluator.bleu_score(ref, cand),
        "rouge_1": evaluator.rouge_n_score(ref, cand, 1),
        "rouge_2": evaluator.rouge_n_score(ref, cand, 2),
    }
    print(f"Ref: {ref[:30]}...")
    print(f"Cand: {cand[:30]}...")
    print(f"Scores: {scores}\n")

2. LLM-as-Judge con GPT-4

from openai import OpenAI
from pydantic import BaseModel
from typing import Optional
import json

class EvaluationResult(BaseModel):
    relevance: int
    accuracy: int
    completeness: int
    clarity: int
    safety: int
    overall: int
    reasoning: str

class LLMJudge:
    """Usa GPT-4 como juez para evaluar respuestas."""
    
    JUDGE_PROMPT = """Eres un evaluador experto de respuestas de IA.
Evalúa la siguiente respuesta del asistente en una escala de 1-5.

Pregunta: {question}

Respuesta del asistente: {response}

Responde SOLO con JSON válido:
{{
  "relevance": <1-5>,
  "accuracy": <1-5>,
  "completeness": <1-5>,
  "clarity": <1-5>,
  "safety": <1-5>,
  "overall": <1-5>,
  "reasoning": "<explicación breve>"
}}"""
    
    def __init__(self, api_key: str):
        self.client = OpenAI(api_key=api_key)
        self.model = "gpt-4o"
    
    def evaluate(
        self, 
        question: str, 
        response: str,
        reference_answer: Optional[str] = None
    ) -> EvaluationResult:
        """Evalúa una respuesta simple."""
        
        prompt = self.JUDGE_PROMPT.format(
            question=question,
            response=response
        )
        
        if reference_answer:
            prompt += f"\n\nRespuesta de referencia (para contexto):\n{reference_answer}"
        
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}],
            temperature=0.0,  # Determinístico para reproducibilidad
            response_format={"type": "json_object"}
        )
        
        result = json.loads(response.choices[0].message.content)
        return EvaluationResult(**result)
    
    def batch_evaluate(
        self, 
        items: list[dict]
    ) -> list[EvaluationResult]:
        """Evalúa múltiples respuestas."""
        results = []
        for item in items:
            result = self.evaluate(
                question=item["question"],
                response=item["response"],
                reference_answer=item.get("reference")
            )
            results.append(result)
        return results

# Uso

3. Construir un Eval Pipeline Completo

from dataclasses import dataclass
from enum import Enum
from typing import Optional, Callable
import time
from datetime import datetime

class TaskType(Enum):
    QA = "qa"                    # Preguntas y respuestas
    SUMMARIZATION = "summ"       # Resúmenes
    TRANSLATION = "trans"        # Traducción
    CODE_GENERATION = "code"     # Generación de código
    CREATIVE = "creative"        # Escritura creativa

@dataclass
class EvalTask:
    task_id: str
    task_type: TaskType
    prompt: str
    reference: Optional[str] = None
    metadata: dict = None

@dataclass
class EvalResult:
    task_id: str
    task_type: TaskType
    metrics: dict
    latency_ms: float
    timestamp: datetime
    error: Optional[str] = None

class EvalPipeline:
    """Pipeline completo de evaluación para LLMs."""
    
    def __init__(self, model, judge: Optional[LLMJudge] = None):
        self.model = model
        self.judge = judge
        self.nlp_evaluator = NLPMetrics()
    
    def run_task(self, task: EvalTask) -> EvalResult:
        """Ejecuta una tarea individual y la evalúa."""
        start = time.time()
        
        try:
            # Generar respuesta
            response = self.model.generate(task.prompt)
            latency_ms = (time.time() - start) * 1000
            
            # Calcular métricas según el tipo de tarea
            metrics = self._compute_metrics(task, response)
            
            # Si hay judge, agregar evaluación humana
            if self.judge and task.task_type == TaskType.QA:
                judge_result = self.judge.evaluate(task.prompt, response, task.reference)
                metrics["llm_judge"] = {
                    "overall": judge_result.overall,
                    "relevance": judge_result.relevance,
                    "accuracy": judge_result.accuracy,
                    "reasoning": judge_result.reasoning
                }
            
            return EvalResult(
                task_id=task.task_id,
                task_type=task.task_type,
                metrics=metrics,
                latency_ms=latency_ms,
                timestamp=datetime.now()
            )
            
        except Exception as e:
            return EvalResult(
                task_id=task.task_id,
                task_type=task.task_type,
                metrics={},
                latency_ms=(time.time() - start) * 1000,
                timestamp=datetime.now(),
                error=str(e)
            )
    
    def _compute_metrics(self, task: EvalTask, response: str) -> dict:
        """Computa métricas según el tipo de tarea."""
        metrics = {"response_length": len(response)}
        
        if task.reference:
            # Métricas con referencia
            metrics["bleu"] = self.nlp_evaluator.bleu_score(task.reference, response)
            metrics["rouge_1"] = self.nlp_evaluator.rouge_n_score(task.reference, response, 1)
            metrics["rouge_2"] = self.nlp_evaluator.rouge_n_score(task.reference, response, 2)
        
        # Métricas sin referencia (固有)
        metrics["fluency"] = self._estimate_fluency(response)
        metrics["diversity"] = self._estimate_diversity(response)
        
        return metrics
    
    def _estimate_fluency(self, text: str) -> float:
        """Estimación simple de fluidez basada en estructuras."""
        sentences = text.split(".")
        avg_words = sum(len(s.split()) for s in sentences) / max(len(sentences), 1)
        # Oscila entre 0 y 1, óptimo alrededor de 15-25 palabras por oración
        return min(1.0, abs(20 - avg_words) / 20)
    
    def _estimate_diversity(self, text: str) -> float:
        """Ratio de tokens únicos vs total."""
        tokens = text.lower().split()
        if not tokens:
            return 0.0
        return len(set(tokens)) / len(tokens)
    
    def run_benchmark(self, tasks: list[EvalTask]) -> dict:
        """Ejecuta un benchmark completo."""
        results = [self.run_task(task) for task in tasks]
        
        # Agregar resultados
        successful = [r for r in results if not r.error]
        failed = [r for r in results if r.error]
        
        aggregate = {
            "total_tasks": len(tasks),
            "successful": len(successful),
            "failed": len(failed),
            "avg_latency_ms": sum(r.latency_ms for r in successful) / max(len(successful), 1),
        }
        
        # Agregar métricas por tipo de tarea
        for task_type in TaskType:
            type_results = [r for r in successful if r.task_type == task_type]
            if type_results:
                type_metrics = {}
                for metric_key in type_results[0].metrics.keys():
                    values = [r.metrics.get(metric_key, 0) for r in type_results]
                    type_metrics[f"{metric_key}_mean"] = sum(values) / len(values)
                
                aggregate[f"{task_type.value}_metrics"] = type_metrics
        
        return {"aggregate": aggregate, "detailed_results": results}

4. Diseñar Tasks Específicos para Tu Use Case

class TaskFactory:
    """Factory para crear tareas de evaluación específicas."""
    
    @staticmethod
    def create_qa_tasks(questions: list[dict]) -> list[EvalTask]:
        """Crea tareas de Q&A con ground truth."""
        return [
            EvalTask(
                task_id=q["id"],
                task_type=TaskType.QA,
                prompt=q["question"],
                reference=q.get("answer"),
                metadata={"source": q.get("source"), "difficulty": q.get("difficulty")}
            )
            for q in questions
        ]
    
    @staticmethod
    def create_code_tasks(coding_prompts: list[dict]) -> list[EvalTask]:
        """Crea tareas de generación de código con tests unitarios."""
        return [
            EvalTask(
                task_id=p["id"],
                task_type=TaskType.CODE_GENERATION,
                prompt=p["prompt"],
                reference=p.get("solution"),
                metadata={
                    "language": p["language"],
                    "tests": p.get("tests"),
                    "complexity": p.get("complexity", "medium")
                }
            )
            for p in coding_prompts
        ]
    
    @staticmethod
    def create_domain_specific_tasks(
        domain: str,
        samples: list[dict]
    ) -> list[EvalTask]:
        """Crea tareas específicas para un dominio (ej. legal, medical, finance)."""
        
        domain_config = {
            "legal": {
                "task_type": TaskType.QA,
                "required_fields": ["case_description", "question", "correct_answer"],
            },
            "medical": {
                "task_type": TaskType.QA,
                "required_fields": ["symptoms", "question", "diagnosis"],
            },
            "finance": {
                "task_type": TaskType.QA,
                "required_fields": ["transaction_data", "question", "expected_result"],
            }
        }
        
        config = domain_config.get(domain, {})
        return [
            EvalTask(
                task_id=s.get("id", f"{domain}_{i}"),
                task_type=config.get("task_type", TaskType.QA),
                prompt=s.get("prompt") or TaskFactory._build_prompt(domain, s),
                reference=s.get("answer") or s.get("correct_answer") or s.get("diagnosis"),
                metadata={"domain": domain, **s}
            )
            for i, s in enumerate(samples)
        ]
    
    @staticmethod
    def _build_prompt(domain: str, sample: dict) -> str:
        """Construye prompt desde campos específicos del dominio."""
        if domain == "legal":
            return f"Caso: {sample['case_description']}\nPregunta: {sample['question']}"
        elif domain == "medical":
            return f"Síntomas: {sample['symptoms']}\nPregunta: {sample['question']}"
        return str(sample)

🚨 Los 3 Errores Más Graves que He Visto en Producción

Error 1: Usar Perplexity Como Métrica Principal (El Error del 90%)

**El problema**: Me dice "Nuestro modelo tiene perplexity = 15.3, que es muy buena". No, parcero. Perplexity mide qué tan surprised está el modelo por el texto, no si el modelo es útil.

La relación entre perplexity y calidad perceptual es weak en el mejor de los casos:

  • Un modelo que memorizó Wikipedia tendrá baja perplexity en textos similares, pero fallará en preguntas de sentido común
  • Perplexity no captura coherencia, factualidad, o helpfulness
  • Dos modelos con perplexity similar pueden tener desempeño radicalmente diferente en tareas reales

**El fix correcto**: Perplexity es útil para comparar versiones del mismo modelo durante entrenamiento, pero para evaluación de calidad usa:

# LO QUE HACES (MAL):
model_a_perplexity = 42.3
model_b_perplexity = 38.7
# => "Modelo B es mejor porque tiene menor perplexity"

# LO QUE DEBERÍAS HACER:

    EvalTask(task_id="t1", task_type=TaskType.QA, 
             prompt="¿Por qué el cielo es azul?", reference="Dispersión Rayleigh..."),
    EvalTask(task_id="t2", task_type=TaskType.QA,
             prompt="¿Cómo funciona la fotosíntesis?", reference="Conversión de luz..."),
    # ... 100+ tareas específicas de tu dominio
]

pipeline_a = EvalPipeline(model_a, judge=judge)

print(f"Modelo B - LLM Judge Overall: {results_b['aggregate']['qa_metrics']['llm_judge_overall_mean']:.2f}")

Error 2: No Tener Ground Truth para Tu Use Case Específico (El Error del 80%)

**El problema**: Evalúas con benchmarks genéricos (MMLU, HELM) y infieres que tu modelo para atención médica colombiana va a funcionar bien. NO.

Los benchmarks genéricos no capturan:

  • El vocabulario específico de tu dominio
  • Las edge cases de tu mercado (ej. regulaciones colombianas)
  • Las distribuciones de queries reales de tus usuarios

**El fix correcto**: Construir un eval set de tu dominio específico:

class DomainEvalSetBuilder:
    """Construye un eval set específico para tu dominio."""
    
    def __init__(self, domain: str):
        self.domain = domain
        self.tasks = []
    
    def add_task(self, prompt: str, reference: str, metadata: dict = None):
        """Agrega una tarea al eval set."""
        self.tasks.append({
            "prompt": prompt,
            "reference": reference,
            "metadata": metadata or {}
        })
    
    def add_from_samples(self, samples: list[dict], prompt_field: str, 
                         reference_field: str):
        """Agrega tareas desde samples existentes."""
        for sample in samples:
            self.add_task(
                prompt=sample[prompt_field],
                reference=sample[reference_field],
                metadata=sample
            )
    
    def build(self, train_ratio: float = 0.0) -> tuple:
        """Construye train/val/test splits."""
        # Para evaluation pura, train_ratio = 0
        n_total = len(self.tasks)
        n_train = int(n_total * train_ratio)
        
        np.random.shuffle(self.tasks)
        
        train = self.tasks[:n_train]
        val = self.tasks[n_train:]
        
        train_tasks = [EvalTask(**t) for t in train]
        val_tasks = [EvalTask(**t) for t in val]
        
        return train_tasks, val_tasks
    
    def save(self, path: str):
        """Guarda el eval set a disco."""
        import json
        with open(path, 'w') as f:
            json.dump({"domain": self.domain, "tasks": self.tasks}, f, indent=2)

Error 3: Evaluar en Test Set Igual al Deployment Distribution (El Error del 70%)

**El problema**: Hiciste eval enBenchmarks y tu modelo sacó 92% en MMLU. Perfecto, ¿no? Pero en producción, tus usuarios preguntan cosas diferentes — preguntas en español colombiano, con referencias culturales locales, sobre productos específicos del mercado local.

Esto se llama distribution shift: tu eval set no refleja la distribución real de inputs en producción.

**El fix correcto**: Diseña tu eval set con distribución que refleje producción + casos edge:

class ProductionReflectiveEvalSet:
    """Construye eval set que refleja la distribución real de producción."""
    
    def __init__(self, production_logs: list[dict]):
        """
        production_logs: lista de {'prompt': str, 'response': str, 
                                   'user_rating': int, 'metadata': dict}
        """
        self.logs = production_logs
        self.eval_tasks = []
    
    def build_from_logs(self, sample_size: int = 1000) -> list[EvalTask]:
        """Construye eval set muestreando de logs de producción."""
        # Sample estratificado basado en user_rating
        low_rating = [l for l in self.logs if l.get('user_rating', 3) <= 2]
        mid_rating = [l for l in self.logs if l.get('user_rating', 3) == 3]
        high_rating = [l for l in self.logs if l.get('user_rating', 3) >= 4]
        
        # 50% de casos problemáticos (low rating)
        # 30% de casos neutros
        # 20% de casos exitosos
        n_low = int(sample_size * 0.5)
        n_mid = int(sample_size * 0.3)
        n_high = sample_size - n_low - n_mid
        
        sampled = (
            random.sample(low_rating, min(n_low, len(low_rating))) +
            random.sample(mid_rating, min(n_mid, len(mid_rating))) +
            random.sample(high_rating, min(n_high, len(high_rating)))
        )
        
        # Crear tareas con la respuesta de producción como "reference"
        # y evaluar si tu nuevo modelo puede igualar o superar
        for i, log in enumerate(sampled):
            self.eval_tasks.append(EvalTask(
                task_id=f"prod_{i}",
                task_type=TaskType.QA,  # Ajustar según dominio
                prompt=log['prompt'],
                reference=log['response'],  # La respuesta actual en producción
                metadata={
                    'user_rating': log.get('user_rating'),
                    'original_model': log.get('model_version'),
                    'is_problematic': log.get('user_rating', 3) <= 2
                }
            ))
        
        return self.eval_tasks
    
    def add_adversarial_cases(self, adversarial_prompts: list[str]):
        """Agrega casos adversarial conocidos."""
        for i, prompt in enumerate(adversarial_prompts):
            self.eval_tasks.append(EvalTask(
                task_id=f"adv_{i}",
                task_type=TaskType.QA,
                prompt=prompt,
                reference="[RESPONSE_SHOULD_BE_SAFE]",  # Placeholder
                metadata={'is_adversarial': True}
            ))

✅ Resumen y Cierre

Parcero, la evaluación de LLMs no es trivial y el error más grave es medir lo fácil en vez de lo importante. Resumiendo lo que aprendimos hoy:

  • Perplexity = útil solo para comparar versiones de un mismo modelo durante entrenamiento, NO para calidad
  • BLEU/ROUGE = útiles para tareas con referencia única (traducción, summarización), limitados para generación abierta
  • LLM-as-Judge = el estándar actual, pero costoso y con sesgos propios
  • Benchmarks (MMLU, HELM) = buenos para comparación general, NO reflejan tu use case específico
  • Eval set propio = obligatorio si vas a deployar en producción

La fórmula para eval que funcione:

Eval_{good} = \{t_i \sim P_{production}\} \cup \{adversarial\} \cup \{edge\_cases\}

Es decir, tu eval set debe muestrear de la distribución real de producción, más casos adversarial, más edge cases.

Y recuerdalo: en Colombia decimos "el que no mide, no mejora". Si no tienes un eval pipeline robusto, no estás mejorando tu modelo — estás adivinando.
