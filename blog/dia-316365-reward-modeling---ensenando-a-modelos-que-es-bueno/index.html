LLM Code Understanding — El 80% No Sabe y el 20% Lo Usa Para Entender Código

Hagale pues, parcero. Día 316 y hoy le vamos a meter el diente al tema de usar LLMs para entender código. Porque voir, hay mucha gente que o no los usa para esto, o los usa mal. El 80% no sabe cómo hacerlo correctamente. Hoy les voy a mostrar cómo el 20%剩余 lo usa para entender código, encontrar bugs y hacer code review como profesionales. Póngale café porque esto va interesante.

🤔 El Problema: Por Qué el Código Necesita LLMs

El código es lenguaje. Y los LLMs son dioses en lenguaje. Entonces, ¿por qué tanta gente no los usa para entender código? La respuesta es simple: no saben cómo preguntar. Le piden "explica este código" y el LLM les da una respuesta genérica y useless. Hay que saber promptear para obtener información útil.

Qué Puede Hacer un LLM Con Código:

  • Explicar código complejo: Traducir lógica críptica a español claro
  • Encontrar bugs: Detectar edge cases y errores lógicos
  • Code review: Identificar mejoras, security issues, performance
  • Trace execution: Simular el flujo de ejecución paso a paso
  • Documentar: Generar docs desde el código

⚠️ Error 1: No Usar LLMs Para Code Review

El primer error que veo es que la gente hace code review sola, sin ayuda de un LLM. O peor, no hace code review del todo. Esto es un error gravísimo porque un LLM puede revisar tu código en segundos y encontrar problemas que a ti te tomarían horas.

El Fix: Code Review Asistido con LLM

from typing import List, Dict, Optional
import re

class LLMCodeReviewer:
    """Framework para code review asistido con LLM."""
    
    def __init__(self, llm_client):
        self.llm = llm_client
        self.review_categories = [
            "security",
            "performance", 
            "readability",
            "bug_risk",
            "best_practices",
            "error_handling"
        ]
    
    def review_code(self, code: str, language: str = "python") -> Dict:
        """Realizar review completo del código."""
        # Análisis estático primero
        static_analysis = self._static_analysis(code, language)
        
        # Análisis dinámico con LLM
        llm_review = self._llm_review(code, language)
        
        # Combinar resultados
        return {
            "static": static_analysis,
            "llm": llm_review,
            "summary": self._generate_summary(static_analysis, llm_review),
            "severity": self._calculate_severity(llm_review)
        }
    
    def _static_analysis(self, code: str, language: str) -> Dict:
        """Análisis estático sin LLM."""
        issues = []
        
        # Detectar credenciales hardcodeadas
        if re.search(r'(password|api_key|secret|token)\s*=\s*["\'][^"\']+["\']', code, re.I):
            issues.append({"type": "security", "severity": "critical", 
                          "message": "Posible credencial hardcodeada"})
        
        # Detectar TODO/FIXME
        todos = re.findall(r'(TODO|FIXME|HACK|XXX):?', code, re.I)
        if todos:
            issues.append({"type": "maintainability", "severity": "low",
                          "message": f"Encontrados {len(todos)} marcadores: {todos}"})
        
        # Detectar except vacío
        if re.search(r'except\s*:\s*(?:pass)?\s*(?:#|$)', code, re.M):
            issues.append({"type": "bug_risk", "severity": "high",
                          "message": "Except vacío que ignora errores"})
        
        return {"issues": issues, "lines": len(code.splitlines())}
    
    def _llm_review(self, code: str, language: str) -> Dict:
        """Review profundo con LLM."""
        prompt = f"""Analiza el siguiente código {language} y proporciona:
1. Explicación del propósito del código
2. Posibles bugs o edge cases
3. Mejoras de seguridad
4. Mejoras de performance
5. Mejoras de legibilidad

Código:
```{language}
{code}
```"""
        
        # Aquí iría la llamada real al LLM
        # Por ahora retornamos estructura
        return {
            "purpose": "Análisis pendiente de LLM",
            "bugs": [],
            "security": [],
            "performance": [],
            "readability": []
        }

La regla de oro: Nunca hagas code review solo. Un LLM puede revisar tu código en 10 segundos y encontrar problemas que vos no viste en horas. Úsalo como primer filtro antes de pedirle a un humano que lo revise.

⚠️ Error 2: Confiar en el LLM Sin Verificación

El segundo error es trusting the LLM's code understanding sin verificar. El LLM te dice "este código está bien" y vos lo creés. Grave error. Los LLMs pueden malinterpretar el código, especialmente si es complejo o tiene dependencias externas.

El Fix: Verificación de Entendimiento con Tests

class CodeUnderstandingVerifier:
    """Verificador de que el LLM realmente entendió el código."""
    
    def __init__(self, llm_client, code_executor):
        self.llm = llm_client
        self.executor = code_executor
    
    def verify_understanding(self, code: str, explanation: str) -> Dict:
        """Verificar que la explicación del LLM es correcta."""
        # Generar test cases basados en la explicación
        test_cases = self._generate_tests_from_explanation(code, explanation)
        
        results = []
        for test in test_cases:
            # Ejecutar test
            execution_result = self.executor.run(test["code"], test["input"])
            expected = test["expected"]
            
            # Comparar
            matches = execution_result == expected
            results.append({
                "test": test["description"],
                "input": test["input"],
                "expected": expected,
                "actual": execution_result,
                "passed": matches
            })
        
        # Calcular accuracy
        accuracy = sum(1 for r in results if r["passed"]) / len(results) if results else 0
        
        return {
            "accuracy": accuracy,
            "results": results,
            "understanding_verified": accuracy >= 0.8,
            "warnings": self._generate_warnings(results)
        }
    
    def _generate_tests_from_explanation(self, code: str, explanation: str) -> List[Dict]:
        """Generar tests que verifican la explicación del LLM."""
        # El LLM genera casos de prueba basados en su explicación
        prompt = f"""Basado en esta explicación del código:
{explanation}

Genera 3-5 casos de prueba en formato:
- descripción
- input
- código de test
- expected output

Código original:
{code}"""
        
        # Aquí iría la llamada al LLM
        return []
    
    def _generate_warnings(self, results: List[Dict]) -> List[str]:
        """Generar warnings si hay problemas."""
        warnings = []
        failed = [r for r in results if not r["passed"]]
        if failed:
            warnings.append(f"{len(failed)}/{len(results)} tests fallaron")
            for fail in failed:
                warnings.append(f"  - {fail['test']}: expected {fail['expected']}, got {fail['actual']}")
        return warnings

La regla de oro: Si el LLM te explica código y decís implementarlo, generá tests primero. Si los tests fallan, el LLM no entendió bien el código. Verify, then trust.

⚠️ Error 3: No Saber Cómo Promptear Para Code Understanding

El tercer error es no saber cómo preguntar. Le decís "explica este código" y obtenés una respuesta genérica. Pero si le preguntás bien, obtenés información específica y útil. La diferencia está en el prompt.

El Fix: Prompts Específicos Para Diferentes Objetivos

class CodeUnderstandingPrompter:
    """Colección de prompts optimizados para entender código."""
    
    # Prompts para diferentes objetivos
    EXPLAIN_WITH_CONTEXT = """Explica este código como si fuera un mentor senior.
Contexto del proyecto: {context}
Código:
```{language}
{code}
```

Para cada función/método principal:
1. Qué hace (en 1-2 oraciones)
2. Por qué está implementado así (no de otra forma)
3. Posibles edge cases"""

    FIND_BUGS = """Eres un bug hunter experto. Analiza este código {language} y busca:
- Bugs lógicos (división por cero, null pointers, off-by-one)
- Edge cases no manejados
- Race conditions (si es concurrent)
- Memory leaks (si es C/C++/Rust)

Código:
```{language}
{code}
```

Para cada bug encontrado:
1. Ubicación (línea/función)
2. Descripción del problema
3. Condición que lo dispara
4. Severidad (crit/high/medium/low)"""

    TRACE_EXECUTION = """Tracea la ejecución de este código paso a paso, como un debugger humano.
Para cada paso indica:
1. Línea que se ejecuta
2. Estado de las variables importantes
3. Decisión que se toma (si hay condicional)

Código:
```{language}
{code}
```

Input de prueba: {input}"""

    REVIEW_SECURITY = """Eres un security auditor. Revisa este código {language} buscando:
- Inyección SQL/NoSQL
- XSS (si output HTML)
- Path traversal
- Hardcoded credentials
- Unsafe deserialization
- CSRF vulnerabilities

Código:
```{language}
{code}
```

Para cada vulnerabilidad:
1. Tipo
2. Ubicación
3. Exploit scenario
4. Fix recomendado"""

    def __init__(self, llm_client):
        self.llm = llm_client
    
    def explain(self, code: str, context: str = "", language: str = "python") -> str:
        """Explicación con contexto."""
        prompt = self.EXPLAIN_WITH_CONTEXT.format(
            context=context, code=code, language=language
        )
        return self.llm.generate(prompt)
    
    def find_bugs(self, code: str, language: str = "python") -> List[Dict]:
        """Encontrar bugs con severidad."""
        prompt = self.FIND_BUGS.format(code=code, language=language)
        return self.llm.generate_structured(prompt)
    
    def trace(self, code: str, input_data: str, language: str = "python") -> str:
        """Tracear ejecución con input específico."""
        prompt = self.TRACE_EXECUTION.format(
            code=code, input=input_data, language=language
        )
        return self.llm.generate(prompt)

📐 Code Understanding Framework Completo

class CompleteCodeUnderstandingFramework:
    """
    Framework completo para entender código con LLMs.
    Incluye: explicación, bug finding, review, y tracing.
    """
    
    def __init__(self, llm_client, code_executor=None):
        self.llm = llm_client
        self.reviewer = LLMCodeReviewer(llm_client)
        self.verifier = CodeUnderstandingVerifier(llm_client, code_executor)
        self.prompter = CodeUnderstandingPrompter(llm_client)
    
    def understand(self, code: str, mode: str = "explain", **kwargs) -> Dict:
        """
        Entender código en diferentes modos.
        
        Modes:
        - explain: Explicación general con contexto
        - bugs: Encontrar bugs potenciales
        - review: Code review completo
        - trace: Tracear ejecución con input
        - security: Auditoría de seguridad
        """
        if mode == "explain":
            result = self.prompter.explain(
                code, 
                context=kwargs.get("context", ""),
                language=kwargs.get("language", "python")
            )
            # Verificar que entendió bien
            if kwargs.get("verify", True):
                verification = self.verifier.verify_understanding(code, result)
                return {"explanation": result, "verification": verification}
            return {"explanation": result}
        
        elif mode == "bugs":
            return self.prompter.find_bugs(code, kwargs.get("language", "python"))
        
        elif mode == "review":
            return self.reviewer.review_code(code, kwargs.get("language", "python"))
        
        elif mode == "trace":
            return self.prompter.trace(
                code,
                input_data=kwargs.get("input", ""),
                language=kwargs.get("language", "python")
            )
        
        elif mode == "security":
            return self.prompter.review_security(
                code, 
                language=kwargs.get("language", "python")
            )
        
        else:
            raise ValueError(f"Modo desconocido: {mode}")

📊 Resumen: Las 3 Reglas de Oro

  • Usa LLMs para code review: No hagas review solo. El LLM es tu primer filtro — rápido, no se cansa, y encuentra cosas que vos no viste. Después un humano revisa lo que el LLM encontró.
  • Verifica siempre: Si el LLM te explica código y decís implementarlo, generá tests primero. Si los tests fallan, el LLM no entendió bien. Verify, then trust.
  • Preguntá bien: "Explica este código" vs "Encuentra bugs de seguridad en este código" vs "Tracea la ejecución con input X". Cada pregunta genera respuestas diferentes. Aprende a promptear.
