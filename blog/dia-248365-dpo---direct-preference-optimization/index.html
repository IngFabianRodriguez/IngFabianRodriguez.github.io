DPO - Direct Preference Optimization

Hagale pues, parcero. Hoy es el Dia 248 y hablamos de DPO: Direct Preference Optimization. La alternativa a RLHF que es mas simple. Cafe.

DPO

DPO (Direct Preference Optimization) es una tecnica que elimina la necesidad de reward model y PPO. Usa una perdida directa para alinear el modelo con preferencias humanas.

Ventajas sobre RLHF:

  • Mas Simple: Sin reward model separado
  • Mas Estable: Sin hyperparameters de PPO
  • Menos Computo: Solo una perdida, no iteraciones de RL

La Loss De DPO

import torch

def dpo_loss(policy_chosen, policy_rejected, 
              ref_chosen, ref_rejected, beta=0.1):
    """
    policy_chosen: log probs del modelo para respuesta elegida
    policy_rejected: log probs para respuesta rechazada
    ref_* : log probs del modelo de referencia (SFT)
    """
    # Ratio de probabilidades
    chosen_probs = torch.exp(policy_chosen - ref_chosen)
    rejected_probs = torch.exp(policy_rejected - ref_rejected)
    
    # Loss de DPO
    logits = chosen_probs / (chosen_probs + rejected_probs)
    loss = -torch.log(logits + 1e-8).mean()
    
    return loss

Errores Comunes

Error 1: Beta Muy Alto

El problema: Desviacion excesiva del modelo base.

La solucion: Beta entre 0.1-0.3 es tipicamente bueno.
