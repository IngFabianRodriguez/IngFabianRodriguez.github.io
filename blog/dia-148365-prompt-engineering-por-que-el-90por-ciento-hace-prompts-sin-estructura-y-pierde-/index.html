Prompt Engineering - Por qué el 90% hace prompts sin estructura y pierde performance

28 de april de 2026
openai

Hola, parcero. Llegamos al Día 148 y hoy vamos con Prompt Engineering Avanzado. Este tema me lo piden cada semana: la gente hace prompts como si fuera WhatsApp — un párrafo largo sin estructura y se preguntan por qué el modelo responde cualquier cosa. El 90% menciona el título. Vamos a cambiar eso hoy con implementaciones reales y los errores que veo en producción. Acompañame.

📐 Fundamentos Teóricos

Un prompt no es "un texto que le mando al modelo". Es un programa que le dice al modelo cómo pensar, no solo qué responder. La diferencia entre un buen y mal prompt es la misma diferencia entre un programa bien estructurado y un script spaguetti.

Few-shot examples son demonios de demostraciones. En lugar de explicarrules abstractas, le das al modelo ejemplos concretos de input → output. El modelo infiere el patrón. Pero aquí está el detalle: si tus ejemplos no son diversos ni representativos de la distribución real de inputs, el modelo sobreajusta a esos ejemplos específicos y falla en inputs distintos.

Chain-of-Thought (CoT) es la técnica de agregar "pasos de razonamiento" antes de la respuesta final. Funciona porque fuerza al modelo a mostrar su trabajo — errores de reasoning se hacen visibles y corregibles. Pero para tareas simples (clasificaciónbinaria, extracción de entidades), CoT es overkill: agrega tokens innecesarios y latency sin beneficio.

Tree-of-Thoughts (ToT) extiende CoT permitiendo múltiples ramas de razonamiento paralelo. El modelo explora varios paths y selecciona el mejor. Más computación, pero mejor calidad en tareas de planificación.

Self-consistency muestrea el mismo prompt múltiples veces con temperature > 0 y selecciona la respuesta más frecuente. Reduce la varianza en tareas de reasoning donde múltiples paths pueden llegar a diferentes respuestas.

💻 Implementación Práctica

import torch
from typing import List, Dict, Any, Optional
from collections import Counter

# ──────────────────────────────────────────────
# 1. FEW-SHOT EXAMPLE SELECTOR
# ──────────────────────────────────────────────

class FewShotExampleSelector:
    """Selecciona ejemplos diversos y representativos para few-shot prompting."""

    def __init__(self, examples: List[Dict[str, str]], embedding_model=None):
        self.examples = examples
        self.embedding_model = embedding_model or self._default_embedding

    def _default_embedding(self, text: str) -> torch.Tensor:
        # Simulación simple de embedding usando hash + dirección
        hash_val = hash(text) % 1000
        vec = torch.zeros(128)
        vec[hash_val % 128] = 1.0
        vec[(hash_val * 3) % 128] = 0.5
        return vec

    def select_diverse(self, query: str, n: int = 4) -> List[Dict[str, str]]:
        """Selecciona n ejemplos diversos cubriendo diferentes aspectos."""
        query_emb = self.embedding_model(query)
        example_embs = [self.embedding_model(ex['input']) for ex in self.examples]

        # Calcular similitud coseno
        similarities = [
            torch.nn.functional.cosine_similarity(query_emb.unsqueeze(0), ex.unsqueeze(0)).item()
            for ex in example_embs
        ]

        # Primero: el más similar (más relevante)
        most_similar_idx = similarities.index(max(similarities))
        selected = [self.examples[most_similar_idx]]

        # Segundo: seleccionar los más diversos entre sí
        remaining_idx = [i for i in range(len(self.examples)) if i != most_similar_idx]
        while len(selected) < n and remaining_idx:
            # Seleccionar el que maximice la distancia mínima a los ya seleccionados
            best_idx = None
            best_min_dist = -1
            for idx in remaining_idx:
                min_dist = min(
                    torch.nn.functional.pairwise_distance(
                        example_embs[idx].unsqueeze(0),
                        example_embs[s_idx].unsqueeze(0)
                    ).item()
                    for s_idx in [self.examples.index(ex) for ex in selected]
                )
                if min_dist > best_min_dist:
                    best_min_dist = min_dist
                    best_idx = idx

            if best_idx is not None:
                selected.append(self.examples[best_idx])
                remaining_idx.remove(best_idx)
            else:
                break

        return selected

    def format_prompt(self, query: str, n: int = 4) -> str:
        """Formatea prompt con n ejemplos few-shot."""
        selected = self.select_diverse(query, n)
        prompt = "Ejemplos:\n"
        for ex in selected:
            prompt += f"Input: {ex['input']}\nOutput: {ex['output']}\n\n"
        prompt += f"Input: {query}\nOutput:"
        return prompt

# ──────────────────────────────────────────────
# 2. CHAIN-OF-THOUGHT PROMPTING
# ──────────────────────────────────────────────

class ChainOfThoughtPrompting:
    """Chain-of-thought con few-shot examples."""

    def __init__(self, model, use_cot: bool = True):
        self.model = model
        self.use_cot = use_cot

    def format_cot_example(self, input_text: str, output_text: str) -> str:
        """Formatea ejemplo con razonamiento chain-of-thought."""
        return f"Input: {input_text}\nRazonamiento: {output_text.split('|')[0].strip()}\nRespuesta: {output_text.split('|')[1].strip()}\n"

    def format_no_cot_example(self, input_text: str, output_text: str) -> str:
        """Formatea ejemplo sin CoT (respuesta directa)."""
        return f"Input: {input_text}\nRespuesta: {output_text}\n"

    def generate(self, prompt: str, few_shot_examples: List[Dict], temperature: float = 0.7) -> Dict[str, str]:
        """Genera respuesta con o sin CoT."""
        if not self.use_cot:
            formatted_prompt = "Ejemplos:\n"
            for ex in few_shot_examples:
                formatted_prompt += self.format_no_cot_example(ex['input'], ex['output'])
            formatted_prompt += f"\n{prompt}\nRespuesta:"
        else:
            formatted_prompt = "Ejemplos (con razonamiento):\n"
            for ex in few_shot_examples:
                formatted_prompt += self.format_cot_example(ex['input'], ex['output'])
            formatted_prompt += f"\nInput: {prompt}\nRazonamiento:"

        # Simular llamada al modelo
        response = self.model(formatted_prompt, temperature=temperature)

        if self.use_cot and '|' in response:
            reasoning, answer = response.rsplit('|', 1)
            return {'reasoning': reasoning.strip(), 'answer': answer.strip()}
        return {'answer': response.strip()}

# ──────────────────────────────────────────────
# 3. SELF-CONSISTENCY
# ──────────────────────────────────────────────

def self_consistency(model_fn, prompt: str, n_samples: int = 5, temperature: float = 0.8) -> Dict[str, Any]:
    """
    Self-consistency: muestrea n veces y selecciona la respuesta más frecuente.
    Reduce varianza en tareas de razonamiento.
    """
    responses = []
    for _ in range(n_samples):
        response = model_fn(prompt, temperature=temperature)
        # Extraer la respuesta final (última oración o línea)
        answer = response.strip().split('\n')[-1]
        responses.append(answer)

    counter = Counter(responses)
    most_common = counter.most_common()

    return {
        'most_frequent_answer': most_common[0][0],
        'frequency': most_common[0][1] / n_samples,
        'all_answers': most_common,
        'entropy': -sum(
            (count/n_samples) * torch.log(torch.tensor(count/n_samples))
            for _, count in most_common
        ).item()
    }

# 4. PROMPT TEMPLATE FORMATTER
# ──────────────────────────────────────────────

class PromptTemplate:
    """Template de prompt con variables."""

    def __init__(self, template: str):
        self.template = template

    def format(self, **kwargs) -> str:
        try:
            return self.template.format(**kwargs)
        except KeyError as e:
            raise ValueError(f"Variable faltante en template: {e}")

    @staticmethod
    def few_shot_template() -> 'PromptTemplate':
        return PromptTemplate(
            """Contexto: {context}

Ejemplos:
{examples}

Pregunta: {question}

Instrucciones: {instructions}"""
        )

# 5. SYSTEM PROMPT MANAGER
# ──────────────────────────────────────────────

class SystemPromptManager:
    """Administra system prompts evitando que Compitan con user prompts."""

    MAX_SYSTEM_PROMPT_TOKENS = 500  # Aproximado

    def __init__(self, system_prompt: str):
        self.base_system_prompt = system_prompt

    def build(self, user_prompt: str, context: Optional[str] = None, task_instructions: str = "") -> Dict[str, str]:
        """
        Construye messages para API, separando claramente system y user.
        """
        full_system = self.base_system_prompt
        if task_instructions:
            full_system += f"\n\n## Tarea Actual\n{task_instructions}"
        if context:
            full_system += f"\n\n## Contexto\n{context}"

        # Warning si el system prompt está creciendo demasiado
        estimated_tokens = len(full_system.split()) * 1.3
        if estimated_tokens > self.MAX_SYSTEM_PROMPT_TOKENS:
            print(f"[WARNING] System prompt estimado en {estimated_tokens:.0f} tokens, mayor a {self.MAX_SYSTEM_PROMPT_TOKENS}")

        return {
            'system': full_system,
            'user': user_prompt
        }

# ──────────────────────────────────────────────
# 6. COMPARISON DE PROMPTING STRATEGIES
# ──────────────────────────────────────────────

def compare_prompting_strategies(task: str, model_fn, n_trials: int = 3) -> Dict[str, List[Dict]]:
    """
    Compara diferentes prompting strategies en la misma tarea.
    """
    strategies = {
        'direct': f"Responde directamente: {task}",
        'few_shot_2': f"Input: ejemplo1 → Output: resp1\nInput: ejemplo2 → Output: resp2\n\nInput: {task}\nOutput:",
        'cot': f"Input: {task}\nRazonamiento paso a paso:\n1.",
        'cot_few_shot': "Ejemplos:\nInput: p1 → Razonamiento: r1 paso | Respuesta: a1\nInput: p2 → Razonamiento: r2 paso | Respuesta: a2\n\n" + f"Input: {task}\nRazonamiento:",
    }

    results = {}
    for name, prompt in strategies.items():
        strategy_results = []
        for trial in range(n_trials):
            response = model_fn(prompt, temperature=0.7)
            strategy_results.append({
                'trial': trial + 1,
                'response': response,
                'length': len(response.split())
            })
        results[name] = strategy_results

    return results

🚨 Los 3 Errores Más Frecuentes

❌ Error 1: Few-shot sin ejemplos diversos ni representativos

Este error es más común de lo que crees. La gente toma los primeros 4 ejemplos que tiene a mano y los pone en el prompt. Si esos ejemplos son todos del mismo tipo de input, el modelo aprende a responder solo para ese tipo específico.

Por ejemplo, si todos tus ejemplos de sentiment son sobre productos tecnológicos, y el usuario pregunta sobre una película, el modelo fallará. O si todos tus ejemplos de code review son de Python y el usuario pregunta sobre JavaScript, el modelo aplicará patrones incorrectos.

Fix: Selecciona ejemplos que cubran la diversidad de la distribución real de inputs:

  • Usa clustering sobre embeddings de inputs para asegurar diversidad
  • Incluye ejemplos edge case y de dificultad variada
  • Si la tarea tiene subtipos, incluye ejemplos de cada subtipo
  • Usa técnicas de active learning para seleccionar los ejemplos más informativos
# Selección inteligente de ejemplos
def smart_few_shot_selector(examples: List[Dict], query: str, n: int = 4):
    """Selecciona ejemplos diversos Y relevantes para el query."""
    # 1. Embeddings de query y ejemplos
    query_emb = embed(query)
    ex_embs = [embed(ex['input']) for ex in examples]

    # 2. Calcular relevancia (similitud) y diversidad (distancia)
    relevance_scores = [cosine_sim(query_emb, ex) for ex in ex_embs]

    # 3. MMR (Maximal Marginal Relevance) para balancear
    selected_idx = []
    remaining = list(range(len(examples)))

    for _ in range(n):
        if not remaining:
            break
        mmr_scores = []
        for idx in remaining:
            relevance = relevance_scores[idx]
            diversity = min(
                cosine_sim(ex_embs[idx], ex_embs[i])
                for i in selected_idx
            ) if selected_idx else 0
            mmr = 0.7 * relevance + 0.3 * diversity
            mmr_scores.append((idx, mmr))

        best_idx = max(mmr_scores, key=lambda x: x[1])[0]
        selected_idx.append(best_idx)
        remaining.remove(best_idx)

    return [examples[i] for i in selected_idx]

❌ Error 2: Chain-of-thought para tareas simples

CoT tiene un costo. Aumenta el número de tokens generados por respuesta (latency + costo). Si tu tarea es clasificación binaria simple, extracción de entidades, o cualquier tarea donde la respuesta es directa, CoT no solo es innecesario — puede empeorar los resultados porque el modelo tiene más espacio para desviarse del path correcto.

Un indicador de que CoT es overkill: si puedes resolver la tarea mirando solo el input sin necesidad de "pensar en voz alta".

Fix: Usa CoT solo cuando la tarea lo justifique:

  • Sí CoT: math reasoning, lógica compleja, debugging, planificación multi-step, preguntas que requieren justificación
  • No CoT: sentiment binario, extracción de keywords, clasificación en categorías conocidas, formateo de datos

❌ Error 3: System prompt tan largo que compite con el user prompt por atención

He visto system prompts de 2000+ palabras. Parece razonable: "el modelo necesita saber todo sobre cómo comportarse". Pero la realidad es queattention es un recurso limitado. Si el system prompt tiene 50 instrucciones compitiendo entre sí, el modelo diluye su focus y puede priorizar instrucciones secundarias sobre la tarea específica del user prompt.

Fix: System prompts cortos y enfocados:

# ❌ MAL: System prompt de 2000 palabras

system_prompt_good = "Eres un clasificador de sentimiento especializado en reseñas de productos. Responde JSON: {\"sentiment\": \"positivo|negativo|neutral|mixto\", \"intensity\": 1-5, \"aspects\": []}"

def analyze_sentiment(user_text: str) -> dict:
    messages = [
        {"role": "system", "content": system_prompt_good},
        {"role": "user", "content": f"Analiza: {user_text}"}
    ]
    return openai.ChatCompletion.create(messages=messages)

Regla práctica: si tu system prompt tiene más de 500 tokens, probablemente está pidiendo demasiado. Divide en múltiples system prompts especializados y selecciónalos por tipo de tarea.

✅ Resumen y Recomendaciones

  • Tareas complejas (reasoning, planificación): Chain-of-Thought + few-shot con ejemplos de razonamiento
  • Tareas de alta varianza (razonamiento multi-path): Self-consistency con n=5-10 samples
  • System prompts: Máximo 300-500 tokens. Foco en rol y formato. Details en el user prompt.
  • Few-shot: Selección inteligente (MMR, clustering) sobre random sampling
  • Direct prompting: Para tareas simples donde CoT es overkill

Eso es todo, parcero. Prompt engineering no es un arte vago — es engineering. La diferencia entre el 90% que hace prompts sin estructura y el 10% que optimiza cada componente es measurable en calidad de outputs y costos de API. Estructura tus prompts como programas, no como mensajes de WhatsApp.
