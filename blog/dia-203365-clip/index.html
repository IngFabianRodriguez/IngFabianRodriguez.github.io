Face Recognition — Siamese Networks, Triplet Loss y ArcFace

Hagale pues, parcero. Dia 203 y hoy llegamos a un tema que usamos todos los días sin detenernos a pensar: el reconocimiento facial. Cada vez que desbloqueas el celular con la cara, o cuando el banco te valida con tu selfie, una red neuronal está trabajando tras bambalinas. Eso sí, no es magia — es arquitectura cuidadosa y una función de pérdida que hace toda la diferencia. Café en mano, que esto se pone interesante.

🎯 Face Verification vs Face Identification

Antes de meternos en código, aclaremos dos conceptos que se confusean bastante:

  • Face Verification: ¿Es esta persona quien dice ser? Ejemplo: desbloqueo facial del celular. Comparas una foto contra una referencia y respondes sí/no.
  • Face Identification: ¿Quién es esta persona en un grupo? Ejemplo: encontrar a alguien en una base de datos de 1 millón de caras.

La verification es un problema 1:1, mientras que la identificación es 1:N. Esta distinción determina qué arquitectura y función de pérdida te conviene más.

📐 Siamese Networks — Aprendiendo a Comparar

Una Siamese Network es elegante en su simplicidad: dos hermanos gemelos ( branches ) que procesan dos imágenes y producen embeddings. Si las imágenes son de la misma persona, los embeddings deben ser cercanos en el espacio; si son de personas distintas, deben estar lejos.

import torch
import torch.nn as nn
import torch.nn.functional as F

class EmbeddingNetwork(nn.Module):
    """Red que produce un embedding de dimension fija para cada cara."""
    def __init__(self, embedding_dim=128):
        super().__init__()
        # Backbone simulado — en la vida real usarías ResNet o EfficientNet
        self.conv1 = nn.Conv2d(3, 64, kernel_size=3, padding=1)
        self.conv2 = nn.Conv2d(64, 128, kernel_size=3, padding=1)
        self.conv3 = nn.Conv2d(128, 256, kernel_size=3, padding=1)
        self.conv4 = nn.Conv2d(256, 512, kernel_size=3, padding=1)
        
        self.pool = nn.AdaptiveAvgPool2d((1, 1))
        self.fc = nn.Linear(512, embedding_dim)
        
    def forward(self, x):
        x = F.relu(self.conv1(x))
        x = F.max_pool2d(x, 2)
        x = F.relu(self.conv2(x))
        x = F.max_pool2d(x, 2)
        x = F.relu(self.conv3(x))
        x = F.max_pool2d(x, 2)
        x = F.relu(self.conv4(x))
        x = self.pool(x)
        x = x.view(x.size(0), -1)
        x = self.fc(x)
        # Normalizar para que similitud coseno funcione bien
        return F.normalize(x, p=2, dim=1)


class SiameseNetwork(nn.Module):
    """Dos redes gemelas que producen embeddings para comparacion."""
    def __init__(self, embedding_dim=128):
        super().__init__()
        self.embedding_net = EmbeddingNetwork(embedding_dim)
        
    def forward(self, x1, x2):
        emb1 = self.embedding_net(x1)
        emb2 = self.embedding_net(x2)
        return emb1, emb2
    
    def get_embedding(self, x):
        return self.embedding_net(x)

🔢 Triplet Loss — La Función de Pérdida que Cambió Todo

Aquí es donde las cosas se ponen elegantes. El triplet loss fue introducido por Google en 2015 (FaceNet) y es el corazón de muchos sistemas de reconocimiento facial modernos.

Dado un tripleto (A, P, N):

  • A (Anchor): imagen de referencia de una persona
  • P (Positive): otra imagen de la misma persona que A
  • N (Negative): imagen de una persona diferente

La idea es simple: la distancia entre A y P debe ser menor que la distancia entre A y N por un margen α.

Triplet Loss:

$$L = \max\left(0,\ \|f(A) - f(P)\|^2 - \|f(A) - f(N)\|^2 + \alpha\right)$$

Donde $f$ es la red que produce embeddings y α es el margen (típicamente 0.2-0.5).

class TripletLoss(nn.Module):
    """Triplet loss con margen."""
    def __init__(self, margin=0.2):
        super().__init__()
        self.margin = margin
        
    def forward(self, anchor, positive, negative):
        # Distancia euclidiana al cuadrado
        dist_pos = F.pairwise_distance(anchor, positive)
        dist_neg = F.pairwise_distance(anchor, negative)
        
        # Triplet loss: cuando dist_pos - dist_neg + margin > 0, hay loss
        losses = F.relu(dist_pos - dist_neg + self.margin)
        return losses.mean()


class OnlineTripletDataset:
    """Genera triplets en tiempo real — mas eficiente que generar todos los triplets."""
    def __init__(self, labels):
        # labels: lista de etiquetas por imagen
        self.labels = labels
        self.labels_set = list(set(labels))
        self.label_to_indices = {label: [i for i, l in enumerate(labels) if l == label] 
                                  for label in self.labels_set}
        
    def __call__(self, batch_size):
        """Genera un batch de triplets."""
        n_labels = len(self.labels_set)
        indices = [randint(0, n_labels - 1) for _ in range(batch_size)]
        
        triplets = []
        for idx in indices:
            label = self.labels_set[idx]
            # Elegir anchor y positive random del mismo label
            pos_indices = self.label_to_indices[label]
            anc_idx, pos_idx = sample(pos_indices, 2)
            
            # Elegir negative de un label diferente
            neg_label = choice([l for l in self.labels_set if l != label])
            neg_idx = choice(self.label_to_indices[neg_label])
            
            triplets.append((anc_idx, pos_idx, neg_idx))
        return triplets

⚡ Hard Negative Mining — Entrenamiento Más Eficiente

Aquí viene un error común que slow down training: no usar hard negative mining. Si eliges los negativos al azar, la mayoría serán triviales (fáciles de distinguir) y la red no aprende nada nuevo.

Hard Negative Mining: Elegir los negativos que están más cerca del anchor (los más parecidos pero de personas diferentes). Esto fuerza a la red a aprender discriminaciones finas.

def get_hard_negatives(anchor_embedding, all_embeddings, labels, anchor_label, top_k=3):
    """Encuentra los k negativos mas cercanos (hard negatives)."""
    # Calcular distancias con todos los embeddings
    distances = F.pairwise_distance(anchor_embedding, all_embeddings)
    
    # Crear mascara para solo negativos (labels diferentes al anchor)
    mask = (labels != anchor_label).float()
    distances = distances + (1 - mask) * 1e9  # Poner distancia infinita a positivos
    
    # Obtener los top_k negativos mas cercanos
    _, top_indices = torch.topk(distances, min(top_k, mask.sum().long().item()), largest=False)
    return top_indices


def train_with_hard_mining(model, images, labels, optimizer, margin=0.2):
    """Un paso de entrenamiento con hard negative mining."""
    embeddings = model.get_embedding(images)  # (batch, embedding_dim)
    
    batch_losses = []
    for i in range(len(embeddings)):
        anchor_emb = embeddings[i:i+1]
        anchor_label = labels[i]
        
        # Encontrar hard negatives
        hard_neg_indices = get_hard_negatives(anchor_emb, embeddings, labels, anchor_label)
        
        for neg_idx in hard_neg_indices:
            # Obtener positive al azar (de la misma persona)
            pos_candidates = torch.where(labels == anchor_label)[0]
            pos_candidates = pos_candidates[pos_candidates != i]
            if len(pos_candidates) == 0:
                continue
            pos_idx = choice(pos_candidates.tolist())
            pos_emb = embeddings[pos_idx:pos_idx+1]
            neg_emb = embeddings[neg_idx:neg_idx+1]
            
            # Calcular triplet loss
            dist_pos = F.pairwise_distance(anchor_emb, pos_emb)
            dist_neg = F.pairwise_distance(anchor_emb, neg_emb)
            loss = F.relu(dist_pos - dist_neg + margin)
            
            if loss > 0:
                batch_losses.append(loss)
    
    if batch_losses:
        optimizer.zero_grad()
        torch.stack(batch_losses).mean().backward()
        optimizer.step()

📊 ArcFace Loss — La Evolución Natural

ArcFace (2018) dio un salto conceptual: en lugar de aprender distancias, aprender ángulos en el espacio de embeddings. Esto es más robusto porque la normalización explícita hace que el modelo se enfoque en la dirección del embedding, no en su magnitud.

ArcFace additive angular margin loss:

$$L = -\log\frac{e^{s\cos(\theta_{y_i}+m)}}{e^{s\cos(\theta_{y_i}+m)} + \sum_{j \neq y_i} e^{s\cos(\theta_j)}}$$

Donde:

  • $\theta_j$ es el ángulo entre el embedding y el centroide de la clase $j$
  • $m$ es el margen angular (típicamente 0.5 radians = ~28.6°)
  • $s$ es la escala (típicamente 64)
class ArcFaceLayer(nn.Module):
    """ArcFace head para clasificacion con margen angular."""
    def __init__(self, in_features, out_features, s=64.0, m=0.5):
        super().__init__()
        self.in_features = in_features
        self.out_features = out_features
        self.s = s  # scale
        self.m = m  # angular margin
        self.weight = nn.Parameter(torch.FloatTensor(out_features, in_features))
        nn.init.xavier_uniform_(self.weight)
        
        # Para calculos intermedios
        self.cos_m = math.cos(m)
        self.sin_m = math.sin(m)
        self.th = math.cos(math.pi - m)  # threshold
        self.mm = math.sin(math.pi - m) * m
        
    def forward(self, embeddings, labels=None):
        # Normalizar embeddings y weights
        embeddings_norm = F.normalize(embeddings, p=2, dim=1)
        weights_norm = F.normalize(self.weight, p=2, dim=1)
        
        # Coseno del angulo entre embedding y cada centroide
        cos_theta = F.linear(embeddings_norm, weights_norm)
        
        if labels is None:
            # Modo inference: devolver logits normalizados
            return cos_theta * self.s
        
        # Modo entrenamiento: aplicar margen angular solo a la clase correcta
        sin_theta = torch.sqrt(1.0 - torch.pow(cos_theta, 2))
        
        # cos(theta + m) = cos(theta)cos(m) - sin(theta)sin(m)
        cos_theta_m = cos_theta * self.cos_m - sin_theta * self.sin_m
        
        # Para valores numericos estables cuando theta + m > pi
        cos_theta_m = torch.where(cos_theta > self.th, cos_theta_m, cos_theta - self.mm)
        
        # One-hot encode labels
        one_hot = torch.zeros_like(cos_theta)
        one_hot.scatter_(1, labels.view(-1, 1), 1.0)
        
        # Aplicar margen solo a la clase verdadera
        logits = one_hot * cos_theta_m + (1.0 - one_hot) * cos_theta
        logits *= self.s
        
        return logits


class ArcFaceModel(nn.Module):
    """Modelo completo con ArcFace loss."""
    def __init__(self, num_identities, embedding_dim=512, s=64.0, m=0.5):
        super().__init__()
        self.backbone = EmbeddingNetwork(embedding_dim)
        self.arcface = ArcFaceLayer(embedding_dim, num_identities, s=s, m=m)
        
    def forward(self, x, labels=None):
        embeddings = self.backbone(x)
        logits = self.arcface(embeddings, labels)
        return logits

🔍 Inference — Verification en la Práctica

Para hacer verification (1:1), el proceso es directo: extraer embeddings de ambas imágenes y comparar. Aquí es crucial entender FAR (False Acceptance Rate) y FRR (False Rejection Rate) para calibrar el threshold.

def verify_faces(model, img1, img2, threshold=0.5):
    """Verifica si dos imagenes son de la misma persona."""
    model.eval()
    with torch.no_grad():
        emb1 = model.get_embedding(img1.unsqueeze(0))
        emb2 = model.get_embedding(img2.unsqueeze(0))
        
        # Similitud coseno (vectores ya normalizados)
        similarity = F.cosine_similarity(emb1, emb2).item()
        
        is_same = similarity >= threshold
        return is_same, similarity


def find_best_threshold(model, validation_pairs, labels, thresholds=None):
    """Encuentra el threshold optimo balanceando FAR y FRR."""
    if thresholds is None:
        thresholds = [i * 0.01 for i in range(100)]
    
    model.eval()
    best_threshold = 0.5
    best_accuracy = 0.0
    
    with torch.no_grad():
        # Extraer todos los embeddings
        all_embeddings = []
        for img, _ in validation_pairs:
            emb = model.get_embedding(img.unsqueeze(0))
            all_embeddings.append(emb)
        all_embeddings = torch.cat(all_embeddings, dim=0)
        
        for threshold in thresholds:
            correct = 0
            total = 0
            
            for i, (img, label) in enumerate(validation_pairs):
                emb = all_embeddings[i]
                
                for j, (other_img, other_label) in enumerate(validation_pairs):
                    if i >= j:
                        continue
                    
                    other_emb = all_embeddings[j]
                    similarity = F.cosine_similarity(emb, other_emb).item()
                    
                    predicted_same = similarity >= threshold
                    actual_same = label == other_label
                    
                    if predicted_same == actual_same:
                        correct += 1
                    total += 1
            
            accuracy = correct / total if total > 0 else 0
            if accuracy > best_accuracy:
                best_accuracy = accuracy
                best_threshold = threshold
    
    print(f"Mejor threshold: {best_threshold:.2f} con accuracy: {best_accuracy:.2%}")
    return best_threshold

⚠️ Errores Comunes

Error 1: Usar Classification Loss en Vez de Triplet/ArcFace

El problema: Si entrenas face recognition con una simple cross-entropy para clasificar N identities, el modelo aprende a separar las clases pero no aprende una métrica de similitud útil. Cuando ves una cara nueva (no vista en entrenamiento), no tienes forma de verificarla porque no hay manera de comparar embeddings.

La solución: Usa triplet loss o ArcFace loss. Ambos aprenden un espacio de embeddings donde la distancia es significativa para verificación. ArcFace es generalmente mejor porque la normalización explícita y el margen angular producen distribuciones más compactas y separables.

Error 2: No Usar Hard Negative Mining

El problema: Si generas triplets al azar (anchor, positive de la misma persona, negative de cualquier otra), la mayoría de los negatives serán "fáciles" — claramente diferentes del anchor. La red no necesita esforzarse para distinguirlos y el entrenamiento converge lentamente porque no aprende nada nuevo de casos triviales.

La solución: Implementa hard negative mining. Elige los negativos que están más cerca del anchor (los más parecidos pero de personas diferentes). Esto fuerza a la red a aprender discriminaciones más finas. Técnicas como Semi-Hard Negative Mining (del paper FaceNet original) o BMVC (Batch Hard) son estándares en la industria.

Error 3: Inference Sin Proper Threshold Tuning para FAR/FRR Tradeoff

El problema: Poner un threshold arbitrario (como 0.5) sin entender FAR (False Acceptance Rate — aceptas impostores) y FRR (False Rejection Rate — rechazas personas legítimas). En seguridad alta (banco), quieres FRR bajo; en conveniencia (desbloqueo de celular), aceptas más FAR a cambio de menos FRR.

La solución: Calibra el threshold en tu validation set. Usa una curva ROC o calcula EER (Equal Error Rate, donde FAR = FRR). Para sistemas de producción, grafica FAR vs FRR para diferentes thresholds y elige según tu caso de uso — no hay un threshold universal.

📝 Resumen

  • Verification vs Identification: 1:1 vs 1:N — arquitecturas diferentes
  • Siamese Network: Dos ramas gemelas que producen embeddings comparables
  • Triplet Loss: $L = \max(0, \|A-P\|^2 - \|A-N\|^2 + \alpha)$ — aprende distancias
  • ArcFace: Usa margen angular sobre cos(theta) — más robusto y estándar en producción
  • Hard Negative Mining: Elige negativos difíciles para acelerar entrenamiento
  • Threshold tuning: Calibra según FAR/FRR tradeoff de tu aplicación
