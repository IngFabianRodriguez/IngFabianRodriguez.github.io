Parcero, día 172 y hoy我们来聊聊 RLHF y DPO — los mecanismos de entrenamiento que hacen que los LLMs sean útiles y no meramente predictivos. Si el modelo que estás usando hoy responde bien, es porque alguien (muchos alguien) le enseñó qué es "bueno" y qué es "malo" a nivel humano. Eso no sale gratis del pre-training. De una.

RLHF (Reinforcement Learning from Human Feedback) y DPO (Direct Preference Optimization) son las dos aproximaciones principales para alinear modelos con preferencias humanas. La diferencia conceptual es grande: RLHF usa un loop de RL con reward model; DPO reformula el problema como classification directa. Cada una tiene trade-offs en complejidad, data eficiencia, y estabilidad de entrenamiento.

🎯 Por Qué Necesitamos Alinear Modelos

dur ante todo, un LLM pre-entrenado solo aprende a predecir el siguiente token dado contexto. No sabe qué es "útil", qué es "dañino", qué es "honesto" vs "halagador". Solo tiene estadísticas de texto.

El problema: las说话了 en internet incluyen contenido dañino, sesgado, y técnicamente incorrecto pero persuasivo. Un modelo pre-entrenado sin más podríagenear cualquiera de eso si el prompt lo induce.

RLHF y DPO son las técnicas para enseñarle al modelo a preferir respuestas que humanos considerarían mejores — útiles, precisas, no dañinas. Es el secreto detrás de ChatGPT, Claude, Gemini.

📐 La Matemática de RLHF

RLHF tiene tres fases:

Fase 1: Reward Model Training

Dado un prompt $x$ y dos respuestas $y_1, y_2$ etiquetadas por humanos (cuál es mejor), entrenamos un reward model $r_\theta(y|x)$:

$$L_R = -\mathbb{E}_{(x, y_1, y_2) \sim D}[\log \sigma(r_\theta(y_1|x) - r_\theta(y_2|x) - \beta)]$$

donde $\beta$ es un hyperparameter de regularization. El modelo aprende a predecir qué respuesta humanos prefieren.

Fase 2: RL Fine-Tuning

Usamos el reward model para optimizar el LLM policy $\pi_\theta$ con PPO (Proximal Policy Optimization):

$$L_{PPO} = -\mathbb{E}_{x \sim D, y \sim \pi_\theta}[r_\theta(y|x)] + \beta \cdot KL[\pi_\theta(y|x) || \pi_{ref}(y|x)]$$

El término KL penaliza desviarse demasiado del modelo original (por eso se mantiene una reference model). Sin esto, el modelooptimizaría el reward sin límite, generando texto reward-high pero nonsense.

📐 DPO: Direct Preference Optimization

DPO reformula el problema. En lugar de entrenar reward + usar RL, usamos una classification loss directa:

$$L_{DPO} = -\mathbb{E}_{(x, y_w, y_l) \sim D}[\log \sigma(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)})]$$

donde $y_w$ es la respuesta preferida (winner) e $y_l$ es la less preferred (loser). Simplifica el pipeline a solo una fase de training (sin separate reward model ni PPO).

💻 Código Production-Grade de RLHF Pipeline

"""
Pipeline de RLHF para alinear un LLM con preferencias humanas.
Implementación con reward model training + PPO optimization.
"""
import torch
import torch.nn as nn
from torch.utils.data import Dataset, DataLoader
from dataclasses import dataclass
from typing import List, Dict, Tuple, Optional
from transformers import AutoModelForCausalLM, AutoTokenizer
from transformers import Trainer, TrainingArguments
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)


@dataclass
class PreferencePair:
    """Un par de respuestas con label de preferencia humana."""
    prompt: str
    chosen_response: str
    rejected_response: str


class RewardModel(nn.Module):
    """
    Reward model que puntúa respuestas dada un prompt.
    Arquitectura: LLM base + linear head sobre last token.
    """
    
    def __init__(self, base_model_name: str, reward_scale: float = 1.0):
        super().__init__()
        self.base_model = AutoModelForCausalLM.from_pretrained(base_model_name)
        self.reward_scale = reward_scale
        # Reward head: toma el hidden state del último token
        hidden_size = self.base_model.config.hidden_size
        self.reward_head = nn.Linear(hidden_size, 1, bias=False)
    
    def forward(
        self, 
        input_ids: torch.Tensor, 
        attention_mask: torch.Tensor
    ) -> torch.Tensor:
        """
        Retorna reward scalar por cada sample en el batch.
        """
        outputs = self.base_model(
            input_ids=input_ids,
            attention_mask=attention_mask,
            output_hidden_states=True
        )
        # Hidden state del último token
        last_hidden = outputs.hidden_states[-1]
        # Solo el último token (para causalmask)
        last_token_hidden = last_hidden[:, -1, :]
        reward = self.reward_head(last_token_hidden).squeeze(-1)
        return reward * self.reward_scale
    
    def gradient_checkpointing_enable(self):
        """Ahorra memoria durante entrenamiento."""
        self.base_model.gradient_checkpointing_enable()


class PreferenceDataset(Dataset):
    """Dataset de pares de preferencia para reward model."""
    
    def __init__(self, pairs: List[PreferencePair], tokenizer, max_length: int = 512):
        self.pairs = pairs
        self.tokenizer = tokenizer
        self.max_length = max_length
    
    def __len__(self) -> int:
        return len(self.pairs)
    
    def __getitem__(self, idx: int) -> Dict[str, torch.Tensor]:
        pair = self.pairs[idx]
        
        # Tokenize chosen y rejected
        chosen = self.tokenizer(
            pair.prompt + " " + pair.chosen_response,
            max_length=self.max_length,
            truncation=True,
            padding="max_length",
            return_tensors="pt"
        )
        
        rejected = self.tokenizer(
            pair.prompt + " " + pair.rejected_response,
            max_length=self.max_length,
            truncation=True,
            padding="max_length",
            return_tensors="pt"
        )
        
        return {
            "chosen_input_ids": chosen["input_ids"].squeeze(0),
            "chosen_attention_mask": chosen["attention_mask"].squeeze(0),
            "rejected_input_ids": rejected["input_ids"].squeeze(0),
            "rejected_attention_mask": rejected["attention_mask"].squeeze(0),
            "prompt": pair.prompt,
        }


def reward_model_loss(
    reward_model: RewardModel,
    batch: Dict[str, torch.Tensor]
) -> torch.Tensor:
    """
    Computa la loss de Bradley-Terry para reward model.
    
    L = -log(sigmoid(reward_chosen - reward_rejected))
    """
    chosen_rewards = reward_model(
        batch["chosen_input_ids"],
        batch["chosen_attention_mask"]
    )
    rejected_rewards = reward_model(
        batch["rejected_input_ids"],
        batch["rejected_attention_mask"]
    )
    
    # Log sigmoid de la diferencia
    diff = chosen_rewards - rejected_rewards
    loss = -torch.nn.functional.logsigmoid(diff).mean()
    
    return loss


def train_reward_model(
    reward_model: RewardModel,
    train_dataset: PreferenceDataset,
    eval_dataset: PreferenceDataset,
    output_dir: str,
    num_epochs: int = 3,
    per_device_batch_size: int = 8,
    learning_rate: float = 1e-5,
) -> RewardModel:
    """Entrena el reward model con preference pairs."""
    
    training_args = TrainingArguments(
        output_dir=output_dir,
        num_train_epochs=num_epochs,
        per_device_train_batch_size=per_device_batch_size,
        per_device_eval_batch_size=per_device_batch_size,
        learning_rate=learning_rate,
        eval_strategy="steps",
        save_strategy="steps",
        logging_steps=10,
        bf16=True,
        remove_unused_columns=False,
    )
    
    # Custom trainer para reward model
    class RewardModelTrainer(Trainer):
        def compute_loss(self, model, batch, return_outputs=False):
            loss = reward_model_loss(model, batch)
            return (loss, batch) if return_outputs else loss
    
    trainer = RewardModelTrainer(
        model=reward_model,
        args=training_args,
        train_dataset=train_dataset,
        eval_dataset=eval_dataset,
    )
    
    trainer.train()
    reward_model.save_pretrained(f"{output_dir}/final_reward_model")
    return reward_model


def compute_ppo_loss(
    policy_model,
    ref_model,
    reward_model,
    query_tokens,
    response_tokens,
    beta: float = 0.1,
) -> Tuple[torch.Tensor, Dict]:
    """
    Computa PPO loss para policy optimization.
    
    Args:
        policy_model: Modelo a optimizar (LLM)
        ref_model: Reference model (frozen)
        reward_model: Reward model para calcular reward
        query_tokens: Tokens del prompt
        response_tokens: Tokens de la respuesta generada
        beta: KL penalty coefficient
        
    Returns:
        Loss y métricas
    """
    # Concatenar query + response para reward model
    full_tokens = torch.cat([query_tokens, response_tokens], dim=-1)
    attention_mask = torch.ones_like(full_tokens)
    
    # Reward de la response completa
    reward = reward_model(full_tokens, attention_mask)
    
    # KL divergence con reference model
    with torch.no_grad():
        ref_logits = ref_model(query_tokens, attention_mask[:, :query_tokens.size(1)])
        ref_logprobs = torch.log_softmax(ref_logits, dim=-1)
    
    policy_logits = policy_model(query_tokens, attention_mask[:, :query_tokens.size(1)])
    policy_logprobs = torch.log_softmax(policy_logits, dim=-1)
    
    # KL entre policy y reference
    kl = torch.nn.functional.kl_div(
        policy_logprobs[:, :-1],
        ref_logprobs[:, :-1],
        reduction="batchmean"
    )
    
    # PPO objective: maximize reward - beta * KL
    loss = -(reward - beta * kl).mean()
    
    metrics = {
        "reward": reward.mean().item(),
        "kl": kl.item(),
    }
    
    return loss, metrics


# Usage example
if __name__ == "__main__":
    # Initialize models
    model_name = "meta-llama/Llama-2-7b"
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    
    logger.info("Inicializando reward model...")
    reward_model = RewardModel(model_name)
    
    # Sample preference data
    preference_pairs = [
        PreferencePair(
            prompt="Explain quantum computing",
            chosen_response="Quantum computing uses qubits that can be 0 and 1 simultaneously through superposition...",
            rejected_response="Quantum is like regular computing but faster and more advanced."
        ),
        # ... más pares en producción
    ]
    
    dataset = PreferenceDataset(preference_pairs, tokenizer)
    logger.info("Entrenando reward model...")
    reward_model = train_reward_model(
        reward_model, dataset, dataset, "./reward_model_output"
    )

⚠️ Errores Comunes en RLHF/DPO

Error 1: Reward hacking — sobreoptimizar el reward

El problema: El modelo encuentra formas de maximizar el reward model que no corresponden a realmente mejores respuestas. Por ejemplo: respuestas más largas pero vacías, o evitar ciertos temas aunque sean relevantes. Esto se llama reward hacking y es análogo a Goodhart's Law: "When a measure becomes a target, it ceases to be a good measure."

Fix: Incluir el término KL que penaliza desvío de la reference model. En DPO, el término $\beta$ cumple esta función. También ayuda tener reward model ensemble y diversify training data.

Error 2: Labeler agreement bajo

El problema: Si los humanos que labelean las respuestas no están de acuerdo entre sí (inter-annotator agreement bajo), el reward model aprende señales ruido. Típicamente pasa cuando las instrucciones de labeling son ambiguas o los labelers no tienen expertise en el dominio.

Fix: Antes de entrenar, medir agreement entre annotators. Si es bajo (<70%), clarificar guidelines o re-entrenar annotators. En producción, usar multiple annotators por par y voting o averaging.

Error 3: DPO es inestable con modelos pequeños

El problema: DPO asume que el policy actual $\pi_\theta$ y la reference $\pi_{ref}$ son similares (KL pequeño). En modelos pequeños o con distribución de preferencias muy skewed, DPO puede destabilizarse. El 60% de implementaciones de DPO en modelos <7B reportan training instability.

Fix: Usar $\beta$ mayor (0.3-0.5) para más regularization KL. O usar RLHF con PPO que es más estable aunque más complejo. Para modelos <7B, preferir RLHF sobre DPO.

✅ Resumen y Cierre

  • RLHF: 3 fases — SFT, Reward Model, PPO. Más complejo pero estable.
  • DPO: Reformulación como classification directa. Más simple, 1 fase menos, pero inestable en algunos casos.
  • Reward hacking es el principal riesgo — el término KL previene pero no elimina.
  • Data quality importa más que arquitectura. Annotation agreement bajo = reward model malo.

Hágale que RLHF y DPO son lo que hace la diferencia entre un modelo que merely predicts tokens y uno que es genuinamente útil. Sin esto, ni ChatGPT ni Claude serían lo que son. Parcero, eso es lo que el alignment hace.
