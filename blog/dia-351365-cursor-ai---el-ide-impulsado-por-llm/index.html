🎯 Integration Patterns: Conectando LLMs con el Mundo Real

Un LLM fuera de contexto es como un参考书 en otro idioma — potencialmente útil pero completamente disconnected de lo que necesitas. Los integration patterns son los bridges que hacen que tu modelo realmente resuelva problemas.

Retrieval-Augmented Generation (RAG)

RAG combina la potencia generativa del LLM con información externa retrieval-time. La idea: recuperar documentos relevantes y pasarlos como contexto.

"""
RAG Pipeline completo — del retrieval al generation
"""

class SimpleRAGPipeline:
    def __init__(self, llm, vector_store, retriever_config: dict):
        self.llm = llm
        self.vector_store = vector_store
        self.top_k = retriever_config.get("top_k", 5)
        self.reranker = retriever_config.get("reranker", None)
        self.rewrite_query = retriever_config.get("rewrite_query", False)

    def retrieve(self, query: str) -> list[Document]:
        """Recupera documentos relevantes del vector store"""
        query_embedding = self.llm.embed(query)

        # Búsqueda en espacio vectorial
        results = self.vector_store.similarity_search(
            query_embedding,
            k=self.top_k * 2  # Extra para reranking
        )

        # Reranking si está configurado
        if self.reranker:
            results = self.reranker.rerank(query, results, top_k=self.top_k)
        else:
            results = results[:self.top_k]

        return results

    def rewrite_query_if_needed(self, query: str) -> str:
        """Rewriting de query para mejor retrieval"""
        if not self.rewrite_query:
            return query

        prompt = f"""Given the following user query, rewrite it to be
more effective for semantic search. Focus on key concepts and intent.

Original query: {query}

Rewritten query:"""

        return self.llm.generate(prompt).strip()

    def generate_with_context(
        self,
        query: str,
        system_prompt: str = "You are a helpful AI assistant."
    ) -> str:
        """Genera respuesta usando contexto recuperado"""
        # Rewriting de query
        search_query = self.rewrite_query_if_needed(query)

        # Retrieval
        retrieved_docs = self.retrieve(search_query)

        # Construir contexto
        context = "\n\n".join([
            f"[Source {i+1}] {doc.content}"
            for i, doc in enumerate(retrieved_docs)
        ])

        # Prompt con contexto
        full_prompt = f"""{system_prompt}

Context from retrieved documents:
{context}

User question: {query}

Based on the context, answer the question. If the context
doesn't contain relevant information, say so.
"""
        return self.llm.generate(full_prompt)


# --- Advanced: Hybrid Search ---
def hybrid_search(
    vector_results: list,
    keyword_results: list,
    alpha: float = 0.5,
    max_results: int = 10
) -> list[tuple[Document, float]]:
    """
    Combina búsqueda vectorial + keyword-based (BM25).

    Score final: α × vector_score + (1-α) × bm25_score

    α=0.5: peso igual a ambos métodos
    α→1: privilegia búsqueda semántica
    α→0: privilegia búsqueda por keywords
    """
    from collections import defaultdict

    doc_scores = defaultdict(float)
    doc_order = {}

    # Normalizar y combinar scores vectoriales
    if vector_results:
        max_vec_score = max(score for _, score in vector_results)
        for doc, score in vector_results:
            doc_scores[doc.id] += alpha * (score / max_vec_score)
            doc_order[doc.id] = doc

    # Normalizar y combinar scores BM25
    if keyword_results:
        max_bm25_score = max(score for _, score in keyword_results)
        for doc, score in keyword_results:
            doc_scores[doc.id] += (1 - alpha) * (score / max_bm25_score)
            doc_order[doc.id] = doc

    # Ordenar por score combinado
    ranked = sorted(
        [(doc_order[doc_id], score) for doc_id, score in doc_scores.items()],
        key=lambda x: x[1],
        reverse=True
    )

    return ranked[:max_results]

Chain-of-Thought Prompting

CoT induces reasoning by asking el modelo para explicitar su reasoning process antes de dar la respuesta final.

"""
Chain-of-Thought implementation con verification
"""

def chain_of_thought(
    llm,
    problem: str,
    include_verification: bool = True
) -> dict:
    """
    CoT prompting con paso de verificación.

    Returns: {
        "reasoning_steps": [...],
        "answer": str,
        "verification": bool,
        "confidence": float
    }
    """

    cot_prompt = f"""Solve this problem step by step. For each step:
1. Write what you're thinking
2. Write what you're doing
3. Write the intermediate result

Problem: {problem}

Steps:"""

    # Generar reasoning steps
    raw_response = llm.generate(cot_prompt)

    # Parsear pasos
    steps = parse_reasoning_steps(raw_response)

    # Extraer respuesta final
    final_answer = extract_final_answer(steps)

    # Verificación si está habilitada
    verification = None
    confidence = 0.5

    if include_verification:
        verification_prompt = f"""Given the following problem and solution,
verify if the answer is correct. Also estimate confidence 0-1.

Problem: {problem}
Proposed answer: {final_answer}
Reasoning steps: {steps}

Is the answer correct? What is your confidence level?
Provide a brief explanation.
"""
        verification_response = llm.generate(verification_prompt)
        verification = parse_verification(verification_response)
        confidence = verification.get("confidence", 0.5)

    return {
        "reasoning_steps": steps,
        "answer": final_answer,
        "verification": verification,
        "confidence": confidence
    }


def tree_of_thought(llm, problem: str, num_branches: int = 3) -> str:
    """
    Tree-of-Thought: explora múltiples paths de reasoning
    en paralelo and selecciona el mejor.
    """
    prompts = [
        f"""Solve this problem using one specific approach.
Think carefully about this approach and show your work.

Problem: {problem}

Approach {i+1}:"""
        for i in range(num_branches)
    ]

    # Generar en paralelo
    branch_responses = llm.generate_parallel(prompts)

    # Evaluar y seleccionar mejor
    evaluation_prompt = f"""Given the problem and these solution approaches,
select the best one and explain why.

Problem: {problem}

Approaches:
{chr(10).join([f'Approach {i+1}: {r}' for i, r in enumerate(branch_responses)])}

Best approach and why:"""

    final = llm.generate(evaluation_prompt)
    return final

🚀 Deployment Strategies: De Notebook a Producción

El problema del 90% de los deployments de LLM: treat it like a regular API. Un LLM es probabilístico, latente, y resource-intensive. Necesita una estrategia diferente.

Deployment Architecture Patterns

"""
LLM Deployment Patterns — scalability y reliability
"""

# --- Pattern 1: Gateway con Fallback ---
class LLMGateway:
    """
    Gateway que redirige a múltiples providers con fallback.
    """

    def __init__(self):
        self.providers = [
            {"name": "openai", "client": OpenAIClient(), "priority": 1},
            {"name": "anthropic", "client": AnthropicClient(), "priority": 2},
            {"name": "local", "client": LocalLLMClient(), "priority": 3},
        ]
        self.current_provider = 0

    def generate(self, prompt: str, **kwargs) -> str:
        """Intenta providers en orden hasta que uno succeeds"""
        errors = []

        for provider in self.providers:
            try:
                return provider["client"].generate(prompt, **kwargs)
            except Exception as e:
                errors.append(f"{provider['name']}: {str(e)}")
                continue

        # Todos fallaron
        raise LLMAllProvidersFailedError(errors)


# --- Pattern 2: Async con Streaming ---
import asyncio
from typing import AsyncGenerator

class StreamingLLM:
    """LLM con streaming asíncrono para baja latencia percibida"""

    def __init__(self, client):
        self.client = client

    async def stream_generate(
        self,
        prompt: str,
        model: str = "gpt-4"
    ) -> AsyncGenerator[str, None]:
        """Genera tokens asíncronamente mientras llegan"""
        loop = asyncio.get_event_loop()

        # Wrapper para convertir sync streaming a async
        def sync_stream():
            for token in self.client.stream_generate(prompt, model=model):
                yield token

        # Run blocking generator en thread pool
        for token in await loop.run_in_executor(None, sync_stream):
            yield token


# --- Pattern 3: Caching Strategy ---
class SemanticCache:
    """
    Cache semántico: guarda prompts similares y sus respuestas.
    Reduce costo y latencia drásticamente.
    """

    def __init__(self, embedding_model, vector_db, similarity_threshold: float = 0.95):
        self.embedding_model = embedding_model
        self.vector_db = vector_db
        self.similarity_threshold = similarity_threshold

    def get_cached_response(self, prompt: str) -> tuple[str, float] | None:
        """Busca en cache. Returns (response, similarity) o None"""
        embedding = self.embedding_model.encode(prompt)

        results = self.vector_db.similarity_search(embedding, k=1)

        if not results:
            return None

        cached_prompt, cached_response, similarity = results[0]

        if similarity >= self.similarity_threshold:
            return cached_response, similarity

        return None

    def store(self, prompt: str, response: str):
        """Guarda en cache"""
        embedding = self.embedding_model.encode(prompt)
        self.vector_db.insert(embedding, prompt, response)


# --- Pattern 4: Load Balancing ---
class LLMLoadBalancer:
    """
    Distribuye requests entre múltiples deployments.
    Considera: latencia actual, rate limits, costo.
    """

    def __init__(self):
        self.instances = []
        self.metrics = {}  # instance_id -> {"latency": [], "requests": int}

    def add_instance(self, instance: dict):
        self.instances.append(instance)
        self.metrics[instance["id"]] = {"latency": [], "requests": 0}

    def select_instance(self) -> dict:
        """
        Selecciona mejor instancia basado en:
        - Latencia promedio reciente
        - Rate limit remaining
        - Priority/weight
        """
        scored = []

        for instance in self.instances:
            metrics = self.metrics[instance["id"]]
            avg_latency = sum(metrics["latency"]) / max(len(metrics["latency"]), 1)

            # Score más bajo = mejor
            # Normaliza: menor latencia y más rate limit = mejor
            score = avg_latency / instance.get("rate_limit_remaining", 1)

            scored.append((instance, score))

        # Selecciona el de menor score
        best = min(scored, key=lambda x: x[1])
        return best[0]

    async def generate(self, prompt: str) -> str:
        instance = self.select_instance()
        start = time.time()

        try:
            response = await instance["client"].generate(prompt)
            latency = time.time() - start

            # Update metrics
            self.metrics[instance["id"]]["latency"].append(latency)
            self.metrics[instance["id"]]["requests"] += 1

            # Mantener solo últimos 100 latency measurements
            if len(self.metrics[instance["id"]]["latency"]) > 100:
                self.metrics[instance["id"]]["latency"] = \
                    self.metrics[instance["id"]]["latency"][-100:]

            return response
        except Exception as e:
            # Marcar instance como unavailable temporalmente
            instance["consecutive_failures"] = instance.get("consecutive_failures", 0) + 1
            raise

Key Deployment Formulas

Metrics que importan en producción:

Time to First Token (TTFT):

$$TTFT = t_{encode} + t_{queue} + t_{first\_token}$$

donde $t_{encode}$ es tiempo de encoding del prompt, $t_{queue}$ espera en cola, y $t_{first\_token}$ primera inferencia.

Throughput efectivo:

$$Throughput = \frac{total\_tokens}{t_{total} - t_{TTFT}}$$

**Costo por 1K tokens:**

$$Costo_{1K} = \frac{precio_{modelo} \times 1000}{tokens\_por\_dollar}$$

⚠️ Errores Críticos en Deployment

Error 1: No Tener Deployment Strategy

El problema: Hacer deploy del modelo más grande sin considerar latency, costo, o fallback. En producción, esto significa downtime cuando el provider tiene problemas o cuando el costo se dispara.

La solución: Implementar gateway con fallback desde día uno. Empezar con el modelo más pequeño que cumpla los requisitos de calidad. Planificar для capacity desde el inicio.

# Ejemplo: Strategy desde el inicio
DEPLOYMENT_STRATEGY = {
    "tier_1": {  # Producción
        "model": "gpt-4o-mini",
        "max_latency_ms": 2000,
        "fallback_to": "gpt-3.5-turbo"
    },
    "tier_2": {  # Fallback
        "model": "gpt-3.5-turbo",
        "max_latency_ms": 3000,
        "fallback_to": "local-llama"
    },
    "tier_3": {  # Emergencia
        "model": "llama-3.1-8b",
        "max_latency_ms": 5000,
        "fallback_to": None  # Última instancia
    }
}

Error 2: No Integrar Properly

El problema: Llamar el LLM sin contexto, sin cache, sin manejo de errores. Esto resulta en respuestas irrelevantes, costos inflados, y crashes en producción.

La solución: Implementar RAG pipeline, semantic cache, y retry logic. El contexto es king — un LLM sin contexto es inútil.

# Integration checklist
INTEGRATION_CHECKLIST = [
    "☐ RAG pipeline con hybrid search",
    "☐ Semantic cache para prompts repetitivos",
    "☐ Retry con exponential backoff",
    "☐ Circuit breaker para failures sostenidos",
    "☐ Monitoring de latencia, costo, y calidad",
    "☐ A/B testing de prompts",
    "☐ Fallback chain configurado"
]

Error 3: No Follow Best Practices

El problema: Tratar LLMs como deterministic APIs. No hacer prompt versioning, no monitorear drift, no tener escalation paths. Esto acumula technical debt que después es cara de pagar.

La solución: Treat your prompts como código. Versionarlos, testearlos, hacer code review. Monitorear outputs por drift. Tener humanos en el loop para decisiones críticas.

📊 Resumen de Fórmulas Clave

  • RAG hybrid score: $S_{final} = \alpha \cdot S_{vector} + (1-\alpha) \cdot S_{bm25}$
  • TTFT: $t_{encode} + t_{queue} + t_{first\_token}$
  • Throughput: $\frac{tokens}{t_{total} - t_{TTFT}}$
  • Cache hit ratio: $\frac{cache\_hits}{total\_requests}$
  • Effective cost: $c_{base} \times (1 - hit\_ratio) + c_{cache} \times hit\_ratio$
