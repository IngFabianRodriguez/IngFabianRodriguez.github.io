Towards Binary Features - Caracteristicas Binarias

26 de noviembre de 2026

🎯 Por Qué binary Features

En el artículo anterior hablamos de superposition y cómo los modelos representan múltiples features usando las mismas neuronas. Hoy exploramos una idea related: binary features. La intuición es que en lugar de representar features como valores continuous, el modelo podría estar usando representaciones discretas o binarias.

La pregunta central es: ¿son los features en redes neuronales fundamentalmente continuos o discretos? La evidencia reciente sugiere que muchos features tienen un carácter casi-discreto: están "activos" o "inactivos" en diferentes contextos, con poca variación intermedia.

Hay varias razones por las que esto es interesante:

  • Eficiencia computacional - operaciones binarias son más baratas
  • Robustez - pequeñas perturbaciones no cambian el feature
  • Interpretabilidad - binario es más fácil de razonar
  • Compresión - almacenar binario vs float32 es 32x más pequeño

🧠 Feature Binarization Natural

Resulta que muchos features en LLMs se comportan de manera casi-binaria. Cuando analizas las activaciones para diferentes inputs, encuentras que muchos features tienen una distribución bimodal: o están "off" o están "on", con pocos valores intermedios.

Esto es diferente a la representación vectorial continua típica. En una representación binaria:

  • El feature F está activo si la activación > threshold
  • El feature F está inactivo si la activación < threshold
  • La transición entre estados es sharp, no gradual

Los investigadores han encontrado que este comportamiento emerge naturalmente en redes entrenadas con regularización. Modelos más pequeños o con más regularización tienden a tener features más discretos.

import torch
import torch.nn as nn
import numpy as np
from typing import Dict, List, Tuple

class BinaryFeatureDetector:
    """
    Detecta si features tienen comportamiento binario.
    """
    
    def __init__(self, model: nn.Module, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
    
    def compute_activation_distribution(self, texts: List[str], 
                                       layer_name: str) -> Dict[int, Dict]:
        """
        Computa la distribución de activaciones para cada feature en una capa.
        
        Returns:
            Dict mapping feature_idx -> {mean, std, bimodality_score, n_modes}
        """
        self.model.eval()
        
        # Coleccionar activaciones
        all_activations = []
        for text in texts:
            act = self._get_layer_activations(text, layer_name)
            # Tomar el último token
            act = act[0, -1, :].numpy()
            all_activations.append(act)
        
        activations = np.array(all_activations)  # (n_texts, d_model)
        
        results = {}
        for feat_idx in range(activations.shape[1]):
            feat_acts = activations[:, feat_idx]
            
            # Calcular statistics
            mean = np.mean(feat_acts)
            std = np.std(feat_acts)
            
            # Calcular bimodality usando el coeficiente de Fisher
            # Alto valor = más bimodal (dos picos separados)
            n = len(feat_acts)
            if std > 0:
                # Kurtosis: qué tan "puntiaguda" es la distribución
                kurtosis = np.mean((feat_acts - mean)**4) / (std**4) - 3
                
                # Bimodality score: diferencia entre max y min normalizada
                range_ratio = (np.max(feat_acts) - np.min(feat_acts)) / (std + 1e-6)
                
                # Número de "modas" aproximadas usando histograma
                hist, _ = np.histogram(feat_acts, bins=10)
                n_peaks = sum(1 for i in range(len(hist)-1) 
                             if hist[i] > hist[i-1] and hist[i] > hist[i+1])
            else:
                kurtosis = 0
                range_ratio = 0
                n_peaks = 1
            
            results[feat_idx] = {
                "mean": mean,
                "std": std,
                "kurtosis": kurtosis,
                "range_ratio": range_ratio,
                "n_peaks": n_peaks,
                "is_bimodal": kurtosis > 1.0 and n_peaks >= 2
            }
        
        return results
    
    def find_binary_features(self, texts: List[str], 
                            layer_name: str,
                            threshold_std: float = 2.0,
                            threshold_range: float = 5.0) -> List[int]:
        """
        Encuentra features que son aproximadamente binarios.
        
        Args:
            texts: Textos para análisis
            layer_name: Capa a analizar
            threshold_std: Mínima desviación estándar para considerar
            threshold_range: Mínimo ratio rango/std para considerar
        
        Returns:
            Lista de índices de features binarios
        """
        dists = self.compute_activation_distribution(texts, layer_name)
        
        binary_features = []
        for feat_idx, stats in dists.items():
            if (stats["std"] > threshold_std and 
                stats["range_ratio"] > threshold_range and
                stats["is_bimodal"]):
                binary_features.append(feat_idx)
        
        return binary_features
    
    def compute_bimodality_coefficient(self, data: np.ndarray) -> float:
        """
        Calcula el coeficiente de bimodalidad de Fisher.
        
        Valores > 0.555 indican distribución bimodal.
        """
        n = len(data)
        if n < 3:
            return 0.0
        
        mean = np.mean(data)
        std = np.std(data)
        if std == 0:
            return 0.0
        
        # Skewness (asimetría)
        skewness = np.mean((data - mean)**3) / (std**3)
        
        # Kurtosis (curtosis)
        kurtosis = np.mean((data - mean)**4) / (std**4) - 3
        
        # Coeficiente de bimodalidad
        numerator = (skewness**2 + 1) * (kurtosis**2)
        denominator = (3 * (n - 1)**2) / ((n - 2) * (n - 3))
        
        bc = np.sqrt(numerator) / (denominator + 1e-6)
        
        return bc

class BinaryFeatureModel(nn.Module):
    """
    Modelo que usa features binarios explícitamente.
    """
    
    def __init__(self, d_model: int, n_features: int, threshold: float = 0.5):
        super().__init__()
        self.d_model = d_model
        self.n_features = n_features
        self.threshold = threshold
        
        # Proyección de embedding a features
        self.feature_projection = nn.Linear(d_model, n_features)
        
        # Para reconstruir de features binarios a logits
        self.reconstruction = nn.Linear(n_features, d_model)
    
    def forward(self, x: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]:
        """
        Forward pass con binarización.
        
        Returns:
            (binary_features, reconstructed_output)
        """
        # Proyectar a espacio de features
        features = self.feature_projection(x)
        
        # Binarizar usando hard sigmoid + threshold
        binary_features = (torch.sigmoid(features) > self.threshold).float()
        
        # Reconstruir (opcional, para autoencoder)
        reconstructed = self.reconstruction(binary_features)
        
        return binary_features, reconstructed
    
    def straight_through_estimator(self, x: torch.Tensor) -> torch.Tensor:
        """
        Straight-through estimator para backprop a través de binarización.
        
        Usa la señal del gradiente continuo pero aplica el threshold en forward.
        """
        # Forward: binarizado
        features = torch.sigmoid(self.feature_projection(x))
        binary = (features > self.threshold).float()
        
        # Backward: usa la señal suave
        return binary + (features - binary).detach()

📐.binary vs Soft Features

No todos los features son binarios. Hay un espectro desde puramente continuos hasta puramente binarios. Entender dónde cae cada feature nos ayuda a saber cómo intervenirlos.

Tipos de Features

  • Puramente binarios: activación sharp, dos estados claros
  • Casi-binarios: distribución bimodal pero con ruido
  • Graduales: respuesta proporcional al estímulo
  • Continuous no lineal: respuesta compleja, no simple

La pregunta es: ¿cuál es la distribución real de tipos en un LLM típico? Investigaciones recientes sugieren que la mayoría de los features de alto nivel son al menos parcialmente discretos, mientras que features de bajo nivel tienden a ser más continuos.

import numpy as np
from scipy import stats
from typing import List, Dict, Tuple

class FeatureTypeClassifier:
    """
    Clasifica features en tipos según su distribución de activación.
    """
    
    FEATURE_TYPES = {
        "purely_binary": "Activación sharp con exactamente 2 valores",
        "quasi_binary": "Distribución bimodal con algo de ruido",
        "graded": "Respuesta proporcional gradual",
        "multimodal": "Más de 2 modos claros",
        "continuous": "Distribución unimodal suave",
        "sparse": "Mayormente inactivo con activaciones ocasionales"
    }
    
    def classify_feature(self, activations: np.ndarray) -> str:
        """
        Clasifica un feature según su patrón de activación.
        
        Args:
            activations: Array de activaciones (n_samples,)
        
        Returns:
            Tipo del feature
        """
        # Limpiar NaNs
        activations = activations[~np.isnan(activations)]
        if len(activations) < 10:
            return "unknown"
        
        # Calcular estadísticas
        mean = np.mean(activations)
        std = np.std(activations)
        skew = stats.skew(activations)
        kurtosis = stats.kurtosis(activations)
        
        # Detectar si es bimodal usando Hartigan's dip test simplificado
        is_bimodal = self._is_bimodal(activations)
        
        # Fraction of zeros (sparsity)
        sparsity = np.mean(np.abs(activations) < 0.01)
        
        # Rango normalizado
        range_norm = (np.max(activations) - np.min(activations)) / (std + 1e-6)
        
        # Clasificación based en características
        if sparsity > 0.9 and std < 0.1:
            return "sparse"
        
        if is_bimodal and range_norm > 5:
            # ¿2 modos bien separados o más?
            n_modes = self._count_modes(activations)
            if n_modes == 2:
                if std < 0.5:
                    return "purely_binary"
                else:
                    return "quasi_binary"
            else:
                return "multimodal"
        
        if kurtosis < -0.5:
            return "graded"
        
        return "continuous"
    
    def _is_bimodal(self, data: np.ndarray, threshold: float = 0.3) -> bool:
        """
        Test simplificado de bimodalidad.
        
        Compara la distribución con una mezcla de 2 Gaussianas vs 1 Gaussiana.
        """
        from scipy.optimize import minimize
        
        # Función de verosimilitud para 1 vs 2 Gaussianas
        def neg_log_likelihood_1gauss(params):
            mu, sigma = params
            sigma = max(sigma, 0.01)
            log_lik = np.sum(stats.norm.logpdf(data, mu, sigma))
            return -log_lik
        
        def neg_log_likelihood_2gauss(params):
            mu1, sigma1, mu2, sigma2, pi = params
            sigma1, sigma2 = max(sigma1, 0.01), max(sigma2, 0.01)
            pi = max(0.01, min(0.99, pi))
            
            g1 = stats.norm.pdf(data, mu1, sigma1)
            g2 = stats.norm.pdf(data, mu2, sigma2)
            mix = pi * g1 + (1 - pi) * g2
            mix = np.maximum(mix, 1e-10)
            log_lik = np.sum(np.log(mix))
            return -log_lik
        
        # Fit 1 Gaussiana
        res1 = minimize(neg_log_likelihood_1gauss, [np.mean(data), np.std(data)],
                       bounds=[(data.min(), data.max()), (0.01, data.std()*3)])
        
        # Fit 2 Gaussianas
        res2 = minimize(neg_log_likelihood_2gauss, 
                       [np.mean(data)-std, std, np.mean(data)+std, std, 0.5],
                       bounds=[(data.min(), data.max()), (0.01, data.std()*2)]*2 + [(0.1, 0.9)])
        
        # Si 2 gaussianas_fit es significativamente mejor, es bimodal
        improvement = res1.fun - res2.fun
        
        return improvement > threshold * len(data)
    
    def _count_modes(self, data: np.ndarray, bandwidth: float = None) -> int:
        """
        Cuenta el número de modos (picos) en la distribución.
        """
        if bandwidth is None:
            bandwidth = 0.3 * np.std(data) * (len(data) ** -0.2)
        
        # KDE
        kde = stats.gaussian_kde(data, bw_method=bandwidth)
        x_range = np.linspace(data.min(), data.max(), 100)
        densities = kde(x_range)
        
        # Contar picos locales
        modes = 0
        for i in range(1, len(densities) - 1):
            if densities[i] > densities[i-1] and densities[i] > densities[i+1]:
                modes += 1
        
        return modes

💡 Implicaciones para Interpretability

Si los features son (casi-)binarios, esto tiene implicaciones importantes para cómo hacemos interpretability:

Más Fácil Intervention

Con features continuos, intervenir es tricky: ¿qué valor pones? ¿0.5? ¿1.0? ¿-0.3? Con features binarios, es fácil: pones 0 o 1. Esto hace que los experimentos de causalidad sean más limpios.

Más Fácil Attribution

Si un feature está "presente" o "ausente", podemos preguntarnos directamente: ¿qué atención heads o MLP layers lo activan? La respuesta es más discrete que cuando hay valores intermedios.

Circuit Discovery Más Simple

Encontrar circuits que implementan features binarios es más straightforward. El feature tiene dos estados bien definidos, y podemos rastrear qué lo activa en cada estado.

⚠️ Caveats y Complications

No todo es tan simple. Hay varias razones por las que los features binarios no son la historia completa:

Contexto Dependencia

Un feature puede ser binario en un contexto pero continuo en otro. Por ejemplo, el feature de "python code" podría ser bimodal cuando el modelo está en modo generación de código pero continuo cuando solo está leyendo código.

Superposition Persistente

Incluso si individual features son binarios, la superposition significa que cada neurona participa en múltiples features. Jadi una neurona individual puede mostrar comportamiento polifacético aunque cada feature sea binario.

Noise y Medición

Las activaciones tienen ruido de medición. Lo que parece binario podría ser una aproximación ruidosa de un feature verdaderamente continuo.

📝 Resumen y Cierre

Binary features representa una dirección fascinante en interpretabilidad. La idea de que los modelos representan información de manera parcialmente discreta tiene implicaciones para cómo entendemos, intervenimos, y optimizamos redes neuronales.

La evidencia sugiere que muchos features en LLMs tienen comportamiento al menos parcialmente binario, especialmente en capas de alto nivel. Esto podría hacer la interpretabilidad más tractable de lo que pensábamos.

Eso sí, hay que ser cuidadosos. Los features binarios no son toda la historia - el contexto importa, la superposition complica las cosas, y el ruido puede mislead. Pero como aproximación prag马拉, binary features nos da una nueva lens para entender cómo funcionan los modelos.
