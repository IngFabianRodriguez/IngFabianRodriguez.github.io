Atención (Attention) - El Mecanismo que Hizo que las RNNs Quedaran Obsoletas

13 de marzo de 2026
attention mechanismself-attentionquery-key-valuescaled dot-product attention

La Intro que el 85% Se Salta

Parcero, ¿por qué cuando leíste "el gato estaba sentado en el" tu cerebro inmediatamente supo que la siguiente palabra probable es "sofá" o "piso"? No procesaste la oración palabra por palabra — procesaste toda la estructura simultáneamente y usaste el contexto para predecir. Las RNNs procesaban secuencialmente (palabra por palabra). Los transformers procesan todo a la vez, pero necesitan un mecanismo para saber qué palabras importan más en relación a las demás. Ese mecanismo es attention.

Yo vi el paper "Attention Is All You Need" (Vaswani et al., 2017) en 2017 y mi primera reacción fue: "esto es demasiado simple para funcionar". Comparado con LSTM con attention complejo, el transformer original era casi trivial. Pero los resultados hablaron solos: mejor que todo lo anterior en traducción, y con entrenamiento significativamente más paraleloizable.

Hoy: cómo funciona el mecanismo de attention, por qué es tan efectivo, y cómo se implementa.

¿Qué Es Attention?

Attention es un mecanismo que permite a cada posición del output enfocarse en cualquier posición del input. Para traducción, esto significa que cuando traduces "gato" puedes ver "estaba", "sentado", "en", "el" — todas las palabras — y decidir cuáles importan más para esa traducción.

La matemática de Scaled Dot-Product Attention:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

Donde:

  • $Q$ (Query): Lo que estoy buscando. Cada posición del output tiene un query.
  • $K$ (Key): Lo que cada posición del input ofrece para ser matcheado.
  • $V$ (Value): El contenido real de cada posición del input.

El output es una weighted sum de los values, donde los weights están determinados por qué tan bien el query matchea cada key.

Multi-Head Attention

Un solo attention head captura solo un tipo de relación. Multi-head attention proyecta $Q, K, V$ en $h$ subspaces diferentes y aplica attention en paralelo:

$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_h)W^O$$

Donde $\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$

Cada head puede aprender un tipo diferente de relación: uno podría enfocarse en relaciones sintácticas (sujeto-verbo), otro en relaciones semánticas (gato-animal), otro en relaciones de proximidad, etc.

Código Production-Grade

import torch
import torch.nn as nn
import torch.nn.functional as F
import math


class ScaledDotProductAttention(nn.Module):
    """Scaled Dot-Product Attention: softmax(QK^T / sqrt(d_k)) V"""
    def forward(self, query, key, value, mask=None):
        d_k = query.size(-1)
        scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(d_k)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, -1e9)
        attention_weights = F.softmax(scores, dim=-1)
        return torch.matmul(attention_weights, value), attention_weights


class MultiHeadAttention(nn.Module):
    """Multi-Head Attention con h heads en paralelo."""
    def __init__(self, d_model=512, num_heads=8, dropout=0.1):
        super().__init__()
        assert d_model % num_heads == 0
        self.d_k = d_model // num_heads
        self.num_heads = num_heads

        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.w_o = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)
        self.attention = ScaledDotProductAttention()

    def forward(self, query, key, value, mask=None):
        batch_size = query.size(0)

        # Linear projections y split en heads
        Q = self.w_q(query).view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        K = self.w_k(key).view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        V = self.w_v(value).view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)

        # Apply attention
        x, attn_weights = self.attention(Q, K, V, mask)

        # Concatenar heads y aplicar output projection
        x = x.transpose(1, 2).contiguous().view(batch_size, -1, self.num_heads * self.d_k)
        return self.w_o(x), attn_weights


class SelfAttention(nn.Module):
    """Self-Attention: Q, K, V vienen del mismo sequence."""
    def __init__(self, d_model, num_heads=8):
        super().__init__()
        self.mha = MultiHeadAttention(d_model, num_heads)

    def forward(self, x, mask=None):
        # Self-attention: query, key, value son el mismo input
        return self.mha(x, x, x, mask)


class CausalSelfAttention(nn.Module):
    """Self-Attention causal (para language modeling). No puede ver el futuro."""
    def __init__(self, d_model, num_heads=8, max_seq_len=512, dropout=0.1):
        super().__init__()
        self.mha = MultiHeadAttention(d_model, num_heads, dropout)
        self.register_buffer(
            "causal_mask",
            torch.tril(torch.ones(max_seq_len, max_seq_len)).view(1, 1, max_seq_len, max_seq_len)
        )

    def forward(self, x):
        # Crear causal mask para no ver el futuro
        seq_len = x.size(1)
        mask = self.causal_mask[:, :, :seq_len, :seq_len]
        return self.mha(x, x, x, mask)


if __name__ == '__main__':
    # Demo
    batch_size, seq_len, d_model = 2, 10, 128
    num_heads = 8

    x = torch.randn(batch_size, seq_len, d_model)
    attn = SelfAttention(d_model, num_heads)
    out, weights = attn(x)

    print(f"Input: {x.shape}")  # [2, 10, 128]
    print(f"Output: {out.shape}")  # [2, 10, 128]
    print(f"Attention weights: {weights.shape}")  # [2, 8, 10, 10]

Errores Comunes

Error 1: No aplicar el mask causal en language modeling

Cuando usas attention para language modeling, el modelo no debería poder ver las palabras futuras — si no, el training es trivially incorrect porque el objetivo sería visible en el input. Sin causal mask, el modelo aprende a "hacer trampa" mirando el target.

Fix: Aplica un causal mask (mask triangular inferior): torch.tril(torch.ones(seq_len, seq_len)). Esto asegura que cada posición solo pueda attend a sí misma ya posiciones anteriores.

Error 2: Attention sin scale adecuado

Si no divides por $\sqrt{d_k}$ en el dot product, el softmax puede entrar en regiones de gradientes muy pequeños cuando $d_k$ es grande. Para $d_k = 512$, el dot product puede ser hasta $512 \times \text{max value} \approx 512$ — softmax de valores tan extremos es esencialmente one-hot, matando el gradiente.

Fix: SIEMPRE escala por $\sqrt{d_k}$. Esto mantiene la varianza de los dot products aproximadamente constante.

Error 3: Memory/performance issues con sequences muy largas

Attention es $O(n^2)$ en memoria y cómputo — cada posición attend a todas las demás. Para una sequence de 4096 tokens, esto es 16M operaciones. Para 32K tokens, es 1B. En long sequences, esto se vuelve prohibitivo.

Fix: Para sequences largas, usa attention sparse (Longformer, BigBird), linear attention (Performer), o sliding window attention. O usa architectures que reducen la longitud efectiva (compresión, chunking).

Resumen del Día

  • Attention: Permite enfocarse en diferentes partes del input. softmax(QK^T / √d_k)V.
  • Q, K, V: Query (lo que busco), Key (lo que oferezco), Value (el contenido real).
  • Multi-Head: h attention heads en paralelo, cada uno captura diferentes tipos de relaciones.
  • Causal Mask: Para LM, solo permite ver el pasado, no el futuro.
  • Scale: Dividir por √d_k para evitar softmax de valores extremos.
  • O(n²): Attention es cuadrático en la longitud de la secuencia.

El Cierre

Parcero, attention es el corazón de los transformers y de muchos modelos de lenguaje modernos. La idea es simple — weighted sum de values según qué tan bien query matchea key — pero el impacto es profond. Permite que cada posición vea todo el contexto simultáneamente, sin recurrence ni convolución.

Esa vaina de "attention es todo lo que necesitas" no es exagerada: eliminó la necesidad de recurrence y convolución para muchas tareas de secuencia. Y la razón por la que funciona tan bien es que permite al modelo aprender qué relaciones son importantes — syntactic, semantic, positional — sin que le digamos explícitamente qué mirar. ¡Nos vemos en el día 88!
