📐 Fundamentos Teóricos

Antes de escribir una sola línea de código necesitamos entender qué es un sentence embedding y por qué es radicalmente diferente a sumar palabras.

¿Qué es un Sentence Transformer?

Un Sentence Transformer (basado en Sentence-BERT o SBERT) es un modelo que toma una oración completa y la convierte en un vector denso de dimensión fija — típicamente 768 para modelos como bert-base-nli-cls-token o 384 para modelos más pequeños como all-MiniLM-L6-v2.

La diferencia clave con métodos clásicos es que ese vector captura significado semántico completo, no promedios de palabras sueltas.

La matemática detrás: Cosine Similarity

Para comparar dos oraciones usamos cosine similarity:

\text{cosine\\_similarity}(A, B) = \frac{A \cdot B}{||A|| \cdot ||B||} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum_{i=1}^{n} A_i^2} \cdot \sqrt{\sum_{i=1}^{n} B_i^2}}

Esto mide el ángulo entre dos vectores en espacio denso. Un valor de 1.0 significa misma dirección (idéntico significado), 0.0 significa ortogonal (sin relación), y -1.0 significa dirección opuesta (significado opuesto).

Triplet Loss: Cómo se entrena SBERT

SBERT se entrena con triplet loss. Dados tres oraciones:

  • Anchor (A): la oración original
  • Positive (P): una oración con significado similar a A
  • Negative (N): una oración con significado diferente a A

El objetivo es que la distancia entre A y P sea menor que la distancia entre A y N por un margen α:

\mathcal{L} = \max\left(0,\; d(A, P) - d(A, N) + \alpha\right)

donde d es típicamente cosine distance = 1 - cosine_similarity. Esto empuja el modelo a agrupar oraciones semánticamente similares cerca en el espacio vectorial.

Contrastive Learning y siamese networks

SBERT usa una arquitectura siamese: dos redes gemelas (compartiendo pesos) procesan las dos oraciones y producen embeddings. A diferencia de BERT estándar que requiere comparar cada par en O(n²) (insoportable para 10,000 oraciones = 50 millones de comparaciones), SBERT reduce esto a O(n) usando embeddings precomputados.

Multilingual Sentence Embeddings

Modelos como paraphrase-multilingual-MiniLM-L12-v2 o multilingual-e5-base permiten que oraciones en español, inglés o cualquier idioma se representen en el mismo espacio vectorial. Esto habilita cross-lingual retrieval: buscar en español con queries en inglés, por ejemplo.

"""

Implementación completa con PyTorch y sentence-transformers.

]

# Compute embeddings para todo el corpus (batch processing)
print(f"Computing embeddings para {len(corpus)} oraciones...")
start = time.time()

    corpus,
    batch_size=4,
    show_progress_bar=True,

    convert_to_tensor=True
)
elapsed = time.time() - start
print(f"Tiempo: {elapsed:.3f}s — Shape: {corpus_embeddings.shape}")

# ─────────────────────────────────────────────────────────────────
# 3. BÚSQUEDA SEMÁNTICA CON COSINE SIMILARITY
# ─────────────────────────────────────────────────────────────────
print("\n" + "=" * 60)
print("3. BÚSQUEDA SEMÁNTICA")

def semantic_search(query: str, corpus_embeddings: torch.Tensor,
                    corpus: list, top_k: int = 3) -> list:
    """
    Búsqueda semántica: given una query, encuentra los top-k
    resultados más similares en el corpus usando cosine similarity.
    """
    # Encode la query
    query_embedding = model.encode(
        query,
        normalize_embeddings=True,
        convert_to_tensor=True
    )

    # cosine_similarity requiere numpy arrays o podemos hacerlo manual
    # Usando PyTorch directamente (más control)
    similarities = F.cosine_similarity(
        query_embedding.unsqueeze(0),
        corpus_embeddings
    )

    # Obtener top-k resultados
    top_scores, top_indices = torch.topk(similarities, k=min(top_k, len(corpus)))

    results = []
    for score, idx in zip(top_scores, top_indices):
        results.append({
            "oracion": corpus[idx],
            "similitud": round(score.item(), 4),
            "indice": idx.item()
        })

    return results


# Query en español
query_es = "¿Cómo funciona el aprendizaje automático?"
print(f"\nQuery (español): '{query_es}'")
results = semantic_search(query_es, corpus_embeddings, corpus, top_k=3)
print("\nResultados:")
for r in results:
    print(f"  [{r['similitud']:.4f}] \"{r['oracion']}\"'")

# Query en inglés (cross-lingual!)
query_en = "How does machine learning work?"
print(f"\nQuery (inglés): '{query_en}'")
results = semantic_search(query_en, corpus_embeddings, corpus, top_k=3)
print("\nResultados:")
for r in results:

# ─────────────────────────────────────────────────────────────────

# Mostrar las 5 más similares para cada oración
print("\nPares más similares (excluyendo diagonal):")
n = len(corpus)
best_pairs = []
for i in range(n):
    for j in range(n):
        if i != j:
            best_pairs.append((sim_matrix[i, j], i, j))

best_pairs.sort(reverse=True)
for sim, i, j in best_pairs[:5]:
    print(f"  [{sim:.4f}] \"{corpus[i]}\" ↔ \"{corpus[j]}\"")

    InputExample(texts=["El banco me aprobación un crédito", "El restaurant tiene buena comida"], label=0.0),
    InputExample(texts=["Necesito un médico urgently", "Busco atención médica urgente"], label=1.0),

🚨 Los 3 Errores que el 75% Commete en Producción

❌ Error 1: Usar Word2Vec promediado en lugar de Sentence Embeddings

Este es el error más común y el más grave. Muchas personas todavía usan este patrón:

# ❌ CÓDIGO INCORRECTO — NO HACER ESTO
import gensim

model_wv = gensim.models.Word2Vec.load("word2vec.model")

def sentence_similarity_w2v(s1, s2):
    """Promediar vectores de palabras = NO captura semantics"""
    v1 = np.mean([model_wv.wv[w] for w in s1.split() if w in model_wv.wv], axis=0)
    v2 = np.mean([model_wv.wv[w] for w in s2.split() if w in model_wv.wv], axis=0)
    return np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2))

¿Por qué está mal? El promedio de Word2Vec ignora completamente el orden de las palabras y diluye el significado en frases negativas o con negaciones. "No voy al médico" y "Voy al médico" tendrán embeddings casi idénticos. Además, frases con múltiples sentidos se promedian sin capturar cuál predomina.

✅ Fix: Usar sentence-transformers siempre:

# ✅ CÓDIGO CORRECTO
model = SentenceTransformer("all-MiniLM-L6-v2")

def sentence_similarity_sbert(s1, s2):
    """SBERT captura semantics completa, incluyendo negaciones"""
    emb1 = model.encode(s1, normalize_embeddings=True)
    emb2 = model.encode(s2, normalize_embeddings=True)
    return np.dot(emb1, emb2)  # Ya normalizados → esto es cosine similarity

❌ Error 2: No normalizar los embeddings antes de cosine similarity

La fórmula completa de cosine similarity divide por las normas. Si normalizas antes, el resultado es idéntico pero el cómputo es más estable numéricamente. Pero hay otro problema peor: si no haces ninguna de las dos, puedes obtener valores incorrectos cuando las normas de los vectores difieren significativamente.

# ❌ CÓDIGO INCORRECTO
def bad_cosine_sim(a, b):
    """No normaliza ni usa la fórmula correcta"""
    return np.dot(a, b)  # ¡Esto es el PRODUCTO INTERNO, no cosine similarity!

# Caso problemático:
a = np.array([100.0, 0.0, 0.0])  # norma = 100
b = np.array([1.0, 0.0, 0.0])    # norma = 1
print(bad_cosine_sim(a, b))       # = 100 → ¡fuera de rango [-1, 1]!

# ✅ CÓDIGO CORRECTO
def correct_cosine_sim(a, b):
    """Cosine similarity real con normalización"""
    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)
    if norm_a == 0 or norm_b == 0:
        return 0.0
    return np.dot(a, b) / (norm_a * norm_b)

# O mejor aún: normaliza desde el inicio y usa producto punto directo
def normalized_cosine_sim(a, b):
    """Más eficiente: normaliza primero, luego producto punto"""
    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)
    if norm_a == 0 or norm_b == 0:
        return 0.0
    a_norm = a / norm_a
    b_norm = b / norm_b
    return np.dot(a_norm, b_norm)

❌ Error 3: Usar un modelo monolingüe para otro idioma sin verificar

Esto pasa constantemente: alguien entrenó un modelo en inglés, lo usa para español, y los embeddings son ruido. O peor, usa un modelo "multilingual" sin verificar que cubra bien el par de idiomas que necesita.

# ❌ CÓDIGO INCORRECTO
model_en = SentenceTransformer("bert-base-uncased")  # Solo inglés
emb_es = model_en.encode("Hola, ¿cómo estás?")  # ¡Embedding meaningless!
emb_en = model_en.encode("Hello, how are you?")
print(F.cosine_similarity(
    torch.tensor(emb_es).unsqueeze(0),
    torch.tensor(emb_en).unsqueeze(0)
))
# Resultado: ~0.85 pero es COMPLETAMENTE ARBITRARIO
# porque el modelo NO fue entrenado con español

# ✅ CÓDIGO CORRECTO: Verificar calidad cross-lingual primero
from sentence_transformers import evaluation

# Modelo multilingual apropiado
model_ml = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

# Evaluación en el par de idiomas que necesitas
sentences_test = {
    "es": [
        "El gato está en la alfombra",
        "Necesito un médico urgentemente",
        "La reunión fue muy productiva",
    ],
    "en": [
        "The cat is on the rug",
        "I need a doctor urgently",
        "The meeting was very productive",
    ]
}

# Embeddings
es_emb = model_ml.encode(sentences_test["es"])
en_emb = model_ml.encode(sentences_test["en"])

# Verificar que las oraciones correspondientes sean cercanas
for i in range(len(sentences_test["es"])):
    sim = np.dot(es_emb[i], en_emb[i]) / (np.linalg.norm(es_emb[i]) * np.linalg.norm(en_emb[i]))
    print(f"[{sim:.4f}] ES: '{sentences_test['es'][i]}' / EN: '{sentences_test['en'][i]}'")

✅ Resumen y cierre

Hoy aprendimos que medir similitud semántica no es hacer np.mean(word2vec_vectors). Es usar sentence transformers que capturan el significado completo de la oración, normalizar siempre antes de comparar, y verificar que el modelo que usas soporte los idiomas de tu aplicación.

En Colombia esto es especialmente relevante porque muchos proyectos mezclan español con inglés (o con lenguas nativas en будущем), y un embedding mal elegido produce retrievers de documentación que dan resultados sin sentido.

El 75% que menciona el título no es exageración: en producción, la mayoría de pipelines de semantic search que he auditado cometen al menos uno de estos tres errores. Con esto que te llevas hoy, ya estás por delante de esa mayoría. Nos vemos en el Día 124.
