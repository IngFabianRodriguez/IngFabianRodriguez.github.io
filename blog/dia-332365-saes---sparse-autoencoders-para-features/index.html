📐 La Matemática del Costo de Inferencia

Cada request a un LLM tiene un costo que depende de dos cosas: los tokens de entrada y los tokens de salida. La fórmula base es:

Costo = (Tokens_entrada × Costo_por_token_entrada) + (Tokens_salida × Costo_por_token_salida)

Pero hay más. El costo real de inference tiene tres componentes principales:

  • Costo computacional: Dominado por las operaciones de matrix multiplication
  • Costo de memoria: El KV cache ocupa VRAM proporcional a la longitud del contexto
  • Costo de latencia: Tiempo de ejecución = dinero en servidores ocupados

La matemática clave del KV cache:

KV_cache_size = 2 × n_layers × n_heads × head_dim × seq_len × bytes_per_param

Para GPT-3 (175B params, 96 layers, 96 heads, 128 head_dim):

KV_cache por token = 2 × 96 × 96 × 128 × 2 bytes (fp16) ≈ 48 MB por token

¡Ojo! Eso es 48 MB SOLO para el KV cache de un solo token. Con un contexto de 2048 tokens:

2048 × 48 MB ≈ 98 GB

Solo en KV cache. Por request. Eso es una locura, parcero.

class QuantizationManager:
    """Gestión de quantization para reducir memoria y costo."""
    
    @staticmethod
    def int8_quantize(weights: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]:
        """Quantize a int8 con scaling factors."""
        # Calcular scaling factor por canal
        scales = weights.abs().max(dim=-1, keepdim=True).values / 127.0
        
        # Quantize
        quantized = (weights / scales).round().clamp(-127, 127).to(torch.int8)
        
        return quantized, scales
    
    @staticmethod
    def int4_quantize(weights: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]:
        """Quantize a int4 con scaling factors."""
        scales = weights.abs().max(dim=-1, keepdim=True).values / 7.0
        quantized = (weights / scales).round().clamp(-7, 7).to(torch.int4)
        
        return quantized, scales
    
    @staticmethod
    def nf4_quantize(weights: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor, List[float]]:
        """NF4: 4-bit normalized float - mejor para distribución normal."""
        # 16 niveles NF4
        nf4_levels = [0.0, 0.0121, 0.0243, 0.0368, 0.0494, 0.0622, 0.0752, 0.0885,
                      0.1021, 0.1161, 0.1307, 0.1459, 0.1619, 0.1789, 0.1972, 0.2197]
        
        scales = weights.abs().max(dim=-1, keepdim=True).values / 0.2197
        normalized = weights / scales
        
        # Asignar al nivel NF4 más cercano
        indices = torch.zeros_like(weights, dtype=torch.uint8)
        for i, level in enumerate(nf4_levels):
            mask = (normalized >= level - 0.006 if i > 0 else normalized >= level - 0.1) & \
                   (normalized < level + 0.006 if i < len(nf4_levels) - 1 else normalized <= level + 0.1)
            indices[mask] = i
        
        return indices, scales, nf4_levels

class KVCacheOptimizer:
    """Optimización del KV cache para reducir uso de memoria 10x."""
    
    def __init__(self, cache_mode: str = "streaming"):
        self.cache_mode = cache_mode
        self.saved_memory = 0
    
    def estimate_kv_cache_size(self, n_layers: int, n_heads: int, 
                                 head_dim: int, seq_len: int, 
                                 n_params: int = 1) -> int:
        """Estima tamaño del KV cache en bytes."""
        # 2 (K and V) × n_layers × n_heads × head_dim × seq_len × 2 bytes (fp16)
        bytes_per_element = 2
        total = 2 * n_layers * n_heads * head_dim * seq_len * bytes_per_element
        return total
    
    def apply_paged_attention(self, keys: torch.Tensor, values: torch.Tensor,
                               block_size: int = 16) -> Tuple[torch.Tensor, List[int]]:
        """Paged attention: reducir fragmentación del KV cache."""
        # Dividir en bloques de tamaño fijo
        n_tokens = keys.shape[2]
        n_blocks = (n_tokens + block_size - 1) // block_size
        
        # Padding al tamaño de bloque
        padded_len = n_blocks * block_size
        keys_padded = F.pad(keys, (0, 0, 0, padded_len - n_tokens))
        values_padded = F.pad(values, (0, 0, 0, padded_len - n_tokens))
        
        # Reshape en bloques
        keys_blocks = keys_padded.reshape(
            keys.shape[0], keys.shape[1], n_blocks, block_size, -1
        )
        values_blocks = values_padded.reshape(
            values.shape[0], values.shape[1], n_blocks, block_size, -1
        )
        
        self.saved_memory = (padded_len - n_tokens) * keys.shape[1] * keys.shape[3] * 2
        return keys_blocks, values_blocks
    
    def apply_prefix_caching(self, keys: torch.Tensor, values: torch.Tensor,
                             prefix: str) -> Tuple[torch.Tensor, torch.Tensor, float]:
        """Cache de prefijos comunes para reutilizar KV de prompts repetidos."""
        # En producción: guardar en Redis/Memcached con key = hash(prefix)
        # Aquí solo simulamos el ahorro
        cache_hit_ratio = 0.7  # 70% de los tokens son prefijos comunes
        memory_saved = keys.shape[2] * keys.shape[3] * keys.shape[0] * cache_hit_ratio
        return keys, values, memory_saved

class SpeculativeDecoding:
    """Speculative decoding: usar modelo pequeño para predecir, grande para verificar."""
    
    def __init__(self, draft_model, target_model, gamma: int = 4):
        self.draft = draft_model
        self.target = target_model
        self.gamma = gamma  # Número de tokens a especular
    
    def decode(self, x: torch.Tensor, max_len: int) -> List[int]:
        """Decodificación especulativa."""
        generated = []
        
        while len(generated) < max_len:
            # 1. Modelo draft propone gamma tokens
            draft_tokens = []
            x_draft = x
            for _ in range(self.gamma):
                with torch.no_grad():
                    logits = self.draft(x_draft)
                    next_tok = logits[-1].argmax().item()
                draft_tokens.append(next_tok)
                x_draft = torch.cat([x_draft, torch.tensor([[next_tok]])], dim=-1)
            
            # 2. Modelo target verifica todos los tokens en paralelo
            with torch.no_grad():
                target_logits = self.target(x_draft)
            
            # 3. Accept o reject cada token
            accepted = []
            for i, draft_tok in enumerate(draft_tokens):
                target_tok = target_logits[i].argmax().item()
                # Accept si son iguales o si la probabilidad del draft > threshold
                draft_prob = F.softmax(target_logits[i], dim=-1)[draft_tok].item()
                if draft_tok == target_tok or draft_prob > 0.5:
                    accepted.append(draft_tok)
                else:
                    accepted.append(target_tok)
                    break  # A partir de aquí, el target tiene la razón
            
            generated.extend(accepted)
            
            # 4. Si todos aceptados, continuar
            if len(accepted) == self.gamma:
                x = x_draft  # Continuar con draft
            else:
                # Añadir token del target que difirió
                x = torch.cat([x, torch.tensor([[accepted[-1]]])], dim=-1)
        
        return generated

class BatchOptimizer:
    """Optimización de batching para maximizar throughput."""
    
    def __init__(self, max_batch_size: int = 64, max_tokens_per_batch: int = 8192):
        self.max_batch_size = max_batch_size
        self.max_tokens_per_batch = max_tokens_per_batch
    
    def dynamic_batching(self, requests: List[Dict]) -> List[List[Dict]]:
        """Agrupar requests dinámicamente por longitud para evitar padding excesivo."""
        # Ordenar por longitud de input
        sorted_reqs = sorted(requests, key=lambda r: len(r["input_ids"]))
        
        batches = []
        current_batch = []
        current_tokens = 0
        
        for req in sorted_reqs:
            req_tokens = len(req["input_ids"]) + req.get("max_tokens", 256)
            
            # Si agregar este request excede límites, empezar nuevo batch
            if (len(current_batch) >= self.max_batch_size or 
                current_tokens + req_tokens > self.max_tokens_per_batch):
                if current_batch:
                    batches.append(current_batch)
                current_batch = [req]
                current_tokens = req_tokens
            else:
                current_batch.append(req)
                current_tokens += req_tokens
        
        if current_batch:
            batches.append(current_batch)
        
        return batches
    
    def estimate_cost_savings(self, n_requests: int, avg_input_tokens: int,
                              avg_output_tokens: int, batch_size: int) -> Dict[str, float]:
        """Estima ahorros de cost con batching vs requests individuales."""
        # Sin batching: cada request tiene overhead de atención
        # Con batching: attention computada una vez para todo el batch
        
        # Costo relativo: menor batch_size = mayor costo por token
        base_cost = 1.0
        batched_cost = base_cost / (batch_size ** 0.2)  # Empirically ~1/sqrt(batch)
        
        total_cost_no_batch = n_requests * (avg_input_tokens + avg_output_tokens) * base_cost
        total_cost_batch = n_requests * (avg_input_tokens + avg_output_tokens) * batched_cost
        
        return {
            "cost_no_batch": total_cost_no_batch,
            "cost_batched": total_cost_batch,
            "savings_ratio": total_cost_no_batch / total_cost_batch,
            "savings_percent": (1 - batched_cost / base_cost) * 100
        }

class LLMCostOptimizer:
    """Framework completo de optimización de costos."""
    
    def __init__(self, config: OptimizedConfig):
        self.config = config
        self.quant_manager = QuantizationManager()
        self.kv_optimizer = KVCacheOptimizer()
        self.batch_optimizer = BatchOptimizer(
            max_batch_size=config.batch_size
        )
        self.cost_history: List[Dict] = []
    
    def quantize_model(self, model: torch.nn.Module) -> torch.nn.Module:
        """Aplica quantization al modelo completo."""
        if self.config.quantization == "int8":
            for name, param in model.named_parameters():
                if "weight" in name:
                    param.data, scales = self.quant_manager.int8_quantize(param.data)
                    # Guardar scales para dequantize después
                    model.register_buffer(f"{name}_scale", scales)
        
        elif self.config.quantization == "int4":
            for name, param in model.named_parameters():
                if "weight" in name:
                    param.data, scales = self.quant_manager.int4_quantize(param.data)
                    model.register_buffer(f"{name}_scale", scales)
        
        elif self.config.quantization == "nf4":
            for name, param in model.named_parameters():
                if "weight" in name:
                    param.data, scales, levels = self.quant_manager.nf4_quantize(param.data)
                    model.register_buffer(f"{name}_scale", scales)
        
        return model
    
    def optimize_kv_cache(self, keys: torch.Tensor, values: torch.Tensor,
                          prefix: Optional[str] = None) -> Tuple[torch.Tensor, torch.Tensor, Dict]:
        """Optimiza KV cache y retorna métricas de ahorro."""
        metrics = {"original_size": keys.numel() * 2 * 4}  # fp32
        
        if self.config.use_kv_cache_optimization:
            # Aplicar paged attention
            keys_opt, values_opt = self.kv_optimizer.apply_paged_attention(keys, values)
            
            if prefix:
                keys_opt, values_opt, saved = self.kv_optimizer.apply_prefix_caching(
                    keys_opt, values_opt, prefix
                )
                metrics["prefix_caching_savings"] = saved
            
            metrics["optimized_size"] = keys_opt.numel() * 2 * 1  # int4
            metrics["compression_ratio"] = metrics["original_size"] / max(metrics["optimized_size"], 1)
        else:
            keys_opt, values_opt = keys, values
            metrics["optimized_size"] = metrics["original_size"]
            metrics["compression_ratio"] = 1.0
        
        return keys_opt, values_opt, metrics
    
    def calculate_cost_per_request(self, input_tokens: int, output_tokens: int,
                                    use_cache: bool = False) -> Dict[str, float]:
        """Calcula costo real por request con todas las optimizaciones."""
        # Base: $0.002 por 1K tokens (precio ejemplo GPT-4)
        base_rate = 0.002 / 1000
        
        base_cost = (input_tokens + output_tokens) * base_rate
        
        # Aplicar optimizaciones
        multiplier = 1.0
        
        if self.config.quantization in ["int8", "int4", "nf4"]:
            # Quantization reduce costo ~2-4x dependiendo del método
            q_factors = {"int8": 2.0, "int4": 4.0, "nf4": 4.5}
            multiplier /= q_factors.get(self.config.quantization, 1.0)
        
        if self.config.use_kv_cache_optimization:
            # Prefix caching puede reducir hasta 70% de tokens repetidos
            multiplier *= 0.6  # Assume 40% savings from prefix caching
        
        if self.config.use_batching:
            # Batching reduce overhead significativamente
            multiplier /= 1.5  # ~1.5x savings
        
        if use_cache:
            # Cache hit: solo costo de lookup, no inference
            multiplier *= 0.01  # 99% savings
        
        optimized_cost = base_cost * multiplier
        
        return {
            "base_cost": base_cost,
            "optimized_cost": optimized_cost,
            "savings_ratio": base_cost / optimized_cost if optimized_cost > 0 else 0,
            "savings_percent": (1 - optimized_cost / base_cost) * 100 if base_cost > 0 else 0
        }

⚠️ Los 3 Errores Más Comunes (y Sus Arreglos)

Error 1: No Medir el Costo Por Request

El problema: La mayoría de equipos no tienen ni idea de cuánto les cuesta cada request. Saben el costo mensual total del cloud, pero no el costo por request individual. Esto es como saber que su restaurante gasta $10,000 en ingredientes al mes pero no saber cuánto le cuesta preparar cada plato. Imposible optimizar sin esta visibilidad.

La solución: Instrumentar cada request con costo calculado. Guardar métricas por request: tokens input, tokens output, latency, y costo estimado. Agregar a dashboards para ver tendencias.

# ❌ MAL: Sin medición de costos
async def bad_generate(request):
    return await llm.predict(request.prompt)

# ✅ BIEN: Con medición detallada de costos
async def good_generate(request, cost_tracker):
    start = time.time()
    
    # Medir antes
    input_tokens = len(tokenizer.encode(request.prompt))
    
    result = await llm.predict(request.prompt)
    
    # Medir después
    output_tokens = len(tokenizer.encode(result))
    latency = time.time() - start
    
    # Calcular costo
    cost = calculate_cost(input_tokens, output_tokens)
    
    # Guardar métricas
    await cost_tracker.log({
        "request_id": request.id,
        "input_tokens": input_tokens,
        "output_tokens": output_tokens,
        "latency_ms": latency * 1000,
        "cost_usd": cost,
        "timestamp": time.time()
    })
    
    return result

Error 2: No Usar Quantization

El problema: Usar modelos en fp16 o fp32 cuando no es necesario. Un modelo de 70B parámetros en fp16 ocupa ~140GB de VRAM. En int8 ocupa ~70GB. En int4 ocupa ~35GB. El mismo modelo, 4x menos memoria, y la diferencia de calidad para la mayoría de aplicaciones es negligible.

La solución: Cuantizar! Empezar con int8 que tiene mínimo impacto en calidad. Si se necesita más ahorro, int4 con calibration dataset. Para cosas muy sensibles a calidad, nf4 que es mejor para distribuciones normales.

# ❌ MAL: fp16 sin razón
model = load_model("llama-70b", precision="fp16")  # 140GB VRAM

# ✅ BIEN: Quantized appropriately
model = load_model("llama-70b", precision="int4", calibration_data=calib_dataset)
# 35GB VRAM - 4x menos, mismo throughput 4x mayor

Error 3: No Optimizar Batching

El problema: Procesar requests de uno en uno cuando podrían ir en batch. Si tiene 32 requests de 100 tokens cada uno, procesarlos por separado significa 32 × 100 = 1600 operaciones de atención. Procesarlos en batch de 32 es UNA operación de atención de 3200 tokens, más eficiente por el parallelismo de GPU.

La solución: Implementar dynamic batching: agrupar requests por longitud similar para minimizar padding waste. Usar prefixed batching para requests con prefijos comunes.

# ❌ MAL: Un request a la vez
async def bad_serve(request):
    result = await model.generate(request.prompt)
    return result

# ✅ BIEN: Dynamic batching
async def good_serve(requests: List[Request]):
    # Agrupar por longitud
    batches = batch_optimizer.dynamic_batching([
        {"input_ids": r.prompt, "max_tokens": r.max_tokens}
        for r in requests
    ])
    
    all_results = []
    for batch in batches:
        # Procesar batch completo
        results = await model.generate_batch([r.prompt for r in batch])
        all_results.extend(results)
    
    return all_results
