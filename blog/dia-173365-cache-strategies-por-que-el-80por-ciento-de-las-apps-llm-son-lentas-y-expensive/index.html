🎯 Por Qué El Cache Es Crítico

Parcero, día 173 y hoy我们来聊聊 Cache Strategies para LLMs. Esa vaina de que cada vez que un usuario hace la misma pregunta, el modelo regenera todo desde cero — eso es tirar dinero y latency. El 80% de las apps LLM en producción están dejando Performance sobre la mesa por no implementar caching correctamente. De una.

Los costos de API de OpenAI/Anthropic son por token, y la latencia de generación escala con el número de tokens generados. Si puedes cachear respuestas frecuentes, reduces costos 10-100x y latencia de segundos a milisegundos. Eso es el diferencia entre una app rentable y una que quema money.

Hagamos las matemáticas: una pregunta común como "¿Cómo hago reset de mi contraseña?" puede representar el 5% de todos los requests. Si tu app tiene 100K requests/día, eso son 5K requests repetidos. Con caching, esos 5K requests se sirven en ~10ms en lugar de ~2s. Eso es:

  • 50 segundos totales de latency ahorrados por esa query sola
  • $0.00 en costos de inferencia en lugar de ~$0.50 (5K tokens × $0.0001)
  • 99%+ cache hit ratio para queries frecuentes en producción

En apps con mucho tráfico, caching es la optimización de mayor impacto por esfuerzo. No es opcional — es survival básico.

📐 Niveles de Cache

Existen múltiples niveles donde podemos cachear:

Level 1: Token-level KV Cache

Dentro del transformer, el KV cache guarda los estados de keys y values para los tokens ya generados. Esto es intra-request — no shared entre requests. Evita recalcular attention para tokens previos.

Level 2: Semantic Cache

Cache a nivel de request completo. Identifica si un nuevo prompt es semánticamente similar a uno ya respondido. Si similarity > threshold, devuelve la respuesta cacheada.

Level 3: Static Cache

Para prompts known-to-be-frequent como instrucciones de sistema, templates de prompts, o conocimiento factual que nunca cambia. Se valida por TTL o version hash.

💻 Código Production-Grade con Semantic Cache

"""
Semantic Cache para LLM API usando Redis y embeddings.
Detecta queries similares y sirve respuestas cacheadas.
"""
import hashlib
import json
import logging
import time
from dataclasses import dataclass, field
from typing import Optional, List, Dict, Any, Tuple
from collections import OrderedDict
import numpy as np

import redis
from sentence_transformers import SentenceTransformer
import torch
from transformers import AutoTokenizer, AutoModel

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)


@dataclass
class CacheConfig:
    """Configuración del semantic cache."""
    redis_host: str = "localhost"
    redis_port: int = 6379
    redis_db: int = 0
    similarity_threshold: float = 0.92
    embedding_model: str = "sentence-transformers/all-MiniLM-L6-v2"
    max_cache_size: int = 100_000
    default_ttl_seconds: int = 3600 * 24 * 7  # 1 semana
    device: str = "cuda" if torch.cuda.is_available() else "cpu"


class SemanticCache:
    """
    Cache semántico para respuestas de LLM.
    
    Usa embeddings para encontrar queries similares
    y sirve respuestas cacheadas cuando similarity > threshold.
    """
    
    def __init__(self, config: CacheConfig):
        self.config = config
        self.redis_client = redis.Redis(
            host=config.redis_host,
            port=config.redis_port,
            db=config.redis_db,
            decode_responses=True
        )
        
        # Cargar modelo de embeddings
        logger.info(f"Cargando modelo de embeddings: {config.embedding_model}")
        self.embedding_model = SentenceTransformer(
            config.embedding_model,
            device=config.device
        )
        
        # Dimensionalidad del embedding
        self.embedding_dim = self.embedding_model.get_sentence_embedding_dimension()
        
        # Namespace para keys de Redis
        self.ns = "llm_cache:"
        
        logger.info(f"Semantic cache inicializado. "
                   f"Threshold: {config.similarity_threshold}, "
                   f"Device: {config.device}")
    
    def _compute_hash(self, prompt: str, **kwargs) -> str:
        """
        Genera hash único para un prompt + parámetros.
        """
        key_parts = [prompt]
        for k, v in sorted(kwargs.items()):
            key_parts.append(f"{k}={v}")
        key_str = "|".join(key_parts)
        return hashlib.sha256(key_str.encode()).hexdigest()[:16]
    
    def _get_embedding(self, text: str) -> np.ndarray:
        """Computa embedding para un texto."""
        embedding = self.embedding_model.encode(
            text,
            convert_to_numpy=True,
            show_progress_bar=False,
            normalize_embeddings=True  # Cosine similarity = dot product
        )
        return embedding.astype(np.float32)
    
    def _store_embedding(self, key: str, embedding: np.ndarray) -> None:
        """Guarda embedding en Redis con TTL."""
        embedding_bytes = embedding.tobytes()
        self.redis_client.setex(
            f"{self.ns}emb:{key}",
            self.config.default_ttl_seconds,
            embedding_bytes
        )
    
    def _find_similar(
        self, 
        query_embedding: np.ndarray,
        limit: int = 5
    ) -> List[Tuple[str, float]]:
        """
        Encuentra los keys más similares al query embedding.
        Usa ANN (Approximate Nearest Neighbors) via Redis.
        
        Returns:
            Lista de (key, similarity_score) tuples.
        """
        # En producción usar RedisVSS o similar para ANN indexing
        # Por ahora, scan lineal (aceptable para <100K items)
        all_keys = list(self.redis_client.scan_iter(f"{self.ns}emb:*"))
        
        if not all_keys:
            return []
        
        similarities = []
        pipe = self.redis_client.pipeline()
        for key in all_keys:
            pipe.get(key)
        embeddings_raw = pipe.execute()
        
        for key, emb_bytes in zip(all_keys, embeddings_raw):
            if emb_bytes is None:
                continue
            cached_emb = np.frombuffer(emb_bytes, dtype=np.float32)
            # Cosine similarity (embeddings ya normalizados)
            sim = np.dot(query_embedding, cached_emb)
            cache_key = key.replace(f"{self.ns}emb:", "")
            similarities.append((cache_key, float(sim)))
        
        # Ordenar por similarity descendente
        similarities.sort(key=lambda x: x[1], reverse=True)
        return similarities[:limit]
    
    def get(
        self, 
        prompt: str, 
        **generation_kwargs
    ) -> Tuple[Optional[str], Optional[float]]:
        """
        Intenta recuperar una respuesta cacheada para el prompt.
        
        Args:
            prompt: Texto del prompt
            **generation_kwargs: Parámetros de generación (temperature, etc.)
            
        Returns:
            (respuesta_cacheada, similarity_score) o (None, None) si no hit.
        """
        key = self._compute_hash(prompt, **generation_kwargs)
        
        # Check exact match primero
        cached = self.redis_client.get(f"{self.ns}resp:{key}")
        if cached:
            logger.info(f"Exact cache hit for key {key}")
            return cached, 1.0
        
        # Buscar similar
        query_emb = self._get_embedding(prompt)
        similar = self._find_similar(query_emb, limit=1)
        
        if similar:
            similar_key, similarity = similar[0]
            if similarity >= self.config.similarity_threshold:
                # Verificar que los generation_params también matcheen
                cached_params = self.redis_client.hgetall(
                    f"{self.ns}params:{similar_key}"
                )
                cached_params_match = all(
                    str(generation_kwargs.get(k)) == v 
                    for k, v in cached_params.items()
                )
                
                if cached_params_match:
                    cached_response = self.redis_client.get(
                        f"{self.ns}resp:{similar_key}"
                    )
                    if cached_response:
                        logger.info(
                            f"Semantic cache hit for key {key} -> {similar_key} "
                            f"(similarity={similarity:.3f})"
                        )
                        return cached_response, similarity
        
        return None, None
    
    def set(
        self, 
        prompt: str, 
        response: str,
        **generation_kwargs
    ) -> None:
        """
        Guarda una respuesta en el cache.
        
        Args:
            prompt: Texto del prompt
            response: Respuesta generada
            **generation_kwargs: Parámetros usados para generar
        """
        key = self._compute_hash(prompt, **generation_kwargs)
        
        # Guardar respuesta
        self.redis_client.setex(
            f"{self.ns}resp:{key}",
            self.config.default_ttl_seconds,
            response
        )
        
        # Guardar parámetros
        if generation_kwargs:
            self.redis_client.hset(
                f"{self.ns}params:{key}",
                mapping={k: str(v) for k, v in generation_kwargs.items()}
            )
            self.redis_client.expire(
                f"{self.ns}params:{key}",
                self.config.default_ttl_seconds
            )
        
        # Guardar embedding
        query_emb = self._get_embedding(prompt)
        self._store_embedding(key, query_emb)
        
        # Evict oldest si excede max size
        current_size = self.redis_client.dbsize()
        if current_size > self.config.max_cache_size:
            self._evict_oldest(int(current_size * 0.1))  # Evict 10%
        
        logger.info(f"Cached response for key {key}")
    
    def _evict_oldest(self, count: int) -> None:
        """Evict las entradas más antiguas (LRU-like)."""
        # En producción, usar Redis SORTED SET con timestamps
        # Por simplicidad,这儿 usamos keys aleatorias
        keys_to_evict = list(self.redis_client.scan_iter(f"{self.ns}*"))[:count]
        if keys_to_evict:
            self.redis_client.delete(*keys_to_evict)
            logger.info(f"Evicted {len(keys_to_evict)} cache entries")
    
    def get_stats(self) -> Dict[str, Any]:
        """Retorna estadísticas del cache."""
        info = self.redis_client.info()
        all_keys = list(self.redis_client.scan_iter(f"{self.ns}resp:*"))
        return {
            "total_entries": len(all_keys),
            "memory_used_mb": info.get("used_memory", 0) / (1024 * 1024),
            "hit_rate": self.redis_client.get(f"{self.ns}stats:hits") or 0,
            "miss_rate": self.redis_client.get(f"{self.ns}stats:misses") or 0,
        }


class LLMClientWithCache:
    """
    Cliente LLM con cache semántico integrado.
    """
    
    def __init__(
        self,
        api_key: str,
        cache_config: Optional[CacheConfig] = None,
    ):
        self.cache = SemanticCache(cache_config or CacheConfig())
        self.api_key = api_key
        self.stats = {"hits": 0, "misses": 0, "errors": 0}
    
    def generate(
        self,
        prompt: str,
        model: str = "gpt-3.5-turbo",
        temperature: float = 0.7,
        max_tokens: int = 1000,
        **kwargs
    ) -> Dict[str, Any]:
        """
        Genera respuesta con cache semántico.
        
        1. Check cache
        2. Si hit, retorna cacheado
        3. Si miss, llama API, cachea resultado
        """
        start_time = time.time()
        
        # Intentar cache
        cached_response, similarity = self.cache.get(
            prompt, 
            model=model, 
            temperature=temperature,
            max_tokens=max_tokens,
            **kwargs
        )
        
        if cached_response is not None:
            self.stats["hits"] += 1
            latency_ms = (time.time() - start_time) * 1000
            return {
                "response": cached_response,
                "cached": True,
                "similarity": similarity,
                "latency_ms": latency_ms,
                "cache_hit": True,
            }
        
        # Cache miss — llamar API
        try:
            import openai
            openai.api_key = self.api_key
            
            response = openai.ChatCompletion.create(
                model=model,
                messages=[{"role": "user", "content": prompt}],
                temperature=temperature,
                max_tokens=max_tokens,
                **kwargs
            )
            
            full_response = response.choices[0].message.content
            
            # Cachear resultado
            self.cache.set(
                prompt,
                full_response,
                model=model,
                temperature=temperature,
                max_tokens=max_tokens,
                **kwargs
            )
            
            self.stats["misses"] += 1
            latency_ms = (time.time() - start_time) * 1000
            
            return {
                "response": full_response,
                "cached": False,
                "latency_ms": latency_ms,
                "usage": response.usage.to_dict(),
                "cache_hit": False,
            }
            
        except Exception as e:
            self.stats["errors"] += 1
            logger.error(f"Error generando respuesta: {e}")
            raise


# Usage
if __name__ == "__main__":
    cache_config = CacheConfig(
        redis_host="localhost",
        similarity_threshold=0.92,
        embedding_model="sentence-transformers/all-MiniLM-L6-v2",
    )
    
    client = LLMClientWithCache(
        api_key="your-api-key",
        cache_config=cache_config,
    )
    
    # Primera llamada — cache miss
    result1 = client.generate(
        "Explain how blockchain consensus works",
        model="gpt-3.5-turbo",
        temperature=0.7,
    )
    print(f"First call: cached={result1['cached']}, latency={result1['latency_ms']:.1f}ms")
    
    # Segunda llamada con mismo prompt — cache hit
    result2 = client.generate(
        "Explain how blockchain consensus works",
        model="gpt-3.5-turbo",
        temperature=0.7,
    )
    print(f"Second call: cached={result2['cached']}, latency={result2['latency_ms']:.1f}ms")
    
    # Similar pero no idéntico — semantic hit
    result3 = client.generate(
        "How does blockchain achieve consensus?",
        model="gpt-3.5-turbo",
        temperature=0.7,
    )
    print(f"Similar call: cached={result3['cached']}, similarity={result3.get('similarity', 0):.3f}")
    
    print(f"Stats: {client.stats}")

⚠️ Errores Comunes con Cache

Error 1: No normalizar prompts antes de cache lookup

El problema: Prompts como "Explain blockchain" y "Explain blockchain " (con trailing space) son diferentes strings pero semánticamente idénticas. Sin normalización, el cache miss rate sube artificialmente. El 70% de implementaciones de cache ignora esto.

Fix: Normalizar: strip(), lower(), remover multiple spaces. Idealmente usar semantic similarity con embeddings en lugar de exact string match.

Error 2: Threshold de similarity muy alto o muy bajo

El problema: Si el threshold es muy alto (>0.95), casi nunca hay cache hits porque prompts nunca son idénticos enough. Si es muy bajo (<0.80), puedes retornar respuestas cached para queries diferentes que producen respuestas incorrectas para el contexto específico del usuario.

Fix: Empezar con 0.90-0.92 para la mayoria de casos. Para dominios técnicos, puede necesitar ser más alto (0.95+). Monitorear cache hit rate y adjust.

Error 3: No invalidar cache cuando el modelo cambia

El problema: Si cambias el modelo (ej: de gpt-3.5 a gpt-4) o actualizas el prompt template, las respuestas cacheadas con el modelo viejo son incorrectas. Pero el cache sigue retornándolas.

Fix: Incluir model version en el cache key hash. Cuando desplieges nuevo modelo, los cache keys cambiarán automáticamente porque incluyen el model name/version.

✅ Resumen y Cierre

  • Semantic cache puede reducir costos 80-95% para queries repetidas.
  • Similarity threshold de 0.90-0.92 es un buen punto de partida.
  • Normalizar prompts antes de caching es critical.
  • Model version en cache key previene stale responses post-model-update.

Hágale que caching no es opcional en producción. Con 80% de queries siendo repetidas o similares, dejar de cachear es como tirar dinero a la basura. Implementen semantic cache desde el día uno, parcero.
