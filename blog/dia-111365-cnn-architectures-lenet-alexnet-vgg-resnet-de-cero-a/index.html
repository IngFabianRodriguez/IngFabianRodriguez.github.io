La Revolución Convolucional: De LeNet a ResNet

Las redes neuronales convolucionales (CNN) son el motor de todo lo que ves hoy: detección de objetos, segmentación médica, reconocimiento facial, hasta el filtro de tu foto del paseíto en Medellín. Pero no nacieron así de powerful. Vamos a recorrer la evolución histórica, y más importante: por qué cada arquitectura resolvió problemas específicos.

LeNet-5 (1998) — El Abuelo Que Lo Empezó Todo

Yann LeCun, en Bell Labs, creó LeNet-5 para reconocimiento de dígitos en cheques bancarios. Sí, en 1998. Esto es más viejo que Google, parcero. Y lo más increíble es que la arquitectura básica sigue vigente.

La estructura era elegante en su simplicidad:

  • C1: Conv 5x5, 6 filtros → 32x32 → 28x28
  • S2: MaxPool 2x2 → 14x14
  • C3: Conv 5x5, 16 filtros → 10x10
  • S4: MaxPool 2x2 → 5x5
  • C5: Conv 5x5, 120 filtros → 1x1
  • F6: Fully connected, 84 unidades
  • Output: 10 clases (dígitos 0-9)

El secreto de LeNet era el receptive field local: cada neurona solo miraba un pedacito de la imagen, no toda la imagen completa. Esto reducía parámetros dramáticamente comparado con MLPs puros.

AlexNet (2012) — El Que Cambió Todo

Aquí es donde la cosa se puso seria. AlexNet ganó ImageNet 2012 con un 84.6% de top-5 accuracy, frente al 73.8% del segundo lugar (métodos tradicionales). La comunidad vio que el deep learning era el camino.

Innovaciones clave de AlexNet:

  • ReLU en vez de tanh/sigmoid — el training era 6x más rápido
  • GPU training — usaron 2 GPUs GTX 580, era revolucionário
  • Dropout — la primera línea de defensa contra overfitting masivo
  • Local Response Normalization — inspirada en la competencia biológica entre neuronas
  • Overlapping pooling — stride menor que el kernel size

La arquitectura tenía 8 capas: 5 convolucionales + 3 fully connected. 60 millones de parámetros. En 2012 esto era un monstruo. Hoy entrenamos modelos con 7 billones de parámetros, pero las GPUs son proporcionalmente más potentes.

VGG-16/19 (2014) — La Profundidad Por Profundidad

VGG (Visual Geometry Group, Oxford) propuso algo simple pero efectivo: más profundidad con kernels más pequeños. En vez de Conv 11x11 y Conv 5x5 como en AlexNet, VGG usaba puras Conv 3x3. ¿El resultado? Más capas, más no-linearidad, menos parámetros.

La lógica detrás de las Conv 3x3:

  • Dos Conv 3x3 apiladas tienen receptive field de 5x5 — equivalent a una Conv 5x5 pero con 18 parámetros en vez de 25 (2×3×3 vs 1×5×5)
  • Tres Conv 3x3 apiladas = receptive field 7x7 con solo 27 parámetros vs 49
  • Además, cada Conv 3x3 trae su propia ReLU, añadiendo no-linealidad

VGG-16 tiene 138 millones de parámetros. VGG-19, 144 millones. Esto era un problema, como veremos en los errores comunes.

La Matemática Que Lo Mueve Todo

La convolución en 2D es la operación central. Para un input $H \times W \times C_{in}$ y un kernel $K_h \times K_w$:

La salida de un feature map con stride $S$ y padding $P$ es:

$$ H_{out} = \left\lfloor \frac{H_{in} + 2P - K_h}{S} \right\rfloor + 1 $$

$$ W_{out} = \left\lfloor \frac{W_{in} + 2P - K_w}{S} \right\rfloor + 1 $$

El número de parámetros de una capa convolucional:

$$ \text{Params} = K_h \times K_w \times C_{in} \times N_{filters} + N_{filters} \text{ (bias)} $$

Para una Conv 3x3 con 64 filtros en una capa con 128 canales de input:

$$ \text{Params} = 3 \times 3 \times 128 \times 64 + 64 = 73{,}856 \text{ parámetros} $$

El Problema De La Profundidad: Vanishing Gradients

Mientras más capas añadiamos, pasa algo raro: el gradient se hace chiquito, chiquito, hasta que las primeras capas casi no aprenden. Esto es el vanishing gradient problem.

La razón: en redes profundas, el gradient se multiplica capa por capa durante el backpropagation. Si cada capa multiplica por valores menores a 1, el producto se encoge exponencialmente. Las primeras capas reciben updates microscópicos.

La solución: skip connections (conexiones de salto). Esto es el corazón de ResNet.

ResNet Y Las Skip Connections

ResNet (2015) propuso algo elegantemente simple: añade la entrada directamente a la salida del bloque.

$$ \mathbf{y} = \mathcal{F}(\mathbf{x}, \{W_i\}) + \mathbf{x} $$

Si $\mathcal{F}$ aprende a ser cero, $\mathbf{y} = \mathbf{x}$. La red puede "saltarse" capas si no son necesarias. El gradient ahora tiene un camino directo sin multiplicaciones, así que fluye sin vanishing.

Esto permitió entrenar redes de 152 capas (ResNet-152) vs las 8-19 de arquitecturas anteriores. Y paradójicamente, redes más profundas entrenaban más fácil que las shallow.

Implementación Completa En PyTorch

Acá va el código real, 100+ líneas, pa' que veas cómo implementar esto desde cero y compararlo con los modelos pretrained de torchvision.

import torch
import torch.nn as nn
import torch.nn.functional as F
import torchvision.models as models
import torchvision.transforms as transforms
from torch.utils.data import DataLoader
import matplotlib.pyplot as plt
import numpy as np

# ============================================================
# PARTE 1: LeNet-5 Implementación Desde Cero
# ============================================================
class LeNet5(nn.Module):
    """LeNet-5 original: 60K params, diseñado para MNIST 32x32."""
    
    def __init__(self, num_classes=10):
        super().__init__()
        # C1: Conv 5x5, 6 filtros
        self.conv1 = nn.Conv2d(1, 6, kernel_size=5, padding=0)  # 32->28
        # S2: MaxPool 2x2
        # C3: Conv 5x5, 16 filtros
        self.conv2 = nn.Conv2d(6, 16, kernel_size=5, padding=0)  # 14->10
        # S4: MaxPool 2x2 -> 5x5
        # C5: Conv 5x5, 120 filtros
        self.conv3 = nn.Conv2d(16, 120, kernel_size=5, padding=0)  # 5->1
        # F6: Fully connected
        self.fc1 = nn.Linear(120, 84)
        self.fc2 = nn.Linear(84, num_classes)
        
    def forward(self, x):
        x = F.relu(self.conv1(x))    # 32x32 -> 28x28
        x = F.max_pool2d(x, 2, 2)    # 28x28 -> 14x14
        x = F.relu(self.conv2(x))    # 14x14 -> 10x10
        x = F.max_pool2d(x, 2, 2)    # 10x10 -> 5x5
        x = F.relu(self.conv3(x))    # 5x5 -> 1x1
        x = x.view(x.size(0), -1)     # flatten: (B, 120)
        x = F.relu(self.fc1(x))      # (B, 84)
        x = self.fc2(x)              # (B, 10)
        return x

# ============================================================
# PARTE 2: Bloque Residual (ResNet Building Block)
# ============================================================
class ResidualBlock(nn.Module):
    """Basic residual block con skip connection."""
    
    def __init__(self, in_channels, out_channels, stride=1):
        super().__init__()
        self.conv1 = nn.Conv2d(in_channels, out_channels, 
                               kernel_size=3, stride=stride, padding=1, bias=False)
        self.bn1 = nn.BatchNorm2d(out_channels)
        self.conv2 = nn.Conv2d(out_channels, out_channels,
                               kernel_size=3, stride=1, padding=1, bias=False)
        self.bn2 = nn.BatchNorm2d(out_channels)
        
        # Skip connection: identity o projection
        self.skip = nn.Sequential()
        if stride != 1 or in_channels != out_channels:
            self.skip = nn.Sequential(
                nn.Conv2d(in_channels, out_channels, 
                          kernel_size=1, stride=stride, bias=False),
                nn.BatchNorm2d(out_channels)
            )
    
    def forward(self, x):
        residual = self.skip(x)
        out = F.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        out += residual  # Skip connection: la magia de ResNet
        out = F.relu(out)
        return out

# PARTE 4: Feature Map Visualization (LeNet-5)
# ============================================================
def visualize_feature_maps(model, image_tensor):
    """Visualiza los feature maps de la primera capa convolucional."""
    
    model.eval()
    
    # Hook para capturar activaciones
    activations = []
    
    def hook_fn(module, input, output):
        activations.append(output.detach())
    
    handle = model.conv1.register_forward_hook(hook_fn)
    
    with torch.no_grad():
        output = model(image_tensor.unsqueeze(0))
    
    handle.remove()
    
    # Visualize los 6 filtros de la primera capa
    feature_maps = activations[0][0]  # (6, 28, 28)
    
    fig, axes = plt.subplots(2, 3, figsize=(10, 6))
    fig.suptitle('Feature Maps - Capa Conv1 (LeNet-5)', fontsize=14)
    
    for i, ax in enumerate(axes.flat):
        im = ax.imshow(feature_maps[i].numpy(), cmap='viridis')
        ax.set_title(f'Filtro {i+1}')
        ax.axis('off')
    
    plt.tight_layout()
    plt.savefig('/tmp/lenet5_feature_maps.png', dpi=150, bbox_inches='tight')
    print("Feature maps guardados en /tmp/lenet5_feature_maps.png")
    return feature_maps

# ============================================================
# PARTE 5: Transfer Learning Desde ResNet
# ============================================================
class ResNetTransferLearner(nn.Module):
    """ResNet-50 adaptado para transferencia con fine-tuning."""
    
    def __init__(self, num_classes=5, freeze_backbone=False):
        super().__init__()
        # Cargar ResNet-50 pretrained
        resnet = models.resnet50(weights=models.ResNet50_Weights.DEFAULT)
        
        # Extraer el backbone (todas las capas excepto el FC final)
        self.backbone = nn.Sequential(*list(resnet.children())[:-1])  # Remove FC
        
        # Freeze o no el backbone
        if freeze_backbone:
            for param in self.backbone.parameters():
                param.requires_grad = False
        
        # Nuevo clasificador pa' 5 clases
        self.classifier = nn.Linear(2048, num_classes)
        
    def forward(self, x):
        features = self.backbone(x)  # (B, 2048, 1, 1)
        features = features.view(features.size(0), -1)  # (B, 2048)
        logits = self.classifier(features)
        return logits

⚠️ Errores Comunes Y Sus Soluciones

Error 1: Usar VGG-16/19 Cuando ResNet Es Mejor Y Más Eficiente

El problema: VGG-16 tiene 138 millones de parámetros y logra 71.1% en ImageNet. ResNet-50 tiene solo 25 millones de parámetros (5.5x menos) y logra 76.1%. Es más rápido de entrenar, más内存-efficient, y mejor accuracy. Pero muchos devs siguen usando VGG porque "siempre lo han hecho así" o porque encontraron tutorials de 2016.

La solución: Usa ResNet (o EfficientNet, o ConvNeXt) en vez de VGG. Si ya tienes código con VGG, es plug-and-play con torchvision:

# MAL: VGG-16 (138M params, 71.1% acc)
model = models.vgg16(weights=models.VGG16_Weights.DEFAULT)

# BIEN: ResNet-50 (25M params, 76.1% acc) - 5x menos params, 5% mejor acc
model = models.resnet50(weights=models.ResNet50_Weights.DEFAULT)

Si por alguna razón necesitas VGG (ej: transferencia a características específicas), al menos usa VGG-16 y no VGG-19. La diferencia de accuracy es marginal (1.3%) pero el costo computacional es значительно.

Error 2: No Usar Pretrained Models Cuando Se Puede Hacer Transfer Learning

El problema: Muchos devs entrenan redes desde cero en datasets pequeños (1000-10000 imágenes) cuando podrían usar transfer learning y obtener 90%+ accuracy. Entrenar desde cero en datasets pequeños es una receta segura para el overfitting. Los features de ImageNet son sorprendentemente transferibles a otros dominios: imágenes médicas, satélite, productos industriales, rostros.

La solución: Siempre empieza con transfer learning. Es el estándar de la industria:

import torchvision.models as models

# Opción 1: Fine-tune completo (más params trainables, mejor accuracy)
model = models.resnet50(weights=models.ResNet50_Weights.DEFAULT)
model.fc = nn.Linear(2048, num_classes)  # Reemplaza el clasificador

# Opción 2: Freeze backbone (menos overfitting, más rápido)
model = models.resnet50(weights=models.ResNet50_Weights.DEFAULT)
for param in model.parameters():
    param.requires_grad = False
model.fc = nn.Linear(2048, num_classes)

# Training loop con los parámetros correctos
optimizer = torch.optim.Adam(
    filter(lambda p: p.requires_grad, model.parameters()),  # Solo trainable
    lr=1e-3
)

Error 3: Deep Networks Sin Skip Connections Que Sufren Vanishing Gradients

El problema: Cuando construyes una red neuronal profunda (20+ capas) sin skip connections, el gradient se desvanece en las primeras capas durante backpropagation. Los updates son microscópicos, el training se estanca, la red no converge. Esto no es un bug — es matemática. En redes densas sin skip connections:

$$ \frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(l)}} = \frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(L)}} \prod_{i=l}^{L-1} \mathbf{W}^{(i)} $$

Si los eigenvalues de $\mathbf{W}^{(i)}$ son menores que 1, el producto se desvanece exponencialmente con la profundidad.

La solución: Usa skip connections siempre en redes profundas. Si construyes una red custom con más de 10 capas, añade residual blocks:

# MAL: Red profunda sin skip connections (vanishing gradients)
class DeepConvNetBad(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 64, 3, padding=1)
        self.conv2 = nn.Conv2d(64, 64, 3, padding=1)
        self.conv3 = nn.Conv2d(64, 64, 3, padding=1)
        # ... 20 capas así
        # Resultado: vanishing gradients, no converge
        
# BIEN: Residual blocks con skip connections
class DeepConvNetGood(nn.Module):
    def __init__(self, num_blocks=20):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 64, 3, padding=1)
        self.res_blocks = nn.ModuleList([
            ResidualBlock(64, 64) for _ in range(num_blocks)
        ])
        self.conv_final = nn.Conv2d(64, 10, 1)
    
    def forward(self, x):
        x = F.relu(self.conv1(x))
        for block in self.res_blocks:
            x = block(x)  # Skip connections permiten gradient flow directo
        return self.conv_final(x)

Resumen Del Día — De Colombia Pa' El Mundo

Hoy aprendimos que las CNN architectures no nacieron de la noche a la mañana — son el resultado de décadas de investigación, errores, y iteraciones. Desde LeNet-5 con sus 60K parámetros hasta ResNet con skip connections que permiten entrenar redes de 152 capas, cada innovación resolvió un problema específico.

Lo clave pa' llevar: Si estás empezando un proyecto de computer vision, no reinventes la rueda. Usa transfer learning con ResNet o EfficientNet. No uses VGG si puedes usar ResNet (menos params, mejor accuracy). Y si construyes redes profundas, siempre añade skip connections — el gradient te lo va a agradecer.

El que llega lejos no es el que más corre, sino el que mejor arquitecturas usa. Eso es todo por hoy, parcero. Mañana seguimos con la Revolución del Attention en el Día 112.
