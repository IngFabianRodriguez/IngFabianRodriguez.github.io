🎯 ¿Por Qué Las Loss Functions Son Tan Importantes?

La loss function es la brújula que guía todo el aprendizaje. Si elegís la wrong loss, tu modelo puede converger a algo completamente diferente a lo que esperás. No es un hiperparámetro menor — es la función que define qué significa "bueno" para tu modelo.

La mayoría de los errores que veo en producción no son de arquitectura ni de datos. Son de usar CrossEntropy donde corresponde BCE, o de no usar class weights cuando el dataset tiene imbalance severo. Vamos paso a paso.

📐 La Matemática De Las Loss Functions

CrossEntropyLoss: Log-Softmax + NLL

CrossEntropy en PyTorch combina log-softmax y negative log-likelihood en una sola función:

$$\text{CrossEntropy}(x, y) = -\sum_{c=1}^{C} y_c \log\left(\frac{\exp(x_c)}{\sum_{j=1}^{C} \exp(x_j)}\right)$$

Para una muestra con clase verdadera $y$, esto se reduce a:

$$\text{CE}(x, y_{\text{true}}) = -\log\left(\frac{\exp(x_{y_{\text{true}}})}{\sum_{j} \exp(x_j)}\right) = -x_{y_{\text{true}}} + \log\sum_{j=1}^{C} \exp(x_j)$$

PyTorch implementa esto como nn.CrossEntropyLoss que espera raw logits (no softmaxeados). El softmax está incluido internamente para estabilidad numérica.

Binary Cross-Entropy (BCE)

Para clasificación binaria o multi-label:

$$\text{BCE}(x, y) = -\frac{1}{N} \sum_{i=1}^{N} \left[ y_i \cdot \log(\sigma(x_i)) + (1 - y_i) \cdot \log(1 - \sigma(x_i)) \right]$$

Donde $\sigma$ es la sigmoid. PyTorch ofrece dos versiones:

  • nn.BCELoss: espera probabilidades (después de sigmoid)
  • nn.BCEWithLogitsLoss: espera logits (sigmoid incluida internamente) — más estable numéricamente

Focal Loss (Lin et al., 2017)

Para class imbalance severo, Focal Loss modifica CrossEntropy con un factor de focus:

$$\text{FL}(p_t) = -\alpha_t (1 - p_t)^{\gamma} \log(p_t)$$

Donde $p_t$ es la probabilidad de la clase verdadera, $\gamma$ (gamma) controla cuánto focus en ejemplos hard, y $\alpha$ es un weight factor por clase. Cuando $\gamma = 0$, Focal es equivalente a CrossEntropy.

Label Smoothing

Label smoothing reemplaza los labels hard (0 y 1) con un mix suave:

$$y_{\text{smoothed}} = y \cdot (1 - \epsilon) + \frac{\epsilon}{C}$$

Donde $\epsilon$ es el smoothing factor y $C$ es el número de clases. Un valor de 0.1 significa que la clase verdadera tiene weight $0.9$ y las demás $0.1/C$ cada una.

    print("\nRegla de oro: ¿Una muestra puede tener múltiples labels? -> BCE")

def demo_focal_loss():
    """Focal Loss implementation para class imbalance severo"""
    print("=" * 60)
    print("FOCAL LOSS (Lin et al., 2017)")
    print("=" * 60)
    
    class FocalLoss(nn.Module):
        """Focal Loss para class imbalance.
        
        FL(p_t) = -alpha * (1 - p_t)^gamma * log(p_t)
        
        gamma: focusing parameter (default=2)
          - gamma=0: equivalent to CE
          - gamma>0: reduces loss for well-classified examples, focuses on hard ones
        alpha: class weight per class
        """
        def __init__(self, gamma=2.0, alpha=None, reduction='mean'):
            super().__init__()
            self.gamma = gamma
            self.alpha = alpha  # Tensor of shape [C] or None
            self.reduction = reduction
        
        def forward(self, inputs, targets):
            # inputs: [N, C] logits
            # targets: [N] class labels (integer)
            p = torch.softmax(inputs, dim=1)  # [N, C]
            ce = F.cross_entropy(inputs, targets, reduction='none')  # [N]
            p_t = p.gather(1, targets.unsqueeze(1)).squeeze(1)  # [N]
            
            # Focal weight: (1 - p_t)^gamma
            focal_weight = (1 - p_t) ** self.gamma
            
            focal_loss = focal_weight * ce
            
            if self.alpha is not None:
                alpha_t = self.alpha.gather(0, targets)  # [N]
                focal_loss = alpha_t * focal_loss
            
            if self.reduction == 'mean':
                return focal_loss.mean()
            elif self.reduction == 'sum':
                return focal_loss.sum()
            return focal_loss
    
    # Dataset imbalanceado: clase 0 es 80% de los datos
    # Entrenar con CE normal va a dar un modelo biased hacia clase 0
    # Focal con gamma=2 focus en los ejemplos hard (clase minoritaria)
    
    logits = torch.randn(100, 2)  # 100 samples, 2 classes
    labels = torch.zeros(100, dtype=torch.long)
    labels[:20] = 1  # Clases 1: 20%, clase 0: 80%
    
    # CE normal
    ce_loss = F.cross_entropy(logits, labels)
    print(f"CrossEntropy loss: {ce_loss.item():.4f}")
    
    # Focal loss con gamma=2
    focal = FocalLoss(gamma=2.0)
    focal_loss = focal(logits, labels)
    print(f"Focal loss (gamma=2): {focal_loss.item():.4f}")
    
    print("\nCon gamma=2, Focal reduce el peso de ejemplos easy (alta conf)")
    print("y aumenta el foco en ejemplos hard (baja conf/confusos).")


def demo_label_smoothing():
    """Label Smoothing CrossEntropy"""
    print("=" * 60)
    print("LABEL SMOOTHING")
    print("=" * 60)
    
    class LabelSmoothingCrossEntropy(nn.Module):
        """CrossEntropy con label smoothing.
        
        y_smooth = y * (1 - eps) + eps / C
        
        Ventaja: evita overconfidence — el modelo no se backpropaga
        con gradientes infinitos cuando predice con 99.9% de certeza.
        """
        def __init__(self, epsilon=0.1):
            super().__init__()
            self.epsilon = epsilon
        
        def forward(self, inputs, targets):
            C = inputs.size(1)
            log_probs = F.log_softmax(inputs, dim=1)
            
            #targets_one_hot = F.one_hot(targets, C).float()
            # Verificar forma correcta para newer PyTorch
            targets_one_hot = torch.zeros_like(log_probs).scatter_(
                1, targets.unsqueeze(1), 1.0
            )
            
            # Label smoothing
            targets_smooth = targets_one_hot * (1 - self.epsilon) + \
                            self.epsilon / C * torch.ones_like(targets_one_hot)
            
            loss = (-targets_smooth * log_probs).sum(dim=1).mean()
            return loss
    
    # Test
    logits = torch.tensor([[4.0, 0.5, -1.0],   # Clase 0 dominante
                          [0.3, 3.5, 0.2],     # Clase 1 dominante
                          [-0.5, 0.8, 3.0]])  # Clase 2 dominante
    labels = torch.tensor([0, 1, 2])
    
    # CE con label smoothing
    criterion = LabelSmoothingCrossEntropy(epsilon=0.1)
    loss_smooth = criterion(logits, labels)
    
    # CE normal (hard labels)
    loss_hard = F.cross_entropy(logits, labels)
    
    print(f"Label smoothing (eps=0.1) loss: {loss_smooth.item():.4f}")
    print(f"Hard labels CE loss:          {loss_hard.item():.4f}")
    
    print("\nLabel smoothing es efectivo con valores 0.05-0.2.")
    print("¡NO uses valores > 0.3! Destruye el learning.")

⚠️ Errores Comunes Y Cómo Evitarlos

❌ Error 1: Usar CrossEntropy para multi-label

El problema: CrossEntropy asume que cada muestra pertenece a exactamente una clase. Si tu tarea tiene múltiples labels activos por muestra (tagging, atributos, detección de múltiples objetos), CrossEntropy va a optimizar para una sola clase y va a ignorar las demás. En producción, esto se manifiesta como recall terrible en las clases que no son la principal.

La solución: Para multi-label, usá BCEWithLogitsLoss. Cada clase se evalúa independientemente como un clasificador binario. Si necesitás multi-label con múltiples clases activas simultáneamente, esta es tu loss.

# MAL: CrossEntropy para tagging multi-label
# tags = ["gato", "pelaje_blanco", "ojos_verdes"] por imagen
logits = model(images)  # [B, num_tags]
loss = nn.CrossEntropyLoss()(logits, target_tags)  # Asume UNA clase

# BIEN: BCEWithLogitsLoss para multi-label
loss = nn.BCEWithLogitsLoss()(logits, target_tags.float())  # Cada tag como binary

❌ Error 2: No usar class weights cuando hay imbalance severo

El problema: Si tu dataset tiene una clase que aparece 20x más que otra, el modelo va a optimizarse para predecir la clase mayoritaria y va a ignorar la minoritaria. La loss no weighteada trata cada muestra igual, así que 95% de las updates van a empujar hacia la clase mayoritaria. El resultado: un modelo que dice "gato" para todo.

La solución: Calculá los class weights como la frecuencia inversa de cada clase. PyTorch lo hace directo.

# MAL: dataset con 95% clase 0, 5% clase 1
criterion = nn.CrossEntropyLoss()  # Ignora el imbalance

# BIEN: weights basados en frecuencia inversa
class_counts = torch.bincount(dataset_labels)  # [num_classes]
weights = 1.0 / class_counts.float()           # Frecuencia inversa
weights = weights / weights.sum() * len(weights)  # Normalizar
criterion = nn.CrossEntropyLoss(weight=weights)

# También podés usar la fórmula de effective samples:
# n_samples / (num_classes * count_of_class)

❌ Error 3: Label smoothing con valor muy alto (>0.3)

El problema: Label smoothing es excelente con valores 0.05-0.2 para evitar overconfidence y mejorar generalización. Pero valores >0.3 introducen too much noise en los labels, y el modelo empieza a aprender que ninguna clase es realmente correcta. En la práctica, esto destruye el learning y el modelo no converge o converge a algo mediocre. Es un error que he visto en implementaciones copiadas de internet sin entender el impacto.

La solución: Usá label smoothing con valores entre 0.05 y 0.2. Para la mayoría de los casos, 0.1 es un buen default. Si estás haciendo knowledge distillation, 0.05 es más seguro. Nunca超过 0.3.

# MAL: label smoothing con 0.5 — destruye learning
criterion = LabelSmoothingCrossEntropy(epsilon=0.5)

# BIEN: smoothing moderado — 0.1 es el sweet spot
criterion = LabelSmoothingCrossEntropy(epsilon=0.1)

# Para distillation: valores más bajos
criterion = LabelSmoothingCrossEntropy(epsilon=0.05)

💡 Tips Para Producción

  • Siempre usá BCEWithLogitsLoss en vez de BCELoss. La versión WithLogits tiene sigmoid incluida y es numéricamente más estable.
  • Calculá los class weights desde tu dataset, no los adivines. Si tu dataset cambia, los weights también.
  • Para detección de objetos (YOLO, Faster R-CNN), usá Focal Loss para manejar el foreground-background imbalance. La mayoría de las regiones de una imagen son background.
  • Monitoreá la distribución de predictions. Si tu modelo predice 99% de las muestras como una sola clase, tenés un problema de imbalance o de loss incorrecta.
  • En tareas de retrieval/embedding, considerá triplet loss o contrastive loss en vez de CrossEntropy directa. La métrica de retrieval no siempre se alinea con la clasificación.

📝 Resumen

  • CrossEntropy para clasificación multi-clase (una clase por muestra). BCE para multi-label (varias clases por muestra).
  • Class weights son obligatorios cuando hay imbalance > 3:1. No optional.
  • Focal Loss para imbalance severo y detección de objetos — focus en ejemplos hard.
  • Label smoothing con epsilon 0.05-0.2 para evitar overconfidence. Nunca > 0.3.
  • BCEWithLogitsLoss > BCELoss (más estable numéricamente).
