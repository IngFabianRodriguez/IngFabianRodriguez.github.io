Model Interpretability — LIME, SHAP Y El Arte De Explicar Lo Que No Entiende El Modelo

Hagale pues, parcero. Aquí en Colombia tenemos la tradición del "sabelotodo" — el que todo lo explica, pero cuando le preguntas por qué, no sabe. Eso mismo pasa con muchos modelos de ML: hacen predicciones increíbles pero no pueden explicar por qué. Día 212 y hoy le metemos lupa a la interpretabilidad de modelos. ¿Por qué el modelo dijo eso? SHAP y LIME nos ayudan a responder.

🎯 Por Qué La Interpretabilidad Importa

Un modelo de ML es útil cuando:

  • El cliente pregunta "¿por qué me negara el crédito?" y tienes que responder
  • El regulator pide explicabilidad del modelo para auditarla
  • Quieres debuggear por qué el modelo falla en ciertos casos
  • Necesitas confianza para tomar decisiones de alto impacto

Sin interpretabilidad, tu modelo es una caja negra que genera outputs pero no genera entendimiento.

📐 Global vs Local Interpretability

Global Interpretability

Entender el comportamiento general del modelo: ¿cuáles features son más importantes en promedio?

$$\text{Feature Importance} = \mathbb{E}[| \frac{\partial f(x)}{\partial x_j}|]$$

La importancia de una feature $j$ es el valor esperado de su gradiente absoluto a través de todas las instancias.

Local Interpretability

Entender por qué el modelo hizo una predicción específica: ¿por qué a este cliente específico le negara el crédito?

$$g(z) \approx f(x) + \sum_{i=1}^{M} \phi_i z_i$$

Donde $g$ es el modelo interpretable local, $z$ son las features simplificadas, y $\phi_i$ son las importancias locales.

🔍 SHAP — SHapley Additive exPlanations

SHAP usa la teoría de juegos para calcular la contribución de cada feature a una predicción. Se basa en Shapley values de la teoría de cooperative game theory.

$$\phi_i = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!(|F|-|S|-1)!}{|F|!} [f(S \cup \{i\}) - f(S)]$$

Donde $F$ es el conjunto de features, $S$ es un subset, y $f(S)$ es la predicción del modelo con solo las features en $S$.

import shap
import numpy as np

# Supongamos que tenemos un modelo entrenado
# model: RandomForestClassifier o cualquier modelo con .predict_proba

# Crear explainer de SHAP
# Para modelos tree-based, usar TreeExplainer
explainer = shap.TreeExplainer(model)

# Calcular SHAP values para un conjunto de datos
# Cada fila: contribution de cada feature para esa instancia
shap_values = explainer.shap_values(X_test)

# SHAP values para la primera instancia (clase positiva)
# Valores positivos empujan la predicción hacia 1
# Valores negativos empujan hacia 0
print("SHAP values para instancia 0:")
print(f"Predicción base: {explainer.expected_value:.4f}")
print(f"SHAP values: {shap_values[0]}")
print(f"Predicción final: {explainer.expected_value + shap_values[0].sum():.4f}")

def global_shap_importance(shap_values, feature_names):
    """
    Calcula importancia global de features usando |mean(SHAP values)|
    """
    # Mean absolute SHAP values por feature
    mean_abs_shap = np.abs(shap_values).mean(axis=0)
    
    # Ordenar por importancia
    indices = np.argsort(mean_abs_shap)[::-1]
    
    importance_df = pd.DataFrame({
        'feature': [feature_names[i] for i in indices],
        'mean_abs_shap': [mean_abs_shap[i] for i in indices]
    })
    
    return importance_df

# Obtener importancia global

importance_df = global_shap_importance(shap_values, feature_names)

🍋 LIME — Local Interpretable Model-agnostic Explanations

LIME explica predicciones locales construyendo un modelo interpretable simple (ej. linear regression) alrededor de la instancia a explicar, usando datos perturbados localmente.

import lime
import lime.lime_tabular

# Crear explainer de LIME para datos tabulares
explainer = lime.lime_tabular.LimeTabularExplainer(
    training_data=X_train.values,
    feature_names=feature_names,
    class_names=['Negado', 'Aprobado'],
    mode='classification'
)

# Explicar una predicción específica
instance_idx = 0
instance = X_test.iloc[instance_idx].values

explanation = explainer.explain_instance(
    instance, 
    model.predict_proba,
    num_features=len(feature_names),
    num_samples=5000  # Cuántas perturbaciones generar
)

# Mostrar en consola
print(f"Predicción: {model.predict_proba([instance])[0]}")
print(f"\nTop features que influyeron:")

# Obtener feature contributions
for feature, weight in explanation.as_list():
    direction = "↑" if weight > 0 else "↓"
    print(f"  {feature}: {weight:+.4f} {direction}")

# Visualizar
explanation.show_in_notebook()

LIME vs SHAP

  • SHAP: Teóricamente fundamentado (Shapley values), más consistente, pero más lento
  • LIME: Más flexible, funciona con cualquier modelo, pero puede ser inestable
  • Recomendación: Usa ambos. SHAP para análisis global y auditoría, LIME para explicaciones locales a usuarios

🚀 Interpretability En Producción

class InterpretableModel:
    """
    Wrapper que añade interpretabilidad a cualquier modelo sklearn.
    """
    def __init__(self, model, feature_names, mode='classification'):
        self.model = model
        self.feature_names = feature_names
        self.mode = mode
        self.explainer = None
        self._setup_explainers()
        
    def _setup_explainers(self):
        """Inicializa explainers de SHAP y LIME"""
        if hasattr(self.model, 'predict_proba'):
            # SHAP para tree-based
            try:
                self.shap_explainer = shap.TreeExplainer(self.model)
            except:
                self.shap_explainer = shap.KernelExplainer(
                    self.model.predict_proba, 
                    X_train.sample(100)
                )
            
            # LIME
            self.lime_explainer = lime.lime_tabular.LimeTabularExplainer(
                training_data=X_train.values,
                feature_names=self.feature_names,
                mode=self.mode
            )
    
    def explain_prediction(self, instance, method='both'):
        """
        Genera explicación para una predicción específica.
        
        Args:
            instance: DataFrame o array con features de una instancia
            method: 'shap', 'lime', o 'both'
            
        Returns:
            dict con explicaciones
        """
        result = {}
        
        if method in ['shap', 'both']:
            # SHAP values
            if isinstance(instance, pd.DataFrame):
                instance_arr = instance.values
            else:
                instance_arr = instance.reshape(1, -1)
            
            shap_vals = self.shap_explainer.shap_values(instance_arr)
            
            # Para clasificación, tomar clase positiva
            if isinstance(shap_vals, list):
                shap_vals = shap_vals[1]
                
            result['shap'] = {
                'values': shap_vals[0] if len(shap_vals.shape) > 1 else shap_vals,
                'base_value': self.shap_explainer.expected_value,
                'feature_contributions': dict(zip(
                    self.feature_names, 
                    shap_vals[0] if len(shap_vals.shape) > 1 else shap_vals
                ))
            }
        
        if method in ['lime', 'both']:
            # LIME explanation
            if isinstance(instance, pd.DataFrame):
                instance_arr = instance.values[0]
            else:
                instance_arr = instance
                
            lime_exp = self.lime_explainer.explain_instance(
                instance_arr, 
                self.model.predict_proba,
                num_features=len(self.feature_names)
            )
            
            result['lime'] = {
                'as_list': lime_exp.as_list(),
                'prediction': self.model.predict_proba([instance_arr])[0]
            }
        
        return result
    
    def generate_fairness_report(self, X, sensitive_features):
        """
        Genera reporte de fairness con interpretabilidad.
        """
        predictions = self.model.predict(X)
        proba = self.model.predict_proba(X)[:, 1]
        
        report = {
            'overall': {
                'approval_rate': predictions.mean(),
                'mean_score': proba.mean()
            }
        }
        
        # Por grupo sensible
        for feat in sensitive_features:
            report[feat] = {}
            for group in X[feat].unique():
                mask = X[feat] == group
                report[feat][group] = {
                    'approval_rate': predictions[mask].mean(),
                    'mean_score': proba[mask].mean(),
                    'count': mask.sum()
                }
        
        return report

# Uso en producción
model_wrapper = InterpretableModel(credit_model, feature_names, mode='classification')

# Explicar decisión para un cliente
cliente = X_test.iloc[0:1]
explanation = model_wrapper.explain_prediction(cliente)

⚠️ Los 3 Errores Más Costosos

Error 1: Usar SHAP Sin Entender Los Assumptions Del Método

El problema: SHAP tiene assumptions que si no conoces, puedes interpretar mal los resultados. Por ejemplo, KernelSHAP no es exacto, es un estimador. Y TreeExplainer solo funciona para modelos tree-based.

La solución: Lee la paper original de Lundberg & Lee (2017). Entiende qué tipo de SHAP necesitas para tu modelo. TreeExplainer para XGBoost/RandomForest, KernelExplainer para redes neuronales.

# Elegir el SHAP explainer correcto según el modelo
def get_shap_explainer(model, X_background=None):
    """
    Selecciona el SHAP explainer apropiado según el tipo de modelo.
    """
    model_type = type(model).__name__
    
    if 'tree' in model_type.lower():
        print(f"Usando TreeExplainer para {model_type}")
        return shap.TreeExplainer(model)
    elif 'linear' in model_type.lower():
        print(f"Usando LinearExplainer para {model_type}")
        return shap.LinearExplainer(model, X_background)
    elif 'kernel' in model_type.lower():
        print(f"Usando KernelExplainer (fallback genérico)")
        return shap.KernelExplainer(model.predict, X_background)
    else:
        # Para redes neuronales, deep learning
        print(f"Usando KernelExplainer para {model_type}")
        return shap.KernelExplainer(model.predict, X_background)

Error 2: Local Explanation Que No Generaliza A Global Behavior

El problema: "Este feature es importante para esta instancia, entonces es importante siempre". Falso. Una explicación local puede ser muy diferente del comportamiento global del modelo.

La solución: Siempre combina análisis local con global. Un feature puede ser crucial para predecir un caso específico pero irrelevante en general.

Error 3: Interpretability Como Afterthought En Vez De Diseño Desde El Inicio

El problema: "Ya entrenamos el modelo, ahora le metemos SHAP para el reporte". Si la interpretabilidad es opcional, el modelo probablemente no fue diseñado para ser interpretable.

La solución: Diseña tu pipeline pensando en interpretabilidad desde el día 1. Usa features que sean interpretables, documenta decisiones, y genera explicaciones como parte del output del modelo.

# Diseño correcto: interpretabilidad desde el inicio
class InterpretablePipeline:
    """
    Pipeline que garantiza interpretabilidad desde el diseño.
    """
    def __init__(self):
        self.preprocessor = None
        self.model = None
        self.explainer = None
        self.feature_names = None
        
    def fit(self, X, y):
        # 1. Features interpretables
        # No usar embeddings opacos sin forma de revertirlos
        # No usar transformaciones que pierdan significado
        self.preprocessor = StandardScaler()  # Interpretable scaling
        X_processed = self.preprocessor.fit_transform(X)
        
        # 2. Modelo interpretable cuando sea posible
        # Si necesitas black box, al menos usa tree-based
        # No usos redes neuronales profundas si no es necesario
        self.model = GradientBoostingClassifier(
            n_estimators=100,
            max_depth=5,  # No muy profundo para mantener interpretabilidad
        )
        self.model.fit(X_processed, y)
        
        # 3. Setup explainer
        self.feature_names = X.columns.tolist()
        self.explainer = shap.TreeExplainer(self.model)
        
        return self
    
    def predict_with_explanation(self, X):
        """
        Retorna predicción Y explicación simultáneamente.
        """
        X_processed = self.preprocessor.transform(X)
        prediction = self.model.predict(X_processed)
        shap_values = self.explainer.shap_values(X_processed)
        
        # Construir explicación legible
        explanations = []
        for i, (pred, shap_val) in enumerate(zip(prediction, shap_values)):
            top_features = sorted(
                zip(self.feature_names, shap_val),
                key=lambda x: abs(x[1]),
                reverse=True
            )[:5]
            
            explanations.append({
                'prediction': pred,
                'top_features': top_features
            })
        
        return prediction, explanations

📝 Resumen

  • Global interpretability: feature importance promediada sobre todo el dataset
  • Local interpretability: por qué una predicción específica
  • SHAP: fundamentos teóricos sólidos (Shapley values), ideal para auditoría
  • LIME: flexible, modelo-agnostic, ideal para explicaciones a usuarios
  • Feature importance plots: visualizan contribución de features
  • Diseño desde el inicio: interpretabilidad no es optional
