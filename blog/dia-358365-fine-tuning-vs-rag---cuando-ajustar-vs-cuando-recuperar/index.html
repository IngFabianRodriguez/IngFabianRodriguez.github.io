LLM Architectures 2026 II — Open Source vs Proprietary

Hagale pues, parcero. Día 358 y hoy le metemos la segunda parte de nuestro deep dive en arquitecturas LLM. Si ayer hablamos destate of the art y quiénes lideran, hoy nos metemos de lleno en la pelea quedefine 2026: ¿open source o proprietary? Y más importante: ¿qué viene despues? Quédate que esto está interesante.

spoiler: la respuesta correcta no es "open source es mejor" ni "proprietary es mejor". La respuesta correcta es "depende de tu contexto". Y hoy vas a saber exactamente cómo hacer ese análisis.

⚔️ La Guerra Open Source vs Proprietary en 2026

Hace 3 años la discusión era sencilla: los modelos proprietary ganaban en capability por un margen enorme, y la unica razón para usar open source era si tenías constraints de privacy o no podías pagar la API. En 2026 esa historia cambió dramáticamente.

La brecha se cerró:

  • Llama 4 Sovereign (open source) vs GPT-4o Max (proprietary): en reasoning general, la diferencia es marginal — dentro del margen de error estadístico en la mayoría de benchmarks
  • DeepSeek V3 (open source, chino) vs Claude 4 Opus: en matemáticas y código, DeepSeek a veces outperforma, a un fracción del costo
  • Modelos open source de 7B-13B ahora equalan a GPT-3.5-turbo de 2023 en la mayoría de tareas

"En 2026 el verdadero tradeoff ya no es capability vs costo — es control vs conveniencia. Y esa es una decisión de negocio, no de ingeniería."

  • Perplexity AI: No es modelo base pero es un sistema completo de búsqueda aumentada. Destruyó el modelo de búsqueda tradicional.

🧮 La Matemática de la Decisión

Vamos a la matemática real. El costo total de ownership (TCO) de un modelo no es solo el costo de API:

$$\text{TCO} = C_{\text{inference}} + C_{\text{infrastructure}} + C_{\text{operations}} + C_{\text{switching risk}}$$

Desglosemos cada componente:

1. Costo de Inference

Para modelos proprietary:

$$C_{\text{inference}} = \text{price per 1M tokens} \times \text{volume monthly (M tokens)}$$

Para modelos open source, el cálculo cambia:

$$C_{\text{inference}} = (\text{GPU hours} \times \text{cost per GPU hour}) + \text{networking} + \text{storage}$$

Ejemplo numérico:

  • GPT-4o Max: 100M tokens/mes × $15/1M = $1,500/mes
  • DeepSeek V3 desplegado en vLLM en 2xH100 ($2.5/GPU/hr): ~$600/mes para el mismo volume con optimizaciones
  • Ahorro potencial: $900/mes = $10,800/año

2. Costo de Infrastructure

Solo aplica para open source (desplegado en tus GPUs o en la nube):

# Calculo de infrastructure para modelo open source
def calculate_infrastructure_cost(
    model_params_billions: float,
    quantización: str,  # 'fp16', 'int8', 'int4'
    monthly_tokens_m: float,
    gpu_model: str = "H100",  # o "A100", "H200"
    gpu_cost_per_hour: float = 2.5,
):
    # Rough estimation: 1B params ≈ 2GB en fp16
    memory_fp16_tb = model_params_billions * 2 / 1000
    
    # GPUs necesarias (H100 tiene 80GB por GPU)
    gpus_needed = max(1, int(memory_fp16_tb / 80))
    
    # Throughput estimado (tokens/seg por GPU, aproximada)
    throughput_per_gpu = {
        "7b": 150, "13b": 80, "34b": 35, "70b": 20, "400b": 5
    }
    
    # Latency vs throughput tradeoff
    # Mas GPUs = mayor throughput pero igual latencia por query
    
    # horas de GPU al mes (asumiendo 30 dias, 24 hrs)
    hours_per_month = 30 * 24
    
    # Calculate tokens processed per month with this setup
    tokens_per_second_total = throughput_per_gpu[f"{model_params_billions}b"] * gpus_needed
    tokens_per_month = tokens_per_second_total * hours_per_month * 3600 / 1_000_000  # M tokens
    
    # Si el volumen excede la capacidad, necesitas mas GPUs o mas horas
    gpu_months_needed = monthly_tokens_m / (tokens_per_month / gpus_needed)
    
    cost = gpus_needed * gpu_months_needed * gpu_cost_per_hour * hours_per_month
    
    return {
        "gpus_needed": gpus_needed,
        "gpu_hours_per_month": gpu_months_needed * hours_per_month,
        "monthly_cost": cost,
        "cost_per_1m_tokens": cost / monthly_tokens_m
    }

3. Costo de Operations

Este es el costo que la mayoría ignora:

  • DevOps/SRE: 0.5-1 FTE para mantener infraestructura de modelos
  • Prompt engineering: Los modelos open source a veces requieren más iterations
  • Fine-tuning pipeline: Si necesitas adaptar el modelo, requiere expertise adicional
  • Monitoring y debugging: Sin dashboard tipo OpenAI/Anthropic, tienes que construirlo

$$\text{C}_{\text{operations}} = \text{salary}_\text{infra} \times \text{FTE allocation} + \text{tools} + \text{onboarding}$$

4. Costo de Switching Risk

Este es el más difícil de cuantificar pero quizás el más importante:

  • Vendor lock-in: proprietary = dependes del provider
  • Deprecation risk: Modelos se deprecated. OpenAI deprecated GPT-3.5 hace poco.
  • Performance regression: Si el provider cambia el modelo sin notice (que pasa)
  • Compliance risk: Si tus datos van a terceros

"""
Open Source vs Proprietary Decision Framework

Framework para decidir entre modelos open source y proprietary
basado en requirements específicos de la organización.

from dataclasses import dataclass
from typing import List, Dict, Optional, Tuple
from enum import Enum
import json


class DeploymentType(Enum):
    API_PROPRIETARY = "api_proprietary"
    SELF_HOSTED_OPEN_SOURCE = "self_hosted_open_source"
    MANAGED_OPEN_SOURCE = "managed_open_source"  # Replicate, Modal, etc.


@dataclass
class CostBreakdown:
    """Desglose completo de costos."""
    inference_monthly: float
    infrastructure_monthly: float
    operations_monthly: float
    switching_risk_annual: float  # Valor monetario del riesgo
    
    @property
    def total_monthly(self) -> float:
        return self.inference_monthly + self.infrastructure_monthly + self.operations_monthly
    
    @property
    def total_annual(self) -> float:
        return self.total_monthly * 12 + self.switching_risk_annual


@dataclass  
class OrgRequirements:
    """Requisitos de la organización."""
    monthly_tokens_m: float = 1000  # Millones de tokens por mes
    max_latency_p95_ms: float = 2000  # Latencia máxima aceptable
    required_context_window: int = 32_000
    must_support_multimodal: bool = False
    must_support_function_calling: bool = True
    data_residency: Optional[str] = None  # "EU", "US", "APAC"
    has_internal_ml_team: bool = True
    ml_team_size: int = 5
    compliance_required: List[str] = None  # ["GDPR", "HIPAA", "SOC2"]
    max_monthly_budget: float = 10_000  # USD
    can_use_cloud_gpus: bool = True
    has_on_prem_gpus: bool = False


@dataclass
class ModelComparison:
    """Resultado de comparación para un modelo específico."""
    model_name: str
    deployment_type: DeploymentType
    cost_breakdown: CostBreakdown
    capability_score: float  # 0-100
    latency_score: float  # 0-100
    compliance_score: float  # 0-100
    operational_complexity: float  # 0-10 (10 = muy complejo)
    overall_score: float  # Weighted combination
    
    def __str__(self):
        return f"""
{self.model_name}
{'='*50}

Costo anual: ${self.cost_breakdown.total_annual:.2f}

Latency: {self.latency_score}/100  
Compliance: {self.compliance_score}/100
Complejidad operacional: {self.operational_complexity}/10
OVERALL: {self.overall_score}/100
"""

def calculate_open_source_cost(
    model_name: str,
    model_spec: Dict,
    requirements: OrgRequirements,
    gpu_cost_per_hour: float = 2.5,  # H100 on-demand
) -> CostBreakdown:
    """Calcula el costo total para un modelo open source."""
    
    spec = model_spec
    params_b = spec["params_billions"]
    
    # 1. Inference cost (GPU infrastructure)
    # Memory needed: ~2 bytes per param in fp16
    memory_tb_fp16 = params_b * 2 / 1000
    
    # GPU memory: H100 = 80GB, A100 = 40GB (use H100 for large models)
    gpu_memory_gb = 80 if gpu_cost_per_hour >= 2.0 else 40
    gpus_needed = max(1, int(memory_tb_fp16 * 1000 / gpu_memory_gb))
    
    # Quantization reduces memory by 2-4x, allowing fewer GPUs
    # int4 ≈ 4x reduction, int8 ≈ 2x reduction
    gpus_needed_int8 = max(1, gpus_needed // 2)
    gpus_needed_int4 = max(1, gpus_needed // 4)
    
    # Throughput calculation
    tokens_per_sec_per_gpu = spec["throughput_tokens_per_sec_per_gpu"]
    
    # Calculate hours needed to process monthly tokens
    tokens_per_month = requirements.monthly_tokens_m * 1_000_000
    tokens_per_second_needed = tokens_per_month / (30 * 24 * 3600)
    
    # With current GPU setup
    tokens_per_second_available = tokens_per_sec_per_gpu * gpus_needed
    gpu_hours_per_month = (tokens_per_second_needed / tokens_per_second_available) * 30 * 24
    
    # Always-on cost vs burst cost
    # Assume always-on for production
    gpu_hours_per_month = gpus_needed * 30 * 24  # Always-on
    
    infrastructure_monthly = gpus_needed * gpu_hours_per_month * gpu_cost_per_hour
    
    # If using int8/int4 quantization, fewer GPUs needed
    # For simplicity, using fp16 costs here
    
    # 2. Operations cost
    if requirements.has_internal_ml_team:
        # Estimate FTE allocation to this model
        fte_allocation = 0.2  # 20% of 1 engineer
        infra_engineer_monthly = (120_000 / 12) * fte_allocation
    else:
        # Need to hire or use managed service
        infra_engineer_monthly = 500  # Managed service overhead
    
    operations_monthly = infra_engineer_monthly
    
    # 3. Inference cost (actually 0 for open source, just GPU)
    inference_monthly = 0
    
    # 4. Switching risk (lower for open source)
    switching_risk_annual = 1000  # Bajo riesgo de vendor lock-in
    
    return CostBreakdown(
        inference_monthly=inference_monthly,
        infrastructure_monthly=infrastructure_monthly,
        operations_monthly=operations_monthly,
        switching_risk_annual=switching_risk_annual
    )


def calculate_proprietary_cost(
    model_name: str,
    model_spec: Dict,
    requirements: OrgRequirements,
) -> CostBreakdown:
    """Calcula el costo total para un modelo proprietary."""
    
    # 1. Inference cost
    inference_monthly = requirements.monthly_tokens_m * model_spec["cost_per_1m_tokens"]
    
    # 2. Infrastructure (minimal - just API calls)
    infrastructure_monthly = 0
    
    # 3. Operations (lower for proprietary - managed service)
    if requirements.has_internal_ml_team:
        # Less infra work, more prompt engineering
        fte_allocation = 0.1  # 10% of 1 engineer
        operations_monthly = (120_000 / 12) * fte_allocation
    else:
        operations_monthly = 0
    
    # 4. Switching risk (HIGHER for proprietary)
    # Risk of API changes, deprecation, price increases
    switching_risk_annual = inference_monthly * 12 * 0.15  # 15% risk premium
    
    return CostBreakdown(
        inference_monthly=inference_monthly,
        infrastructure_monthly=infrastructure_monthly,
        operations_monthly=operations_monthly,
        switching_risk_annual=switching_risk_annual
    )


def compare_models(requirements: OrgRequirements) -> List[ModelComparison]:
    """Compara todos los modelos relevantes para los requisitos dados."""
    
    results = []
    
    # Evaluate proprietary models
    for model_name, model_spec in PROPRIETARY_MODELS.items():
        # Filter by requirements
        if requirements.required_context_window > model_spec["context_window"]:
            continue
        if requirements.must_support_multimodal and not model_spec["multimodal"]:
            continue
        if requirements.must_support_function_calling and not model_spec.get("function_calling"):
            continue
        if requirements.data_residency:
            # Check compliance
            if requirements.data_residency == "EU" and "GDPR" not in model_spec.get("compliance", []):
                continue
        
        costs = calculate_proprietary_cost(model_name, model_spec, requirements)
        
        comparison = ModelComparison(
            model_name=model_name,
            deployment_type=DeploymentType.API_PROPRIETARY,
            cost_breakdown=costs,
            capability_score=85,  # Based on benchmarks
            latency_score=80,
            compliance_score=90,
            operational_complexity=2,  # Low - managed service
            overall_score=0  # Calculate below
        )
        
        # Calculate overall score
        # Higher cost = lower score
        cost_score = max(0, 100 - (costs.total_monthly / requirements.max_monthly_budget) * 100)
        comparison.overall_score = (
            0.3 * comparison.capability_score +
            0.2 * comparison.latency_score +
            0.2 * (100 - comparison.operational_complexity * 10) +
            0.3 * cost_score
        )
        
        results.append(comparison)
    
    # Evaluate open source models
    for model_name, model_spec in OPEN_SOURCE_MODELS.items():
        # Filter by requirements
        if requirements.required_context_window > model_spec["context_window"]:
            continue
        if requirements.must_support_multimodal and not model_spec["multimodal"]:
            continue
        if requirements.must_support_function_calling and not model_spec.get("function_calling"):
            continue
        
        # Check if can deploy (has team or can use managed)
        if not requirements.has_internal_ml_team and not requirements.can_use_cloud_gpus:
            continue
        
        costs = calculate_open_source_cost(model_name, model_spec, requirements)
        
        # Calculate overall score
        cost_score = max(0, 100 - (costs.total_monthly / requirements.max_monthly_budget) * 100)
        capability_score = 80  # Open source slightly behind proprietary generally
        
        comparison = ModelComparison(
            model_name=model_name,
            deployment_type=DeploymentType.SELF_HOSTED_OPEN_SOURCE,
            cost_breakdown=costs,
            capability_score=capability_score,
            latency_score=75,  # Depends on infrastructure
            compliance_score=95,  # Full control over data
            operational_complexity=8 if requirements.has_internal_ml_team else 6,
            overall_score=0
        )
        
        comparison.overall_score = (
            0.3 * comparison.capability_score +
            0.2 * comparison.latency_score +
            0.2 * (100 - comparison.operational_complexity * 10) +
            0.3 * cost_score
        )
        
        results.append(comparison)
    
    # Sort by overall score
    results.sort(key=lambda x: x.overall_score, reverse=True)
    return results

⚠️ Los 3 Errores Más Comunes (y Sus Fixes)

Error 1: No Entender la Diferencia Real — "Open Source es Siempre Más Barato"

El problema: Asumir que open source = gratis o mucho más barato. Esto ignora los costos de infrastructure y operations que pueden make open source MORE expensive en ciertos escenarios.

La matemática real:

Para volúmenes bajos (< 100M tokens/mes), proprietary suele ser más económico porque no tienes que pay for idle GPUs. La formula del break-even point:

$$\text{Break-even tokens/mes} = \frac{C_{\text{gpu monthly}} + C_{\text{ops monthly}}}{C_{\text{proprietary per 1M}}}$$

Para un setup típico de 2xH100 ($1,200/mes GPU) + ops ($1,000/mes), con GPT-4o a $15/1M tokens:

$$\text{Break-even} = \frac{2200}{15} = 147M \text{ tokens/mes}$$

Debajo de 147M tokens/mes, proprietary es más barato. Encima, open source gana.

El fix:

# Decision framework con break-even analysis
BREAK_EVEN_ANALYSIS = {
    "gpt-4o_max": {
        "cost_per_1m": 15.0,
        "break_even_2x_h100": "147M tokens/mes",
        "break_even_1x_h100": "74M tokens/mes",
    },
    "claude-4-opus": {
        "cost_per_1m": 18.0,
        "break_even_2x_h100": "122M tokens/mes",
    },
    "gemini-2-ultra": {
        "cost_per_1m": 7.0,
        "break_even_2x_h100": "314M tokens/mes",  # Open source needs bigger savings
    }
}

def should_go_open_source(volume_monthly_mtokens, model_choice="gpt-4o_max"):
    """
    Returns (decision, reasoning, savings)
    """
    # Get break-even point
    break_even = float(BREAK_EVEN_ANALYSIS[model_choice]["break_even_2x_h100"].replace("M tokens/mes", ""))
    
    if volume_monthly_mtokens < break_even:
        return ("proprietary", 
                f"Volume {volume_monthly_mtokens}M below break-even {break_even}M",
                0)
    
    # Calculate savings
    gpu_monthly = 1200  # 2x H100
    ops_monthly = 1000
    open_source_monthly = gpu_monthly + ops_monthly
    
    proprietary_monthly = volume_monthly_mtokens * BREAK_EVEN_ANALYSIS[model_choice]["cost_per_1m"]
    
    savings = proprietary_monthly - open_source_monthly
    
    return ("open_source",
            f"Volume {volume_monthly_mtokens}M above break-even {break_even}M",
            savings)

Error 2: No Tomar Decisiones Informadas — "Usemos lo que el Competitor Usa"

El problema: Copiar lo que hace la competencia sin analizar si sus constraints son iguales a los tuyos. Tu competitor puede tener:

  • Un team de 50 ML engineers (tú tienes 3)
  • Un budget 10x mayor
  • Restricciones de compliance completamente diferentes
  • Métricas de éxito distintas

El fix:

# Requirements-driven decision, not competitor-driven
def decision_by_requirements(org_profile):
    """
    Org profile incluye:
    - team_size, team_skill_level
    - monthly_budget, volume_estimate
    - compliance_needs, latency_requirements
    - data_sensitivity
    """
    
    # Si es early stage (< 6 meses runway)
    if org_profile["runway_months"] < 6:
        return "proprietary", "Minimize distraction, focus on product"
    
    # Si tiene team pequeño sin infra expertise
    if org_profile["team_size"] < 3 or org_profile["infra_skill"] == "low":
        if org_profile["volume_monthly_mtokens"] < 100:
            return "proprietary", "No justification for infra complexity"
    
    # Si tiene compliance requirements estrictos (GDPR, HIPAA)
    if org_profile["compliance"] and "EU" in org_profile["compliance"]:
        if org_profile["data_sensitivity"] == "high":
            return "open_source_self_hosted", "Cannot send EU citizen data to third parties"
    
    # Si el volume es alto y tiene team capability
    if org_profile["volume_monthly_mtokens"] > 500 and org_profile["team_size"] >= 5:
        if org_profile["infra_skill"] in ["medium", "high"]:
            return "open_source", f"Saving ${calculate_savings(org_profile)}/year"
    
    # Default to proprietary if unsure
    return "proprietary", "Safer default, switch when justified"

Error 3: Seguir Trends Sin Análisis — "Todos Están yendo a Llama, Hagamos lo Mismo"

El problema: El hype de Twitter no es estrategia. En 2025 hubo un migration masiva a Llama cuando salió Llama 3. Muchas empresas migraron sin analysis adecuada y ended up con:

  • Modelos que no cumplían sus latency requirements
  • Teams sin expertise para fine-tune o debuggear
  • Costos de operations que no habían calculado
  • Compliance issues (data residency, IP)

La fórmula correcta para decisiones:

$$\text{Decision} = f(\text{requirements}, \text{constraints}, \text{capabilities})$$

NO:

$$\text{Decision} = f(\text{twitter\_trends})$$

El fix:

# Framework anti-hype para selección de modelos
def evaluate_model_choice(
    proposed_model: str,
    actual_requirements: Dict,
) -> Tuple[bool, str]:
    """
    Evalúa si la elección de modelo está justificada.
    Returns (is_justified, reasoning)
    """
    issues = []
    
    # Check 1: ¿Cumple los requisitos hard?
    if actual_requirements["min_context"] > MODELS[proposed_model]["context"]:
        issues.append(f"Context {actual_requirements['min_context']} exceeds model capacity")
    
    if actual_requirements["needs_multimodal"] and not MODELS[proposed_model]["multimodal"]:
        issues.append("Model doesn't support multimodal but requirement is true")
    
    # Check 2: ¿Tienes el team para manejarlo?
    if is_open_source(proposed_model):
        if actual_requirements["team_infra_skill"] < 6:  # Scale of 1-10
            issues.append(f"Team infra skill {actual_requirements['team_infra_skill']}/10 insufficient for open source deployment")
    
    # Check 3: ¿El costo está justificado?
    monthly_cost = estimate_monthly_cost(proposed_model, actual_requirements["volume_m_tokens"])
    if monthly_cost > actual_requirements["max_budget"]:
        issues.append(f"Monthly cost ${monthly_cost} exceeds budget ${actual_requirements['max_budget']}")
    
    if issues:
        return False, "Issues found: " + "; ".join(issues)
    
    return True, "Model meets all requirements"
