Métricas de Evaluación: El Problema de Medir Qualité

Mano, hoy vamos a hablar de algo que el 85% de la gente que trabaja con LLMs no entiende bien: cómo demonios medir si tu modelo está funcionando bien o no. Y no, no es simplemente preguntar "¿te parece bien?" y ya.

En Colombia decimos que "lo que no se mide, no se mejora". Y en el mundo de los LLMs, esto es más cierto que nunca. Si no sabes qué métricas usar, estás básicamente volando a ciegas cuando decides si tu modelo mejoró o empeoró después de un cambio.

Por Qué Una Sola Métrica No Es Suficiente

El error más común es decir "vamos a usar BLEU score" y punto. Error fatal. Cada métrica tiene limitaciones, y si solo usas una, estás ignorando aspectos importantes de la calidad. Necesitas un portfolio de métricas que se complementen.

Vamos a ver las métricas más importantes y cómo implementarlas, incluyendo cómo diseñar las tuyas propias cuando las existentes no sirven.

BLEU Score: El Clásico de NLP

Qué Es y Cómo Funciona

BLEU (Bilingual Evaluation Understudy) fue propuesto por Google en 2002 para evaluar traducciones automáticas. Mide la precisión de n-gramas entre el texto generado y referencias humanas.

La fórmula básica de precisión de n-gramas:

Precision_n = (n-gramas en común con refs) / (total de n-gramas en output)

BLEU usa precisión modificada con penalización por brevedad (brevity penalty):

BLEU = BP * exp(sum_{n=1 to N} w_n * log(precision_n))

Donde BP = min(1, |output| / |ref_más_cercana|)

from collections import Counter
import math

def modified_precision(candidate: str, reference: str, n: int) -> float:
    """
    Calcula precisión modificada para n-gramas.
    Cuenta cuántas veces aparece cada n-grama en el candidato
    vs. el máximo que aparece en cualquier referencia.
    """
    cand_ngrams = Counter(ngrams(candidate, n))
    ref_ngrams = Counter(ngrams(reference, n))
    
    numerator = 0
    denominator = 0
    
    for ngram, count in cand_ngrams.items():
        numerator += min(count, ref_ngrams.get(ngram, 0))
        denominator += count
    
    return numerator / denominator if denominator > 0 else 0

def ngrams(text: str, n: int):
    """Genera n-gramas de un texto."""
    tokens = text.split()
    return tuple(tokens[i:i+n] for i in range(len(tokens) - n + 1))

def brevity_penalty(candidate: str, reference: str) -> float:
    """
    Penaliza outputs más cortos que la referencia.
    Si el candidato es más largo, no hay penalización.
    """
    c_len = len(candidate.split())
    r_len = len(reference.split())
    
    if c_len > r_len:
        return 1.0
    elif c_len == 0:
        return 0.0
    else:
        return math.exp(1 - r_len / c_len)

def bleu_score(candidate: str, reference: str, weights=(0.25, 0.25, 0.25, 0.25)) -> float:
    """
    Calcula BLEU score con pesos para 1-gram a 4-gram.
    Por defecto usa pesos uniformes.
    """
    precisions = []
    for i, w in enumerate(weights, 1):
        if i > 4:
            break
        p = modified_precision(candidate, reference, i)
        precisions.append(p)
    
    # Si alguna precisión es 0, BLEU es 0
    if any(p == 0 for p in precisions):
        return 0.0
    
    log_precisions = [math.log(p) for p in precisions]
    geometric_mean = math.exp(sum(w * lp for w, lp in zip(weights, log_precisions)))
    bp = brevity_penalty(candidate, reference)
    
    return geometric_mean * bp

# Ejemplo de uso
ref = "El gato está sentado sobre la mesa."
cand = "El gato está en la mesa."

print(f"BLEU: {bleu_score(cand, ref):.4f}")

Limitaciones de BLEU

  • No captura semántica: "El perro persigue al gato" y "El gato es perseguido por el perro" tienen BLEU bajo pero son semánticamente equivalentes
  • Sensible a tokens exactos: variaciones de puntuación o mayúsculas afectan el score
  • No funciona bien para generación creativa: traduce bien pero mal para resúmenes o chat

ROUGE Score: Recall-Oriented

Qué Es y Por Qué Importa

ROUGE (Recall-Oriented Understudy for Gisting Evaluation) mide recall: qué tanto del texto de referencia aparece en el output generado. A diferencia de BLEU que mide precisión.

Las variantes principales:

  • ROUGE-N: overlap de n-gramas (similar a BLEU pero recall)
  • ROUGE-L: longest common subsequence
  • ROUGE-S: skip-bigram co-occurrence
def rouge_n(candidate: str, reference: str, n: int = 1) -> float:
    """
    ROUGE-N: fracción de n-gramas de referencia que aparecen en candidato.
    Mide recall, no precisión.
    """
    cand_ngrams = Counter(ngrams(candidate, n))
    ref_ngrams = Counter(ngrams(reference, n))
    
    overlap = sum(min(cand_ngrams.get(ng, 0), ref_ngrams[ng]) for ng in ref_ngrams)
    total_ref = sum(ref_ngrams.values())
    
    return overlap / total_ref if total_ref > 0 else 0.0

def lcs_length(s1: str, s2: str) -> int:
    """Longest common subsequence - algorithm."""
    m, n = len(s1), len(s2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    
    return dp[m][n]

def rouge_l(candidate: str, reference: str) -> float:
    """
    ROUGE-L: longest common subsequence ratio.
    Captura estructura de secuencias.
    """
    ref_tokens = reference.split()
    cand_tokens = candidate.split()
    
    lcs = lcs_length(ref_tokens, cand_tokens)
    
    return (2 * lcs) / (len(ref_tokens) + len(cand_tokens)) if (len(ref_tokens) + len(cand_tokens)) > 0 else 0.0

def rouge_s(candidate: str, reference: str) -> float:
    """
    ROUGE-S: skip-bigram co-occurrence.
    Permite gaps entre palabras (ordén parcial).
    """
    def skip_bigrams(tokens):
        return [(tokens[i], tokens[j]) for i in range(len(tokens)) for j in range(i+1, len(tokens))]
    
    cand_sb = set(skip_bigrams(candidate.split()))
    ref_sb = set(skip_bigrams(reference.split()))
    
    overlap = len(cand_sb & ref_sb)
    total_ref = len(ref_sb)
    
    return overlap / total_ref if total_ref > 0 else 0.0

# Ejemplo de uso
ref = "El gato está sentado sobre la mesa."
cand = "El gato está en la mesa."

print(f"ROUGE-1: {rouge_n(cand, ref, 1):.4f}")
print(f"ROUGE-2: {rouge_n(cand, ref, 2):.4f}")
print(f"ROUGE-L: {rouge_l(cand, ref):.4f}")
print(f"ROUGE-S: {rouge_s(cand, ref):.4f}")

METEOR: La Evolución de BLEU

METEOR (Metric for Evaluation of Translation with Explicit ORdering) aborda varias limitaciones de BLEU:

  • Usa sinónimos via WordNet
  • Alignment más flexible: permite mappings no contiguos
  • Combina precisión y recall
# Versión simplificada de METEOR
# La versión completa usa WordNet para sinónimos y stemming

def meteor_score(candidate: str, reference: str, stemming: bool = False) -> float:
    """
    METEOR simplificado: combinación de precisión y recall con alignment.
    """
    cand_tokens = candidate.lower().split()
    ref_tokens = reference.lower().split()
    
    # Alignment con tolerancia a reordenamiento
    aligned = []
    ref_used = [False] * len(ref_tokens)
    cand_used = [False] * len(cand_tokens)
    
    # Unigrams alignment (greedy, mejor match primero)
    for c_idx, c_tok in enumerate(cand_tokens):
        best_match = None
        best_r_idx = None
        for r_idx, r_tok in enumerate(ref_tokens):
            if not ref_used[r_idx]:
                if c_tok == r_tok:  # Match exacto
                    best_match = c_tok
                    best_r_idx = r_idx
                    break
        if best_match:
            aligned.append((c_tok, r_idx))
            cand_used[c_idx] = True
            ref_used[r_idx] = True
    
    # Calcular precisión y recall
    matches = len(aligned)
    precision = matches / len(cand_tokens) if cand_tokens else 0
    recall = matches / len(ref_tokens) if ref_tokens else 0
    
    if precision + recall == 0:
        return 0.0
    
    f_mean = 10 * precision * recall / (recall + 25 * precision)
    
    # Penalty por fragmentación (how jumbled the alignment is)
    penalty = 0.5 * (len(aligned) / len(cand_used)) ** 3 if aligned else 0
    
    return f_mean * (1 - penalty)

# Ejemplo
print(f"METEOR: {meteor_score(cand, ref):.4f}")

BERTScore: La Revolución Contextual

Por Qué Es Diferente

BLEU y ROUGE usan coincidencia literal de tokens. BERTScore usa embeddings contextuales de BERT para capturar significado, no solo texto exacto. Esto resuelve el mayor problema de las métricas tradicionales.

BERTScore calcula similaridad coseno entre cada token del candidato y su mejor matching token en la referencia:

BERTScore = cos(embed(cand_i), embed(ref_j))

# Versión conceptual de BERTScore
# En producción usar: pip install bert-score

import numpy as np

def bert_score_simplified(candidate: str, reference: str, embeddings: dict) -> dict:
    """
    BERTScore simplificado usando embeddings pre-computados.
    En producción, usaríamos BERT real para embeddings contextuales.
    
    Args:
        candidate: texto generado
        reference: texto de referencia
        embeddings: dict de word -> embedding vector
    """
    cand_tokens = candidate.lower().split()
    ref_tokens = reference.lower().split()
    
    # Obtener embeddings (silently skip OOV)
    cand_embs = [embeddings.get(t) for t in cand_tokens if t in embeddings]
    ref_embs = [embeddings.get(t) for t in ref_tokens if t in embeddings]
    
    if not cand_embs or not ref_embs:
        return {"precision": 0.0, "recall": 0.0, "f1": 0.0}
    
    # Para cada token del candidato, encontrar el max similarity en referencia
    def max_sim_cosine(emb, ref_embs):
        max_sim = 0
        for ref_emb in ref_embs:
            sim = np.dot(emb, ref_emb) / (np.linalg.norm(emb) * np.linalg.norm(ref_emb) + 1e-9)
            max_sim = max(max_sim, sim)
        return max_sim
    
    # Precision: avg max similarity para tokens del candidato
    precisions = [max_sim_cosine(e, ref_embs) for e in cand_embs]
    precision = np.mean(precisions)
    
    # Recall: avg max similarity para tokens de la referencia
    recalls = [max_sim_cosine(e, cand_embs) for e in ref_embs]
    recall = np.mean(recalls)
    
    f1 = 2 * precision * recall / (precision + recall + 1e-9)
    
    return {"precision": precision, "recall": recall, "f1": f1}

Evaluation Framework Completo

Ahora que conoces las métricas principales, vamos a construir un evaluation framework que combine todas ellas y sea fácil de extender.

from dataclasses import dataclass, field
from typing import List, Dict, Callable, Optional
import json

@dataclass
class EvaluationResult:
    """Resultado de una evaluación individual."""
    metric_name: str
    score: float
    details: Optional[dict] = None

@dataclass
class EvaluationReport:
    """Reporte completo de evaluación de un modelo."""
    model_name: str
    timestamp: str
    results: List[EvaluationResult] = field(default_factory=list)
    
    def get_metric(self, name: str) -> Optional[float]:
        for r in self.results:
            if r.metric_name == name:
                return r.score
        return None
    
    def summary(self) -> dict:
        return {r.metric_name: r.score for r in self.results}

class EvaluationFramework:
    """
    Framework completo para evaluar outputs de LLMs.
    Combina múltiples métricas y permite extensión fácil.
    """
    
    def __init__(self, name: str = "default"):
        self.name = name
        self.metrics: Dict[str, Callable] = {}
        self._register_default_metrics()
    
    def _register_default_metrics(self):
        """Registra las métricas por defecto."""
        self.register_metric("bleu", lambda c, r: bleu_score(c, r))
        self.register_metric("rouge_1", lambda c, r: rouge_n(c, r, 1))
        self.register_metric("rouge_2", lambda c, r: rouge_n(c, r, 2))
        self.register_metric("rouge_l", lambda c, r: rouge_l(c, r))
        self.register_metric("meteor", lambda c, r: meteor_score(c, r))
    
    def register_metric(self, name: str, fn: Callable[[str, str], float]):
        """Registra una nueva métrica al framework."""
        self.metrics[name] = fn
    
    def evaluate(
        self,
        candidate: str,
        reference: str,
        model_name: str = "model"
    ) -> EvaluationReport:
        """Evalúa un candidato contra una referencia con todas las métricas."""
        from datetime import datetime
        
        results = []
        for metric_name, metric_fn in self.metrics.items():
            try:
                score = metric_fn(candidate, reference)
                results.append(EvaluationResult(
                    metric_name=metric_name,
                    score=round(score, 4)
                ))
            except Exception as e:
                results.append(EvaluationResult(
                    metric_name=metric_name,
                    score=0.0,
                    details={"error": str(e)}
                ))
        
        return EvaluationReport(
            model_name=model_name,
            timestamp=datetime.now().isoformat(),
            results=results
        )
    
    def evaluate_dataset(
        self,
        dataset: List[Dict[str, str]],
        model_fn: Callable[[str], str],
        model_name: str = "model"
    ) -> Dict[str, float]:
        """
        Evalúa un modelo sobre un dataset completo.
        Promedia los scores de todas las métricas.
        """
        all_scores: Dict[str, List[float]] = {}
        
        for item in dataset:
            candidate = model_fn(item["input"])
            reference = item["reference"]
            
            report = self.evaluate(candidate, reference, model_name)
            
            for result in report.results:
                if result.metric_name not in all_scores:
                    all_scores[result.metric_name] = []
                all_scores[result.metric_name].append(result.score)
        
        # Promediar
        return {name: sum(scores) / len(scores) for name, scores in all_scores.items()}

# Ejemplo de uso completo
def demo_evaluation_framework():
    # Dataset de ejemplo
    dataset = [
        {
            "input": "¿Cuál es la capital de Francia?",
            "reference": "La capital de Francia es París."
        },
        {
            "input": "Explica la fotosíntesis",
            "reference": "La fotosíntesis es el proceso por el cual las plantas convierten luz solar en energía."
        },
    ]
    
    # Modelo a evaluar (mock)
    def my_model(prompt):
        if "Francia" in prompt:
            return "París es la capital de Francia."
        if "fotosíntesis" in prompt:
            return "Las plantas usan luz solar para crear energía."
        return "No sé."
    
    # Framework
    framework = EvaluationFramework("mi-framework")
    
    # Agregar métrica custom si quieres
    def custom_accuracy(pred: str, ref: str) -> float:
        """Métrica simple: 1.0 si el output contiene la info clave de la ref."""
        ref_lower = ref.lower()
        # Extraer "palabras de contenido" (más de 4 chars)
        content_words = [w for w in ref_lower.split() if len(w) > 4]
        matches = sum(1 for w in content_words if w in pred.lower())
        return matches / len(content_words) if content_words else 0.0
    
    framework.register_metric("content_coverage", custom_accuracy)
    
    # Evaluar dataset completo
    avg_scores = framework.evaluate_dataset(dataset, my_model)
    
    print("=== Resultados Promedio ===")
    for metric, score in avg_scores.items():
        print(f"{metric}: {score:.4f}")

demo_evaluation_framework()

Métricas Custom Para Tu Dominio

A veces las métricas existentes no capturan lo que te importa. En esos casos, necesitas diseñar tu propia métrica. Aquí van ejemplos de métricas custom por dominio.

# ===========================================
# MÉTRICAS CUSTOM POR DOMINIO
# ===========================================

class DomainSpecificMetrics:
    """Colección de métricas específicas para diferentes dominios."""
    
    @staticmethod
    def code_execution_accuracy(code_output: str, expected_output: str) -> float:
        """
        Para tareas de generación de código:
        verifica que el output contiene el resultado esperado.
        """
        return 1.0 if expected_output in code_output else 0.0
    
    @staticmethod
    def factual_consistency_ner(prediction: str, reference: str) -> float:
        """
        Para generación factual:
        extrae Named Entities y verifica que coincidan.
        """
        # En producción usar spaCy o similar para NER
        def extract_mock_entities(text):
            # Mock NER - solo para demostración
            words = text.split()
            return set(w for w in words if w[0].isupper() and len(w) > 2)
        
        pred_ents = extract_mock_entities(prediction)
        ref_ents = extract_mock_entities(reference)
        
        if not ref_ents:
            return 1.0
        
        return len(pred_ents & ref_ents) / len(ref_ents)
    
    @staticmethod
    def response_length_score(response: str, min_len: int = 50, max_len: int = 500) -> float:
        """
        Para chat: penaliza respuestas demasiado cortas o largas.
        """
        length = len(response.split())
        
        if length < min_len:
            return length / min_len  # 0.0 a 1.0
        elif length > max_len:
            return max(0, 1 - (length - max_len) / max_len)
        else:
            return 1.0
    
    @staticmethod
    def safety_score(response: str, forbidden_patterns: List[str]) -> float:
        """
        Para safety: verifica que no contenga patrones prohibidos.
        """
        response_lower = response.lower()
        violations = sum(1 for pattern in forbidden_patterns if pattern.lower() in response_lower)
        
        return max(0, 1 - violations * 0.25)  # Cada violación resta 0.25
    
    @staticmethod
    def tone_consistency(responses: List[str], target_tone: str = "professional") -> float:
        """
        Para consistencia de tono en multi-turn:
        verifica que todas las respuestas tengan el mismo tono.
        """
        # En producción: usar clasificador de tono entrenado
        # Mock: asumimos todas en el mismo tono si no hay markers de cambio
        tone_markers = {
            "professional": ["cordialmente", "atentamente", "es un placer"],
            "casual": ["che", ["qué onda", "genial", "bueno"],
        }
        
        markers = tone_markers.get(target_tone, [])
        consistent_count = sum(1 for r in responses if any(m in r.lower() for m in markers))
        
        return consistent_count / len(responses) if responses else 0.0

# Ejemplo de uso
metrics = DomainSpecificMetrics()

print(f"Code accuracy: {metrics.code_execution_accuracy('Output: 42', '42')}")
print(f"Factual consistency: {metrics.factual_consistency_ner('Paris is capital', 'Paris is capital of France')}")
print(f"Length score: {metrics.response_length_score('Short')}")
print(f"Safety score: {metrics.safety_score('Hello world', ['hack', 'exploit'])}")

Los 3 Errores Comunes (y Sus Soluciones)

Error 1: Confiar Solo en Una Métrica

El problema: "Nuestro modelo tiene BLEU 0.85, está excelente." No. BLEU alto no garantiza calidad. Puedes tener BLEU perfecto con un texto sin sentido y BLEU bajo con una respuesta perfecta pero expresada diferente.

La solución: Usa múltiples métricas que se complementen. Mínimo: BLEU + ROUGE + una métrica de semantic similarity. Idealmente: un framework como el que construimos arriba con al menos 5 métricas de categorías distintas.

def comprehensive_evaluation(candidate: str, reference: str) -> dict:
    """
    Evaluación comprehensiva que NO depende de una sola métrica.
    """
    return {
        "bleu": bleu_score(candidate, reference),
        "rouge_1": rouge_n(candidate, reference, 1),
        "rouge_2": rouge_n(candidate, reference, 2),
        "rouge_l": rouge_l(candidate, reference),
        "meteor": meteor_score(candidate, reference),
        # NO BERTScore aquí porque necesitamos embeddings reales
        # pero las demás son computables sin modelo externo
    }

Error 2: No Entender las Limitaciones de las Métricas Automáticas

El problema: Usas BERTScore y asumes que captura todo. No captura. BERTScore no mide si la información es verdadera, solo si es similar contextualment. Un modelo que genera tonterías coherentes tendrá BERTScore alto.

La solución: Entiende qué mide cada métrica y para qué NO sirve:

  • BLEU/ROUGE: no miden semantic, solo texto literal
  • BERTScore: no mide factualidad, solo similitud contextual
  • Todas: no miden si la información es verdadera

"Métricas automáticas miden correlación con referencias humanas, no calidad intrínseca. Son un proxy, no la verdad."

Error 3: No Tener Evaluación Humana Para Complementar

El problema: Confías 100% en métricas automatizadas y te sorprendes cuando usuarios reportan que el modelo dice puras tonterías con BERTScore 0.9.

La solución:: Implementa un pipeline de evaluación mixta:

  • 80% de casos: métricas automatizadas (rápido, barato)
  • 20% de casos: evaluación humana (Likert scales, A/B testing)
  • 定期: calibración de métricas vs. juicios humanos
class HumanEvaluationSampler:
    """
    Sistema para muestrear casos para evaluación humana.
    """
    
    def __init__(self, automation_threshold: float = 0.85):
        self.automation_threshold = automation_threshold
    
    def should_human_review(self, metrics: dict) -> bool:
        """
        Decide si este caso necesita revisión humana.
        Si todas las métricas automatizadas están muy altas o muy bajas,
        lo automatizamos. Los casos dudosos van a humano.
        """
        scores = list(metrics.values())
        avg_score = sum(scores) / len(scores)
        
        # Si está en zona gris (0.3 a 0.7), necesita humano
        if 0.3 <= avg_score <= 0.7:
            return True
        
        # Si todas las métricas concordar (varianza baja), automatizable
        variance = sum((s - avg_score) ** 2 for s in scores) / len(scores)
        if variance < 0.01:  # Métricas muy alineadas
            return False
        
        # Alta varianza entre métricas = necesita revisión humana
        return True
    
    def sample_for_calibration(
        self, 
        dataset_size: int, 
        calibration_ratio: float = 0.1
    ) -> int:
        """
        Calcula cuántos casos necesitan calibración humana periódica.
        """
        return max(1, int(dataset_size * calibration_ratio))

Matemáticas de las Métricas

La Fórmula de BLEU en Detalle

BLEU se define como:

BLEU = BP · exp(Σ w_n · log p_n)

Donde:

  • BP = Brevity Penalty
  • w_n = pesos (normalmente 0.25 para cada n-grama de 1 a 4)
  • p_n = precisión modificada para n-gramas

La Brevity Penalty previene preferir outputs cortos artificialmente:

BP = 1 if c > r; else exp(1 - r/c)

Donde c = longitud del candidato, r = longitud de referencia efectiva.

BERTScore y Similitud Coseno

BERTScore usa similitud coseno entre embeddings:

cosine(A, B) = (A · B) / (||A|| · ||B||)

Para cada token en el candidato, se encuentra el token en la referencia con máxima similitud:

R = Σ max_sim(emb_cand[i], emb_ref) / Σ ||emb_ref||

import numpy as np

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    """Similitud coseno entre dos vectores."""
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-9)

def bertscore_recall(embeddings_candidate: List[np.ndarray], 
                      embeddings_reference: List[np.ndarray]) -> float:
    """
    Recall de BERTScore: qué tanto del reference está cubierto por candidate.
    Para cada token de referencia, encuentra el token más similar en candidato.
    """
    recalls = []
    for ref_emb in embeddings_reference:
        similarities = [cosine_similarity(ref_emb, c_emb) for c_emb in embeddings_candidate]
        recalls.append(max(similarities))
    
    return np.mean(recalls)

Resumen y Cierre

Ahora tienes un arsenal completo para evaluar LLMs:

  • BLEU: bueno para traducción literal, no para semántica
  • ROUGE: mejor recall, útil para summarization
  • METEOR: más robusto que BLEU, usa sinónimos
  • BERTScore: el mejor para semantic similarity contextual
  • Custom metrics: diseña los tuyos para tu dominio específico

Y recuerda: nunca confíes ciegamente en una métrica. Un buen evaluation framework combina múltiples métricas con evaluación humana periódica.
