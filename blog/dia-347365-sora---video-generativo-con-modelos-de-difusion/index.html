Fundamentos Matematicos

Antes de meternos en codigo, necesitamos la base. Cuando combinamos tecnicas de prompting, estamos manipulando probabilidades condicionales:

La probabilidad de una respuesta R dado un contexto C y una tecnica T:

$$P(R | C, T) = \frac{P(C, T | R) \cdot P(R)}{P(C, T)}$$

En la practica, usamos el teorema de Bayes para combinar evidencia de multiples tecnicas. Si tenemos tecnica A (CoT) y tecnica B (ToT), la probabilidad combinada es:

$$P(R | C) = \alpha \cdot P(R | C, T_{CoT}) + (1-\alpha) \cdot P(R | C, T_{ToT})$$

Donde α es el peso que balancea ambas tecnicas. Esto es basicamente lo que hace un sistema de ensemble cuando combina respuestas de multiples LLMs o multiples prompts.

Combinacion de Tecnicas Avanzadas

Aqui es donde las cosas se ponen interesantes. No se trata de usar una tecnica, sino de combinarlas estrategicamente:

"""
Advanced LLM Technique Combiner Framework
Combina multiples tecnicas de prompting para mejor rendimiento
"""

from dataclasses import dataclass
from typing import List, Dict, Callable, Optional
import json


@dataclass
class TechniqueConfig:
    """Configuracion para una tecnica de prompting"""
    name: str
    prompt_template: str
    weight: float  # Peso en el ensemble final
    temperature: float = 0.7
    max_tokens: int = 2048


class AdvancedTechniqueCombiner:
    """
    Framework para combinar multiples tecnicas avanzadas de LLM.
    
    Patron de uso:
        combiner = AdvancedTechniqueCombiner()
        combiner.add_technique(TechniqueConfig(
            name="CoT",
            prompt_template="Let's think step by step: {question}",
            weight=0.4
        ))
        combiner.add_technique(TechniqueConfig(
            name="ToT",
            prompt_template="Let me explore multiple approaches:\n{question}",
            weight=0.3
        ))
        combiner.add_technique(TechniqueConfig(
            name="Reflexion",
            prompt_template="Let me analyze this carefully:\n{question}\n\nMy previous thought: {previous}",
            weight=0.3
        ))
        result = combiner.combine(question)
    """
    
    def __init__(self):
        self.techniques: List[TechniqueConfig] = []
        self.response_history: List[Dict] = []
    
    def add_technique(self, config: TechniqueConfig) -> None:
        """Agrega una tecnica al combiner"""
        self.techniques.append(config)
        print(f"Added technique: {config.name} with weight {config.weight}")
    
    def _apply_technique(
        self, 
        technique: TechniqueConfig, 
        question: str,
        context: Optional[Dict] = None
    ) -> Dict:
        """Aplica una tecnica individual y retorna la respuesta"""
        # Simular llamada al LLM
        prompt = technique.prompt_template.format(
            question=question,
            previous=context.get('previous_response', '') if context else ''
        )
        
        return {
            "technique": technique.name,
            "prompt": prompt,
            "weight": technique.weight,
            "response": f"Response from {technique.name}",
            "confidence": 0.85,  # Simulado
            "reasoning_steps": self._extract_reasoning_steps(prompt)
        }
    
    def _extract_reasoning_steps(self, prompt: str) -> List[str]:
        """Extrae los pasos de razonamiento del prompt"""
        # En produccion aqui se parsearia la respuesta del LLM
        return [
            "Step 1: Analyze the problem",
            "Step 2: Break down into components", 
            "Step 3: Apply domain knowledge",
            "Step 4: Synthesize solution"
        ]
    
    def combine(
        self, 
        question: str, 
        method: str = "weighted_voting"
    ) -> Dict:
        """
        Combina respuestas de multiples tecnicas.
        
        Args:
            question: Pregunta original
            method: Metodo de combinacion ('weighted_voting', 'sequential', 'hierarchical')
        
        Returns:
            Respuesta combinada con metadata
        """
        print(f"\nCombining {len(self.techniques)} techniques using {method}")
        
        if method == "weighted_voting":
            return self._weighted_voting(question)
        elif method == "sequential":
            return self._sequential_refinement(question)
        elif method == "hierarchical":
            return self._hierarchical_combination(question)
        else:
            raise ValueError(f"Unknown combination method: {method}")
    
    def _weighted_voting(self, question: str) -> Dict:
        """Weighted voting: combina respuestas basadas en pesos"""
        responses = []
        for tech in self.techniques:
            resp = self._apply_technique(tech, question)
            responses.append(resp)
        
        # Calcular score ponderado
        total_weight = sum(r['weight'] for r in responses)
        weighted_confidence = sum(
            r['confidence'] * (r['weight'] / total_weight) 
            for r in responses
        )
        
        return {
            "method": "weighted_voting",
            "responses": responses,
            "final_response": f"Combined response (confidence: {weighted_confidence:.2f})",
            "confidence": weighted_confidence,
            "reasoning_chain": self._build_reasoning_chain(responses)
        }
    
    def _sequential_refinement(self, question: str) -> Dict:
        """Refinamiento secuencial: la salida de una tecnica es entrada de la siguiente"""
        context = {"previous_response": ""}
        responses = []
        
        for tech in self.techniques:
            resp = self._apply_technique(tech, question, context)
            responses.append(resp)
            context["previous_response"] = resp["response"]
        
        return {
            "method": "sequential_refinement",
            "responses": responses,
            "final_response": responses[-1]["response"],
            "confidence": responses[-1]["confidence"],
            "reasoning_chain": self._build_reasoning_chain(responses)
        }
    
    def _hierarchical_combination(self, question: str) -> Dict:
        """
        Combinacion jerarquica: usa tecnicas simples rapidas primero,
        luego tecnicas complejas solo cuando es necesario.
        """
        # Nivel 1: Respuesta rapida con CoT basico
        basic_response = self._apply_technique(
            self.techniques[0], question
        )
        
        # Nivel 2: Si la confianza es baja, usar tecnicas adicionales
        if basic_response["confidence"] < 0.7:
            complex_responses = [
                self._apply_technique(tech, question)
                for tech in self.techniques[1:]
            ]
            all_responses = [basic_response] + complex_responses
            final_confidence = sum(
                r['confidence'] * r['weight'] 
                for r in all_responses
            )
        else:
            all_responses = [basic_response]
            final_confidence = basic_response["confidence"]
        
        return {
            "method": "hierarchical",
            "responses": all_responses,
            "final_response": f"Hierarchical response (confidence: {final_confidence:.2f})",
            "confidence": final_confidence,
            "reasoning_chain": self._build_reasoning_chain(all_responses)
        }
    
    def _build_reasoning_chain(self, responses: List[Dict]) -> List[str]:
        """Construye una cadena de razonamiento unificada"""
        chain = []
        for resp in responses:
            chain.extend([
                f"[{resp['technique']}]",
                *resp.get('reasoning_steps', [])
            ])
        return chain

    combiner.add_technique(TechniqueConfig(
        name="Chain_of_Thought",
        prompt_template="Let's think step by step:\n{question}",
        weight=0.35
    ))
    
    combiner.add_technique(TechniqueConfig(
        name="Tree_of_Thoughts",
        prompt_template="Let me explore multiple paths:\n{question}",
        weight=0.25
    ))
    
    combiner.add_technique(TechniqueConfig(
        name="Self_Reflexion",
        prompt_template="Let me analyze my previous reasoning:\n{previous}\n\nNow for: {question}",
        weight=0.25
    ))

Patrones de Arquitectura Avanzados

Ahora hablemos de como estructurar sistemas que usan LLMs de manera profesional:

"""
Advanced LLM Architecture Patterns
Patrones de arquitectura para sistemas de produccion con LLMs
"""

from abc import ABC, abstractmethod
from typing import List, Optional, Dict, Any
from enum import Enum
import time


class CacheStrategy(Enum):
    """Estrategias de cache para respuestas de LLM"""
    NO_CACHE = "no_cache"
    SEMANTIC_CACHE = "semantic"  # Cache basado en similitud semantica
    EXACT_MATCH = "exact"        # Cache exacto por hash del prompt


class LLMProvider(Enum):
    """Proveedores de LLM soportados"""
    OPENAI = "openai"
    ANTHROPIC = "anthropic"
    LOCAL = "local"  # Llama, Mistral, etc.
    VERTEX = "vertex"


@dataclass
class LLMConfig:
    """Configuracion para un proveedor de LLM"""
    provider: LLMProvider
    model: str
    temperature: float = 0.7
    max_tokens: int = 4096
    cache_strategy: CacheStrategy = CacheStrategy.NO_CACHE
    fallback_models: List[str] = None  # Modelos de respaldo en caso de falla
    
    def __post_init__(self):
        if self.fallback_models is None:
            self.fallback_models = []


@dataclass
class LLMResponse:
    """Respuesta unificada de un LLM"""
    content: str
    model: str
    latency_ms: float
    tokens_used: int
    cached: bool = False
    confidence: float = 1.0


class AdvancedLLMArchitect(ABC):
    """
    Clase base para patrones de arquitectura avanzada de LLM.
    
    Este patron define la interfaz para implementar:
    - Routing inteligente entre modelos
    - Circuit breakers para manejo de fallas
    - Rate limiting adaptativo
    - Observabilidad completa
    """
    
    @abstractmethod
    def generate(self, prompt: str, config: Optional[LLMConfig] = None) -> LLMResponse:
        """Genera una respuesta usando el LLM configurado"""
        pass
    
    @abstractmethod
    def batch_generate(
        self, 
        prompts: List[str], 
        config: Optional[LLMConfig] = None
    ) -> List[LLMResponse]:
        """Genera respuestas para multiples prompts"""
        pass


class IntelligentRouter(AdvancedLLMArchitect):
    """
    Router inteligente: selecciona el modelo optimo basado en la complejidad de la tarea.
    
    Complejidad baja (preguntas simples) -> Modelo pequeno y rapido (GPT-3.5, Llama-7B)
    Complejidad media -> Modelo mediano (GPT-4, Claude-3-Haiku)
    Complejidad alta (razonamiento complejo) -> Modelo grande (GPT-4-Turbo, Claude-3-Opus)
    
    Matematica del routing:
        score = w1 * task_complexity + w2 * latency_requirement + w3 * cost_sensitivity
    
    Donde:
        - task_complexity: 0-1 estimado por analisis del prompt
        - latency_requirement: 0-1 (0 = sin prisa, 1 = urgente)
        - cost_sensitivity: 0-1 (0 =不在乎 costo, 1 = muy在乎)
    """
    
    COMPLEXITY_KEYWORDS = {
        "high": ["analyze", "compare and contrast", "evaluate", "synthesize", "design", "architect"],
        "medium": ["explain", "describe", "summarize", "implement", "create"],
        "low": ["what is", "who is", "when did", "define", "list"]
    }
    
    def __init__(self):
        self.models_config: Dict[LLMProvider, List[LLMConfig]] = {}
        self.usage_stats: Dict[str, List[float]] = {}  # Para observabilidad
        self.circuit_breakers: Dict[str, CircuitBreaker] = {}
    
    def register_model(self, config: LLMConfig) -> None:
        """Registra un modelo disponible"""
        if config.provider not in self.models_config:
            self.models_config[config.provider] = []
        self.models_config[config.provider].append(config)
        self.usage_stats[config.model] = []
    
    def _estimate_complexity(self, prompt: str) -> float:
        """Estima la complejidad de una tarea (0-1)"""
        prompt_lower = prompt.lower()
        
        high_count = sum(1 for kw in self.COMPLEXITY_KEYWORDS["high"] if kw in prompt_lower)
        medium_count = sum(1 for kw in self.COMPLEXITY_KEYWORDS["medium"] if kw in prompt_lower)
        low_count = sum(1 for kw in self.COMPLEXITY_KEYWORDS["low"] if kw in prompt_lower)
        
        total = high_count + medium_count + low_count
        if total == 0:
            return 0.5  # Default medio
        
        # Ponderacion: palabras clave altas pesan mas
        weighted = (high_count * 1.0 + medium_count * 0.5 + low_count * 0.2) / total
        return min(1.0, weighted * 1.5)  # Escalar a 0-1 con maximo en 1.0
    
    def _select_optimal_model(
        self, 
        prompt: str,
        latency_requirement: float = 0.5,
        cost_sensitivity: float = 0.5
    ) -> LLMConfig:
        """
        Selecciona el modelo optimo basado en complejidad y requerimientos.
        
        Formula:
            model_score = α * complexity_match + β * (1 - normalized_latency) + γ * (1 - normalized_cost)
        
        Donde α + β + γ = 1 y se ajustan segun los requerimientos del usuario.
        """
        complexity = self._estimate_complexity(prompt)
        
        candidates = []
        for provider, configs in self.models_config.items():
            for config in configs:
                # Calcular score basado en match de complejidad
                # Modelos pequenos para tareas simples, grandes para complejas
                model_tier = self._get_model_tier(config.model)
                
                complexity_match = 1.0 - abs(complexity - model_tier)
                
                # Normalizar latencia (estimado basado en tier)
                normalized_latency = self._estimate_latency(config) / 10.0  # Normalizar a 0-1
                
                # Normalizar costo (estimado)
                normalized_cost = self._estimate_cost(config) / 10.0
                
                # Pesos ajustables
                α, β, γ = 0.4, 0.3, 0.3
                
                # Ajustar pesos segun requerimientos
                if latency_requirement > 0.7:
                    β = 0.5
                    α, γ = 0.25, 0.25
                if cost_sensitivity > 0.7:
                    γ = 0.5
                    α, β = 0.25, 0.25
                
                score = (
                    α * complexity_match + 
                    β * (1 - normalized_latency) + 
                    γ * (1 - normalized_cost)
                )
                
                candidates.append((score, config))
        
        # Seleccionar el mejor scoring
        candidates.sort(reverse=True, key=lambda x: x[0])
        selected = candidates[0][1]
        
        print(f"Selected model: {selected.model} (complexity={complexity:.2f}, score={candidates[0][0]:.2f})")
        return selected
    
    def _get_model_tier(self, model_name: str) -> float:
        """Obtiene el tier de un modelo (0-1, mayor = mas capaz)"""
        # clasificacion simplificada
        if any(x in model_name.lower() for x in ["gpt-4-turbo", "claude-3-opus", "claude-3-5-sonnet"]):
            return 0.9
        elif any(x in model_name.lower() for x in ["gpt-4", "claude-3-sonnet", "claude-3-haiku"]):
            return 0.7
        elif any(x in model_name.lower() for x in ["gpt-3.5", "llama-13b", "mistral"]):
            return 0.5
        else:
            return 0.3  # Modelos pequenos
    
    def _estimate_latency(self, config: LLMConfig) -> float:
        """Estima latencia en segundos basada en configuracion"""
        base_latencies = {
            LLMProvider.OPENAI: 2.0,
            LLMProvider.ANTHROPIC: 2.5,
            LLMProvider.LOCAL: 5.0,  # Depende del hardware
        }
        return base_latencies.get(config.provider, 3.0) * (1 + config.temperature * 0.2)
    
    def _estimate_cost(self, config: LLMConfig) -> float:
        """Estima costo por 1K tokens"""
        costs = {
            "gpt-4-turbo": 0.01,
            "gpt-4": 0.03,
            "gpt-3.5-turbo": 0.002,
            "claude-3-opus": 0.015,
            "claude-3-sonnet": 0.003,
            "claude-3-haiku": 0.00025,
        }
        return costs.get(config.model, 0.01)
    
    def generate(self, prompt: str, config: Optional[LLMConfig] = None) -> LLMResponse:
        """Genera respuesta con routing inteligente"""
        start_time = time.time()
        
        # Si no hay config, seleccionar automaticamente
        if config is None:
            config = self._select_optimal_model(prompt)
        
        # Intentar con fallback si falla
        models_to_try = [config] + [
            m for m in config.fallback_models 
            if m != config.model
        ]
        
        last_error = None
        for model_config in models_to_try:
            try:
                # Simular llamada
                response = self._call_llm(prompt, model_config)
                latency = (time.time() - start_time) * 1000
                
                # Registrar para observabilidad
                self.usage_stats[model_config.model].append(latency)
                
                return response
            except Exception as e:
                last_error = e
                print(f"Failed {model_config.model}: {e}")
                continue
        
        raise RuntimeError(f"All models failed. Last error: {last_error}")
    
    def _call_llm(self, prompt: str, config: LLMConfig) -> LLMResponse:
        """Simula llamada al LLM (en produccion seria API real)"""
        return LLMResponse(
            content=f"Response from {config.model}",
            model=config.model,
            latency_ms=1500,
            tokens_used=len(prompt.split()) * 1.3,
            cached=False
        )
    
    def batch_generate(
        self, 
        prompts: List[str], 
        config: Optional[LLMConfig] = None
    ) -> List[LLMResponse]:
        """Genera respuestas en paralelo para multiples prompts"""
        # En produccion usar asyncio o thread pool
        return [self.generate(p, config) for p in prompts]
    
    def get_observability_stats(self) -> Dict[str, Any]:
        """Retorna estadisticas de uso para observabilidad"""
        return {
            model: {
                "avg_latency_ms": sum(latencies) / len(latencies) if latencies else 0,
                "call_count": len(latencies),
                "total_tokens": sum(latencies) * 1.3  # Estimado
            }
            for model, latencies in self.usage_stats.items()
        }


class CircuitBreaker:
    """
    Circuit Breaker pattern para manejo de fallas de LLM.
    
    Estados:
    - CLOSED: Operacion normal, todas las llamadas pasan
    - OPEN: Demasiadas fallas,拒绝了 todas las llamadas inmediatamente
    - HALF_OPEN: Prueba periodica para ver si el servicio se recupero
    
    La matematica del circuit breaker:
        failure_rate = failures / (failures + successes)
        Si failure_rate > threshold -> abrir circuit
        Si successes en HALF_OPEN > success_threshold -> cerrar circuit
    """
    
    def __init__(
        self,
        failure_threshold: float = 0.5,
        success_threshold: int = 3,
        timeout_seconds: float = 60.0
    ):
        self.failure_threshold = failure_threshold
        self.success_threshold = success_threshold
        self.timeout_seconds = timeout_seconds
        
        self.failures = 0
        self.successes = 0
        self.state = "CLOSED"  # CLOSED, OPEN, HALF_OPEN
        self.last_failure_time: Optional[float] = None
        self.opening_time: Optional[float] = None
    
    def record_success(self) -> None:
        """Registra una llamada exitosa"""
        self.successes += 1
        self.failures = max(0, self.failures - 1)
        
        if self.state == "HALF_OPEN":
            if self.successes >= self.success_threshold:
                self._close_circuit()
    
    def record_failure(self) -> None:
        """Registra una falla"""
        self.failures += 1
        self.last_failure_time = time.time()
        
        total = self.failures + self.successes
        if total > 0:
            failure_rate = self.failures / total
            
            if failure_rate >= self.failure_threshold:
                self._open_circuit()
    
    def _open_circuit(self) -> None:
        """Abre el circuit (rejecting all calls)"""
        self.state = "OPEN"
        self.opening_time = time.time()
        self.successes = 0
        print(f"Circuit OPENED (failure_rate={self.failures/(self.failures+self.successes):.2%})")
    
    def _close_circuit(self) -> None:
        """Cierra el circuit (allowing calls)"""
        self.state = "CLOSED"
        self.failures = 0
        self.successes = 0
        print("Circuit CLOSED")
    
    def can_execute(self) -> bool:
        """Verifica si se puede ejecutar una llamada"""
        if self.state == "CLOSED":
            return True
        
        if self.state == "OPEN":
            # Check if timeout has passed to try again
            if (time.time() - self.opening_time) > self.timeout_seconds:
                self._half_open_circuit()
                return True
            return False
        
        # HALF_OPEN: allow limited calls
        return True
    
    def _half_open_circuit(self) -> None:
        """Pone el circuit en modo half-open (probando)"""
        self.state = "HALF_OPEN"
        self.successes = 0
        print("Circuit HALF_OPEN (testing recovery)")

Estrategias de Optimizacion

La optimizacion de pipelines de LLM es un campo en si mismo. Aqui van las estrategias mas importantes:

Prompt Caching

Si tienes contexto que no cambia entre llamadas (instrucciones del sistema, documentacion), cacheselo:

$$T_{total} = n \cdot T_{inference} + T_{cache\_lookup} \cdot (n-1)$$

Donde n es el numero de requests y T_{cache_lookup} es mucho menor que T_{inference}.

Batch Processing

En lugar de procesar requests uno por uno, agrupalos:

# Procesamiento en batch vs secuencial
BATCH_STRATEGY = {
    "sequential": {
        "time_per_request": 2.0,  # segundos
        "total_for_100": 200.0,
        "pros": ["Simples"],
        "cons": ["Lento"]
    },
    "batch_16": {
        "time_per_batch": 3.0,  # segundos para 16 requests
        "total_for_100": 3.0 * 7,  # ~19 segundos
        "pros": ["~10x mas rapido"],
        "cons": ["Latencia inicial mayor"]
    }
}

Speculative Decoding

Usa un modelo pequeno para generar candidatos rapidos, y el modelo grande solo para verificarlos:

Speedup = $\frac{T_{large}(n)}{T_{small}(n) + T_{verify}(k)}$

Donde n es la longitud total y k es el numero de tokens verificados.

Errores Comunes

Error 1: No Combinar Tecnicas

El problema: Usar solo una tecnica de prompting cuando la combinacion podria dar mejores resultados.

La solucion: Implementar un framework de combinacion como el AdvancedTechniqueCombiner que use weighted voting o refinamiento secuencial. No te cases con una sola aproximacion — experimenta con CoT + ToT + Reflexion.

Error 2: No Entender los Tradeoffs

El problema: Usar GPT-4 para todo cuando un modelo mas pequeno seria suficiente, o usar un modelo pequeno para tareas que requieren razonamiento complejo.

La solucion: Implementar un IntelligentRouter que seleccione el modelo optimo basado en la complejidad de la tarea. Mide la complejidad del prompt y balancea entre costo, latencia y calidad. La formula: model_score = α * complexity_match + β * latency_fit + γ * cost_fit.

Error 3: Over-Engineering

El problema: Construir una arquitectura de 15 capas con circuit breakers, caches, rate limiters, yfallback a 3 modelos cuando solo necesitas un prompt simple.

La solucion: Follow the YAGNI principle. Empieza simple, mide donde estan los cuellos de botella reales, y agrega complejidad solo cuando hayas identificado un problema concreto. Un buen pipeline de LLM es el que cumple su objetivo con la menor complejidad posible.

Resumen y Cierre

Dia 347 y hoy aprendimos que los LLMs avanzados no se tratan solo de mejores prompts, sino de como combinamos tecnicas, disenamos arquitecturas robustas y optimizamos el pipeline completo.

Las claves:

  • Combinar tecnicas con pesos apropiados (CoT + ToT + Reflexion)
  • Router inteligente que seleccione modelos segun complejidad
  • Patrones de arquitectura: circuit breakers, cache, observabilidad
  • Optimizar con batch processing y speculative decoding
  • Evitar over-engineering: resuelve el problema real, no el problema imaginario

Recuerden: la mejor arquitectura es la que funciona para su caso especifico. No todo el mundo necesita un router inteligente con 5 modelos diferentes. Empiecen simple, midan, iteren.
