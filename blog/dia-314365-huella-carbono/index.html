Adapter Methods — Módulos que Se Aprenden

10 de noviembre de 2026

Intro — El Problema de Fine-tuning Todo

Qué tal, parce. Día 314. Hoy vamos a hablar de Adapter Methods, que son una familia de técnicas para adaptar modelos pre-entrenados sin modificar todos sus parámetros. El problema con fine-tuning tradicional es que actualiza TODOS los parámetros del modelo. Si usted quiere que su modelo de 7B parámetros sepa algo nuevo, tiene que actualizar 7B números. Los adapters le permiten actualizar solo unos pocos millones.

Piénselo como aprender un nuevo idioma: no necesita cambiar cómo funciona su cerebro completo, solo agregar nuevas conexiones neurales. Los adapters son esas nuevas conexiones.

Arquitectura de un Adapter

Un adapter básico es un módulo pequeño que se inserta en cada capa del transformer:

$$h_{new} = h_{old} + f(W_{down} \cdot h_{old}) \cdot W_{up}$$

donde:

  • $W_{down}$: Proyección hacia dimensión menor (bottleneck)
  • $W_{up}$: Proyección de vuelta a dimensión original
  • $f$: Función de activación (típicamente GELU)

Tipos de Adapters

Bottleneck Adapter

El adapter tradicional con bottleneck:

class BottleneckAdapter(nn.Module):
    def __init__(self, d_model, reduction_factor=16):
        super().__init__()
        bottleneck_dim = d_model // reduction_factor  # ej: 4096 / 16 = 256
        
        self.down_project = nn.Linear(d_model, bottleneck_dim)
        self.up_project = nn.Linear(bottleneck_dim, d_model)
        self.activation = nn.GELU()
        
        # Inicialización estratégica
        nn.init.zeros_(self.up_project.weight)
        nn.init.zeros_(self.up_project.bias)
    
    def forward(self, x):
        h = self.activation(self.down_project(x))
        h = self.up_project(h)
        return x + h  # Residual connection

Parallel Adapter

El adapter opera en paralelo con la atención en lugar de en serie:

class ParallelAdapter(nn.Module):
    def __init__(self, d_model, reduction_factor=16):
        super().__init__()
        bottleneck_dim = d_model // reduction_factor
        
        self.down_project = nn.Linear(d_model, bottleneck_dim)
        self.up_project = nn.Linear(bottleneck_dim, d_model)
        self.activation = nn.GELU()
    
    def forward(self, x, attn_output):
        # Adapter en paralelo con atención
        adapter_output = self.activation(self.down_project(x))
        adapter_output = self.up_project(adapter_output)
        
        # Combinar con salida de atención
        return attn_output + adapter_output

LayerScale Adapter

Añade escalado aprendible por capa:

class LayerScaleAdapter(nn.Module):
    def __init__(self, d_model, reduction_factor=16):
        super().__init__()
        bottleneck_dim = d_model // reduction_factor
        
        self.down_project = nn.Linear(d_model, bottleneck_dim)
        self.up_project = nn.Linear(bottleneck_dim, d_model)
        self.activation = nn.GELU()
        
        # LayerScale: inicialización cuidadosa
        self.gamma = nn.Parameter(torch.ones(d_model) * 1e-2)
    
    def forward(self, x):
        h = self.activation(self.down_project(x))
        h = self.up_project(h)
        return x + self.gamma * h

Compilación de Adapters

Un problema con múltiples adapters es que cada uno puede interferir con los otros. CompILATE propone un método para combinarlos:

$$\alpha_i = \text{softmax}(W_\alpha [h; p_i])$$

donde $p_i$ es el vector de prompt para el adapter $i$.

class CompILATEAdapter(nn.Module):
    def __init__(self, d_model, num_adapters, reduction_factor=16):
        super().__init__()
        self.num_adapters = num_adapters
        bottleneck_dim = d_model // reduction_factor
        
        # Un adapter por tarea
        self.adapters = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, bottleneck_dim),
                nn.GELU(),
                nn.Linear(bottleneck_dim, d_model)
            )
            for _ in range(num_adapters)
        ])
        
        # Router que combina adapters
        self.router = nn.Sequential(
            nn.Linear(d_model + num_adapters, d_model),
            nn.GELU(),
            nn.Linear(d_model, num_adapters)
        )
    
    def forward(self, x, task_prompts=None):
        # Calcular pesos de combinación
        if task_prompts is not None:
            combined = torch.cat([x, task_prompts], dim=-1)
        else:
            combined = x
        
        weights = self.router(combined)  # [batch, num_adapters]
        weights = torch.softmax(weights, dim=-1)
        
        # Combinar salidas de todos los adapters
        output = torch.zeros_like(x)
        for i, adapter in enumerate(self.adapters):
            output += weights[:, i:i+1] * adapter(x)
        
        return output

AdapterFusion

AdapterFusion combina múltiples adapters de forma dinámica:

class AdapterFusion(nn.Module):
    def __init__(self, d_model, num_tasks):
        super().__init__()
        self.num_tasks = num_tasks
        
        # Query para atención
        self.query = nn.Linear(d_model, d_model)
        
        # Llaves y valores de cada adapter (pre-computados)
        self.adapter_keys = nn.ParameterList([
            nn.Parameter(torch.randn(d_model)) for _ in range(num_tasks)
        ])
        self.adapter_values = nn.ParameterList([
            nn.Parameter(torch.randn(d_model)) for _ in range(num_tasks)
        ])
    
    def forward(self, x, adapter_outputs):
        """
        x: [batch, seq, d_model]
        adapter_outputs: list of [batch, seq, d_model], one per task
        """
        # Query del estado actual
        q = self.query(x)  # [batch, seq, d_model]
        
        # Calcular atención sobre adapters
        attn_scores = torch.einsum('bsd,bd->bs', q, self.adapter_keys)
        attn_weights = F.softmax(attn_scores, dim=-1)
        
        # Combinar outputs de adapters
        fused = torch.zeros_like(x)
        for i, adapter_out in enumerate(adapter_outputs):
            fused += attn_weights[:, i:i+1] * adapter_out
        
        return fused

Adapters vs LoRA

Comparando los dos enfoques:

  • LoRA: $h = W_0 x + BAx$ donde $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$
  • Adapter: $h = W_0 x + f(W_{down}W_{up})x$ con no linealidad

LoRA es más parameter-efficient para atención, adapters son más expresivos pero más pesados.

Errores Comunes

Error 1: Poner Adapters en Todas las Capas

El error: Insertar adapters en cada capa del modelo. Esto puede causar sobreajuste y ralentizar la inferencia.

El fix: Solo poner adapters en las últimas N capas o en las capas de atención. Experimente con 2-4 capas para modelos grandes.

Error 2: No Usar Inicialización Cero

El error: Inicializar los pesos del adapter aleatoriamente. Esto puede destruir la representación pre-entrenada al inicio del entrenamiento.

El fix: Inicialice los pesos de salida a cero (up_projection). Esto hace que el adapter empiece como identidad y gradualmente aprenda.

Error 3: Olvidar el Dropout

El error: Entrenar adapters sin dropout. Overfitting rápido.

El fix: Use dropout de 0.1-0.2 en el bottleneck del adapter.

Resumen

Los adapters son como lecciones de chino para su modelo: no necesita reprogramar todo el cerebro.

  • Bottleneck adapter: Proyección down-up con activación
  • Parallel adapter: En paralelo con atención
  • LayerScale: Escalado por capa
  • CompILATE: Combina múltiples adapters dinámicamente
  • AdapterFusion: Atención sobre outputs de adapters
