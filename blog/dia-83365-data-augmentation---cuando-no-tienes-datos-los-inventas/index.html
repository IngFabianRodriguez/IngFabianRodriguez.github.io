Data Augmentation - Cuando No Tienes Datos, los Inventas (y Funciona)

9 de marzo de 2026
data augmentationtorchvision.transformsRandomHorizontalFlipmixupcutmix

La Intro que el 85% Se Salta

Parcero, ¿cuántas veces has escuchado "necesitamos más data"? Es el primer instinto cuando un modelo no funciona. Pero hay otra respuesta que el 85% subestima: si no tienes más data, usa la que tienes mejor. Data augmentation es la técnica de generar training samples artificiales aplicando transformaciones que preservan el label — rotación, flip, crop, noise — para que el modelo vea másvariación sin recoger nuevos datos.

Yo lo descubrí con un modelo de detección de fraude en imágenes de documentos. Tenía solo 2,000 samples positivos (fraudes) y el modelo sobreajustábay no generalizaba. Añadí data augmentation específica para documentos — rotación leve, cambio de brillo, compresión JPEG, crop aleatorio — y la accuracy de test subió 15%. Todo sin recoger un solo fraude nuevo.

Hoy: todas las técnicas de data augmentation, cuándo usar cada una, y cómo implementarlas correctamente para computer vision y texto.

¿Por Qué Funciona la Data Augmentation?

El fundamento teórico: el modelo debería ser invariante a ciertas transformaciones que no cambian el label semantics. Si roto un gato 15 grados, sigue siendo un gato. Si cambio el brillo de una foto de documento, sigue siendo el mismo documento. La data augmentation fuerza al modelo a aprender estas invarianzas en lugar de memorizar features espurios.

Hay dos tipos: in-place (aplica la transformación y entrena directamente con el resultado) y on-the-fly (aplica la transformación en runtime cada epoch, generando infinite data variability).

Augmentations para Imágenes

Geometricas:

  • Random Horizontal/Vertical Flip: El más básico.翻了 gato sigue siendo gato.
  • Random Rotation: Rota la imagen ±10-30 grados. Buena para objetos que no tienen orientación fija.
  • Random Crop: Toma un crop aleatorio de la imagen. Enseña al modelo a reconocer objetos parcialmente visibles.
  • Random Resize and Crop: Escala la imagen, luego hace crop. Simula diferentes distancias.
  • Random Perspective/Shear: Transformación afín. Simula distorsión de perspectiva.

Color/Aprovechadas por pixeles:

  • Color Jitter: Cambia brightness, contrast, saturation, hue aleatoriamente.
  • Grayscale: Convierte a grayscale con cierta probabilidad.
  • Gaussian Blur: Simula imágenes fuori de foco.
  • Noise Gaussiano: Añade ruido. Hace el modelo más robusto a perturbaciones.
  • Random Erasing/Cutout: Apaga una región rectangular aleatoria. fuerza al modelo a no depender de features específicos.
  • MixUp/CutMix: Mezcla dos imágenes y sus labels proporcionalmente. Muy efectivo para classification.

Código Production-Grade

import torch
import torchvision.transforms as T
import torchvision.transforms.functional as TF
import random
from PIL import Image
import numpy as np


class RandomAugment:
    """Data augmentation pipeline configurable."""
    def __init__(self, p=0.5, intensity='medium'):
        self.p = p
        self.intensity = intensity
        intensity_levels = {
            'light': {'rotate': 5, 'color_jitter': 0.1, 'blur': 0.5},
            'medium': {'rotate': 15, 'color_jitter': 0.2, 'blur': 1.0},
            'heavy': {'rotate': 30, 'color_jitter': 0.3, 'blur': 2.0},
        }
        self.params = intensity_levels[intensity]

    def __call__(self, img):
        # Geometric augmentations
        if random.random() < self.p:
            angle = random.uniform(-self.params['rotate'], self.params['rotate'])
            img = TF.rotate(img, angle)

        if random.random() < self.p:
            img = TF.hflip(img) if random.random() < 0.5 else img

        # Color augmentations
        if random.random() < self.p:
            img = TF.adjust_brightness(img, 1 + random.uniform(-self.params['color_jitter'], self.params['color_jitter']))
            img = TF.adjust_contrast(img, 1 + random.uniform(-self.params['color_jitter'], self.params['color_jitter']))

        # Cutout (Random Erasing)
        if random.random() < self.p * 0.5:
            w, h = img.size
            cut_w = int(w * 0.1)
            cut_h = int(h * 0.1)
            x = random.randint(0, w - cut_w)
            y = random.randint(0, h - cut_h)
            img = TF.pil_to_tensor(img)
            img[:, y:y+cut_h, x:x+cut_w] = 0
            img = TF.to_pil_image(img)

        return img


class MixUp:
    """MixUp augmentation: linearly interpolate images and labels."""
    def __init__(self, alpha=0.2):
        self.alpha = alpha

    def __call__(self, batch_x, batch_y):
        lam = np.random.beta(self.alpha, self.alpha)
        batch_size = batch_x.size(0)
        index = torch.randperm(batch_size)
        mixed_x = lam * batch_x + (1 - lam) * batch_x[index]
        y_a, y_b = batch_y, batch_y[index]
        return mixed_x, y_a, y_b, lam


class CutMix:
    """CutMix: cut a patch from one image and paste it onto another."""
    def __init__(self, alpha=1.0):
        self.alpha = alpha

    def __call__(self, batch_x, batch_y):
        lam = np.random.beta(self.alpha, self.alpha)
        batch_size = batch_x.size(0)
        index = torch.randperm(batch_size)

        # Get bounding box
        _, _, H, W = batch_x.shape
        cut_ratio = np.sqrt(1 - lam)
        cut_h = int(H * cut_ratio)
        cut_w = int(W * cut_ratio)
        cx = np.random.randint(W)
        cy = np.random.randint(H)

        x1 = np.clip(cx - cut_w // 2, 0, W)
        y1 = np.clip(cy - cut_h // 2, 0, H)
        x2 = np.clip(cx + cut_w // 2, 0, W)
        y2 = np.clip(cy + cut_h // 2, 0, H)

        # Apply cutmix
        batch_x[:, :, y1:y2, x1:x2] = batch_x[index, :, y1:y2, x1:x2]
        lam = 1 - ((x2 - x1) * (y2 - y1) / (W * H))
        return batch_x, batch_y, batch_y[index], lam


def get_training_transforms(augmentation='medium', input_size=224):
    """Standard training transforms con data augmentation."""
    return T.Compose([
        T.RandomResizedCrop(input_size, scale=(0.8, 1.0)),
        T.RandomHorizontalFlip(p=0.5),
        T.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, hue=0.1),
        T.RandomRotation(degrees=15),
        T.ToTensor(),
        T.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
        T.RandomErasing(p=0.2, scale=(0.02, 0.2)),
    ])


def get_inference_transforms(input_size=224):
    return T.Compose([
        T.Resize(int(input_size * 1.14)),
        T.CenterCrop(input_size),
        T.ToTensor(),
        T.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
    ])

Errores Comunes

Error 1: Aplicar augmentations que cambian el label

El error más grave: aplicar una transformación que no preserva el label semantics. Rotar un dígito "6" por 180 grados lo convierte en "9" — si tu dataset incluye dígitos, rotaciones grandes cambian el label. Similarmente, vertical flip en texto o en señales de tráfico cambia completamente el significado.

Fix: Entender tu dominio. Para dígitos: solo horizontal flip. Para documentos: rotation leve (max ±10°). Para autos autónomos: semantically correct augmentations (no flip vertical de señales de stop).

Error 2: Data augmentation en test set

Aplicar data augmentation al test set para "ver más datos" es completamente incorrecto. El test set DEBE ser representative del deployment real. Si tu aplicación recibe fotos de frente de documentos, no deberías aplicar rotation aleatoria a tus test images.

Fix: Aplica data augmentation SOLO al training set. El test set debe pasarse por preprocessing fijo y determinístico.

Error 3: Demasiada augmentation que destruye el signal

Con augmentation muy agresiva, destruyes el signal en lugar de aumentarlo. Si cambias brightness de ±100%, la imagen se vuelve illegible. Si aplicas cutout de 50% de la imagen, el modelo no tiene suficiente contexto para aprender.

Fix: Valora tus augmentations. Aplica augmentation gradually y monitorea si el training loss converge. Si la augmentation es demasiado fuerte, el modelo no podrá aprender.

Resumen del Día

  • Data Augmentation: Genera training samples artificiales con transformaciones que preservan el label.
  • Geometricas: Flip, rotation, crop, perspective. Enseñan invarianzas espaciales.
  • Color: Brightness, contrast, saturation, blur. Enseñan invarianzas照明.
  • Cutout/Random Erasing: Apaga regiones aleatorias. Fuerza al modelo a no depender de features específicos.
  • MixUp/CutMix: Mezcla imágenes y labels. Muy efectivo para regularización.
  • Solo training: Data augmentation es SOLO para training. Test set debe ser fijo.
  • Dominio específico: No todas las augmentations son válidas para todos los dominios.

El Cierre

Parcero, data augmentation es probablemente la forma más efectiva de mejorar generalization cuando tienes limited data. Y no cuesta nada: solo tiempo de cómputo extra durante training. La clave es pensar en qué invarianzas tiene tu problema: si un objeto rotado sigue siendo el mismo objeto, rota. Si el brightness no importa, jitter brightness.

Esa vaina de "mientras más augmentations mejor" no es cierta. La sobre-augmentation destruye el signal. Encuentra el balance correcto para tu dominio específico. Y recuerda: el test set es sagrado — augmentation solo en training. ¡Nos vemos en el día 84!
