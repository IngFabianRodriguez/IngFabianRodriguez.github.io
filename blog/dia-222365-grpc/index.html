Federated Learning — El Aprendizaje Que No Cierra La Ventana Pero Protege Los Datos

Hagale pues, parcero. Aquí en Colombia, cuando un banco en Bogotá tiene datos de sus clientes y una fintech en Medellín tiene otros datos, la pregunta es: ¿cómo entrenar un modelo jointly sin que nadie tenga que compartir su información? Eso es exactamente lo que resuelve Federated Learning. Hoy lo desarmamos completo.

🏥 El Problema Que Resuelve Federated Learning

En el mundo real, los datos están esparcidos:

  • Hospitales tienen registros médicos que no pueden compartir por HIPAA
  • Bancos tienen transaction history que competencias no quieren exponer
  • Telcos tienen datos de ubicación que reguladores vigilan
  • Empresas tienen datos propietarios que son su ventaja competitiva

Federated Learning dice: "No mandes los datos. Manda los gradientes." En lugar de centralizar datos, distribuyes el entrenamiento.

🔧 FedAvg — El Algoritmo Central

FedAvg (Federated Averaging) es el algoritmo foundational. La idea es simple:

"""
Federated Averaging (FedAvg)
1. Server envía modelo global a clients
2. Cada client entrena localmente con sus datos
3. Clients envían gradientes/actualizaciones al server
4. Server promedia las actualizaciones
5. Repetir hasta convergencia
"""

import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset

class FederatedServer:
    def __init__(self, model, clients):
        self.global_model = model
        self.clients = clients
        self.round = 0
    
    def broadcast_model(self):
        """Envía modelo global a todos los clients"""
        for client in self.clients:
            client.set_model(self.global_model.state_dict())
    
    def aggregate_updates(self, updates, weights=None):
        """
        Promedia las actualizaciones de los clients
        weights = número de samples por client (importante para non-IID!)
        """
        if weights is None:
            weights = [1.0 / len(updates)] * len(updates)
        
        total_weight = sum(weights)
        weighted_updates = []
        
        for update, weight in zip(updates, weights):
            weighted_updates.append({k: v * (weight / total_weight) 
                                   for k, v in update.items()})
        
        # Sumar los weighted updates
        averaged_update = {}
        for key in weighted_updates[0].keys():
            averaged_update[key] = sum(u[key] for u in weighted_updates)
        
        return averaged_update
    
    def apply_update(self, update):
        """Aplica la actualización al modelo global"""
        with torch.no_grad():
            for key, value in update.items():
                self.global_model.state_dict()[key] += value
    
    def federated_round(self, weights=None):
        """Una ronda completa de FedAvg"""
        self.broadcast_model()
        
        updates = []
        for client in self.clients:
            update = client.train_local()
            updates.append(update)
        
        averaged_update = self.aggregate_updates(updates, weights)
        self.apply_update(averaged_update)
        
        self.round += 1
        return self.global_model.state_dict()


class FederatedClient:
    def __init__(self, model, dataset, device='cpu'):
        self.model = model
        self.dataset = dataset
        self.device = device
        self.local_epochs = 2
        self.batch_size = 32
        self.lr = 0.01
    
    def set_model(self, state_dict):
        self.model.load_state_dict(state_dict)
    
    def train_local(self):
        """Entrena localmente y retorna la actualización (delta de pesos)"""
        self.model.train()
        optimizer = optim.SGD(self.model.parameters(), lr=self.lr)
        
        dataloader = DataLoader(self.dataset, batch_size=self.batch_size, shuffle=True)
        
        # Guardar pesos antes del entrenamiento
        before_state = {k: v.clone() for k, v in self.model.state_dict().items()}
        
        for epoch in range(self.local_epochs):
            for X_batch, y_batch in dataloader:
                X_batch, y_batch = X_batch.to(self.device), y_batch.to(self.device)
                
                optimizer.zero_grad()
                output = self.model(X_batch)
                loss = nn.CrossEntropyLoss()(output, y_batch)
                loss.backward()
                optimizer.step()
        
        # Calcular delta (actualización)
        after_state = self.model.state_dict()
        delta = {k: after_state[k] - before_state[k] for k in before_state.keys()}
        
        return delta

📊 Non-IID Data — El Desafío Real

El problema más grande en Federated Learning es que los datos de cada client raramente son IID (independent and identically distributed). Esto causa que los modelos diverjan.

¿Qué es Non-IID?

# Non-IID scenarios comunes:

# 1. Feature distribution shift (clients tienen diferentes features)
# Client A: datos de adultos-jóvenes, solo transacciones pequeñas
# Client B: datos de adultos-mayores, transacciones grandes

# 2. Label distribution shift (clients tienen diferentes clases)
# Hospital A: mayoría pacientes con diabetes
# Hospital B: mayoría pacientes con hipertensión

# 3. Quantity skew (clients tienen diferentes cantidades de datos)
# Banco grande: 1M samples
# Banco pequeño: 1K samples

# 4. Same labels pero diferentes features
# Dos banks en diferentes regionesgeográficas

Solución: FedProx y Estrategias de Compensación

# FedProx: agrega term de regularización para handle non-IID
class FedProxClient(FederatedClient):
    def __init__(self, model, dataset, mu=0.01, **kwargs):
        super().__init__(model, dataset, **kwargs)
        self.mu = mu  # parámetro de penalización
    
    def train_local(self):
        before_state = {k: v.clone() for k, v in self.model.state_dict().items()}
        
        self.model.train()
        optimizer = optim.SGD(self.model.parameters(), lr=self.lr)
        dataloader = DataLoader(self.dataset, batch_size=self.batch_size, shuffle=True)
        
        for epoch in range(self.local_epochs):
            for X_batch, y_batch in dataloader:
                X_batch, y_batch = X_batch.to(self.device), y_batch.to(self.device)
                
                optimizer.zero_grad()
                output = self.model(X_batch)
                loss = nn.CrossEntropyLoss()(output, y_batch)
                
                # Término de proximal regularization (FedProx)
                proximal_term = 0
                for name, param in self.model.named_parameters():
                    proximal_term += torch.sum((param - before_state[name]) ** 2)
                loss += (self.mu / 2) * proximal_term
                
                loss.backward()
                optimizer.step()
        
        after_state = self.model.state_dict()
        delta = {k: after_state[k] - before_state[k] for k in before_state.keys()}
        
        return delta

def adaptive_weights(clients_metrics):
    """
    Ponderar updates basado en qué tan bien performs el client
    """
    # Normalizar métricas
    total = sum(clients_metrics)
    return [m / total for m in clients_metrics]

🔒 Differential Privacy — La Capa de Protección Que Hace Falta

Aquí viene la verdad incómoda: si solo mandas gradientes, un adversary puede reconstruir datos de otros clients. Differential Privacy (DP) añade ruido para prevenir esto.

import torch
import numpy as np

class DPFederatedClient(FederatedClient):
    def __init__(self, model, dataset, epsilon=1.0, delta=1e-5, **kwargs):
        super().__init__(model, dataset, **kwargs)
        self.epsilon = epsilon  # Privacy budget
        self.delta = delta     # Failure probability
        self.sensitivity = 1.0  # Maximum change en un parámetro
        self.noise_scale = self.sensitivity * np.sqrt(2 * np.log(1.25 / self.delta)) / self.epsilon
    
    def add_noise(self, parameters):
        """Añade Gaussian noise a los gradientes para DP"""
        noisy_parameters = {}
        for name, param in parameters.items():
            noise = torch.randn_like(param) * self.noise_scale
            noisy_parameters[name] = param + noise
        return noisy_parameters
    
    def clip_gradients(self, delta, max_norm=1.0):
        """Clip gradientes para bound sensitivity"""
        total_norm = torch.sqrt(sum(torch.sum(p ** 2) for p in delta.values()))
        
        clip_factor = max_norm / total_norm.item() if total_norm.item() > max_norm else 1.0
        
        return {k: v * clip_factor for k, v in delta.items()}
    
    def train_local(self):
        """Entrena con Differential Privacy"""
        before_state = {k: v.clone() for k, v in self.model.state_dict().items()}
        
        self.model.train()
        optimizer = optim.SGD(self.model.parameters(), lr=self.lr)
        dataloader = DataLoader(self.dataset, batch_size=self.batch_size, shuffle=True)
        
        for epoch in range(self.local_epochs):
            for X_batch, y_batch in dataloader:
                X_batch, y_batch = X_batch.to(self.device), y_batch.to(self.device)
                
                optimizer.zero_grad()
                output = self.model(X_batch)
                loss = nn.CrossEntropyLoss()(output, y_batch)
                loss.backward()
                optimizer.step()
        
        after_state = self.model.state_dict()
        delta = {k: after_state[k] - before_state[k] for k in before_state.keys()}
        
        # DP: Clip + add noise
        clipped_delta = self.clip_gradients(delta)
        noisy_delta = self.add_noise(clipped_delta)
        
        return noisy_delta

⚠️ Los 3 Errores Que El 90% Commete

Error 1: Federated Sin Differential Privacy Es Menos Private De Lo Que Crees

El problema: Mandar gradientes puros es inseguro. Un adversary puede hacer membership inference attacks para determinar si un datapoint específico estaba en el dataset de otro client.

# Membership inference attack simplificado:
# 1. Interceptor conoce el modelo antes de la ronda
# 2. Interceptor conoce el modelo después de la ronda
# 3. Si la diferencia es muy pequeña, el datapoint probablemente estaba
#    en el training set del client

# Solución: ALWAYS usar DP cuando privacy es un requerimiento

La solución: Implementar differential privacy desde el inicio. Usar:

  • Gradient clipping (bound sensitivity)
  • Gaussian noise addition
  • Secure aggregation (server no ve updates individuales)
  • Formal privacy accounting (epsilon, delta budgets)

Error 2: No Handle Non-IID Data Distributions Correctamente

El problema: Si usas FedAvg vanilla con datos non-IID, el modelo global diverge y no converge bien.

# NO HACER ESTO (FedAvg vanilla con non-IID):
server = FederatedServer(model, clients)
for round in range(100):
    server.federated_round()  # Sin adjustar por non-IID!

# Resultado: modelo converge a algo mediocre para todos

La solución:

  • Usar FedProx en lugar de FedAvg
  • Ajustar weights por distribución de datos
  • Implementar个性化 local adaptation
  • Considerar mezcla de datos sintéticos

Error 3: No Considerar Communication Efficiency

El problema: En federated setup real, communication es el bottleneck. Mandar modelos completos cada ronda es costoso y lento.

# Gradient compression ejemplo:
def compress_gradient(gradient, compression_ratio=0.1):
    """Top-k compression: solo manda el 10% de gradientes más importantes"""
    flat = gradient.flatten()
    k = int(len(flat) * compression_ratio)
    
    # Encontrar top-k valores absolutos
    _, indices = torch.topk(torch.abs(flat), k)
    
    # Crear sparse representation
    compressed = torch.zeros_like(flat)
    compressed[indices] = flat[indices]
    
    return compressed, indices

def decompress_gradient(compressed, indices, original_shape):
    """Reconstruir gradiente sparse"""
    gradient = torch.zeros(original_shape).flatten()
    gradient[indices] = compressed[indices]
    return gradient.view(original_shape)

📚 Resumen y Cierre

Hagale pues, parcero. Federated Learning es una de las tecnologías más importantes para el futuro de ML con privacy. Pero no es mágicay tiene sus complicaciones.

Lo que debes recordar:

  • FedAvg es el foundation pero no funciona bien con non-IID out of the box
  • Differential Privacy NO es opcional si privacy es un requerimiento real
  • Non-IID data es la norma, no la excepción — prepárate para handlearlo
  • Communication efficiency es crítica en producción real
  • Aplicaciones en healthcare y finance son el caso de uso más fuerte
