Object Detection - Encontrar Cosas En Imagenes

05 de octubre de 2026
object-detectionyolorcnncomputer-vision

Detectar es Localizar

Clasificar una imagen es decir "hay un gato". Object detection es decir "hay un gato en la posición (x1, y1, x2, y2)". La diferencia parece simple pero el problema técnico es radicalmente diferente: necesitas encontrar objetos, clasificarlos, y localizarlos simultáneamente. Durante años fue uno de los problemas más difíciles de computer vision. Hoy, con YOLO y sus descendientes, puedes hacerlo en tiempo real en tu teléfono.

El Problema: Simultaneous Classification y Localization

Imagina que tienes una foto de una calle. Una CNN clásica te diría "hay peatones, autos, señales". Pero un detector de objetos te dice exactamente dónde está cada peatón, cada auto, cada señal — con bounding boxes que los delimitan. Esto es esencial para:

  • Autos autónomos: detectar peatones, otros vehículos, señales en tiempo real
  • Medicina: localizar tumores en radiografías con bounding boxes
  • Retail: contar productos en estantes, detectar stock
  • Agricultura: identificar plagas en plantas específicas

Evolución de Arquitecturas

R-CNN (2014): La Primera Solución

Ross Girshick propuso un pipeline de tres pasos:

  1. Selective Search: genera ~2000 regiones candidatas en la imagen
  2. CNN: extrae features de cada región propuesta
  3. SVM: clasifica cada región como objeto o fondo

Funcionaba, pero era lento: 47 segundos por imagen. No servía para tiempo real.

Fast R-CNN (2015): Compartiendo Computación

La innovación clave: en lugar de procesar cada región por separado, procesa la imagen completa una vez y luego extrae features de las regiones propuestas usando RoI pooling. Esto redujo el tiempo a ~2 segundos por imagen.

$$\text{RoI Pooling}: \text{divide cada región propuesta en } H \times W \text{ sub-regiones y hace max pooling}$$

Faster R-CNN (2016): End-to-End

Reemplazó Selective Search con una Region Proposal Network (RPN): una pequeña red neuronal que aprende a proponer regiones. Todo el sistema se entrena end-to-end:

import torch
import torch.nn as nn

class RegionProposalNetwork(nn.Module):
    """
    RPN genera regiones candidatas (anchors) para objetos.
    Para cada posición espacial, propone k anchors de diferentes escalas.
    """
    def __init__(self, in_channels=512, num_anchors=9):
        super().__init__()
        # Convolución compartida para propuestas
        self.rpn_conv = nn.Conv2d(in_channels, in_channels, 3, padding=1)
        # Clasificador: ¿hay objeto o no?
        self.rpn_cls = nn.Conv2d(in_channels, num_anchors * 2, 1)
        # Regresor: ¿cómo ajustar el anchor?
        self.rpn_reg = nn.Conv2d(in_channels, num_anchors * 4, 1)
    
    def forward(self, feature_map):
        """
        Args:
            feature_map: (batch, channels, H, W) de la CNN backbone
        Returns:
            rpn_cls: (batch, num_anchors*2, H, W) - logits para objectness
            rpn_reg: (batch, num_anchors*4, H, W) - deltas para bounding boxes
        """
        x = torch.relu(self.rpn_conv(feature_map))
        rpn_cls = self.rpn_cls(x)  # shape: (B, num_anchors*2, H, W)
        rpn_reg = self.rpn_reg(x)  # shape: (B, num_anchors*4, H, W)
        return rpn_cls, rpn_reg

# Los anchors son cajas predefinidas en diferentes escalas y ratios
# Típicamente: 3 escalas (128, 256, 512) × 3 ratios (1:1, 1:2, 2:1) = 9 anchors

YOLO (2016): You Only Look Once

La revolución de YOLO: no generar propuestas de región. Dividir la imagen en una grilla y predecir directamente bounding boxes y clases para cada celda. Esto es 10x más rápido que Faster R-CNN:

$$S \times S \times (B \times 5 + C)$$

donde $S$ es el tamaño de la grilla, $B$ el número de bounding boxes por celda, y $C$ el número de clases.

import torch
import torch.nn as nn

class YOLOv1(nn.Module):
    """
    YOLO v1: grid de 7x7, cada celda predice 2 boxes y 20 clases (PASCAL VOC).
    Output: 7x7x(2*5 + 20) = 7x7x30
    """
    def __init__(self, S=7, B=2, C=20):
        super().__init__()
        self.S = S
        self.B = B
        self.C = C
        # Backbone: 24 capas convolucionales
        self.backbone = nn.Sequential(
            nn.Conv2d(3, 64, 7, stride=2, padding=3), nn.ReLU(),
            nn.MaxPool2d(2, 2),
            nn.Conv2d(64, 192, 3, padding=1), nn.ReLU(),
            nn.MaxPool2d(2, 2),
            # ... más capas ...
        )
        # Output: predice B boxes con 5 valores cada uno (x, y, w, h, conf)

        self.output = nn.Conv2d(1024, self.B * 5 + self.C, 1)

        # x: (batch, 3, 448, 448)
        features = self.backbone(x)
        out = self.output(features)
        # out: (batch, B*5+C, 7, 7)
        return out

YOLOv3-v8: Evolución Continua

YOLO ha evolucionado significativamente:

  • YOLOv3 (2018): Darknet-53, feature pyramids para detectar objetos a múltiples escalas
  • YOLOv5 (2020): más rápido, mejor accuracy, implementado en PyTorch
  • YOLOv8 (2023): anchor-free, mejor generalización, NMS mejorado
  • YOLOv10 (2024): end-to-end sin NMS, optimización para inference

Conceptos Clave en Object Detection

Intersection over Union (IoU)

Para evaluar si un bounding box predicho es correcto, usamos IoU:

$$\text{IoU} = \frac{\text{Área de intersección}}{\text{Área de unión}}$$

IoU de 1.0 es predicción perfecta, 0.0 es completamente incorrecto. Típicamente, se considera "correcto" si IoU > 0.5 (para Pascal VOC) o IoU > 0.5:0.95 (para COCO, promediando varios thresholds).

Non-Maximum Suppression (NMS)

Un objeto puede generar múltiples detecciones superpuestas. NMS selecciona la mejor:

def non_maximum_suppression(boxes, scores, iou_threshold=0.5):
    """
    Elimina boxes redundantes que se solapan demasiado.
    
    Args:
        boxes: (N, 4) en formato [x1, y1, x2, y2]
        scores: (N,) confidence scores
        iou_threshold: si dos boxes tienen IoU > threshold, eliminar la de menor score
    Returns:
        indices de boxes seleccionados
    """
    # Ordenar por score descendente
    order = scores.argsort(descending=True)
    keep = []
    
    while order.numel() > 0:
        if order.numel() == 1:
            keep.append(order[0].item())
            break
        
        # Seleccionar el de mayor score
        best_idx = order[0].item()
        keep.append(best_idx)
        
        # Calcular IoU con todos los demás
        best_box = boxes[best_idx]
        remaining_boxes = boxes[order[1:]]
        
        ious = compute_iou(best_box.unsqueeze(0), remaining_boxes)
        
        # Mantener solo boxes con IoU bajo el threshold
        mask = ious <= iou_threshold
        order = order[1:][mask]
    
    return keep

def compute_iou(box1, boxes):
    """Calcula IoU entre un box y varios boxes."""
    # box1: (1, 4), boxes: (N, 4)
    x1 = torch.max(box1[..., 0:1], boxes[..., 0:1])  # x1 del intersection
    y1 = torch.max(box1[..., 1:2], boxes[..., 1:2])
    x2 = torch.min(box1[..., 2:3], boxes[..., 2:3])
    y2 = torch.min(box1[..., 3:4], boxes[..., 3:4])
    
    intersection = (x2 - x1).clamp(0) * (y2 - y1).clamp(0)
    
    area1 = (box1[..., 2] - box1[..., 0]) * (box1[..., 3] - box1[..., 1])
    area2 = (boxes[..., 2] - boxes[..., 0]) * (boxes[..., 3] - boxes[..., 1])
    
    union = area1 + area2 - intersection
    
    return intersection / (union + 1e-6)

mAP: La Métrica Estándar

Mean Average Precision promedia la precisión a diferentes niveles de recall. Para COCO se reporta mAP@0.5:0.95 (promedio de IoU thresholds de 0.5 a 0.95). Para Pascal VOC se usa mAP@0.5.

Los 3 Errores Más Comunes

Error 1: Ignorar el balanceo de clases

El error: En datasets del mundo real, hay objetos que aparecen mucho más que otros (e.g., 90% de los boxes son "carro" y 10% "peatón"). Entrenar sin manejar esto produce un modelo que solo detecta la clase mayoritaria.

La solución: Usa focal loss en lugar de cross-entropy para classification, y asegúrate de tener suficiente data para clases minority.

Error 2: No usar data augmentation específica para detección

El error: Usar augmentation de clasificación (random crop, flip) sin ajustar los bounding boxes correspondientes. El modelo aprende con annotations incorrectas.

La solución: Asegúrate de que las transforms afecten tanto la imagen como los boxes. Libraries como albumentations lo hacen correctamente.

Error 3: Entrenar sin fine-tuning de anchors

El error: Usar los anchors por defecto sin analizar si sirven para tu dataset. Si tus objetos son mucho más pequeños o tienen aspectos diferentes, los anchors por defecto serán subóptimos.

La solución: Analiza la distribución de tus bounding boxes (área, aspect ratio) y ajusta los anchors usando k-means clustering en tus annotations.

Resumen y Cierre

Object detection pasó de pipelines complejos de 47 segundos por imagen a modelos en tiempo real que corren en dispositivos móviles. La clave fue pasar de "generar regiones y clasificar" (R-CNN) a "predecir directamente" (YOLO).

Hoy tienes herramientas como YOLOv8 que puedes usar en minutos para detectar cualquier objeto en tus imágenes. La pregunta no es si puedes hacer object detection — es qué objetos importan para tu problema y cómo consigues data suficiente para detectarlos bien.

La próxima vez que veas un auto autónomo detectando peatones en tiempo real, recuerda: detrás hay una grilla de 7x7 (o mucho más fina) prediciendo bounding boxes 30 veces por segundo. Simple en concepto, complexo en implementación.
