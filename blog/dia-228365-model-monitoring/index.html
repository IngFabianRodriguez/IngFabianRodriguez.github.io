Hagale pues, parcero. Día 228 y hoy vamos a hablar de plata — literalmente. En asesoría, el problema número uno que veo en empresas Colombianas con ML en producción no es el modelo. Es que están tirando plata por la ventana en inferencia. El 90% de los equipos que evalúo están pagando al menos 3x más de lo que deberían. Café en mano, vamos a cambiar eso.

🎯 Por Qué los Costos de ML Se Disparan en Producción

El entrenamiento es una inversión única. La inferencia es el costo recurrente. Y aquí está la matemática que nadie hace:

Costo por predicción = (Costo GPU/hora) / (Predicciones/hora con ese hardware)

Esa ecuación simple es lo que la mayoría ignora. No importa cuánto pagues por la GPU — lo que importa es cuántas predicciones rindes por peso invertido.

📐 Auto-Scaling Para ML Inference

El primer mistake que veo es dejar instancias fixed para inferencia. Esto es tirar plata:

# Auto-scaling con Kubernetes y KEDA para ML inference

        metricName: http_requests_total
        metricSelector:
          matchLabels:
            model: "nlp-classifier"
        target:
          type: AverageValue
          averageValue: "50"  # 50 requests per replica antes de escalar

El valor de `averageValue: 50` significa: si hay más de 50 requests promedio por réplica, agrega otra. Este número depende de tu modelo y latencia objetivo.

Calculando el punto óptimo de replicas

La fórmula para el número óptimo de réplicas es:

Réplicas óptimas = (Requests/segundo × Latencia promedio en segundos) / Utilización objetivo

# Script para calcular replicas optimas
def calcular_replicas_optimas(
    requests_por_segundo: float,
    latencia_p99_ms: float,
    utilizacion_objetivo: float = 0.7,
    max_replicas: int = 10
) -> dict:
    """
    Calcula réplicas óptimas para inference endpoint.
    
    Args:
        requests_por_segundo: QPS promedio durante peak
        latencia_p99_ms: Latencia P99 del modelo en milisegundos
        utilizacion_objetivo: % objetivo de utilización de GPU (default 70%)
        max_replicas: Máximo de réplicas permitidas
    
    Returns:
        Dict con análisis completo
    """
    latencia_segundos = latencia_p99_ms / 1000
    
    # Concurrencia = requests en flight
    concurrencia = requests_por_segundo * latencia_segundos
    
    # Réplicas base (sin utilización)
    replicas_base = concurrencia / utilizacion_objetivo
    
    # Redondear y limitar
    replicas_necesarias = min(max(1, int(replicas_base) + 1), max_replicas)
    
    return {
        'requests_por_segundo': requests_por_segundo,
        'latencia_p99_ms': latencia_p99_ms,
        'concurrencia': concurrencia,
        'replicas_base': replicas_base,
        'replicas_recomendadas': replicas_necesarias,
        'costo_mensual_estimado': replicas_necesarias * 730 * 0.50  # $0.50/hora por ml.m5.large
    }

# Ejemplo: modelo de NLP con 100 RPS y 150ms latencia
resultado = calcular_replicas_optimas(100, 150)
print(f"Réplicas recomendadas: {resultado['replicas_recomendadas']}")
print(f"Costo mensual estimado: ${resultado['costo_mensual_estimado']:.2f}")

🚀 Spot Instances y Preemptible VMs Para Training

El segundo mistake gigante es no usar spot instances para training. Si tu training puede tolerar interrupciones (y el 80% de los trainings pueden), estás dejando dinero en la mesa:

# AWS Spot Instances para training con checkpointing
import boto3
import time

class SpotTrainingManager:
    def __init__(self, instance_type='ml.p3.2xlarge'):
        self.ec2 = boto3.client('ec2')
        self.instance_type = instance_type
        self.checkpoint_path = 's3://mi-bucket/checkpoints/'
        
    def request_spot_instance(self, max_price='2.50'):
        """Solicita una spot instance para training."""
        response = self.ec2.request_spot_instances(
            InstanceType=self.instance_type,
            LaunchSpecification={
                'ImageId': 'ami-0c55b159cbfafe1f0',
                'InstanceType': self.instance_type,
                'Placement': {'AvailabilityZone': 'us-east-1a'}
            },
            SpotPrice=str(max_price),
            Type='persistent'  # Se reinicia automáticamente si se interrumpe
        )
        return response['SpotInstanceRequests'][0]['SpotInstanceRequestId']
    
    def calculate_savings(self, on_demand_price=3.06, spot_price=1.50, hours=100):
        """Calcula ahorro usando spot vs on-demand."""
        on_demand_total = on_demand_price * hours
        spot_total = spot_price * hours
        savings = on_demand_total - spot_total
        savings_percent = (savings / on_demand_total) * 100
        
        print(f"On-demand: ${on_demand_total:.2f}")
        print(f"Spot: ${spot_total:.2f}")
        print(f"Ahorro: ${savings:.2f} ({savings_percent:.1f}%)")
        return savings

📊 Cost Tracking Con Prometheus y Grafana

No puedes optimizar lo que no mides. El tercer error es no tener visibilidad de costo por predicción:

# Prometheus metrics para tracking de costo por prediction
# Agregar a tu inference service:

from prometheus_client import Counter, Histogram, Gauge

# Métricas de negocio
predictions_total = Counter(
    'ml_predictions_total',
    'Total de predicciones',
    ['model_name', 'model_version']
)

prediction_latency = Histogram(
    'ml_prediction_latency_seconds',
    'Latencia de predicción',
    ['model_name'],
    buckets=[0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0]
)

# Nueva métrica: costo estimado por request
cost_per_prediction = Gauge(
    'ml_cost_per_prediction_usd',
    'Costo estimado por predicción',
    ['model_name', 'instance_type']
)

# En tu código de predicción:
def predict(model, input_data):
    start = time.time()
    result = model.predict(input_data)
    latency = time.time() - start
    
    # Registrar métricas
    predictions_total.labels(model_name='nlp-classifier', model_version='v2').inc()
    prediction_latency.labels(model_name='nlp-classifier').observe(latency)
    
    # Calcular costo basado en tiempo y tipo de instancia
    costo_por_hora = {
        'ml.m5.large': 0.10,
        'ml.m5.xlarge': 0.20,
        'ml.p3.2xlarge': 3.06,  # V100
    }
    instance_type = get_current_instance_type()
    hourly_rate = costo_por_hora.get(instance_type, 0.10)
    
    # Costo = (tiempo en segundos / 3600) * costo por hora
    cost_usd = (latency / 3600) * hourly_rate
    cost_per_prediction.labels(model_name='nlp-classifier', instance_type=instance_type).set(cost_usd)
    
    return result

⚠️ Los 3 Errores Más Comunes

Error 1: No Usar Spot Instances Cuando el Training Puede Tolerar Interrupciones

El problema: Estás pagando precio completo por instancias que podrían costar 60-70% menos. Un training de 100 horas a $3/hora = $300 on-demand. Con spot: ~$90.

La solución:

# Checklist para determinar si tu training puede usar spot:
checklist_spot_friendly = {
    'checkpointing_implementado': True,  # ¿Guardas checkpoints?
    'epocas_independientes': False,       # ¿Puede continuar desde cualquier checkpoint?
    'batch_size_grande': True,            # ¿Usa batches grandes para eficiencia?
    'graceful_shutdown': True,            # ¿Maneja señales de terminación?
    'max_duration_设置': True             # ¿Tienes un tiempo máximo para limitar costos?
}

# Si 4/5 son True, tu training es spot-friendly
spot_friendly = sum(checklist_spot_friendly.values()) >= 4
print(f"¿Training es spot-friendly? {spot_friendly}")

Error 2: No Implementar Efficient Batching (Enviando 1 Request a la Vez Cuando Podrías Batch=16)

El problema: GPU utilization frustantes baja. Estás usando 1/16 de la capacidad de tu GPU porque envías requests uno por uno. Math:

Si latency por request = 10ms, entonces:

  • Sin batching: 100 requests/segundo por GPU
  • Con batch=16: 1600 requests/segundo por GPU

La solución:

# Batching dinámico para inference
import asyncio
from typing import List
import time

class DynamicBatcher:
    def __init__(self, model, max_batch_size=16, max_wait_ms=10):
        self.model = model
        self.max_batch_size = max_batch_size
        self.max_wait_ms = max_wait_ms
        self.queue = asyncio.Queue()
        
    async def add_request(self, input_data):
        future = asyncio.Future()
        await self.queue.put((input_data, future))
        return await future
    
    async def process_loop(self):
        while True:
            batch = []
            futures = []
            
            # Recolectar hasta max_batch_size o timeout
            deadline = time.time() + self.max_wait_ms / 1000
            
            while len(batch) < self.max_batch_size:
                remaining = deadline - time.time()
                if remaining <= 0:
                    break
                    
                try:
                    item = await asyncio.wait_for(
                        self.queue.get(),
                        timeout=remaining
                    )
                    batch.append(item[0])
                    futures.append(item[1])
                except asyncio.TimeoutError:
                    break
            
            if batch:
                # Procesar batch
                results = self.model.predict_batch(batch)
                for future, result in zip(futures, results):
                    future.set_result(result)

🧮 Quantization Para Reducir Costos

Finalmente, una de las herramientas más poderosas para reducir costos: quantization. Un modelo en FP32 ocupa 4 bytes por parámetro. En INT8 ocupa 1 byte. Math:

Reducción de memoria = 4x | Reducción de costo ≈ 2-4x (más predictions por GPU)

# Quantization con PyTorch
import torch
from torch.quantization import quantize_dynamic

def quantize_model(model, dtype=torch.qint8):
    """
    Cuantiza modelo dinámicamente (ideal para inference).
    Convierte pesos de float32 a int8.
    """
    quantized_model = quantize_dynamic(
        model,
        {torch.nn.Linear, torch.nn.LSTM, torch.nn.Linear},
        dtype=dtype
    )
    return quantized_model

# Verificar mejora
def measure_inference_speedup(model_fp32, model_int8, input_data):
    import time
    
    # Warm-up
    for _ in range(10):
        _ = model_fp32(input_data)
        _ = model_int8(input_data)
    
    # Medir
    iterations = 100
    
    start = time.time()
    for _ in range(iterations):
        _ = model_fp32(input_data)
    time_fp32 = time.time() - start
    
    start = time.time()
    for _ in range(iterations):
        _ = model_int8(input_data)
    time_int8 = time.time() - start
    
    speedup = time_fp32 / time_int8
    print(f"Speedup con INT8: {speedup:.2f}x más rápido")
    
    return speedup

📝 Resumen y Cierre

Para resumir lo que hemos visto:

  • Auto-scaling: No dejes instancias fixed. Usa KEDA o similar para escalar según demanda real.
  • Spot instances: 60-70% de descuento en training que puede checkpoint. No usarlos es tirar plata.
  • Batching eficiente: batch=16 puede darte 16x throughput. No enviar requests uno por uno.
  • Monitoring de costo por predicción: Si no lo mides, no lo puedes optimizar.
  • Quantization: INT8 reduce 4x la memoria y puede dar 2-4x speedup en throughput.
