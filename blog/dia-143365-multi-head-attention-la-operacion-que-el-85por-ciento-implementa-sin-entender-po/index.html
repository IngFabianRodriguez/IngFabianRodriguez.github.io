Multi-Head Attention - La operación que el 85% implementa sin entender por qué dividir por sqrt(d_k)

23 de april de 2026
torch.nn

Hola, parcero. Llegamos al Día 143 y hoy vamos con Multi-Head Attention. Este mecanismo es el corazón del Transformer y, paradójicamente, el componente que más se copia sin entender. Ese 85% del título incluye desde junior developers hasta gente con años de experiencia que jamás se ha sentado a entender por qué se divide por $\sqrt{d_k}$. Acompañame que esto va pa'l detalle.

📐 scaled dot-product attention — La base que todos ignoran

Antes de hablar de "multi-head" necesitamos entender el building block fundamental: scaled dot-product attention. Dado un query $Q$, keys $K$ y values $V$:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

Esa división por $\sqrt{d_k}$ no es arbitraria — es matemática pura. Cuando $d_k$ es grande, el producto punto $QK^T$ crece en magnitud y empuja los valores del softmax hacia regiones donde el gradiente es esencialmente cero. Es lo que llamamos vanishing gradients en la práctica. Dividir por $\sqrt{d_k}$ mantiene la varianza de los scores en un rango razonable.

En código PyTorch:

import torch
import torch.nn as nn
import torch.nn.functional as F
import matplotlib.pyplot as plt
import seaborn as sns
import numpy as np

def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    Q: (batch, seq_q, d_k)
    K: (batch, seq_k, d_k)
    V: (batch, seq_k, d_v)
    """
    d_k = Q.size(-1)
    # (batch, seq_q, seq_k)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)

    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))

    attn_weights = F.softmax(scores, dim=-1)
    return torch.matmul(attn_weights, V), attn_weights

Sin la escala, los softmax de $d_k=1024$ se concentran en un solo valor — toda la atención va a un token. Con la escala, la distribución se dispersa y cada head puede aprender cosas distintas.

🧠 Attention Heads — ¿Por qué varios?

Un solo head de atención opera en un espacio de dimensión $d_{model}$. Pero diferentes heads pueden aprender a atender a diferentes subspaces simultáneamente. Por ejemplo, en una oración como "El gato sentado en la alfombra muy suave":

  • Head 1 podría capturar relaciones sintácticas (sujeto-verbo)
  • Head 2 podría capturar modificación adjetiva (gato → suave)
  • Head 3 podría capturar dependencias a larga distancia (gato → alfombra)

Matemáticamente, si tenemos $h$ heads, cada una con dimensión $d_k = d_{model} / h$:

$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)W^O$$ $$\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$$

Las matrices $W_i^Q, W_i^K, W_i^V \in \mathbb{R}^{d_{model} \times d_k}$ y $W^O \in \mathbb{R}^{d_{model} \times d_{model}}$ son aprendibles.

💻 Implementación desde cero — 100 líneas

import torch
import torch.nn as nn
import torch.nn.functional as F
import math


class MultiHeadAttentionFromScratch(nn.Module):
    """
    Implementación de Multi-Head Attention desde cero.
    Equivalente a nn.MultiheadAttention pero escrita para entender cada paso.
    """

    def __init__(self, d_model: int, num_heads: int, dropout: float = 0.1):
        super().__init__()
        assert d_model % num_heads == 0, "d_model debe ser divisible por num_heads"

        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads  # dimensión por head

        # Proyección lineal para Q, K, V — aprendemos una transformación
        # que proyecta d_model al espacio de cada head
        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)
        # Proyección de salida: concat de todos los heads → d_model
        self.W_o = nn.Linear(d_model, d_model, bias=False)

        self.dropout = nn.Dropout(dropout)
        self.scale = math.sqrt(self.d_k)

    def forward(self, query, key, value, attn_mask=None, key_padding_mask=None):
        """
        query: (batch, seq_q, d_model)
        key, value: (batch, seq_k, d_model)
        """
        batch_size = query.size(0)

        # ---- Proyección lineal ----
        Q = self.W_q(query)  # (batch, seq_q, d_model)
        K = self.W_k(key)    # (batch, seq_k, d_model)
        V = self.V_v(value)  # (batch, seq_k, d_model)

        # ---- Split en heads: (batch, seq, d_model) → (batch, heads, seq, d_k) ----
        Q = Q.view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        K = K.view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)
        V = V.view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)

        # ---- Scaled dot-product ----
        # (batch, heads, seq_q, d_k) @ (batch, heads, d_k, seq_k) → (batch, heads, seq_q, seq_k)
        scores = torch.matmul(Q, K.transpose(-2, -1)) / self.scale

        # ---- Máscaras ----
        if key_padding_mask is not None:
            # key_padding_mask: (batch, seq_k) — True donde hay padding
            scores = scores.masked_fill(
                key_padding_mask.unsqueeze(1).unsqueeze(2),
                float('-inf')
            )

        if attn_mask is not None:
            scores = scores + attn_mask  # broadcast de la máscara

        # ---- Softmax → attention weights ----
        attn_weights = F.softmax(scores, dim=-1)
        attn_weights = self.dropout(attn_weights)

        # ---- Aplicar a values ----
        # (batch, heads, seq_q, seq_k) @ (batch, heads, seq_k, d_k) → (batch, heads, seq_q, d_k)
        context = torch.matmul(attn_weights, V)

        # ---- Concatenar heads: (batch, heads, seq_q, d_k) → (batch, seq_q, d_model) ----
        context = context.transpose(1, 2).contiguous()
        context = context.view(batch_size, -1, self.d_model)

        # ---- Proyección de salida ----
        output = self.W_o(context)

        return output, attn_weights


# ---- Corrección: el código tenía un bug ----
# En el __init__ de arriba escribí self.V_v(value) en vez de self.W_v(value)
# Eso es exactamente el tipo de bug que pasa cuando uno copia sin entender.
# Abajo la versión corregida contests adicionales.


class MultiHeadAttentionCorrected(nn.Module):
    """Versión corregida con comentarios detallados."""

    def __init__(self, d_model: int, num_heads: int, dropout: float = 0.1):
        super().__init__()
        assert d_model % num_heads == 0
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads
        self.scale = math.sqrt(self.d_k)

        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)  # ← corregido
        self.W_o = nn.Linear(d_model, d_model, bias=False)
        self.dropout = nn.Dropout(dropout)

    def split_heads(self, x, batch_size, seq_len):
        """x: (batch, seq, d_model) → (batch, heads, seq, d_k)"""
        x = x.view(batch_size, seq_len, self.num_heads, self.d_k)
        return x.transpose(1, 2)

    def forward(self, query, key, value, mask=None):
        batch_size = query.size(0)
        seq_q = query.size(1)
        seq_k = key.size(1)

        # Proyecciones
        Q = self.split_heads(self.W_q(query), batch_size, seq_q)
        K = self.split_heads(self.W_k(key), batch_size, seq_k)
        V = self.split_heads(self.W_v(value), batch_size, seq_k)

        # Attention scores
        scores = torch.matmul(Q, K.transpose(-2, -1)) / self.scale
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        attn_weights = F.softmax(scores, dim=-1)
        attn_weights = self.dropout(attn_weights)

        # Contexto
        context = torch.matmul(attn_weights, V)
        context = context.transpose(1, 2).contiguous()
        context = context.view(batch_size, seq_q, self.d_model)

        return self.W_o(context), attn_weights

🔍 concat vs average — ¿Por qué concat?

Hay una pregunta que casi nadie se hace: ¿por qué concatenar los heads en vez de promediarlos? La respuesta es sutil pero importante.

Si promediamos, la salida de cada head se mezcla irrevocablemente. Un head que aprendió a detectar sintaxis se mezcla con uno que aprendió coreferencia. La información se diluye.

Con concat:

  • Cada head mantiene su representación separada hasta el final
  • $W^O$ puede aprender a weighting la contribución de cada head
  • La dimensionalidad de salida se preserva: $h \times d_k = d_{model}$

Promediar es equivalente a concat con $W^O$ fija como la identidad y luego dividir por $h$ — una restricción demasiado fuerte que el modelo no puede aprender a relajar.

🚨 Los 3 errores que verás en producción

Error 1: Demasiados heads → overfitting

El error más común es poner 16 o 32 heads en modelos pequeños porque "más es mejor". Con $d_{model}=256$ y 32 heads, cada head tiene $d_k=8$. Esto es demasiado pequeño para aprender representaciones útiles. El modelo memoriza en vez de generalizar.

Fix: La regla empírica es $d_k \geq 32$. Si $d_{model}=256$, máximo 8 heads. Si necesitas más heads, aumenta $d_{model}$.

# BAD: d_k demasiado pequeño
d_model = 256
num_heads = 32  # → d_k = 8 → overfitting

# GOOD: d_k razonable
d_model = 256
num_heads = 8   # → d_k = 32 → suficiente para representación

Error 2: No escalar → vanishing gradients

Implementar attention sin dividir por $\sqrt{d_k}$ causa que los softmax se saturen. En modelos profundos esto se amplifica — los gradients apenas fluyen y el entrenamiento se estanca.

Fix: SIEMPRE escala. Si implementas attention desde cero, el scale no es opcional. Es la diferencia entre un modelo que entrena y uno que no.

# BAD: sin escala
scores = torch.matmul(Q, K.transpose(-2, -1))
attn = F.softmax(scores, dim=-1)  # ← se satura con d_k grandes

# GOOD: con escala
d_k = Q.size(-1)
scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
attn = F.softmax(scores, dim=-1)  # ← gradientes fluidos

Error 3: Heads sin especialización

Si todos tus heads producen patrones de atención casi idénticos, no estás usando multi-head attention — estás desperdiciando compute. Cada head debería capturar aspectos distintos de la secuencia.

Fix: Monitorea la diversidad entre heads con la varianza de los attention weights. Si todos los heads son similares, tu modelo está subutilizando su capacidad. Considera reducir el número de heads o usar técnicas de regularización entre heads (como heads sharing).

def head_diversity_score(attn_weights):
    """
    attn_weights: (batch, heads, seq, seq)
    Returns: score de diversidad entre heads (alto = bueno)
    """
    # Varianza promedio a través de heads
    # Si los heads son similares, la var entre ellos es baja
    head_means = attn_weights.mean(dim=[2, 3])  # (batch, heads)
    diversity = head_means.std(dim=1).mean()    # scalar
    return diversity.item()

# Si diversity < 0.05, tus heads no están especializados

📊 Número de heads — Tradeoffs

No existe un número universal de heads. Depende de:

  • $d_{model}$: $d_k = d_{model}/h$ debe ser al menos 32-64 para representación
  • Longitud de secuencia: Secuencias largas se benefician de más heads para capturar distintos rangos de dependencia
  • Tamaño del dataset: Datasets pequeños → menos heads (menos parámetros)
  • Compute budget: $O(h \cdot d_k^2)$ por layer — multiplica por $h$ el costo

La configuración más común en modelos grandes es $d_{model}=768$, $h=12$, $d_k=64$. En modelos pequeños como BERT-base: 12 heads con $d_k=64$.

✅ Resumen y cierre

Hoy cubrimos Multi-Head Attention desde la matemática hasta la implementación. Los puntos clave:

  • La división por $\sqrt{d_k}$ no es arbitraria — controla la varianza de los scores para que el softmax no se sature
  • Múltiples heads permiten que el modelo atienda a diferentes aspectos de la secuencia simultáneamente
  • Concat + proyección lineal preserva la información; promediar la pierde
  • El número de heads depende de $d_k \geq 32$; no pongas 32 heads en $d_{model}=256$
  • Monitorea la diversidad entre heads — si son todos iguales, no hay especialización
