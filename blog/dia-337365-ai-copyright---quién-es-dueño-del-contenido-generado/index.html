🎯 LLM Function Calling — Por Qué el 80% Lo Hace Mal

Hagale pues, parcero. Hoy es Día 337 de 365 y vamos a hablar de algo que el 80% de los desarrolladores implementa incorrectamente: LLM Function Calling. Muchos abren ChatGPT y usan plugins sin entender cómo funciona por debajo. Yo prefiero explicar la matemática y el código. Sígame.

📐 La Matemática Detrás del Function Calling

El function calling no es magia. Es un proceso de generación condicionada:

Dada una secuencia de tokens x₁, x₂, ..., xₜ, el LLM genera el siguiente token:

xₜ₊₁ = argmax P(xₜ₊₁ | x₁,...,xₜ, tools)

Donde tools son las definiciones de funciones en el prompt. El modelo no "elige" una función — aprende a generar tokens que representan una llamada a función válida según el schema.

Tool Schema Structure

{
  "name": "get_weather",
  "description": "Obtiene el clima de una ciudad",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "Ciudad para el clima"
      },
      "unit": {
        "type": "string",
        "enum": ["celsius", "fahrenheit"]
      }
    },
    "required": ["city"]
  }
}

💻 Implementación Completa del Framework

"""
Function Calling Framework — Día 337
Implementación completa con tool schemas, parsing y manejo de errores
"""
import json
import re
from typing import Any, Callable, Optional
from dataclasses import dataclass
from enum import Enum
from datetime import datetime

class ToolError(Exception):
    """Error base para herramientas"""
    pass

class ToolNotFoundError(ToolError):
    """Herramienta no encontrada"""
    pass

class ToolExecutionError(ToolError):
    """Error ejecutando la herramienta"""
    pass

class InvalidArgumentsError(ToolError):
    """Argumentos inválidos para la herramienta"""
    pass

@dataclass
class ToolCall:
    """Representa una llamada a función del LLM"""
    name: str
    arguments: dict
    call_id: str
    timestamp: datetime = None
    
    def __post_init__(self):
        if self.timestamp is None:
            self.timestamp = datetime.now()

@dataclass  
class ToolResult:
    """Resultado de ejecutar una herramienta"""
    call_id: str
    success: bool
    result: Any = None
    error: Optional[str] = None
    execution_time_ms: float = 0

class FunctionCallingFramework:
    """
    Framework completo para function calling con LLMs.
    
    El proceso es:
    1. Definir tools con schemas JSON
    2. Enviar tools + prompt al LLM
    3. Parsear la respuesta del LLM
    4. Ejecutar la función
    5. Devolver resultado al LLM
    6. Repetir si hay más llamadas en cadena
    """
    
    def __init__(self, llm_client, max_retries: int = 3):
        self.llm = llm_client
        self.tools: dict[str, Callable] = {}
        self.tool_schemas: list[dict] = []
        self.max_retries = max_retries
        self.call_history: list[ToolCall] = []
        self.execution_log: list[ToolResult] = []
    
    def register_tool(
        self,
        name: str,
        func: Callable,
        description: str,
        parameters: dict
    ):
        """Registra una herramienta con su schema"""
        self.tools[name] = func
        self.tool_schemas.append({
            "name": name,
            "description": description,
            "parameters": parameters
        })
    
    def get_tools_for_llm(self) -> list[dict]:
        """Devuelve los schemas de herramientas para el LLM"""
        return self.tool_schemas
    
    def parse_llm_response(self, response: str) -> list[ToolCall]:
        """
        Parsea la respuesta del LLM para extraer llamadas a funciones.
        
        El LLM devuelve algo como:
        <tool_call>
        {"name": "get_weather", "arguments": {"city": "Bogotá", "unit": "celsius"}, "id": "call_123"}
        </tool_call>
        """
        tool_calls = []
        
        # Patrón para extraer llamadas a función
        pattern = r'<tool_call>\s*(.*?)\s*</tool_call>'
        matches = re.findall(pattern, response, re.DOTALL)
        
        for match in matches:
            try:
                data = json.loads(match)
                tool_call = ToolCall(
                    name=data["name"],
                    arguments=data["arguments"],
                    call_id=data.get("id", f"call_{len(self.call_history)}")
                )
                tool_calls.append(tool_call)
                self.call_history.append(tool_call)
            except json.JSONDecodeError as e:
                print(f"Error parseando tool call: {e}")
                continue
        
        return tool_calls
    
    def validate_arguments(
        self, 
        tool_name: str, 
        arguments: dict,
        schema: dict
    ) -> tuple[bool, Optional[str]]:
        """
        Valida que los argumentos cumplan con el schema.
        
        Usa JSON Schema validation simplificada:
        - Verifica campos requeridos
        - Verifica tipos de datos
        - Verifica enums
        """
        props = schema.get("parameters", {}).get("properties", {})
        required = schema.get("parameters", {}).get("required", [])
        
        # Verificar campos requeridos
        for field in required:
            if field not in arguments:
                return False, f"Campo requerido faltante: {field}"
        
        # Verificar tipos y constraints
        for field, value in arguments.items():
            if field not in props:
                return False, f"Campo desconocido: {field}"
            
            field_schema = props[field]
            field_type = field_schema.get("type")
            
            # Validación de tipos
            if field_type == "string" and not isinstance(value, str):
                return False, f"{field} debe ser string, got {type(value)}"
            elif field_type == "number" and not isinstance(value, (int, float)):
                return False, f"{field} debe ser number, got {type(value)}"
            elif field_type == "boolean" and not isinstance(value, bool):
                return False, f"{field} debe ser boolean, got {type(value)}"
            elif field_type == "array" and not isinstance(value, list):
                return False, f"{field} debe ser array, got {type(value)}"
            elif field_type == "object" and not isinstance(value, dict):
                return False, f"{field} debe ser object, got {type(value)}"
            
            # Validar enum
            if "enum" in field_schema:
                if value not in field_schema["enum"]:
                    return False, f"{field} debe ser uno de {field_schema['enum']}, got {value}"
        
        return True, None
    
    def execute_tool(
        self, 
        tool_call: ToolCall,
        retry_count: int = 0
    ) -> ToolResult:
        """
        Ejecuta una herramienta con manejo de errores y retries.
        
        El retry exponential backoff:
        wait_time = base_delay * (2 ^ retry_count) + random_jitter
        """
        import time
        import random
        
        if tool_call.name not in self.tools:
            return ToolResult(
                call_id=tool_call.call_id,
                success=False,
                error=f"Herramienta no encontrada: {tool_call.name}"
            )
        
        func = self.tools[tool_call.name]
        
        # Encontrar el schema para validación
        schema = next(
            (s for s in self.tool_schemas if s["name"] == tool_call.name),
            None
        )
        
        # Validar argumentos si hay schema
        if schema:
            valid, error_msg = self.validate_arguments(
                tool_call.name,
                tool_call.arguments,
                schema
            )
            if not valid:
                return ToolResult(
                    call_id=tool_call.call_id,
                    success=False,
                    error=f"Argumentos inválidos: {error_msg}"
                )
        
        # Ejecutar con retries
        base_delay = 1.0
        last_error = None
        
        for attempt in range(self.max_retries):
            try:
                start_time = time.time()
                result = func(**tool_call.arguments)
                execution_time = (time.time() - start_time) * 1000
                
                tool_result = ToolResult(
                    call_id=tool_call.call_id,
                    success=True,
                    result=result,
                    execution_time_ms=execution_time
                )
                self.execution_log.append(tool_result)
                return tool_result
                
            except Exception as e:
                last_error = str(e)
                if attempt < self.max_retries - 1:
                    # Exponential backoff
                    delay = base_delay * (2 ** attempt) + random.uniform(0, 0.1)
                    time.sleep(delay)
        
        # Todos los retries fallaron
        return ToolResult(
            call_id=tool_call.call_id,
            success=False,
            error=f"Error después de {self.max_retries} intentos: {last_error}"
        )
    
    def execute_tool_chain(self, tool_calls: list[ToolCall]) -> list[ToolResult]:
        """Ejecuta una cadena de llamadas a funciones"""
        results = []
        for tool_call in tool_calls:
            result = self.execute_tool(tool_call)
            results.append(result)
            if not result.success:
                # Detener cadena si hay error
                break
        return results
    
    def format_results_for_llm(self, results: list[ToolResult]) -> str:
        """Formatea los resultados para enviarlos al LLM"""
        formatted = []
        for result in results:
            if result.success:
                formatted.append(
                    f"[{result.call_id}] {json.dumps(result.result)}"
                )
            else:
                formatted.append(
                    f"[{result.call_id}] ERROR: {result.error}"
                )
        return "\n".join(formatted)
    
    def call_llm_with_tools(
        self,
        messages: list[dict],
        tools: Optional[list[dict]] = None
    ) -> dict:
        """
        Hace una llamada al LLM con herramientas.
        Detecta si hay tool_calls en la respuesta y las ejecuta.
        """
        response = self.llm.chat(messages, tools=tools or self.tool_schemas)
        
        # Verificar si hay llamadas a funciones
        tool_calls = self.parse_llm_response(response.get("content", ""))
        
        if not tool_calls:
            return response
        
        # Ejecutar las herramientas
        results = self.execute_tool_chain(tool_calls)
        
        # Agregar resultados al mensaje
        messages.append({
            "role": "assistant",
            "content": response.get("content", "")
        })
        
        for tc, result in zip(tool_calls, results):
            messages.append({
                "role": "tool",
                "tool_call_id": tc.call_id,
                "content": json.dumps(result.result) if result.success else f"ERROR: {result.error}"
            })
        
        # Llamada recursiva si hay más herramientas
        return self.call_llm_with_tools(messages)


# Ejemplo de uso completo

🔄 Chaining Tool Calls — La Magia de Encadenar

El chaining de tools es cuando el LLM hace múltiples llamadas en secuencia:

# Ejemplo de cadena de tools
# 1. Buscar usuario por email
# 2. Obtener sus pedidos
# 3. Calcular total de compras

CHAIN_STEPS = [
    {"tool": "find_user", "input": "email", "output": "user_id"},
    {"tool": "get_orders", "input": "user_id", "output": "orders"},
    {"tool": "calculate_total", "input": "orders", "output": "total"}
]

# El LLM ejecuta cada paso y pasa el resultado al siguiente
def execute_chain(initial_input: dict, chain: list) -> dict:
    context = initial_input.copy()
    
    for step in chain:
        result = execute_single_tool(
            step["tool"], 
            {step["input"]: context[step["input"]]}
        )
        context[step["output"]] = result
    
    return context

⚠️ Los 3 Errores Que el 80% Comete

Error 1: No Usar Function Calling Cuando es Beneficial

El problema: Muchas aplicaciones usan prompts vagos cuando deberían usar function calling estructurado.

El escenario: En lugar de pedir "busca información del clima", el LLM podría generar código que llame directamente a una API.

La solución: Usa function calling cuando:

  • Necesitas datos estructurados y precisos
  • La acción tiene efectos secundarios (enviar email, hacer pago)
  • Quieres evitar prompts injection
  • La tarea requiere datos externos en tiempo real
# MAL: Prompt vago
messages = [{"role": "user", "content": "Busca el clima de Bogotá"}]

# BIEN: Function calling estructurado
tools = [{
    "name": "get_weather",
    "parameters": {
        "type": "object",
        "properties": {"city": {"type": "string"}},
        "required": ["city"]
    }
}]
messages = [{"role": "user", "content": "¿Qué clima hace en Bogotá?"}]

Error 2: No Definir Buenos Tool Schemas

El problema: Schemas vagos o incompletos llevan a llamadas incorrectas.

El error común: No especificar tipos, no marcar campos requeridos, descripciones ambiguas.

# MAL: Schema incompleto
{
    "name": "search",
    "parameters": {"type": "object", "properties": {"query": {}}}
}

# BIEN: Schema completo con tipos y descripciones
{
    "name": "search",
    "description": "Busca productos en el catálogo por nombre o categoría",
    "parameters": {
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "Texto de búsqueda (mínimo 2 caracteres)"
            },
            "category": {
                "type": "string",
                "enum": ["electronics", "clothing", "home", "sports"],
                "description": "Filtrar por categoría (opcional)"
            },
            "max_results": {
                "type": "integer",
                "description": "Máximo de resultados (default: 10, max: 50)",
                "default": 10
            }
        },
        "required": ["query"]
    }
}

Error 3: No Manejar Errores de Herramientas Gracefully

El problema: La herramienta falla y el sistema se rompe sin explicación útil.

El scenario: API externa caída, timeout, rate limit — y el usuario no sabe qué pasó.

# MAL: Sin manejo de errores
def handle_tool_result(result):
    return result.result  # Explota si hay error

# BIEN: Manejo completo con retries y feedback
def handle_tool_result_with_fallback(
    tool_call: ToolCall,
    framework: FunctionCallingFramework
) -> str:
    
    result = framework.execute_tool(tool_call)
    
    if result.success:
        return f"✅ {result.result}"
    
    # Clasificar el error para dar feedback útil
    error_type = classify_error(result.error)
    
    if error_type == "network":
        return ("🌐 Error de red. La API no está disponible. "
                "Intentando nuevamente...")
    elif error_type == "rate_limit":
        return ("⏳ Rate limit alcanzado. "
                "Esperando antes de reintentar...")
    elif error_type == "invalid_args":
        return (f"❌ Argumentos inválidos: {result.error}. "
                "Revisa los parámetros.")
    else:
        return (f"❌ Error inesperado: {result.error}. "
                "Contacta soporte si persiste.")
    
    return f"✅ Resultado: {result.result}"

def classify_error(error_msg: str) -> str:
    """Clasifica el tipo de error para feedback apropiado"""
    error_msg = error_msg.lower()
    if "network" in error_msg or "connection" in error_msg:
        return "network"
    elif "rate limit" in error_msg or "429" in error_msg:
        return "rate_limit"
    elif "invalid" in error_msg or "required" in error_msg:
        return "invalid_args"
    return "unknown"

📊 Resumen y Cierre

El 80% hace function calling mal porque:

  • No entiende que es generación condicionada, no magia
  • Define tool schemas incompletos sin tipos ni descripciones
  • No maneja errores y deja al usuario sin feedback

El 20% que lo hace bien:

  • Diseña schemas completos con validación
  • Implementa retries con exponential backoff
  • Da feedback claro según el tipo de error
  • Encadena tools cuando la tarea lo requiere

La matemática es simple: el LLM genera tokens condicionados a las tool definitions. La implementación es compleja: necesitas validación, retries, encadenamiento, y feedback. Pero eso es lo que separa al 80% del 20%.
