QLoRA — Fine-tuning Cuantizado

09 de noviembre de 2026
qlorafine-tuningquantizationlora

Intro — Fine-tuning Accesible

Qué tal, parce. Día 313. Hoy vamos a hablar de QLoRA, que es como hacer fine-tuning de un modelo grande pero sin necesitar una GPU del tamaño de una nevera. QLoRA = Quantized Low-Rank Adaptation, y es la técnica que permitió que personas como usted y como yo podamos afinar modelos de 7B, 13B, incluso 70B parámetros en una sola GPU de 24GB.

El problema con fine-tuning normal es que requiere actualizar TODOS los parámetros del modelo. Si su modelo tiene 7 mil millones de parámetros, está actualizando 7B números. QLoRA reduce dramáticamente ese costo.

La Magia de QLoRA

QLoRA combina tres tricks en uno:

  • Quantization: Reducir la precisión de los pesos de 16-bit a 4-bit
  • Low-Rank Adaptation: Solo entrenar adapters pequeños, no el modelo completo
  • Double Quantization: Cuantizar también los factores de cuantización
  • Paged Optimizers: Manejar memoria de forma inteligente

La fórmula clave:

$$h = W_0 x + \Delta W x = W_0 x + BAx$$

donde $W_0$ está congelado y solo $A$ y $B$ se entrenan. Esto reduce parámetros de $\Delta W \in \mathbb{R}^{d \times k}$ a solo $A \in \mathbb{R}^{r \times k}$ y $B \in \mathbb{R}^{d \times r}$ donde $r \ll \min(d, k)$.

4-Bit NormalFloat Quantization

QLoRA usa NF4 (4-bit NormalFloat), un tipo de cuantización óptimo para pesos normalmente distribuidos:

$$\text{NF4}[i] = \text{sign}(x) \cdot \frac{-Q[i] + Q[i+1]}{2}$$

El proceso de cuantización:

def quantize_nf4(tensor, quantile_boundaries):
    """
    Cuantiza tensor a 4-bit NormalFloat.
    """
    # Calcular cuantiles para 16 valores (4-bit = 2^4 = 16 niveles)
    num_bits = 4
    num_values = 2 ** num_bits  # 16 niveles
    
    # Cuantiles igualmente espaciados
    quantiles = torch.linspace(0, 1, num_values + 1)
    
    # Boundarios basados en la distribución de los datos
    boundaries = torch.quantile(tensor.abs(), quantiles[1:-1])
    
    # Asignar cada valor a un nivel
    indexes = torch.bucketize(tensor.abs(), boundaries)
    
    # Escalar para el rango NF4
    qtensor = (indexes.float() - 7.5) / 7.5  # Normalizar a [-1, 1]
    
    return qtensor * tensor.sign()

Implementación con bitsandbytes

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# Configuración de cuantización 4-bit
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",  # NormalFloat4
    bnb_4bit_compute_dtype=torch.bfloat16,
)

# Cargar modelo cuantizado
model_name = "meta-llama/Llama-2-7b-hf"
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto",
    trust_remote_code=True
)

# Preparar para entrenamiento con k-bit
model = prepare_model_for_kbit_training(model)

# Configurar LoRA
lora_config = LoraConfig(
    r=64,  # Rank de adaptación
    lora_alpha=16,  # Scaling factor
    target_modules=[  # Módulos a adaptar
        "q_proj",
        "v_proj",
        "k_proj",
        "o_proj",
        "gate_proj",
        "up_proj",
        "down_proj"
    ],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

# Aplicar LoRA al modelo
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()

Double Quantization

QLoRA también cuantiza los constante de cuantización (los valores de normalización). Esto puede parecer overkill pero ahorra memoria adicional:

# Double quantization: también cuantizar los cambios de cuantización
class DoubleQuantize:
    def __init__(self, nbits=4):
        self.nbits = nbits
        self.block_size = 64  # Tamaño de bloque para cuantización
    
    def quantize(self, weights):
        # Primera cuantización: pesos a 4-bit
        qweights, scale = self.first_quant(weights)
        
        # Cuantizar el scale también (double quantization)
        qscale = self.second_quant(scale)
        
        return qweights, qscale
    
    def second_quant(self, scale):
        # Cuantizar los valores de escala a 8-bit
        # Esto reduce la memoria de normalización
        scale_abs = scale.abs()
        max_val = scale_abs.max()
        scale_int = (scale_abs / max_val * 127).round().to(torch.int8)
        return scale_int, max_val / 127

Comparación de Memoria

El ahorro de memoria es dramático:

  • Fine-tuning normal (7B): ~28GB GPU
  • QLoRA (7B): ~6GB GPU
  • Fine-tuning normal (65B): >400GB (imposible en una sola GPU)
  • QLoRA (65B): ~48GB GPU

Errores Comunes

Error 1: Usar el Wrong Rank

El error: Usar rank=8 porque "menos es más rápido". El modelo no aprende lo suficiente.

El fix: Rank 64 es un buen default para la mayoría de casos. Para modelos pequeños, incluso rank 128 puede ser necesario.

Error 2: No Usar bf16

El error: Usar fp16 para el entrenamiento. Esto causa overflow en gradientes grandes.

El fix: Usa bf16 (brain float 16) para el entrenamiento. Es más estable.

Error 3: target_modules Incompletos

El error: Solo adaptar q_proj y v_proj como se sugiere en tutoriales básicos.

El fix: Adapta todos los módulos de atención + los MLP layers (gate_proj, up_proj, down_proj) para mejor calidad.

Resumen

QLoRA es como el servicio de maleteros del fine-tuning: reduce el peso sin perder calidad.

  • Cuantización NF4: 4-bit con distribución normal óptima
  • Low-rank adapters: Solo entrenar pequeños incrementos
  • Double quantization: Cuantizar también los cuantizadores
  • Paged optimizers: Manejo inteligente de memoria
