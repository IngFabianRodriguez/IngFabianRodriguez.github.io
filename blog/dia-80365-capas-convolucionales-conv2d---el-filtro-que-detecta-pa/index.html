Capas Convolucionales (Conv2D) - El Filtro que Detecta Patrones Visuales sin Que le Explique Qué es un Gato

6 de marzo de 2026
nn.Conv2dfiltersstridespaddingfeature mapskernels

Mirá, parce, yo antes pensaba que las redes neuronales eran magia pura hasta que entendí las capas convolucionales. ¿Cómo es que un filtro de 3×3 puede detectar bordes, texturas, y hasta hocicos de gato sin que nadie le diga qué es un gato? La respuesta es beautiful en su simplicidad: la convolución no sabe qué detecta — simplemente optimiza los filtros para minimizar la pérdida. Si el mejor patrón para distinguir un gato de un perro resulta ser un hocico, el filtro aprenderá a detectar hocicos. El 85% de los practitioners usa Conv2D sin entender qué está pasando debajo: el output size, cómo elegir kernel size, por qué a veces se usan strides de 2. Hoy desmitificamos la convolución: la matemática, los hiperparámetros, y los errores que el 85% comete implementándola.

## 🎯 ¿Cómo Detecta un Filtro 3×3 Patrones Complejos sin Saber Qué Son? **Definición técnica:** Una capa convolucional aplica $K$ filtros (kernels) de tamaño $H \times W \times C_{in}$ que se deslizan sobre el input tensor $(B, H_{in}, W_{in}, C_{in})$ con stride $S$ y padding $P$, produciendo feature maps de $(B, H_{out}, W_{out}, K)$. Cada filtro aprende a activar (alta respuesta) cuando detecta su patrón específico. **Tipos:** - **Conv2d**: 2D spatial convolution sobre imágenes. Filtro de $(k_h, k_w)$ se desliza en las dos dimensiones espaciales. - **Conv1d**: Para secuencias temporales o texto. Filtro de longitud $k$ se desliza en una dimensión (tiempo o tokens). - **Conv3d**: Para volúmenes 3D (video, CT scans). Filtro de $(k_d, k_h, k_w)$ se desliza en tres dimensiones. - **Depthwise Separable Conv**: Descompone la convolución en depthwise (un filtro por canal) + pointwise (1×1 para mezclar canales). 8-9x menos parámetros y cómputo. - **Transposed Conv (Deconv)**: Convolution al revés — upsampling. Se usa en decoders de U-Net, GANs, super-resolution. **Imaginá**: Es como si tuvieras una lupa de 3×3 que solo ve 9 pixels a la vez, y puedes tener 64 lupas distintas. Cada lupa está entrenada para brillar más cuando ve un patrón específico: una lupa detecta bordes horizontales, otra verticales, otra curvas... y cuando las combinas, puedes detectar \"gato\" emergentemente, aunque ninguna lupa sepa qué es un gato. ## 📐 La Ecuación de la Convolución 2D — LA JOYA Esta ecuación es la base de toda la visión por computadora moderna — desde ResNet hasta YOLO: $$ Y_{b,i,j,k} = \sum_{c=1}^{C_{in}} \sum_{p=1}^{k_h} \sum_{q=1}^{k_w} K_{p,q,c,k} \cdot X_{b, i+p, j+q, c} + B_k $$ "Para cada batch $b$, posición de output $(i,j)$, y filtro $k$,sumamos el producto elemento a elemento del kernel $K$ con la ventana de input centrada en $(i,j)$." **Descomposición:** $$ Y_{b,i,j,k} = \text{Conv2D}(X, K, S, P)_{b,i,j,k} = \sum_{\text{canales}} \sum_{\text{espacio}} K \cdot \text{ventana}(X, i, j, S, P) + B_k $$ **Output spatial size:** $$ H_{out} = \left\lfloor \frac{H_{in} + 2P - k_h}{S} \right\rfloor + 1, \quad W_{out} = \left\lfloor \frac{W_{in} + 2P - k_w}{S} \right\rfloor + 1 $$ **$K_{p,q,c,k}$** = weights del filtro $k$, posición $(p,q)$, canal $c$ **$B_k$** = bias del filtro $k$ **$S$** = stride (cuántos pixels se mueve el kernel por step) **$P$** = padding (zeros agregados alrededor del input) **$k_h, k_w$** = altura y ancho del kernel ### Número de Parámetros de una Conv2d $$ \text{params} = k_h \times k_w \times C_{in} \times K + K $$ Para $k=3, C_{in}=3, K=64$: $3 \times 3 \times 3 \times 64 + 64 = 1,792$ parámetros. ### Dilated (Atrous) Convolution Abre el kernel sin aumentar parameters: $$ Y_{b,i,j,k} = \sum_{c=1}^{C_{in}} \sum_{p=1}^{k_h} \sum_{q=1}^{k_w} K_{p,q,c,k} \cdot X_{b, i + d\cdot p, j + d\cdot q, c} $$ $d$ es el dilation rate. Con $d=2$, el kernel de 3×3 \"ve\" un área de 5×5 con solo 9 parameters. Útil para semantic segmentation sin perder resolución. Ejemplo numérico concreto: ```python import torch import torch.nn as nn import logging from dataclasses import dataclass logging.basicConfig(level=logging.INFO) logger = logging.getLogger(__name__) @dataclass class Conv2dConfig: """Configuración de una capa convolucional.""" in_channels: int out_channels: int kernel_size: int | tuple[int, int] stride: int | tuple[int, int] = 1 padding: int | tuple[int, int] = 0 @property def num_params(self) -> int: k_h, k_w = (self.kernel_size, self.kernel_size) if isinstance(self.kernel_size, int) else self.kernel_size return k_h * k_w * self.in_channels * self.out_channels + self.out_channels class ConvNet(nn.Module): """Red convolucional simple para clasificación de imágenes.""" def __init__(self, in_channels: int = 3, num_classes: int = 10): super().__init__() # Feature extraction: 3 blocks de conv + BN + ReLU + pool self.features = nn.Sequential( # Block 1: 224x224 -> 112x112 nn.Conv2d(in_channels, 64, kernel_size=3, stride=1, padding=1), nn.BatchNorm2d(64), nn.ReLU(), nn.MaxPool2d(kernel_size=2, stride=2), # Block 2: 112x112 -> 56x56 nn.Conv2d(64, 128, kernel_size=3, stride=1, padding=1), nn.BatchNorm2d(128), nn.ReLU(), nn.MaxPool2d(kernel_size=2, stride=2), # Block 3: 56x56 -> 28x28 nn.Conv2d(128, 256, kernel_size=3, stride=1, padding=1), nn.BatchNorm2d(256), nn.ReLU(), nn.MaxPool2d(kernel_size=2, stride=2), ) # Classifier self.classifier = nn.Sequential( nn.AdaptiveAvgPool2d((1, 1)), # Global average pooling nn.Flatten(), nn.Linear(256, num_classes), ) self._init_weights() def _init_weights(self): for m in self.modules(): if isinstance(m, nn.Conv2d): nn.init.kaiming_normal_(m.weight, mode='fan_out', nonlinearity='relu') if m.bias is not None: nn.init.constant_(m.bias, 0) logger.info("Initialized ConvNet weights with Kaiming initialization") def forward(self, x: torch.Tensor) -> torch.Tensor: """ Args: x: (batch, channels, height, width) Returns: (batch, num_classes) """ x = self.features(x) x = self.classifier(x) return x def compute_output_size(H_in: int, W_in: int, cfg: Conv2dConfig) -> tuple[int, int]: """Calcula el output size de una convolución.""" k_h = cfg.kernel_size if isinstance(cfg.kernel_size, int) else cfg.kernel_size[0] k_w = cfg.kernel_size if isinstance(cfg.kernel_size, int) else cfg.kernel_size[1] S_h = cfg.stride if isinstance(cfg.stride, int) else cfg.stride[0] S_w = cfg.stride if isinstance(cfg.stride, int) else cfg.stride[1] P_h = cfg.padding if isinstance(cfg.padding, int) else cfg.padding[0] P_w = cfg.padding if isinstance(cfg.padding, int) else cfg.padding[1] H_out = (H_in + 2 * P_h - k_h) // S_h + 1 W_out = (W_in + 2 * P_w - k_w) // S_w + 1 return H_out, W_out if __name__ == '__main__': # Config example cfg = Conv2dConfig(in_channels=3, out_channels=64, kernel_size=3, stride=1, padding=1) logger.info(f"Conv2dConfig: {cfg}") logger.info(f"Number of parameters: {cfg.num_params}") # Test forward pass model = ConvNet(in_channels=3, num_classes=10) x = torch.randn(4, 3, 224, 224) # batch=4, 3 canales, 224x224 out = model(x) logger.info(f"Input shape: {x.shape} -> Output shape: {out.shape}") # Verify output size formula cfg2 = Conv2dConfig(in_channels=3, out_channels=64, kernel_size=3, stride=2, padding=1) H_out, W_out = compute_output_size(224, 224, cfg2) logger.info(f"With stride=2, padding=1: output size = {H_out}x{W_out}") ``` ## 🚨 Errores Comunes (y Cómo No Cagarla) **Error 1: Confusion entre stride y kernel size para downsampling** **El problema**: Stride y kernel size cumplen roles distintos pero el 85% los confunde. Stride controla cómo se mueve el kernel. Kernel size controla cuántos pixels ve a la vez. Con stride=2 y kernel=3, el output es la mitad del input. Pero muchos usan stride=1 con kernel=3 y luego se preguntan por qué el output tiene el mismo tamaño. ❌ ```python nn.Conv2d(64, 128, kernel_size=3, stride=1, padding=1) # Output size = same as input (224->224) # ¿Esperabas downsampling? Necesitas stride=2 ``` **Por qué falla**: Sin stride adecuado, no hay downsampling. La imagen mantiene el mismo tamaño espacial a través de las capas, haciendo la red computacionalmente cara sin necesidad. $$ H_{out} = \left\lfloor \frac{224 + 2(1) - 3}{1} \right\rfloor + 1 = 224 $$ ✓ ```python # Para downsampling: stride = 2 nn.Conv2d(64, 128, kernel_size=3, stride=2, padding=1) # Output: (224 + 2 - 3) / 2 + 1 = 112 # O usa MaxPool explícitamente: nn.MaxPool2d(kernel_size=2, stride=2) ``` **Error 2: Padding incorrecto导致 output size wrong** **El problema**: Si no usas padding, la imagen se shrink con cada convolución. Para mantener el tamaño espacial, necesitas padding = (kernel_size - 1) / 2. Con kernel=3, padding=1; kernel=5, padding=2. ❌ ```python nn.Conv2d(3, 64, kernel_size=3, stride=1, padding=0) # Input: 224x224 -> Output: 222x222 (se shrinks 1 pixel per side) ``` **Por qué falla**: Cada conv reduce el spatial size por $k_h - 1$ en cada dimensión. Sin padding, después de 3 capas conv ya perdiste 6 pixels por lado — la información del borde se descarta. $$ H_{out} = \left\lfloor \frac{224 + 0 - 3}{1} \right\rfloor + 1 = 222 $$ ✓ ```python # Padding correcto para mantener tamaño nn.Conv2d(3, 64, kernel_size=3, stride=1, padding=1) # Input: 224x224 -> Output: 224x224 # Fórmula: (224 + 2*1 - 3) / 1 + 1 = 224 ``` **Error 3: No usar suficientes canales en capas profundas** **El problema**: Las capas tempranas detectan patrones simples (bordes, texturas) y necesitan pocos canales. Las capas profundas detectan patrones complejos y necesitan muchos más. Poner el mismo número de canales en todas partes es ineficiente. ❌ ```python nn.Sequential( nn.Conv2d(3, 32, 3, padding=1), # Muy pocos canales para la primera capa nn.Conv2d(32, 32, 3, padding=1), # Misma cantidad — no hay "depth" nn.Conv2d(32, 32, 3, padding=1), ) ``` **Por qué falla**: Con 32 canales en todas partes, la red tiene poca capacidad para representar features complejos en capas profundas. Típicamente los canales se duplican: 64→128→256→512. ✓ ```python nn.Sequential( nn.Conv2d(3, 64, 3, padding=1), nn.Conv2d(64, 128, 3, padding=1), # Duplicar canales nn.Conv2d(128, 256, 3, padding=1), # Duplicar de nuevo ) ``` **Error 4: No usar depthwise separable convolution para models pequeños** **El problema**: Una Conv2d normal con kernel 3×3 tiene $k_h \times k_w \times C_{in} \times C_{out}$ parameters. Para $C_{in}=512, C_{out}=512$, eso son $3 \times 3 \times 512 \times 512 = 2,359,296$ parameters solo para esa capa. ❌ ```python # Conv normal: 2.3M parámetros nn.Conv2d(512, 512, kernel_size=3, padding=1) ``` **Por qué falla**: Demasiados parámetros para modelos en dispositivos móviles o embebidos. La red memoriza en vez de generalizar. ✓ ```python # Depthwise separable: 9 * 512 + 512 * 512 = 4,608 + 262,144 = 266,752 # ~9x menos parámetros con几乎 la misma accuracy nn.Sequential( nn.Conv2d(512, 512, kernel_size=3, padding=1, groups=512), # Depthwise nn.Conv2d(512, 512, kernel_size=1), # Pointwise 1x1 ) ``` --- ## 🎯 Resumen Ejecutivo Conv2D no es "aplicar filtros que detectan bordes". Es resolver: $$Y_{b,i,j,k} = \sum_c \sum_{p,q} K_{p,q,c,k} \cdot X_{b, i+p, j+q, c} + B_k$$ Mediante: deslizar $K$ filtros aprendibles sobre el tensor de input con stride y padding configurables. - **Output size**: $H_{out} = \lfloor (H_{in} + 2P - k_h) / S \rfloor + 1$. Verifica siempre que el output sea el esperado. - **Stride vs kernel size**: Stride=2 para downsampling. Kernel size para \"zoom\" del área receptiva. - **Padding**: Usa padding = (k-1)/2 para mantener el spatial size con stride=1. - **Canales por capa**: Duplica los canales en cada downsampling: 64→128→256→512. - **Depthwise separable**: Para modelos ligeros, descompón conv en depthwise (filtra por canal) + pointwise (mezcla canales). ~9x menos params. - **Pooling**: MaxPool para invariance a traducción. AdaptiveAvgPool para reducir a vector fijo. Parcero, Conv2D es la base de toda la visión por computadora moderna. Lo elegante es que los filtros no saben qué detectan — simplemente se optimizan para minimizar la pérdida. Si \"detectar hocico\" resulta útil para clasificar gatos vs perros, el filtro aprenderá hocicos emergentemente. Por eso el 85% se confunde: quieren explicarle a la red qué es un gato, cuando en realidad solo necesitas muchos datos y la arquitectura correcta deja que los filtros aprendan solos. La próxima vez que veas una Conv2d y no entiendas por qué tiene kernel=3, stride=1, padding=1... ya sabes que es para mantener el spatial size mientras se extraen features. ¡Nos vemos en el día 81!
