Regularización L1 y L2 - Por Qué tu Modelo Necesita Restricciones para No Sobreajustar

La Intro que el 85% Se Salta

Parcero, ¿cuántas veces has visto que tu modelo tiene 95% de accuracy en training pero 78% en test? Eso es overfitting puro, y la regularización es la herramienta principal para combatirlo. Después de 12 años en este juego, te cuento que el 85% sabe que L1 y L2 "son para regularizar" pero no sabe cómo funcionan realmente, cuándo usar cada una, ni cómo interactúan con el optimizador.

Yo lo aprendí de la manera más dolorosa: estaba haciendo feature selection para un modelo de churn prediction con 300 features categóricos. Intenté L1 (Lasso) para hacer feature selection automático. Después de 3 horas de debugging, descubrí que mi implementación estaba haciendo L2 (Ridge) sin saberlo — porque en SGD, weight decay y L2 son matemáticamente equivalentes.

Hoy destapamos L1 y L2: la matemática real, cuándo usar cada una, y los errores que te hacen perder semanas. ¡Presta atención que esto vale oro!

🎯 ¿Tu Modelo Memoriza en Vez de Aprender?

Definición: La regularización es cualquier modificación al training que busca reducir test error a cambio de quizás un poco más training error. Añade un término a la loss que penaliza la complejidad del modelo.

Tipos:

  • L2 (Ridge): Penaliza la norma Euclidiana al cuadrado. Shrinka los pesos suavemente hacia cero pero NUNCA los hace exactamente cero. Geométricamente, constraint el espacio a una esfera.
  • L1 (Lasso): Penaliza la suma de valores absolutos. Hace subset selection automático — muchos coeficientes terminan siendo EXACTAMENTE cero. Geométricamente, constraint a un politopo (octaedro en alta dimensión).

Mirá la diferencia clave: L2 reduce todos los pesos por igual (como encoger); L1 mata los pesos insignificantes directamente (como podar ramas secas).

📐 La Ecuación de la Regularización — LA JOYA

Esta ecuación parece simple pero tiene TODO el poder de transformar un modelo que overfitea en uno que generaliza:

$$ \mathcal{L}_{reg}(\theta) = \mathcal{L}(\theta) + \lambda R(\theta) $$

Descomposición:

  • $\mathcal{L}(\theta)$ = loss original (MSE, cross-entropy, etc.)
  • $R(\theta)$ = función de regularización (L1 o L2)
  • $\lambda$ = hyperparámetro que controla cuánto penalizamos la complejidad

Ejemplo numérico:


import numpy as np
from dataclasses import dataclass
from typing import Literal, Optional
import logging

logger = logging.getLogger(__name__)


@dataclass
class RegularizationResult:
    """Resultado de regularización con metadatos."""
    theta: np.ndarray
    non_zero_count: int
    lambda_used: float
    reg_type: str


def regularized_loss(
    theta: np.ndarray,
    loss_fn: callable,
    X: np.ndarray,
    y: np.ndarray,
    reg_type: Literal['l1', 'l2'] = 'l2',
    lambda_reg: float = 0.1,
) -> float:
    """Calcula loss con regularización L1 o L2."""
    base_loss = loss_fn(theta, X, y)
    if reg_type == 'l2':
        reg_term = (lambda_reg / 2) * np.sum(theta ** 2)
        logger.debug(f"L2 reg term: {reg_term:.4f}")
    elif reg_type == 'l1':
        reg_term = lambda_reg * np.sum(np.abs(theta))
        logger.debug(f"L1 reg term: {reg_term:.4f}")
    else:
        reg_term = 0.0
        logger.warning(f"Unknown reg_type: {reg_type}, no regularization applied")
    return base_loss + reg_term


def ridge_solution(X: np.ndarray, y: np.ndarray, lambda_reg: float) -> np.ndarray:
    """Solución analítica para Ridge (L2) regression."""
    return np.linalg.solve(X.T @ X + lambda_reg * np.eye(X.shape[1]), X.T @ y)


def lasso_solution(
    X: np.ndarray,
    y: np.ndarray,
    lambda_reg: float,
    max_iter: int = 1000,
    tol: float = 1e-6,
) -> np.ndarray:
    """Solución numérica para Lasso (L1) usando coordinate descent."""
    n_features = X.shape[1]
    theta = np.zeros(n_features)
    XtX = X.T @ X
    Xty = X.T @ y

    for _ in range(max_iter):
        theta_old = theta.copy()
        for j in range(n_features):
            residual = Xty[j] - XtX[j, :] @ theta + XtX[j, j] * theta[j]
            rho_j = residual
            if rho_j > lambda_reg:
                theta[j] = rho_j - lambda_reg
            elif rho_j < -lambda_reg:
                theta[j] = rho_j + lambda_reg
            else:
                theta[j] = 0.0

        if np.max(np.abs(theta - theta_old)) < tol:
            break

    return theta


# Demo
np.random.seed(42)
n_samples, n_features = 100, 10
X = np.random.randn(n_samples, n_features)
true_theta = np.array([3, -1, 0.5, 0, 0, 0, 0, 0, 0, 0])
y = X @ true_theta + 0.1 * np.random.randn(n_samples)

logger.info("Comparing OLS vs Ridge vs Lasso")
theta_ridge = ridge_solution(X, y, lambda_reg=1.0)
theta_lasso = lasso_solution(X, y, lambda_reg=0.5)
theta_ols = ridge_solution(X, y, lambda_reg=0.0)

print(f"OLS (λ=0):            {theta_ols.round(3)}")
print(f"Ridge (λ=1.0):         {theta_ridge.round(3)}")
print(f"Lasso (λ=0.5):         {theta_lasso.round(3)}")
print(f"True theta:           {true_theta}")
print(f"\nNon-zero: OLS={np.sum(theta_ols != 0)}, Ridge={np.sum(theta_ridge != 0)}, Lasso={np.sum(theta_lasso != 0)}")

🚨 Errores Comunes (y Cómo No Cagarla)

Error 1: L2 en SGD = Weight Decay pero L2 en Adam ≠ Weight Decay

El problema: En SGD (con momentum), añadir $\lambda \|w\|_2^2$ a la loss y usar weight_decay en el optimizer producen el mismo gradiente. En Adam, NO. weight_decay de Adam aplica el decay uniformemente (resta $\lambda w$), no como L2 (que escala el gradiente por $w$ en el segundo momento).

❌ # Esto NO es L2 regularization real en Adam!
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=0.01)

Por qué falla: En Adam, el weight_decay se aplica como $w \leftarrow w - \eta \cdot \text{sign}(w) \cdot \lambda$, no como gradiente del término $\lambda \|w\|_2^2$.

$$ \nabla_w (\lambda \|w\|_2^2) = 2\lambda w \quad \text{(L2 real)} $$

AdamW resta $\lambda \cdot \text{sign}(w)$, que no es lo mismo.

✓ # AdamW SI implementa weight decay correctamente (similar a L2 en SGD)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)

Error 2: No normalizar los features antes de aplicar L1/L2

El problema: La regularización penaliza los coeficientes $\theta_i$ por igual. Si feature $i$ tiene escala 1000 y feature $j$ tiene escala 0.001, penalizar $|\theta_i|$ y $|\theta_j|$ por igual no tiene sentido físico. El modelo va a querer shrinkear el feature de escala pequeña para no penalizar tanto.

❌ # X_raw tiene features en escalas completamente diferentes
model = Lasso(alpha=0.1)
model.fit(X_raw, y)

Por qué falla: La penalización $\|w\|_1$ o $\|w\|_2^2$ no sabe nada de las escalas de los features. Un coeficiente grande en escala significa algo diferente que uno pequeño.

✓ # CORRECTO: normalizar primero
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_raw)
model = Lasso(alpha=0.1)
model.fit(X_scaled, y)

Error 3: Elegir alpha por trial-and-error sin CV

El problema: El 85% hace model = Lasso(alpha=0.1) porque "se ve bien" sin hacer cross-validation. Pero alpha tiene un efecto dramático en sparsity y generalización. Un alpha muy alto = underfitting; muy bajo = overfitting.

❌ # "este se ve bien" — sin CV esto es gambling
model = Lasso(alpha=0.1)
model.fit(X_train, y_train)

Por qué falla: Sin CV, no tienes idea de qué alpha généraliza mejor. Y el "se ve bien" es subjetivo — puede ser que simplemente overfiteaste el training set menos visiblemente.

✓ # CORRECTO: usar LassoCV para seleccionar alpha automáticamente
from sklearn.linear_model import LassoCV
model = LassoCV(alphas=np.logspace(-4, 1, 50), cv=5, max_iter=10000)
model.fit(X_train, y_train)
print(f"Mejor alpha: {model.alpha_:.6f}")

🎯 Resumen Ejecutivo

Regularización L1/L2 no es "añadir una penalización a la loss".

Es resolver: $$ \min_\theta \mathcal{L}(\theta) + \lambda R(\theta) $$

Mediante: $$ R_{L2} = \frac{1}{2}\|\theta\|_2^2 \quad \text{o} \quad R_{L1} = \|\theta\|_1 $$

  • L2 (Ridge): Shrinka todos los pesos suavemente. Mejor cuando tienes features correlacionados y no quieres feature selection.
  • L1 (Lasso): Hace subset selection automático — muchos pesos quedan exactamente en zero = sparse model = interpretabilidad.
  • Elastic Net: Combina L1 + L2 cuando quieres sparsity Y tienes features correlacionados.
  • Weight Decay: En SGD = L2. En AdamW ≈ L2 (correcto). En Adam vanilla ≠ L2 real.
  • Siempre normalizar: StandardScaler antes de aplicar regularización — sin esto, la penalización no tiene sentido físico.

Parcero, L1 y L2 son las regularizaciones más básicas y efectivas que tienes. L1 para hacer feature selection cuando sabes (o sospechas) que la mayoría de features son ruido. L2 para mejorar generalización cuando tienes buenos features pero tu modelo es demasiado complejo. Y si no estás seguro, usa Elastic Net. Recuerda: ninguna regularización reemplaza data buena. ¡Nos vemos en el día 78!
