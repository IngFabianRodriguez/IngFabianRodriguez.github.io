Hola, parcero. Hoy llegamos al Dia 169 y vamos con un tema que me preguntan cada semana en el grupo de machine learning de Bogota: fine-tuneo el modelo o uso RAG? La respuesta no es trivial y el 70% de los equipos que veo comete al menos uno de los tres errores que cubriremos aqui. Acompaname con la taza de cafe porque esto se pone matematico.

Fundamentos: La matematica que decide por ti

Antes de escribir una sola linea de codigo, necesitamos la formula que va a gobernar nuestra decision. La eleccion entre fine-tuning y RAG depende de tres variables fundamentales:

La entropia de tarea $H(T)$ mide cuanta variacion hay en el tipo de respuestas que esperas. Una tarea de clasificacion binaria tiene baja entropia; una de generacion creativa la tiene altisima.

La razon de conocimiento $R_k = \frac{K_{dinamico}}{K_{estatico}}$ compara tu conocimiento que cambia frecuentemente (precios, noticias, documentos) contra el conocimiento estable (terminos tecnicos, formatos).

La complejidad de formato $F$ mide cuan especifico es el estilo de salida que necesitas: JSON estricto vs. texto libre, por ejemplo.

La funcion de decision es:

$$D = \alpha \cdot H(T) + \beta \cdot R_k + \gamma \cdot F$$

Donde $\alpha, \beta, \gamma$ son pesos que calibras segun tu caso. Si $D > \tau$ (un umbral que tu defines), usa RAG. Si $D < \tau$, considera fine-tuning. Y si $R_k$ es muy alto Y $F$ es alto, vas por un enfoque hibrido.

Implementacion: RAG Pipeline con LangChain

Vamos con codigo real. Implementemos un RAG pipeline completo que puedas adaptar:

"""
RAG Pipeline con LangChain - Dia 169
Arquitectura: Embedding -> Vector Store -> Retrieval -> Generation
"""
import os
from langchain_community.document_loaders import PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain.chains import RetrievalQA
from langchain.prompts import PromptTemplate

# 1. Carga de documentos
def load_documents(pdf_path: str):
    loader = PyPDFLoader(pdf_path)
    documents = loader.load()
    return documents

# 2. Chunking estrategico
def split_documents(documents, chunk_size=1000, chunk_overlap=200):
    text_splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        separators=["\n\n", "\n", " ", ""]
    )
    chunks = text_splitter.split_documents(documents)
    return chunks

# 3. Embedding y vector store
def create_vector_store(chunks, persist_directory="./chroma_db"):
    embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
    vector_store = Chroma.from_documents(
        documents=chunks,
        embedding=embeddings,
        persist_directory=persist_directory
    )
    return vector_store

# 4. Retrieval con similarity score threshold
def retrieve_context(vector_store, query: str, k=5, similarity_threshold=0.7):
    docs = vector_store.similarity_search_with_score(query, k=k)
    filtered_docs = [doc for doc, score in docs if score < (1 - similarity_threshold)]
    return filtered_docs

# 5. Generacion con prompt personalizado
def create_rag_chain(vector_store, model_name="gpt-4o"):
    llm = ChatOpenAI(model=model_name, temperature=0.3)

    prompt_template = """Eres un asistente tecnico especializado.
Contexto recuperado:
{context}

Pregunta: {question}

Responde de forma precisa usando SOLO el contexto proporcionado.
Si la respuesta no esta en el contexto, dice "No tengo esa informacion en los documentos". """

    prompt = PromptTemplate(
        template=prompt_template,
        input_variables=["context", "question"]
    )

    chain = RetrievalQA.from_chain_type(
        llm=llm,
        chain_type="stuff",
        retriever=vector_store.as_retriever(search_kwargs={"k": 5}),
        return_source_documents=True
    )
    return chain

Fine-tuning Decision Framework

Ahora el framework para decidir cuando realmente necesitas fine-tunear vs. cuando con RAG cubres el negocio:

"""
Fine-tuning vs RAG Decision Framework - Dia 169
Usa la formula: D = alpha H(T) + beta R_k + gamma F
"""
from dataclasses import dataclass
from typing import Literal

@dataclass
class TaskSpec:
    task_type: Literal["classification", "generation", "extraction", "chat"]
    knowledge_update_frequency: Literal["daily", "weekly", "monthly", "never"]
    output_format: Literal["json", "markdown", "free_text", "code"]
    examples_count: int
    consistency_requirement: float  # 0-1

def calculate_decision_score(spec: TaskSpec) -> dict:
    # Pesos calibrables
    alpha, beta, gamma = 0.4, 0.4, 0.2

    # Entropia de tarea
    entropy_map = {"classification": 0.2, "extraction": 0.4, "chat": 0.7, "generation": 0.9}
    H_T = entropy_map[spec.task_type]

    # Razon de conocimiento
    freq_map = {"daily": 0.9, "weekly": 0.6, "monthly": 0.3, "never": 0.0}
    K_dynamic = freq_map[spec.knowledge_update_frequency]
    K_static = 1.0 - K_dynamic
    R_k = K_dynamic / (K_dynamic + K_static) if K_dynamic + K_static > 0 else 0

    # Complejidad de formato
    format_map = {"json": 0.9, "code": 0.8, "markdown": 0.4, "free_text": 0.1}
    F = format_map[spec.output_format]

    # Decision
    D = alpha * H_T + beta * R_k + gamma * F

    # Recomendacion
    if D > 0.6:
        recommendation = "RAG (con posible hybrid si F es alto)"
    elif D < 0.3:
        recommendation = "FINE-TUNING (o prefix tuning si datos limitados)"
    else:
        recommendation = "HYBRID: RAG + fine-tuning para format"

    return {
        "D_score": round(D, 3),
        "H_T": H_T,
        "R_k": round(R_k, 3),
        "F": F,
        "recommendation": recommendation,
        "rationale": f"Entropia={H_T}, razon conocimiento={R_k:.2f}, formato={F}"
    }

# Ejemplo: Chatbot de soporte con documentos que cambian diario
spec = TaskSpec(
    task_type="chat",
    knowledge_update_frequency="daily",
    output_format="markdown",
    examples_count=50,
    consistency_requirement=0.7
)
result = calculate_decision_score(spec)
print(result)
# D_score: 0.64 -> RAG recomendado

Los 3 Errores Que Van a Hacerte Perder Plata

Error 1: Fine-tunear cuando RAG es suficiente

El problema: Tu equipo fine-tunea un modelo de $2000 porque "asi el modelo sabe mas". Pagas $2000 en GPU hours, esperas 3 dias, y el resultado es apenas 5% mejor que un RAG bien implementado que te cuesta $50 al mes.

La matematica: El costo total de ownership de fine-tuning es:

$$C_{ft} = C_{gpu} \cdot t_{training} + C_{inference} \cdot n_{requests} + C_{maintenance}$$

Mientras RAG escala linealmente con uso y no requiere reentrenamiento cuando cambia tu knowledge base.

La solucion: Antes de fine-tunear, calcula $R_k$. Si $R_k > 0.5$, estas en territorio de RAG. Solo ve a fine-tuning si $R_k < 0.3$ Y $F > 0.6$.

Error 2: RAG cuando fine-tuning es mejor

El problema: Usas RAG para un task de clasificacion donde la consistencia de formato es critica. El modelo genera respuestas "casi correctas" pero el JSON a veces tiene keys diferentes, los enum no son consistentes, y pasas 2 semanas afinando el prompt. Gaste mas en llamadas API que si hubiera fine-tuneado.

La senal: Si estas escribiendo prompts de mas de 500 tokens para forzar un formato, esto es una senal de que el formato deberia ser aprendido via fine-tuning.

La solucion: Aplica el test de format-flexibility: si puedes expresar la regla de formato en menos de 10 ejemplos, usa fine-tuning. Si necesitas 50+ ejemplos, sigue con RAG + prompt engineering.

Error 3: No usar hybrid cuando ambos aplican

El problema: Tomas una decision binaria y pierdes lo mejor de ambos mundos. O solo fine-tuneas (y no puedes actualizar conocimiento sin reentrenar) o solo RAG (y el modelo no captura tu "forma de pensar").

La arquitectura hibrida:

# Hybrid: RAG (conocimiento) + Fine-tuned (formato/estilo)
def hybrid_query(query: str, vector_store, fine_tuned_model, k=5):
    # 1. Recupera contexto relevante via RAG
    docs = vector_store.similarity_search(query, k=k)
    context = "\n".join([doc.page_content for doc in docs])

    # 2. Genera con modelo fine-tuned para formato/estilo
    # El fine-tuned ya sabe el formato, solo pidele que use el contexto
    prompt = f"Contexto: {context}\n\nPregunta: {query}"
    response = fine_tuned_model.generate(prompt)

    return response

La decision hibrida: Cuando $R_k > 0.4$ Y $F > 0.5$, vas por hibrido. No lo pienses.

Resumen y Cierre

Parcero, la decision entre fine-tuning y RAG no es religiosa. Es matematica. Resume lo que aprendimos:

  • Usa RAG cuando tu conocimiento cambia frecuentemente o cuando $R_k$ es alto.
  • Usa Fine-tuning cuando el formato y estilo son lo mas importante y la consistencia es critica.
  • Usa Hybrid cuando ambos factores aplican: conocimiento dinamico Y formato estricto.
