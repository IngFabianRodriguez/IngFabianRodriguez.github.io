Que es RAG y Por Que Existe

Hagale pues, parcero. Dia 356 y hoy nos metemos con uno de los patrones mas importantes en aplicaciones de LLM: Retrieval Augmented Generation o RAG. Si alguna vez te preguntaste como hacer que un modelo de lenguaje responda preguntas sobre informacion que no conoce, o como darle memoria de largo plazo, o como reducir alucinaciones — este es tu articulo.

Antes de meternos en codigo: por que existe RAG?. Los LLMs como GPT-4 o Claude son entrenados con conocimiento hasta una fecha especifica. Si le preguntas sobre eventos recientes, simplemente no lo saben. Y si le preguntas sobre documentos internos de tu empresa, tampoco. RAG es la solucion a este problema: en lugar de confiar solo en el conocimiento interno del modelo, retrievamos informacion relevante de una fuente externa y la inyectamos en el prompt.

La Arquitecura Basica de RAG

Un sistema RAG tiene tres componentes fundamentales:

  • Retriever: Encuentra los documentos o chunks mas relevantes a la query del usuario
  • Vector Database: Almacena embeddings de documentos para busqueda eficiente por similitud
  • Generator: El LLM que produce la respuesta final usando el contexto recuperado

El flujo es:

  1. Usuario hace una pregunta
  2. La pregunta se convierte en un embedding (vector numerico)
  3. Se buscan los k documentos mas similares en la vector database
  4. Esos documentos se concatenan con la pregunta original
  5. El LLM genera la respuesta usando ese contexto enriquecido

Implementando RAG desde Cero

import numpy as np
from typing import List, Tuple

# === EMBEDDING SIMPLE (en produccion usar OpenAI, Cohere, o local) ===
class SimpleEmbedder:
    """Embedding basado en hash - simplificado para demostracion"""
    def __init__(self, dim: int = 384):
        self.dim = dim
    
    def embed(self, text: str) -> np.ndarray:
        # En produccion: usar API de OpenAI/Cohere
        # Aqui simulamos con hashing
        vec = np.zeros(self.dim)
        for i, char in enumerate(text):
            vec[i % self.dim] += ord(char) * (i + 1)
        return vec / (np.linalg.norm(vec) + 1e-8)


class VectorStore:
    """Base de datos vectorial simple en memoria"""
    def __init__(self):
        self.documents: List[str] = []
        self.embeddings: np.ndarray = None
    
    def add_documents(self, docs: List[str], embedder: SimpleEmbedder):
        """Agrega documentos y los convierte en embeddings"""
        self.documents = docs
        embeddings = []
        for doc in docs:
            emb = embedder.embed(doc)
            embeddings.append(emb)
        self.embeddings = np.array(embeddings)
        print(f"Agregados {len(docs)} documentos al vector store")
    
    def search(self, query: str, embedder: SimpleEmbedder, k: int = 3) -> List[Tuple[str, float]]:
        """Busca los k documentos mas similares a la query"""
        query_emb = embedder.embed(query)
        
        # Calcular similitud coseno
        similarities = self.embeddings @ query_emb
        
        # Obtener indices de los k mas similares
        top_k_idx = np.argsort(similarities)[-k:][::-1]
        
        results = []
        for idx in top_k_idx:
            results.append((self.documents[idx], similarities[idx]))
        
        return results


# === RAG SYSTEM ===
class RAGSystem:
    def __init__(self, vector_store: VectorStore, embedder: SimpleEmbedder, llm_name: str = "gpt-4"):
        self.vector_store = vector_store
        self.embedder = embedder
        self.llm_name = llm_name
    
    def retrieve(self, query: str, k: int = 3) -> List[str]:
        """Recupera los k documentos mas relevantes"""
        results = self.vector_store.search(query, self.embedder, k)
        return [doc for doc, score in results]
    
    def build_prompt(self, query: str, context_docs: List[str]) -> str:
        """Construye el prompt con el contexto recuperado"""
        context = "\n\n".join([f"Documento {i+1}:\n{doc}" for i, doc in enumerate(context_docs)])
        
        prompt = f"""Usa el siguiente contexto para responder la pregunta. Si la respuesta no esta en el contexto, indica que no tienes suficiente información.

Contexto:
{context}

Pregunta: {query}

Respuesta:"""
        return prompt
    
    def answer(self, query: str, k: int = 3) -> str:
        """Pipeline completo de RAG"""
        # 1. Retrieve
        relevant_docs = self.retrieve(query, k)
        print(f"Documentos recuperados: {len(relevant_docs)}")
        
        # 2. Build prompt
        prompt = self.build_prompt(query, relevant_docs)
        
        # 3. Generate (en produccion: llamada al LLM)
        # response = call_llm(self.llm_name, prompt)
        
        return f"[Respuesta simulada basada en {len(relevant_docs)} documentos]"

Chunking: La Parte Mas Importante

Uno de los aspectos mas descuidados en RAG es el chunking: como dividir tus documentos en pedazos indexables. Un buen chunking puede hacer o deshacer tu sistema.

def chunk_text(text: str, chunk_size: int = 500, overlap: int = 50) -> List[str]:
    """
    Divide texto en chunks con solapamiento.
    
    Args:
        text: Texto a dividir
        chunk_size: Tamanio aproximado de cada chunk en caracteres
        overlap: Numero de caracteres que se solapan entre chunks
    
    Returns:
        Lista de chunks
    """
    chunks = []
    start = 0
    text_len = len(text)
    
    while start < text_len:
        end = start + chunk_size
        
        # Ajustar para no cortar en medio de palabra
        if end < text_len:
            # Ir atras hasta encontrar un espacio
            while end > start and text[end] not in ' \n\t':
                end -= 1
            if end == start:
                end = start + chunk_size  # Forzar corte si no hay espacios
        
        chunk = text[start:end].strip()
        if chunk:
            chunks.append(chunk)
        
        start = end - overlap  # Solapamiento para mantener contexto
    
    return chunks


def chunk_by_semantics(text: str, max_chunk_size: int = 500) -> List[str]:
    """
    Chunking inteligente basado en estructura semantica.
    Respeta parrafos y secciones.
    """
    import re
    
    # Dividir por parrafos
    paragraphs = re.split(r'\n\n+', text)
    
    chunks = []
    current_chunk = ""
    
    for para in paragraphs:
        para = para.strip()
        if not para:
            continue
        
        # Si el parrafo cabe en el chunk actual
        if len(current_chunk) + len(para) < max_chunk_size:
            current_chunk += "\n\n" + para
        else:
            # Guardar chunk actual si no esta vacio
            if current_chunk.strip():
                chunks.append(current_chunk.strip())
            
            # Si el parrafo individual es muy largo, dividirlo por oraciones
            if len(para) > max_chunk_size:
                sentences = re.split(r'(?<=[.!?])\s+', para)
                current_chunk = ""
                for sent in sentences:
                    if len(current_chunk) + len(sent) < max_chunk_size:
                        current_chunk += " " + sent
                    else:
                        if current_chunk.strip():
                            chunks.append(current_chunk.strip())
                        current_chunk = sent
            else:
                current_chunk = para
    
    # No olvidar el ultimo chunk
    if current_chunk.strip():
        chunks.append(current_chunk.strip())
    
    return chunks

Retrieval: Mas Alla del Simple Embedding

El retriever simple que mostre usa similitud coseno sobre embeddings. En produccion hay tecnicas mas sofisticadas:

# === HYBRID RETRIEVAL ===
class HybridRetriever:
    """
    Combina busqueda densa (embeddings) con busqueda dispersa (BM25).
    Generalmente outperforms a cualquiera de los dos metodos solos.
    """
    def __init__(self, vector_store: VectorStore, embedder: SimpleEmbedder):
        self.vector_store = vector_store
        self.embedder = embedder
        self.bm25_scores = None  # Calculado previamente
    
    def dense_search(self, query: str, k: int = 5) -> List[Tuple[int, float]]:
        """Busqueda densa por embeddings"""
        query_emb = self.embedder.embed(query)
        similarities = self.vector_store.embeddings @ query_emb
        top_k = np.argsort(similarities)[-k:][::-1]
        return [(idx, similarities[idx]) for idx in top_k]
    
    def sparse_search(self, query: str, k: int = 5) -> List[Tuple[int, float]]:
        """
        Busqueda dispersa con BM25.
        En produccion usar: rank_bm25.RankBM25
        """
        # Simulado - en produccion usar biblioteca real
        from collections import Counter
        import math
        
        query_terms = query.lower().split()
        doc_scores = []
        
        for i, doc in enumerate(self.vector_store.documents):
            doc_terms = doc.lower().split()
            # TF-IDF simplificado
            tf = Counter(doc_terms)
            score = sum(tf.get(t, 0) for t in query_terms)
            doc_scores.append((i, score))
        
        doc_scores.sort(key=lambda x: x[1], reverse=True)
        return doc_scores[:k]
    
    def hybrid_search(self, query: str, k: int = 5, alpha: float = 0.5) -> List[Tuple[str, float]]:
        """
        Combina busqueda densa y dispersa.
        
        alpha = 1.0 -> solo densa
        alpha = 0.0 -> solo dispersa
        alpha = 0.5 -> igualmente ponderadas
        """
        dense_results = self.dense_search(query, k * 2)
        sparse_results = self.sparse_search(query, k * 2)
        
        # Normalizar scores
        max_dense = max(s for _, s in dense_results) if dense_results else 1
        max_sparse = max(s for _, s in sparse_results) if sparse_results else 1
        
        dense_norm = {idx: score/max_dense for idx, score in dense_results}
        sparse_norm = {idx: score/max_sparse for idx, score in sparse_results}
        
        # Combinar
        all_idx = set(dense_norm.keys()) | set(sparse_norm.keys())
        combined = {}
        for idx in all_idx:
            d = dense_norm.get(idx, 0)
            s = sparse_norm.get(idx, 0)
            combined[idx] = alpha * d + (1 - alpha) * s
        
        top_k = sorted(combined.items(), key=lambda x: x[1], reverse=True)[:k]
        return [(self.vector_store.documents[idx], score) for idx, score in top_k]


# === METRICS DE RETRIEVAL ===
def evaluate_retrieval(retriever, queries: List[str], relevant_docs: List[List[int]]) -> dict:
    """
    Evalua el retriever con queries y documentos relevantes conocidos.
    
    relevant_docs: para cada query, indices de los documentos relevantes
    """
    metrics = {"precision@5": [], "recall@5": [], "mrr": []}
    
    for query, relevant in zip(queries, relevant_docs):
        results = retriever.dense_search(query, k=5)
        retrieved_indices = [idx for idx, _ in results]
        
        # Precision@5
        relevant_set = set(relevant)
        retrieved_set = set(retrieved_indices)
        precision = len(relevant_set & retrieved_set) / min(5, len(retrieved_set))
        metrics["precision@5"].append(precision)
        
        # Recall@5
        recall = len(relevant_set & retrieved_set) / len(relevant_set)
        metrics["recall@5"].append(recall)
        
        # MRR (Mean Reciprocal Rank)
        for i, idx in enumerate(retrieved_indices):
            if idx in relevant_set:
                metrics["mrr"].append(1 / (i + 1))
                break
        else:
            metrics["mrr"].append(0)
    
    return {k: sum(v) / len(v) for k, v in metrics.items()}

RAG en Produccion: Lo Que Nadie Te Dice

El Problema de la ventana de contexto

Si retrievas demasiados documentos, puedes exceder la ventana de contexto del modelo. Si retrievas muy pocos, puedes no tener suficiente informacion. El sweet spot depende de:

  • Longitud de los chunks: Chunks mas pequenos = mas contexto cabra, pero puede perder semantica
  • Modelo usado: GPT-4o soporta 128k tokens, modelos pequenos pueden tener 4k
  • Precision vs Recall: Mas chunks = mejor recall pero peor precision

Re-ranking: El Segundo Paso

Despues del retrieval inicial, un re-ranker puede mejorar significativamente la calidad:

class ReRanker:
    """
    Re-rankea resultados del retriever inicial.
    Usa un modelo de cross-encoder para mejor precision.
    """
    def __init__(self, model_name: str = "cross-encoder/ms-marco"):
        self.model_name = model_name
        # En produccion: from sentence_transformers import CrossEncoder
    
    def rerank(self, query: str, documents: List[str], top_k: int = 3) -> List[Tuple[str, float]]:
        """
        Re-rankea los documentos segun su relevancia directa a la query.
        
        En produccion:
        model = CrossEncoder(self.model_name)
        pairs = [(query, doc) for doc in documents]
        scores = model.predict(pairs)
        """
        # Simulado
        import hashlib
        scores = []
        for doc in documents:
            # Usar overlap de terms como proxy
            query_terms = set(query.lower().split())
            doc_terms = set(doc.lower().split())
            overlap = len(query_terms & doc_terms)
            score = overlap / max(len(query_terms), 1)
            scores.append(score)
        
        # Ordenar por score
        results = sorted(zip(documents, scores), key=lambda x: x[1], reverse=True)
        return results[:top_k]


class RAGWithReranker(RAGSystem):
    """RAG con re-ranking de resultados"""
    def __init__(self, vector_store, embedder, reranker: ReRanker):
        super().__init__(vector_store, embedder)
        self.reranker = reranker
    
    def answer(self, query: str, k: int = 10, final_k: int = 3) -> str:
        # 1. Retrieve inicial (mas documentos)
        initial_docs = self.retrieve(query, k)
        
        # 2. Re-rank
        reranked = self.reranker.rerank(query, initial_docs, top_k=final_k)
        final_docs = [doc for doc, score in reranked]
        
        # 3. Build prompt y generate
        prompt = self.build_prompt(query, final_docs)
        return f"[Respuesta basada en {len(final_docs)} documentos re-rankeados]"

Resumen y Cierre

Eso era RAG, parcero. Un patron fundamental para cualquier aplicacion de LLM que necesite contexto externo. Los puntos clave:

  • Chunking importa mucho: La forma en que divides tus documentos determina la calidad del retrieval
  • Hybrid retrieval: Combina busqueda densa (embeddings) con dispersa (BM25)
  • Re-ranking mejora precision: Un segundo paso de re-ordenamiento vale la pena
  • Evalua siempre: Sin metricas no sabes si tu RAG funciona o no
