🎯 Intro — El Problema de Contexto que Todos Ignoran

Pues resulta que en Bogotá, cuando uno va a una gallera y pregunta por el gallito bueno, le dicen: "el que tiene historia, el que viene de buena estirpe". Los LLMs funcionan igual — sin un knowledge graph que les diga de dónde viene la información, contestan con lo primero que encuentran en el vector store, sin contexto genealógico. Hoy día 309 del reto, vamos a meterle estructura cerebral a esos modelos.

El 85% de las implementaciones RAG usan solo búsqueda vectorial. Eso funciona, pero pierdes las relaciones entre entidades. Un knowledge graph captura exactamente eso: quién está conectado con quién, cómo, y desde cuándo.

📐 La Matemática Detrás del Knowledge Graph

Un knowledge graph G = (V, E) donde:

  • V = {v₁, v₂, ..., vₙ} son las entidades (nodos)
  • E = {(h, r, t) | h ∈ V, t ∈ V, r ∈ R} son las tripletas head-relation-tail (bordes)

Para embedding de nodos en un espacio de dimensión d, usamos:

f(h, r, t) = ||embed(h) + embed(r) - embed(t)||²

Esto es TransE. El scoring indica qué tan válida es la relación. Para texto, extraemos tripletas via NER y dependency parsing.

🔧 Extracción de Entidades y Relaciones

import spacy
from spacy.tokens import Span

nlp = spacy.load("es_core_news_lg")

def extract_triplets(text: str) -> list[tuple[str, str, str]]:
    """Extrae tripletas (cabeza, relación, cola) del texto."""
    doc = nlp(text)
    triplets = []

    for sent in doc.sents:
        for token in sent:
            # Relación verbal como predicado
            if token.pos_ == "VERB" and token.dep_ == "ROOT":
                subject = None
                object = None

                for child in token.children:
                    if child.dep_ in ("nsubj", "nsubj:pass"):
                        subject = child.subtree_text.strip()
                    if child.dep_ in ("obj", "obl", "iobj"):
                        object = child.subtree_text.strip()

                if subject and object:
                    triplets.append((subject, token.lemma_, object))

    return triplets

# Ejemplo
text = "GPT-4 fue desarrollado por OpenAI en San Francisco. Claude es de Anthropic."
triplets = extract_triplets(text)
print(triplets)
# [('GPT-4', 'desarrollar', 'OpenAI'), ('GPT-4', 'estar en', 'San Francisco'), ('Claude', 'ser', 'Anthropic')]

🚀 Construcción del KG y Búsqueda Híbrida

from dataclasses import dataclass, field
from typing import Optional
import numpy as np

@dataclass
class KGNode:
    id: str
    label: str
    type: str  # 'entity' | 'concept'
    properties: dict = field(default_factory=dict)
    embedding: Optional[np.ndarray] = None

@dataclass
class KGEdge:
    source: str
    target: str
    relation: str
    weight: float = 1.0

class KnowledgeGraph:
    def __init__(self, embedding_dim: int = 384):
        self.nodes: dict[str, KGNode] = {}
        self.edges: list[KGEdge] = []
        self.embedding_dim = embedding_dim
        self._vector_index: list[tuple[str, np.ndarray]] = []

    def add_node(self, id: str, label: str, node_type: str,
                 properties: dict = None, embedding: np.ndarray = None):
        node = KGNode(id, label, node_type, properties or {}, embedding)
        self.nodes[id] = node
        if embedding is not None:
            self._vector_index.append((id, embedding))

    def add_edge(self, source_id: str, target_id: str,
                 relation: str, weight: float = 1.0):
        if source_id in self.nodes and target_id in self.nodes:
            self.edges.append(KGEdge(source_id, target_id, relation, weight))

    def hybrid_search(self, query: str, top_k: int = 10,
                      alpha: float = 0.5) -> list[dict]:
        """
        Búsqueda híbrida: combina KG paths (alpha=1) con vectores (alpha=0).
        alpha=0.5 = mitad KG estructurado, mitad vectorial.
        """
        # 1. Retrieval vectorial puro
        query_embedding = self._embed_text(query)
        vector_scores = self._cosine_scores(query_embedding)

        # 2. Retrieval vía KG paths
        kg_scores = self._kg_path_scores(query)

        # 3. Fusión híbrida: alpha * KG + (1-alpha) * vector
        all_ids = set(vector_scores.keys()) | set(kg_scores.keys())
        hybrid = {}
        for node_id in all_ids:
            v_score = vector_scores.get(node_id, 0.0)
            kg_score = kg_scores.get(node_id, 0.0)
            hybrid[node_id] = alpha * kg_score + (1 - alpha) * v_score

        results = sorted(hybrid.items(), key=lambda x: x[1], reverse=True)
        return [
            {"id": nid, "score": score, "node": self.nodes[nid]}
            for nid, score in results[:top_k]
        ]

    def _cosine_scores(self, query_emb: np.ndarray) -> dict[str, float]:
        scores = {}
        for nid, emb in self._vector_index:
            sim = np.dot(query_emb, emb) / (
                np.linalg.norm(query_emb) * np.linalg.norm(emb) + 1e-8
            )
            scores[nid] = float(sim)
        return scores

    def _kg_path_scores(self, query: str) -> dict[str, float]:
        """Usa las relaciones del KG para puntuar nodos conectados."""
        query_lower = query.lower()
        scores = {}
        # Nodos cuyas etiquetas coinciden con la query
        for nid, node in self.nodes.items():
            if query_lower in node.label.lower():
                scores[nid] = 1.0
                # Bonus por conexiones
                for edge in self.edges:
                    if edge.source == nid or edge.target == nid:
                        scores[nid] = max(scores[nid], scores.get(nid, 0) + 0.2 * edge.weight)
        return scores

    def _embed_text(self, text: str) -> np.ndarray:
        # Placeholder: usa tu modelo de embedding favorito
        # (SentenceTransformers, OpenAI embeddings, etc.)
        return np.random.randn(self.embedding_dim)

# Uso
kg = KnowledgeGraph(embedding_dim=384)
kg.add_node("openai", "OpenAI", "organization", {"founded": 2015})
kg.add_node("gpt4", "GPT-4", "model", {"params": "1.8T", "release": "2023"})
kg.add_node("san_francisco", "San Francisco", "location")

kg.add_edge("openai", "gpt4", "desarrolló", weight=1.0)
kg.add_edge("gpt4", "san_francisco", "ubicado_en", weight=0.5)

results = kg.hybrid_search("GPT-4 y OpenAI", top_k=5, alpha=0.5)
for r in results:
    print(f"{r['node'].label} ({r['score']:.3f})")

⚠️ Error 1: No Considerar Knowledge Graphs

El error: Creer que con un vector store simple basta. Es como ir a Proc大概率 y comprar la primera carnada que veas — a veces funciona, pero no siempre.

El fix: Implementa KG extraction desde el inicio. 即使你的文档是英文, la estructura relacional mejora la recuperación en 30-40% según estudios de Microsoft y Google.

⚠️ Error 2: Construir el KG Sin NLP

El error: Usar regex manuales para extraer entidades. Eso solo captura lo que tus regex anticipan, y el lenguaje es demasiado desordenado para eso.

El fix: Usa modelos NER especializados. Para español, es_core_news_lg de spaCy o modelos de HuggingFace fine-tuned en tu dominio. El parseo sintáctico (dependency parsing) captura relaciones que regex jamás verán.

⚠️ Error 3: No Integrar KG con Vector Search

El error: Usar KG puro o vector puro. Cada uno tiene debilidades — KG es frágil en queries abiertas, vectores fallan en relaciones lógicas (preguntas de "por qué" o "cómo").

El fix: Fusión híbrida como mostrado arriba. alpha es tu dial de riesgo: queries de relaciones → alpha alto; queries de contenido denso → alpha bajo.

📊 Resumen — Colombianizando la Ciencia

A nivel de resumen, un knowledge graph es como la red de contactos en una挤aypa: sabes quién conoce a quién, qué venden, de dónde viene la mercancía. Los LLMs sin KG son como el que llega nuevo a la plaza — conoce los productos pero no sabe quién es de confianza.

  • Usa KG para queries donde las relaciones importan: genealogía de conceptos, cadenas de causa-efecto, historia de productos
  • Usa vectores para semántica abierta: definición de términos, explicaciones, contexto general
  • Usa ambos con fusión híbrida — el futuro es estructurado + denso
