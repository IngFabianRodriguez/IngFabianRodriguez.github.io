La Matemática del Quantization

Un modelo de lenguaje tiene pesos en precisión completa (FP32 = 32 bits = 4 bytes por parámetro). Para un modelo de 7B parámetros:

  • FP32: 7B × 4 bytes = 28 GB
  • FP16/BF16: 7B × 2 bytes = 14 GB
  • INT8: 7B × 1 byte = 7 GB
  • INT4: 7B × 0.5 bytes = 3.5 GB

La formula de quantization es simple:

$$x_{int} = \text{round}\left(\frac{x_{fp32}}{s}\right)$$

donde $s$ es el scale factor calculado como:

$$s = \frac{\max(|x_{fp32}|)}{2^{n-1} - 1}$$

Para desquantizar:

$$\hat{x}_{fp32} = x_{int} \times s$$

Tipos de Quantization

Dynamic vs Static Quantization

Dynamic quantization: Los scales se calculan on-the-fly durante la inferencia. Bueno para LLM porque las activaciones varían mucho.

Static quantization: Los scales se calculan anticipadamente con un dataset de calibración. Mejor para modelos pequeños y CNNs.

Quantization Symmetric vs Asymmetric

Symmetric: Usa el mismo scale para valores positivos y negativos. Rango [-127, 127] para INT8.

Asymmetric: Tiene un zero-point adicional. Permite mejor uso del rango pero complica la implementación.

Implementación con PyTorch

import torch
from torch import nn
import torch.nn.functional as F

class DynamicQuantizer:
    """Quantization dinámica para pesos de LLM."""
    
    @staticmethod
    def quantize_tensor(x: torch.Tensor, dtype: torch.dtype = torch.int8) -> tuple[torch.Tensor, float]:
        """
        Cuantiza un tensor a INT8/INT4.
        Retorna (tensor_cuantizado, scale_factor)
        """
        # Calcular scale factor
        max_val = x.abs().max().item()
        
        if dtype == torch.int8:
            qmax = 127.0
        elif dtype == torch.int4:
            qmax = 7.0
        else:
            raise ValueError(f"dtype {dtype} no soportado")
        
        scale = max_val / qmax
        
        # Cuantizar
        x_quant = torch.round(x / scale).to(dtype)
        
        return x_quant, scale
    
    @staticmethod
    def dequantize_tensor(x_quant: torch.Tensor, scale: float, dtype: torch.dtype = torch.int8) -> torch.Tensor:
        """Descuantiza un tensor."""
        x_fp32 = x_quant.float() * scale
        return x_fp32

# Ejemplo de uso
weight = torch.randn(512, 512) * 2.5  # Pesos simulados
w_quant, scale = DynamicQuantizer.quantize_tensor(weight, dtype=torch.int8)
w_dequant = DynamicQuantizer.dequantize_tensor(w_quant, scale)

print(f"Original shape: {weight.shape}, dtype: {weight.dtype}")
print(f"Cuantizado shape: {w_quant.shape}, dtype: {w_quant.dtype}")
print(f"Error de cuantización: {(weight - w_dequant).abs().mean():.6f}")

Quantization Aware Training (QAT)

Para mejores resultados, el quantization se puede hacer durante el entrenamiento (QAT) en vez de post-hoc. Esto permite que el modelo aprenda a compensar la pérdida de precisión.

import torch
import torch.nn as nn
from torch.ao.quantization import QuantStub, DeQuantStub, QConfig

class QATModel(nn.Module):
    """Modelo con quantization aware training."""
    
    def __init__(self, base_model: nn.Module):
        super().__init__()
        self.model = base_model
        self.quant = QuantStub()
        self.dequant = DeQuantStub()
    
    def forward(self, x):
        # Insertar nodos de cuantización
        x = self.quant(x)
        x = self.model(x)
        x = self.dequant(x)
        return x
    
    def prepare_for_qat(self):
        """Prepara el modelo para QAT."""
        self.model.qconfig = QConfig(
            activation=torch.ao.quantization.FakeQuantize,
            weight=torch.ao.quantization.FakeQuantize
        )
        torch.quantization.prepare_qat(self.model, inplace=True)
        return self

# Durante entrenamiento, los pesos se mantienen en FP32 pero simulan quantization
# En deployment, se convierte a INT8/INT4

GPTQ — Quantization de Post-Entrenamiento

GPTQ es una técnica popular para cuantizar LLMs post-entrenamiento sin reentrenar. Funciona muy bien para modelos de 7B-70B.

# Usando auto-gptq para cuantizar un modelo
# pip install auto-gptq

from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig

model_name = "meta-llama/Llama-2-7b-hf"
quantization_config = GPTQConfig(
    bits=4,
    dataset="c4",
    tokenizer=AutoTokenizer.from_pretrained(model_name)
)

# Cuantizar el modelo
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=quantization_config,
    device_map="auto"
)

# Guardar modelo cuantizado
model.save_pretrained("./llama-2-7b-4bit")

AWQ — Activation-Aware Quantization

AWQ asume que no todos los pesos son iguales de importantes. Ignora el 1% de los pesos más importantes y cuantiza el resto. Esto reduce significativamente la degradación de accuracy.

# AWQ implementation conceptual
def awq_quantize(weights, activations=None, q_bit=4):
    """
    AWQ: Ignora pesos menos importantes para preservar accuracy.
    """
    # Encontrar pesos importantes (los que tienen mayor magnitud)
    # En práctica se usa la activación como proxy
    if activations is not None:
        importance = (activations.abs().mean(dim=0)).pow(2)
    else:
        importance = weights.abs().mean(dim=0)
    
    # Scaling factors
    scales = importance / importance.max()
    
    # Cuantizar solo el 99% menos importante
    q_weights = weights.clone()
    mask = scales < 0.99  # Ignorar top 1%
    
    for i in range(weights.shape[0]):
        if mask[i]:
            max_val = weights[i].abs().max()
            scale = max_val / (2 ** (q_bit - 1) - 1)
            q_weights[i] = torch.round(weights[i] / scale) * scale
    
    return q_weights

Errores Comunes

Error 1: Cuantizar Todo a INT4

El error: Creer que INT4 siempre es mejor. Para algunas tareas, especialmente matemáticas y código, la pérdida de precisión mata el rendimiento.

El fix: Usa INT4 para modelos grandes (70B+) donde la diferencia de memoria es crítica. Para modelos menores de 13B, INT8 es generalmente seguro.

Error 2: No Calibrar en el Dominio Correcto

El error: Usar un dataset genérico para calibrar. Si su modelo es médico, calíbrelo con datos médicos.

El fix: Seleccione 100-1000 ejemplos representativos de su dominio para calibración estática.

Error 3: Ignorar las Activaciones

El error: Cuantizar solo los pesos. Las activaciones también ocupan memoria y compute.

El fix: Para KV cache y activaciones intermedias, use INT8 o FP16. Solo los pesos son seguros en INT4.

Resumen

El quantization es como hacer maleta para un viaje corto: hay que saber qué dejar y cómo empacar lo que queda.

  • INT8: Buen balance para modelos 7B-13B
  • INT4: Para modelos grandes (70B+) en hardware limitado
  • GPTQ/AWQ: Post-training quantization con mínima pérdida
  • QAT: Si puede reentrenar, mejores resultados
