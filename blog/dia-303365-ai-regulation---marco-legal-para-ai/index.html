Intro - ¿Por Qué Tu LLM Genera Texto Que Parece Escrito por un Robot Borracho?

El resultado: respuestas que incluían frases como "Estimado cliente, su solicitud ha sido procesada satisfactoriamente" repetidas 47 veces seguidas. Cuando me contó que estaba usando temperature=0.7 para todo, le dije que eso era como usar la misma velocidad para manejar en la Avenida Caracas y en una trocha de Nariño. No funciona igual.

En este artículo vamos a hablar de cómo generar texto de calidad con LLMs. No de la arquitectura del transformer (ya hablamos de eso en el día 88), sino de la parte que nadie explica bien: las sampling strategies, cómo controlar la repetición, cómo manejar la longitud, y cómo evaluar si lo que salió está bien o es un desastre. Todo con código real que puedes usar mañana.

La Matemática Detrás de la Generación

Antes de hablar de código, necesitamos entender la matemática. Un LLM genera texto token por token. En cada paso, calcula una distribución de probabilidad sobre todo el vocabulario:

$$P(token_{t} | token_{1}, token_{2}, ..., token_{t-1})$$

El modelo asigna una puntuación (logit) a cada posible token. La temperature controla qué tan "confiado" o "creativo" es el modelo:

# Sin temperature (T=1): la distribución original
probs = softmax(logits)

# Con temperature: suaviza o concentra la distribución
# T > 1: más uniforme, más random/creativo
# T < 1: más puntiagudo, más determinista
probs = softmax(logits / T)

Cuando T → 0, el modelo se vuelve completamente determinista: siempre elige el token con mayor probabilidad. Esto se llama greedy decoding. Cuando T → ∞, todos los tokens tienen probabilidad casi igual: caos total.

La fórmula de softmax con temperature:

$$P_T(token_i) = \frac{e^{z_i/T}}{\sum_{j} e^{z_j/T}}$$

donde z_i son los logits y T es la temperature. Un valor de T=0.7 significa que dividimos los logits entre 0.7, haciendo la distribución más uniforme (más "creativa"). Un valor de T=1.5 la hace aún más uniforme.

Top-K y Top-P: Filtrando el Caos

Temperature solo no basta. Aquí es donde entran top-k y top-p (nucleus sampling):

  • Top-K: Solo considera los K tokens con mayor probabilidad. Si pones K=50, solo miras los 50 candidatos más probables.
  • Top-P: Selecciona el smallest set de tokens cuya probabilidad acumulada sea al menos P. Si P=0.9, cubres el 90% de la probabilidad total.

Top-P es generalmente preferido porque se adapta dinámicamente: en distribuciones peaked toma pocos tokens, en distribuciones flat toma más.

Código: Text Generation Framework

Vamos a implementar un framework completo para experimentar con diferentes estrategias de generación:

import torch
import torch.nn.functional as F
from typing import List, Dict, Optional, Tuple
from dataclasses import dataclass
import json

@dataclass
class GenerationConfig:
    """Configuración para generación de texto."""
    temperature: float = 1.0
    top_k: int = 50
    top_p: float = 0.9
    max_new_tokens: int = 100
    repetition_penalty: float = 1.0
    stop_strings: List[str] = None
    seed: Optional[int] = None

class TextGenerator:
    """Framework para experimentación con generación de texto."""

    def __init__(self, model, tokenizer, device='cuda'):
        self.model = model
        self.tokenizer = tokenizer
        self.device = device

    def apply_temperature(self, logits: torch.Tensor, temperature: float) -> torch.Tensor:
        """Aplica temperature scaling a los logits."""
        if temperature == 0:
            # Greedy: возвращает índice del máximo
            return logits
        return logits / temperature

    def apply_top_k(self, logits: torch.Tensor, k: int) -> torch.Tensor:
        """Filtra a top-k tokens."""
        if k == 0:
            return logits
        # Poner en -inf los logits fuera del top-k
        top_k_logits, top_k_indices = torch.topk(logits, k)
        mask = torch.zeros_like(logits).fill_(float('-inf'))
        mask.scatter_(1, top_k_indices, top_k_logits)
        return mask

    def apply_top_p(self, logits: torch.Tensor, p: float) -> torch.Tensor:
        """Nucleus sampling: filtra por probabilidad acumulada."""
        if p == 1.0:
            return logits
        sorted_logits, sorted_indices = torch.sort(logits, descending=True)
        cumsum = torch.cumsum(F.softmax(sorted_logits, dim=-1), dim=-1)

        # Encontrar el punto donde la probabilidad acumulada cruza p
        # Incluir el token que cruza el umbral
        mask = cumsum > p
        # Asegurar que al menos un token esté disponible
        mask[..., 1:] = mask[..., :-1].clone()
        mask[..., 0] = False

        # Aplicar mask
        sorted_logits[mask] = float('-inf')
        # Desordenar de vuelta
        logits.scatter_(1, sorted_indices, sorted_logits)
        return logits

    def apply_repetition_penalty(self, logits: torch.Tensor,
                                  generated_tokens: List[int]) -> torch.Tensor:
        """Penaliza tokens ya generados para reducir repetición."""
        if self.repetition_penalty == 1.0 or not generated_tokens:
            return logits

        for token in generated_tokens:
            logits[0, token] /= self.repetition_penalty
        return logits

    def sample_token(self, logits: torch.Tensor,
                     generation_config: GenerationConfig) -> int:
        """Samplea un token aplicando todas las estrategias."""
        # 1. Aplicar repetition penalty
        logits = self.apply_repetition_penalty(
            logits.clone(),
            generation_config.generated_tokens[-50:]  # Solo últimos 50
        )

        # 2. Aplicar temperature
        logits = self.apply_temperature(logits, generation_config.temperature)

        # 3. Filtrar con top-k
        logits = self.apply_top_k(logits, generation_config.top_k)

        # 4. Filtrar con top-p
        logits = self.apply_top_p(logits, generation_config.top_p)

        # 5. Convertir a probabilidades y samplear
        probs = F.softmax(logits, dim=-1)
        token = torch.multinomial(probs, num_samples=1).item()
        return token

    def generate(self, prompt: str,
                 config: GenerationConfig) -> str:
        """Genera texto desde un prompt."""
        self.model.eval()

        # Tokenizar
        input_ids = self.tokenizer.encode(prompt, return_tensors='pt').to(self.device)
        generated = input_ids[0].tolist()
        config.generated_tokens = generated.copy()

        # Generación autoregresiva
        with torch.no_grad():
            for _ in range(config.max_new_tokens):
                # Obtener logits del siguiente token
                outputs = self.model(input_ids)
                next_token_logits = outputs.logits[:, -1, :]

                # Samplear siguiente token
                next_token = self.sample_token(
                    next_token_logits,
                    config
                )

                # Verificar stop strings
                if config.stop_strings:
                    current_text = self.tokenizer.decode(generated + [next_token])
                    for stop in config.stop_strings:
                        if stop in current_text:
                            return current_text

                # Agregar token
                generated.append(next_token)
                input_ids = torch.cat([
                    input_ids,
                    torch.tensor([[next_token]], device=self.device)
                ], dim=1)

                # Verificar token de fin
                if next_token == self.tokenizer.eos_token_id:
                    break

        return self.tokenizer.decode(generated)

Los 3 Errores Que el 85% Comete

Error 1: Usar Default Temperature Para Todo

El error más común. Dejar temperature=0.7 o temperature=1.0 para todos los casos sin pensar qué tipo de output necesitas.

¿Por qué está mal? Una temperature de 0.7 puede ser perfecta para writing creativo pero desastrosa para generación de código técnico donde necesitas precisión. Y viceversa.

La solución: Ajusta la temperature según el caso de uso:

def get_temperature_for_task(task: str) -> float:
    """Recomienda temperature según el tipo de tarea."""
    task_temperatures = {
        # Alta creatividad: diferentes tonos, ideas diversas
        'escribir_poesia': 1.0,
        'brainstorming': 0.9,
        'escribir_historias': 0.85,

        # Temperatura media: balance entre coherencia y creatividad
        'escribir_correos': 0.5,
        'chat_general': 0.6,
        'resumir_documentos': 0.4,

        # Baja temperatura: máxima precisión, mínima aleatoriedad
        'generar_codigo': 0.2,
        'matematicas': 0.1,
        'extraccion_datos': 0.0,  # Greedy
        'clasificación': 0.0,
    }
    return task_temperatures.get(task, 0.7)

Error 2: No Controlar la Repetición

Cuando generas texto largo, es común ver el modelo repetirse en círculos. "El producto es excelente. El producto es excelente. El producto es excelente."

¿Por qué está mal? Sin penalización de repetición, el modelo puede entrar en loops de alta probabilidad local que no son coherentes globalmente.

La solución: Implementar repetition penalty y n-gram blocking:

class RepetitionController:
    """Controla y previene repetición excesiva."""

    def __init__(self, penalty: float = 1.2, window_size: int = 5):
        self.penalty = penalty
        self.window_size = window_size
        self.generated_tokens = []

    def penalize(self, logits: torch.Tensor, last_token: int) -> torch.Tensor:
        """Aplica penalización a tokens repetidos recientemente."""
        self.generated_tokens.append(last_token)

        # Mantener solo la ventana reciente
        recent = self.generated_tokens[-self.window_size:]

        for token in set(recent):
            if token in recent[-3:]:  # Si aparece más de una vez en ventana
                logits[token] /= self.penalty

        return logits

    def check_ngram_repetition(self, text: str, n: int = 3) -> bool:
        """Detecta si hay n-grams repetidos."""
        tokens = text.split()
        if len(tokens) < n * 2:
            return False

        ngrams = [tuple(tokens[i:i+n]) for i in range(len(tokens) - n + 1)]
        return len(ngrams) != len(set(ngrams))

class AdvancedTextGenerator(TextGenerator):
    """Versión avanzada con control de repetición mejorado."""

    def __init__(self, model, tokenizer, device='cuda'):
        super().__init__(model, tokenizer, device)
        self.repetition_controller = RepetitionController(
            penalty=1.5,
            window_size=6
        )

    def sample_token_advanced(self, logits: torch.Tensor,
                              generated_tokens: List[int]) -> int:
        """Sampleo con control de repetición y diversidad."""
        # Aplicar temperature
        logits = logits / 0.8  # temperatura media por defecto

        # Aplicar penalización de repetición
        if generated_tokens:
            logits = self.repetition_controller.penalize(
                logits.clone(),
                generated_tokens[-1]
            )

        # Top-k y top-p
        logits = self.apply_top_k(logits, k=50)
        logits = self.apply_top_p(logits, p=0.92)

        # Convertir a probabilidades
        probs = F.softmax(logits, dim=-1)

        # Diversificación:boost tokens no vistos recientemente
        if len(generated_tokens) > 10:
            recent = set(generated_tokens[-20:])
            boost = torch.ones_like(probs) * 0.1
            for token in range(probs.shape[1]):
                if token not in recent:
                    boost[0, token] = 1.0
            probs = probs + boost * 0.2
            probs = probs / probs.sum()  # Renormalizar

        return torch.multinomial(probs, num_samples=1).item()

Error 3: No Evaluar la Diversidad del Output

El tercer error crítico: solo medir si el texto "suena bien" sin cuantificar la diversidad. Puedes tener outputs coherentes pero sin variedad.

¿Por qué está mal? Sin diversidad, tu aplicación se vuelve monótona. Cada respuesta del chatbot suena igual. Cada código generado usa los mismos patrones.

La solución: Métricas cuantitativas de diversidad:

from collections import Counter
import math

class DiversityMetrics:
    """Métricas para evaluar diversidad del texto generado."""

    @staticmethod
    def token_type_ratio(text: str) -> float:
        """Type-Token Ratio: proporción de tokens únicos."""
        tokens = text.split()
        if not tokens:
            return 0.0
        unique_tokens = len(set(tokens))
        return unique_tokens / len(tokens)

    @staticmethod
    def unique_bigrams_ratio(text: str) -> float:
        """Proporción de bigramas únicos."""
        tokens = text.split()
        if len(tokens) < 2:
            return 0.0
        bigrams = [tuple(tokens[i:i+2]) for i in range(len(tokens) - 1)]
        return len(set(bigrams)) / len(bigrams)

    @staticmethod
    def entropy(text: str) -> float:
        """Entropía de Shannon: mide impredecibilidad."""
        tokens = text.split()
        if not tokens:
            return 0.0
        freq = Counter(tokens)
        total = len(tokens)
        entropy = 0.0
        for count in freq.values():
            p = count / total
            entropy -= p * math.log2(p)
        return entropy

    @staticmethod
    def repetition_ratio(text: str, n: int = 10) -> float:
        """Proporción de n-grams que se repiten."""
        tokens = text.split()
        if len(tokens) < n:
            return 0.0
        ngrams = [tuple(tokens[i:i+n]) for i in range(len(tokens) - n + 1)]
        unique = len(set(ngrams))
        repeated = len(ngrams) - unique
        return repeated / len(ngrams)

    @staticmethod
    def evaluate_diversity(texts: List[str]) -> Dict[str, float]:
        """Evalúa diversidad de un conjunto de textos."""
        results = {
            'avg_ttr': 0.0,
            'avg_entropy': 0.0,
            'avg_repetition_ratio': 0.0,
            'avg_unique_bigrams': 0.0,
        }

        for text in texts:
            results['avg_ttr'] += DiversityMetrics.token_type_ratio(text)
            results['avg_entropy'] += DiversityMetrics.entropy(text)
            results['avg_repetition_ratio'] += DiversityMetrics.repetition_ratio(text)
            results['avg_unique_bigrams'] += DiversityMetrics.unique_bigrams_ratio(text)

        n = len(texts)
        for key in results:
            results[key] /= n

        return results

Cómo Controlar Longitud y Formato

Para controlar longitud, tienes varias opciones:

  • max_new_tokens: Limita tokens nuevos (no afecta el prompt).
  • min_tokens: Asegura un mínimo (puede causar truncado extraño).
  • Stop sequences: Detener en ciertos strings como "###" o "\n\n".
  • Longitud target: Calcular tokens aproximados para el largo deseado.
class LengthControlledGenerator:
    """Generador con control de longitud preciso."""

    def __init__(self, model, tokenizer, target_words: int = 100):
        self.generator = TextGenerator(model, tokenizer)
        self.target_words = target_words
        # Aproximación: 1 token ≈ 0.75 palabras en inglés, 0.6 en español
        self.avg_words_per_token = 0.65
        self.target_tokens = int(target_words / self.avg_words_per_token)

    def generate_with_length_control(
        self,
        prompt: str,
        min_length: int = 20,
        max_length: int = 300,
        stop_at: List[str] = None
    ) -> str:
        """Genera texto con control de longitud."""

        max_new = max_length

        # Calcular tokens del prompt
        prompt_tokens = len(self.tokenizer.encode(prompt))
        max_new = min(self.target_tokens, max_length) - prompt_tokens

        config = GenerationConfig(
            max_new_tokens=max_new,
            stop_strings=stop_at or ["\n\n", "###", "FIN."]
        )

        result = self.generator.generate(prompt, config)

        # Post-procesamiento: asegurar que no exceda el límite de palabras
        words = result.split()
        if len(words) > self.target_words * 1.2:
            # Recortar al límite
            result = ' '.join(words[:int(self.target_words * 1.2)])

        return result

def format_output_json(text: str, fields: List[str]) -> str:
    """Formatea la salida como JSON con campos específicos."""

    lines = text.strip().split('\n')
    output = {}

    for field in fields:
        for line in lines:
            if field.lower() in line.lower():
                # Extraer valor después de los dos puntos
                if ':' in line:
                    value = line.split(':', 1)[1].strip()
                    output[field] = value
                    break

    return json.dumps(output, ensure_ascii=False, indent=2)

Resumen: sampling strategies para cada situación

# Quick reference para sampling strategies
SAMPLING_STRATEGIES = {
    # Conservative: máximo control, mínimo riesgo
    'code_generation': {
        'temperature': 0.2,
        'top_k': 20,
        'top_p': 0.85,
        'repetition_penalty': 1.3,
    },

    # Balanced: buena calidad con algo de variabilidad
    'general_writing': {
        'temperature': 0.6,
        'top_k': 40,
        'top_p': 0.9,
        'repetition_penalty': 1.2,
    },

    # Creative: máxima variabilidad
    'creative_writing': {
        'temperature': 1.0,
        'top_k': 80,
        'top_p': 0.95,
        'repetition_penalty': 1.0,  # Sin penalización para máxima creatividad
    },

    # Diversity-focused: para variedad máxima
    'diverse_outputs': {
        'temperature': 1.2,
        'top_k': 100,
        'top_p': 0.98,
        'repetition_penalty': 1.5,
    },

    # Extraction: datos estructurados
    'structured_extraction': {
        'temperature': 0.0,  # Greedy
        'top_k': 1,
        'top_p': 1.0,
        'repetition_penalty': 1.0,
    },
}

def get_best_strategy(task: str) -> Dict:
    """Retorna la mejor estrategia según el tipo de tarea."""
    if 'code' in task or 'program' in task:
        return SAMPLING_STRATEGIES['code_generation']
    elif 'creative' in task or 'story' in task or 'poem' in task:
        return SAMPLING_STRATEGIES['creative_writing']
    elif 'extract' in task or 'classif' in task or 'fact' in task:
        return SAMPLING_STRATEGIES['structured_extraction']
    elif 'diverse' in task or 'variety' in task:
        return SAMPLING_STRATEGIES['diverse_outputs']
    else:
        return SAMPLING_STRATEGIES['general_writing']

Cierre - Colombianito

Muy bien, entonces hoy aprendimos que generar texto con LLMs no es solo apretar el botón y rezar. Temperature, top-k, top-p, repetition penalty, control de longitud... todo importa. Y lo más importante: medir la diversidad de tus outputs.

La próxima vez que alguien te diga que su chatbot dice "Estimado cliente, su solicitud ha sido procesada satisfactoriamente" 47 veces, ya sabes qué responderle: "Amigo, eso no es un chatbot, eso es un loro con bachelor's degree en burocracia."

En resumen: ajusta la temperature según la tarea, controla la repetición, y siempre mide la diversidad. Si sigues estos tres principios, el 85% de los problemas de generación de texto desaparecen. Y eso, mi gente, es lo que separa a los que generan texto delicia de los que generan texto de voleta.
