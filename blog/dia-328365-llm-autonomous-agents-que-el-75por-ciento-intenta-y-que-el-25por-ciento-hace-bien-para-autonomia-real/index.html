🤖 LLM Autonomous Agents

Bueno, pues aquí andamos en el día 328, parcero. Hoy vamos a hablar de algo que mucho mundo intenta y poco pocos hacen bien: LLM Autonomous Agents. Sistemas que usan LLMs como el "cerebro" para tomar decisiones, planificar a largo plazo, y adaptarse cuando las cosas salen mal.

La idea es simple en papel: un agent que puede receber una tarea de alto nivel, decomposed en subtareas, execute actions, observe resultados, y adjust su approach based on feedback. Pero cuando uno se sienta a implementarlo, ahí es donde empieza el drama.

🏗️ Agent Architecture

Un LLM Autonomous Agent típico tiene varios componentes key:

  • Agent Core: El LLM que hace reasoning y decision-making
  • Memory: Sistema de almacenamiento para context, history, learned knowledge
  • Tools: Capacidades de acción (API calls, file operations, web search)
  • Planning: decompose tareas en steps, handle long-horizon planning
  • Reflection: Self-critique, error recovery, learning from mistakes

La arquitectura más popular (y la que vamos a implementar) es el agent loop: perception → reasoning → action → observation → repeat.

📐 El Agent Loop

"""
Agent Loop basico:
while not done:
    1. Perceive: obtener estado actual del ambiente
    2. Reason: usar LLM para decidir siguiente acción
    3. Act: ejecutar la acción
    4. Observe: obtener feedback del ambiente
    5. Reflect: actualizar memoria, evaluar si se necesita replan
"""

class AgentLoop:
    def __init__(self, llm, tools, memory_system):
        self.llm = llm
        self.tools = tools
        self.memory = memory_system
        self.max_iterations = 50
        self.success_criteria = None
    
    def run(self, task: str, initial_state: dict) -> dict:
        """
        Ejecuta el agent loop hasta completar la tarea o max_iterations.
        
        Args:
            task: Descripción de la tarea en lenguaje natural
            initial_state: Estado inicial del ambiente
        
        Returns:
            Dict con resultado final, historia de acciones, y métricas
        """
        state = initial_state.copy()
        history = []
        iteration = 0
        
        # Guardar la tarea en memoria
        self.memory.add("task", task)
        
        while iteration < self.max_iterations:
            iteration += 1
            
            # 1. PERCEPTION: Obtener contexto relevante de memoria
            relevant_context = self.memory.get_relevant(task, state, k=10)
            
            # 2. REASONING: El LLM decide la siguiente acción
            action = self._reason_about_action(task, state, relevant_context)
            
            if action is None:
                # No hay más acciones útiles, terminar
                break
            
            # 3. ACTION: Ejecutar la acción
            obs = self._execute_action(action, state)
            history.append({"iteration": iteration, "action": action, "observation": obs})
            
            # 4. OBSERVATION: Actualizar estado
            state.update(obs)
            
            # 5. REFLECTION: Evaluar y actualizar memoria
            self._reflect(action, obs, state, history)
            
            # Check si completamos la tarea
            if self._check_success(task, state):
                break
        
        return {
            "success": self._check_success(task, state),
            "iterations": iteration,
            "history": history,
            "final_state": state,
            "memory_summary": self.memory.get_summary()
        }
    
    def _reason_about_action(
        self, 
        task: str, 
        state: dict, 
        context: str
    ) -> Optional[dict]:
        """
        Usa el LLM para razonar sobre el siguiente action.
        
        El prompt incluye:
        - Tarea actual
        - Estado del ambiente
        - Contexto relevante de memoria
        - Available tools
        """
        available_tools = ", ".join(self.tools.list_available())
        
        prompt = f"""You are an autonomous agent. Your task is: {task}

Current state:
{self._format_state(state)}

Relevant context from memory:
{context}

Available tools: {available_tools}

Based on the current state and your task, decide on the next action to take.
Output format: JSON with 'tool_name' and 'parameters'.
If the task is complete, output: {{"tool_name": "done", "parameters": {{"reason": "explanation"}}}}
If you cannot make progress, output: {{"tool_name": "fail", "parameters": {{"reason": "explanation"}}}}
Only output valid JSON."""
        
        response = self.llm.generate(prompt)
        return self._parse_action(response)
    
    def _execute_action(self, action: dict, state: dict) -> dict:
        """Ejecuta una acción y retorna la observación."""
        tool_name = action.get("tool_name")
        params = action.get("parameters", {})
        
        if tool_name == "done" or tool_name == "fail":
            return {"terminal": True, "reason": params.get("reason")}
        
        # Ejecutar el tool
        tool = self.tools.get(tool_name)
        if tool is None:
            return {"error": f"Unknown tool: {tool_name}"}
        
        try:
            result = tool.execute(**params)
            return {"observation": result}
        except Exception as e:
            return {"error": str(e), "tool": tool_name}
    
    def _reflect(
        self, 
        action: dict, 
        observation: dict, 
        state: dict, 
        history: list
    ):
        """
        Reflection es lo que hace el agent 25% que lo hace bien.
        
        Después de cada acción, el agent:
        1. Evalúa si la acción fue útil
        2. Actualiza memoria con learnings
        3. Detecta si está stuck en un loop
        4. Considera estrategias alternativas si hay failures
        """
        # Guardar en memoria para futuro
        self.memory.add("action_result", {
            "action": action,
            "observation": observation,
            "timestamp": len(history)
        })
        
        # Detectar si estamos progresando
        recent_history = history[-5:]
        if self._is_stuck(recent_history):
            # Estamos en un loop, guardar fallback strategy
            self.memory.add("loop_detected", {
                "iteration": len(history),
                "strategy": "replan"
            })
        
        # Si hubo error, guardar para evitar en el futuro
        if "error" in observation:
            self.memory.add("error", {
                "action": action,
                "error": observation["error"],
                "iteration": len(history)
            })
    
    def _is_stuck(self, recent_history: list) -> bool:
        """Detecta si el agent está stuck en un loop."""
        if len(recent_history) < 5:
            return False
        
        recent_actions = [h["action"].get("tool_name") for h in recent_history]
        # Si las últimas 5 acciones son iguales, estamos en loop
        return len(set(recent_actions)) == 1
    
    def _check_success(self, task: str, state: dict) -> bool:
        """Check si la tarea fue completada."""
        # Lógica de success criteria
        return state.get("terminal", False)
    
    def _format_state(self, state: dict) -> str:
        """Formatea estado para el prompt."""
        return "\n".join([f"{k}: {v}" for k, v in state.items()])
    
    def _parse_action(self, response: str) -> Optional[dict]:
        """Parsea la respuesta del LLM a un action dict."""
        import json
        import re
        
        json_match = re.search(r'\{.*\}', response, re.DOTALL)
        if not json_match:
            return None
        
        try:
            return json.loads(json_match.group())
        except json.JSONDecodeError:
            return None

🧠 Self-Reflection y Error Recovery

El verdadero diferenciador entre agents que funcionan y los que no es el self-reflection. Sin esto, el agent hace las mismas ошибки una y otra vez. Con self-reflection, el agent aprende de sus fallos y adapta su estrategia.

class SelfReflectingAgent:
    """
    Agent con capacidades de self-reflection.
    
    Después de cada acción (o secuencia de acciones), el agent
    evalúa:
    1. ¿Fue exitosa la acción?
    2. ¿Qué aprendí de esta acción?
    3. ¿Debería cambiar mi estrategia?
    """
    
    def __init__(self, llm, tools, memory):
        self.llm = llm
        self.tools = tools
        self.memory = memory
        self.reflection_threshold = 3  # Reflexionar después de N acciones
    
    def reflect_on_action(self, action: dict, observation: dict, state: dict) -> str:
        """
        Genera una self-reflection sobre la acción ejecutada.
        
        Returns:
            String con la reflexión que se guarda en memoria
        """
        prompt = f"""Reflect on the following action and its result:

Action taken: {action}
Observation: {observation}
Current state: {state}

Evaluate:
1. Was this action successful? Why or why not?
2. What did I learn from this?
3. Should I change my approach for similar situations in the future?

Be concise and specific. Store key learnings that would help in similar situations."""

        reflection = self.llm.generate(prompt)
        
        # Guardar reflexión en memoria
        self.memory.add("reflection", {
            "action": action,
            "reflection": reflection,
            "timestamp": observation.get("iteration", 0)
        })
        
        return reflection
    
    def should_replan(self, history: list) -> tuple[bool, str]:
        """
        Decide si el agent debería replanificar completamente.
        
        Returns:
            (should_replan, reason)
        """
        if len(history) < self.reflection_threshold:
            return False, ""
        
        # Analizar últimos N intentos
        recent = history[-self.reflection_threshold:]
        errors = sum(1 for h in recent if "error" in h.get("observation", {}))
        
        if errors >= self.reflection_threshold // 2:
            # Más de la mitad fallaron, replanificar
            return True, f"{errors}/{len(recent)} actions failed recently"
        
        # Check por loops
        if self._detect_pattern_loop(history):
            return True, "Detected repeating pattern without progress"
        
        return False, ""
    
    def _detect_pattern_loop(self, history: list, window: int = 6) -> bool:
        """Detecta si estamos ejecutando el mismo patrón repetidamente."""
        if len(history) < window:
            return False
        
        recent = history[-window:]
        actions = [h["action"].get("tool_name") for h in recent]
        
        # Si todas las acciones en la ventana son iguales
        return len(set(actions)) == 1
    
    def generate_alternative_strategy(self, task: str, history: list) -> str:
        """
        Cuando el agent está stuck, genera una estrategia alternativa.
        """
        # Obtener historial relevante
        history_summary = self._summarize_history(history)
        
        prompt = f"""The current approach to this task isn't working.

Task: {task}

History of attempts:
{history_summary}

Based on what has and hasn't worked, propose a COMPLETELY DIFFERENT approach.
Think creatively about alternative methods to accomplish the same goal.
What assumptions are you making that might be wrong?

Provide a new strategy in clear steps."""

        new_strategy = self.llm.generate(prompt)
        
        self.memory.add("strategy_change", {
            "old_approach": history_summary,
            "new_strategy": new_strategy
        })
        
        return new_strategy
    
    def _summarize_history(self, history: list) -> str:
        """Resume el historial para el prompt."""
        lines = []
        for i, h in enumerate(history[-10:]):  # Últimas 10 acciones
            action = h.get("action", {})
            obs = h.get("observation", {})
            lines.append(f"{i+1}. {action.get('tool_name')}: {obs.get('observation', obs.get('error', 'no result'))}")
        return "\n".join(lines)

💾 Memory Management para Agents

El tercer pilar de agents confiables es el memory management. Sin una buena gestión de memoria, el agent no puede mantener contexto a largo plazo, aprende de errores pasados, ni sabe qué ha intentado antes.

from dataclasses import dataclass, field
from typing import Any, Optional, List
from datetime import datetime
import json

@dataclass
class MemoryEntry:
    """Una entrada individual en la memoria del agent."""
    type: str  # 'task', 'action_result', 'reflection', 'error', 'learned_fact'
    content: Any
    timestamp: float
    importance: float = 1.0  # 0-1, usado para prioritization
    access_count: int = 0
    last_accessed: Optional[float] = None

class VectorMemory:
    """
    Sistema de memoria para agents con retrieval por similitud.
    
    Organiza memories por tipo y permite retrieval basado en:
    1. Similitud semántica (usando embeddings)
    2. Recencia (tiempo desde último acceso)
    3. Importancia (relevancia global del hecho)
    4. Access frequency (hechos frecuentemente accedidos son más salient)
    """
    
    def __init__(self, embedder=None):
        # Store por tipo para acceso rápido
        self.by_type: dict[str, List[MemoryEntry]] = {}
        self.entries: List[MemoryEntry] = []
        self.embedder = embedder  # Para similarity search
        
        # Config
        self.max_entries = 10000
        self.importance_decay = 0.99  # Decay por acceso
        self.recency_weight = 0.3
        self.importance_weight = 0.3
        self.frequency_weight = 0.2
        self.relevance_weight = 0.2
    
    def add(self, type: str, content: Any, importance: float = 1.0):
        """Añade una entrada a la memoria."""
        entry = MemoryEntry(
            type=type,
            content=content,
            timestamp=datetime.now().timestamp(),
            importance=importance
        )
        
        self.entries.append(entry)
        
        if type not in self.by_type:
            self.by_type[type] = []
        self.by_type[type].append(entry)
        
        # Cleanup si hay overflow
        if len(self.entries) > self.max_entries:
            self._cleanup()
    
    def get_relevant(
        self, 
        query: str, 
        current_state: dict, 
        k: int = 10
    ) -> str:
        """
        Obtiene las k memorias más relevantes para la query actual.
        
        Usa un scoring ponderado de:
        - Similitud semántica con query
        - Recencia
        - Importancia
        - Frecuencia de acceso
        """
        now = datetime.now().timestamp()
        
        # Calcular scores para todas las entries
        scored_entries = []
        for entry in self.entries:
            recency_score = 1.0 / (1.0 + (now - entry.last_accessed) / 3600) if entry.last_accessed else 1.0
            frequency_score = min(entry.access_count / 10, 1.0)
            relevance_score = self._calculate_relevance(query, entry, current_state)
            
            total_score = (
                self.recency_weight * recency_score +
                self.importance_weight * entry.importance +
                self.frequency_weight * frequency_score +
                self.relevance_weight * relevance_score
            )
            
            scored_entries.append((total_score, entry))
        
        # Ordenar por score y tomar top k
        scored_entries.sort(reverse=True, key=lambda x: x[0])
        top_entries = scored_entries[:k]
        
        # Actualizar access stats
        for score, entry in top_entries:
            entry.access_count += 1
            entry.last_accessed = now
        
        # Formatear resultado
        return self._format_context(top_entries)
    
    def get_by_type(self, type: str, k: Optional[int] = None) -> List[Any]:
        """Obtiene todas las entradas de un tipo específico."""
        entries = self.by_type.get(type, [])
        if k:
            entries = entries[-k:]
        return [e.content for e in entries]
    
    def get_summary(self) -> str:
        """Retorna un resumen de la memoria actual."""
        type_counts = {t: len(entries) for t, entries in self.by_type.items()}
        return json.dumps({
            "total_entries": len(self.entries),
            "by_type": type_counts,
            "most_accessed": self._get_most_accessed(5)
        })
    
    def _calculate_relevance(
        self, 
        query: str, 
        entry: MemoryEntry, 
        current_state: dict
    ) -> float:
        """
        Calcula qué tan relevante es una memoria para la query actual.
        
        Considera:
        - Si la query menciona el tipo de contenido
        - Si el contenido es relevante al estado actual
        """
        query_lower = query.lower()
        content_str = json.dumps(entry.content).lower()
        
        # Score por coincidencia de keywords
        relevance = 0.0
        if entry.type in query_lower:
            relevance += 0.3
        if any(word in content_str for word in query_lower.split()[:5]):
            relevance += 0.5
        
        return min(relevance, 1.0)
    
    def _format_context(self, scored_entries: list) -> str:
        """Formatea las entries para contexto del LLM."""
        lines = ["Relevant context from memory:"]
        for i, (score, entry) in enumerate(scored_entries, 1):
            content = entry.content if isinstance(entry.content, str) else json.dumps(entry.content)
            lines.append(f"{i}. [{entry.type}] {content[:200]}")
        return "\n".join(lines)
    
    def _cleanup(self):
        """Remove entries menos importantes cuando hay overflow."""
        # Calcular scores y remover bottom 10%
        now = datetime.now().timestamp()
        scored = []
        for entry in self.entries:
            score = entry.importance * (0.9 ** entry.access_count)
            scored.append((score, entry))
        
        scored.sort(key=lambda x: x[0])
        to_remove = scored[:len(scored) // 10]
        
        for score, entry in to_remove:
            self.entries.remove(entry)
            if entry in self.by_type.get(entry.type, []):
                self.by_type[entry.type].remove(entry)
    
    def _get_most_accessed(self, k: int) -> List[str]:
        """Retorna los tipos de las k memorias más accedidas."""
        by_access = sorted(
            self.entries, 
            key=lambda e: e.access_count, 
            reverse=True
        )
        return [e.type for e in by_access[:k]]

⚠️ Los 3 Errores Que el 75% Comete

❌ Error 1: No Tener una Agent Architecture Proper

El error más básico es construir agents sin una arquitectura clara. La gente hace un while loop con un LLM y espera que funcione. Spoiler: no funciona.

Un agent sin arquitectura adecuada tiene problemas como:

  • No puede mantener contexto a largo plazo
  • No distingue entre diferentes tipos de información
  • No tiene manera de recover de errores
  • Se olvida de lo que hizo hace 10 iterations

Fix: Diseñar desde el inicio con componentes separados: memory system, planning module, reflection module, tool interface. Cada uno con responsabilidad clara.

❌ Error 2: No Handle Failures Gracefully

El segundo error es assumed que todas las acciones van a succeed. En el mundo real, las APIs fallan, los calls timeout, los parámetros son wrong. Si el agent no handlea failures, se queda stuck o hace cosas peores.

"Un agent que no puede handle failure no es un agent autónomo — es un script frágil que se rompe con el primer error."

Fix: Implementar:

  • Try-catch en todas las executions
  • Retry logic con exponential backoff
  • Error categorization (retryable vs fatal)
  • Fallback strategies cuando primary approach falla
  • Self-reflection después de failures para evitar repetir errores

❌ Error 3: No Tener Memory Management

El tercer error es ignorar la memoria del agent. Sin memoria, cada iteration es como starting from scratch. El agent no aprende de errores pasados, no sabe qué ha intentado, y no puede build on previous work.

Los symptoms de no tener memoria:

  • El agent hace la misma pregunta repetidamente
  • No reconoce que ya intentó algo y falló
  • Cada conversation es completamente independent
  • No puede accumulate knowledge across tasks

Fix: Implementar un memory system con:

  • Short-term memory para contexto inmediato
  • Long-term memory para facts learned
  • Episodic memory para guardar action sequences completas
  • Prioritized retrieval basado en relevance y recency

📊 La Formula del Agent Reliability

Podemos medir la confiabilidad de un agent con:

"""
Agent Reliability Score = f(success_rate, avg_iterations, recovery_rate)

- success_rate: % de tareas completadas exitosamente
- avg_iterations: promedio de iteraciones por tarea
- recovery_rate: % de failures de los que el agent se recovered

Un agent confiable tiene:
- High success_rate (>80%)
- Low avg_iterations (<20 para tareas típicas)
- High recovery_rate (>50% de errores recuperados)
"""

def calculate_agent_reliability(history: list) -> dict:
    total_tasks = len(history)
    if total_tasks == 0:
        return {"reliability_score": 0}
    
    successes = sum(1 for h in history if h.get("success"))
    total_iterations = sum(h.get("iterations", 0) for h in history)
    recoveries = sum(1 for h in history if h.get("recovered_from_error"))
    
    success_rate = successes / total_tasks
    avg_iterations = total_iterations / total_tasks
    recovery_rate = recoveries / max(sum(1 for h in history if not h.get("success")), 1)
    
    # Score compuesto (0-100)
    reliability = (
        success_rate * 50 +  # 50% del score es success rate
        max(0, (20 - avg_iterations) / 20) * 25 +  # 25% es eficiencia
        recovery_rate * 25  # 25% es capacidad de recovery
    )
    
    return {
        "reliability_score": reliability * 100,
        "success_rate": success_rate,
        "avg_iterations": avg_iterations,
        "recovery_rate": recovery_rate
    }

🎯 Resumen y Cierre Colombiano

Pues ahí lo tienen, gente. LLM Autonomous Agents es un campo donde el 75% intenta pero el 25% lo hace bien. La diferencia está en los detalles:

  1. Arquitectura proper: No es solo un while loop con un LLM. Son componentes separados que trabajan juntos.
  2. Error handling robusto: Los failures son inevitables. Lo que diferencia a los buenos agents es cómo se recovered de ellos.
  3. Memory management serio: Sin memoria, no hay autonomía real. El agent tiene que poder aprender y recordar.

El agent del 25% tiene reflection, memory, recovery strategies, y una arquitectura que permite que cada pieza haga lo que tiene que hacer bien. El agent del 75% hace un loop de "generate action, execute, repeat" y se sorprende cuando se rompe.

Construir agents confiables es hard. Pero cuando funciona, es poderoso: tienes un sistema que puede receber una tarea compleja, decomposed en partes, execute con robustness, y learn from experience.
