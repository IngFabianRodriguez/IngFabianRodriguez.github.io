Dia 221/365: APIs REST con FastAPI — La torre de control que tu modelo llevaba años necesitando

9 de agosto de 2026
fastapi, uvicorn

Introduccion: La mentira del "es solo JSON"

Hay una frase que he escuchado en cuatro empresas distintas, casi con las mismas palabras: "parce, monte el endpoint y ya, ¿qué tan dificil es serializar un dict?". Esa frase es el preludio de un incidente a las 3 a. m. Tres ejemplos sin nombres, pero con la cicatriz:

Primero: equipo de riesgo crediticio en fintech, XGBoost afinado tres meses, AUC 0.91. Lo desplegaron detrás de un endpoint FastAPI con model.predict() sincrono y body JSON de tamano variable. Funciono en staging con 50 RPS. El dia uno en produccion, un cliente corporativo mando un payload de 1.4 MB con un campo historical_transactions de 8 000 elementos sin comprimir. El event loop se bloqueo 1.8 segundos, p99 salto de 80 ms a 4 100 ms y el CEO llamo.

Segundo: equipo de vision con un detector YOLO. Mismo FastAPI, mismo error conceptual: preprocesamiento dentro del handler. La convolucion bloqueaba el loop. Una sola imagen grande colapsaba la cola entera.

Tercero, el mas bonito: una API REST que parecia REST pero no lo era. Devolvia 200 OK con error: "validation failed" dentro del body. La libreria cliente no chequeaba status_code, solo leia el JSON. Bugs silenciosos durante seis meses. Eso no es REST, es HTTP vestido de domingo.

Lo que une los tres: pensaron que la capa de transporte era "gratis". No lo es. Cada byte que entra, cada byte que sale, cada milisegundo que el event loop pasa bloqueado, es dinero real en SLA y credibilidad tecnica. Este articulo es sobre la matematica que sustenta una API REST production-grade y como FastAPI + Uvicorn la implementan (casi) sin que tengas que pensarlo, pero solo si entiendes que estan haciendo por debajo.

1. Que es una API REST? (Y por que deberia importarte)

1.1 La analogia cotidiana: la torre de control de El Dorado

Piensa en la torre de control del aeropuerto El Dorado. Torre REST y aeropuerto operado comparten la misma estructura. El controlador (servidor) no pilota los aviones (no ejecuta la logica de negocio de cada vuelo), coordina y delega. Cada avion (request) lleva plan de vuelo firmado (headers), lista de pasajeros y carga (body) y destino especifico (path: /flights/AA1234). El controlador no recuerda el vuelo de ayer para autorizar el de hoy: cada operacion se evalua con la informacion que trae el avion en ese instante. Eso es stateless.

La pista tiene capacidad finita (concurrencia del event loop). Si llegan demasiados aviones a la vez, el controlador pone algunos en patron de espera sobre la pista auxiliar (cola interna, backpressure) o los desvia a otro aeropuerto (502/503 desde el load balancer upstream). La torre no asume que el avion de las 14:00 hablo con el de las 14:05. No guarda estado entre operaciones, pero si mantiene libro de registro permanente (logs) y transmisiones radiales bien tipificadas (HTTP status codes).

Cuando un avion aterriza, recibe acuse formal: pista ocupada, timestamp de touchdown, numero de puerta asignado (response con headers + status 200/201). Si algo sale mal, no aterrizo: recibio "go around" (4xx para errores del cliente, 5xx para errores del servidor). Lo critico: el acuse es normalizado. No importa si el avion es de Avianca, LATAM o jet privado. El formato de la respuesta es predecible. Eso es la Uniform Interface, la constraint mas abusada y la mas importante.

1.2 La matematica que Fielding escondio en su tesis

Roy Fielding fundo REST en el 2000. Lo que el 90% de los articulos repiten son los nombres de las seis constraints. Lo que nadie desglosa es que propiedad operativa garantiza cada una. Vamos alla:

$$S_{t+1} = f(R_t)$$

Stateless: el estado del sistema al recibir el request $R_t$ depende solo de $R_t$, no de $R_{t-1}$ ni de variables internas del servidor. Por eso cualquier worker puede procesar cualquier request sin coordinarse con los demas. En terminos de capacidad se traduce directo a la Ley de Little:

$$L = \lambda \cdot W$$

donde $L$ es el numero promedio de requests en el sistema, $\lambda$ la tasa de llegada (RPS) y $W$ el tiempo promedio de residencia (latencia end-to-end). Si tu $W$ sube por un await asyncio.sleep(2) mal puesto, $L$ sube linealmente. Si $L$ supera la concurrencia maxima del event loop, empiezas a rechazar. Esa es la matematica del colapso.

Cacheable: las respuestas deben declarar si son cacheables (Cache-Control, ETag). Si GET /models/v3 cambia cada 60 s, declararlo cacheable reduce $\lambda$ efectiva al servidor segun el hit ratio $h$:

$$\lambda_{\text{server}} = \lambda_{\text{client}} \cdot (1 - h)$$

Con $h = 0.7$, tu servidor solo ve el 30% del trafico. Eso es dinero, no poesia.

Uniform Interface: el recurso se identifica por URI, la representacion es separada de la identidad (un mismo recurso puede devolverse como JSON o XML), y los mensajes son autodescriptivos. Que tu API use POST para todo y devuelva 200 OK con error adentro no es REST. Es HTTP decorativo.

$$\text{Idempotencia: } f(x) = f(f(x))$$

Safety e idempotencia por metodo: GET es safe (ejecutarlo N veces produce el mismo estado observable); PUT/DELETE son idempotentes (producen el mismo estado final ejecutados una o N veces). Esto es lo que permite que un cliente reintente sin causar duplicados. Si tu POST /charge-card no es idempotente, una caida de red te puede cobrar dos veces. He visto el chargeback.

Layered System: el cliente no debe distinguir si habla con el servidor real o un proxy. Se rompe cuando firmas responses con secretos que el CDN no deberia ver, o cuando metes logica de negocio en nginx.

2. Como FastAPI + Uvicorn resuelven esto por vos

La torre (Uvicorn) maneja el patron de trafico global. El sistema de aterrizaje automatico (Starlette, sobre el que se monta FastAPI) ejecuta el protocolo por avion. Los controladores de vuelo especificos (tus handlers, tu Pydantic) deciden si ese avion tiene permiso para aterrizar.

Internet (TCP)
   |
   v
[ uvicorn: socket server + event loop (uvloop) ]
   |
   v
[ httptools: parser HTTP/1.1 byte-by-byte ]
   |
   v
[ ASGI scope dict por request ]
   |
   v
[ Starlette: router -> endpoint -> response ]
   |
   v
[ Tu handler + Pydantic validation + tu modelo ]

Uvicorn recibe bytes del socket TCP, los pasa por httptools (parser en C, 2-3x mas rapido que http.server de stdlib) y por cada request construye un dict scope que es la especificacion ASGI. El scope contiene type, method, path, headers, query_string y state. Tu app FastAPI hereda de Starlette, implementacion canonica de ASGI.

El event loop por defecto usa asyncio puro. Uvicorn puede reemplazarlo por uvloop, un binding a libuv (mismo motor de Node.js). En operaciones I/O la diferencia es tipicamente 2x a 4x. En CPU-bound no se siente porque hay un solo thread.

Starlette convierte el scope en una request, ejecuta el middleware chain, hace routing y entrega la request a tu handler. FastAPI anade encima: validacion con Pydantic, OpenAPI auto, dependency injection y response models.

Pydantic v2 reescribio el nucleo en Rust (pydantic-core). Validacion que en v1 tomaba ~120 us por objeto, en v2 toma ~10 us. A 10 000 transacciones por minuto y ~20 campos cada una, ahorras 1.2 segundos de CPU por minuto solo validando.

3. FastAPI: Uso directo y casos de control fino

Cuando la app es critica no uses decoradores sueltos. App factory + lifespan (reemplazo moderno de @app.on_event("startup") deprecado en Starlette 0.21+):

# app/app_factory.py
from __future__ import annotations

import logging
import os
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI
from prometheus_client import make_asgi_app

from app.inference import FraudInferenceEngine
from app.metrics import MetricsMiddleware
from app.routes import predictions, batch

log = logging.getLogger("fraud.api")


def create_app(model_path: str, *, workers: int = 1) -> FastAPI:
    engine = FraudInferenceEngine(model_path=model_path)

    @asynccontextmanager
    async def lifespan(app: FastAPI) -> AsyncIterator[None]:
        await engine.warmup()
        log.info("engine ready: %s", engine.version)
        try:
            yield
        finally:
            await engine.drain(timeout_s=10.0)
            log.info("engine drained, exiting cleanly")

    app = FastAPI(
        title="fraud-inference",
        version="2.4.1",
        lifespan=lifespan,
        docs_url="/docs" if os.getenv("ENV") != "prod" else None,
        openapi_url=None if os.getenv("ENV") == "prod" else "/openapi.json",
    )

    app.state.engine = engine
    app.state.workers = workers

    # /metrics separado del flujo principal de negocio
    app.mount("/metrics", make_asgi_app())
    # Middleware: orden importa. Metricas ANTES de auth.
    app.add_middleware(MetricsMiddleware, threshold_ms=100.0)

    app.include_router(predictions.router, prefix="/v2")
    app.include_router(batch.router, prefix="/v2")
    return app
# main.py
import os
import uvicorn

if __name__ == "__main__":

        port=int(os.getenv("PORT", "8080")),
        workers=int(os.getenv("WEB_CONCURRENCY", "1")),
        loop="uvloop",
        http="httptools",

4. Implementacion Production-Ready: FraudInferenceService

Servicio real de scoring de fraude. Pensado para 500 RPS con p99 de 80 ms sobre CPU-only.

4.1 Tipos y protocolos

# app/schemas.py
from __future__ import annotations

from datetime import datetime, timezone
from enum import Enum
from typing import Annotated, Literal

from pydantic import BaseModel, ConfigDict, Field, field_validator


class MerchantCategory(str, Enum):
    RETAIL = "retail"
    TRAVEL = "travel"
    GAMING = "gaming"
    DIGITAL_GOODS = "digital_goods"


class FeatureVector(BaseModel):
    """Validado en el borde. frozen=True previene mutaciones accidentales."""
    model_config = ConfigDict(extra="forbid", frozen=True, str_strip_whitespace=True)

    transaction_id: Annotated[str, Field(min_length=8, max_length=64,
                                        pattern=r"^[A-Z0-9_-]+$")]
    amount_cents: Annotated[int, Field(ge=0, le=10**11)]
    merchant_category: MerchantCategory
    device_trust_score: Annotated[float, Field(ge=0.0, le=1.0)]
    hour_of_day: Annotated[int, Field(ge=0, le=23)]
    historical_avg_amount_cents: Annotated[int, Field(ge=0)]

    @field_validator("amount_cents")
    @classmethod
    def sane_amount(cls, v: int) -> int:
        if v > 5_000_000_000:
            raise ValueError("amount_cents exceeds 50M COP units hard cap")
        return v

    @field_validator("device_trust_score")
    @classmethod
    def not_nan(cls, v: float) -> float:
        if v != v:  # NaN != NaN, unico test confiable
            raise ValueError("device_trust_score must not be NaN")
        return v


class FraudDecision(str, Enum):
    APPROVE = "approve"
    REVIEW = "review"
    DECLINE = "decline"


class FraudPrediction(BaseModel):
    model_config = ConfigDict(extra="forbid")

    transaction_id: str
    risk_score: Annotated[float, Field(ge=0.0, le=1.0)]
    decision: FraudDecision
    model_version: str
    scored_at: datetime
    latency_ms: Annotated[float, Field(ge=0.0)]
    feature_importance: dict[str, float]

    @field_validator("scored_at")
    @classmethod
    def utc_only(cls, v: datetime) -> datetime:
        if v.tzinfo is None or v.utcoffset() != timezone.utc.utcoffset(v):
            raise ValueError("scored_at must be UTC-aware")
        return v


class HealthStatus(BaseModel):
    model_config = ConfigDict(extra="forbid")

    status: Literal["healthy", "degraded", "down"]
    model_version: str
    model_loaded_at: datetime
    queue_depth: Annotated[int, Field(ge=0)]
    p99_latency_ms: Annotated[float, Field(ge=0.0)]
    last_drain_at: datetime | None

extra="forbid" evita inyeccion de campos no documentados. frozen=True evita que un middleware intermedio mute el request. pattern=r"^[A-Z0-9_-]+$" evita basura en logs downstream. Defensa en profundidad sin ser overkill.

4.2 El motor principal

# app/inference.py
from __future__ import annotations

import asyncio
import logging
import time
from collections import deque
from datetime import datetime, timezone
from pathlib import Path

import numpy as np
import onnxruntime as ort

from app.schemas import FeatureVector, FraudPrediction, FraudDecision, MerchantCategory

log = logging.getLogger("fraud.engine")


class ServiceShuttingDown(Exception):
    """El cliente debe reintentar en otro nodo."""


class FraudInferenceEngine:
    """Encapsula carga lazy del modelo, cola con backpressure,
    p99 con sliding window y drain en shutdown."""

    def __init__(self, model_path: str | Path, *,
                 max_inflight: int = 64, window_size: int = 1024) -> None:
        self._model_path = Path(model_path)
        self._session: ort.InferenceSession | None = None
        self._sem = asyncio.Semaphore(max_inflight)
        self._latencies: deque[float] = deque(maxlen=window_size)
        self._in_flight = 0
        self._draining = False
        self._model_loaded_at: datetime | None = None

    async def warmup(self) -> None:
        loop = asyncio.get_running_loop()
        self._session = await loop.run_in_executor(None, self._load_session)
        # 5 iteraciones dummy: ONNX pre-compila kernels.
        for _ in range(5):
            await self._predict_raw(np.zeros((1, 6), dtype=np.float32))
        self._model_loaded_at = datetime.now(timezone.utc)

    def _load_session(self) -> ort.InferenceSession:
        sess = ort.InferenceSession(self._model_path.as_posix(),
                                    providers=["CPUExecutionProvider"])
        return sess

    async def drain(self, *, timeout_s: float) -> None:
        self._draining = True
        deadline = time.monotonic() + timeout_s
        while self._in_flight > 0 and time.monotonic() < deadline:
            await asyncio.sleep(0.05)
        log.info("drain complete, %d still in flight", self._in_flight)

    async def score(self, fv: FeatureVector) -> FraudPrediction:
        if self._draining:
            raise ServiceShuttingDown("engine draining, retry elsewhere")
        async with self._sem:
            self._in_flight += 1
            try:
                t0 = time.perf_counter()
                arr = self._to_array(fv)
                risk, top_feats = await self._predict_raw(arr)
                dt_ms = (time.perf_counter() - t0) * 1000.0
                self._latencies.append(dt_ms)
                return FraudPrediction(
                    transaction_id=fv.transaction_id,
                    risk_score=float(risk),
                    decision=_to_decision(float(risk)),
                    model_version=self.version,
                    scored_at=datetime.now(timezone.utc),
                    latency_ms=dt_ms,
                    feature_importance=top_feats,
                )
            finally:
                self._in_flight -= 1

    def _to_array(self, fv: FeatureVector) -> np.ndarray:
        return np.array([[
            fv.amount_cents / 100.0,
            fv.device_trust_score,
            fv.hour_of_day / 23.0,
            float(fv.merchant_category == MerchantCategory.GAMING),
            float(fv.merchant_category == MerchantCategory.TRAVEL),
            float(fv.merchant_category == MerchantCategory.DIGITAL_GOODS),
        ]], dtype=np.float32)

    async def _predict_raw(self, arr: np.ndarray) -> tuple[float, dict[str, float]]:
        assert self._session is not None
        loop = asyncio.get_running_loop()
        # onnxruntime NO libera el GIL: run_in_executor es obligatorio.
        outs, exps = await loop.run_in_executor(
            None, self._session.run,
            ["risk_score", "top_features"], {"features": arr},
        )
        return float(outs[0][0]), dict(exps)

    @property
    def version(self) -> str:
        return "fraud-xgb-v3.4.1-onnx"

    @property
    def p99_latency_ms(self) -> float:
        if not self._latencies:
            return 0.0
        s = sorted(self._latencies)
        return s[int(0.99 * (len(s) - 1))]

    @property
    def queue_depth(self) -> int:
        return self._in_flight


def _to_decision(risk: float) -> FraudDecision:
    # Umbrales calibrados contra la curva ROC del ultimo mes.
    # NO hardcodear: vendran de config remota.
    if risk < 0.20:
        return FraudDecision.APPROVE
    if risk < 0.65:
        return FraudDecision.REVIEW
    return FraudDecision.DECLINE

Decisiones deliberadas:

  • asyncio.Semaphore para backpressure: en lugar de rechazar a ciegas cuando llega la request 65, el semaforo encola hasta max_inflight=64 y rechaza en el handler si la cola esta saturada. Esto es el equivalente a "go around" del avion.
  • deque(maxlen=window_size) para p99: O(1) por insercion, O(N log N) por sort al consultar. Para 1 024 muestras son microsegundos.
  • run_in_executor para ONNX: onnxruntime no libera GIL en CPU. Mover inferencia a thread pool evita bloquear el event loop.

4.3 Utilidades de analisis y verificacion

# app/load_test.py
"""Stress test client. NO es parte del API, vive aparte."""
from __future__ import annotations

import asyncio
import statistics
import time

import httpx

from app.schemas import FeatureVector, MerchantCategory


def make_sample(i: int) -> FeatureVector:
    cats = list(MerchantCategory)
    return FeatureVector(
        transaction_id=f"TXN-{i:08d}",
        amount_cents=(i * 137) % 1_000_000,
        merchant_category=cats[i % len(cats)],
        device_trust_score=0.5 + 0.5 * (i % 100) / 100,
        hour_of_day=i % 24,
        historical_avg_amount_cents=10_000,
    )


async def load_test(base_url: str = "http://localhost:8080",
                    *, n: int = 5000, concurrency: int = 50) -> None:
    samples = [make_sample(i).model_dump() for i in range(n)]
    async with httpx.AsyncClient(base_url=base_url,
                                 timeout=httpx.Timeout(30.0)) as client:
        sem = asyncio.Semaphore(concurrency)

        async def one(i: int) -> float:
            async with sem:
                t0 = time.perf_counter()
                r = await client.post("/v2/predict", json=samples[i])
                r.raise_for_status()
                return (time.perf_counter() - t0) * 1000.0

        t_global = time.perf_counter()
        results = await asyncio.gather(*(one(i) for i in range(n)))
        elapsed = time.perf_counter() - t_global

    p50 = statistics.median(results)
    p99 = sorted(results)[int(0.99 * len(results)) - 1]
    rps = n / elapsed
    print(f"n={n} concurrency={concurrency} elapsed={elapsed:.2f}s "
          f"rps={rps:.1f} p50={p50:.1f}ms p99={p99:.1f}ms")


if __name__ == "__main__":
    asyncio.run(load_test())

Si lo corres contra uvicorn app.main:app --workers 4 en 8 cores deberias ver p50 ~12 ms y p99 ~50 ms para 5 000 requests. Si no, mira la seccion de debugging.

Caso 2: shadow traffic para validar v4 contra v3.4.1.

# app/routes/predictions.py
from __future__ import annotations

import asyncio
import logging

from fastapi import APIRouter, Request, Response

from app.inference import FraudInferenceEngine
from app.schemas import FeatureVector

log = logging.getLogger("fraud.routes")
router = APIRouter(tags=["predictions"])


@router.post("/predict")
async def predict(payload: FeatureVector, request: Request) -> Response:
    engine: FraudInferenceEngine = request.app.state.engine
    primary = await engine.score(payload)

    v4_engine = getattr(request.app.state, "v4_engine", None)
    if v4_engine is not None:
        asyncio.create_task(_shadow_score(payload, primary, v4_engine))

    body = primary.model_dump_json()
    return Response(content=body, media_type="application/json",
                    headers={"X-Model-Version": primary.model_version})


async def _shadow_score(payload: FeatureVector, primary,
                        v4_engine: FraudInferenceEngine) -> None:
    try:
        shadow = await v4_engine.score(payload)
        if abs(shadow.risk_score - primary.risk_score) > 0.30:
            log.warning("shadow_divergence id=%s v3=%.3f v4=%.3f",
                        payload.transaction_id,
                        primary.risk_score, shadow.risk_score)
    except Exception:
        # Shadow NUNCA debe afectar al primary.
        log.exception("shadow_failed id=%s", payload.transaction_id)

Canary release para modelos: el cliente nunca sabe que existe v4, pero tu mides divergencia. Cuando el 0.1% de transacciones diverge mas de 0.30 en risk_score, haces el switch.

Caso 3: batch scoring asincrono (jobs corporativos > 10k txs).

# app/routes/batch.py
from __future__ import annotations

import asyncio
from uuid import uuid4

from fastapi import APIRouter, BackgroundTasks, HTTPException, status

from app.inference import FraudInferenceEngine
from app.schemas import FeatureVector, FraudPrediction

router = APIRouter(prefix="/batch", tags=["batch"])
_JOBS: dict[str, dict] = {}  # en prod: Redis o Postgres


@router.post("/score", status_code=status.HTTP_202_ACCEPTED)
async def submit_batch(payload: list[FeatureVector],
                       background: BackgroundTasks) -> dict:
    if len(payload) > 50_000:
        raise HTTPException(
            status_code=status.HTTP_413_REQUEST_ENTITY_TOO_LARGE,
            detail="batch > 50k transactions must be uploaded to S3",
        )
    job_id = str(uuid4())
    _JOBS[job_id] = {"status": "pending", "received": len(payload),
                     "processed": 0, "results": []}
    background.add_task(_run_batch, job_id, payload)
    return {"job_id": job_id, "status_url": f"/v2/batch/{job_id}"}


@router.get("/{job_id}")
async def get_job(job_id: str) -> dict:
    job = _JOBS.get(job_id)
    if job is None:
        raise HTTPException(status_code=404, detail="job not found")
    return {"status": job["status"], "processed": job["processed"],
            "total": job["received"]}


async def _run_batch(job_id: str, payload: list[FeatureVector]) -> None:
    engine: FraudInferenceEngine = _JOBS[job_id].get("_engine")  # wired en lifespan
    results: list[FraudPrediction] = []
    for i, fv in enumerate(payload):
        results.append(await engine.score(fv))
        _JOBS[job_id]["processed"] = i + 1
    _JOBS[job_id].update({"status": "done", "results": results})

Devolvemos 202 Accepted con job_id y URL de polling. Esa es la semantica REST correcta: el servidor no termino, pero reconoce la recepcion. El cliente hace GET periodico a /v2/batch/{job_id}.

6. Debugging: Cuando todo se va a la mierda

Problema 1: el event loop se bloquea con payloads grandes

Sintoma: p99 salta de 80 ms a segundos, todas las requests concurrentes sufren. Deteccion numerica con un middleware de observabilidad:

# app/metrics.py
from __future__ import annotations

import logging
import time
from collections import defaultdict

from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.types import ASGIApp

log = logging.getLogger("fraud.metrics")


class MetricsMiddleware(BaseHTTPMiddleware):
    """Detecta handlers que bloquean el event loop >= threshold ms."""

    def __init__(self, app: ASGIApp, *, threshold_ms: float = 100.0) -> None:
        super().__init__(app)
        self.threshold_ms = threshold_ms
        self._suspects: dict[str, list[float]] = defaultdict(list)

    async def dispatch(self, request: Request, call_next):
        t0 = time.perf_counter()
        response = await call_next(request)
        elapsed_ms = (time.perf_counter() - t0) * 1000.0
        path = request.url.path
        if elapsed_ms > self.threshold_ms and path not in ("/health", "/metrics"):
            self._suspects[path].append(elapsed_ms)
            recent = self._suspects[path][-20:]
            if len(self._suspects[path]) >= 5:
                avg = sum(recent) / len(recent)
                log.warning("slow handler: %s avg=%.1fms last=%.1fms",
                            path, avg, elapsed_ms)
        return response

Si vez "slow handler", el culpable es codigo dentro del handler que no es await-able. Las tres soluciones:

# MAL: handler sync tocando CPU pesada => bloquea el loop
@router.post("/predict")
def predict(payload: FeatureVector):  # sync, NO async
    df = pd.DataFrame([payload.model_dump()])
    return model.predict(df)

# BIEN Opcion A: handler async + run_in_executor
@router.post("/predict")
async def predict(payload: FeatureVector):
    loop = asyncio.get_running_loop()
    df = await loop.run_in_executor(None, pd.DataFrame, [payload.model_dump()])
    return await loop.run_in_executor(None, model.predict, df)

# BIEN Opcion B: handler sync declarado, FastAPI lo envia al default_executor
@router.post("/predict")
def predict(payload: FeatureVector):
    return model.predict(pd.DataFrame([payload.model_dump()])).tolist()

# BIEN Opcion C: el handler es I/O puro, todo async
@router.post("/predict")
async def predict(payload: FeatureVector):
    async with httpx.AsyncClient() as client:
        r = await client.post(downstream_url, json=payload.model_dump())
    return r.json()

Regla: si tocas CPU pesada (pandas, numpy, onnx) y declaras async def, debes usar run_in_executor adentro. Si no tocas CPU, declara async def y usa solo awaits.

7. Optimizaciones de produccion

Opt 1: orjson en lugar de json estandar

orjson es 2-5x mas rapido serializando Python objects a JSON y soporta Enum, datetime, dataclass nativamente.

# app/orjson_patch.py
from __future__ import annotations

import orjson

from fastapi.responses import JSONResponse as _JSONResponse


class ORJSONResponse(_JSONResponse):
    def render(self, content) -> bytes:
        return orjson.dumps(content, option=orjson.OPT_NON_STR_KEYS)


# Uso:
@router.get("/health", response_class=ORJSONResponse)
async def health():
    return {"status": "healthy"}

Trade-off: ganais latencia, perdes el json.dumps configurable de stdlib (por ejemplo, allow_nan=False ya es default en orjson, que tira error en vez de generar NaN JSON invalido: esto es bueno). En APIs de lectura intensivas es casi obligatorio.

8. Conclusion: por que esto te salva el pellejo en produccion

Tu modelo no vale nada si la API que lo expone colapsa bajo carga o devuelve semantica incorrecta. La torre de El Dorado no se improvisa, y tu endpoint REST tampoco. Repaso final en cinco bullets:

  • Stateless real: si guardas sesion en memoria del worker, pierdes escalado horizontal. Sacalo a Redis o JWT.
  • OpenAPI generado pero cerrado en prod: /docs y /openapi.json son superficie de ataque. Configuralos con variable de entorno.
  • asyncio.Semaphore + run_in_executor: la combinacion correcta para backpressure sin bloquear el event loop.
  • uvloop + httptools + orjson: triple activacion en uvicorn.run(...) para ~3x throughput medible en benchmarks sinteticos.
  • Validacion en el borde con extra="forbid" y frozen=True: la entrada es la unica superficie que controlas fuerte. Se paranoico.

No hay fiesta con la API del modelo. Es el contrato entre tu matematica y el mundo real. Si esta mal, todo lo que hiciste durante semanas de entrenamiento es invisible.
