Causal Inference en ML — El Pensamiento Que El 90% Evita Y Paga Con Conclusiones Equivocadas

Hagale pues, parcero. Aquí en Medellín, cuando alguien dice "después del aguacero siempre sale el sol", está haciendo inferencia causal sin saberlo. Pero en machine learning, el 90% de los practitioners confunde correlación con causalidad y termina tomando decisiones basadas en espejismos estadísticos. Hoy desarmamos ese problema.

🌧️ Correlación vs Causalidad — El Error Que Cuesta Millones

Todo empieza con una distinción fundamental. Dos variables correlacionadas no necesariamente tienen relación de causa-efecto.

# Ejemplo clásico: correlación no implica causalidad
import numpy as np
import pandas as pd

np.random.seed(42)
n = 1000

# Confounder: ambos causados por una tercera variable
confounder = np.random.normal(0, 1, n)

# X y Y parecen correlacionadas, pero no hay relación causal directa
X = confounder + np.random.normal(0, 0.5, n)
Y = confounder + np.random.normal(0, 0.5, n)

df = pd.DataFrame({'X': X, 'Y': Y})
print(f"Correlación X-Y: {df['X'].corr(df['Y']):.3f}")
# Sale ~0.7, pero X no causa Y

La correlación entre ventas de helado y crímenes en Bogotá no significa que el helado cause crímenes. Ambas suben porque en verano hace calor. El confounder es la temperatura.

El Costo Real

En producción, este error se manifiesta cuando:

  • Una fintech rechaza crédito a personas "parecidas" a morosos, sin entender qué variable realmente causa el incumplimiento
  • Un modelo de recomendaciones sugiere que "comprar paraguas causa lluvia" porque ve correlación en los datos de compra
  • Un hospital cambia un tratamiento basándose en qué pacientes "se parecen" a otros que murieron, sin ajustar por severidad

🔗 Causal Graphs — Mapas Que Previenen Conclusiones Falsas

Un causal graph (DAG - Directed Acyclic Graph) explicita las relaciones de causa-efecto entre variables. Esto cambia todo.

# Causal Graph con DoWhy
import dowhy
from dowhy import CausalModel

# Definimos el grafo causal
model = CausalModel(
    data=df,
    treatment='X',
    outcome='Y',
    common_causes=['confounder']  # El nodo que causa ambos
)

# Verificamos el grafo identificado
model.view_model()

Un buen causal graph incluye:

  • Nodos: variables del sistema
  • Aristas: relaciones causales directas
  • Confounders: nodos que causan múltiples variables de interés
  • Colliders: nodos causados por múltiples fuentes (pattern que hay que evitar)

Identificación de Confounders

# Backdoor criterion: qué variables controlar para eliminar confusión
# Un conjunto Z bloquea todos los backdoor paths de X → Y si:
# 1. Z bloquea todo path que no sea de intervención directa
# 2. No contiene ningún collider

identified_estimand = model.identify_effect(proceed_when_unidentifiable=True)
print(identified_estimand)

🔢 Do-Calculus — La Matemática de Intervenir

Judea Pearl introdujo el operador do(X=x) para modelar intervenciones. No es lo mismo "observar que alguien compra paraguas" que "obligar a alguien a comprar paraguas".

Las Tres Reglas del Do-Calculus

# Regla 1 - Insertar/deletar observaciones:
# P(Y | do(X), Z) = P(Y | do(X)) si Z es independiente de Y dado X

# Regla 2 - Intervención e observación:
# P(Y | do(X), do(Z)) = P(Y | do(X), Z) bajo ciertas condiciones

# Regla 3 - Insertar/deletar intervenciones:
# P(Y | do(X), do(Z)) = P(Y | do(X)) si X y Z son independientes

La intervención do(X=1) significa: "fuerza el tratamiento X a valor 1, sin importar qué hubiera pasado". Esto elimina el sesgo de confusión porque cortas todas las flechas que entran a X.

Efecto Causal Promedio (ATE)

# El Average Treatment Effect (ATE) es lo que queremos estimar:
# ATE = E[Y | do(X=1)] - E[Y | do(X=0)]

# Con el framework de DoWhy
estimate = model.estimate_effect(
    identified_estimand,
    method_name="backdoor.linear_regression"
)

print(f"ATE estimado: {estimate.value:.3f}")
print(f"Efecto causal real: ~0.0 (porque no hay causalidad real)")

📊 Cómo Causal Inference Mejora Modelos de ML

1. Feature Engineering Causal

# No todas las features son igualmente útiles
# Features correlacionadas pero no causales pueden ser peligrosas

# Feature causal: modificar esta variable cambia Y
# Feature espuria: correlacionada pero no causal

# Ejemplo: en predicción de default, "score de crédito" es causal
# "Dirección IP del usuario" puede ser correlacionada pero no causal

2. Detección de Spurious Correlations

# Test de causalidad antes de confiar en una feature
from scipy import stats

def test_causal_direction(X, Y, Z):
    """
    Test simple: si Z causa X e Y, entonces:
    - X y Y son independientes condicionando en Z
    """
    # Partial correlation: correlación X-Y controlada por Z
    from sklearn.linear_model import LinearRegression
    
    # Residuales de X predicho por Z
    res_x = X - LinearRegression().fit(Z.reshape(-1,1), X).predict(Z.reshape(-1,1))
    # Residuales de Y predicho por Z
    res_y = Y - LinearRegression().fit(Z.reshape(-1,1), Y).predict(Z.reshape(-1,1))
    
    # Correlación de residuales
    return stats.pearsonr(res_x, res_y)

3. Causal Inference para A/B Testing

# A/B test clásico vs Causal A/B test
# A/B test clásico asume que los grupos son intercambiables
# Causal inference incorpora el grafo causal

import dowhy.datasets

# Dataset con efecto causal conocido
data = dowhy.datasets.linear_dataset(
    beta=10,
    num_common_causes=5,
    num_instruments=2,
    num_samples=10000,
    treatment_is_binary=True
)

df = data["df"]

# Modelar el A/B test como experimento causal
model = CausalModel(
    data=df,
    treatment=data["treatment_name"][0],
    outcome=data["outcome_name"][0],
    common_causes=data["common_causes_names"],
    instruments=data["instrument_names"]
)

# Estimar el efecto real (CACE - Complier Average Causal Effect)
estimate = model.estimate_effect(
    identified_estimand,
    method_name="iv.bootstrap",
    confidence_intervals=True
)

print(f"Efecto causal del tratamiento: {estimate.value:.3f}")
print(f"Intervalo de confianza: {estimate.get_confidence_intervals()}")

🎯 Instrumental Variables — Cuando No Puedes Intervenir

¿Qué pasa cuando no puedes hacer un experimento controlado? Las variables instrumentales (IV) son tu herramienta.

# Condiciones de un buen instrumento Z para X → Y:
# 1. Z correlaciona con X (relevancia)
# 2. Z no correlaciona directamente con Y (exclusión)
# 3. Z no tiene confounder con Y (independencia)

# Ejemplo clásico: efecto de educación en ingresos
# No podemos randomizar educación, pero podemos usar:
# - Cuarto de nacimiento (instrumento)
# - Cambio en leyes de escolaridad obligatoria

from sklearn.linear_model import LinearRegression

def two_stage_least_squares(X, Y, Z):
    """
    IV estimation via 2SLS
    """
    # Primera etapa: predecir X con Z
    X_pred = LinearRegression().fit(Z, X).predict(Z)
    
    # Segunda etapa: estimar efecto de X_pred en Y
    beta_iv = LinearRegression().fit(X_pred.reshape(-1,1), Y).coef_[0]
    
    return beta_iv

# En nuestro dataset de ejemplo con instrumentos
Z = df[data["instrument_names"]].values
X = df[data["treatment_name"][0]].values
Y = df[data["outcome_name"][0]].values

effect = two_stage_least_squares(X, Y, Z)
print(f"Efecto causal estimado via IV: {effect:.3f}")

⚠️ Los 3 Errores Que El 90% Commete

Error 1: Confundir Correlación con Causalidad

El problema: Ver que "usuarios que compran X también compran Y" y concluir que "X causa Y". Esto lleva a intervenciones fallidas.

# NO HACER ESTO:
# if correlation(user_bought_X, user_bought_Y) > 0.8:
#     recommend_Y_when_X_bought()  # Puede no funcionar!

# El problema: ambos pueden ser causados por un third factor

La solución: Construir un causal graph explícito. Usar domain knowledge para identificar confounders antes de actuar. Siempre pregúntate: "¿qué podría causar ambas cosas?"

Error 2: No Controlar Por Confounders

El problema: En un A/B test, si no контролируешь por confounders, el efecto estimado está sesgado.

# NO HACER ESTO:
# naive_effect = mean(Y|A=1) - mean(Y|A=0)
# ¡Esto puede ser completamente errado!

# HACER ESTO:
# Ajustar por confounders usando regression o stratification
from sklearn.linear_model import LogisticRegression

# Ajustar por confounders
X_confounders = df[confounders].values
treatment = df['treatment'].values

# Estimar efecto con ajuste
model = LogisticRegression()
model.fit(X_confounders, treatment)

# O usar matching, IPW, o doubly robust estimators

La solución: Incluir todos los confounders conocidos en el análisis. Usar técnicas como matching, inverse probability weighting (IPW), o doubly-robust estimation.

Error 3: A/B Test Sin Considerar Causal Inference

El problema: Lanzar un A/B test, ver lift positivo, y escalar sin preguntarse si el efecto es real o espurio.

# NO HACER ESTO:
# if ab_test.pvalue < 0.05:
#     ship_it()  # ¡Puedo estar错了!

# El problema: múltiples testing, novelty effects,
# selección de métricas, etc.

La solución: Complementar el A/B test con análisis causal. Preguntar:

  • ¿El efecto persiste en diferentes segmentos?
  • ¿Hay effect heterogeneity (el efecto varía por grupo)?
  • ¿El mecanismo de acción valida la hipótesis causal?
  • ¿Hay placebo tests que confirmen la validez?

📚 Resumen y Cierre

Hagale pues, parcero. Causal inference no es un tema académico — es la diferencia entre modelos que realmente entienden el mundo y modelos que ven fantasmas en los datos.

Lo que debes recordar:

  • Correlación ≠ Causalidad. Siempre pregúntate qué causa qué.
  • Causal graphs hacen explícito tu conocimiento causal — y exponen lo que no sabes.
  • Do-calculus te permite estimar efectos causales incluso sin experimentos.
  • Instrumental variables son tu opción cuando no puedes intervenir.
  • En A/B testing, siempre ajusta por confounders.

En下次 vez que tu modelo diga que "X causa Y", pregúntate: ¿realmente lo hace? ¿O hay un confounder escondido? En Medellín decimos "el que no pregunta, se equivoca". En ML, el que no hace causal inference, paga con conclusiones equivocadas.
