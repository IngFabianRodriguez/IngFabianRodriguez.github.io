🏛️ Qué es Constitutional AI

El concepto central detrás de Claude es Constitutional AI (CAI). La idea es simple pero poderosa: en lugar de solo entrenar con feedback humano (RLHF), el modelo aprende de un constitution — un conjunto de principios que guían el comportamiento.

El constitution incluye principios como:

  • Elige la respuesta que sea más útil y menos dañina
  • Evita generados contenido que podría causar daño
  • Responde con honestidad y reconoce limitaciones
  • Evita pretenses de identidad o emociones humanas
"""
Constitutional AI — Framework Simplificado
"""
from dataclasses import dataclass
from typing import List, Optional
from enum import Enum


class HarmCategory(Enum):
    HARM_DELETREOUS = " potentially harmful content"
    HARM_ILLICIT = " illegal or unethical"
    HARM_MANIPULATIVE = " manipulative or deceptive"
    HARM_INCOMPLETE = " honest but incomplete"


@dataclass
class ConstitutionalPrinciple:
    """
    Un principio del constitution
    """
    principle: str
    harm_category: HarmCategory
    critique_template: str
    revision_template: str


CONSTITUTION = [
    ConstitutionalPrinciple(
        principle="Elige la respuesta que sea más útil y menos dañina",
        harm_category=HarmCategory.HARM_DELETREOUS,
        critique_template="¿Esta respuesta podría causar daño directo o indirecto?",
        revision_template="Revisa la respuesta para minimizar daño potencial"
    ),
    ConstitutionalPrinciple(
        principle="Responde con honestidad y reconoce limitaciones",
        harm_category=HarmCategory.HARM_INCOMPLETE,
        critique_template="¿Esta respuesta es completa o está omitiendo información importante?",
        revision_template="Añade cualificaciones o reconoce limitaciones"
    ),
    ConstitutionalPrinciple(
        principle="Evita contenido manipulativo o engañoso",
        harm_category=HarmCategory.HARM_MANIPULATIVE,
        critique_template="¿Esta respuesta podría manipular al usuario de alguna forma?",
        revision_template="Haz la respuesta más directa y menos manipulativa"
    ),
]


class ConstitutionalAI:
    """
    Implementación simplificada de Constitutional AI
    
    El proceso:
    1. Generate initial response
    2. Critique based on principles
    3. Revise response
    4. Evaluate safety
    """
    
    def __init__(self, base_model, constitution: List[ConstitutionalPrinciple]):
        self.base_model = base_model
        self.constitution = constitution
    
    def generate_critique(self, response: str, principle: ConstitutionalPrinciple) -> str:
        """Genera una crítica basada en un principio"""
        prompt = f"""
Responda a la siguiente crítica basada en este principio: {principle.principle}

Crítica: {principle.critique_template}

Respuesta a criticar: {response}

Su crítica:
"""
        return self.base_model.generate(prompt)
    
    def generate_revision(self, response: str, critique: str, principle: ConstitutionalPrinciple) -> str:
        """Genera una revisión mejorada"""
        prompt = f"""
Revisa la siguiente respuesta basándote en esta crítica y principio.

Principio: {principle.principle}
Crítica: {critique}
Respuesta original: {response}

Respuesta revisada:
"""
        return self.base_model.generate(prompt)
    
    def process_response(self, user_input: str) -> str:
        """Procesa una respuesta pasando por todos los principios"""
        # Paso 1: Respuesta inicial
        response = self.base_model.generate(user_input)
        
        # Paso 2: Pasar por cada principio del constitution
        for principle in self.constitution:
            # Criticar
            critique = self.generate_critique(response, principle)
            
            # Revisar
            response = self.generate_revision(response, critique, principle)
        
        return response

🛡️ El Enfoque de Seguridad en Capas

Anthropic implementa seguridad en múltiples niveles:

Capa 1: Entrenamiento con Principles

Durante el entrenamiento, el modelo aprende a balancear utilidad y seguridad. No es solo "no respondas esto" — es "responde de forma que sea útil pero segura".

Capa 2: RLHF con Feedback de Seguridad

El Reinforcement Learning from Human Feedback incluye explícitamente evaluadores entrenados para identificar contenido problemático:

"""
RLHF con Safety Feedback — Concepto
"""
from dataclasses import dataclass
from typing import Tuple


@dataclass
class SafetyReward:
    """
    Reward que combina utilidad y seguridad
    """
    utility_score: float  # 0-1, qué tan útil es la respuesta
    safety_score: float   # 0-1, qué tan segura es la respuesta
    
    @property
    def combined_reward(self) -> float:
        """
        Combina utilidad y seguridad.
        
        Key insight: Si safety es muy bajo, el reward total baja
        significativamente, incluso si utilidad es alta.
        """
        # Función que penaliza fuertemente respuestas unsafe
        safety_weight = 0.7
        utility_weight = 0.3
        
        # Soft floor en safety: por debajo de 0.3, penalización extrema
        if self.safety_score < 0.3:
            adjusted_safety = self.safety_score * 0.1  # Penalty severa
        else:
            adjusted_safety = self.safety_score
        
        return (
            utility_weight * self.utility_score +
            safety_weight * adjusted_safety
        )


class SafetyEvaluator:
    """
    Evalúa respuestas para el RLHF
    """
    
    def __init__(self, annotators: list):
        self.annotators = annotators
    
    def evaluate(self, prompt: str, response: str) -> SafetyReward:
        """
        Evalúa una respuesta en términos de utilidad y seguridad
        """
        # Múltiples anotadores evalúan independientemente
        utility_scores = []
        safety_scores = []
        
        for annotator in self.annotators:
            u, s = annotator.evaluate(prompt, response)
            utility_scores.append(u)
            safety_scores.append(s)
        
        return SafetyReward(
            utility_score=sum(utility_scores) / len(utility_scores),
            safety_score=sum(safety_scores) / len(safety_scores)
        )

🔍 Cómo Funciona el Safety en la Práctica

1. Input Filtering

Prompts que claramente buscan contenido dañino son interceptados early:

"""
Input Safety Filter — Concepto
"""
import re


class SafetyFilter:
    """
    Filtro de seguridad para inputs
    """
    
    def __init__(self):
        # Patterns conocidos de intentos de bypass
        self.jailbreak_patterns = [
            r"ignore\s+(previous|all|prior)\s+instructions",
            r"you\s+are\s+now\s+(DAN|different\s+AI|unrestricted)",
            r"forget\s+everything\s+about\s+your\s+rules",
            r"pretend\s+you\s+can\s+(do|be)\s+anything",
            r"\\x|\\u00|base64\s+decode"
        ]
        
        self.unsafe_topics = [
            "how to make weapon",
            "how to create bomb",
            "synthesize drugs",
            "hack into system",
            "bypass security"
        ]
    
    def check(self, prompt: str) -> dict:
        """
        Returns:
            dict con:
            - is_safe: bool
            - reason: str si no es seguro
            - risk_level: low/medium/high
        """
        prompt_lower = prompt.lower()
        
        # Check jailbreak attempts
        for pattern in self.jailbreak_patterns:
            if re.search(pattern, prompt_lower, re.IGNORECASE):
                return {
                    "is_safe": False,
                    "reason": "Detected jailbreak attempt",
                    "risk_level": "high"
                }
        
        # Check unsafe topics
        for topic in self.unsafe_topics:
            if topic in prompt_lower:
                return {
                    "is_safe": False,
                    "reason": f"Unsafe topic detected: {topic}",
                    "risk_level": "medium"
                }
        
        return {
            "is_safe": True,
            "reason": None,
            "risk_level": "low"
        }

2. Output Scoping

Claude está entrenado para reconocer cuándo拒绝 es apropiada vs. cuándo puede responder de forma limitada:

"""
Output Safety Scoping — Concepto
"""
from enum import Enum


class ResponseLevel(Enum):
    FULL = "full"           # Respuesta completa y detallada
    PARTIAL = "partial"    # Respuesta parcial, evitando lo sensitive
    REFusal = "refusal"    # No puede responder
    EMPATHETIC_REFUSAL = "empathetic_refusal"  # Explica por qué no puede


class ResponseScoper:
    """
    Determina qué nivel de respuesta es apropiado
    """
    
    def determine_level(self, prompt: str, category: str) -> ResponseLevel:
        """
        Args:
            prompt: El prompt del usuario
            category: Categoría del contenido solicitado
        
        Returns:
            Nivel de respuesta apropiado
        """
        # Casos claros de refusal
        if category in ["illegal", "harmful", "dangerous"]:
            return ResponseLevel.REFUSAL
        
        # Casos que pueden tener respuesta parcial
        if category in ["medical", "legal", "financial"]:
            # Añadir disclaimers
            return ResponseLevel.PARTIAL
        
        # Caso normal
        return ResponseLevel.FULL
    
    def apply_disclaimer(self, response: str, category: str) -> str:
        """Añade disclaimer apropiado"""
        disclaimers = {
            "medical": "\n\n⚠️ Importante: Esta información es solo educativa y no sustituye el consejo médico profesional.",
            "legal": "\n\n⚠️ Importante: Esto es información general y no constituye asesoría legal.",
            "financial": "\n\n⚠️ Importante: Consulta con un profesional financiero antes de tomar decisiones.",
        }
        
        if category in disclaimers:
            response += disclaimers[category]
        
        return response

🎯 El Balance Utilidad-Seguridad

El mayor achievement de Anthropic es demostrar que no hay trade-off necesario entre utilidad y seguridad:

  • Modelos anteriores: eran muy restrictive (poco útiles) o muy permissive (inseguros)
  • Claude 3: es útil Y seguro

Esto se logra con:

  1. Entrenamiento más largo con datos de safety diversos
  2. RLHF específicamente diseñado para balancear
  3. Evaluación humana extensiva de edge cases
  4. 迭代 improvement basado en red teaming

⚠️ Críticas y Limitaciones

No todo es perfecto:

  • Still can be jailbroken: ningún sistema es perfecto
  • Refusals can be frustrating: a veces niega cosas legítimas
  • Safety overhead: añade latencia a cada request
  • Evaluar "daño" es субъективно: qué считается dañino varies por cultura y contexto

📊 Resumen y Recomendaciones

Anthropic ha establecido un nuevo standard para cómo hacer IA segura:

  • Constitutional AI: Principios explícitos guían el comportamiento
  • RLHF con Safety: Seguridad explícitamente rewardada
  • Capacidades no sacrificadas: Claude 3 es competitivo con GPT-4
  • Transparencia: Publicaron papers detallando su enfoque
