Fine-Tuning con LoRA - Eficiencia en Adaptacion

03 de septiembre de 2026
lorafine-tuningparameter-efficienttraining

Introduccion: Por Que Fine-Tuning Completo Es Impractico

Hagale pues, parcero. Dia 246 y hoy nos metemos con un tema que el 85% de los practitioners de LLM no usan pero deberian: LoRA y el fine-tuning eficiente en parametros. Un modelo de 7B parametros tiene aproximadamente 7,000,000,000 valores que se pueden entrenar. Entrenarlos todos es costoso y lento. LoRA reduce eso a millones o miles. Despues de este articulo va a saber exactamente como funciona y por que es un game-changer. Vamos.

El Problema del Fine-Tuning Tradicional

Cuando fine-tunea un LLM de forma tradicional, usted actualiza TODOS los parametros del modelo. Para un modelo de 7B:

  • 7B parametros requieren almacenamiento masivo
  • 7B gradientes se calculan en cada paso de entrenamiento
  • 7B parametros se actualizan en cada optimizacion
  • Costos: GPU de alta gama por semanas

La formulacion del update tradicional:

W_new = W_old - learning_rate * gradiente

Para un modelo de 7B, esto es impráctico en la mayoria de casos de uso.

La Intuicion de LoRA

LoRA (Low-Rank Adaptation) se basa en una observacion clave: durante el fine-tuning, los cambios en los pesos no son cualquier matriz de alta dimensionalidad, sino matrices de bajo rango.

La hipotesis de rank bajo: los pesos delta tienen muchos menos grados de libertad que los pesos originales porque el modelo ya sabe mucho y solo necesita ajustes pequenos.

La Formulacion Matematica

En lugar de actualizar W directamente, LoRA entrena una representacion de bajo rango de los cambios:

W_new = W_old + BA

Donde:

  • W_old son los pesos congelados del modelo original
  • B es una matriz de tamano d x r
  • A es una matriz de tamano r x k
  • r es el rank (mucho menor que d y k)

Para una capa con pesos W de tamano d x k, en lugar de entrenar d x k parametros, entrenamos d x r + r x k = r(d + k) parametros.

Implementacion de LoRA

import torch
import torch.nn as nn
import math

class LoRALinear(nn.Module):
    """
    Capa lineal con adaptacion LoRA.
    
    En lugar de: y = Wx + b
    Hacemos:     y = (W + BA)x + b
    
    donde A y B son las matrices de bajo rank entrenables.
    """
    
    def __init__(self, in_features, out_features, rank=4, alpha=1.0, dropout=0.0):
        super().__init__()
        self.in_features = in_features
        self.out_features = out_features
        self.rank = rank
        self.alpha = alpha
        self.scale = alpha / rank  # Scaling factor
        
        # Pesos originales congelados
        self.weight = nn.Parameter(
            torch.randn(out_features, in_features),
            requires_grad=False
        )
        self.bias = nn.Parameter(
            torch.zeros(out_features),
            requires_grad=False
        ) if True else None  # Simplificado
        
        # Matrices LoRA (entrenables)
        self.lora_A = nn.Parameter(torch.randn(rank, in_features) / math.sqrt(rank))
        self.lora_B = nn.Parameter(torch.zeros(out_features, rank))
        
        # Dropout opcional
        self.dropout = nn.Dropout(dropout) if dropout > 0 else nn.Identity()
        
        # Marcar como entrenables
        self.lora_A.requires_grad = True
        self.lora_B.requires_grad = True
    
    def forward(self, x):
        # Forward original (congelado)
        base_output = torch.nn.functional.linear(x, self.weight, self.bias)
        
        # LoRA forward: BA es la adaptacion de bajo rank
        lora_output = (self.lora_B @ self.lora_A) @ x.T
        lora_output = lora_output @ torch.eye(self.out_features, self.in_features).to(x.device)
        
        # Escalar y agregar
        scaled_lora = self.scale * lora_output.T
        return base_output + self.dropout(scaled_lora)
    
    def merge_weights(self):
        """
        Merge los pesos LoRA en el modelo base para inferencia.
        """
        delta_W = self.lora_B @ self.lora_A * self.scale
        merged_weight = self.weight + delta_W
        return merged_weight


# Ejemplo de uso
layer = LoRALinear(in_features=512, out_features=512, rank=4, alpha=8)

print(f"Pesos originales: {512 * 512:,} parametros")
print(f"Pesos LoRA A: {4 * 512:,} parametros")
print(f"Pesos LoRA B: {512 * 4:,} parametros")
print(f"Total entrenable: {4 * 512 + 512 * 4:,} parametros")
print(f"Reduccion: {512 * 512 / (4 * 512 * 2):.1f}x")

LoRA con Transformers

from peft import LoraConfig, get_peft_model, TaskType
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

# Cargar modelo base
model_name = "gpt2"  # Ejemplo con GPT2 pequeno
model = AutoModelForCausalLM.from_pretrained(model_name)

# Configuracion LoRA
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,
    r=8,                          # Rank de las matrices
    lora_alpha=16,                 # Factor de escala (usualmente 2x rank)
    lora_dropout=0.05,            # Dropout para regularizacion
    target_modules=[              # Modulos a adaptar
        "q_proj",                 # Query projection
        "v_proj",                 # Value projection
        "k_proj",                 # Key projection
        "o_proj",                 # Output projection
    ],
    bias="none",                  # No entrenar biases
    inference_mode=False,
)

# Aplicar LoRA al modelo
model = get_peft_model(model, lora_config)

# Ver parametros entrenables
model.print_trainable_parameters()
# Output: trainable params: 884,736 || all params: 124,440,576 || trainable%: 0.711%

QLoRA: LoRA + Quantization

QLoRA (Quantized LoRA) combina LoRA con quantization para entrenar modelos grandes en hardware limitado:

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# Configuracion para cargar en 4 bits
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
)

# Cargar modelo cuantizado
model_name = "meta-llama/Llama-2-7b-hf"
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto",
)

# Preparar para k-bit training
model = prepare_model_for_kbit_training(model)

# Configuracion LoRA
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type=TaskType.CAUSAL_LM,
)

# Aplicar LoRA
model = get_peft_model(model, lora_config)

# Verificamos el modelo
model.print_trainable_parameters()
# 7B modelo, solo ~0.1% entrenable!

Fine-Tuning Completo con LoRA

from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments, Trainer
from datasets import load_dataset
from peft import LoraConfig, get_peft_model

# 1. Cargar modelo y tokenizer
model_name = "gpt2"
model = AutoModelForCausalLM.from_pretrained(model_name)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

# 2. Aplicar LoRA
lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    target_modules=["c_attn", "c_proj"],  # Para GPT2
    lora_dropout=0.05,
    bias="none",
)
model = get_peft_model(model, lora_config)

# 3. Preparar dataset
def tokenize_function(examples):
    result = tokenizer(
        examples["text"],
        truncation=True,
        max_length=512,
        padding="max_length",
    )
    result["labels"] = result["input_ids"].copy()
    return result

# Dataset de ejemplo (usualmente su propio dataset)
dataset = load_dataset("wikitext", "wikitext-2-raw-v1", split="train")
dataset = dataset.map(tokenize_function, batched=True, remove_columns=["text"])

# 4. Configuracion de entrenamiento
training_args = TrainingArguments(
    output_dir="./lora-finetuned",
    num_train_epochs=3,
    per_device_train_batch_size=8,
    gradient_accumulation_steps=4,
    learning_rate=3e-4,
    warmup_ratio=0.03,
    lr_scheduler_type="cosine",
    logging_steps=10,
    save_steps=100,
    fp16=True,
    report_to="tensorboard",
)

# 5. Trainer
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
)

# 6. Entrenar!
trainer.train()

# 7. Guardar adaptadores
model.save_pretrained("./lora-finetuned-adapter")

Configuracion de Hiperparametros

Rank (r)

  • Rank pequeno (2-8): Menos parametros, menos sobreajuste, pero puede no capturar suficiente complejidad
  • Rank grande (64-128): Mas capacidad, mas riesgo de sobreajuste, mayor demanda computacional
  • Recomendacion: Empiece con r=8, incremente si el modelo no aprende lo suficiente

Alpha (lora_alpha)

  • Regla empirica: alpha = 2 * rank es un buen punto de partida
  • Alpha mayor: Incrementa la contribucion de LoRA relative al modelo base

Merge y Exportacion del Modelo

from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

def merge_lora_to_base(base_model_path, adapter_path, output_path):
    """
    Combina los pesos LoRA con el modelo base y guarda el resultado.
    """
    # Cargar modelo base
    base_model = AutoModelForCausalLM.from_pretrained(
        base_model_path,
        torch_dtype=torch.float16,
        device_map="auto",
    )
    
    # Cargar y merge de adaptadores LoRA
    model = PeftModel.from_pretrained(base_model, adapter_path)
    model = model.merge_and_unload()
    
    # Guardar
    model.save_pretrained(output_path)
    
    # Guardar tokenizer
    tokenizer = AutoTokenizer.from_pretrained(base_model_path)
    tokenizer.save_pretrained(output_path)
    
    print(f"Modelo guardado en: {output_path}")
    return model, tokenizer


# Uso
base_model = "gpt2"
adapter_model = "./lora-finetuned-adapter"
output_model = "./gpt2-finetuned-merged"

merge_lora_to_base(base_model, adapter_model, output_model)

Variantes de LoRA

QLORA

QLoRA agrega quantization a LoRA para mayor eficiencia:

  • NF4 (Normal Float 4): Formato de cuantizacion optimizado para LLMs
  • Double Quant: Cuantiza los factores de escala para mayor compresion
  • Paged Optimizers: Maneja memoria de optimizers en pages para models grandes

AdaLoRA

AdaLoRA ajusta automaticamente el rank de cada capa basado en su importancia:

# Configuracion AdaLoRA
from peft import AdaLoraConfig

ada_config = AdaLoraConfig(
    r=8,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj", "k_proj", "o_proj"],
    ada_lora=True,  # Habilitar adaptacion automatica de rank
    task_type=TaskType.CAUSAL_LM,
)

DoRA

DoRA (Weight-Decomposed LoRA) descompone los pesos en magnitud y direccion:

# Configuracion DoRA
from peft import LoRAConfig, TaskType

dora_config = LoRAConfig(
    r=8,
    lora_alpha=16,
    target_modules=["q_proj", "v_proj"],
    use_dora=True,  # Habilitar DoRA
    task_type=TaskType.CAUSAL_LM,
)

Resumen y Cierre Colombiano

Hagale pues, Parcero. Hoy cubrimos LoRA a fondo y espero que ahora entienda por que esta tecnica es un game-changer para adaptar LLMs.

Los puntos clave:

  • Fine-tuning tradicional es impráctico para modelos grandes (7B+ parametros)
  • LoRA reduce parametros entrenables en 100-1000x usando descomposicion de bajo rank
  • QLoRA combina LoRA con quantization para entrenar modelos grandes en hardware limitado
  • Hyperparametros principales: rank (r) y alpha (escala)
  • Empiece con r=8, ajuste basado en resultados
  • El modelo base se mantiene congelado, solo se entrenan las matrices A y B
  • QLoRA permite fine-tunar un 70B en una sola GPU de 24GB
  • Existen variantes como AdaLoRA y DoRA para casos especificos

La proxima vez que alguien le diga "no puedo fine-tunar porque no tengo 8 GPUs", usted ya sabe que responder: usa QLoRA con r=16 y listo.
