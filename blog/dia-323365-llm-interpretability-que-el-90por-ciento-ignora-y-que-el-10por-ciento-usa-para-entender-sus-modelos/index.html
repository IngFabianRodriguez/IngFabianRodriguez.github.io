LLM Interpretability: Lo Que El 90% No Se Pregunta

Qué tal parcero, hoy 19 de noviembre de 2026, Día 323 del #365DaysOfAI. Mientras la mayoría solo ve el output del modelo como una caja negra — "funciona" o "no funciona" — hay un 10% que está tratando de entender qué está pasando adentro. Hoy nous vamos a ese lado: LLM interpretability, feature attribution, activation analysis, y probing classifiers. Porque si no entiendes tu modelo, no puedes confiar en él, ni debuguearlo, ni mejorarlo de manera informada. Eso es lo que hoof hoy.

Por Qué Importa La Interpretabilidad

Piénsalo así: si tu modelo de lenguaje te dice "Colombia debería cambiar su moneda al euro", puedes aceptar eso como respuesta o puedes preguntarte por qué el modelo dijo eso. Estaba razonando sobre economía? Estaba repitiendo sesgos de los datos de entrenamiento? Estaba siguiendo un patrón que no tiene nada que ver con la realidad colombiana?

Sin interpretabilidad, no hay manera de saberlo. Y eso es peligroso cuando:

  • El modelo se usa para decisiones médicas o legales
  • El modelo muestra comportamiento inesperado en producción
  • Necesitas explicar la decisión del modelo a reguladores (Ley 2302 de 2023 en Colombia exige explicabilidad en sistemas automatizados)
  • Quieres mejorar el modelo de manera dirigida en lugar de probar randomicamente

La interpretabilidad no es solo para investigadores. Es para cualquier engineer que desplegue LLMs en producción y necesite accountability.

Feature Attribution: Atribuyendo Importancia

Feature attribution responde a: qué partes del input son más importantes para la predicción del modelo?

La forma más básica es saliency maps, pero en LLMs el input es tokens, no píxeles.所以我们用不同的方法。

1. Attention-based Attribution

Los attention weights nos dicen qué tokens enfocó el modelo para generar cada salida:

import torch
import numpy as np
from transformers import AutoModelForCausalLM, AutoTokenizer
import matplotlib.pyplot as plt

class AttentionAttributor:
    """Atribución basada en attention weights"""
    
    def __init__(self, model_name="gpt2"):
        self.model = AutoModelForCausalLM.from_pretrained(model_name)
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model.eval()
    
    def get_attention_weights(self, input_text):
        """Extrae attention weights para cada capa"""
        inputs = self.tokenizer(input_text, return_tensors="pt")
        
        with torch.no_grad():
            outputs = self.model(**inputs, output_attentions=True)
        
        # attentions: tuple de (layers, batch, heads, seq_len, seq_len)
        attentions = outputs.attentions
        return attentions
    
    def compute_token_importance(self, input_text):
        """Calcula importancia de cada token basándose en attention"""
        inputs = self.tokenizer(input_text, return_tensors="pt")
        tokens = self.tokenizer.convert_ids_to_tokens(inputs['input_ids'][0])
        
        attentions = self.get_attention_weights(input_text)
        
        # Promediar attention weights sobre capas y heads
        # Cada entry: (layers, batch, heads, query_len, key_len)
        layer_weights = torch.stack([layer[0] for layer in attentions])
        # Promedio sobre heads: (layers, seq_len, seq_len)
        avg_heads = layer_weights.mean(dim=1)
        # Promedio sobre capas: (seq_len, seq_len)
        overall_attention = avg_heads.mean(dim=0)
        
        # Importancia = suma de attention dirigida hacia cada token
        token_importance = overall_attention.sum(dim=0).numpy()
        
        return dict(zip(tokens, token_importance))
    
    def visualize_importance(self, input_text, save_path="attention.png"):
        """Visualiza importancia de tokens"""
        importance = self.compute_token_importance(input_text)
        tokens = list(importance.keys())
        scores = list(importance.values())
        
        # Normalizar scores
        scores = np.array(scores)
        scores = (scores - scores.min()) / (scores.max() - scores.min() + 1e-8)
        
        plt.figure(figsize=(max(8, len(tokens) * 0.5), 4))
        plt.bar(range(len(tokens)), scores)
        plt.xticks(range(len(tokens)), tokens, rotation=45, ha='right')
        plt.title("Token Importance via Attention")
        plt.tight_layout()
        plt.savefig(save_path)
        plt.close()
        return save_path

2. Gradient-based Attribution: Integrated Gradients

Integrated Gradients atribuye importancia computando gradientes a lo largo de un path desde un baseline hasta el input real:

class IntegratedGradients:
    """Integrated Gradients para feature attribution en LLMs"""
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
    
    def integrated_gradients(self, input_text, baseline=None, num_steps=50):
        """
        Calcula Integrated Gradients para cada token.
        
        La intuición: en lugar de solo ver el gradiente en el input real,
        promediamos gradientes a lo largo del path de interpolation.
        """
        inputs = self.tokenizer(input_text, return_tensors="pt")
        input_ids = inputs['input_ids']
        tokens = self.tokenizer.convert_ids_to_tokens(input_ids[0])
        
        # Baseline: input de-reference (puede ser zeros o un prompt neutral)
        if baseline is None:
            baseline = torch.zeros_like(input_ids)
        
        # Generar interpolated inputs
        alphas = torch.linspace(0, 1, num_steps).reshape(-1, 1, 1)
        interpolated = baseline + alphas * (input_ids - baseline).unsqueeze(1)
        
        # Calcular gradientes para cada interpolación
        gradients = []
        for i in range(num_steps):
            interp_input = interpolated[i].requires_grad_(True)
            outputs = self.model(interp_input)
            
            # Get prediction (usamos el logit del token final para clasificadores)
            prediction = outputs.logits[0, -1].sum()
            
            # Backprop
            grad = torch.autograd.grad(prediction, interp_input)[0]
            gradients.append(grad[0])
        
        gradients = torch.stack(gradients)  # (num_steps, seq_len, vocab_size)
        
        # Promediar gradientes sobre steps
        avg_gradients = gradients.mean(dim=0)
        
        # Multiplying por la diferencia del input
        input_difference = input_ids.float() - baseline.float()
        ig_scores = (input_difference * avg_gradients).sum(dim=-1)[0]  # Sum sobre vocab
        
        return dict(zip(tokens, ig_scores.numpy()))
    
    def a_path_integrated_gradients(self, input_text, target_token_idx, num_steps=50):
        """
        IG para un token específico como target.
        """
        inputs = self.tokenizer(input_text, return_tensors="pt")
        input_ids = inputs['input_ids']
        tokens = self.tokenizer.convert_ids_to_tokens(input_ids[0])
        
        baseline = torch.zeros_like(input_ids)
        
        alphas = torch.linspace(0, 1, num_steps)
        ig_attribution = torch.zeros_like(input_ids, dtype=torch.float)
        
        for alpha in alphas:
            interpolated = baseline + alpha * (input_ids.float() - baseline)
            interpolated = interpolated.requires_grad_(True)
            
            outputs = self.model(interpolated.long())
            
            # Focus en el target token
            target_logit = outputs.logits[0, -1, target_token_idx]
            
            self.model.zero_grad()
            grad = torch.autograd.grad(target_logit, interpolated)[0]
            ig_attribution += (input_ids.float() - baseline) * grad
        
        ig_attribution = ig_attribution / num_steps
        
        return dict(zip(tokens, ig_attribution[0].numpy()))

Activation Analysis: Mirando Dentro Del Modelo

Los features attribution methods nos dicen qué input importa. Pero qué pasa dentro del modelo? Podemos analizar las activaciones — los patrones de activación de neuronas y capas — para entender qué conceptos está representando el modelo.

class ActivationAnalyzer:
    """Análisis de activaciones de un LLM"""
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
        self.activations = {}
        self.hooks = []
    
    def register_hooks(self, layers_to_capture=None):
        """Registra hooks para capturar activaciones"""
        
        def get_activation(name):
            def hook(module, input, output):
                self.activations[name] = output[0].detach()
            return hook
        
        # Capturar capas del modelo
        if layers_to_capture is None:
            # Por defecto, capturar todas las capas del transformer
            layers_to_capture = list(range(len(self.model.transformer.h)))
        
        for layer_idx in layers_to_capture:
            try:
                hook = self.model.transformer.h[layer_idx].register_forward_hook(
                    get_activation(f"layer_{layer_idx}")
                )
                self.hooks.append(hook)
            except:
                pass
    
    def remove_hooks(self):
        """Remueve todos los hooks registrados"""
        for hook in self.hooks:
            hook.remove()
        self.hooks = []
    
    def get_layer_activations(self, text):
        """Obtiene activaciones para cada capa dado un texto"""
        inputs = self.tokenizer(text, return_tensors="pt")
        
        self.activations = {}
        with torch.no_grad():
            _ = self.model(**inputs)
        
        return self.activations
    
    def compute_cosine_similarity(self, act1, act2):
        """Calcula similitud coseno entre dos sets de activaciones"""
        act1_flat = act1.flatten()
        act2_flat = act2.flatten()
        
        cos = torch.nn.functional.cosine_similarity(
            act1_flat.unsqueeze(0), 
            act2_flat.unsqueeze(0)
        )
        return cos.item()
    
    def find_similar_concepts(self, concept_activation, text_dataset, top_k=5):
        """
        Encuentra textos que activan capas de manera similar a un concepto.
        
        Útil para descubrir qué conceptos activa el modelo en diferentes contextos.
        """
        results = []
        concept_flat = concept_activation.flatten()
        
        for text in text_dataset:
            acts = self.get_layer_activations(text)
            for layer_name, act in acts.items():
                if act is not None:
                    similarity = self.compute_cosine_similarity(act[-1], concept_activation[-1])
                    results.append({
                        "text": text[:100],
                        "layer": layer_name,
                        "similarity": similarity
                    })
        
        return sorted(results, key=lambda x: -x['similarity'])[:top_k]
    
    def visualize_activation_patterns(self, texts, save_path="activations.png"):
        """Visualiza patrones de activación sobre un set de textos"""
        import matplotlib.pyplot as plt
        
        all_activations = []
        for text in texts:
            acts = self.get_layer_activations(text)
            # Promedio de activación por capa
            layer_means = []
            for i in range(len(acts)):
                act = acts.get(f"layer_{i}")
                if act is not None:
                    layer_means.append(act.mean().item())
            all_activations.append(layer_means)
        
        arr = np.array(all_activations)
        
        plt.figure(figsize=(10, 6))
        plt.imshow(arr, aspect='auto', cmap='viridis')
        plt.colorbar(label='Mean Activation')
        plt.xlabel('Layer')
        plt.ylabel('Text')
        plt.title('Activation Patterns Across Layers')
        plt.tight_layout()
        plt.savefig(save_path)
        plt.close()
        return save_path

Probing Classifiers: Detectando Conceptos

Un probing classifier (o probe) es un clasificador ligero que se entrena para predecir alguna propiedad del input a partir de las activaciones del modelo. Si el probe funciona bien, significa que esa propiedad está siendo representada en esas activaciones.

La intuition: el modelo tiene "latent knowledge" que no necessarily se refleja directamente en sus outputs, pero podemos detectarlo mirando sus internal representations.

import torch
import torch.nn as nn
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split
import numpy as np

class ProbingClassifier:
    """Probing classifiers para detectar conceptos en LLM activations"""
    
    def __init__(self, model, tokenizer, layer_to_probe=-1):
        self.model = model
        self.tokenizer = tokenizer
        self.layer_to_probe = layer_to_probe
        self.probe = None
        self.label_encoder = {}
    
    def extract_activations(self, texts, batch_size=8):
        """Extrae activaciones de una capa específica para una lista de textos"""
        activations = []
        
        self.model.eval()
        with torch.no_grad():
            for i in range(0, len(texts), batch_size):
                batch = texts[i:i+batch_size]
                inputs = self.tokenizer(batch, return_tensors="pt", padding=True, truncation=True)
                
                outputs = self.model(**inputs, output_hidden_states=True)
                
                # Obtener hidden states
                hidden_states = outputs.hidden_states
                # Seleccionar capa (layer_to_probe=-1 = última capa)
                layer_acts = hidden_states[self.layer_to_probe]
                
                # Usar representación del [CLS] token o el promedio
                # Para GPT-style (sin [CLS]), usamos el último token
                for j in range(layer_acts.shape[0]):
                    activations.append(layer_acts[j, -1, :].numpy())
        
        return np.array(activations)
    
    def train_probe(self, texts, labels, probe_type="linear", test_size=0.2):
        """
        Entrena un probe para detectar un concepto.
        
        El probe es un clasificador f: R^d -> {0,1} donde d es la dimensión
        de las activaciones. Si el probe logra predecir el label mejor que
        chance, significa que el concepto está representado en esa capa.
        
        Probe score = accuracy del probe - baseline accuracy
        """
        X = self.extract_activations(texts)
        y = np.array(labels)
        
        # Encode labels
        unique_labels = sorted(set(y))
        self.label_encoder = {label: idx for idx, label in enumerate(unique_labels)}
        y_encoded = np.array([self.label_encoder[l] for l in y])
        
        X_train, X_test, y_train, y_test = train_test_split(
            X, y_encoded, test_size=test_size, random_state=42
        )
        
        if probe_type == "linear":
            # Linear probe: regresión logística
            self.probe = LogisticRegression(max_iter=1000)
        elif probe_type == "mlp":
            # MLP probe: red pequeña
            self.probe = nn.Sequential(
                nn.Linear(X.shape[1], 128),
                nn.ReLU(),
                nn.Linear(128, len(unique_labels))
            )
            # Train con PyTorch (simplificado)
            self._train_mlp_probe(X_train, y_train, X_test, y_test)
            return
        
        self.probe.fit(X_train, y_train)
        
        train_acc = self.probe.score(X_train, y_train)
        test_acc = self.probe.score(X_test, y_test)
        
        return {"train_acc": train_acc, "test_acc": test_acc}
    
    def _train_mlp_probe(self, X_train, y_train, X_test, y_test, epochs=100):
        """Entrena un MLP probe"""
        X_train_t = torch.FloatTensor(X_train)
        y_train_t = torch.LongTensor(y_train)
        X_test_t = torch.FloatTensor(X_test)
        y_test_t = torch.LongTensor(y_test)
        
        optimizer = torch.optim.Adam(self.probe.parameters(), lr=0.001)
        criterion = nn.CrossEntropyLoss()
        
        for epoch in range(epochs):
            self.probe.train()
            optimizer.zero_grad()
            outputs = self.probe(X_train_t)
            loss = criterion(outputs, y_train_t)
            loss.backward()
            optimizer.step()
        
        # Evaluar
        self.probe.eval()
        with torch.no_grad():
            train_acc = (self.probe(X_train_t).argmax(1) == y_train_t).float().mean()
            test_acc = (self.probe(X_test_t).argmax(1) == y_test_t).float().mean()
        
        print(f"MLP Probe - Train: {train_acc:.3f}, Test: {test_acc:.3f}")
    
    def evaluate_probe(self, texts, labels):
        """Evalúa el probe en datos nuevos"""
        X = self.extract_activations(texts)
        y = np.array([self.label_encoder[l] for l in labels])
        
        if isinstance(self.probe, nn.Module):
            self.probe.eval()
            with torch.no_grad():
                X_t = torch.FloatTensor(X)
                preds = self.probe(X_t).argmax(1).numpy()
        else:
            preds = self.probe.predict(X)
        
        accuracy = (preds == y).mean()
        return {"accuracy": accuracy, "predictions": preds, "true": y}
    
    def find_best_layer(self, texts, labels, concept_name):
        """
        Encuentra qué capa representa mejor un concepto.
        
        Para cada capa l, entrenamos un probe y calculamos:
        best_layer = argmax_l accuracy(probe_l)
        
        Un concepto que aparece temprano (ej: superficial syntax)
        tendrá mejor accuracy en capas tempranas.
        Un concepto que aparece después (ej: semantics profundo)
        tendrá mejor accuracy en capas finales.
        """
        num_layers = len(self.model.transformer.h)
        results = []
        
        for layer in range(num_layers):
            self.layer_to_probe = layer
            metrics = self.train_probe(texts, labels)
            results.append({
                "layer": layer,
                "test_accuracy": metrics["test_acc"]
            })
            print(f"Layer {layer}: {metrics['test_acc']:.3f}")
        
        best = max(results, key=lambda x: x["test_accuracy"])
        print(f"\nMejor capa para '{concept_name}': Layer {best['layer']} ({best['test_accuracy']:.3f})")
        
        return results


class SemanticProbingBenchmark:
    """Benchmark de probing para múltiples conceptos semánticos"""
    
    CONCEPTS = {
        "sentiment": ["positive", "negative", "neutral"],
        "tense": ["past", "present", "future"],
        "subject_number": ["singular", "plural"],
        "entity_type": ["person", "location", "organization"],
        "language": ["spanish", "english", "french"]
    }
    
    def __init__(self, model, tokenizer):
        self.probe_framework = ProbingClassifier(model, tokenizer)
    
    def run_full_benchmark(self, dataset):
        """
        Evalúa capacidad del modelo para representar múltiples conceptos.
        
        Para cada concepto, calculamos:
        - probing_accuracy: qué tan bien el probe predice el concepto
        - information_gain: accuracy - baseline (random = 1/n_classes)
        
        Si information_gain > 0.05, el concepto está "presente" en esa capa.
        """
        results = {}
        
        for concept_name, concept_labels in self.CONCEPTS.items():
            texts = [d["text"] for d in dataset if d.get("concept") == concept_name]
            labels = [d["label"] for d in dataset if d.get("concept") == concept_name]
            
            if len(texts) < 10:
                continue
            
            print(f"\n=== Probing concept: {concept_name} ===")
            layer_results = self.probe_framework.find_best_layer(texts, labels, concept_name)
            
            best_layer = max(layer_results, key=lambda x: x["test_accuracy"])
            baseline = 1.0 / len(set(labels))
            
            results[concept_name] = {
                "best_layer": best_layer["layer"],
                "probing_accuracy": best_layer["test_accuracy"],
                "information_gain": best_layer["test_accuracy"] - baseline,
                "layer_curve": layer_results
            }
        
        return results

Interpretability Framework Completo

Ahora juntamos todo en un framework integrado que combina attribution, activation analysis, y probing:

class LLMInterpretabilityFramework:
    """
    Framework completo para interpretabilidad de LLMs.
    
    Combina:
    - Feature attribution (qué input importa)
    - Activation analysis (qué pasa dentro)
    - Probing classifiers (qué conceptos representa)
    """
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
        self.attributor = AttentionAttributor(model, tokenizer)
        self.activation_analyzer = ActivationAnalyzer(model, tokenizer)
        self.probe_classifier = ProbingClassifier(model, tokenizer)
        self.activation_analyzer.register_hooks()
    
    def full_analysis(self, input_text, target_concept=None):
        """
        Corre un análisis completo de interpretabilidad.
        
        Returns:
        - attention_attribution: importancia de cada token
        - ig_attribution: feature attribution via integrated gradients
        - layer_activations: activaciones por capa
        - probing_results: resultados de probing si hay concepto target
        """
        results = {}
        
        # 1. Attention-based attribution
        results['attention_attribution'] = self.attributor.compute_token_importance(input_text)
        
        # 2. Integrated gradients
        results['ig_attribution'] = self.attributor.integrated_gradients(input_text)
        
        # 3. Activation analysis
        results['layer_activations'] = self.activation_analyzer.get_layer_activations(input_text)
        
        # 4. Probing (si hay target)
        if target_concept:
            results['probing'] = self.probe_classifier.evaluate_probe([input_text], [target_concept])
        
        return results
    
    def compare_models(self, texts, model_a, model_b, tokenizer_a, tokenizer_b):
        """
        Compara interpretabilidad entre dos modelos.
        
        Para validar que modelos más grandes o mejores tienen mejor
        representación, comparamos:
        - Probing accuracy: qué tan bien cada modelo representa conceptos
        - Activation similarity: qué tan similares son las representaciones
        - Attribution overlap: qué tan similares son las explicaciones
        """
        analyzer_a = ActivationAnalyzer(model_a, tokenizer_a)
        analyzer_b = ActivationAnalyzer(model_b, tokenizer_b)
        
        similarities = []
        for text in texts:
            acts_a = analyzer_a.get_layer_activations(text)
            acts_b = analyzer_b.get_layer_activations(text)
            
            # Comparar activación de última capa
            if acts_a and acts_b:
                sim = analyzer_a.compute_cosine_similarity(
                    acts_a[list(acts_a.keys())[-1]],
                    acts_b[list(acts_b.keys())[-1]]
                )
                similarities.append(sim)
        
        return {
            "mean_similarity": np.mean(similarities),
            "std_similarity": np.std(similarities)
        }
    
    def generate_explanation_report(self, input_text, output_text):
        """
        Genera un reporte explicativo para una predicción del modelo.
        """
        analysis = self.full_analysis(input_text)
        
        # Encontrar tokens más importantes
        top_tokens = sorted(
            analysis['attention_attribution'].items(),
            key=lambda x: -abs(x[1])
        )[:5]
        
        # Calcular stats de activación
        layer_means = []
        for layer, acts in analysis['layer_activations'].items():
            if acts is not None:
                layer_means.append(acts.mean().item())
        
        report = f"""
=== REPORTE DE INTERPRETABILIDAD ===

Input: {input_text}
Output: {output_text}

TOKENS MÁS IMPORTANTES (Attention):
"""
        for token, score in top_tokens:
            report += f"  - '{token}': {score:.4f}\n"
        
        report += f"""
PATRÓN DE ACTIVACIÓN:
  - Capas analizadas: {len(layer_means)}
  - Activación promedio: {np.mean(layer_means):.4f}
  - Activación std: {np.std(layer_means):.4f}
  - Capa con mayor activación: layer_{np.argmax(layer_means)}
"""
        return report

Los 3 Errores Principales

Error 1: No Intentar Entender Los Internals Del Modelo

El Error: Tratar el LLM como caja negra absoluta. Solo mirás el output y si parece razonable, lo usás. No hay debugging, no hay confianza, no hay mejora informada.

El Fix: Implementar interpretability como parte del pipeline de desarrollo. Antes de desplegar, hacer un análisis de qué está haciendo el modelo. No tiene que ser perfecto — incluso un attention visualization básico ya da intuición.

# Quick sanity check - no tiene que ser complejo
def basic_interpretability_check(model, tokenizer, concerning_prompts):
    """
    Check básico de interpretabilidad para prompts problemáticos.
    """
    for prompt in concerning_prompts:
        attributor = AttentionAttributor(model, tokenizer)
        importance = attributor.compute_token_importance(prompt)
        
        # Si el prompt menciona algo sensível y la atención va a tokens no relacionados,
        # eso podría indicar un problema
        print(f"\nPrompt: {prompt}")
        print(f"Top tokens por atención: {sorted(importance.items(), key=lambda x: -x[1])[:3]}")

Error 2: Confiar Solo En Black-Box Evaluation

El Error: Evaluar el modelo solo por accuracy/BLEU/Perplexity sin mirar cómo llega a esas respuestas. Dos modelos pueden tener la misma accuracy pero razonar de maneras completamente diferentes — uno puede estar copiando del training data y otro genuinamente razonando.

El Fix: Complementar métricas de evaluación con analysis de activación y probing. Por ejemplo, si el modelo es bueno en math, verificar que las capas finales tengan representaciones matemáticas (probing) y no solo esté memorizando soluciones.

class EvaluationWithInterpretability:
    """
    Combina evaluación standard con interpretabilidad.
    """
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
        self.probe = ProbingClassifier(model, tokenizer)
    
    def evaluate_with_explanation(self, test_set):
        """
        Evalúa modelo + explica por qué da esas respuestas.
        
        Evaluamos dos cosas:
        1. Performance standard: accuracy, F1, etc.
        2. Understanding score: qué tan bien las internal representations
           capturan el concepto correcto (via probing)
        """
        # Standard evaluation
        standard_metrics = self._standard_evaluation(test_set)
        
        # Probing evaluation
        if "concept_labels" in test_set[0]:
            texts = [d["text"] for d in test_set]
            labels = [d["concept_labels"] for d in test_set]
            
            probe_results = self.probe.find_best_layer(texts, labels, "semantic")
            understanding_score = max(r["test_accuracy"] for r in probe_results)
        else:
            understanding_score = None
        
        return {
            **standard_metrics,
            "understanding_score": understanding_score,
            "explanation": " probing score > 0.6 indicates good concept representation"
        }

Error 3: No Usar Interpretability Para Debug

El Error: Cuando el modelo falla, no hay manera de diagnosticar por qué. Se cambia randomicamente hyperparameters o se agrega más data sin saber qué está pasando.

El Fix: Usar activation analysis para identificar qué capas están fallando. Si el modelo genera output tóxico, analizar qué tokens y capas contribuyen a esa toxicidad. Si el modelo no sigue instrucciones, verificar si las capas de reasoning están activas.

class InterpretabilityDebugger:
    """Usa interpretabilidad para debuggear failures"""
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
    
    def diagnose_failure(self, prompt, bad_output, expected_output):
        """
        Diagnostica por qué un modelo falló en un caso específico.
        
        Strategy:
        1. Ver attention patterns — a qué tokens prestó atención?
        2. Comparar activaciones con casos exitoso
        3. Identificar qué capas están sub/over-activadas
        """
        # Get attention for the failing case
        attributor = AttentionAttributor(self.model, self.tokenizer)
        bad_attention = attributor.compute_token_importance(prompt)
        
        # Get activations
        analyzer = ActivationAnalyzer(self.model, self.tokenizer)
        analyzer.register_hooks()
        bad_activations = analyzer.get_layer_activations(prompt)
        
        # Find anomaly: capas con activación muy alta o baja vs baseline
        layer_means = {k: v.mean().item() for k, v in bad_activations.items() if v is not None}
        
        # Capas con activación fuera de rango normal (> 2 std)
        mean_act = np.mean(list(layer_means.values()))
        std_act = np.std(list(layer_means.values()))
        anomalous_layers = [
            (layer, act) for layer, act in layer_means.items()
            if abs(act - mean_act) > 2 * std_act
        ]
        
        return {
            "attention": bad_attention,
            "anomalous_layers": anomalous_layers,
            "hypothesis": self._interpret_anomaly(anomalous_layers)
        }
    
    def _interpret_anomaly(self, anomalous_layers):
        """Interpreta qué significan las capas anómalas"""
        if not anomalous_layers:
            return "No anomaly detected - failure may be in data or architecture"
        
        interpretations = []
        for layer, act in anomalous_layers:
            if act > mean_act + 2*std_act:
                interpretations.append(f"{layer} is over-activating (possible memorization)")
            else:
                interpretations.append(f"{layer} is under-activating (possible reasoning failure)")
        return interpretations

La Matemática Detrás

La interpretabilidad tiene fundamentos matemáticos sólidos:

Integrated Gradients — La atribución de feature importance más rigurosa:

Dado un input $x = (x_1, ..., x_n)$ y un modelo $f$, la importancia del feature $i$ es:

$$IG_i(x) = (x_i - x'_i) \times \int_{\alpha=0}^{1} \frac{\partial f(x' + \alpha(x-x'))}{\partial x_i} d\alpha$$

donde $x'$ es un baseline (input de-reference). La integral se aproxima numéricamente.

Probing Classifier — Formalizado como:

$$score_c(l) = \mathbb{E}_{(x,y) \sim D}[ \mathbb{1}_{h_{probe,l}(x) = y} ] - \mathbb{E}_{(x,y) \sim D}[ \mathbb{1}_{h_{baseline}(x) = y} ]$$

donde $h_{probe,l}$ es el probe entrenado sobre la capa $l$, y el baseline es predict siempre la clase más frecuente.

Information Bottleneck en Layers — La teoría dice que:

$$I(X;Z_l) \geq I(Z_{l+1};Z_l) \geq ... \geq I(Z_L;Y)$$

La información sobre el input $X$ se va comprimiendo a través de las capas hasta llegar a la predicción $Y$. Las capas intermedias $Z_l$ contienen toda la información necesaria para predecir $Y$.

  2. Confiar solo en black-box evaluation → Fix: complementar métricas con probing classifiers para verificar qué representa el modelo
