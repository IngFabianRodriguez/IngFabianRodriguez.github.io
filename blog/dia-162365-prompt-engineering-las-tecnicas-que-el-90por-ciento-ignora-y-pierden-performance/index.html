📐 Fundamentos Teóricos

Antes de hablar de herramientas, necesitamos entender qué está pasando debajo. Los LLMs para código son una categoría completamente diferente de modelos.

¿Qué son los Code LLMs?

Los Code LLMs son modelos entrenados específicamente para entender y generar código. A diferencia de LLMs generales (GPT-4, Claude), estos modelos fueron pre-entrenados con:

  • Billones de líneas de código de repositorios públicos (GitHub, GitLab)
  • Múltiples lenguajes: Python, JavaScript, TypeScript, Go, Rust, etc.
  • Contexto de documentación: issues, PRs, comments

La matemática del code completion

El code completion funciona para predecir la siguiente secuencia de tokens dado un contexto.

P(code | contexto) = \prod_{t=1}^{n} P(token_t | token_{1:t-1}, contexto)

Esto es simplemente una red transformer decoder. Lo crucial es que el modelo aprende patrones de código que van más allá de estadísticas locales — entiende estructuras, dependencias, y semántica.

💻 Implementación Práctica

Code Completion con HuggingFace

# Code Completion con HuggingFace
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

# Cargar StarCoder
model_name = "bigcode/starcoder"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.bfloat16,
    device_map="auto"
)

def complete_code(prompt, max_new_tokens=50):
    """Genera código basado en el prompt."""
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    
    outputs = model.generate(
        **inputs,
        max_new_tokens=max_new_tokens,
        temperature=0.2,
        top_p=0.95,
        do_sample=True
    )
    
    return tokenizer.decode(outputs[0], skip_special_tokens=True)

# Ejemplo de uso
prompt = """def fibonacci(n):
    '''Calcula el n-ésimo número de Fibonacci'''
    if n <= 1:
        return n
    """
    
result = complete_code(prompt)
print(result)

Fine-tuning para Código Específico

# Fine-tuning de Code LLM con HuggingFace TRL
from transformers import AutoModelForCausalLM, AutoTokenizer
from trl import SFTTrainer, DataCollatorForCompletionOnlyLM
from datasets import load_dataset

# Cargar modelo base
model_name = "bigcode/starcoder"
model = AutoModelForCausalLM.from_pretrained(model_name)
tokenizer = AutoTokenizer.from_pretrained(model_name)

# Preparar dataset - USA DATOS DE CALIDAD
def format_for_code_gen(example):
    """Formatea ejemplos para fine-tuning de código."""
    return {
        "text": f"### Problema\n{example['description']}\n### Código\n{example['code']}\n### Explicación\n{example['explanation']}"
    }

dataset = load_dataset("your-quality-code-dataset", split="train")
dataset = dataset.map(format_for_code_gen)

# Configurar trainer
trainer = SFTTrainer(
    model=model,
    train_dataset=dataset,
    tokenizer=tokenizer,
    max_seq_length=512,
    dataset_text_field="text",
)

# Fine-tune (usa una muestra pequeña para prueba)
trainer.train()

Revisa el siguiente código y sugiere mejoras:

```python
{code}
```

Formato de respuesta:
- **Bugs encontrados:** [lista]
- **Mejoras de estilo:** [lista]
- **Mejoras de performance:** [lista]
- **Mejoras de seguridad:** [lista]
"""

CODE_REFACTOR_TEMPLATE = """Refactoriza el siguiente código para que sea más limpio y idiomático.
Mantén la funcionalidad exacta.

```python
{code}
```"""

def explain_code(code: str, model) -> str:
    """Genera explicación de código."""
    prompt = CODE_EXPLANATION_TEMPLATE.format(code=code)
    return model.generate(prompt)

def review_code(code: str, model) -> str:
    """Genera code review."""
    prompt = CODE_REVIEW_TEMPLATE.format(code=code)
    return model.generate(prompt)

🔬 Math Behind the Scenes

Perplejidad en Code Generation

La calidad de un code LLM se mide frecuentemente con perplexity:

PP(code) = \exp\left(-\frac{1}{N}\sum_{i=1}^{N} \log P(token_i)\right)

Menor perplexidad = mejor el modelo predice código. StarCoder achieves ~3.5 perplexity en HumanEval.

Exact Match vs Pass@k

Pass@k = 1 - \frac{\binom{N-c}{k}}{\binom{N}{k}}

Donde N es el número de intentos y c es el número de correctos. Pass@1 es la probabilidad de acertar en el primer intento.

🚨 Errores Comunes (y sus fixes)

Error 1: Usar LLM para código sin verificar las suggestions

Este es el error más peligroso, parcero. Copilot te sugiere código y tú le das Accept sin revisar. Grave error.

El problema: Los LLMs generan código que puede compilar pero estar equivocado. Pueden:

  • Introducir bugs sutiles
  • Usar APIs deprecadas
  • Implementar lógica incorrecta
  • Crear vulnerabilidades de seguridad

El fix: SIEMPRE haz code review de las sugerencias:

# Workflow correcto con LLM para código
def usar_llm_codigo():
    # 1. Genera la sugerencia
    suggestion = llm.generate_code(prompt)
    
    # 2. SIEMPRE lee y entiende lo que generó
    print("Sugerencia:", suggestion)
    
    # 3. Verifica manualmente:
    # - ¿La lógica tiene sentido?
    # - ¿Maneja edge cases?
    # - ¿Hay tests?
    
    # 4. Antes de aceptar, corre tests
    # 5. Si no entiendes algo, PIDE EXPLICACIÓN
    explanation = llm.explain_code(suggestion)
    print("Explicación:", explanation)
    
    # SOLO después de verificar, usa el código
    return suggestion

Error 2: Fine-tuning de código con datos de baja calidad

He visto muchos que agarran cualquier código de GitHub, lo meten al fine-tuning, y esperan magia. No funciona así.

El problema: Garbage in, garbage out. Si entrenas con código de baja calidad:

  • El modelo aprende patrones malos
  • Genera código con los mismos bugs
  • El modelo memoriza en vez de generalizar

El fix: Curación rigurosa del dataset:

# Dataset de calidad para fine-tuning de código
from datasets import load_dataset

def curate_quality_dataset():

    # 4. Verificar que compila

Error 3: No usar los modelos específicos para código (CodeGen, StarCoder)

Mucha gente usa GPT-4 o Claude para todo, incluyendo código. Y sí, funcionan, pero no son óptimos.

El problema: Modelos generales tienen:

  • Menor specialized training para código
  • Context window puede ser desperdiciado
  • Costos más altos
  • Latencia mayor

El fix: Usa el modelo correcto para cada tarea:

# Estrategia de modelos para código
from transformers import AutoModelForCausalLM, AutoTokenizer

def select_code_model(task: str, budget: str = "medium"):
    """Selecciona el modelo óptimo para la tarea."""
    
    models = {
        "completion": {
            "best": "bigcode/starcoder",
            "fast": "bigcode/santacoder",
        },
        "generation": {
            "best": "Salesforce/codegen25-7b-multi",
            "fast": "Salesforce/codegen25-1b-multi",
        },
        "explanation": {
            "best": "claude-3-opus",  # Si budget lo permite
            "good": "gpt-4o",
        },
        "review": {
            "best": "claude-3-opus",
            "good": "gpt-4o",
        }
    }
    
    # Código simple → modelos pequeños y rápidos
    # Código complejo → modelos grandes y precisos
    # Explicaciones → modelos con buen lenguaje (Anthropic)
    # Production code → siempre verifica
    
    if task == "completion" and budget == "low":
        return "bigcode/santacoder"  # Rápido y gratis
    
    if task == "generation" and budget == "high":
        return "Salesforce/codegen25-7b-multi"  # Mejor calidad
    
    return "bigcode/starcoder"  # Good balance

✅ Mejores Prácticas

  • Usa modelos especializados: CodeGen y StarCoder para completion/generación
  • Verifica siempre: Code review de TODAS las sugerencias
  • Datos de calidad: Si fine-tunebas, curado riguroso es no negociable
  • Prompts específicos: Contexto, formato, constraints
  • Chain of thought: Para tareas complejas, pide razonamiento
  • Tests obligatorios: Antes de usar código generado en producción

📊 Resumen

  • Code LLMs como CodeGen y StarCoder están redefiniendo el desarrollo de software
  • Code completion es solo el comienzo — explanation, review, refactoring son igual de valiosos
  • Usa modelos especializados para código en vez de modelos generales cuando sea posible
  • SIEMPRE verifica el código generado — no es porque compile que está bien
  • Fine-tuning requiere datos de calidad, no cualquier código

Pues ahí lo tienes, parcero. Los LLMs para código son una herramienta poderosa, pero como toda herramienta, hay que saber usarla. No se trata de reemplazar a los developers, sino de amplificar su productividad. Nos vemos mañana con más.
