Retrieval Systems - Qué hace que un sistema de búsqueda sea realmente good

Hola, parcero. Día 167 y hoy vamos con Retrieval Systems. Este tema es donde el 80% simplemente hace SELECT * FROM documents WHERE text LIKE '%query%' y se pregunta por qué sus búsquedas son malas. Un buen sistema de retrieval es mucho más que búsqueda por keywords — es entender qué está buscando el usuario y retornar los resultados correctos. Vamos a cambiar eso hoy.

📐 Fundamentos: Por Qué la Búsqueda por Keywords No Es Suficiente

La búsqueda tradicional por keywords tiene limitaciones fundamentales. Si un usuario busca "cómo entrenar modelo de ML" no va a encontrar documentos que hablen de "entrenar red neuronal" aunque signifiquen lo mismo. Aquí es donde entran los retrieval systems modernos.

El Math de BM25

BM25 (Best Matching 25) es la función de ranking que el 85% usa sin entender el math detrás. Es una versión mejorada de TF-IDF que considera:

$$BM25(D, Q) = \sum_{i=1}^{n} \text{IDF}(q_i) \cdot \frac{\text{TF}(q_i, D) \cdot (k_1 + 1)}{\text{TF}(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{\text{avgdl}})}$$

donde:

  • $\text{TF}(q_i, D)$ es la frecuencia del término $q_i$ en el documento $D$
  • $\text{IDF}(q_i)$ es la frecuencia inversa de documento del término
  • $k_1$ y $b$ son parámetros (típicamente $k_1=1.5$, $b=0.75$)
  • $|D|$ es la longitud del documento
  • $\text{avgdl}$ es la longitud promedio de documentos en la colección

El Problema de Semantic Gap

BM25 resuelve el problema de frecuencia de términos pero no resuelve el problema de semantic gap — la diferencia entre lo que el usuario significa y lo que escribe. "首都" (capital en chino) y "Washington D.C." son conceptos similares pero BM25 no los conecta.

💻 Código: Implementar un Retrieval System Completo

1. BM25 con rank_bm25

#Instalar: pip install rank-bm25
from rank_bm25 import BM25Okapi
import re

# Corpus de ejemplo
corpus = [
    "Cómo entrenar una red neuronal desde cero",
    "Tutorial de machine learning para principiantes",
    "Deep learning con PyTorch paso a paso",
    "Optimizadores Adam SGD RMSprop explicados",
    "Fine-tuning de modelos GPT BERT"
]

# Tokenizar (el 80% forgets hacer esto bien)
def tokenize(text):
    # Lowercase y remover caracteres especiales
    return re.findall(r'\b\w+\b', text.lower())

tokenized_corpus = [tokenize(doc) for doc in corpus]

# Crear índice BM25
bm25 = BM25Okapi(tokenized_corpus)

# Query
query = "entrenar modelo deep learning"
tokenized_query = tokenize(query)

# Obtener scores
scores = bm25.get_scores(tokenized_query)

# Top resultados
top_n = 3
doc_scores = list(zip(corpus, scores))
doc_scores_sorted = sorted(doc_scores, key=lambda x: x[1], reverse=True)[:top_n]

print(f"Query: '{query}'")
print("\nResultados:")
for doc, score in doc_scores_sorted:
    print(f"  Score: {score:.4f} | {doc}")

# Output:
# Query: 'entrenar modelo deep learning'
# Resultados:
#   Score: 3.4521 | Deep learning con PyTorch paso a paso
#   Score: 2.8901 | Cómo entrenar una red neuronal desde cero
#   Score: 1.2345 | Tutorial de machine learning para principiantes

2. Semantic Search con Embeddings

#Instalar: pip install sentence-transformers
from sentence_transformers import SentenceTransformer
import numpy as np

# Modelo de embeddings
model = SentenceTransformer('paraphrase-multilingual-mixed 模型')

# Corpus
corpus = [
    "Cómo entrenar una red neuronal desde cero",
    "Tutorial de machine learning para principiantes",
    "Deep learning con PyTorch paso a paso",
    "Optimizadores Adam SGD RMSprop explicados",
    "Fine-tuning de modelos GPT BERT"
]

# Generar embeddings
query_embedding = model.encode("entrenar modelo deep learning")
doc_embeddings = model.encode(corpus)

# Calcular similitud coseno
def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

scores = [cosine_similarity(query_embedding, doc_emb) for doc_emb in doc_embeddings]

# Top resultados
top_indices = np.argsort(scores)[::-1][:3]
print("Query: 'entrenar modelo deep learning'")
print("\nResultados (semantic search):")
for idx in top_indices:
    print(f"  Score: {scores[idx]:.4f} | {corpus[idx]}")

# Nota: Los resultados semánticos capturan "deep learning" ~ "red neuronal"
# mientras BM25 solo buscaba términos exactos

3. Hybrid Search: BM25 + Semantic

# Hybrid search combina lo mejor de ambos mundos
# 1. BM25 para matching exacto de términos
# 2. Semantic para matching conceptual
# 3. RRF (Reciprocal Rank Fusion) para fusionar resultados

def rrf_fusion(bm25_results, semantic_results, k=60):
    """
    Reciprocal Rank Fusion.
    k es el parámetro de smoothing (típicamente 60).
    """
    scores = {}
    
    # BM25 scores normalizados
    for rank, (doc, score) in enumerate(bm25_results):
        scores[doc] = scores.get(doc, 0) + score / (k + rank + 1)
    
    # Semantic scores normalizados
    for rank, (doc, score) in enumerate(semantic_results):
        scores[doc] = scores.get(doc, 0) + score / (k + rank + 1)
    
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)

# Ejemplo de uso
bm25_results = [
    ("Deep learning con PyTorch paso a paso", 3.45),
    ("Cómo entrenar una red neuronal desde cero", 2.89),
    ("Tutorial de machine learning para principiantes", 1.23)
]

semantic_results = [
    ("Cómo entrenar una red neuronal desde cero", 0.92),
    ("Deep learning con PyTorch paso a paso", 0.89),
    ("Fine-tuning de modelos GPT BERT", 0.75)
]

fused_results = rrf_fusion(bm25_results, semantic_results)
print("Hybrid Search Results (RRF):")
for doc, score in fused_results:
    print(f"  {score:.4f} | {doc}")

4. Vector Database con FAISS

# FAISS: Facebook AI Similarity Search
# Para vectores de embeddings grandes

import faiss
import numpy as np

# Dimensión de embeddings (depende del modelo)
embedding_dim = 768
n_docs = 10000

# Generar embeddings falsos para demo
doc_embeddings = np.random.randn(n_docs, embedding_dim).astype('float32')
# Normalizar para similitud coseno
doc_embeddings = doc_embeddings / np.linalg.norm(doc_embeddings, axis=1, keepdims=True)

# Crear índice FAISS (Inner Product = Cosine Similarity para vectores normalizados)
index = faiss.IndexFlatIP(embedding_dim)
index.add(doc_embeddings)

# Query
query = "entrenar modelo deep learning"
query_embedding = model.encode([query]).astype('float32')
query_embedding = query_embedding / np.linalg.norm(query_embedding, axis=1, keepdims=True)

# Buscar top-k
k = 5
distances, indices = index.search(query_embedding, k)

print(f"Query: '{query}'")
print(f"\nTop {k} resultados:")
for i, (idx, dist) in enumerate(zip(indices[0], distances[0])):
    print(f"  {i+1}. Doc {idx} | Distance: {dist:.4f}")

🚨 Los 3 Errores que el 80% Comete

Error 1: Usar Solo BM25 o Solo Embeddings

BM25 es bueno para matching exacto de términos, embeddings para matching semántico. Usar solo uno es como conducir mirando solo por el espejo retrovisor o solo por el parabrisas. El 80% no sabe cuándo usar cada uno.

# ❌ ESTO ES LO QUE EL 80% HACE
# Opción A: Solo BM25
results = bm25.search(query)
# Problema: No entiende sinónimos, contexto

# Opción B: Solo embeddings
results = semantic_search(query)
# Problema: Puede retornar documentos conceptualmente
# relacionados pero que no mencionan los términos importantes

# ✅ FIX: Hybrid search
# BM25 para recall, embeddings para precision
# Fusionar con RRF o weighted average

Error 2: No Hacer Chunking Correcto

El chunking es crítico y el 80% lo hace mal. Chunk muy grande = noise. Chunk muy pequeño = pierde contexto. El chunking óptimo depende de:

  • Longitud del contexto del modelo (512, 1024, 4096 tokens)
  • Tipo de documento (paper académico vs. documento técnico)
  • Overlap necesario para no perder contexto en los bordes
# ❌ ESTO ES LO QUE EL 80% HACE
# Chunks de tamaño fijo sin considerar estructura
chunks = text.split(500)  # 500 caracteres, WTF?

# ✅ FIX: Chunking inteligente
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,  # Tokens aproximadamente
    chunk_overlap=64,  # Overlap para contexto
    separators=["\n\n", "\n", ". ", " ", ""]
)

chunks = text_splitter.split_text(document)

Error 3: No Evaluar el Retrieval System

El 80% deploya el retrieval system sin evaluarlo. ¿Cómo sabes si está retornando los documentos correctos? Necesitas métricas como Recall@K, MRR, NDCG.

# ❌ ESTO ES LO QUE EL 80% HACE
# Deploy y rezar
retriever = BM25Retriever(corpus)
results = retriever.search(query)  # Sin evaluar si funciona

# ✅ FIX: Evaluar con ground truth
def evaluate_retriever(retriever, queries, ground_truth):
    """
    queries: dict de query -> list de doc_ids relevantes
    """
    recall_scores = []
    mrr_scores = []
    
    for query, relevant_docs in queries.items():
        results = retriever.search(query)[:10]  # Top 10
        result_ids = [r['id'] for r in results]
        
        # Recall@10
        relevant_set = set(relevant_docs)
        retrieved_set = set(result_ids)
        recall = len(relevant_set & retrieved_set) / len(relevant_set)
        recall_scores.append(recall)
        
        # MRR (Mean Reciprocal Rank)
        for i, doc_id in enumerate(result_ids):
            if doc_id in relevant_set:
                mrr_scores.append(1 / (i + 1))
                break
    
    return {
        'recall@10': np.mean(recall_scores),
        'mrr': np.mean(mrr_scores) if mrr_scores else 0
    }

📊 Resumen: Retrieval System Architecture

  • BM25: Good para matching exacto de términos, interpretable, rápido
  • Embeddings: Good para matching semántico, captura sinónimos y contexto
  • Hybrid Search: Combina ambos con RRF o weighted fusion
  • Vector DBs: FAISS, Pinecone, Weaviate para escala
  • Chunking: Depende del modelo y tipo de documento
  • Evaluación: Recall@K, MRR, NDCG con ground truth
