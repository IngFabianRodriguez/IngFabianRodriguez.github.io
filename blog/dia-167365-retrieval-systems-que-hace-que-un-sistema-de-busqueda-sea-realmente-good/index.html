📐 Fundamentos: Qué Es ONNX y Por Qué Debería Importarte

ONNX (Open Neural Network Exchange) es un formato interoperable para representar modelos de machine learning. La idea es simple: una vez que entrenas tu modelo en PyTorch, TensorFlow, o cualquier framework, lo exportas a ONNX y puedes deployarlo en cualquier plataforma sin necesidad de Python.

El Math de la Exportación a ONNX

Exportar un modelo a ONNX implica trazar las operaciones del grafo computacional. Dado un modelo $f(x; \theta)$ donde $\theta$ son los pesos, la exportación captura:

$$\text{ONNX Graph} = \{\text{Input}, \text{Output}, \text{Nodes}, \text{Initializers}\}$$

Cada nodo en el grafo ONNX representa una operación como MatMul, Conv, Softmax, etc. La exportación verifica que el grafo es válido y que puede ser ejecutado por el runtime de ONNX.

TorchScript vs ONNX: Cuándo Usar Cuál

TorchScript es la solución de PyTorch para serializar modelos. Es ideal cuando:

  • Tu modelo es 100% PyTorch
  • Quieres hacer inference en un servidor PyTorch
  • Necesitas optimizar con torch.compile

ONNX es mejor cuando:

  • Deploy en edge devices (iOS, Android, Raspberry Pi)
  • Necesitas inference en Azure, AWS, o Google Cloud sin overhead de Python
  • Quieres usar ONNX Runtime que puede ser 2-3x más rápido
  • Interoperabilidad con modelos de otros frameworks

💻 Código: Exportar, Verificar y Optimizar

1. Exportar un Modelo a ONNX

import torch
import torch.nn as nn
import onnx
import onnxruntime as ort
import numpy as np

# Definimos un modelo simple para demostración
class SimpleTransformer(nn.Module):
    def __init__(self, d_model=512, nhead=8, num_layers=6):
        super().__init__()
        self.embedding = nn.Embedding(10000, d_model)
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead, batch_first=True),
            num_layers
        )
        self.fc = nn.Linear(d_model, 10000)
    
    def forward(self, x):
        x = self.embedding(x)
        x = self.transformer(x)
        x = self.fc(x)
        return x

# Crear modelo y exportar a ONNX
model = SimpleTransformer()
model.eval()

# Input de ejemplo (batch_size=1, seq_len=128)
example_input = torch.randint(0, 10000, (1, 128))

# Exportar a ONNX
torch.onnx.export(
    model,
    example_input,
    "model.onnx",
    input_names=["input_ids"],
    output_names=["logits"],
    dynamic_axes={
        "input_ids": {0: "batch_size", 1: "seq_len"},
        "logits": {0: "batch_size", 1: "seq_len"}
    },
    opset_version=17,  # Versión de operadores ONNX
    do_constant_folding=True,  # Optimización: pliega constantes
)

print("Modelo exportado a ONNX exitosamente")

2. Verificar el Modelo ONNX

# Verificar que el modelo ONNX es válido
onnx_model = onnx.load("model.onnx")
onnx.checker.check_model(onnx_model)
print("✓ Modelo ONNX es válido")

# Verificar que produce los mismos outputs que PyTorch
# Esto es CRÍTICO y el 80% no lo hace

# Inference en PyTorch
with torch.no_grad():
    pt_output = model(example_input)
    pt_prediction = torch.argmax(pt_output, dim=-1)

# Inference en ONNX Runtime
ort_session = ort.InferenceSession("model.onnx")
ort_inputs = {"input_ids": example_input.numpy().astype(np.int64)}
ort_output = ort_session.run(None, ort_inputs)[0]
ort_prediction = np.argmax(ort_output, axis=-1)

# Comparar
if np.allclose(pt_prediction.numpy(), ort_prediction, rtol=1e-3, atol=1e-3):
    print("✓ PyTorch y ONNX producen los mismos resultados")
else:
    print("✗ ERROR: Los outputs no coinciden!")
    print(f"PyTorch: {pt_prediction[:5]}")
    print(f"ONNX:     {ort_prediction[:5]}")

3. Optimizar con ONNX Runtime

# ONNX Runtime con optimizaciones
from onnxruntime import SessionOptions, GraphOptimizationLevel

# Configurar sesión optimizada
sess_options = SessionOptions()
sess_options.graph_optimization_level = GraphOptimizationLevel.ORT_ENABLE_ALL
sess_options.intra_op_num_threads = 4  # Paralelismo intra-op
sess_options.inter_op_num_threads = 4  # Paralelismo inter-op

# Crear sesión optimizada
ort_session = ort.InferenceSession(
    "model.onnx",
    sess_options,
    providers=['CUDAExecutionProvider', 'CPUExecutionProvider']
)

# Benchmark: PyTorch vs ONNX Runtime
import time

n_runs = 100

# PyTorch
model.cuda()
example_input_cuda = example_input.cuda()

start = time.time()
for _ in range(n_runs):
    with torch.no_grad():
        _ = model(example_input_cuda)
pt_time = time.time() - start

# ONNX Runtime (usando GPU si disponible)
if 'CUDAExecutionProvider' in ort_session.get_providers():
    ort_session.set_providers(['CUDAExecutionProvider'])
    
start = time.time()
for _ in range(n_runs):
    ort_output = ort_session.run(None, ort_inputs)[0]
ort_time = time.time() - start

print(f"PyTorch time:      {pt_time:.3f}s ({n_runs} runs)")
print(f"ONNX Runtime time: {ort_time:.3f}s ({n_runs} runs)")
print(f"Speedup:           {pt_time/ort_time:.2f}x")

4. TorchScript: Exportación Alternativa

# TorchScript: otra forma de serializar modelos PyTorch
# Método 1: torch.jit.trace (solo funciona con inputs fijos)
traced_model = torch.jit.trace(model, example_input)
traced_model.save("model_traced.pt")

# Método 2: torch.jit.script (para modelos con control flow)
@torch.jit.script
def process_sequence(x):
    return model(x)

scripted_model = process_sequence(example_input)
scripted_model.save("model_scripted.pt")

# Cargar y usar
loaded_model = torch.jit.load("model_traced.pt")
with torch.no_grad():
    output = loaded_model(example_input)

print("TorchScript modelo cargado y funcionando")

🚨 Los 3 Errores que el 80% Comete

Error 1: No Exportar a ONNX Cuando Necesitas Cross-Platform Deployment

Este es el error más común. La gente entrena en PyTorch y deploya PyTorch en producción, incluyendo el interpretador Python completo, Docker image gigante, y todos los overheads. ONNX existe para esto — para liberate tu modelo del Runtime de Python.

Error 2: No Verificar Que el Modelo Exportado Produce los Mismos Outputs

Este error es crítico y causa bugs en producción que son muy difíciles de debuggear. El modelo exportado "funciona" pero produce resultados diferentes al original. En sistemas de producción esto puede causar que las predicciones cambien sutilmente — o drásticamente — sin que nadie se dé cuenta.

# ❌ ESTO ES LO QUE EL 80% HACE
torch.onnx.export(model, example_input, "model.onnx")
#listo, a producción... sin verificar nada

# ✅ FIX: Verificación rigurosa de equivalencia
def verify_model_equivalence(pytorch_model, onnx_path, test_cases):
    """Verifica que el modelo ONNX produce los mismos outputs que PyTorch."""
    
    ort_session = ort.InferenceSession(onnx_path)
    
    for i, (input_data, expected_output) in enumerate(test_cases):
        # PyTorch
        pytorch_model.eval()
        with torch.no_grad():
            pt_out = pytorch_model(input_data)
        
        # ONNX
        ort_in = {"input_ids": input_data.numpy().astype(np.int64)}
        ort_out = ort_session.run(None, ort_in)[0]
        
        # Verificar
        if not np.allclose(pt_out.numpy(), ort_out, rtol=1e-3, atol=1e-3):
            raise ValueError(f"Output mismatch on test case {i}")
    
    print("✓ Verificación completa: modelos equivalentes")
    
# Usar con múltiples test cases
test_cases = [
    (torch.randint(0, 10000, (1, 128)), None),
    (torch.randint(0, 10000, (1, 256)), None),
    (torch.randint(0, 10000, (2, 128)), None),  # batch size diferente
]
verify_model_equivalence(model, "model.onnx", test_cases)

Error 3: No Usar ONNX Runtime Optimization

ONNX Runtime tiene optimizaciones que pueden hacer tu inference 2-3x más rápido. Pero por defecto no están habilitadas. La mayoría de la gente usa ONNX Runtime sin configurar las optimizaciones y se preguntan por qué no es más rápido que PyTorch.

# ❌ ESTO ES LO QUE EL 80% HACE
sess = ort.InferenceSession("model.onnx")  # Sin opciones = sin optimizaciones
result = sess.run(None, {"input_ids": x})

# ✅ FIX: Habilitar todas las optimizaciones
from onnxruntime import SessionOptions, GraphOptimizationLevel

sess_options = SessionOptions()
sess_options.graph_optimization_level = GraphOptimizationLevel.ORT_ENABLE_ALL

# Para inference en GPU:
sess_options.provider_options = [
    {"device_id": "0", "cudnn_conv_algo_search": "DEFAULT"}
]

sess = ort.InferenceSession("model.onnx", sess_options)

# ONNX Runtime aplica automáticamente:
# - Constant folding
# - Node elimination
# - Node fusion (fusionar ops adyacentes)
# - Memory optimization
# - Graph partitioning (dividir por dispositivo)

print(f"Providers disponibles: {sess.get_providers()}")

📊 Resumen: ONNX vs TorchScript

  • ONNX: Formato interoperable, ideal para deployment cross-platform, ONNX Runtime ofrece 2-3x speedup
  • TorchScript: Serialización nativa de PyTorch, ideal para inference en entornos PyTorch
  • Verificación: SIEMPRE verificar que el modelo exportado produce los mismos outputs
  • Dynamic shapes: Usa dynamic_axes para manejar batch sizes y seq lengths variables
  • ONNX Runtime: Habilita todas las optimizaciones con ORT_ENABLE_ALL
  • Opset version: Usa la versión más reciente que soporte tu target deployment
