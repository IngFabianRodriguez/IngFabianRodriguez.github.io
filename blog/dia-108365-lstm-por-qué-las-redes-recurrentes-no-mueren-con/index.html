🎯 ¿Qué Es LSTM?

Volvimos, parcero. Día 108 y hoy hablamos de LSTM (Long Short-Term Memory). Si attention era lo que hizo obsoletas a las RNN, LSTM fue lo que las mantuvo vivas cuando todos las daban por muertas. La clave:解决的 el vanishing gradient problem que perseguía a las redes recurrentes desde los años 90. Sin LSTM, no habríamos tenido traductors ni modelos de secuencia decentes antes de Transformers. Así que respetá a los pioneeros.

📐 La Matemática De LSTM

LSTM resuelve el vanishing gradient con una idea elegante: tener un "highway" (cell state) donde la información fluye casi sin modificación a través del tiempo, selectivamente añadiendo o quitando información mediante compuertas (gates).

Las tres compuertas (gates)

  • Forget Gate (f): Decide qué información del cell state anterior OLVIDAR. Recibe h_{t-1} y x_t, produce un vector entre 0 y 1 para cada elemento del cell state.
  • Input Gate (i): Decide qué información NUEVA agregar al cell state. Un sigmoid decide qué actualizar, un tanh genera el candidato.
  • Output Gate (o): Decide qué parte del cell state sale como hidden state. El cell state pasa por tanh (escala a -1,1) y se multiplica por la compuerta de output.

Las ecuaciones

Dada la entrada x_t y el hidden state anterior h_{t-1}:

  • f_t = σ(W_f · [h_{t-1}, x_t] + b_f) — Forget gate
  • i_t = σ(W_i · [h_{t-1}, x_t] + b_i) — Input gate
  • C̃_t = tanh(W_C · [h_{t-1}, x_t] + b_C) — Candidate cell state
  • C_t = f_t × C_{t-1} + i_t × C̃_t — Cell state update
  • o_t = σ(W_o · [h_{t-1}, x_t] + b_o) — Output gate
  • h_t = o_t × tanh(C_t) — Hidden state

La magia está en C_t: el forget gate f_t cerca de 1 significa "mantener toda la información anterior", cerca de 0 significa "olvidar casi todo". El input gate i_t cerca de 1 significa "agregar toda la información nueva", cerca de 0 significa "no agregar nada". Esto es casi como un sistema de lectura/escritura en memoria selectiva.

# ============================================================
# 1. LSTM CELL DESDE CERO — IMPLEMENTACIÓN MANUAL
# ============================================================
class LSTMCellManual(nn.Module):
    """
    Un LSTM Cell (una celda, un timestep) implementado desde cero.
    """
    def __init__(self, input_size, hidden_size):
        super().__init__()
        self.input_size = input_size
        self.hidden_size = hidden_size
        
        # Gates: forget, input, output
        # Cada gate tiene: W_ii, W_if, W_io + bias correspondiente
        self.weight_ih = nn.Parameter(torch.randn(3 * hidden_size, input_size))
        self.weight_hh = nn.Parameter(torch.randn(3 * hidden_size, hidden_size))
        self.bias = nn.Parameter(torch.zeros(3 * hidden_size))
        
        # Candidate cell state
        self.weight_ch = nn.Parameter(torch.randn(hidden_size, input_size))
        self.weight_chh = nn.Parameter(torch.randn(hidden_size, hidden_size))
        self.bias_ch = nn.Parameter(torch.zeros(hidden_size))
    
    def forward(self, x, hidden_state):
        """
        x: (batch, input_size) — input en timestep t
        hidden_state: tuple de (h_{t-1}, C_{t-1})
        """
        h_prev, c_prev = hidden_state
        
        # Linear para gates: concatenation [h_{t-1}, x]
        gates = torch.mm(x, self.weight_ih.t()) + torch.mm(h_prev, self.weight_hh.t()) + self.bias
        f, i, o = gates.chunk(3, dim=1)  # Split en 3 partes
        
        # Candidate cell state
        c_tilde = torch.tanh(torch.mm(x, self.weight_ch.t()) + 
                            torch.mm(h_prev, self.weight_chh.t()) + self.bias_ch)
        
        # Apply sigmoid a gates
        f = torch.sigmoid(f)  # Forget gate
        i = torch.sigmoid(i)  # Input gate
        o = torch.sigmoid(o)  # Output gate
        
        # Update cell state: "highway" donde gradientes fluyen
        c_next = f * c_prev + i * c_tilde
        
        # Update hidden state
        h_next = o * torch.tanh(c_next)
        
        return h_next, c_next

# 2. BIDIRECTIONAL LSTM PARA SEQUENCE LABELING
# ============================================================
class BiLSTMForSequenceLabeling(nn.Module):
    """
    Bidirectional LSTM para NER, POS tagging, etc.
    Cada timestep tiene contexto de izquierda Y derecha.
    """
    def __init__(self, vocab_size, embed_dim, hidden_size, num_tags):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(
            input_size=embed_dim,
            hidden_size=hidden_size,
            num_layers=2,
            batch_first=True,
            bidirectional=True,
            dropout=0.3
        )
        # +2 porque bidirectional: hidden_size * 2
        self.classifier = nn.Linear(hidden_size * 2, num_tags)
    
    def forward(self, x, mask=None):
        """
        x: (batch, seq_len) — token IDs
        mask: (batch, seq_len) — 1 para tokens válidos, 0 para padding
        """
        # Embedding
        embedded = self.embedding(x)  # (batch, seq_len, embed_dim)
        
        # LSTM — bidirectional
        lstm_out, (h_n, c_n) = self.lstm(embedded)
        # lstm_out: (batch, seq_len, hidden_size * 2)
        
        # Clasificar cada timestep
        logits = self.classifier(lstm_out)  # (batch, seq_len, num_tags)
        
        return logits

# 3. STACKED LSTM LAYERS (DEEP LSTM)
# ============================================================
class StackedLSTM(nn.Module):
    """
    Multiple LSTM layers apiladas.
    La salida de una capa es la entrada de la siguiente.
    """
    def __init__(self, input_size, hidden_size, num_layers, dropout=0.5):
        super().__init__()
        self.num_layers = num_layers
        
        self.lstm_layers = nn.ModuleList()
        for layer in range(num_layers):
            # Primera capa recibe input_size, capas siguientes reciben hidden_size
            lstm_input_size = input_size if layer == 0 else hidden_size
            self.lstm_layers.append(
                nn.LSTM(
                    input_size=lstm_input_size,
                    hidden_size=hidden_size,
                    num_layers=1,
                    batch_first=True,
                    dropout=dropout if layer < num_layers - 1 else 0
                )
            )
    
    def forward(self, x, hidden_states=None):
        """
        x: (batch, seq_len, input_size)
        hidden_states: opcional, tuple (h_0, c_0) para todas las capas
        """
        if hidden_states is None:
            hidden_states = [None] * self.num_layers
        
        outputs = [x]
        final_h, final_c = [], []
        
        for layer_idx, lstm in enumerate(self.lstm_layers):
            h_0, c_0 = hidden_states[layer_idx]
            
            # Si no se provee estado inicial, usar ceros
            if h_0 is None:
                h_0 = torch.zeros(1, x.size(0), lstm.hidden_size, device=x.device)
            if c_0 is None:
                c_0 = torch.zeros(1, x.size(0), lstm.hidden_size, device=x.device)
            
            lstm_out, (h_n, c_n) = lstm(outputs[-1], (h_0, c_0))
            outputs.append(lstm_out)
            final_h.append(h_n)
            final_c.append(c_n)
        
        return outputs[-1], (torch.stack(final_h), torch.stack(final_c))

# 4. GRADIENT FLOW EN LSTM — CELL STATE COMO "HIGHWAY"
# ============================================================
def visualize_gradient_flow_lstm():
    """
    Visualiza cómo el gradient fluye a través del cell state.
    El cell state es un "gradient highway" que permite skip-connections.
    """
    import numpy as np
    
    hidden_size = 50
    seq_len = 20
    steps = np.arange(seq_len)
    
    # Simular gradient decay a través del tiempo
    # En RNN vanilla: gradiente decae exponencialmente
    # En LSTM: gradiente se mantiene gracias al cell state
    
    vanilla_decay = 0.7 ** steps  # Decaimiento exponencial
    lstm_decay = np.exp(-0.05 * steps)  # Decaimiento mucho más lento
    
    plt.figure(figsize=(10, 6))
    plt.plot(steps, vanilla_decay, 'r-', linewidth=2, label='RNN Vanilla (decaye rápido)')
    plt.plot(steps, lstm_decay, 'b-', linewidth=2, label='LSTM (highway mantiene gradiente)')
    
    plt.xlabel('Timestep en la secuencia')
    plt.ylabel('Magnitud del gradiente (log scale)')
    plt.title('Gradient Flow: Cómo LSTM Evita Vanishing Gradients')
    plt.yscale('log')
    plt.legend()
    plt.grid(True, alpha=0.3)
    plt.tight_layout()
    plt.savefig('lstm_gradient_flow.png', dpi=150)
    plt.close()
    
    print("Gradient flow visualization guardado en lstm_gradient_flow.png")
    return 'lstm_gradient_flow.png'

# 5. LSTM PARA TEXT CLASSIFICATION
# ============================================================
class LSTMTextClassifier(nn.Module):
    """
    Clasificador de texto usando LSTM bidireccional.
    Usa el hidden state final como representación de la secuencia completa.
    """
    def __init__(self, vocab_size, embed_dim, hidden_size, num_classes, dropout=0.3):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.lstm = nn.LSTM(
            input_size=embed_dim,
            hidden_size=hidden_size,
            num_layers=2,
            batch_first=True,
            bidirectional=True,
            dropout=dropout
        )
        self.dropout = nn.Dropout(dropout)
        # Bidirectional: hidden_size * 2
        self.fc1 = nn.Linear(hidden_size * 2, hidden_size)
        self.fc2 = nn.Linear(hidden_size, num_classes)
        self.relu = nn.ReLU()
    
    def forward(self, x, lengths=None):
        """
        x: (batch, seq_len) — token IDs
        lengths: (batch,) — longitud real de cada secuencia (para packing)
        """
        embedded = self.embedding(x)  # (batch, seq_len, embed_dim)
        embedded = self.dropout(embedded)
        
        # Si tenemos lengths, podemos usar pack_packed_sequence para eficiencia
        if lengths is not None:
            # Ordenar por longitud (necesario para packed sequence)
            lengths_sorted, sorted_idx = lengths.sort(descending=True)
            embedded_sorted = embedded[sorted_idx]
            
            # Pack
            embedded_packed = nn.utils.rnn.pack_padded_sequence(
                embedded_sorted, 
                lengths_sorted.cpu(),
                batch_first=True,
                enforce_sorted=True
            )
            
            # LSTM
            lstm_out_packed, (h_n, c_n) = self.lstm(embedded_packed)
            
            # Unpack
            lstm_out, _ = nn.utils.rnn.pad_packed_sequence(
                lstm_out_packed, 
                batch_first=True,
                total_length=x.size(1)
            )
            
            # Desordenar para restaurar orden original
            _, unsort_idx = sorted_idx.sort()
            lstm_out = lstm_out[unsort_idx]
            h_n = h_n[:, unsort_idx, :]
        else:
            lstm_out, (h_n, c_n) = self.lstm(embedded)
        
        # Concatenar hidden states finales de ambas direcciones
        # h_n: (num_layers * num_directions, batch, hidden_size)
        # Para bidirectional: tomar última capa, ambas direcciones
        h_forward = h_n[-2]    # Forward hidden state, última capa
        h_backward = h_n[-1]   # Backward hidden state, última capa
        h_combined = torch.cat([h_forward, h_backward], dim=1)  # (batch, hidden*2)
        
        # Clasificación
        x = self.dropout(h_combined)
        x = self.relu(self.fc1(x))
        x = self.dropout(x)
        logits = self.fc2(x)
        
        return logits

# EJEMPLO COMPLETO: ENTRENAMIENTO LSTM PARA SENTIMENT
# ============================================================
def train_lstm_sentiment_demo():
    """
    Demo completo de entrenamiento LSTM para sentiment analysis.
    """
    from torch.utils.data import DataLoader, TensorDataset
    import torch.nn.functional as F
    
    # Config
    vocab_size = 5000
    embed_dim = 64
    hidden_size = 64
    num_classes = 2
    batch_size = 32
    epochs = 3
    
    # Modelo
    model = LSTMTextClassifier(vocab_size, embed_dim, hidden_size, num_classes)
    optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
    criterion = nn.CrossEntropyLoss()
    
    # Datos sintéticos
    X_train = torch.randint(1, vocab_size, (200, 50))
    y_train = torch.randint(0, 2, (200,))
    lengths_train = torch.randint(10, 50, (200,))
    
    dataset = TensorDataset(X_train, lengths_train, y_train)
    dataloader = DataLoader(dataset, batch_size=batch_size, shuffle=True)
    
    print(f"\n=== Entrenamiento LSTM Sentiment ===")
    model.train()
    
    for epoch in range(epochs):
        total_loss = 0
        correct = 0
        total = 0
        
        for batch_x, batch_lengths, batch_y in dataloader:
            optimizer.zero_grad()
            
            logits = model(batch_x, batch_lengths)
            loss = criterion(logits, batch_y)
            
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
            optimizer.step()
            
            total_loss += loss.item()
            _, predicted = logits.max(1)
            correct += (predicted == batch_y).sum().item()
            total += batch_y.size(0)
        
        avg_loss = total_loss / len(dataloader)
        accuracy = 100 * correct / total
        print(f"Epoch {epoch+1}/{epochs} - Loss: {avg_loss:.4f} - Acc: {accuracy:.2f}%")
    
    print("✅ Entrenamiento completado!")


train_lstm_sentiment_demo()

⚠️ Errores Comunes Y Cómo Evitarlos

❌ Error 1: Usar LSTM cuando un Transformer es mejor — sin sequential dependency real

El problema: LSTM procesa secuencias token por token (secuencialmente). Si tu tarea no requiere realmente capturar dependencias temporales/ordenas (ej: clasificación de documentos donde el orden no importa tanto, o cuando ya tienes embeddings que capturan todo el contexto), LSTM añade complejidad innecesaria y es más lento. Los Transformers paralelizan todo y típicamente superan a LSTM en estas tareas.

La solución: Pregúntate: ¿NECESITO realmente procesar la secuencia en orden? Si no, usa un Transformer o incluso una red fully connected sobre los embeddings:

# ❌ WRONG — usar LSTM para tareas sin dependencia secuencial real
class DocumentClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_size, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(embed_dim, hidden_size, batch_first=True)
        self.classifier = nn.Linear(hidden_size, num_classes)
    
    def forward(self, x):
        # LSTM innecesario si solo necesitamos mean pooling
        embedded = self.embedding(x).mean(dim=1)  # Promedio simple
        return self.classifier(embedded)

# ✅ CORRECTO — no LSTM si el orden no importa
class DocumentClassifierSimple(nn.Module):
    def __init__(self, vocab_size, embed_dim, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.classifier = nn.Linear(embed_dim, num_classes)
    
    def forward(self, x):
        # Mean pooling: el orden no importa para sentiment de documento
        embedded = self.embedding(x).mean(dim=1)
        return self.classifier(embedded)

❌ Error 2: Hidden state no se resetea entre secuencias diferentes — contaminación de contexto

El problema: Si procesas múltiples secuencias en un mismo forward pass sin reiniciar el hidden state, la primera secuencia "contamina" la representación de las siguientes. En tareas como NER donde cada documento es independiente, esto causa que predictions estén sesgadas por el documento anterior.

La solución: Resetea siempre el hidden state al inicio de cada nueva secuencia. En PyTorch, puedes pasar hidden_state=(h0, c0) inicializado en zeros a cada llamada del LSTM, o usa detach() en h y c si reutilizas:

# ❌ WRONG — hidden state se arrastra entre secuencias
model = LSTMTextClassifier(...)
for documents in dataloader:
    logits = model(documents)  # h0, c0 defaults a ceros la primera vez
    # La segunda vez SE ARRastra el hidden state de la primera!

# ✅ CORRECTO — resetear hidden state explícitamente
model = LSTMTextClassifier(...)
h0 = torch.zeros(2, batch_size, hidden_size)  # 2 layers, bidirectional
c0 = torch.zeros(2, batch_size, hidden_size)

for documents in dataloader:
    # Siempre iniciar desde cero
    logits, (h_n, c_n) = model.lstm(embedded, (h0, c0))
    # h_n y c_n ahora contienen el estado final, pero la próxima vez
    # volvemos a usar h0, c0 inicializados en zeros

❌ Error 3: Bidirectional LSTM en inference/autoregressive generation — causa data leakage

El problema: Bidirectional LSTM ve la secuencia COMPLETA durante el forward pass. En tareas de generación autoregresiva (traducción, resumen), esto es data leakage: el modelo puede "ver" la respuesta completa mientras genera, aprendiendo a copiar en lugar de predecir. En inference esto no aplica porque generas token por token, pero en entrenamiento causa que el modelo no aprenda correctamente a generar.

La solución: Para tareas generativas, usa LSTM unidireccional (forward only). Bidirectional es para tareas donde el input completo está disponible al momento de la predicción (NER, POS tagging, sentiment classification donde el documento completo se conoce):

# ❌ WRONG — bidirectional en tarea generativa
class Seq2SeqTranslator(nn.Module):
    def __init__(self, ...):
        self.encoder_lstm = nn.LSTM(..., bidirectional=True)  # VE TODO
        self.decoder_lstm = nn.LSTM(..., bidirectional=True)    # También ve todo!
        
    def forward(self, src, tgt):
        # Encoder ve el source completo
        encoder_out = self.encoder_lstm(src)
        # Decoder ve el target completo — LEAKAGE!
        decoder_out = self.decoder_lstm(tgt)


# ✅ CORRECTO — unidirectional para generación
class Seq2SeqTranslator(nn.Module):
    def __init__(self, ...):
        self.encoder_lstm = nn.LSTM(..., bidirectional=True)  # OK: encoder recibe input completo
        self.decoder_lstm = nn.LSTM(..., bidirectional=False)  # Solo forward: genera un token a la vez
        
    def forward(self, src, tgt):
        encoder_out = self.encoder_lstm(src)
        # Decoder forward-only: teacher forcing con tgt pero el modelo
        # aprende a predecir el siguiente token dado los anteriores
        decoder_out = self.decoder_lstm(tgt)

💡 Resumen

LSTM fue un avance fundamental que permitió entrenar RNNs profundas. Sus gates (forget, input, output) dan al modelo control sobre qué información recordar y olvidar, creando un "highway" (cell state) para que los gradientes fluyan sin decaer.

Lo critical en producción:

  1. Usa LSTM solo cuando hay sequential dependency real — si el orden no importa, un mean pooling o Transformer es mejor
  2. SIEMPRE resetea hidden state entre secuencias independientes — si no, contaminás el contexto
  3. Bidirectional para encoding (input conocido), unidirectional para decoding (generación) — mezcla correcta de direcciones

LSTM sigue siendo útil para:

  • Tareas con dependencias temporales reales (series de tiempo)
  • Cuando tenés constraints de memoria/commodity hardware
  • Modelos híbridos (LSTM + attention para reducir complejidad de Transformers)

Pero para la mayoría de tareas de NLP modernas, Transformers ganan. Conoce ambas herramientas y usá la correcta para el problema. Mañana vemos GRU, la alternativa más eficiente a LSTM. ¡Hasta entonces, parcero!
