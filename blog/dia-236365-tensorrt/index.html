Dia 236/365: TensorRT — El director de orquesta que reescribe tu modelo para el escenario de producción

24 de agosto de 2026
tensorrt

Introduccion: Cuando el modelo entrena fino pero la inferencia se arrastra

Tienes el modelo con 0.92 de F1 en el set de validación. Lo serviste con FastAPI y TorchServe, viste que en tu RTX 3090 corre a 38 ms por request, y pensaste que con un batch decente estaba listo. Llegas a producción, lo montas en una T4 del cloud, y la inferencia se te va a 140 ms por request. SLA en 100 ms. Incumplido. El cliente te escribe. Tu jefe te escribe. No hay fiesta.

El problema no es el modelo. El problema es que PyTorch o TensorFlow están diseñados para entrenar: grafos dinámicos, kernels genéricos, precisión FP32 por defecto, memoria sin compactar. Lo que necesitas en producción es un motor especializado para inferencia que ocupe menos memoria, haga menos accesos a global memory y use instrucciones nativas de la GPU que estás apuntando.

TensorRT es exactamente eso: un compilador y runtime de inferencia de NVIDIA que toma un modelo entrenado (ONNX, TF, PyTorch) y produce un engine optimizado para una GPU específica. La promesa concreta: 2x a 6x de speedup sobre PyTorch eager mode en inferencia, sin tocar el modelo. En este artículo te voy a mostrar la matemática detrás de por qué funciona, cómo se usa de verdad en producción, y los tres huecos donde te vas a tropezar si no lees el código.

1. Que es TensorRT? (Y por que deberia importarte)

1.1 La analogia cotidiana

Imagina un compositor que escribe una sinfonía para orquesta completa: 80 músicos, cuatro secciones, páginas y páginas de partitura. Ahora imagina que un director de orquesta recibe esa misma pieza y tiene que ejecutarla con un formato de cámara: 12 músicos. El director no se limita a borrar 68 pentagramas: re-escribe la obra. Fusiona voces que eran independientes en líneas melódicas únicas. Reescribe pasajes que dependían de la sección de cuerdas para que el cuarteto las absorba. Elimina dobles redondas que en el formato grande tenían sentido de respiracion pero ahora son lastre. El resultado no es "menos música": es la misma música en un formato distinto, optimizada para el escenario concreto donde va a sonar.

TensorRT es ese director. Tu modelo entrenado es la sinfonía completa. TensorRT toma el grafo de cómputo y lo reescribe: combina operaciones (kernel fusion), calibra precisión (FP32 a FP16 o INT8), reorganiza memoria para que los accesos sean coalescentes, y selecciona los kernels CUDA exactos para tu GPU. La función matemática $f_\theta(x)$ es la misma; el camino para evaluarla cambia.

1.2 La matematica formal

TensorRT resuelve un problema de optimización combinatoria sobre un grafo de cómputo. Sea $G = (V, E)$ el grafo de tu modelo, donde cada nodo $v_i \in V$ es un operador (Conv, MatMul, ReLU, BatchNorm) y cada arista $e_{ij} \in E$ es un tensor intermedio. El objetivo es encontrar un grafo equivalente $G' = (V', E')$, tal que:

$$\text{Latency}(G', x) \leq \text{Latency}(G, x) \quad \forall x \in \mathcal{X}$$

sujeta a restricciones de equivalencia numérica:

$$\|f_{G'}(x) - f_G(x)\|_2 \leq \epsilon \cdot \|f_G(x)\|_2$$

para alguna tolerancia $\epsilon$ (típicamente $10^{-3}$ para FP16, $10^{-2}$ para INT8).

Las transformaciones que TensorRT aplica se formalizan así:

Layer fusion (Conv-BN-ReLU): El caso más común. Sea la composición:

$$y = \text{ReLU}\left(\gamma \cdot \frac{W * x - \mu}{\sqrt{\sigma^2 + \epsilon_{bn}}} + \beta\right)$$

Esto equivale a una sola convolución con pesos y bias re-parametrizados:

$$W' = \frac{\gamma}{\sqrt{\sigma^2 + \epsilon_{bn}}} \cdot W, \quad b' = \beta - \frac{\gamma \cdot \mu}{\sqrt{\sigma^2 + \epsilon_{bn}}}$$ $$y = \text{ReLU}(W' * x + b')$$

Resultado: 3 kernels se vuelven 1 kernel, 3 accesos a memoria global se vuelven 1. En una ResNet-50 eso elimina ~140 nodos del grafo.

Cuantización INT8 (asimétrica, por tensor o por canal): Para cada tensor, se calcula una escala $s$ y un cero $z$:

$$s = \frac{x_{\max} - x_{\min}}{255}, \quad z = \text{round}\left(-\frac{x_{\min}}{s}\right)$$

La conversión forward es:

$$x_q = \text{clip}\left(\text{round}\left(\frac{x}{s} + z\right), 0, 255\right)$$

La dequantización para cómputo es:

$$\hat{x} = s \cdot (x_q - z) \approx x$$

El error relativo esperado, asumiendo distribución uniforme y redondeo estocástico, es:

$$E\left[\frac{|\hat{x} - x|}{|x|}\right] \approx \frac{s}{2 \cdot |x|}$$

Para tensores con $|x| \gg s$, el error se vuelve despreciable. Por eso la calibración (elegir $s$ correctamente con datos representativos) es el paso crítico en INT8.

Kernel auto-tuning: TensorRT mide tiempos de múltiples implementaciones candidatas para cada operador en tu GPU específica y selecciona la más rápida. Esto explota el hecho de que el espacio de búsqueda es enorme: una convolución 3x3 con padding=1 tiene ~10 variantes (Winograd, FFT, implicit GEMM, direct) y el óptimo depende del shape concreto.

El pipeline completo es:

   │  │          │ │  Tuning  │ │   Opt.   │ │
   │  └──────────┘ └──────────┘ └──────────┘ │

   │  .engine / .plan │  (binario serializado)
   └──────────────────┘
            │
            ▼
   ┌──────────────────┐
   │ TensorRT Runtime │
   │  (en GPU target) │
   └──────────────────┘

El Builder es la pieza pesada: recibe el grafo, aplica las optimizaciones, prueba kernels, calibra si es INT8, y produce un engine serializado. El Runtime es liviano: carga el engine, crea execution contexts, y corre inferencia. Esa separación es intencional: la construcción puede tardar minutos; la ejecución, microsegundos.

Tres optimizaciones merecen detalle:

  1. Constant folding: subgrafos con inputs conocidos (por ejemplo, un embedding table cargado en el engine) se evalúan en build-time y desaparecen del grafo de inferencia. Si tienes un lookup table de 50 MB, no la copias a la GPU en cada request.
  1. Dynamic tensor memory reuse: TensorRT asigna memoria a tensores intermedios usando un algoritmo de coloreado de grafos. Dos tensores que no están vivos al mismo tiempo comparten el mismo buffer. En una CNN profunda esto reduce el pico de memoria en 30-50%.
  1. Layer fusion con multi-stream: algunas fusiones (Conv + Add + ReLU) permiten emitir resultados a múltiples streams CUDA en paralelo sin barriers explícitos.

3. TensorRT: Uso Directo y Casos de Control Fino

TensorRT tiene tres niveles de control:

  • trtexec (CLI): convierte ONNX a engine con flags. Útil para CI/CD y para verificar que un modelo compila. NO para uso programático serio.
  • API Python (tensorrt package): el camino estándar. Builder, Network, BuilderConfig, Engine, Runtime, ExecutionContext. Te da control fino sobre el grafo y la calibración.
  • API C++: máxima performance y control, pero ciclo de desarrollo más lento. Útil cuando embebes TensorRT en un servicio C++ existente.

Cuándo usar cada uno:

Caso Herramienta
Probar si un modelo compila en CI trtexec
Exportar un modelo estándar (YOLO, BERT) trtexec o API Python
Modelo con custom ops o calibración INT8 no trivial API Python
Servicio de inferencia de ultra-baja latencia en C++ API C++
Servir múltiples modelos con batching dinámico Triton Inference Server (envuelve TensorRT)

El error más común es usar trtexec en producción para "ahorrar código". trtexec no te da logging estructurado, ni manejo de errores robusto, ni la capacidad de cambiar dinámicamente el engine. Para producción, API Python con tu propio wrapper (que es lo que muestro abajo).

4.2 El motor principal

# trt_inference.py
from pathlib import Path
from typing import Dict, List
import numpy as np
import tensorrt as trt
import pycuda.driver as cuda
import pycuda.autoinit  # noqa: F401  inicializa contexto CUDA

from trt_types import TRTConfig, BindingInfo, Precision


TRT_LOGGER = trt.Logger(trt.Logger.WARNING)


class TRTEngineError(RuntimeError):
    """Errores especificos del motor TensorRT."""


class TensorRTInference:
    """
    Wrapper production-grade sobre TensorRT runtime.

    Ciclo de vida:
        engine = TensorRTInference("modelo.engine")
        output = engine.infer(input_batch)
    """

    def __init__(self, engine_path: Path | str, stream: cuda.Stream = None):
        self.engine_path = Path(engine_path)
        if not self.engine_path.exists():
            raise TRTEngineError(f"Engine no encontrado: {self.engine_path}")

        self.logger = TRT_LOGGER
        self.engine = self._load_engine()
        self.context = self.engine.create_execution_context()
        self.stream = stream or cuda.Stream()

        self.bindings: List[BindingInfo] = []
        self._allocate_buffers()

    def _load_engine(self) -> trt.ICudaEngine:
        """Deserializa el engine binario."""
        with open(self.engine_path, "rb") as f:
            engine_bytes = f.read()
        runtime = trt.Runtime(self.logger)
        engine = runtime.deserialize_cuda_engine(engine_bytes)
        if engine is None:
            raise TRTEngineError(
                f"deserialize_cuda_engine devolvio None. "
                f"Verifica que el engine fue construido para esta version de TensorRT "
                f"y esta GPU (compute capability)."
            )
        return engine

    def _allocate_buffers(self) -> None:
        """Asigna memoria host (pagelocked) y device para cada binding."""
        for i in range(self.engine.num_bindings):
            name = self.engine.get_binding_name(i)
            shape = self.engine.get_binding_shape(i)
            dtype = trt.nptype(self.engine.get_binding_dtype(i))

            # Reemplazar -1 (dynamic) por el batch default si existe
            concrete_shape = tuple(s if s > 0 else 1 for s in shape)
            size = int(np.prod(concrete_shape))

            host_mem = cuda.pagelocked_empty(size, dtype)
            device_mem = cuda.mem_alloc(host_mem.nbytes)

            self.bindings.append(BindingInfo(
                name=name,
                shape=concrete_shape,
                dtype=dtype,
                is_input=self.engine.binding_is_input(i),
                device_ptr=int(device_mem),
                host_buffer=host_mem,
            ))

    def set_dynamic_input_shape(self, binding_name: str, shape: tuple) -> None:
        """Configura shape de entrada para engines con dynamic shapes."""
        if not self.context.set_input_shape(binding_name, shape):
            raise TRTEngineError(
                f"set_input_shape fallo para {binding_name}={shape}. "
                f"Verifica que el engine fue construido con optimization profile "
                f"compatible (min <= shape <= max)."
            )

    def infer(self, inputs: Dict[str, np.ndarray]) -> Dict[str, np.ndarray]:
        """
        Corre inferencia asincrona sobre el engine.

        Args:
            inputs: dict {binding_name: numpy_array} con datos en CPU.

        Returns:
            dict {binding_name: numpy_array} con outputs en CPU.

        Verificacion numerica en comentarios:
            - Pre-copia: validamos contigüidad y dtype contra el binding.
            - Post-inferencia: verificamos que no haya NaN/Inf en outputs.
        """
        # Copiar inputs a memoria pagelocked y luego device
        for binding in self.bindings:
            if not binding.is_input:
                continue
            if binding.name not in inputs:
                raise TRTEngineError(f"Falta input requerido: {binding.name}")

            host_in = inputs[binding.name]
            # VERIFICACION: dtype y contigüidad
            if host_in.dtype != binding.dtype:
                host_in = host_in.astype(binding.dtype)
            if not host_in.flags["C_CONTIGUOUS"]:
                host_in = np.ascontiguousarray(host_in)

            expected_size = int(np.prod(binding.shape))
            if host_in.size != expected_size:
                raise TRTEngineError(
                    f"Tamano incorrecto para {binding.name}: "
                    f"esperado {expected_size}, recibido {host_in.size}"
                )

            np.copyto(binding.host_buffer, host_in.ravel())
            cuda.memcpy_htod_async(
                binding.device_ptr,
                binding.host_buffer,
                self.stream,
            )

        # Ejecutar
        bindings_ptrs = [b.device_ptr for b in self.bindings]
        self.context.execute_async_v2(
            bindings=bindings_ptrs,
            stream_handle=self.stream.handle,
        )

        # Copiar outputs de device a host
        outputs: Dict[str, np.ndarray] = {}
        for binding in self.bindings:
            if binding.is_input:
                continue
            cuda.memcpy_dtoh_async(
                binding.host_buffer,
                binding.device_ptr,
                self.stream,
            )
            outputs[binding.name] = binding.host_buffer.copy()

        self.stream.synchronize()

        # VERIFICACION: NaN/Inf en outputs
        for name, arr in outputs.items():
            if not np.isfinite(arr).all():
                raise TRTEngineError(
                    f"Output '{name}' contiene NaN o Inf. "
                    f"Sospechar: calibracion INT8 defectuosa, overflow en FP16, "
                    f"o input fuera de distribucion."
                )

        return outputs

    @property
    def num_inputs(self) -> int:
        return sum(1 for b in self.bindings if b.is_input)

    @property
    def num_outputs(self) -> int:
        return sum(1 for b in self.bindings if not b.is_input)

4.3 Utilidades de análisis y verificación

# trt_utils.py
import time
from pathlib import Path
from typing import Dict, List, Tuple

import numpy as np
import onnx
import tensorrt as trt
import torch

from trt_inference import TensorRTInference
from trt_types import TRTConfig, Precision


def build_engine_from_onnx(
    onnx_path: Path,
    config: TRTConfig,
    calibrator=None,
) -> bytes:
    """
    Construye un engine TensorRT desde un modelo ONNX.

    Args:
        onnx_path: ruta al .onnx exportado.
        config: configuracion del builder.
        calibrator: instancia de trt.IInt8Calibrator (solo para INT8).
                    Implementacion concreta: ver Caso 1 abajo.
    Returns:
        bytes del engine serializado, listo para escribir a disco.
    """
    # VERIFICACION: el modelo ONNX es valido antes de intentar compilar
    onnx_model = onnx.load(str(onnx_path))
    onnx.checker.check_model(onnx_model)

    explicit_batch = 1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH)
    builder = trt.Builder(TRT_LOGGER)
    network = builder.create_network(explicit_batch)
    parser = trt.OnnxParser(network, TRT_LOGGER)

    with open(onnx_path, "rb") as f:
        if not parser.parse(f.read()):
            errors = [parser.get_error(i) for i in range(parser.num_errors)]
            raise RuntimeError(f"Fallo parsing ONNX: {errors}")

    builder_config = builder.create_builder_config()
    builder_config.max_workspace_size = config.max_workspace_size_gb * (1 << 30)

    if config.precision == Precision.FP16:
        builder_config.set_flag(trt.BuilderFlag.FP16)
    elif config.precision == Precision.INT8:
        if calibrator is None:
            raise ValueError("INT8 requiere calibrator")
        builder_config.set_flag(trt.BuilderFlag.INT8)
        builder_config.int8_calibrator = calibrator

    if config.strict_types:
        builder_config.set_flag(trt.BuilderFlag.STRICT_TYPES)

    if config.timing_cache_path and config.timing_cache_path.exists():
        with open(config.timing_cache_path, "rb") as f:
            builder_config.set_timing_cache(f.read(), ignore_mismatch=False)

    engine = builder.build_engine(network, builder_config)
    if engine is None:
        raise RuntimeError("builder.build_engine devolvio None")

    serialized = engine.serialize()
    if serialized is None:
        raise RuntimeError("engine.serialize() devolvio None")

    # Persistir timing cache para acelerar futuros builds
    timing_cache = builder_config.get_timing_cache()
    if config.timing_cache_path and timing_cache:
        with open(config.timing_cache_path, "wb") as f:
            f.write(timing_cache.serialize())

    return serialized


def benchmark_engine(
    engine: TensorRTInference,
    sample_input: Dict[str, np.ndarray],
    n_warmup: int = 50,
    n_iter: int = 500,
) -> Dict[str, float]:
    """Mide latencia p50, p95, p99 y throughput en samples/segundo."""
    # Calentamiento: descarta las primeras iteraciones (compilacion JIT, caches)
    for _ in range(n_warmup):
        engine.infer(sample_input)

    latencies_ms: List[float] = []
    start_total = time.perf_counter()
    for _ in range(n_iter):
        t0 = time.perf_counter()
        engine.infer(sample_input)
        t1 = time.perf_counter()
        latencies_ms.append((t1 - t0) * 1000.0)
    elapsed_total = time.perf_counter() - start_total

    latencies_ms.sort()
    batch_size = next(iter(sample_input.values())).shape[0]

    return {
        "p50_ms": latencies_ms[int(0.50 * n_iter)],
        "p95_ms": latencies_ms[int(0.95 * n_iter)],
        "p99_ms": latencies_ms[int(0.99 * n_iter)],
        "mean_ms": float(np.mean(latencies_ms)),
        "throughput_samples_per_s": (n_iter * batch_size) / elapsed_total,
    }


def compare_pytorch_vs_trt(
    torch_model: torch.nn.Module,
    trt_engine: TensorRTInference,
    sample_input: np.ndarray,
    atol: float = 1e-3,
    rtol: float = 1e-3,
) -> Tuple[float, float, float]:
    """
    Compara outputs del modelo PyTorch vs el engine TensorRT.
    Retorna (max_abs_diff, max_rel_diff, cosine_sim).
    """
    torch_model.eval()
    with torch.no_grad():
        torch_out = torch_model(torch.from_numpy(sample_input)).cpu().numpy()

    trt_out = trt_engine.infer({"input": sample_input})
    trt_arr = next(iter(trt_out.values()))

    # VERIFICACION NUMERICA: tres metricas complementarias
    max_abs = float(np.max(np.abs(torch_out - trt_arr)))
    max_rel = float(np.max(np.abs(torch_out - trt_arr) / (np.abs(torch_out) + 1e-8)))
    cos_sim = float(
        np.dot(torch_out.ravel(), trt_arr.ravel())
        / (np.linalg.norm(torch_out.ravel()) * np.linalg.norm(trt_arr.ravel()) + 1e-8)
    )

    if max_abs > atol and cos_sim < (1.0 - rtol):
        raise AssertionError(
            f"Divergencia significativa: max_abs={max_abs:.4e}, cos_sim={cos_sim:.6f}"
        )

    return max_abs, max_rel, cos_sim

5. Ejemplos de Uso en Casos Reales

Caso 1: BERT-base para clasificación de texto con INT8

# case_bert_int8.py
from pathlib import Path
import numpy as np
import tensorrt as trt

from trt_types import TRTConfig, Precision
from trt_inference import TensorRTInference
from trt_utils import build_engine_from_onnx, benchmark_engine, compare_pytorch_vs_trt


class TextCalibrator(trt.IInt8LegacyCalibrator):
    """
    Calibrador INT8 para inputs de texto tokenizado.

    Requiere ~512 muestras representativas para calibrar escalas establemente.
    Menos de 100 muestras produce escalas ruidosas que degradan accuracy.
    """

    def __init__(self, calib_data: np.ndarray, cache_file: Path, batch_size: int = 64):
        trt.IInt8LegacyCalibrator.__init__(self)
        import pycuda.driver as cuda

        self.cache_file = cache_file
        self.batch_size = batch_size
        self.data = calib_data
        self.current_index = 0
        self.device_input = cuda.mem_alloc(
            self.data[0].nbytes * self.batch_size
        )

    def get_batch_size(self) -> int:
        return self.batch_size

    def get_batch(self, names):
        import pycuda.driver as cuda
        if self.current_index + self.batch_size > len(self.data):
            return None
        batch = self.data[self.current_index : self.current_index + self.batch_size]
        batch = np.ascontiguousarray(batch, dtype=np.int32)
        cuda.memcpy_htod(self.device_input, batch)
        self.current_index += self.batch_size
        return [int(self.device_input)]

    def read_calibration_cache(self) -> bytes:
        if self.cache_file.exists():
            return self.cache_file.read_bytes()
        return None

    def write_calibration_cache(self, cache) -> None:
        self.cache_file.write_bytes(cache)


def build_bert_int8_engine(onnx_path: Path, calib_tokens: np.ndarray):
    """BERT INT8: ~4x compresion vs FP32, ~2-3x speedup en T4."""
    calibrator = TextCalibrator(
        calib_data=calib_tokens,
        cache_file=Path("bert_int8.cache"),
        batch_size=64,
    )
    config = TRTConfig(
        precision=Precision.INT8,
        max_batch_size=64,
        max_workspace_size_gb=4,
        calibration_cache_path=Path("bert_int8.cache"),
    )
    return build_engine_from_onnx(onnx_path, config, calibrator=calibrator)

def export_yolov8_engine(weights: str = "yolov8n.pt") -> Path:
    """
    Exporta YOLOv8 a engine FP16.

    La opcion mas simple para modelos estandar: usar la exportacion de

    ONNX -> TensorRT mostrado arriba.

    model.export(format="engine", half=True, device=0, simplify=True)
    return Path(weights).with_suffix(".engine")


# Latencias tipicas en T4 (batch=1, 640x640):
#   PyTorch FP32: ~25 ms
#   PyTorch FP16: ~15 ms
#   TensorRT FP16: ~7 ms (speedup ~3.5x vs PyTorch FP32)
#   TensorRT INT8: ~4 ms (speedup ~6x)

Caso 3: LLM (Llama-3 8B) con kernel fusion y KV-cache estático

Para LLMs, TensorRT-LLM (librería separada) aplica las mismas ideas pero con optimización específica para attention: PagedAttention, in-flight batching, kernel fusion de QKV projections. El principio es el mismo que TensorRT clásico; el caso de uso típico es servir un LLM en Triton Inference Server con continuous batching. Latencia esperada en H100: 30-50 ms para tokens de salida en Llama-3 8B con batch=8.

6. Debugging: Cuando Todo se Va a la Mierda

Problema 1: NaN en outputs después de INT8

Síntoma: el engine compila, pero engine.infer(...) levanta TRTEngineError: Output 'logits' contiene NaN.

Causa: el calibrador no vio datos representativos. Las escalas $s$ son muy pequeñas y el redondeo a INT8 satura los tensores.

Detección:

# debug_calib_nan.py
def debug_calibration_scales(engine_path: Path):
    """Si TensorRT fue construido con --dump_timing, podemos inspeccionar
    las escalas por tensor. Alternativamente, usar trtexec --verbose."""
    import subprocess
    result = subprocess.run(
        ["trtexec", "--loadEngine", str(engine_path), "--verbose"],
        capture_output=True, text=True,
    )
    # Buscar lineas como: "Layer (Unnamed Layer* 45) [Convolution] ... scales: 0.0023"
    for line in result.stdout.splitlines():
        if "scales:" in line.lower() and ("0.0" in line or "1e-" in line):
            print(f"POSIBLE ESCALA PROBLEMÁTICA: {line}")

Soluciones (probar en orden):

  1. Aumentar el set de calibración a 1000+ muestras con la distribución real.
  2. Activar trt.BuilderFlag.STRICT_TYPES para forzar INT8 en capas que FP16 preferiría.
  3. Usar trt.CalibrationAlgoType.MINMAX_CALIBRATION en lugar de ENTROPY_CALIBRATION_2 si las distribuciones tienen outliers fuertes.
  4. Si todo falla, degradar a FP16 — sigue dando ~2x speedup sin riesgo numérico.

Problema 2: Shape mismatch en dynamic shapes

Síntoma: TRTEngineError: set_input_shape fallo para input_ids=(1, 512).

Causa: el engine se construyó con optimization profile min=(1,128), opt=(8,256), max=(32,512) y estás pasando (1, 512) que viola el máximo de la segunda dimensión.

Detección:

# debug_shapes.py
def validate_input_shape(engine: TensorRTInference, binding_name: str, shape: tuple) -> bool:
    """Consulta el profile de optimization del engine."""
    profile = engine.engine.get_profile_shape(binding_name, 0)  # 0 = primer profile
    if profile is None:
        return False
    min_shape, opt_shape, max_shape = profile
    in_range = all(
        min_shape[i] <= shape[i] <= max_shape[i]
        for i in range(len(shape))
    )
    if not in_range:
        print(f"Shape {shape} fuera de rango. "
              f"min={min_shape}, opt={opt_shape}, max={max_shape}")
    return in_range

Soluciones:

  1. Definir min, opt, max cubriendo tu rango real con holgura.
  2. Si tus inputs varían mucho, construir múltiples engines (uno por rango).
  3. Pad/truncar inputs al opt_shape para máxima eficiencia.

Problema 3: Engine no portable entre GPUs

Síntoma: engine construido en A100 falla al cargarlo en T4. deserialize_cuda_engine devuelve None.

Causa: TensorRT compila kernels específicos para la compute capability de la GPU de build (A100 = 8.0, T4 = 7.5). Un engine de A100 contiene SASS para sm_80, no ejecutable en sm_75.

Soluciones:

  1. Build por target: construir un engine por cada compute capability de tu fleet. En CI, compilar en una máquina con cada GPU objetivo.
  2. Pre-built engines + docker: distribuir el engine dentro del contenedor de despliegue. Si la imagen Docker usa nvidia/cuda con la misma versión de TensorRT que se construyó, evita drift.
  3. DLA (Deep Learning Accelerator): en Jetson y algunas GPUs, parte del grafo puede caer a DLA para ahorrar energía. Engines DLA son incluso más restrictivos en portabilidad.

Regla de oro: nunca hagas git push de un .engine al repo. El engine es un artefacto de build, versionado por GPU + versión de TensorRT + hash del ONNX.

7. Optimizaciones de Produccion

Optimización 1: Triton Inference Server + Dynamic Batching

tritonserver envuelve TensorRT y agrega dynamic batching automático: si llegan 8 requests en una ventana de 5 ms, las fusiona en un solo batch al engine. El throughput mejora 3-5x en LLMs y 2-3x en CNNs. La latencia individual p99 sube ~10 ms (esperar la ventana) pero el throughput compensa.

Optimización 2: CUDA Graphs para inferencia repetitiva

Si tu workload es "mismo shape, muchos requests" (típico en serving), capturar el grafo CUDA una vez y re-ejecutarlo elimina ~100 microsegundos de overhead por request por concepto de launch de kernels.

# cuda_graph_optimization.py
import numpy as np
import pycuda.driver as cuda
from trt_inference import TensorRTInference


class GraphedInference:
    """Captura el flujo de inferencia como CUDA Graph para re-ejecucion O(1)."""

    def __init__(self, engine: TensorRTInference, sample_input: np.ndarray):
        self.engine = engine
        self.sample_input = sample_input

        # Warmup obligatorio antes de capturar
        for _ in range(3):
            engine.infer({"input": sample_input})

        self.graph = cuda.Graph()
        self.graph_exec = None
        self._capture(sample_input)

    def _capture(self, sample_input: np.ndarray) -> None:
        # VERIFICACION: el stream debe estar en modo capture
        self.engine.stream.begin_capture()
        self.engine.infer({"input": sample_input})
        self.graph = self.engine.stream.end_capture()
        self.graph_exec = cuda.GraphExec(self.graph)

    def infer(self, input_data: np.ndarray) -> np.ndarray:
        # Copiar input al buffer existente
        np.copyto(
            self.engine.bindings[0].host_buffer,
            input_data.ravel(),
        )
        cuda.memcpy_htod_async(
            self.engine.bindings[0].device_ptr,
            self.engine.bindings[0].host_buffer,
            self.engine.stream,
        )
        # Re-ejecutar el grafo capturado
        self.graph_exec.launch(self.engine.stream)
        # Copiar output de vuelta
        cuda.memcpy_dtoh_async(
            self.engine.bindings[-1].host_buffer,
            self.engine.bindings[-1].device_ptr,
            self.engine.stream,
        )
        self.engine.stream.synchronize()
        return self.engine.bindings[-1].host_buffer.copy()

Trade-off: CUDA Graphs requiere que el shape del input sea idéntico entre llamadas. Si tus requests tienen shapes variables, esta optimización no aplica directamente (o necesitas un graph por shape frecuente).

8. Conclusion: Por Que Esto te Salva el Pellejo en Produccion

Si llegaste hasta aquí, esto es lo que te llevas:

  • TensorRT no es un conversor mágico: es un compilador que aplica optimización combinatoria sobre el grafo de tu modelo, con fundamento matemático claro (layer fusion algebraica, cuantización por escalas, kernel auto-tuning).
  • El 80% del beneficio viene de FP16, no de INT8. Si tu SLA es flexible, quédate en FP16 y duerme tranquilo. INT8 exige calibración robusta o te explota en producción.
  • Engine != modelo. Un engine es un binario ligado a una GPU específica y versión de TensorRT. Trátalo como artefacto de build, no como código.
  • La calibración es donde mueres en INT8. Más datos representativos, scales validadas, y nunca saltes el paso de comparar outputs FP32 vs INT8 antes de producción.

Mini-checklist antes de desplegar:

# checklist_trt.py
def pre_deploy_checklist(engine_path: Path, pytorch_model, calib_data: np.ndarray):
    """Corre esto antes de cada despliegue a produccion."""

    engine = TensorRTInference(engine_path)

    # 1. Verificar shapes y dtypes
    assert engine.num_inputs > 0, "Engine sin inputs?"
    assert engine.num_outputs > 0, "Engine sin outputs?"

    # 2. Comparar numericamente contra PyTorch
    abs_diff, rel_diff, cos_sim = compare_pytorch_vs_trt(
        pytorch_model, engine, calib_data, atol=1e-2, rtol=1e-2
    )
    assert cos_sim > 0.99, f"cosine_sim={cos_sim:.4f} bajo threshold"

    # 3. Medir latencia bajo carga
    metrics = benchmark_engine(engine, {"input": calib_data[:32]})
    assert metrics["p99_ms"] < 100.0, f"p99={metrics['p99_ms']:.1f}ms excede SLA"

    # 4. Verificar que no hay NaN/Inf (chequeo ya en infer, pero explicito)
    out = engine.infer({"input": calib_data[:1]})
    for arr in out.values():
        assert np.isfinite(arr).all()

    print(f"DEPLOY OK: p99={metrics['p99_ms']:.2f}ms, cos_sim={cos_sim:.6f}")
