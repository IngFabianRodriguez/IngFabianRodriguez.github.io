La Matematica de Information Retrieval con LLMs

Information Retrieval con LLMs se diferencia del search tradicional porque el LLM puede reformular queries, expandir conceptos, y entender intencion. La query original Q se transforma en Q' mediante el LLM:

Q' = LLM_expand(Q) = {q1, q2, ..., qn} donde cada qi es una reformulacion

El retrieval se hace sobre todas las Q' y los scores se fusionan. Esto mejora recall significativamente porque diferentes reformulaciones capturan diferentes aspectos del significado.

La metrica clave es Recall@K: de todos los documentos relevantes, cuantas encontramos en los primeros K. Para RAG efectivo, queremos Recall@50 > 0.85.

Framework de Retrieval con Query Expansion

from openai import OpenAI
from rank_bm25 import BM25Okapi
import numpy as np

client = OpenAI()

class QueryExpansionRetriever:
    """
    Retrieval con query expansion usando LLM.
    El LLM genera multiples reformulaciones de la query
    para capturar diferentes aspectos del significado.
    """
    
    def __init__(self, documents, embedder, alpha=0.5):
        self.documents = documents
        self.embedder = embedder  # Funcion que devuelve embeddings
        self.alpha = alpha  # Peso para hybrid search
        
        # BM25 para retrieval lexico
        self.tokenized_docs = [doc.lower().split() for doc in documents]
        self.bm25 = BM25Okapi(self.tokenized_docs)
        
    def expand_query(self, query, n_expansions=4):
        """
        Genera n_expansions reformulaciones de la query original.
        """
        prompt = f"""Given the following query, generate {n_expansions} different 
        reformulations that capture different aspects or interpretations.
        Return them as a JSON array of strings.
        
        Query: {query}
        
        Reformulations:"""
        
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            response_format={"type": "json_object"},
            temperature=0.8
        )
        
        import json
        expansions = json.loads(response.choices[0].message.content)
        return list(expansions.values())[:n_expansions]
    
    def vector_search(self, query, top_k=50):
        """Busqueda por embeddings."""
        query_emb = self.embedder(query)
        doc_embs = self.embedder(self.documents)
        
        # Similitud coseno
        scores = np.dot(doc_embs, query_emb) / (
            np.linalg.norm(doc_embs, axis=1) * np.linalg.norm(query_emb)
        )
        
        top_indices = np.argsort(scores)[::-1][:top_k]
        return [(idx, float(scores[idx])) for idx in top_indices]
    
    def lexical_search(self, query, top_k=50):
        """Busqueda BM25."""
        tokenized = query.lower().split()
        scores = self.bm25.get_scores(tokenized)
        top_indices = np.argsort(scores)[::-1][:top_k]
        return [(idx, float(scores[idx])) for idx in top_indices]
    
    def search(self, query, top_k=20):
        """
        Busqueda con query expansion: 
        1. Expandir query original
        2. Retrieval para cada expansion
        3. Fusionar scores
        """
        # Expandir query
        expansions = self.expand_query(query)
        all_queries = [query] + expansions
        
        # Fusionar resultados de todas las queries
        fused_scores = {}
        
        for q in all_queries:
            # Vector search
            vector_results = self.vector_search(q, top_k=top_k)
            for rank, (idx, score) in enumerate(vector_results):
                fused_scores[idx] = fused_scores.get(idx, 0) + score / (rank + 1)
            
            # Lexical search
            lexical_results = self.lexical_search(q, top_k=top_k)
            for rank, (idx, score) in enumerate(lexical_results):
                fused_scores[idx] = fused_scores.get(idx, 0) + self.alpha * score / (rank + 1)
        
        # Ordenar por score fusionado
        ranked = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        
        return [
            {"document": self.documents[idx], "score": score}
            for idx, score in ranked[:top_k]
        ]

# Uso:
documents = ["texto1", "texto2", ...]  # Tus documentos
embedder = lambda texts: np.array([...])  # Tu embedder

retriever = QueryExpansionRetriever(documents, embedder)
results = retriever.search("optimizacion de queries PostgreSQL", top_k=10)

Multi-Method Retrieval: No Confies en Solo Uno

El error del 60%: usar solo embeddings o solo BM25. La realidad: diferentes methods rinden mejor para diferentes queries. La solucion: multi-method retrieval con learned fusion.

class MultiMethodRetriever:
    """
    Combina multiples metodos de retrieval:
    - Dense (embeddings)
    - Sparse (BM25)
    - Hybrid (combinacion)
    - Keyword matching
    """
    
    def __init__(self, documents):
        self.documents = documents
        self.dense_retriever = None  # Embeddings
        self.sparse_retriever = None  # BM25
        self.keyword_index = {}  # Indice keyword simple
        
    def add_dense_retriever(self, embedder):
        self.dense_retriever = embedder
        
    def add_sparse_retriever(self, bm25):
        self.sparse_retriever = bm25
        
    def build_keyword_index(self):
        """Indice keyword simple para terminos exactos."""
        for idx, doc in enumerate(self.documents):
            words = doc.lower().split()
            for word in words:
                if word not in self.keyword_index:
                    self.keyword_index[word] = []
                self.keyword_index[word].append(idx)
    
    def keyword_search(self, query, top_k=50):
        """Busqueda por palabras clave exactas."""
        words = query.lower().split()
        scores = {}
        
        for word in words:
            if word in self.keyword_index:
                for idx in self.keyword_index[word]:
                    scores[idx] = scores.get(idx, 0) + 1
        
        ranked = sorted(scores.items(), key=lambda x: x[1], reverse=True)
        return [(idx, score) for idx, score in ranked[:top_k]]
    
    def search(self, query, top_k=20, method_weights=None):
        """
        Retrieval con weights aprendidos para cada metodo.
        """
        if method_weights is None:
            method_weights = {"dense": 0.4, "sparse": 0.3, "keyword": 0.3}
        
        fused_scores = {}
        
        # Dense retrieval
        if self.dense_retriever:
            results = self.dense_retriever(query, top_k=top_k)
            for rank, (idx, score) in enumerate(results):
                fused_scores[idx] = fused_scores.get(idx, 0) + \
                    method_weights["dense"] * score / np.log(rank + 2)
        
        # Sparse retrieval
        if self.sparse_retriever:
            results = self.sparse_retriever.search(query, top_k=top_k)
            for rank, (idx, score) in enumerate(results):
                fused_scores[idx] = fused_scores.get(idx, 0) + \
                    method_weights["sparse"] * score / np.log(rank + 2)
        
        # Keyword search
        results = self.keyword_search(query, top_k=top_k)
        for rank, (idx, score) in enumerate(results):
            fused_scores[idx] = fused_scores.get(idx, 0) + \
                method_weights["keyword"] * score / np.log(rank + 2)
        
        # Ordenar
        ranked = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        
        return [
            {"document": self.documents[idx], "score": score}
            for idx, score in ranked[:top_k]
        ]

# Uso:
multi = MultiMethodRetriever(documents)
multi.add_dense_retriever(dense_embedder)
multi.add_sparse_retriever(bm25)
multi.build_keyword_index()

results = multi.search("PostgreSQL query optimization", top_k=10)

Fusion Strategies: Como Combinar Scores

Hay varias formas de fusionar scores de multiples retrieval methods. La mas robusta: Reciprocal Rank Fusion (RRF) y CombMNZ.

def reciprocal_rank_fusion(results_lists, k=60):
    """
    Reciprocal Rank Fusion: combina rankings multiplicando por 1/(k+rank).
    
    k=60 es el estandar (constante de suavizado).
    """
    fused = {}
    
    for results in results_lists:
        for rank, result in enumerate(results):
            doc_id = result["document"]
            score = 1 / (k + rank + 1)
            fused[doc_id] = fused.get(doc_id, 0) + score
    
    return sorted(fused.items(), key=lambda x: x[1], reverse=True)

def distribution_based_fusion(results_lists):
    """
    Distribution-Based Score Fusion (DBSF):
    Convierte scores a percentiles y promedia.
    Robusto a outliers en scores.
    """
    all_scores = []
    doc_scores = {}
    
    for results in results_lists:
        scores = [r["score"] for r in results]
        all_scores.extend(scores)
        
        for result in results:
            doc_id = result["document"]
            if doc_id not in doc_scores:
                doc_scores[doc_id] = []
            doc_scores[doc_id].append(result["score"])
    
    # Percentiles
    sorted_scores = sorted(all_scores)
    
    def to_percentile(score):
        return sorted_scores.index(score) / len(sorted_scores)
    
    fused = {}
    for doc_id, scores in doc_scores.items():
        percentiles = [to_percentile(s) for s in scores]
        fused[doc_id] = np.mean(percentiles)
    
    return sorted(fused.items(), key=lambda x: x[1], reverse=True)

Evaluando Recall: No Sabes Si No Mides

def evaluate_retrieval(retriever, queries_with_relevant, k_values=[5, 10, 20, 50]):
    """
    Evaluar retrieval con Recall@K y Average Precision (AP).
    
    queries_with_relevant: lista de {"query": str, "relevant": [doc_ids]}
    """
    metrics = {"recall": {}, "mrr": {}, "ap": {}}
    
    for k in k_values:
        recalls = []
        mrrs = []
        aps = []
        
        for item in queries_with_relevant:
            query = item["query"]
            relevant = set(item["relevant"])
            
            # Retrieval
            results = retriever.search(query, top_k=k)
            retrieved = [r["document"] for r in results]
            
            # Recall@K
            relevant_retrieved = relevant & set(retrieved)
            recall = len(relevant_retrieved) / len(relevant)
            recalls.append(recall)
            
            # MRR
            for rank, doc in enumerate(retrieved, 1):
                if doc in relevant:
                    mrrs.append(1 / rank)
                    break
            else:
                mrrs.append(0)
            
            # Average Precision
            num_relevant = 0
            precision_sum = 0
            for rank, doc in enumerate(retrieved, 1):
                if doc in relevant:
                    num_relevant += 1
                    precision_sum += num_relevant / rank
            ap = precision_sum / len(relevant) if relevant else 0
            aps.append(ap)
        
        metrics["recall"][f"@{k}"] = np.mean(recalls)
        metrics["mrr"][f"@{k}"] = np.mean(mrrs)
        metrics["ap"][f"@{k}"] = np.mean(aps)
    
    return metrics

Los 3 Errores Comunes y Sus Arreglos

Error 1: No Usar Query Expansion

El problema: Una query como "error 500 en API REST" no captura que el usuario busca debugging, causes, y soluciones. Un solo embedding no representa todos los aspectos.

La solucion: Expandir la query con reformulaciones LLM que capturen diferentes aspectos.

# Wrong: query sin expansion
results = retriever.search("error 500 API")

# Correct: query expansion
expansions = retriever.expand_query("error 500 API")
print(f"Querys generadas: {expansions}")
# ["HTTP 500 internal server error debugging",
#  "causes of 500 status code in REST API", 
#  "how to fix 500 error in web services"]

Error 2: Confiar en Solo Un Metodo de Retrieval

El problema: Embeddings fallan en matching exacto de keywords tecnicos. BM25 falla en sinonimos. Solo uno deja huecos.

La solucion: Multi-method retrieval combinando dense, sparse, y keyword matching.

# Wrong: solo embeddings
dense_results = dense_retriever.search(query)

# Correct: multi-method con fusion
dense_results = dense_retriever.search(query, top_k=50)
sparse_results = bm25.search(query, top_k=50)
keyword_results = keyword_search(query)

fused = reciprocal_rank_fusion([dense_results, sparse_results, keyword_results])

Error 3: No Evaluar Recall

El problema: Sin medir recall, no sabes quantos documentos relevantes estas perdiendo. Puedes tener precision del 90% pero recall del 20%.

La solucion: Crear ground truth con documentos relevantes para cada query y medir Recall@K y MRR.

# Wrong: solo mirar precision
results = retriever.search(query, top_k=10)
print(f"Tiene {len(results)} resultados")

# Correct: medir recall con ground truth
metrics = evaluate_retrieval(retriever, test_set, k_values=[10, 50])
print(f"Recall@50: {metrics['recall']['@50']:.3f}")  # Debe ser >0.85

Resumen y Cierre Colombiano

Pues ahi lo tiene, parcero. Information Retrieval para LLMs no es solo embedding search. Es todo un framework:

  • Query expansion con LLM para capturar multiples aspectos de la busqueda
  • Multi-method retrieval combinando dense, sparse, y keyword
  • Fusion strategies como RRF, CombMNZ, o DBSF
  • Evaluacion obligatoria con Recall@K y MRR

El 75% de los que implementan RAG no usan query expansion ni multi-method retrieval. Usted ya sabe como hacerlo bien. Practique en sus proyectos, arme su test set con ground truth, y no pare hasta que el Recall@50 sea mayor a 0.85.
