Que Es RAG

Hagale pues, parcero. Estamos en el Día 242 y hoy vamos a meternos en el tema que el 80% implementa incorrectamente: RAG (Retrieval Augmented Generation).

Aquí en Medellín, cuando uno desplega un LLM para preguntas sobre documentos, la primera pregunta es: ¿cómo le doy el contexto? RAG es la respuesta. Pero aquí viene el problema: el 90% hace RAG naive y se pregunta por qué el modelo responde mal.

RAG combina retrieval (búsqueda) con generation (generación). El flujo es:

  1. Usuario hace pregunta
  2. Sistema busca documentos relevantes en base de conocimiento
  3. Documentos relevantes se añaden al prompt
  4. LLM genera respuesta basada en el contexto recuperado

Arquitectura Basica de RAG

Un sistema RAG completo tiene estos componentes:

  • Document Loader: Carga documentos de varias fuentes (PDF, HTML, Markdown, etc.)
  • Text Splitter: Divide documentos en chunks manejables
  • Embedding Model: Convierte texto en vectores
  • Vector Store: Almacena embeddings para búsqueda rápida
  • Retrieval System: Encuentra documentos relevantes
  • Generation Model: Genera respuesta con contexto
"""
RAG Pipeline completo.
Esta es la implementacion que el 80% deberia estar usando.
"""

from typing import List, Optional
from dataclasses import dataclass
import os

@dataclass
class Document:
    """Representa un documento o chunk de documento."""
    content: str
    metadata: dict
    embedding: Optional[List[float]] = None

class SimpleRAG:
    """
    Sistema RAG básico con retrieval y generación.
    """
    
    def __init__(
        self,
        embedding_model,
        vector_store,
        llm,
        chunk_size: int = 500,
        chunk_overlap: int = 50,
    ):
        self.embedding_model = embedding_model
        self.vector_store = vector_store
        self.llm = llm
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        
    def load_documents(self, documents: List[str], metadatas: List[dict] = None) -> List[Document]:
        """
        Carga y divide documentos en chunks.
        """
        docs = []
        for i, doc_content in enumerate(documents):
            # Split simple por parrafos
            chunks = self._split_text(doc_content)
            
            for j, chunk in enumerate(chunks):
                metadata = metadatas[i].copy() if metadatas else {}
                metadata['chunk_id'] = j
                metadata['chunk_count'] = len(chunks)
                
                docs.append(Document(
                    content=chunk,
                    metadata=metadata
                ))
        
        return docs
    
    def _split_text(self, text: str) -> List[str]:
        """
        Divide texto en chunks con solapamiento.
        """
        chunks = []
        start = 0
        
        while start < len(text):
            end = start + self.chunk_size
            chunk = text[start:end]
            
            # Evitar cortes en medio de oraciones
            if end < len(text):
                last_period = chunk.rfind('.')
                if last_period > self.chunk_size // 2:
                    chunk = chunk[:last_period + 1]
                    end = start + last_period + 1
            
            chunks.append(chunk.strip())
            start = end - self.chunk_overlap
        
        return chunks
    
    def index_documents(self, documents: List[Document]) -> None:
        """
        Genera embeddings y los almacena en el vector store.
        """
        # Generar embeddings
        contents = [doc.content for doc in documents]
        embeddings = self.embedding_model.embed_batch(contents)
        
        # Añadir al vector store
        for doc, embedding in zip(documents, embeddings):
            doc.embedding = embedding
            self.vector_store.add(doc.content, embedding, doc.metadata)
    
    def retrieve(self, query: str, top_k: int = 5) -> List[Document]:
        """
        Recupera documentos relevantes para la query.
        """
        # Generar embedding de la query
        query_embedding = self.embedding_model.embed(query)
        
        # Buscar en vector store
        results = self.vector_store.search(query_embedding, top_k)
        
        return results
    
    def generate(
        self,
        query: str,
        context_documents: List[Document],
        system_prompt: str = None
    ) -> str:
        """
        Genera respuesta usando el contexto recuperado.
        """
        # Construir contexto
        context = "\n\n".join([
            f"Documento {i+1}:\n{doc.content}"
            for i, doc in enumerate(context_documents)
        ])
        
        # Prompt
        if system_prompt is None:
            system_prompt = (
                "Eres un asistente útil que responde preguntas basándose "
                "únicamente en el contexto proporcionado."
            )
        
        full_prompt = f"""
{system_prompt}

Contexto:
{context}

Pregunta: {query}

Respuesta (basada únicamente en el contexto proporcionado):
"""
        
        # Generar
        response = self.llm.generate(full_prompt)
        
        return response
    
    def query(self, question: str, top_k: int = 5) -> dict:
        """
        Pipeline completo: retrieve + generate.
        """
        # 1. Retrieve
        relevant_docs = self.retrieve(question, top_k)
        
        # 2. Generate
        answer = self.generate(question, relevant_docs)
        
        return {
            "question": question,
            "answer": answer,
            "retrieved_documents": relevant_docs
        }

Retrieval: El Componente Crítico

Aquí es donde el 90% falla. El retrieval no es solo "buscar en vector store". Hay que considerar:

Chunking Strategy

El chunking determina qué tanto contexto recibe el modelo. Demasiado pequeño = pierdes contexto. Demasiado grande = dilute relevancia y pierdes tokens.

"""
Estrategias de chunking para RAG.
"""

def chunk_by_fixed_size(text: str, chunk_size: int = 500, overlap: int = 50) -> list[str]:
    """
    Chunking de tamaño fijo con solapamiento.
    Más simple pero puede cortar en medio de oraciones.
    """
    chunks = []
    start = 0
    
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap
    
    return chunks

def chunk_by_sentences(text: str, sentences_per_chunk: int = 5) -> list[str]:
    """
    Chunking por oraciones completas.
    Mejor calidad pero Tamaño menos uniforme.
    """
    import re
    sentences = re.split(r'[.!?]+', text)
    sentences = [s.strip() for s in sentences if s.strip()]
    
    chunks = []
    for i in range(0, len(sentences), sentences_per_chunk):
        chunk = '. '.join(sentences[i:i + sentences_per_chunk]) + '.'
        chunks.append(chunk)
    
    return chunks

def chunk_by_semantic_similarity(
    text: str,
    embed_model,
    max_tokens: int = 500,
    threshold: float = 0.7
) -> list[str]:
    """
    Chunking semántico: agrupa texto por similitud de significado.
    Más avanzado, pero más costoso computacionalmente.
    """
    sentences = re.split(r'[.!?]+', text)
    sentences = [s.strip() for s in sentences if s.strip()]
    
    if not sentences:
        return [text]
    
    # Generar embeddings por oración
    embeddings = embed_model.embed_batch(sentences)
    
    chunks = []
    current_chunk = [sentences[0]]
    current_embeddings = [embeddings[0]]
    
    for i in range(1, len(sentences)):
        # Calcular similitud con última oración del chunk
        similarity = cosine_similarity([embeddings[i]], [current_embeddings[-1]])[0][0]
        
        if similarity > threshold:
            current_chunk.append(sentences[i])
            current_embeddings.append(embeddings[i])
        else:
            # Guardar chunk actual e iniciar nuevo
            chunks.append(' '.join(current_chunk))
            current_chunk = [sentences[i]]
            current_embeddings = [embeddings[i]]
    
    # Último chunk
    if current_chunk:
        chunks.append(' '.join(current_chunk))
    
    return chunks

Hybrid Search para Retrieval

Como hablamos ayer, combinar BM25 (lexical) con embeddings (semantic) mejora significativamente el retrieval.

class HybridRetriever:
    """
    Retrieval híbrido combinando BM25 y vector search.
    """
    
    def __init__(
        self,
        vector_store,
        bm25_index,
        embed_model,
        alpha: float = 0.5,
    ):
        self.vector_store = vector_store
        self.bm25_index = bm25_index
        self.embed_model = embed_model
        self.alpha = alpha  # 0 = solo BM25, 1 = solo vector
    
    def retrieve(self, query: str, top_k: int = 10) -> list[tuple[dict, float]]:
        """
        Retrieval híbrido con fusión de scores.
        """
        # 1. Vector search
        query_embedding = self.embed_model.embed(query)
        vector_results = self.vector_store.search(query_embedding, top_k * 2)
        
        # 2. BM25 search
        bm25_results = self.bm25_index.search(query, top_k * 2)
        
        # 3. Fusion de resultados (Reciprocal Rank Fusion)
        fused_scores = {}
        
        # Reciprocal Rank Fusion
        k = 60  # Factor de fusión
        
        for rank, (doc, vector_score) in enumerate(vector_results):
            doc_id = doc['id']
            rrf_score = 1 / (k + rank + 1)
            fused_scores[doc_id] = fused_scores.get(doc_id, 0) + self.alpha * rrf_score
        
        for rank, (doc, bm25_score) in enumerate(bm25_results):
            doc_id = doc['id']
            rrf_score = 1 / (k + rank + 1)
            fused_scores[doc_id] = fused_scores.get(doc_id, 0) + (1 - self.alpha) * rrf_score
        
        # Ordenar por score fusionado
        sorted_results = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        
        # Devolver top_k documentos
        final_results = []
        for doc_id, score in sorted_results[:top_k]:
            doc = self.vector_store.get_document(doc_id)
            final_results.append((doc, score))
        
        return final_results

MMR: Maximal Marginal Relevance

El 90% solo hace retrieval de los documentos más similares. Pero eso puede dar lugar a resultados redundantes. MMR busca diversidad en los documentos recuperados.

def mmr_retrieval(
    query: str,
    documents: list[dict],
    embeddings: list[list[float]],
    query_embedding: list[float],
    top_k: int = 5,
    fetch_k: int = 20,
    lambda_mult: float = 0.5,
) -> list[dict]:
    """
    Maximal Marginal Relevance retrieval.
    
    Selecciona documentos que son:
    1. Relevantes para la query (alto similarity)
    2. Diversos entre sí (bajo similarity entre sí)
    
    lambda_mult controla el balance:
    - Alto (cerca de 1): Más relevancia, menos diversidad
    - Bajo (cerca de 0): Más diversidad, menos relevancia
    """
    from sklearn.metrics.pairwise import cosine_similarity
    import numpy as np
    
    # Calcular similitud con query
    query_similarities = cosine_similarity([query_embedding], embeddings)[0]
    
    # Índices de documentos ya seleccionados
    selected_indices = []
    
    for _ in range(top_k):
        # Para cada documento no seleccionado, calcular score MMR
        best_score = -float('inf')
        best_idx = None
        
        for idx in range(len(documents)):
            if idx in selected_indices:
                continue
            
            # Similitud con query
            query_sim = query_similarities[idx]
            
            # Similitud máxima con documentos ya seleccionados
            if selected_indices:
                doc_embeddings = [embeddings[i] for i in selected_indices]
                doc_sims = cosine_similarity([embeddings[idx]], doc_embeddings)[0]
                max_sim = np.max(doc_sims)
            else:
                max_sim = 0
            
            # Score MMR
            mmr_score = lambda_mult * query_sim - (1 - lambda_mult) * max_sim
            
            if mmr_score > best_score:
                best_score = mmr_score
                best_idx = idx
        
        selected_indices.append(best_idx)
    
    # Devolver documentos seleccionados
    return [documents[i] for i in selected_indices]

Reranking para Mejor Calidad

Después del retrieval inicial, un reranker puede mejorar significativamente la calidad de los documentos seleccionados.

from sentence_transformers import CrossEncoder

class Reranker:
    """
    Reranker usando cross-encoder para mejor selección de documentos.
    """
    
    def __init__(self, model_name: str = "cross-encoder/ms-marco-MiniLM-L-6-v2"):
        self.model = CrossEncoder(model_name)
    
    def rerank(
        self,
        query: str,
        documents: list[dict],
        top_n: int = 10,
    ) -> list[tuple[dict, float]]:
        """
        Rerankea documentos usando cross-encoder.
        
        Cross-encoder pasa query y documento juntos por el transformer,
        produciendo un score de relevancia más preciso.
        """
        # Crear pares query-documento
        pairs = [(query, doc['content']) for doc in documents]
        
        # Obtener scores de relevancia
        scores = self.model.predict(pairs)
        
        # Ordenar por score
        doc_scores = list(zip(documents, scores))
        doc_scores.sort(key=lambda x: x[1], reverse=True)
        
        # Devolver top_n
        return doc_scores[:top_n]

Resumen y Cierre

Hagale pues, parcero. Lo que nos queda es esto:

  • RAG básico: Retrieval + Generation. Simple pero efectivo.
  • Chunking importa: Ni muy pequeño ni muy grande. Encuentra el balance.
  • Hybrid search: Combina BM25 + embeddings para mejor retrieval.
  • MMR: Para diversidad en resultados retrieved.
  • Reranking: Cross-encoder para mejorar selección final.

En Medellín decimos "no pongas todos los huevos en la misma canasta". Para RAG es igual: no confíes solo en vector search, usa hybrid. No uses solo los primeros resultados, usa MMR para diversidad.
