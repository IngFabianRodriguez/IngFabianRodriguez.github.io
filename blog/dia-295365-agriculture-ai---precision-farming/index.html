Intro

Mañana en Bogotá, un ingeniero está mirando una foto satelital de cultivos y una tabla de sensores de humedad, y se pregunta: ¿cómo diablos proceso esto junto con las天气预报 que me llegan en texto? La respuesta está en los LLMs multi-modales — modelos que no solo leen texto, sino que también ven imágenes, escuchan audio y hasta procesan datos de sensores. En Colombia, donde la agricultura de precisión está tomando fuerza desde los valles interandinos hasta la Orinoquía, entender multi-modalidad no es un lujo, es una necesidad. El 80% de los equipos sigue trabajando con cada modality por separado. El 20% que no, está creando experiencias que parecen sacadas de ciencia ficción.

¿Qué es un LLM Multi-Modal?

Un LLM multi-modal es un modelo de lenguaje que puede procesar y generar contenido en múltiples modalidades simultáneamente: texto, imágenes, audio, video, y datos estructurados. La arquitectura típica incluye:

  • Encoders específicos por modality: cada tipo de entrada tiene su propio encoder optimizado (por ejemplo, CLIP para imágenes, wav2vec para audio)
  • Un backbone de lenguaje unificado: el "cerebro" que realmente razona y genera respuestas
  • Projection layers: módulos que mapean representations de cada modality a un espacio compartido de embeddings

La matemática fundamental detrás de la fusión multi-modal se basa en el concepto de joint embedding. Dados embeddings de texto $E_t$ e imágenes $E_i$, queremos que:

$$sim(E_t, E_i) = \frac{E_t \cdot E_i}{|E_t| |E_i|} \approx 1 \text{ cuando son语义amente relacionados}$$

Esto se entrena con contraste multimodal losses que maximizan la similitud entre pares relacionados y la minimizan entre pares no relacionados.

Arquitectura Típica


# Arquitectura conceptual de un pipeline multi-modal
class MultiModalPipeline:
    def __init__(self):
        # Encoders por modality
        self.text_encoder = CLIPTextEncoder()
        self.image_encoder = CLIPImageEncoder()
        self.audio_encoder = Wav2VecEncoder()

        # Proyecciones a espacio compartido
        self.text_projector = ProjectionLayer(text_dim, shared_dim)
        self.image_projector = ProjectionLayer(image_dim, shared_dim)
        self.audio_projector = ProjectionLayer(audio_dim, shared_dim)

        # LLM backbone
        self.llm = LLaVABackbone()

    def process(self, text, image=None, audio=None):
        # Codificar cada modality
        text_emb = self.text_encoder(text)
        image_emb = self.image_encoder(image) if image else None
        audio_emb = self.audio_encoder(audio) if audio else None

        # Proyectar al espacio compartido
        text_proj = self.text_projector(text_emb)
        image_proj = self.image_projector(image_emb) if image_emb else None
        audio_proj = self.audio_projector(audio_emb) if audio_emb else None

        # Concatenar y enviar al LLM
        combined = concatenate_modalities(text_proj, image_proj, audio_proj)
        return self.llm.generate(combined)

Vision-Language Models (VLMs)

Los VLMs son el caso de uso más popular de multi-modalidad. Modelos como LLaVA, GPT-4V, Claude 3 y Gemini Pro pueden analizar imágenes y responder preguntas sobre ellas.

¿Cómo funcionan?

Un VLM toma una imagen, la codifica con un vision encoder (generalmente un ViT - Vision Transformer), y esa representación visual se concatena con el texto de entrada como tokens especiales en el embedding space del LLM.


# Ejemplo con transformers y LLaVA
from transformers import AutoProcessor, LlavaForConditionalGeneration
from PIL import Image

model_id = "llava-hf/llava-1.5-7b-hf"
model = LlavaForConditionalGeneration.from_pretrained(model_id)
processor = AutoProcessor.from_pretrained(model_id)

# Input: imagen + texto
image = Image.open("cultivo.jpg")
prompt = "[INST] <image>\n¿Hay signos de estrés hídrico en esta planta? [/INST]"

inputs = processor(prompt, images=image, return_tensors="pt")
outputs = model.generate(**inputs, max_new_tokens=100)
print(processor.decode(outputs[0], skip_special_tokens=True))

La magia está en que el modelo no solo "describe" la imagen — razona sobre ella. Puede responder preguntas sobre relaciones espaciales, comparar imágenes, contar objetos, y hasta interpretar gráficos complejos. En agricultura, esto significa:

  • Detectar enfermedades en hojas desde fotos de campo
  • Analizar imágenes satelitales para estimar biomasa
  • Interpretar graficos de rendimiento por parcela

Procesamiento de Audio con LLMs

El audio es otra modality que muchos developers ignoran. Pero un pipeline de audio completo incluye:

  1. Speech-to-Text (STT): audio → texto transcrito
  2. Audio understanding: el LLM procesa el audio directamente (sin transcripción)
  3. Text-to-Speech (TTS): respuesta de texto → audio

# Pipeline de audio multi-modal
import torch
from transformers import WhisperProcessor, WhisperForConditionalGeneration
from datasets import load_dataset

class AudioMultiModalPipeline:
    def __init__(self):
        # STT: Whisper para transcripción
        self.stt_processor = WhisperProcessor.from_pretrained("openai/whisper-medium")
        self.stt_model = WhisperForConditionalGeneration.from_pretrained("openai/whisper-medium")

        # LLM multi-modal
        self.llm = LlavaForConditionalGeneration.from_pretrained("llava-hf/llava-1.5-7b-hf")

        # TTS: para respuestas en audio
        self.tts = SpeechT5.from_pretrained("microsoft/speecht5_tts")

    def audio_to_insight(self, audio_path, context_text):
        # 1. Transcribir audio
        audio_input = load_dataset("audio", split="validation", streaming=True)
        inputs = self.stt_processor(audio_path, return_tensors="pt")
        transcription = self.stt_model.generate(inputs.input_features)
        text_input = self.stt_processor.batch_decode(transcription, skip_special_tokens=True)[0]

        # 2. Combinar con contexto de texto
        combined_prompt = f"Contexto del campo: {context_text}\n\nAudio del agricultor: {text_input}"

        # 3. Generar respuesta del LLM
        response = self.llm.generate(combined_prompt)

        # 4. Convertir respuesta a audio
        audio_response = self.tts.generate_speech(response)
        return {"text": response, "audio": audio_response}

Los 3 Errores Comunes (y sus Soluciones)

Error 1: No considerar las capacidades multi-modales del modelo

Síntoma: Estás usando GPT-4 pero solo le envías texto, pagando de más por capacidad que no usas.

Fix: Antes de empezar, audit las capacidades de tu modelo. No todos los LLMs multi-modales funcionan igual:


# Checklist de capabilities antes de elegir modelo
MODALITY_MATRIX = {
    "gpt-4v": {"vision": True, "audio": False, "function_calls": True},
    "claude-3-opus": {"vision": True, "audio": False, "long_context": True},
    "gemini-pro": {"vision": True, "audio": False, "video": True},
    "gpt-4o": {"vision": True, "audio": True, "function_calls": True},
}

def select_model(task_requirements):
    required_modalities = set(task_requirements)
    for model, capabilities in MODALITY_MATRIX.items():
        if required_modalities.issubset(set(capabilities.keys())):
            if all(capabilities[m] for m in required_modalities):
                return model
    raise ValueError("No model supports required modalities")

Error 2: Tratar cada modality como un pipeline separado

Síntoma: Tienes un pipeline de imágenes, otro de audio, y luego los mezclas manualmente. El resultado es frágil y no razona correctamente.

Fix: Usa un LLM nativamente multi-modal que razone sobre todas las modalities juntas. La clave es la joint reasoning:


# MAL: pipelines separados
text_result = process_text(text_input)
image_result = process_image(image_input)
final = combine_manually(text_result, image_result)  # No hay razonamiento joint!

# BIEN: pipeline unificado
class UnifiedMultiModalLLM:
    def __init__(self, model_name="llava-1.5-7b"):
        self.model = LlavaForConditionalGeneration.from_pretrained(model_name)
        self.processor = AutoProcessor.from_pretrained(model_name)

    def query(self, text, image, audio_transcription=None):
        # Todos los inputs van juntos al mismo modelo
        prompt = f"Analiza esta imagen y responde.\n"
        if audio_transcription:
            prompt += f"Contexto de audio: {audio_transcription}\n"
        prompt += f"Pregunta: {text}"

        inputs = self.processor(prompt, images=image, return_tensors="pt")
        # El modelo razona JOINT sobre texto + imagen + contexto de audio
        return self.model.generate(**inputs)

Error 3: No optimizar para inferencia multi-modal

Síntoma: Tu pipeline funciona bien con texto pero es lento cuando añades imágenes o audio. Los costos se disparan.

Fix: La inferencia multi-modal tiene costs asymétricos. Optimiza temprano:


# Optimización multi-modal
from functools import lru_cache
import torch

class OptimizedMultiModalPipeline:
    def __init__(self):
        # Pre-codificar modality-invariant components
        self.image_cache = lru_cache(maxsize=128)(self._encode_image)
        self.prompt_template = "Analiza {} y responde: {}"

        # Cuantización para reducir VRAM
        self.quantized_llm = load_quantized("llava-1.5-7b.Q4_K_M.gguf")

    @torch.cuda.amp.autocast()
    def _encode_image(self, image_path):
        # Solo hacer esto una vez por imagen
        return self.image_encoder(image_path)

    def batch_process(self, queries):
        # Batching: procesar múltiples queries juntas
        # cuando comparten la misma imagen (caso común en agricultura)
        images = list(set(q["image"] for q in queries))
        image_embeddings = {img: self.image_cache(img) for img in images}

        results = []
        for q in queries:
            emb = image_embeddings[q["image"]]
            prompt = self.prompt_template.format(q["context"], q["question"])
            out = self.quantized_llm.generate(emb, prompt)
            results.append(out)
        return results

Métodos de Fusión Multi-Modal

La forma en que combines las modalities afecta diretamente el rendimiento:

1. Concatenation-based (Early Fusion)

Concatenar embeddings antes del LLM. Simple pero puede ser costoso.

$$E_{fused} = [W_t E_t; W_i E_i; W_a E_a]$$

2. Attention-based (Late Fusion)

Cada modality es procesada separadamente, luego se fusiona via cross-attention.


# Cross-attention fusion
class CrossAttentionFusion(torch.nn.Module):
    def __init__(self, dim):
        self.text_attn = nn.MultiheadAttention(dim, 4)
        self.image_attn = nn.MultiheadAttention(dim, 4)
        self.fusion_layer = nn.MultiheadAttention(dim, 4)

    def forward(self, text_emb, image_emb):
        # Procesar cada modality
        text_out, _ = self.text_attn(text_emb, text_emb, text_emb)
        image_out, _ = self.image_attn(image_emb, image_emb, image_emb)

        # Fusionar via cross-attention
        fused, _ = self.fusion_layer(text_out, image_out, image_out)
        return fused

Resumen

Los LLMs multi-modales no son el futuro — son el presente. La capacidad de procesar texto, imágenes y audio en un solo modelo abre posibilidades que antes eran ciencia ficción:

  • Visión-lenguaje: razón sobre imágenes de cultivos, satelitales, y diagrams de rendimiento
  • Audio-lenguaje: transcribe y razona sobre голосовые сообщщения de agricultores en el campo
  • Fusión nativa: los mejores resultados vienen de modelos diseñados multi-modales desde cero, no de pipelines pegados

La matemática de los joint embeddings y la attention-based fusion es elegante, pero la implementación práctica requiere entender qué modelo usar para cada caso y cómo optimizar el inference pipeline.
