LLM Model Editing

Cómo editar knowledge en LLMs post-training

29 de abril de 2026

Buenas, Colombia. Aquí en el día 326, y hoy vamos a meternos en algo que el 75% no conoce y solo el 25% usa para corregir facts: Model Editing. Sí, la capacidad de editar directamente el conocimiento dentro de un LLM después de que ya fue entrenado. Sin hacer fine-tuning completo. Sin reentrenar todo. Directamente ir a los pesos y decir "esto cambió, actualízalo".

Piénsalo así: es como si pudieras abrir el cerebro de un modelo y cambiarle solo el recuerdo específico de algo, sin afectar todo lo demás. Eso es Model Editing. Y no, no es ciencia ficción — ROME y MEMIT lo hacen realidad.

¿Por qué Model Editing?

Los LLMs cometen errores factuales. Eso es un hecho. Y cuando lo hacen, tienes dos opciones:

  1. Fine-tunear todo el modelo con datos correctos (caro, lento, risky)
  2. Editar directamente el conocimiento específico (rápido, surgical, barato)

El Model Editing entra en la segunda categoría. Es la diferencia entre cambiarle el aceite a todo el carro vs. cambiar solo la bujía que está mala.

ROME: Rank-One Model Editing

ROME es un método para editar conocimientos en LLMs encontrando las capas específicas donde se almacena un hecho y modificando solo esos pesos.

La idea central de ROME:

$$W_{new} = W_{old} + \Delta \cdot e_{subject} \cdot e_{relation}^T$$

Donde $\Delta$ es el cambio de conocimiento, $e_{subject}$ es el vector de embedding del sujeto, y $e_{relation}$ codifica la relación.

Esto modifica UNICAMENTE los pesos relacionados con ese hecho, sin tocar el resto del modelo.

El proceso ROME:

  1. Localización: Encontrar qué capas almacenan el conocimiento específico
  2. Computación: Calcular el cambio necesario $\Delta$
  3. Actualización: Aplicar el cambio a los pesos con rank-one update

MEMIT: Model Editing with Memory and Intermediate Tokens

MEMIT extiende ROME para hacer ediciones más robustas y manejar sequences de tokens:

$$W_{memit} = W_{old} + \sum_i \alpha_i \cdot v_i \cdot u_i^T$$

Donde múltiples vectores de intervención $v_i, u_i$ se combinan con pesos $\alpha_i$ para una edición más precisa.

"""
Model Editing Framework
Implementación de ROME y MEMIT para editar conocimientos en LLMs
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
from typing import Dict, List, Tuple, Optional
from dataclasses import dataclass
import numpy as np

@dataclass
class EditTarget:
    """Representa un conocimiento a editar"""
    subject: str          # Ej: "Gustavo Petro"
    relation: str         # Ej: "es presidente de"
    target: str           # Ej: "Colombia"
    subject_tokens: List[int]
    target_tokens: List[int]

@dataclass
class EditingResult:
    """Resultado de una operación de editing"""
    success: bool
    affected_layers: List[int]
    side_effects: Dict[str, float]
    original_value: Optional[str]
    new_value: str

class ModelEditor:
    """
    Framework para editar conocimientos en LLMs post-training
    Soporta ROME y MEMIT
    """
    
    def __init__(self, model: nn.Module, layer_names: List[str]):
        self.model = model
        self.layer_names = layer_names
        self.layer_to_idx = {
            name: idx for idx, name in enumerate(layer_names)
        }
        self.edit_history = []
        
    def locate_knowledge(
        self,
        subject: str,
        relation: str,
        method: str = 'attention'
    ) -> List[int]:
        """
        Localiza las capas donde se almacena un conocimiento
        
        Usa attention patterns o probing para identificar
        qué capas representan qué conocimiento
        """
        if method == 'attention':
            # Seguimiento de atención durante generación
            return self._locate_via_attention(subject, relation)
        elif method == 'probing':
            # Classifier lineal para detectar conocimiento
            return self._locate_via_probing(subject, relation)
        elif method == 'causal':
            # Causal tracing para encontrar dependencias
            return self._locate_via_causal_tracing(subject, relation)
        
        return []
    
    def _locate_via_attention(
        self, 
        subject: str, 
        relation: str
    ) -> List[int]:
        """
        Usa atención para localizar conocimiento
        
        Las capas con mayor atención a los tokens
        del sujeto son las que más contribuyen
        """
        # En implementación real, hacer forward pass
        # y recolectar attention scores
        return [15, 17, 19, 21]  # Capas candidatas
    
    def _locate_via_probing(
        self, 
        subject: str, 
        relation: str
    ) -> List[int]:
        """
        Usa probing classifier para detectar
        si una capa contiene el conocimiento
        """
        # Probing: entrenar classifier lineal enactivations
        # para predecir si el conocimiento está ahí
        return [16, 18, 20, 22]
    
    def _locate_via_causal_tracing(
        self, 
        subject: str, 
        relation: str
    ) -> List[int]:
        """
        Causal tracing: interveniractivations
        y observar efecto en output
        """
        # 1. Tomar clean activation en posición de subject
        # 2. Corromper input
        # 3. Restaurar activación una capa a la vez
        # 4. Medir recuperación del output correcto
        return [17, 19, 21]
    
    def compute_rome_update(
        self,
        layer_idx: int,
        subject_embeddings: torch.Tensor,
        target_embeddings: torch.Tensor,
        relation_embedding: torch.Tensor
    ) -> torch.Tensor:
        """
        Computa el rank-one update para ROME
        
        ΔW = (target - W·subject) · relation^T / ||relation||^2
        
        Esto fuerza que W·subject = target
        """
        # Obtener pesos de la capa
        W = self._get_layer_weights(layer_idx)
        
        # W @ subject = prediction actual
        current_output = W @ subject_embeddings
        
        # Diferencia con output deseado
        delta = target_embeddings - current_output
        
        # Normalizar por relation embedding
        relation_norm = torch.norm(relation_embedding) ** 2 + 1e-8
        
        # Rank-one update
        delta_W = torch.outer(delta, relation_embedding) / relation_norm
        
        return delta_W
    
    def compute_memit_update(
        self,
        layer_idx: int,
        subject_embeddings: torch.Tensor,
        multi_token_targets: List[torch.Tensor],
        relation_embeddings: List[torch.Tensor]
    ) -> torch.Tensor:
        """
        MEMIT: múltiples rank-one updates combinados
        
        W_new = W_old + Σ α_i · v_i · u_i^T
        """
        W = self._get_layer_weights(layer_idx)
        
        total_update = torch.zeros_like(W)
        
        for target, relation in zip(multi_token_targets, relation_embeddings):
            current = W @ subject_embeddings
            delta = target - current
            
            relation_norm = torch.norm(relation) ** 2 + 1e-8
            update = torch.outer(delta, relation) / relation_norm
            
            # Ponderación por posición del token
            alpha = 1.0 / (len(multi_token_targets) + 1e-8)
            total_update += alpha * update
        
        return total_update
    
    def apply_rome_edit(
        self,
        edit: EditTarget,
        layer_idx: Optional[int] = None
    ) -> EditingResult:
        """
        Aplica编辑 ROME a una capa específica
        """
        # Si no se especifica capa, localizarla
        if layer_idx is None:
            layers = self.locate_knowledge(
                edit.subject, 
                edit.relation,
                method='causal'
            )
            layer_idx = layers[0] if layers else self._find_mlp_layer()
        
        # Guardar valor original para rollback
        W_old = self._get_layer_weights(layer_idx).clone()
        original_subject = self._get_subject_representation(edit)
        
        # Computar update
        update = self.compute_rome_update(
            layer_idx,
            edit.subject_tokens,
            edit.target_tokens,
            edit.relation
        )
        
        # Aplicar
        W_new = W_old + update
        self._set_layer_weights(layer_idx, W_new)
        
        # Evaluar side effects
        side_effects = self.evaluate_side_effects(edit)
        
        self.edit_history.append({
            'layer': layer_idx,
            'subject': edit.subject,
            'old_weights': W_old,
            'new_weights': W_new,
            'timestamp': 'now'
        })
        
        return EditingResult(
            success=True,
            affected_layers=[layer_idx],
            side_effects=side_effects,
            original_value=None,
            new_value=edit.target
        )
    
    def apply_memit_edit(
        self,
        edit: EditTarget,
        layer_indices: Optional[List[int]] = None
    ) -> EditingResult:
        """
        Aplica编辑 MEMIT en múltiples capas
        """
        if layer_indices is None:
            layer_indices = self.locate_knowledge(
                edit.subject,
                edit.relation,
                method='causal'
            )
        
        # Obtener todos los embeddings para cada token
        subject_embs = self._get_subject_embeddings(edit)
        target_embs = self._get_target_embeddings(edit)
        relation_embs = self._get_relation_embeddings(edit)
        
        all_updates = []
        
        for layer_idx in layer_indices:
            update = self.compute_memit_update(
                layer_idx,
                subject_embs,
                target_embs,
                relation_embs
            )
            
            W = self._get_layer_weights(layer_idx)
            self._set_layer_weights(layer_idx, W + update)
            all_updates.append(update)
        
        side_effects = self.evaluate_side_effects(edit)
        
        return EditingResult(
            success=True,
            affected_layers=layer_indices,
            side_effects=side_effects,
            original_value=None,
            new_value=edit.target
        )
    
    def evaluate_side_effects(
        self,
        edit: EditTarget,
        test_relations: Optional[List[str]] = None
    ) -> Dict[str, float]:
        """
        Evalúa side effects del editing
        
        Importante: editar un hecho no debe afectar
        hechos relacionados o no relacionados
        """
        if test_relations is None:
            # Testear relaciones comunes
            test_relations = [
                'es', 'fue', 'tiene', 'puede',
                'está en', 'trabaja en'
            ]
        
        side_effects = {}
        
        for relation in test_relations:
            if relation != edit.relation:
                # Evaluar si el subject con esta relación
                # cambió su output
                old_confidence = self._eval_relation(
                    edit.subject, relation
                )
                # El confidence debería ser igual
                # (pero no tenemos modelo real para hacerlo)
                side_effects[relation] = 0.0
        
        return side_effects
    
    def rollback(self, steps: int = 1) -> None:
        """
        Rollback de ediciones previas
        
        Útil si el editing introdujo side effects
        inaceptables
        """
        for _ in range(min(steps, len(self.edit_history))):
            last_edit = self.edit_history.pop()
            layer_idx = last_edit['layer']
            old_weights = last_edit['old_weights']
            self._set_layer_weights(layer_idx, old_weights)
    
    def _get_layer_weights(self, layer_idx: int) -> torch.Tensor:
        """Obtiene pesos de una capa"""
        # Simplified - en implementación real navegar
        # la arquitectura del modelo
        return torch.randn(4096, 4096)
    
    def _set_layer_weights(
        self, 
        layer_idx: int,

    ) -> None:
        """Establece pesos de una capa"""
        pass
    
    def _get_subject_representation(self, edit: EditTarget) -> torch.Tensor:
        """Obtiene embedding del subject"""
        return torch.randn(4096)
    
    def _get_subject_embeddings(self, edit: EditTarget) -> torch.Tensor:
        """Obtiene embeddings para cada token del subject"""
        return torch.randn(len(edit.subject_tokens), 4096)
    
    def _get_target_embeddings(self, edit: EditTarget) -> List[torch.Tensor]:
        """Obtiene embeddings para cada token del target"""
        return [torch.randn(4096) for _ in edit.target_tokens]

class KnowledgeGraphEditor:
    """
    Editor de knowledge graph integrado con Model Editing
    Mantiene consistencia entre KG y pesos del modelo
    """
    
    def __init__(self, model_editor: ModelEditor):
        self.editor = model_editor
        self.knowledge_graph = {}
    
    def edit_with_consistency(
        self,
        subject: str,
        relation: str,
        new_target: str
    ) -> EditingResult:
        """
        Edita con verificación de consistencia
        
        1. Actualizar knowledge graph
        2. Editar modelo
        3. Verificar consistencia
        """
        # 1. Actualizar KG
        old_target = self.knowledge_graph.get(
            (subject, relation), 
            None
        )
        self.knowledge_graph[(subject, relation)] = new_target
        
        # 2. Editar modelo
        edit = EditTarget(
            subject=subject,
            relation=relation,
            target=new_target,
            subject_tokens=[1, 2, 3],
            target_tokens=[4, 5]
        )
        
        result = self.editor.apply_memit_edit(edit)
        
        # 3. Verificar consistencia
        if not self._verify_consistency(subject, relation, new_target):
            # Rollback si hay inconsistencia
            self.editor.rollback()
            self.knowledge_graph[(subject, relation)] = old_target
            result.success = False
        
        return result
    
    def _verify_consistency(
        self,
        subject: str,
        relation: str,
        expected: str
    ) -> bool:
        """Verifica que el modelo respondió consistentemente"""

Los 3 Errores Comunes

Error 1: No editar y dejar errores factuales

El 75% de las implementaciones simplemente aceptan que el modelo tiene errores y punto. No hacen nada. El modelo sigue diciendo que Obama fundó Facebook o que el iPhone salió en 2005. Esto destruye la confianza del usuario.

Fix: Implementar pipeline de detección y corrección de errores factuales. Cuando detectas un error, edítalo. No esperes a que el modelo "aprenda" solito — eso no va a pasar.

Error 2: No entender qué método de editing usar

ROME, MEMIT, KN, ft, MEND... cada método tiene sus casos de uso. Usar ROME para editar conocimiento que requiere cambios en múltiples capas es suboptimal. Usar fine-tuning completo cuando solo necesitas cambiar un fact es overkill.

Fix: Entender la diferencia: ROME es surgical para hechos únicos, MEMIT es para secuencias y cambios multi-capa, fine-tuning es cuando no hay alternativa. Empezar por lo más simple.

Error 3: No evaluar si el editing causa side effects

Edité "Paris" → "Londres" en "capital de Francia" pero ahora el modelo dice que Francia está en Europa del Este. Eso pasa cuando no evalúas generalización y locality post-editing.

Fix: Siempre ejecutar suite de evaluación post-editing: (1) ¿El hecho cambió correctamente? (2) ¿Frases similares también cambiaron? (3) ¿Hechos relacionados se mantuvieron? Si algo falla, rollback.

Métricas de Evaluación

Efficacy: $Acc = (\text{# edits exitosos}) / (\text{# total edits})$

Generalization: ¿El cambio aplica en contextos nuevos?

Locality: $L = 1 - (\text{# hechos relacionados afectados}) / (\text{# total hechos relacionados})$

Fluency: ¿El output sigue siendo gramaticalmente correcto?

Resumen

  • Model Editing permite cambiar hechos específicos sin reentrenar todo
  • ROME usa rank-one updates para ediciones quirúrgicas
  • MEMIT extiende ROME para múltiples capas y tokens
  • Siempre evaluar efficacy, generalization, locality y fluency
  • Rollback está disponible si el editing introduce side effects
  • KG + Model integration mantiene consistencia

No te quedes luchando contra el modelo cuando puedes simplemente cambiar el fact. Eso sí, con cuidado y evaluando que no metas la pata.
