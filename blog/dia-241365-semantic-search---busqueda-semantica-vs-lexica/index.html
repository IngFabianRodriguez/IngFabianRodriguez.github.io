Que Es Busqueda Semantica

Hagale pues, parcero. Estamos en el Día 241 y hoy vamos a meternos en un tema que el 80% confunde con simple keyword matching: búsqueda semántica.

Aquí en Medellín, cuando uno busca en Google, pues uno escribe lo que piensa y espera que el motor entienda qué quiere decir. Eso es búsqueda semántica. Pero aquí viene el problema: el 90% de los sistemas de búsqueda en empresas aún usan matching de keywords. Y sí, funcionan. Pero no entienden qué significa lo que buscas.

La búsqueda semántica usa embeddings para representar el significado de las palabras y frases como vectores en un espacio de alta dimensión. Palabras con significados similares tendrán vectores cercanos en ese espacio.

Busqueda Lexica vs Semantica

Búsqueda léxica (BM25, TF-IDF):

  • Busca palabras exactas o similares en el texto
  • No entiende sinónimos ni contexto
  • "banco" siempre significa lo mismo
  • Funciona bien cuando sabes exactamente qué buscar

Búsqueda semántica (embeddings):

  • Entiende el significado y contexto
  • Maneja sinónimos y variaciones
  • "banco" puede ser financiero o mobiliario según contexto
  • Funciona bien para preguntas naturales

La Matematica Detras de Embeddings

Un embedding es un vector de números que representa texto. Para un modelo como text-embedding-ada-002, cada texto se convierte en un vector de 1536 dimensiones.

Distancia coseno: La similitud entre dos embeddings se mide con el coseno del ángulo entre ellos:

$$similarity(A, B) = \frac{A \cdot B}{||A|| \times ||B||} = cos(\theta)$$

Un coseno de 1 significa que los vectores apuntan en la misma dirección (muy similar). Un coseno de 0 significa que son ortogonales (no relacionados).

import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

def semantic_search(query: str, documents: list[str], embeddings_model) -> list[tuple[int, float]]:
    """
    Búsqueda semántica simple.
    
    Args:
        query: La pregunta del usuario
        documents: Lista de documentos donde buscar
        embeddings_model: Modelo para generar embeddings
    
    Returns:
        Lista de (index, similarity_score) ordenada por relevancia
    """
    # Generar embedding de la query
    query_embedding = embeddings_model.embed(query)
    
    # Generar embeddings de todos los documentos
    doc_embeddings = embeddings_model.embed_batch(documents)
    
    # Calcular similitud coseno entre query y cada documento
    similarities = cosine_similarity([query_embedding], doc_embeddings)[0]
    
    # Ordenar por similitud (mayor primero)
    results = sorted(enumerate(similarities), key=lambda x: x[1], reverse=True)
    
    return results

# Ejemplo de uso
documents = [
    "El banco central subió las tasas de interés",
    "Me senté en un banco del parque",
    "Los bancos deben garantizar la seguridad de los depósitos",
    "Había un banco de niebla cerca de la montaña",
]

query = "instituciones financieras"
results = semantic_search(query, documents, embeddings_model)

for idx, score in results:
    print(f"{score:.4f}: {documents[idx]}")

BM25: El Estandar de Busqueda Lexica

BM25 (Best Matching 25) es el algoritmo que usa Elasticsearch por defecto. Es una mejora sobre TF-IDF que considera la longitud del documento y la frecuencia de términos.

Fórmula BM25:

$$BM25(D, Q) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{avgdl})}$$

from rank_bm25 import BM25Okapi
import re

def build_bm25_index(documents: list[str]) -> BM25Okapi:
    """
    Construye un índice BM25 para búsqueda rápida.
    """
    # Tokenizar documentos
    tokenized_docs = [doc.lower().split() for doc in documents]
    
    # Crear índice BM25
    bm25 = BM25Okapi(tokenized_docs)
    
    return bm25

def lexical_search(query: str, bm25_index: BM25Okapi, documents: list[str], top_k: int = 5) -> list[tuple[int, float]]:
    """
    Búsqueda léxica con BM25.
    """
    # Tokenizar query
    query_tokens = query.lower().split()
    
    # Obtener scores para todos los documentos
    scores = bm25_index.get_scores(query_tokens)
    
    # Ordenar por score
    results = sorted(enumerate(scores), key=lambda x: x[1], reverse=True)[:top_k]
    
    return results

# Ejemplo
bm25 = build_bm25_index(documents)
results = lexical_search("bancos", bm25, documents)

for idx, score in results:
    print(f"{score:.4f}: {documents[idx]}")

Hybrid Search: Lo Mejor de Dos Mundos

Aquí es donde el 90% se confunde. BM25 es bueno para términos exactos (números, códigos, nombres propios). Embeddings son buenos para entender semántica. Por qué no combinar ambos?

def hybrid_search(
    query: str,
    documents: list[str],
    embeddings_model,
    bm25_index,
    alpha: float = 0.5,  # Ponderación: 0 = sólo BM25, 1 = sólo semántico
) -> list[tuple[int, float]]:
    """
    Búsqueda híbrida combinando BM25 y embeddings.
    
    El parámetro alpha controla el balance:
    - alpha=0: Solo BM25 (búsqueda léxica)
    - alpha=1: Solo semántica
    - alpha=0.5: Ambos pesan igual
    """
    # 1. Búsqueda semántica
    query_embedding = embeddings_model.embed(query)
    doc_embeddings = embeddings_model.embed_batch(documents)
    semantic_scores = cosine_similarity([query_embedding], doc_embeddings)[0]
    
    # Normalizar a [0, 1]
    semantic_scores = (semantic_scores - semantic_scores.min()) / (semantic_scores.max() - semantic_scores.min())
    
    # 2. Búsqueda BM25
    bm25_scores = np.array(bm25_index.get_scores(query.lower().split()))
    
    # Normalizar a [0, 1]
    if bm25_scores.max() > 0:
        bm25_scores = bm25_scores / bm25_scores.max()
    
    # 3. Combinar scores
    hybrid_scores = alpha * semantic_scores + (1 - alpha) * bm25_scores
    
    # 4. Ordenar resultados
    results = sorted(enumerate(hybrid_scores), key=lambda x: x[1], reverse=True)
    
    return results

# Ejemplo práctico
results = hybrid_search(
    query="entidades que manejan dinero",
    documents=documents,
    embeddings_model=embeddings_model,
    bm25_index=bm25,
    alpha=0.7  # Más peso a semántica
)

for idx, score in results:
    print(f"{score:.4f}: {documents[idx]}")

Reranking: Mejorando Resultados

El 80% se detiene en el retrieval inicial. Pero los resultados de embedding search no siempre están en el mejor orden. Aquí entra el reranking.

from sentence_transformers import CrossEncoder

def rerank_results(
    query: str,
    documents: list[str],
    initial_scores: list[float],
    reranker_model: CrossEncoder,
    top_k: int = 10
) -> list[tuple[int, float]]:
    """
    Mejora el orden de resultados usando un modelo de reranking.
    
    Cross-encoder pasa la query y documento juntos por el transformer,
    produciendo un score de relevancia más preciso que embedding + coseno.
    """
    # Crear pares query-documento para el reranker
    pairs = [(query, doc) for doc in documents]
    
    # Obtener scores de relevancia del reranker
    rerank_scores = reranker_model.predict(pairs)
    
    # Combinar con scores originales (opcional)
    combined_scores = 0.5 * np.array(initial_scores) + 0.5 * rerank_scores
    
    # Ordenar
    results = sorted(enumerate(combined_scores), key=lambda x: x[1], reverse=True)[:top_k]
    
    return results

# Uso
reranker = CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2')
initial_results = hybrid_search(query, documents, embeddings_model, bm25, alpha=0.7)
top_docs = [documents[i] for i, _ in initial_results[:20]]
top_scores = [s for _, s in initial_results[:20]]

final_results = rerank_results(query, top_docs, top_scores, reranker)

Resumen y Cierre

Hagale pues, parcero. Lo que nos queda es esto:

  • Búsqueda léxica (BM25): Buena para términos exactos, números, códigos. No entiende sinónimos.
  • Búsqueda semántica (embeddings): Entiende contexto y significado. Sensible a sinónimos pero puede perder precisión con términos exactos.
  • Hybrid search: Combina lo mejor de ambos mundos. El alpha controlando el balance.
  • Reranking: Mejora el orden final usando modelos especializados.

En Medellín decimos que "cada cosa tiene su lugar". Para búsqueda es igual: BM25 para cosas exactas, embeddings para significado, y hybrid para cuando quieres ambos.
