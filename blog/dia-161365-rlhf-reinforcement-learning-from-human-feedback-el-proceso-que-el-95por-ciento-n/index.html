LlamaIndex vs LangChain — El 75% elige sin investigar y se arrepiente

11 de may de 2026
llamaindex langchain

Hola, parcero. Llegamos al Día 161 y hoy vamos con un tema que genera más confusión que un partido de Atlético Nacional en los últimos minutos: LlamaIndex vs LangChain. El 75% de los desarrolladores que conozco eligen sin investigar y después se arrepienten cuando el pipeline no escala o cuando el agent hace cosas que no deberían. Acompañame que esto va detallado.

📐 Fundamentos Teóricos

Antes de escribir una sola línea de código, necesitamos entender qué son realmente estos frameworks. Y aquí es donde la mayoría falla.

¿Qué es LlamaIndex?

LlamaIndex (antes GPT-Index) es fundamentalmente un framework de indexación y retrieval. Su valor central es construir interfaces entre tus datos y los LLMs. Piensa en ello como un librarian profesional: organiza tus documentos, entiende cómo buscarlos, y recupera exactamente lo que necesitas.

La arquitectura se basa en:

  • Indices: estructuras de datos que organizan información para retrieval eficiente
  • Nodos: unidades básicas de información (chunks de texto)
  • Consultas: motores que atraviesan los índices para encontrar información relevante

¿Qué es LangChain?

LangChain es un framework de desarrollo de aplicaciones LLM que incluye agents, chains, y herramientas. Si LlamaIndex es un bibliotecario, LangChain es más bien un director de orquesta: coordina múltiples pasos, herramientas, y decisiones.

Sus componentes principales:

  • Chains: secuencias de operaciones que encadenan LLMs con otras funciones
  • Agents: sistemas que usan LLMs para decidir qué acciones tomar
  • Tools: interfaces para que los agents interactúen con el mundo real

La matemática detrás del retrieval

El corazón de RAG (Retrieval-Augmented Generation) es la búsqueda por similitud. Usamos embeddings vectoriales:

$$similaridad(a, b) = cos(θ) = \frac{a \cdot b}{||a|| \cdot ||b||}$$

Donde a y b son vectores de embedding. Cuanto más cercano a 1, más similar es el contenido. Esto es lo que permite encontrar documentos relevantes semanticamente, no solo por keywords.

💻 Implementación Práctica

Construir un RAG Pipeline con LlamaIndex

# RAG Pipeline con LlamaIndex
from llama_index import VectorStoreIndex, SimpleDirectoryReader
from llama_index.llms import OpenAI

# Cargar documentos desde un directorio
documents = SimpleDirectoryReader('./data').load_data()

# Configurar el LLM
llm = OpenAI(model='gpt-4', temperature=0.7)

# Crear el índice vectorial
index = VectorStoreIndex.from_documents(
    documents,
    llm=llm
)

# Crear un motor de query
query_engine = index.as_query_engine(
    similarity_top_k=3,
    verbose=True
)

# Hacer preguntas
response = query_engine.query(
    "¿Cuáles son los principales desafíos de implementar RAG en producción?"
)
print(response)

Construir un Agent con LangChain

# Agent con LangChain
from langchain.agents import AgentExecutor, create_openai_functions_agent
from langchain.tools import Tool
from langchain import OpenAI
from langchain.prompts import ChatPromptTemplate

# Definir herramientas personalizadas
def buscar_en_base_datos(query: str) -> str:
    """Busca información en la base de datos de productos."""
    # Lógica de búsqueda
    return f"Resultados para '{query}': producto A, producto B"

def calcular_metrics(datos: str) -> str:
    """Calcula métricas de rendimiento."""
    # Lógica de cálculo
    return "Métricas calculadas: precisión 94%, recall 87%"

tools = [
    Tool(
        name="buscar_productos",
        func=buscar_en_base_datos,
        description="Útil para buscar productos en el catálogo"
    ),
    Tool(
        name="calcular_metricas",
        func=calcular_metrics,
        description="Útil para calcular métricas de rendimiento"
    )
]

# Crear el agent
llm = OpenAI(temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", "Eres un asistente que ayuda con análisis de productos."),
    ("human", "{input}"),
    ("ai", "{agent_scratchpad}")
])

agent = create_openai_functions_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# Ejecutar
result = agent_executor.invoke({"input": "Busca los productos más vendidos y calcúlame las métricas"})

🔬 Math Behind the Scenes

La eficiencia de un RAG pipeline depende de varios factores matemáticos:

Tasa de Retrieval Efectiva

$$P(recall) = \frac{TP}{TP + FN}$$

Donde TP son los documentos relevantes recuperados correctamente y FN son los relevantes que no se recuperaron.

Latencia del Pipeline

$$L_{total} = L_{retrieval} + L_{llm} + L_{postprocess}$$

Esta ecuación es crucial: encadenar demasiadas operaciones (el Error 3 que veremos) hace que la latencia se dispara porque cada componente suma.

🚨 Errores Comunes (y sus fixes)

Error 1: Elegir framework por popularity en vez de por fit

El error más común que veo, parcero. Ves que LangChain tiene 50k estrellas en GitHub y piensas "entonces es el mejor". Grave error.

El problema: La popularidad no mide fitness para tu caso de uso específico.

El fix: Antes de elegir, responde estas preguntas:

  • ¿Tu caso de uso es principalmente retrieval/QA sobre documentos? → LlamaIndex
  • ¿Necesitas agents que usen múltiples herramientas secuencialmente? → LangChain
  • ¿Ambas cosas? → Considera usar ambos, pero integrados cuidadosamente
# NO HAGAS ESTO - Elegir por popularity
from langchain import everything  # Mal porque sí

# HAZ ESTO - Elegir por fit
if necesita_solo_rag:
    from llama_index import VectorStoreIndex
elif necesita_agents_complejos:
    from langchain.agents import create_openai_functions_agent
elif necesita_ambos:
    # Integración cuidadosa
    from llama_index import VectorStoreIndex
    from langchain.agents import AgentExecutor

Error 2: No entender que ambos son abstracciones que esconden complejidad

Aquí es donde muchos se queman. Instalan LlamaIndex, escriben tres líneas, funciona "perfectamente", y cuando lo llevan a producción... caos.

El problema: Estos frameworks abstracten detalles importantes. Cuando algo falla, no sabes qué está pasando debajo.

El fix: Entiende las capas:

# Entender qué pasa debajo de las abstracciones
from llama_index import VectorStoreIndex

# En lugar de solo esto:
index = VectorStoreIndex.from_documents(documents)

# Entiende las capas:
# 1. Embedding: cómo se convierten los documentos a vectores
from llama_index.embeddings import OpenAIEmbedding
embedding_model = OpenAIEmbedding()

# 2. Chunking strategy: cómo se dividen los documentos
# 3. Vector store: dónde se almacenan los vectores
# 4. Retrieval: cómo se buscan los más similares

# Haz logging para entender qué pasa
import logging
logging.basicConfig(level=logging.DEBUG)

Error 3: Encadenar demasiadas operaciones (causando latency)

Este es el error que más duele en producción. Piensas "voy a encadenar 10 tools en mi agent" o "voy a hacer retrieval de 5 índices diferentes".

El problema: La latencia crece exponencialmente con cada paso encadenado:

$$L_{total} = \sum_{i=1}^{n} L_i + \sum_{j=1}^{n-1} O_{transition_j}$$

Donde L_i es la latencia de cada paso y O_{transition_j} es el overhead de transición entre pasos.

El fix: Aplica estos principios:

  • Parallelization: Cuando sea posible, ejecuta operaciones en paralelo
  • Caching: Cachea resultados de operaciones costosas
  • Early stopping: Detén la cadena cuando tengas suficiente confianza en la respuesta
  • Chunking inteligente: No recuperes más documentos de los necesarios
# FIX: Usar parallelization y caching
from llama_index import VectorStoreIndex
from llama_index.storage.docstore import SimpleDocumentStore
from llama_index.storage.index_store import SimpleIndexStore
from llama_index.storage import StorageContext
from concurrent.futures import ThreadPoolExecutor

# Configurar cache
storage_context = StorageContext.from_defaults(
    docstore=SimpleDocumentStore(),
    index_store=SimpleIndexStore()
)

# Retrieval con límites
query_engine = index.as_query_engine(
    similarity_top_k=3,  # No más de 3
    node_postprocessors=[...]  # Filtros adicionales
)

# Para agents: early stopping
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    max_iterations=5,  # Límite de pasos
    early_stopping_method="force"  # Forzar detención
)

✅ Mejores Prácticas

  • Evalúa antes de elegir: Usa prototipos pequeños con ambos frameworks antes decommitirte
  • Entiende las abstracciones: Lee el código fuente de las capas que usas
  • Monitorea latencia: Cada paso en una cadena debe ser medido
  • Usa hybrid search: Combina búsqueda vectorial con keyword search para mejor recall
  • Implementa retry logic: Los LLMs fallan; tu pipeline debe manejarlo
