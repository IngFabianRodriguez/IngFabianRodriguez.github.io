ONNX - Modelos Portables Entre Frameworks

07 de septiembre de 2026

Hagale pues, mi gente

Qué más pues, mi gente querida. Llegamos al Día 250 — sí, doscientos cincuenta — y hoy vamos a hablar de algo que el 70% de los developers ignoran y pagan el precio: ONNX y la portabilidad de modelos. Entrenaste tu modelo en PyTorch, pero tu producción corre en TensorFlow. O necesitas hacer inference en el edge. O quieres usar un runtime optimizado. Sin ONNX, estás stuck.

ONNX (Open Neural Network Exchange) es el puente que te permite entrenar en un framework y deployar en otro. No es magia — tiene sus limitaciones — pero cuando funciona, te salva de muchos dolores de cabeza. Café listo, que esto está buenísimo.

El Problema: El Fragging de Frameworks

Mira la realidad del ecosistema ML hoy:

  • Entrenas en PyTorch (el standard para investigación)
  • Quieres hacer serving con TensorFlow (o viceversa)
  • Deployas a ONNX Runtime para velocidad
  • Tu edge device usa TensorRT o Core ML

Sin un formato común, cada transición es un pain. Y el 80% de la gente o no sabe que existe ONNX, o sabe pero no lo usa correctamente.

La matemática del problema:

# Sin ONNX: múltiples conversiones manuales
conversions_without_onnx = {
    "PyTorch -> TensorFlow": "No directo, requiere trabajo manual",
    "PyTorch -> TensorRT": "Solo via ONNX o plugins propietarios",
    "TensorFlow -> Core ML": "TF Lite primero, luego manualmente",
    "PyTorch -> ONNX -> Cualquiera": "Conversión estándar y soportada",
}

print("Sin ONNX: Conversiones ad-hoc, propensas a errores")
print("Con ONNX: Un formato, múltiples targets")

Qué es ONNX

ONNX es un formato abierto que representa modelos de ML como un computational graph. Define operaciones (ops) de forma neutral al framework y un formato de serialización estándar.

Un modelo ONNX es básicamente:

  • Un graph de operaciones (nodes)
  • Tensores de input/output
  • Atributos de cada operación (constantes)
  • Metadata (nombre, versión, producer)
# Estructura de un modelo ONNX (simplificado)
onnx_model = {
    "ir_version": 8,  # Versión del IR de ONNX
    "opset_import": [14],  # Versión de opset (operaciones disponibles)
    "graph": {
        "node": [
            {"op": "Conv", "inputs": ["x", "w"], "outputs": ["y"]},
            {"op": "Relu", "inputs": ["y"], "outputs": ["y2"]},
            # ... más nodes
        ],
        "initializer": [w],  # Pesos como constantes
        "input": [{"name": "x", "type": "tensor(float)"}],
        "output": [{"name": "y2", "type": "tensor(float)"}],
    },
    "producer_name": "pytorch",
    "producer_version": "2.0.1",
}

PyTorch a ONNX: Lo Básico

La conversión más común: PyTorch a ONNX. PyTorch tiene soporte nativo para exportar a ONNX.

import torch
import torch.nn as nn

# Un modelo simple
class SimpleModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 16, kernel_size=3, padding=1)
        self.relu = nn.ReLU()
        self.conv2 = nn.Conv2d(16, 3, kernel_size=3, padding=1)
    
    def forward(self, x):
        x = self.conv1(x)
        x = self.relu(x)
        x = self.conv2(x)
        return x

model = SimpleModel()
model.eval()

# Input dummy (requerido para traced models)
dummy_input = torch.randn(1, 3, 224, 224)

# Exportar a ONNX
torch.onnx.export(
    model,
    dummy_input,
    "model.onnx",
    export_params=True,
    opset_version=14,  # Versión de operadores
    do_constant_folding=True,  # Optimización: plegar constantes
    input_names=["input"],  # Nombres para inputs
    output_names=["output"],
    dynamic_axes={  # Dimensiones dinámicas (batch size variable)
        "input": {0: "batch_size"},
        "output": {0: "batch_size"},
    },
)
print("Modelo exportado a ONNX")

Validando el Modelo ONNX

Antes de usar el modelo, siempre valídalo. ONNX tiene un checker que verifica la integridad del graph:

import onnx

# Cargar el modelo
model = onnx.load("model.onnx")

# Verificar estructura
onnx.checker.check_model(model)
print("Modelo ONNX válido ✓")

# Ver información del modelo
print(f"Inputs: {[inp.name for inp in model.graph.input]}")
print(f"Outputs: {[out.name for out in model.graph.output]}")
print(f"Opset: {model.opset_import[0].version}")

ONNX Runtime: Inference Rápida y Portable

ONNX Runtime (ORT) es el runtime de Microsoft para inference de modelos ONNX. Es:

  • 20-60% más rápido que PyTorch/TensorFlow en CPU
  • Soporta GPU, CPU, y edge devices
  • Gratuito y open source
import onnxruntime as ort

# Crear sesión de inference
session = ort.InferenceSession(
    "model.onnx",
    providers=["CPUExecutionProvider"]  # or "CUDAExecutionProvider"
)

# Obtener nombres de inputs/outputs
input_name = session.get_inputs()[0].name
output_name = session.get_outputs()[0].name

# Inference
import numpy as np
input_data = np.random.randn(1, 3, 224, 224).astype(np.float32)

result = session.run([output_name], {input_name: input_data})
print(f"Output shape: {result[0].shape}")

Optimizaciones con ONNX Runtime

ONNX Runtime tiene optimizaciones automáticas que pueden mejorar performance significativamente:

# Session options para optimizar
sess_options = ort.SessionOptions()

# Optimizaciones de graph
sess_options.graph_optimization_level = ort.GraphOptimizationLevel.ORT_ENABLE_ALL

# Paralelismo
sess_options.intra_op_num_threads = 4  # Threads por operación
sess_options.inter_op_num_threads = 2  # Paralelismo entre operaciones

# Memory optimization
sess_options.enable_mem_pattern = True  # Patrones de memoria más eficientes
sess_options.enable_cpu_mem_arena = True  # Arena de memoria compartida

session = ort.InferenceSession(
    "model.onnx",
    sess_options,
    providers=["CPUExecutionProvider"]
)

# Inference con timing
import time
iterations = 100

start = time.time()
for _ in range(iterations):
    result = session.run([output_name], {input_name: input_data})
elapsed = time.time() - start

print(f"Average inference time: {elapsed/iterations*1000:.2f} ms")

Problemas Comunes y Soluciones

Problema 1: Operaciones No Soportadas

El problema: Intentas exportar a ONNX y te dice que cierta operación no está soportada en el opset destino.

La solución: Usa un opset más nuevo (el 14 es común) o implementa un custom op. También puedes usar symbolic_gpt para definir comportamiento de ops custom.

# Verificar opset disponible
import torch
print(f"PyTorch export support opset: {torch.onnx.export_opset_version}")

# Si necesitas un opset específico
torch.onnx.export(
    model,
    dummy_input,
    "model.onnx",
    opset_version=15,  # Más reciente = más operaciones
)

Problema 2: Dynamic Shapes

El problema: Tu modelo tiene batch size variable pero la exportación no lo maneja bien.

La solución: Especifica dynamic_axes claramente. Esto permite que ONNX acepte inputs de diferentes tamaños en inference.

torch.onnx.export(
    model,
    dummy_input,
    "model.onnx",
    dynamic_axes={
        "input": {0: "batch_size", 2: "height", 3: "width"},
        "output": {0: "batch_size"},
    },
)
# Ahora puedes hacer inference con cualquier batch_size y tamaño de imagen

Problema 3: Dype Mismatch

El problema: Tu modelo usa float64 o float16 pero ONNX espera float32.

La solución: Homogeniza a float32 antes de exportar, o especifica el dtype correcto en ONNX.

# Forzar float32 durante exportación
with torch.float32:
    torch.onnx.export(model, dummy_input.float(), "model.onnx")

# O convertir el modelo explícitamente
model = model.to(torch.float32)
torch.onnx.export(model, dummy_input, "model.onnx")

ONNX en Edge Devices

ONNX brilla especialmente cuando necesitas deployar en edge. Hay runtime para todo:

  • ONNX Runtime Mobile: iOS y Android
  • TensorRT: NVIDIA GPUs (conversión via ONNX)
  • Core ML: Apple devices (via ONNX → Core ML converter)
  • WebAssembly: Browser-based inference
# Ejemplo: Cuantización post-export para reducir tamaño
from onnxruntime.quantization import quantize_dynamic, QuantType

# Cuantizar a INT8 dinámicamente (los pesos se quantizan, no el computation)
quantize_dynamic(
    model_input="model.onnx",
    model_output="model_int8.onnx",
    weight_type=QuantType.QInt8,
)

import os
original_size = os.path.getsize("model.onnx") / (1024*1024)
quantized_size = os.path.getsize("model_int8.onnx") / (1024*1024)
print(f"Original: {original_size:.1f} MB")
print(f"Cuantizado: {quantized_size:.1f} MB")
print(f"Reducción: {(1 - quantized_size/original_size)*100:.1f}%")

Resumen: Tu Checklist de ONNX

  • Exporta desde el framework de origen: No intentes convertir entre formatos de forma indirecta.
  • Usa opset reciente: Versión 14 o 15 para máximo soporte de operaciones.
  • Valida siempre post-export: Usa onnx.checker.check_model() antes de deployar.
  • Configura dynamic_axes: Para batch size variable y otros dims que cambian.
  • Usa ONNX Runtime para inference: 20-60% más rápido que frameworks originales en CPU.
  • Cuantiza post-export si necesitas: INT8 o INT4 pueden reducir tamaño 4-8x con poca pérdida de accuracy.
