Por Que Importan Las Arquitecturas

En ML, la arquitectura es todo. No es solo "elija un modelo" — es entender:

  • Como la arquitectura maneja el tradeoff compute vs accuracy
  • Que innovations matematicas la hacen destacar
  • Cuando una arquitectura más simple es mejor que la latest-and-greatest

La diferencia entre elegir bien o mal una arquitectura puede ser 10x en costo de entrenamiento e inferencia, y diferencias sustanciales en performance.

Arquitecturas de Vision

ResNet (2015) — La Baseline Indispensable

ResNet introdujo las residual connections: atajos que permiten a la informacion fluir directamente de capas anteriores a capas posteriores sin pasar por transformation no lineal.

La formula:

$$\mathbf{y} = \mathcal{F}(\mathbf{x}, \{W_i\}) + \mathbf{x}$$

Donde $\mathcal{F}$ es el learned residual mapping y $\mathbf{x}$ es la identidad (skip connection).

import torch
import torch.nn as nn

class ResidualBlock(nn.Module):
    def __init__(self, in_channels, out_channels, stride=1):
        super().__init__()
        self.conv1 = nn.Conv2d(in_channels, out_channels, 3, stride, 1, bias=False)
        self.bn1 = nn.BatchNorm2d(out_channels)
        self.conv2 = nn.Conv2d(out_channels, out_channels, 3, 1, 1, bias=False)
        self.bn2 = nn.BatchNorm2d(out_channels)
        
        # Skip connection: match dimensions if needed
        self.shortcut = nn.Sequential()
        if stride != 1 or in_channels != out_channels:
            self.shortcut = nn.Sequential(
                nn.Conv2d(in_channels, out_channels, 1, stride, bias=False),
                nn.BatchNorm2d(out_channels)
            )
    
    def forward(self, x):
        out = torch.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        out += self.shortcut(x)  # Skip connection
        return torch.relu(out)

# ResNet-50: 50 layers, skip connections every 2 convolutions
# Innovation: permite train networks mucho más profundas sin degradation

Cuando usar ResNet: Baseline para casi cualquier task de vision. Si no sabes que usar, empieza con ResNet-50 o ResNet-101.

EfficientNet (2019) — Compound Scaling

EfficientNet introdujo el compound scaling: escalar depth, width, y resolution de forma balanceada usando un factor $\phi$:

$$\text{depth}: d = \alpha^\phi$$ $$\text{width}: w = \beta^\phi$$ $$\text{resolution}: r = \gamma^\phi$$

Sujeto a: $\alpha \times \beta^2 \times \gamma^2 \approx 2$

# EfficientNet-B0 baseline: α=1.2, β=1.1, γ=1.15
# EfficientNet-B7: φ=7, accuracy de ResNet-200 con 5.3M params vs 64M

import timm

# 4 lineas para usar EfficientNet
model = timm.create_model('efficientnet_b3', pretrained=True)
# B0: 5.3M params, 224x224
# B3: 12M params, 300x300
# B7: 66M params, 600x600

# Auto AUGment: data augmentation aprendido
# Si requires mejor accuracy y tienes budget computacional, EfficientNet es mejor eleccion que ResNet

Cuando usar EfficientNet: Cuando necesitas mejor accuracy que ResNet con menos parametros. B0-B3 para mobile/edge, B4-B7 para servidores.

ViT (Vision Transformer) — Attention Para Vision

Vision Transformer (2020) aplica transformer architecture (originalmente para NLP) a imagenes:

  1. Dividir imagen en patches de 16x16
  2. Flatten cada patch a vector
  3. Apply positional embeddings
  4. Procesar con transformer encoder
import torch
from transformers import ViTForImageClassification

model = ViTForImageClassification.from_pretrained(
    'google/vit-base-patch16-224',
    num_labels=1000
)

# 16x16 patches, 224x224 input = 14x14 = 196 patches
# Cada patch es un "token" en el transformer
# Global average pooling al final para clasificacion

# Ventaja: scales mejor con mas data que CNNs
# Desventaja: requiere mucho mas data para train from scratch

Cuándo usar ViT: Tienes mucho data labeling budget y necesitas state-of-the-art en ImageNet. Fine-tuning con pretrained es essential para datasets pequenos.

Swin Transformer — Hierarquia + Shifted Windows

Swin resolve el problema de ViT (O(n^2) attention sobre toda la imagen) con una window-based attention hierarchical:

# Swin-T: 28M params, 224x224, 81.3% top-1 ImageNet
# Swin-S: 50M params, 224x224, 83.0% top-1
# Swin-B: 88M params, 224x224, 83.5% top-1

model = timm.create_model('swin_base_patch4_window7_224', pretrained=True)

# Shifted windows: cada layer alterna la window partition
# Hierarchical: reduce resolution 2x mientras aumenta canales (C -> 2C -> 4C -> 8C)
# 4 stages de resolution reducida
# Mejor que ViT vanilla para dense prediction (detection, segmentation)

Cuándo usar Swin: Object detection, semantic segmentation, cualquier task que necesite fine-grained spatial reasoning. Es el encoder backbone mas popular para MMDetection.

Arquitecturas de Lenguaje / Multimodal

GPT Family — Autoregressive Language Models

GPT (Generative Pretrained Transformer) usa un decoder-only transformer con causal masking:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}} + M\right)V$$

Donde $M$ es una mascara que impide attending a futuros tokens.

from transformers import GPT2LMHeadModel, GPT2Tokenizer

model = GPT2LMHeadModel.from_pretrained('gpt2')
tokenizer = GPT2Tokenizer.from_pretrained('gpt2')

# GPT-2: 1.5B params, 50257 vocab, 1024 context
# GPT-3: 175B params,2048 context
# GPT-4: rumored 1.8T params (Mixture of Experts?)

# Autoregressive: genera token by token
# P(t) = softmax(W_e * f(t-1, t-2, ..., t-n))
# Muy bueno para generacion creativa, coding, instruction following

# Fine-tune con instruction data para ChatGPT-style models
# RLHF: Reinforcement Learning from Human Feedback para alignment

T5 — Encoder-Decoder para Seq2Seq

T5 (Text-to-Text Transfer Transformer) trata todo como seq2seq: translation, summarization, QA — todos el mismo modelo con diferentes prefixes.

from transformers import T5ForConditionalGeneration, T5Tokenizer

model = T5ForConditionalGeneration.from_pretrained('t5-small')
tokenizer = T5Tokenizer.from_pretrained('t5-small')

# T5-small: 60M params
# T5-base: 220M params
# T5-large: 770M params

# "Translate English to German: Hello world"
# "Summarize: El texto largo va aqui..."
# "Question: {question} Context: {context}"

# Encoder-decoder: input completo visible, output generado auto-regresivamente
# Mejor que GPT para tareas de entendimiento (QA, summarization, translation)

CLIP — Contrastive Language-Image Pretraining

CLIP aprende a alinear imagenes y texto en el mismo embedding space usando contrastive learning:

$$\mathcal{L} = -\frac{1}{N} \sum_i \log \frac{\exp(\text{sim}(I_i, T_i) / \tau)}{\sum_j \exp(\text{sim}(I_i, T_j) / \tau)}$$

import torch
from transformers import CLIPProcessor, CLIPModel

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

# Zero-shot image classification
image = Image.open("dog.jpg")
text = ["a dog", "a cat", "a car"]
inputs = processor(text=text, images=image, return_tensors="pt", padding=True)
outputs = model(**inputs)
logits_per_image = outputs.logits_per_image
probs = logits_per_image.softmax(dim=1)

# 400M image-text pairs para pretraining
# Zero-shot transfer a cualquier dataset de classificacion
# Muy bueno para retrieval, content moderation, image generation conditioning (DALL-E, Stable Diffusion)

Codigo: Framework de Comparacion

"""
Framework para comparar arquitecturas de ML
Benchmark apples-to-apples entre diferentes models
"""
import time
import torch
from dataclasses import dataclass
from typing import List, Dict, Callable
from transformers import AutoModel, AutoTokenizer
import timm

@dataclass
class ModelBenchmark:
    name: str
    params: int
    throughput: float  # samples/second
    accuracy: float
    memory_mb: int
    latency_ms: float

def benchmark_vision_models(models: List[str], input_size=(224, 224)) -> List[ModelBenchmark]:
    """Benchmark modelos de vision en GPU"""
    results = []
    
    for model_name in models:
        # Load model
        model = timm.create_model(model_name, pretrained=True, num_classes=1000)
        model = model.cuda().eval()
        
        # Count parameters
        params = sum(p.numel() for p in model.parameters()) / 1e6
        
        # Memory
        torch.cuda.empty_cache()
        torch.cuda.reset_peak_memory_stats()
        dummy_input = torch.randn(1, 3, *input_size).cuda()
        
        with torch.no_grad():
            # Warmup
            for _ in range(5):
                _ = model(dummy_input)
            
            # Benchmark
            torch.cuda.synchronize()
            start = time.time()
            for _ in range(100):
                _ = model(dummy_input)
            torch.cuda.synchronize()
            elapsed = time.time() - start
        
        memory = torch.cuda.max_memory_allocated() / 1e6
        throughput = 100 * 1000 / elapsed  # samples/sec
        
        results.append(ModelBenchmark(
            name=model_name,
            params=params,
            throughput=throughput,
            accuracy=0.0,  # Fill in from literature
            memory_mb=memory,
            latency_ms=elapsed / 100 * 1000
        ))
        
        print(f"{model_name}: {params:.1f}M params, {throughput:.1f} samples/sec")
    
    return results

def benchmark_language_models(models: List[str], seq_length: int = 128) -> List[ModelBenchmark]:
    """Benchmark modelos de lenguaje en GPU"""
    results = []
    
    for model_name in models:
        model = AutoModel.from_pretrained(model_name).cuda().eval()
        tokenizer = AutoTokenizer.from_pretrained(model_name)
        
        params = sum(p.numel() for p in model.parameters()) / 1e6
        
        torch.cuda.empty_cache()
        dummy_input = torch.randint(0, 1000, (1, seq_length)).cuda()
        
        with torch.no_grad():
            # Warmup
            for _ in range(3):
                _ = model(dummy_input)
            
            torch.cuda.synchronize()
            start = time.time()
            for _ in range(50):
                _ = model(dummy_input)
            torch.cuda.synchronize()
            elapsed = time.time() - start
        
        memory = torch.cuda.max_memory_allocated() / 1e6
        throughput = 50 * 1000 / elapsed
        
        results.append(ModelBenchmark(
            name=model_name,
            params=params,
            throughput=throughput,
            accuracy=0.0,
            memory_mb=memory,
            latency_ms=elapsed / 50 * 1000
        ))
        
        print(f"{model_name}: {params:.1f}M params, {throughput:.1f} tokens/sec")
    
    return results

# Decision framework:
def choose_architecture(task: str, budget: str, data_size: str) -> str:
    """
    task: 'classification', 'detection', 'generation', 'translation', 'qa'
    budget: 'low' (< 10M params), 'medium' (10-100M), 'high' (> 100M)
    data_size: 'small' (< 100K), 'medium' (100K-1M), 'large' (> 1M)
    """
    if task == 'classification':
        if budget == 'low':
            return 'EfficientNet-B0 o ResNet-34'
        elif budget == 'medium':
            return 'EfficientNet-B3 o Swin-Tiny'
        else:
            return 'Swin-Base o ViT-Large'
    
    elif task == 'detection':
        return 'Swin (cualquier tamano) - mejor para dense prediction'
    
    elif task == 'generation':
        if budget == 'low':
            return 'GPT-2 small (~100M)'
        else:
            return 'GPT-3 o GPT-4 (API)'
    
    elif task == 'translation':
        return 'T5 (cualquier tamano) - encoder-decoder es mejor para seq2seq'
    
    elif task == 'qa':
        return 'T5 o FLAN-T5 (instruction-tuned)'
    
    elif task == 'multimodal':
        return 'CLIP para retrieval, BLIP para captioning, GPT-4V para VQA'

3 Errores Fatalisimos

Error 1: Usar "Latest and Greatest" Sin Considerar Tradeoffs

El problema: La tendencia es adoptar Swin/ViT para todo, pero:

  • ViT necesita mucho mas data para training from scratch
  • Swin tiene mas overhead que ResNet para inference en imagenes pequenas
  • Modelos grandes como GPT-4 son overkill si solo necesitas classification de emociones

El fix: Antes de elegir, responde: "Cual es mi budget computacional?" Si tienes GPU pequena, EfficientNet-B0 >> ViT. Si tienes 100K imagenes, ResNet-50 con transfer learning > ViT from scratch.

"El mejor modelo no es el mas grande — es el que fit en tu budget y resuelve tu problema."

Error 2: No Entender Las Innovations Que Importan Para Tu Use Case

El problema: La gente dice "vamos a usar transformer porque es state-of-the-art" sin entender por que transformers funcionan:

  • ResNet: skip connections permiten networks profundas sin degradation
  • EfficientNet: compound scaling optimizado empiricamente
  • Swin: hierarchical attention reduce complexity de O(n^2) a O(n)
  • CLIP: contrastive learning permite zero-shot transfer

El fix: Lee los papers originales — solo 10 pages cada uno. Entiende la contribucion clave. Esto te dice cuando aplicar cada arquitectura y cuando no.

Error 3: Ignorar Efficiency Tradeoffs (Big Model != Best Model)

El problema: Big model ≠ best model para tu aplicacion. Ejemplos:

  • GPT-4 (rumored 1.8T params) vs GPT-3.5 (~20B): para la mayoria de用例, GPT-3.5 es suficiente y 10x mas barato
  • Swin-L (197M) vs Swin-S (50M): Swin-S es casi igual de accurate con la mitad del compute
  • EfficientNet-B7 (66M) vs B3 (12M): B3 es 5x mas rapido, solo 2-3% menos accurate

El fix: Haz el benchmark! No asumas que el mas grande es mejor. En produccion, el tradeoff accuracy vs latency/costo casi siempre favorece al modelo mas pequeno y especializado.

Resumen y Cierre

Las arquitecturas de ML evolucionan rapido, pero los fundamentals permanecen. ResNet establecio skip connections como essential. EfficientNet mostro que compound scaling es la forma correcta de escalar. ViT trajo attention a vision. Swin resolved el scaling problem de transformers. T5 unified NLP tasks. CLIP connected vision y language.

Los puntos clave:

  • Vision: ResNet (baseline), EfficientNet (efficiency), Swin (dense tasks), ViT (high data)
  • Language: GPT (autoregressive generation), T5 (seq2seq), BERT (encoding — no lo mencione antes pero es essencial para embeddings)
  • Multimodal: CLIP (alignment), BLIP (captioning), GPT-4V (VQA)

El skill real no es memorizar architectures — es saber cual elegir dado tu problema, tu data, y tu budget. Eso es lo que el 90% que busca en documentacion dispersa nunca aprende.
