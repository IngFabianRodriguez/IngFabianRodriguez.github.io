Time Series Forecasting — LSTM vs Transformers para Series Temporales

19 de julio de 2026

Hagámosle pues, parcero. Día 200, nada menos. Hoy vamos a meternos en un tema que es clave para cualquier proyecto de datos en producción: cómo predecir valores futuros usando series temporales. LSTM, Transformers, N-BEATS — tres approaches completamente diferentes, cada uno con sus ventajas. Cogemos el café y vamos pa'llá.

¿Qué Es Time Series Forecasting?

El forecasting de series temporales es la técnica de predecir valores futuros basándose en datos históricos ordenados cronológicamente. A diferencia de un problema de regresión normal, aquí el orden temporal importa mucho — el valor de mañana depende de lo que pasó hoy, ayer, y así sucesivamente.

Ejemplos en la vida real:

  • Ventas: Predecir cuántas arepas va a vender una tienda mañana
  • Finanzas: Predecir el precio de una acción o el riesgo de crédito
  • Energía: Forecast de demanda eléctrica para调度 generación
  • Clima: Temperatura, precipitación, calidad del aire
  • IoT: Predecir mantenimiento de equipos antes de que fallen

La formulación matemática es: dado

$$X = {x_1, x_2, ..., x_t}$$

, queremos predecir

$$x_{t+h}$$

donde h es el horizon de predicción. El objetivo es minimizar el error entre

$$\hat{x}_{t+h}$$

y

$$x_{t+h}$$

.

Los Tres Grandes: LSTM, Transformer, N-BEATS

1. LSTM — El Clásico del Deep Learning para Secuencias

Las LSTM (Long Short-Term Memory) son un tipo de RNN diseñada para capturar dependencias a largo plazo en secuencias. Introducen compuertas (gates) que controlan qué información olvidar, qué recordar, y qué输出的.

La matemática detrás:

  • Forget Gate:

    $$f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f)$$

    — qué información olvidar
  • Input Gate:

    $$i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i)$$

    — qué información nueva agregar
  • Cell State:

    $$C_t = f_t * C_{t-1} + i_t * \tilde{C}_t$$

    — estado actualizado
  • Output Gate:

    $$o_t = \sigma(W_o \cdot [h_{t-1}, x_t] + b_o)$$

    — qué hidden state输出
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

class LSTMForecaster(nn.Module):
    """
    LSTM para predicción de series temporales.
    Predice el siguiente valor dado una secuencia de entrada.
    """
    def __init__(self, input_dim=1, hidden_dim=64, num_layers=2, output_dim=1, dropout=0.2):
        super().__init__()
        self.hidden_dim = hidden_dim
        self.num_layers = num_layers
        
        # LSTM layer
        self.lstm = nn.LSTM(
            input_size=input_dim,
            hidden_size=hidden_dim,
            num_layers=num_layers,
            batch_first=True,  # (batch, seq, features)
            dropout=dropout if num_layers > 1 else 0
        )
        
        # Output layer
        self.fc = nn.Linear(hidden_dim, output_dim)
    
    def forward(self, x):
        # x shape: (batch, seq_len, input_dim)
        lstm_out, (h_n, c_n) = self.lstm(x)
        # Usamos el último hidden state
        last_hidden = lstm_out[:, -1, :]
        prediction = self.fc(last_hidden)
        return prediction


def create_sequences(data, seq_length):
    """Crea secuencias de entrada y objetivos para training."""
    X, y = [], []
    for i in range(len(data) - seq_length):
        X.append(data[i:i+seq_length])
        y.append(data[i+seq_length])
    return torch.FloatTensor(X), torch.FloatTensor(y)


def train_lstm_model(X_train, y_train, epochs=100, hidden_dim=64, num_layers=2, lr=1e-3):
    """Entrena el modelo LSTM."""
    device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
    print(f"Entrenando LSTM en: {device}")
    
    model = LSTMForecaster(
        input_dim=X_train.shape[-1],
        hidden_dim=hidden_dim,
        num_layers=num_layers
    ).to(device)
    
    X_tensor = X_train.to(device)
    y_tensor = y_train.to(device)
    
    dataset = TensorDataset(X_tensor, y_tensor)
    dataloader = DataLoader(dataset, batch_size=64, shuffle=True)
    
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, patience=10, factor=0.5)
    criterion = nn.MSELoss()
    
    model.train()
    for epoch in range(epochs):
        total_loss = 0
        for batch_x, batch_y in dataloader:
            pred = model(batch_x).squeeze()
            loss = criterion(pred, batch_y.squeeze())
            
            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # gradient clipping
            optimizer.step()
            total_loss += loss.item()
        
        avg_loss = total_loss / len(dataloader)
        scheduler.step(avg_loss)
        
        if epoch % 20 == 0:
            print(f"Epoch {epoch:3d} | Loss: {avg_loss:.6f}")
    
    return model

2. Transformer — Atención para Series Temporales

Los Transformers原来的 para NLP pero funcionan increíblemente bien para series temporales. La idea es usar multi-head self-attention para capturar relaciones entre diferentes puntos temporales sin procesar secuencialmente.

La clave está en el positional encoding que incluye información temporal:

  • Self-Attention: cada timestep attend a todos los demás timesteps
  • Multi-head: múltiples attention heads capturan diferentes patrones
  • Positional Encoding:

    $$PE(pos, 2i) = \sin(pos / 10000^{2i/d})$$

    — información de posición
import math

class PositionalEncoding(nn.Module):
    """Positional encoding para información temporal."""
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)  # (1, max_len, d_model)
        self.register_buffer('pe', pe)
    
    def forward(self, x):
        return x + self.pe[:, :x.size(1), :]


class TimeSeriesTransformer(nn.Module):
    """
    Transformer para forecasting de series temporales.
    """
    def __init__(self, input_dim=1, d_model=64, nhead=4, num_layers=2, dropout=0.1, output_dim=1):
        super().__init__()
        
        # Proyección de input a d_model
        self.input_projection = nn.Linear(input_dim, d_model)
        
        # Positional encoding
        self.pos_encoder = PositionalEncoding(d_model)
        
        # Encoder layers
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model,
            nhead=nhead,
            dim_feedforward=d_model * 4,
            dropout=dropout,
            batch_first=True
        )
        self.transformer_encoder = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)
        
        # Output layer
        self.fc = nn.Linear(d_model, output_dim)
    
    def forward(self, src):
        # src: (batch, seq_len, input_dim)
        src = self.input_projection(src)  # (batch, seq_len, d_model)
        src = self.pos_encoder(src)
        encoded = self.transformer_encoder(src)  # (batch, seq_len, d_model)
        # Usar solo el último timestep
        out = self.fc(encoded[:, -1, :])  # (batch, output_dim)
        return out


def train_transformer_model(X_train, y_train, epochs=100, d_model=64, nhead=4, lr=1e-3):
    """Entrena el modelo Transformer."""
    device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
    print(f"Entrenando Transformer en: {device}")
    
    model = TimeSeriesTransformer(
        input_dim=X_train.shape[-1],
        d_model=d_model,
        nhead=nhead,
        num_layers=2
    ).to(device)
    
    X_tensor = X_train.to(device)
    y_tensor = y_train.to(device)
    
    dataset = TensorDataset(X_tensor, y_tensor)
    dataloader = DataLoader(dataset, batch_size=64, shuffle=True)
    
    optimizer = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=1e-5)
    scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, patience=10, factor=0.5)
    criterion = nn.MSELoss()
    
    model.train()
    for epoch in range(epochs):
        total_loss = 0
        for batch_x, batch_y in dataloader:
            pred = model(batch_x).squeeze()
            loss = criterion(pred, batch_y.squeeze())
            
            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
            optimizer.step()
            total_loss += loss.item()
        
        avg_loss = total_loss / len(dataloader)
        scheduler.step(avg_loss)
        
        if epoch % 20 == 0:
            print(f"Epoch {epoch:3d} | Loss: {avg_loss:.6f}")
    
    return model

3. N-BEATS — El Enfoque Sin Módulos Específicos de Tiempo

N-BEATS (Neural Basis Expansion Analysis for Time Series) es un enfoque puramente deepen sin suposiciones específicas del dominio. Usa stacks de bloques que aprendan descomposiciones de la serie temporal.

La genialidad de N-BEATS es que no usa embedding de tiempo — aprende los patrones directamente de los valores. Esto lo hace muy generalizable.

class NBeatsBlock(nn.Module):
    """
    Bloque básico de N-BEATS.
    """
    def __init__(self, input_dim, theta_dim, basis_dim, share_thetas=False):
        super().__init__()
        self.share_thetas = share_thetas
        
        # FC layers para generar los coeficientes theta
        self.fc1 = nn.Linear(input_dim, 256)
        self.fc2 = nn.Linear(256, 256)
        self.fc3 = nn.Linear(256, theta_dim)
        
        # La base functions define cómo se reconstruye la señal
        self.basis_parameters = nn.Linear(theta_dim, basis_dim)
    
    def forward(self, x):
        # x: (batch, input_dim) — típicamente los últimos N valores de la serie
        x = torch.relu(self.fc1(x))
        x = torch.relu(self.fc2(x))
        theta = self.fc3(x)
        return theta


class NBeatsForecaster(nn.Module):
    """
    N-BEATS puro para forecasting.
    """
    def __init__(self, input_dim=24, output_dim=1, stack_types=['trend', 'seasonality']):
        super().__init__()
        self.input_dim = input_dim
        self.output_dim = output_dim
        
        # Stacks de bloques
        self.stacks = nn.ModuleList()
        for stack_type in stack_types:
            if stack_type == 'trend':
                block = NBeatsBlock(input_dim, theta_dim=4, basis_dim=output_dim)
            elif stack_type == 'seasonality':
                block = NBeatsBlock(input_dim, theta_dim=8, basis_dim=output_dim)
            self.stacks.append(block)
    
    def forward(self, x):
        # x: (batch, seq_len)
        # Tomamos solo los últimos valores para el forecast
        backcast = x[:, -self.input_dim:]
        
        forecast = 0
        for stack in self.stacks:
            theta = stack(backcast)
            forecast = forecast + self.basis_functions(theta)
        
        return forecast
    
    def basis_functions(self, theta):
        """Genera forecast desde theta."""
        # Simplified — en la versión completa usa basis functions reales
        return torch.tanh(theta[:, :self.output_dim])

class SimpleNBeats(nn.Module):
    def __init__(self, input_dim, hidden_dim=128, n_layers=4, forecast_horizon=1):
        super().__init__()
        self.input_dim = input_dim
        self.forecast_horizon = forecast_horizon
        
        # Redes para backcast y forecast
        layers = []
        for i in range(n_layers):
            in_dim = input_dim if i == 0 else hidden_dim
            layers.append(nn.Linear(in_dim, hidden_dim))
            layers.append(nn.ReLU())
        self.backcast_net = nn.Sequential(*layers)
        self.forecast_net = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, forecast_horizon)
        )
    
    def forward(self, x):
        # x: (batch, seq_len)
        backcast = self.backcast_net(x)
        forecast = self.forecast_net(backcast)
        return forecast

Los 3 Errores Más Comunes

Error 1: No Normalizar/Estandarizar Datos Temporales

El problema: Uno de los errores más graves y más comunes. Si sus datos tienen diferentes escalas (por ejemplo, temperatura entre -10 y 40°C, y ventas entre 0 y 1 millón de pesos), el modelo no va a converger bien. Más aún: si entrena con datos de un período y testa con datos de otro donde las escalas son diferentes, las predicciones serán basura.

En Colombia esto es especialmente relevante porque manejamos cosas como:

  • TRM (Tipo de Cambio Representativo del Mercado) que varía enormemente
  • Precios de commodities en pesos colombianos
  • Datos de sensores industriales con rangos muy distintos

La solución: Siempre normalice/estandarice. Debe guardar los parámetros de normalización (media, desviación estándar, mínimo-máximo) y aplicarlos consistentemente en inferencia. Nunca normalice después de split — hágalo antes para evitar data leakage.

# MAL: no normalizar
model = train_lstm_model(X_train_raw, y_train_raw)

# BIEN: normalizar ANTES del split
from sklearn.preprocessing import StandardScaler

# Normalizar sobre TODOS los datos primero (solo para obtener parámetros)
scaler = StandardScaler()
all_data = np.concatenate([X_train_raw, X_test_raw])
scaler.fit(all_data)  # Fit solo en train en práctica estricta

# Transformar
X_train_scaled = scaler.transform(X_train_raw)
X_test_scaled = scaler.transform(X_test_raw)

# En inferencia: USAR LOS MISMOS PARÁMETROS
# NUNCA hacer scaler.fit() otra vez con datos nuevos
X_new_scaled = scaler.transform(X_new_raw)

Error 2: Data Leakage — Información Futura Leakeando al Pasado

El problema: El data leakage en series temporales es especialmente sutil y devastador. Ocurre cuando durante el entrenamiento el modelo tiene acceso a información que no debería tener en producción — es decir, información del "futuro" respecto al timestep que está prediciendo.

Ejemplos comunes:

  • Normalizar con estadísticas del dataset completo: si usted calcula media y std con todos los datos incluyendo el test set, está filtrando información futura
  • Variables que contienen el target con delay: incluir en las features algo que ya incorpora información del futuro
  • Target lagging incorrecto: crear features como " valor de mañana" para predecir hoy — claramente futuro
  • Global scaling vs local scaling: calcular normalización global cuando debería ser por ventana

La matemática del leakage: si

$$X_{train}$$

incluye información de

$$y_{test}$$

durante el fit del scaler, entonces

$$\hat{y} = f(X_{train})$$

está contaminada porque

$$X_{train}$$

ya conocía parte de la respuesta.

La solución:

# MAL: leakage al normalizar con datos futuros
scaler = StandardScaler()
scaler.fit(X_train_and_test)  # NO — esto filtra información del futuro
X_train = scaler.transform(X_train)
X_test = scaler.transform(X_test)

# MAL 2: feature que es el target shifted
df['target_tomorrow'] = df['target'].shift(-1)  # Esto es leakage puro
df['prediction_feature'] = df['value'].shift(-1)  # Información del futuro

# BIEN: normalización solo con datos de entrenamiento
scaler = StandardScaler()
scaler.fit(X_train)  # Solo train
X_train_norm = scaler.transform(X_train)
X_test_norm = scaler.transform(X_test)  # Aplicar MISMOS parámetros

# BIEN 2: features con delays hacia atrás (solo pasado)
df['value_lag1'] = df['value'].shift(1)   # OK — solo información del pasado
df['value_lag2'] = df['value'].shift(2)  # OK
df['rolling_mean_7'] = df['value'].rolling(7).mean()  # OK — usa solo pasado

Error 3: No Usar Proper Time Series Cross-Validation

El problema: Muchos practitioners usan train_test_split(X, y, random_state=42) o k-fold cross-validation normal para series temporales. Esto está completamente mal porque:

  • Rompe la estructura temporal: el modelo entrena con datos del futuro para predecir el pasado
  • Sobreestimación grotesca: los resultados en test serán mucho mejores de lo que realmente son
  • No evalúa el scenario real: en producción, usted solo tiene el pasado para predecir el futuro

En el contexto colombiano, imagine que está predicendo el precio del café: si hace random split, su modelo "aprende" el precio de mañana cuando entrena — lo cual es imposible en la realidad.

La solución: Usar TimeSeriesSplit o Walk-Forward Validation. La idea es siempre predecir el futuro con información del pasado.

from sklearn.model_selection import TimeSeriesSplit

# Time Series Cross-Validation
tscv = TimeSeriesSplit(n_splits=5, gap=24)  # 5 splits, gap de 24 horas entre train y test

print("Time Series Cross-Validation:")
print("-" * 40)
cv_scores = []

for fold, (train_idx, test_idx) in enumerate(tscv.split(X)):
    X_tr, X_val = X[train_idx], X[test_idx]
    y_tr, y_val = y[train_idx], y[test_idx]
    
    # Entrenar
    model_cv = train_lstm_model(X_tr, y_tr, epochs=30)
    
    # Evaluar
    model_cv.eval()
    with torch.no_grad():
        pred = model_cv(X_val.to(device)).cpu().numpy().flatten()
    mse = mean_squared_error(y_val, pred)
    cv_scores.append(mse)
    
    print(f"  Fold {fold+1}: Train size={len(train_idx)}, Test size={len(test_idx)}, MSE={mse:.6f}")

print(f"\nCV Promedio MSE: {np.mean(cv_scores):.6f} (+/- {np.std(cv_scores):.6f})")


# Walk-Forward Validation (más realista para producción)
def walk_forward_validation(X, y, model_fn, n_splits=5):
    """
    Walk-forward: entrena con todo el pasado hasta t, predice t+1, avanza.
    Este es el método más realista para evaluar forecasting.
    """
    scores = []
    train_size = int(len(X) * 0.6)  # Empezamos con 60% para train inicial
    
    for i in range(n_splits):
        # Split temporal
        X_train = X[:train_size + i * 24]  # Avanzamos 24 timesteps
        y_train = y[:train_size + i * 24]
        X_test = X[train_size + i * 24:train_size + (i+1) * 24]
        y_test = y[train_size + i * 24:train_size + (i+1) * 24]
        
        if len(X_test) == 0:
            break
        
        # Entrenar y evaluar
        model = model_fn(X_train, y_train, epochs=30)
        model.eval()
        with torch.no_grad():
            pred = model(X_test.to(device)).cpu().numpy().flatten()
        
        mse = mean_squared_error(y_test, pred)
        scores.append(mse)
        print(f"  Walk-forward {i+1}: train={len(X_train)}, test={len(X_test)}, MSE={mse:.6f}")
    
    return scores

print("\nWalk-Forward Validation:")
print("-" * 40)
wf_scores = walk_forward_validation(X, y, train_lstm_model, n_splits=5)
print(f"\nWalk-forward Promedio MSE: {np.mean(wf_scores):.6f}")
