Testing LLMs y Prompt Evaluation

Hagale pues, parcero. Así como en Colombia nadie entrega un software sin probar antes (o al menos eso debería pasar), con los LLMs y prompts pasa igual: el 80% no tiene test suite para sus prompts y el 20% que sí la tiene, muchos la usan mal. Hoy es el Día 264 y vamos a aprender cómo testear prompts sistemáticamente, hacer A/B testing, regression testing y construir una prompt test suite como Dios manda. Café en mano, que esto es clave.

🎯 Por Qué Testing de Prompts Es Crítico

Un prompt no es estático. Es código. Y como todo código, necesita:

  • Version control: Saber qué cambió entre versiones
  • Regression testing: Asegurar que cambios no rompan lo que funcionaba
  • Benchmarks reproducibles: Medir mejora o degradación

La realidad: la mayoría trata los prompts como magia — van ajustando "a ojo" hasta que "funciona bien". Hasta que un día el modelo se actualiza y todo se rompe. Y no hay forma de saber qué falló porque no hay tests.

📐 Prompt Test Framework

La arquitectura correcta tiene tres capas:

  1. Test Cases: Ejemplos de input/output esperados
  2. Evaluation Metrics: Cómo medir calidad de respuestas
  3. Automated Runner: CI/CD que corre tests en cada cambio
import json
import hashlib
from dataclasses import dataclass, asdict
from typing import List, Dict, Any, Callable, Optional
from enum import Enum
import re

class TestStatus(Enum):
    PASS = "pass"
    FAIL = "fail"
    PARTIAL = "partial"
    ERROR = "error"

@dataclass
class TestCase:
    """Un caso de prueba para un prompt."""
    id: str
    name: str
    prompt_template: str
    variables: Dict[str, str]
    expected_output: Optional[str] = None
    evaluation_criteria: Optional[Dict[str, float]] = None  # e.g., {"contains": 0.8, "sentiment": 0.9}

    def render_prompt(self) -> str:
        """Renderiza el prompt con las variables."""
        return self.prompt_template.format(**self.variables)

@dataclass
class TestResult:
    """Resultado de evaluar un test case."""
    test_id: str
    status: TestStatus
    actual_output: str
    expected_output: Optional[str]
    metrics: Dict[str, float]
    latency_ms: float
    error: Optional[str] = None

    def to_dict(self) -> dict:
        return {
            "test_id": self.test_id,
            "status": self.status.value,
            "metrics": self.metrics,
            "latency_ms": self.latency_ms,
            "error": self.error
        }

class PromptEvaluator:
    """Framework para evaluar prompts sistemáticamente."""

    def __init__(self, llm_client, scorer: Optional[Callable] = None):
        self.llm = llm_client
        self.scorer = scorer or self._default_scorer
        self.test_history: List[TestResult] = []

    def _default_scorer(self, output: str, criteria: Dict[str, Any]) -> Dict[str, float]:
        """Scorer por defecto: verifica presencia de keywords y length."""
        scores = {}

        if "contains" in criteria:
            keywords = criteria["contains"] if isinstance(criteria["contains"], list) else [criteria["contains"]]
            matches = sum(1 for kw in keywords if kw.lower() in output.lower())
            scores["contains_ratio"] = matches / len(keywords) if keywords else 0

        if "min_length" in criteria:
            scores["length_ok"] = 1.0 if len(output) >= criteria["min_length"] else len(output) / criteria["min_length"]

        if "max_length" in criteria:
            if len(output) <= criteria["max_length"]:
                scores["length_ok"] = 1.0
            else:
                scores["length_ok"] = max(0, 1 - (len(output) - criteria["max_length"]) / criteria["max_length"])

        if "regex_match" in criteria:
            pattern = criteria["regex_match"]
            scores["regex_match"] = 1.0 if re.search(pattern, output) else 0.0

        return scores

    async def run_test(self, test_case: TestCase) -> TestResult:
        """Ejecuta un test case y retorna el resultado."""
        import time
        start = time.time()

        try:
            prompt = test_case.render_prompt()
            output = await self.llm.generate(prompt)

            metrics = self.scorer(output, test_case.evaluation_criteria or {})

            # Determinar status
            all_pass = all(s >= 0.7 for s in metrics.values())
            any_fail = any(s < 0.5 for s in metrics.values())

            if all_pass:
                status = TestStatus.PASS
            elif any_fail:
                status = TestStatus.FAIL
            else:
                status = TestStatus.PARTIAL

            result = TestResult(
                test_id=test_case.id,
                status=status,
                actual_output=output,
                expected_output=test_case.expected_output,
                metrics=metrics,
                latency_ms=(time.time() - start) * 1000
            )

        except Exception as e:
            result = TestResult(
                test_id=test_case.id,
                status=TestStatus.ERROR,
                actual_output="",
                expected_output=test_case.expected_output,
                metrics={},
                latency_ms=(time.time() - start) * 1000,
                error=str(e)
            )

        self.test_history.append(result)
        return result

    async def run_test_suite(self, test_cases: List[TestCase], verbose: bool = True) -> Dict[str, Any]:
        """Ejecuta todos los tests y retorna resumen."""
        results = []
        for tc in test_cases:
            if verbose:
                print(f"▶️  Ejecutando: {tc.name}")
            result = await self.run_test(tc)
            results.append(result)

        # Resumen
        total = len(results)
        passed = sum(1 for r in results if r.status == TestStatus.PASS)
        failed = sum(1 for r in results if r.status == TestStatus.FAIL)
        partial = sum(1 for r in results if r.status == TestStatus.PARTIAL)
        errors = sum(1 for r in results if r.status == TestStatus.ERROR)

        summary = {
            "total": total,
            "passed": passed,
            "failed": failed,
            "partial": partial,
            "errors": errors,
            "pass_rate": passed / total if total > 0 else 0,
            "results": [r.to_dict() for r in results]
        }

        if verbose:
            print(f"\n📊 Resumen: {passed}/{total} tests pasados ({summary['pass_rate']:.1%})")

        return summary

📐 A/B Testing para Prompts

No es suficiente decir "este prompt funciona mejor". Necesitás evidencia estadística. A/B testing te permite comparar dos versiones de un prompt con significancia estadística.

import numpy as np
from scipy import stats
from dataclasses import dataclass
from typing import List, Tuple

@dataclass
class ABTestResult:
    variant_a_results: List[float]
    variant_b_results: List[float]
    p_value: float
    is_significant: bool
    winner: str
    confidence_interval: Tuple[float, float]
    effect_size: float

class ABPromptTester:
    """Test A/B para comparar variantes de prompts."""

    def __init__(self, significance_level: float = 0.05):
        self.alpha = significance_level

    def run_ab_test(
        self,
        prompt_a: str,
        prompt_b: str,
        test_inputs: List[str],
        scorer_fn: callable,
        n_iterations: int = 5
    ) -> ABTestResult:
        """
        Corre test A/B entre dos prompts.

        Para cada input, ejecuta ambos prompts múltiples veces
        para account for variabilidad del LLM.
        """
        scores_a = []
        scores_b = []

        for input_text in test_inputs:
            for _ in range(n_iterations):
                output_a = self.call_llm(prompt_a, input_text)
                output_b = self.call_llm(prompt_b, input_text)

                score_a = scorer_fn(output_a, input_text)
                score_b = scorer_fn(output_b, input_text)

                scores_a.append(score_a)
                scores_b.append(score_b)

        # Test estadístico (t-test de dos muestras)
        t_stat, p_value = stats.ttest_ind(scores_a, scores_b)

        mean_a = np.mean(scores_a)
        mean_b = np.mean(scores_b)

        # Effect size (Cohen's d)
        pooled_std = np.sqrt((np.var(scores_a) + np.var(scores_b)) / 2)
        effect_size = (mean_b - mean_a) / pooled_std if pooled_std > 0 else 0

        # Confidence interval para la diferencia
        se = pooled_std * np.sqrt(2 / len(scores_a))
        ci_margin = 1.96 * se
        ci = (mean_b - mean_a - ci_margin, mean_b - mean_a + ci_margin)

        return ABTestResult(
            variant_a_results=scores_a,
            variant_b_results=scores_b,
            p_value=p_value,
            is_significant=p_value < self.alpha,
            winner="B" if mean_b > mean_a and p_value < self.alpha else "A",
            confidence_interval=ci,
            effect_size=effect_size
        )

def quality_scorer(output: str, reference: str) -> float:
    """Scorer simple: similaridad de contenido."""
    output_words = set(output.lower().split())
    ref_words = set(reference.lower().split())
    if not ref_words:

📐 Regression Testing Automatizado

Cada vez que cambiás un prompt, necesitás saber si empeoraste algo que funcionaba. El regression test suite corre automáticamente en CI/CD.

⚠️ Error 1: No Tener Test Suite para Prompts

El problema: Sin tests, los prompts se convierten en tierra de nadie. Cualquiera puede cambiarlos "porque le pareció mejor". No hay forma de saber si un cambio mejoró o empeoró el comportamiento. Cuando algo falla en producción, no hay forma de hacer debug.

La solución: Crear un test suite desde el día uno. Empezá con 10-20 casos que cubran los escenarios más importantes (happy path, edge cases, inputs problemáticos). Agregá más a medida que encontrés bugs.

⚠️ Error 2: Testing con Pocos Ejemplos Sin Entender la Distribución

El problema: Testeas el prompt con 3-5 ejemplos que vos elegís, funciona perfecto, pero en producción con inputs reales empieza a fallar estrepitosamente. Esto pasa porque tus ejemplos no representan la distribución real de inputs.

La solución: Sampling representativo. Entendé la distribución de tus datos y muestreá proporcionalmente:

from collections import Counter
import random

def create_representative_test_set(real_inputs: List[str], n_samples: int = 100) -> List[str]:
    """
    Crea test set que representa la distribución real de inputs.

    Agrupa inputs similares y muestrea proporcionalmente.
    """
    # Clustering simple por longitud (proxy de complejidad)
    buckets = {
        "short": [],      # < 100 chars
        "medium": [],     # 100-500 chars
        "long": [],       # > 500 chars
    }

    for inp in real_inputs:
        if len(inp) < 100:
            buckets["short"].append(inp)
        elif len(inp) < 500:
            buckets["medium"].append(inp)
        else:
            buckets["long"].append(inp)

    # Distribución observada en producción
    distribution = {
        "short": 0.3,
        "medium": 0.5,
        "long": 0.2
    }

    # Muestrear proporcionalmente
    samples = []
    for bucket_name, ratio in distribution.items():
        n_from_bucket = int(n_samples * ratio)
        bucket_samples = random.sample(
            buckets[bucket_name],
            min(n_from_bucket, len(buckets[bucket_name]))
        )
        samples.extend(bucket_samples)

    return samples

⚠️ Error 3: No Medir Inter-Annotator Agreement

El problema: Usás evaluación humana para medir calidad pero no verificás que los anotadores estén de acuerdo entre sí. Un anotador puede calificar 8/10 y otro 3/10 para el mismo output. ¿A quién creés? Sin agreement, las evaluaciones son ruido.

La solución: Medir agreement con Krippendorff's alpha o Cohen's kappa. Si el agreement es bajo, los criterios no están claros o los anotadores necesitan más guía.

from typing import List, Dict, Tuple
import numpy as np

def cohens_kappa(annotations_1: List[int], annotations_2: List[int]) -> float:
    """Calcula Cohen's kappa entre dos anotadores."""
    n = len(annotations_1)
    assert n == len(annotations_2)

    # Matriz de confusión
    categories = sorted(set(annotations_1 + annotations_2))
    k = len(categories)
    matrix = np.zeros((k, k))

    for a1, a2 in zip(annotations_1, annotations_2):
        i, j = categories.index(a1), categories.index(a2)
        matrix[i, j] += 1

    # Agreement observado
    po = np.trace(matrix) / n

    # Agreement esperado por azar
    pe = 0
    for i in range(k):
        row_sum = matrix[i, :].sum()
        col_sum = matrix[:, i].sum()
        pe += (row_sum * col_sum) / (n * n)

    kappa = (po - pe) / (1 - pe) if pe < 1 else 1.0
    return kappa

def krippendorffs_alpha(
    annotations: Dict[str, List[int]],  # annotator_id -> ratings
    categories: int
) -> float:
    """
    Calcula Krippendorff's alpha para múltiples anotadores.

    categories: número de categorías de rating (e.g., 5 para 1-5)
    """
    # Crear matriz de anotaciones: items x annotators
    items = set()
    for ann_list in annotations.values():
        items.update(range(len(ann_list)))

    n_items = len(items)
    n_annotators = len(annotations)

    # Coincidences matrix
    coincidence = np.zeros((categories, categories))

    for ann_id, ratings in annotations.items():
        for i, rating in enumerate(ratings):
            if i in items:
                coincidence[rating, rating] += 1

    # Agreements observados
    Do = np.trace(coincidence) / coincidence.sum()

    # Agreements esperados
    De = sum(
        coincidence[i, j] * coincidence[j, i]
        for i in range(categories)
        for j in range(categories)
    ) / (coincidence.sum() ** 2)

    alpha = 1 - (Do / De) if De > 0 else 1.0
    return alpha

📊 Métricas de Evaluación de Prompts

Además de tests automatizados, necesitás métricas cuantitativas para comparar versiones de prompts:

class PromptMetrics:
    """Métricas para evaluar calidad de prompts."""

    @staticmethod
    def similarity_score(output: str, reference: str) -> float:
        """Similaridad coseno entre output y referencia (usar embeddings)."""
        # En implementación real: usar sentence-transformers
        return 0.85

    @staticmethod
    def keyword_coverage(output: str, required_keywords: List[str]) -> float:
        """Qué porcentaje de keywords requeridas aparecen en el output."""
        if not required_keywords:
            return 1.0
        present = sum(1 for kw in required_keywords if kw.lower() in output.lower())
        return present / len(required_keywords)

    @staticmethod
    def length_ratio(output: str, target_length: Tuple[int, int]) -> float:
        """Output está dentro del rango de longitud esperado."""
        length = len(output)
        min_len, max_len = target_length
        if min_len <= length <= max_len:
            return 1.0
        elif length < min_len:
            return length / min_len
        else:
            return max(0, 1 - (length - max_len) / max_len)

    @staticmethod
    def toxicity_score(output: str) -> float:
        """Puntaje de toxicidad (menor es mejor)."""
        # En implementación real: usar perspective API o modelo de toxicity
        return 0.05  # 5% de toxicidad

    @staticmethod
    def format_adherence(output: str, required_format: str) -> float:
        """Output sigue el formato requerido (JSON, lista, etc.)."""
        if required_format == "json":
            import json
            try:
                json.loads(output)
                return 1.0
            except:
                return 0.0
        elif required_format == "list":
            lines = [l.strip() for l in output.split('\n') if l.strip()]
            return 1.0 if all('-' in l or l[0].isdigit() for l in lines) else 0.0
        return 0.5

    def compute_composite_score(
        self,
        output: str,
        reference: str = None,
        required_keywords: List[str] = None,
        target_length: Tuple[int, int] = None,
        required_format: str = None,
        weights: Dict[str, float] = None
    ) -> Dict[str, float]:
        """Compute weighted composite score."""
        weights = weights or {
            "similarity": 0.3,
            "keywords": 0.2,
            "length": 0.2,
            "format": 0.15,
            "toxicity": 0.15
        }

        scores = {
            "similarity": self.similarity_score(output, reference) if reference else 1.0,
            "keywords": self.keyword_coverage(output, required_keywords) if required_keywords else 1.0,
            "length": self.length_ratio(output, target_length) if target_length else 1.0,
            "toxicity": 1.0 - self.toxicity_score(output),  # Invertido: menor toxicidad = mayor score
            "format": self.format_adherence(output, required_format) if required_format else 1.0,
        }

        composite = sum(scores[k] * weights[k] for k in weights)
        scores["composite"] = composite

        return scores

📝 Resumen y Cierre

Hagale pues, parcero. Testing de prompts no es opcional ni "nice to have" — es tan importante como los tests de código. Lo que aprendimos hoy:

  • Prompt Test Framework: Estructura para crear, correr y trackear tests de prompts
  • A/B Testing estadístico: Comparar variantes con confianza estadística
  • Regression Testing: Proteger funcionalidad existente en cada cambio
  • Muestreo representativo: Tests que reflejan la distribución real de inputs
  • Inter-annotator agreement: Verificar que evaluación humana sea confiable

El 80% que salta el testing termina con:

  • Prompts que "funcionaban" y de repente no
  • No saber qué cambió cuando algo falla
  • Clientes insatisfechos con outputs inconsistentes

El 20% que hace testing bien tiene:

  • Confianza al hacer cambios
  • Rollback rápido si algo falla
