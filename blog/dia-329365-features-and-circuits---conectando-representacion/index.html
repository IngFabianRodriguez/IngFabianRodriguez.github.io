🎯 Qué Son Features y Circuits en Interpretability

En los últimos días hemos hablado de interpretibilidad como el campo que busca entender cómo funcionan los LLMs por dentro. Hoy vamos más profundo: features y circuits. La idea fundamental es que las redes neuronales representan información a través de patrones de activación llamados features, y procesan información a través de caminos llamados circuits que conectan estos features.

Piense en un circuito como un circuito eléctrico pero neuronal. Una señal entra (un feature), viaja a través de conexiones (pesos), y activa otros features downstream. Entender qué features existen, cómo se conectan, y qué computación implementa cada circuito es el objetivo central de esta línea de investigación.

Esta aproximación es revolutionary porque nos permite ir de "sabemos que el modelo sabe X" a "el modelo sabe X porque tiene un circuito específico que conecta el feature de Y con el feature de Z". Es la diferencia entre arqueología y ingeniería inversa.

Por Qué Importa Esto

Si podemos mapear los circuits que un modelo usa para razonar, podemos:

  • Detectar sesgos - circuitos que conectan género con profesiones
  • Entender errores - por qué el modelo falla en ciertos contextos
  • Auditar seguridad - verificar que no hay circuitos para generar contenido harmful
  • Mejorar modelos - saber exactamente qué cambiar para corregir comportamiento

🔍 Identificando Features en Redes Neuronales

Un feature es una dirección en el espacio de activación de una capa. Cuando procesamos un input, la activación de esa capa puede ser vista como una combinación lineal de features que fueron detectados.

La técnica principal para encontrar features es el probing o análisis de representaciones. Entrenamos un clasificador lineal sobre las activaciones de una capa específica para predecir alguna propiedad del input. Si el clasificador funciona bien, eso sugiere que esa propiedad está siendo representada linealmente en esa capa.

import torch
import torch.nn as nn
from typing import List, Dict, Any

class FeatureDetector:
    """
    Detecta features en capas de una red neuronal usando probing.
    """
    
    def __init__(self, model: nn.Module, layer_name: str):
        self.model = model
        self.layer_name = layer_name
        self.activations: torch.Tensor = None
        self._register_hook()
    
    def _register_hook(self):
        """Registra un forward hook para capturar activaciones"""
        def hook_fn(module, input, output):
            self.activations = output.detach()
        
        for name, module in self.model.named_modules():
            if name == self.layer_name:
                module.register_forward_hook(hook_fn)
                break
    
    def collect_activations(self, texts: List[str], tokenizer, device: str = "cuda"):
        """Colecciona activaciones para una lista de textos"""
        self.model.eval()
        activations_list = []
        
        with torch.no_grad():
            for text in texts:
                inputs = tokenizer(text, return_tensors="pt", padding=True).to(device)
                self.model(**inputs)
                activations_list.append(self.activations.cpu())
        
        return torch.cat(activations_list, dim=0)
    
    def compute_feature_directions(self, activations: torch.Tensor, 
                                   labels: torch.Tensor) -> torch.Tensor:
        """
        Computa direcciones de features usando logistic regression probing.
        
        Args:
            activations: Tensor de shape (n_samples, d_model)
            labels: Labels binarios para el feature (n_samples,)
        
        Returns:
            Vector de dirección del feature (d_model,)
        """
        # Entrenar regresión logística simple
        probe = nn.Linear(activations.shape[1], 1).to(activations.device)
        optimizer = torch.optim.LBFGS(probe.parameters())
        criterion = nn.BCEWithLogitsLoss()
        
        def closure():
            optimizer.zero_grad()
            logits = probe(activations).squeeze(-1)
            loss = criterion(logits, labels.float())
            loss.backward()
            return loss
        
        for _ in range(100):
            optimizer.step(closure)
        
        # La dirección del feature es el peso del probe
        with torch.no_grad():
            direction = probe.weight.data.squeeze()
        
        return direction
    
    def find_features_by_concept(self, texts: List[str], tokenizer,
                                 concept_words: List[str],
                                 device: str = "cuda") -> Dict[str, Any]:
        """
        Encuentra features relacionados con conceptos específicos.
        
        Args:
            texts: Lista de textos a analizar
            tokenizer: Tokenizer del modelo
            concept_words: Palabras que indican el concepto
        
        Returns:
            Diccionario con features detectados
        """
        # Obtener textos positivos y negativos basados en conceptos
        activations = self.collect_activations(texts, tokenizer, device)
        
        # Crear labels: 1 si el texto contiene palabras del concepto
        labels = torch.tensor([
            any(word.lower() in text.lower() for word in concept_words)
            for text in texts
        ], dtype=torch.float)
        
        # Evitar clases vacías
        if labels.sum() == 0 or (1 - labels).sum() == 0:
            return {"error": "No hay ejemplos positivos o negativos"}
        
        # Computar dirección del feature
        feature_direction = self.compute_feature_directions(activations, labels)
        
        return {
            "concept": concept_words,
            "feature_direction": feature_direction,
            "n_positive": labels.sum().item(),
            "n_negative": (1 - labels).sum().item()
        }

⚡ Circuits: Rastreando el Flujo de Información

Un circuit es un subgrafo de la red que implementa una computación específica. Tiene nodos (features en capas específicas) y edges (conexiones con pesos altos entre capas). Un circuit completo conecta features desde el input hasta el output.

Para estudiar circuits, usamos técnicas como:

  • Activation patching - reemplazar activaciones para ver el efecto en el output
  • Gradient analysis - ver qué tan sensible es el output a cada feature
  • Path patching - intervenir en paths específicos entre capas

La idea es cortar o modificar conexiones específicas y observar cómo cambia el comportamiento del modelo. Si al cortar un path específico el modelo deja de realizar una tarea, ese path era parte del circuit que implementaba esa tarea.

class CircuitAnalyzer:
    """
    Analiza circuits en redes neuronales usando patching.
    """
    
    def __init__(self, model: nn.Module, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
        self.cache = {}  # Cache para activaciones
    
    def get_activation(self, layer_name: str, text: str, device: str = "cuda"):
        """Obtiene la activación de una capa específica para un texto"""
        key = f"{layer_name}_{text}"
        if key in self.cache:
            return self.cache[key]
        
        self.model.eval()
        activations = {}
        
        def hook_fn(name):
            def hook(module, input, output):
                activations[name] = output.detach()
            return hook
        
        hooks = []
        for name, module in self.model.named_modules():
            if name == layer_name:
                hooks.append(module.register_forward_hook(hook_fn(name)))
        
        with torch.no_grad():
            inputs = self.tokenizer(text, return_tensors="pt").to(device)
            self.model(**inputs)
        
        for hook in hooks:
            hook.remove()
        
        result = activations.get(layer_name)
        self.cache[key] = result
        return result
    
    def activation_patch(self, prompt: str, target_layer: str,
                        source_activation: torch.Tensor,
                        target_activation: torch.Tensor,
                        patch_layer: str = None) -> float:
        """
        Hace patching de activación y mide efecto en logprobs.
        
        Args:
            prompt: Texto de entrada
            target_layer: Capa donde obtener activación limpia
            source_activation: Activación "limpia" (sin intervención)
            target_activation: Activación "corrupta" (con intervención)
            patch_layer: Capa donde hacer el patch (None = misma que target)
        
        Returns:
            Diferencia en logprob del token correcto
        """
        if patch_layer is None:
            patch_layer = target_layer
        
        self.model.eval()
        
        # Obtener respuesta limpia
        with torch.no_grad():
            clean_inputs = self.tokenizer(prompt, return_tensors="pt").to(source_activation.device)
            clean_logits = self.model(**clean_inputs).logits[0, -1]
            clean_logprob = torch.log_softmax(clean_logits, dim=-1)
        
        # Función de intervención
        def patch_hook(module, input, output):
            # Intervenir en la activación
            patched = output.clone()
            patched[:, -1, :] = target_activation[0, -1, :]
            return patched
        
        # Registrar hook de intervención
        handle = None
        for name, module in self.model.named_modules():
            if name == patch_layer:
                handle = module.register_forward_hook(patch_hook)
        
        # Obtener respuesta con intervención
        with torch.no_grad():
            patched_inputs = self.tokenizer(prompt, return_tensors="pt").to(source_activation.device)
            patched_logits = self.model(**patched_inputs).logits[0, -1]
            patched_logprob = torch.log_softmax(patched_logits, dim=-1)
        
        if handle is not None:
            handle.remove()
        
        # Diferencia de logprob (mayor = más importante el circuit)
        return (clean_logprob - patched_logprob).abs().max().item()
    
    def find_circuit_edges(self, prompt: str, layers: List[str],
                           threshold: float = 0.5) -> List[Dict]:
        """
        Encuentra edges importantes en el circuit para un prompt.
        
        Usa activation patching para identificar qué conexiones importan.
        """
        edges = []
        
        # Obtener activaciones base
        base_activations = {}
        for layer in layers:
            base_activations[layer] = self.get_activation(layer, prompt)
        
        # Para cada capa, medir importancia de intervenir
        for layer in layers:
            clean_act = base_activations[layer]
            
            # Generar activación corrupta (aleatoria)
            corrupted_act = torch.randn_like(clean_act) * clean_act.std() + clean_act.mean()
            
            # Medir efecto de patching
            effect = self.activation_patch(
                prompt=prompt,
                target_layer=layer,
                source_activation=clean_act,
                target_activation=corrupted_act,
                patch_layer=layer
            )
            
            if effect > threshold:
                edges.append({
                    "layer": layer,
                    "effect": effect,
                    "important": True
                })
        
        return edges

📊 El Problema de Superposition

Aquí es donde las cosas se ponen interesantes. Resulta que los modelos no representan features uno a uno. En lugar de tener un neurona por feature, tenemos superposition: múltiples features son representados por las mismas neuronas, usando direcciones casi-ortogonales en el espacio de activación.

Esto pasa porque los modelos tienen más features que neuronas. Si tuvieras 1000 features y 500 neuronas, no puedes representar cada feature con su propia neurona. En cambio, el modelo usa clever combinación linear para comprimir la información.

El problema es que esto hace la interpretability mucho más difícil. Cuando ves una activación, no sabes si viene de un feature u otro. Las neuronas son "poli-funcionales" - responden a múltiples features dependiendo del contexto.

Cómo Detectamos Superposition

Podemos usar el concepto de polysemanticity - una neurona es polifacética si responde a múltiples features no relacionados. Medimos esto calculando la correlación entre los patrones de activación para diferentes features.

import numpy as np
from scipy.stats import correlation
from typing import List, Tuple

class SuperpositionDetector:
    """
    Detecta superposition y polysemanticity en redes neuronales.
    """
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
    
    def compute_activation_correlation(self, texts: List[str], 
                                       layer_name: str) -> np.ndarray:
        """
        Computa matriz de correlación entre activaciones de diferentes textos.
        
        Returns:
            Matriz de correlación (n_texts, n_texts, d_model)
        """
        self.model.eval()
        
        # Coleccionar activaciones
        activations = []
        for text in texts:
            act = self._get_layer_activations(text, layer_name)
            activations.append(act)
        
        activations = np.array(activations)  # (n_texts, d_model)
        
        # Computar correlación por dimensión
        n = len(texts)
        correlation_matrix = np.zeros((n, n, activations.shape[1]))
        
        for dim in range(activations.shape[1]):
            dim_acts = activations[:, dim]
            for i in range(n):
                for j in range(n):
                    if i != j:
                        correlation_matrix[i, j, dim] = np.corrcoef(
                            dim_acts[i], dim_acts[j]
                        )[0, 1]
        
        return correlation_matrix
    
    def detect_polysemantic_neurons(self, texts: List[str], 
                                     layer_name: str,
                                     feature_labels: List[str],
                                     threshold: float = 0.3) -> List[Dict]:
        """
        Detecta neuronas polifacéticas: neuronas que responden a múltiples features.
        
        Args:
            texts: Textos con diferentes features
            layer_name: Capa a analizar
            feature_labels: Labels para cada texto
            threshold: Correlación mínima para considerar respuesta
        
        Returns:
            Lista de neuronas polifacéticas con sus features
        """
        # Obtener activaciones
        activations = []
        for text in texts:
            act = self._get_layer_activations(text, layer_name)
            activations.append(act.mean(axis=0))  # Promedio sobre tokens
        
        activations = np.array(activations)  # (n_texts, d_model)
        
        # Para cada neurona, encontrar a qué features responde
        polysemantic_neurons = []
        
        for neuron_idx in range(activations.shape[1]):
            neuron_activations = activations[:, neuron_idx]
            
            # Calcular correlación con cada feature
            feature_correlations = []
            for feat_idx, feat_name in enumerate(feature_labels):
                corr = np.corrcoef(neuron_activations, 
                                  [1 if i == feat_idx else 0 for i in range(len(texts))])[0, 1]
                if not np.isnan(corr) and abs(corr) > threshold:
                    feature_correlations.append((feat_name, corr))
            
            # Si responde a múltiples features no relacionados
            if len(feature_correlations) >= 2:
                polysemantic_neurons.append({
                    "neuron": neuron_idx,
                    "features": feature_correlations
                })
        
        return polysemantic_neurons
    
    def compute_superposition_score(self, texts: List[str],
                                    layer_name: str,
                                    n_features: int) -> float:
        """
        Calcula un score de superposition para una capa.
        
        Score alto = probable superposition
        Score bajo = representación clara uno-a-uno
        """
        # Usar ICA (Independent Component Analysis) para estimar
        from sklearn.decomposition import FastICA
        
        activations = []
        for text in texts:
            act = self._get_layer_activations(text, layer_name)
            activations.append(act.mean(axis=0))
        
        X = np.array(activations)  # (n_samples, d_model)
        
        if X.shape[1] < n_features:
            return 0.0
        
        # Aplicar ICA
        ica = FastICA(n_components=min(n_features, X.shape[0]))
        try:
            components = ica.fit_transform(X)
            
            # Calcular "mezcla" - qué tan juntos están los componentes
            # Componentes bien separados = bajo superposition
            component_variance = components.var(axis=0)
            mixture_score = 1.0 / (component_variance.mean() + 1e-6)
            
            return mixture_score
        except:
            return 0.0

🔬 Studied Circuits en Practica

Investigadores han identificado circuits específicos para varias tareas. Algunos ejemplos famous:

Circuit de Detección de Mayúsculas

El modelo tiene un circuit específico para detectar si el primer carácter está en mayúscula. Involucra:

  • Una cabeza de atención que mira el primer token
  • Un MLP que detecta el pattern de mayúscula
  • Un connection que propaga esta información a donde se necesita

Circuit de Inducción (Few-Shot)

Para tareas de few-shot learning, el modelo usa un circuit que:

  • Identifica el patrón input-output en los ejemplos
  • Lo aplica al nuevo input
  • Este circuit involucra atención a tokens específicos y MLPs que procesan patterns

Circuit de Simbolos Dependientes

Tareas como "repetir el último símbolo" o "contar caracteres" tienen circuits dedicados que operan en posiciones específicas.

📝 Resumen y Cierre

Features y circuits es el nivel más profundo de interpretabilidad mecanística. La idea es mapear qué features existen en las representaciones del modelo y cómo se conectan para implementar comportamientos.

El reto principal es la superposition: múltiples features comprimidos en las mismas neuronas. Pero con técnicas como probing, activation patching, y análisis de correlación, podemos empezar a desenredar esta complejidad.

Lo que hace esto particularmente emocionante es que nos da herramientas para ir más allá de decir "el modelo sabe X" hacia "el modelo sabe X a través de este circuit específico". Eso abre la posibilidad de intervención precisa: modificar el circuit para cambiar el comportamiento.
