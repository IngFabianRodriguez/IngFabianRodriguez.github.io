Embeddings de Palabras - La Revolución de Representar Texto como Vectores que Capturan Significado

11 de marzo de 2026
word embeddingsembedding layernn.Embeddingsemantic representation

La Intro que el 85% Se Salta

Parcero, ¿cómo haces para que una máquina entienda que "gato" y "felino" son cosas similares? Las redes neuronales no entienden texto — entienden números. Necesitas convertir palabras en vectores numéricos. Y no es tan simple como asignar un número a cada palabra (1=apple, 2=banana) porque eso ignora completamente el significado y el contexto.

La solución: word embeddings. Cada palabra se representa como un vector de números reales (típicamente 50-300 dimensiones) donde palabras con significados similares están cerca en el espacio vectorial. "Gato" y "perro" tienen vectores similares porque ambos son animales. "Rey" y "reina" están relacionados semánticamente. Esto es lo que permite que los modelos de NLP entiendan lenguaje — no procesan símbolos, procesan geometry en un espacio continuo.

Hoy: cómo funcionan los word embeddings, por qué son la base de todo NLP moderno, y cómo implementarlos.

¿Por Qué Son Necessarios los Embeddings?

Una red neuronal espera tensores numéricos. Si le das texto crudo, no puede procesarlo. La solución naive: one-hot encoding. Cada palabra es un vector con 1 en su posición y 0 en las demás. Para un vocabulario de 50,000 palabras, cada vector tiene 49,999 ceros. Además, no capture similarity: "gato" y "perro" son igualmente diferentes de "mesa" en one-hot encoding.

Los embeddings resuelven esto: aprendemos una matrix $E \in \mathbb{R}^{V \times D}$ donde $V$ es el tamaño del vocabulario y $D$ la dimensión del embedding (típicamente 100-300). Cada palabra $w$ tiene un vector $e_w = E[w]$ que se aprende durante el training. La magia: palabras con contextos similares terminan con vectores similares.

La Geometría del Espacio de Embeddings

Lo remarkable de los word embeddings es que capturan relaciones semánticas como direcciones en el espacio vectorial. La famosa relación: vec("rey") - vec("hombre") + vec("mujer") ≈ vec("reina"). Esto significa que "rey es a hombre como reina es a mujer" — una analogía gramatical capturada como algebra lineal.

otras relaciones capturadas:

  • Geografía: París - Francia + Italia ≈ Roma
  • Company - CEO: Apple - Steve + Tim ≈ Tim Cook
  • Plural: cat - cats + dog ≈ dogs

Esto emerge espontáneamente cuando entrenas embeddings en un corpus grande. No es que el modelo "entienda" analogías — es que las relaciones gramaticales y semánticas se reflejan en la geometry del espacio.

Código Production-Grade

import torch
import torch.nn as nn
from dataclasses import dataclass
import numpy as np


@dataclass
class EmbeddingConfig:
    vocab_size: int = 50_000
    embedding_dim: int = 300
    padding_idx: int = 0
    dropout: float = 0.1


class WordEmbeddings(nn.Module):
    """Embedding layer estándar con soporte para padding y freezing."""
    def __init__(self, config: EmbeddingConfig):
        super().__init__()
        self.embedding = nn.Embedding(
            num_embeddings=config.vocab_size,
            embedding_dim=config.embedding_dim,
            padding_idx=config.padding_idx,
        )
        self.dropout = nn.Dropout(config.dropout)
        # Inicialización Xavier para embeddings
        nn.init.xavier_uniform_(self.embedding.weight)
        # Padding token -> vector zero
        with torch.no_grad():
            self.embedding.weight[config.padding_idx].fill_(0)

    def forward(self, x):
        return self.dropout(self.embedding(x))


class PretrainedEmbeddings(nn.Module):
    """Carga embeddings pre-entrenados (GloVe, FastText, etc.) y los fine-tunea."""
    def __init__(self, embedding_path: str, vocab, embedding_dim=300, trainable=True, dropout=0.1):
        super().__init__()
        self.vocab = vocab
        self.embedding_dim = embedding_dim

        # Load pretrained embeddings
        embeddings = np.load(embedding_path)
        self.embedding = nn.Embedding.from_pretrained(
            torch.FloatTensor(embeddings),
            freeze=not trainable,
            padding_idx=vocab[''],
        )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        return self.dropout(self.embedding(x))


class PositionalEncoding(nn.Module):
    """
    Positional Encoding para injectar información de posición en transformers.
    Usa senos y cosenos en diferentes frecuencias.
    """
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-np.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)  # [1, max_len, d_model]
        self.register_buffer('pe', pe)

    def forward(self, x):
        # x: [batch, seq_len, d_model]
        x = x + self.pe[:, :x.size(1)]
        return x


class LearnedPositionalEncoding(nn.Module):
    """Alternative: positional embeddings aprendidas en lugar de fixed sinusoidales."""
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        self.pe = nn.Embedding(max_len, d_model)

    def forward(self, x):
        batch_size, seq_len, _ = x.shape
        positions = torch.arange(seq_len, device=x.device).unsqueeze(0).expand(batch_size, -1)
        return x + self.pe(positions)


# ─── Similaridad entre palabras ───────────────────────────────────────────────
def cosine_similarity(a, b):
    """Calcula similaridad coseno entre dos vectores."""
    return torch.nn.functional.cosine_similarity(a.unsqueeze(0), b.unsqueeze(0))


def find_similar_words(word, embeddings, vocab, top_k=5):
    """Encuentra las top-k palabras más similares a una palabra dada."""
    word_idx = vocab[word]
    word_vec = embeddings.weight[word_idx]
    similarities = torch.nn.functional.cosine_similarity(
        embeddings.weight, word_vec.unsqueeze(0), dim=1
    )
    top_indices = similarities.topk(top_k + 1)[1][1:]  # Excluir la palabra misma
    return [(vocab.get(idx, ''), similarities[idx].item()) for idx in top_indices]


if __name__ == '__main__':
    config = EmbeddingConfig()
    embeddings = WordEmbeddings(config)

    # Simular input: [batch=2, seq_len=5]
    x = torch.LongTensor([[1, 2, 3, 4, 0], [5, 6, 0, 0, 0]])
    out = embeddings(x)
    print(f"Output shape: {out.shape}")  # [2, 5, 300]

    # Positional encoding
    pos_enc = PositionalEncoding(d_model=300)
    out_pos = pos_enc(out)
    print(f"With positional encoding: {out_pos.shape}")

Errores Comunes

Error 1: No congelar los embeddings pre-entrenados cuando el vocabulario es diferente

Si cargas embeddings pre-entrenados (GloVe con 400K palabras) y tu vocabulario tiene 50K palabras, hay palabras en tu vocab que no tienen embedding pre-entrenado (UNK tokens). Si descongelas los embeddings, los UNK se inicializan aleatoriamente y pueden corromper los embeddings vecinos durante el training.

Fix: Si usas embeddings pre-entrenados y tu vocab es diferente, congela los embeddings pre-entrenados y usa un learnable <UNK> token. Solo descongela si tienes suficiente data para fine-tunearlos.

Error 2: Ignorar el padding en la loss

Cuando haces sequence modeling, si no mask el padding, la red aprende a predecir tokens de padding (que son mayoría si usas batches con sequences de diferente longitud). Esto degrada la calidad del modelo significativamente.

Fix: En la loss function, ignora los índices de padding: loss = criterion(outputs[targets != pad_idx], targets[targets != pad_idx]). O usa torch.nn.utils.rnn.pack_padded_sequence.

Error 3: Usar embeddings aprendidos sin pre-entrenamiento cuando tienes poca data

Si entrenas embeddings desde cero con un dataset pequeño (10K documents), los embeddings capturarán poco significado porque no hay suficiente contexto para aprender buenas representaciones. "gato" y "perro" terminarán con embeddings similares solo porque aparecen en contextos similares, pero las relaciones semánticas más sutiles no emergerán.

Fix: Usa embeddings pre-entrenados (GloVe, FastText, Word2Vec) cuando tienes poca data. Solo entrena desde cero si tienes un corpus grande (1M+ documents).

Resumen del Día

  • Word Embedding: Representa palabras como vectores densos en $\mathbb{R}^D$.
  • One-hot vs Dense: One-hot es sparse y no captura similarity. Embeddings densos capturan semántica.
  • Analogías como geometría: vec("rey") - vec("hombre") + vec("mujer") ≈ vec("reina").
  • Pre-entrenamiento: GloVe, FastText, Word2Vec. Úsalos cuando tienes poca data.
  • Padding mask: Siempre ignora padding en la loss.
  • Positional Encoding: Necesario para que el modelo sepa la posición de las palabras.

El Cierre

Parcero, los word embeddings son el foundation de todo NLP moderno. Sin ellos, un transformer no podría procesar texto. Con ellos, el modelo puede razonar sobre relaciones semánticas, analogías, y similitud entre palabras. Son la forma en que las máquinas "entienden" el significado de las palabras — no como símbolos discretos, sino como puntos en un espacio continuo.

Esa vaina de "los embeddings son magia negra" es cierta en cierto modo: emergent behavior como analogías surge de simplemente predecir qué palabra viene dado el contexto. No hay supervisión semántica explícita — solo geometría. Hágale que la próxima vez que veas un embedding, pienses en él como coordenadas en un espacio semántico donde las palabras similares están cerca. ¡Nos vemos en el día 86!
