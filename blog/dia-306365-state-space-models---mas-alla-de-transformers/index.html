State Space Models - Mas Alla De Transformers

02 de noviembre de 2026
state-spacessmmambaarchitecture

🎯 Por Que State Space Models?

Hagale pues, parcero. Los transformers han dominado deep learning por años, pero tienen un problema fundamental: la complejidad es O(n²) en la longitud de secuencia. Para secuencias de 1M tokens esto es prohibitive. State Space Models (SSMs) prometen O(n) linear — permitiendo procesar secuencias extremadamente largas de manera eficiente.

SSMs no son nuevos: vienen de la teoría de control y sistemas dinámicos. Lo nuevo es que мы渗ns aprenderlos end-to-end con deep learning, dando origen a arquitecturas como Mamba que compiten con transformers.

📐 La Matematica De SSMs

Un State Space Model continuo representa un sistema dinámico:

$$\dot{x}(t) = \mathbf{A}x(t) + \mathbf{B}u(t)$$

$$y(t) = \mathbf{C}x(t) + \mathbf{D}u(t)$$

Donde:

  • $x(t)$ es el estado interno del sistema
  • $u(t)$ es la entrada
  • $y(t)$ es la salida
  • $\mathbf{A}, \mathbf{B}, \mathbf{C}, \mathbf{D}$ son matrices de parámetros

Para hacer esto discreto (computable), discretizamos con un paso $\Delta$:

$$x_{t} = \bar{\mathbf{A}}x_{t-1} + \bar{\mathbf{B}}u_t$$

$$y_t = \mathbf{C}x_t + \mathbf{D}u_t$$

con $\bar{\mathbf{A}} = e^{\mathbf{A}\Delta}$ y $\bar{\mathbf{B}} = \mathbf{A}^{-1}(e^{\mathbf{A}\Delta} - I)\mathbf{B}\Delta$.

🔄 La Conexion Con RNNs

Un SSM es esencialmente una RNN sofisticada. La diferencia clave: los parámetros A, B, C son learned y optimizados, no fija. Esto permite que el modelo aprenda representaciones de estado óptimas.

La recurrence es:

$$h_t = \bar{\mathbf{A}}h_{t-1} + \bar{\mathbf{B}}x_t$$

$$y_t = \mathbf{C}h_t$$

🔬 Implementacion de SSM Basico

import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np

class StateSpaceModel(nn.Module):
    """
    State Space Model discretizado con parámetros aprendibles.
    """
    def __init__(self, d_model: int, d_state: int, dt_min: float = 0.001, dt_max: float = 0.1):
        super().__init__()
        self.d_model = d_model
        self.d_state = d_state
        
        # Parámetros del SSM (discretizado)
        # A: matriz de estado (d_state x d_state)
        # B: matriz de entrada (d_state x 1) 
        # C: matriz de salida (1 x d_state)
        # D: skip connection (scalar)
        
        # Inicialización tipo HiPPO (para buena memoria)
        A = np.zeros((d_state, d_state), dtype=np.float32)
        for i in range(d_state):
            for j in range(d_state):
                if i >= j:
                    A[i, j] = -(i + 1)
        A = A / (dt_max - dt_min) * 0.5  # Escala
        
        self.A = nn.Parameter(torch.tensor(A, dtype=torch.float32))
        self.B = nn.Parameter(torch.randn(d_state, 1) * 0.1)
        self.C = nn.Parameter(torch.randn(1, d_state) * 0.1)
        self.D = nn.Parameter(torch.zeros(1))
        
        # Paso de discretización aprendible
        self.log_dt = nn.Parameter(torch.tensor(0.0))
    
    def discretize(self):
        """Discretiza las matrices contínuas usando zero-order hold."""
        dt = torch.exp(self.log_dt)
        # A_discreto = exp(A * dt) ≈ I + A * dt (para dt pequeño)
        I = torch.eye(self.d_state, device=self.A.device)
        A_bar = I + self.A * dt.unsqueeze(-1)
        # B_discreto = B * dt
        B_bar = self.B * dt.unsqueeze(-1)
        return A_bar, B_bar
    
    def forward(self, x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
        """
        x: [batch, seq_len] - input sequence
        Retorna: (output, final_state)
        """
        batch_size, seq_len = x.shape
        
        A_bar, B_bar = self.discretize()
        
        # State initialization
        h = torch.zeros(batch_size, self.d_state, device=x.device)
        outputs = []
        
        for t in range(seq_len):
            u_t = x[:, t:t+1]  # [batch, 1]
            h = A_bar @ h.unsqueeze(-1) + B_bar @ u_t.unsqueeze(-1)
            h = h.squeeze(-1)  # [batch, d_state]
            
            y_t = self.C @ h.unsqueeze(-1) + self.D * u_t
            outputs.append(y_t.squeeze(-1))
        
        output = torch.stack(outputs, dim=1)  # [batch, seq_len]
        return output, h

# Ejemplo
batch_size, seq_len = 4, 100
d_model, d_state = 128, 16

x = torch.randn(batch_size, seq_len)
ssm = StateSpaceModel(d_model, d_state)
output, final_state = ssm(x)

print(f"Input shape: {x.shape}")
print(f"Output shape: {output.shape}")
print(f"Final state shape: {final_state.shape}")

⚡ Mamba - SSM Selectivo

El breakthrough de Mamba es hacer el SSM selectivo: el router (qué estado recordar/olvidar) es aprendido dependiendo del input. Esto es análogo a attention mechanisms en transformers.

La diferencia clave de Mamba vs SSM básico:

  • SSM básico: parámetros fijos para todos los inputs
  • Mamba: parámetros varían con el input (selección)

La selección ocurre en las matrices B, C y el paso dt:

$$B_t = \text{Linear}_B(x_t), \quad C_t = \text{Linear}_C(x_t), \quad \Delta_t = \tau_\Delta(\text{Linear}_\Delta(x_t))$$

class MambaBlock(nn.Module):
    """
    Mamba Block - SSM con selección de parámetros por input.
    """
    def __init__(self, d_model: int, d_state: int = 16, d_conv: int = 4, expand: int = 2):
        super().__init__()
        self.d_model = d_model
        self.d_state = d_state
        self.d_inner = int(expand * d_model)
        
        # Proyección de entrada
        self.in_proj = nn.Linear(d_model, self.d_inner * 2, bias=False)
        
        # Convolución 1D para procesamiento local
        self.conv1d = nn.Conv1d(
            in_channels=self.d_inner,
            out_channels=self.d_inner,
            kernel_size=d_conv,
            padding=d_conv - 1,
            groups=self.d_inner,
        )
        
        # SSM parameters con selección
        self.x_proj = nn.Linear(self.d_inner, d_state * 2 + 1, bias=False)  # B, C, dt
        self.out_proj = nn.Linear(self.d_inner, d_model, bias=False)
        
        # Inicialización de A (HiPPO)
        A = np.zeros((d_state, self.d_inner), dtype=np.float32)
        for i in range(d_state):
            for j in range(self.d_inner):
                if i >= j:
                    A[i, j] = -(i + 1) * (j + 1)
        self.A_log = nn.Parameter(torch.tensor(A, dtype=torch.float32))
        
        self.dt_bias = nn.Parameter(torch.zeros(d_state))
    
    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """
        x: [batch, seq_len, d_model]
        """
        batch_size, seq_len, d_model = x.shape
        
        # Split y proyectar
        xz = self.in_proj(x)  # [batch, seq, 2*d_inner]
        x_inner, z = xz.chunk(2, dim=-1)
        
        # Convolución + SiLU
        x_conv = x_inner.transpose(1, 2)  # [batch, d_inner, seq]
        x_conv = self.conv1d(x_conv)[:, :, :seq_len].transpose(1, 2)  # [batch, seq, d_inner]
        x_ssm = F.silu(x_conv)
        
        # Proyectar para obtener B, C, dt
        x_proj = self.x_proj(x_ssm)  # [batch, seq, d_state*2 + 1]
        B = x_proj[:, :, :self.d_state]  # [batch, seq, d_state]
        C = x_proj[:, :, self.d_state:self.d_state*2]  # [batch, seq, d_state]
        dt = x_proj[:, :, -1]  # [batch, seq]
        
        # Discretización
        dt = F.softplus(dt + self.dt_bias)  # Positive step
        A = -torch.exp(self.A_log.float())  # [d_state, d_inner]
        
        # SSM step (simplificado - versión completa usaría scan)
        # Aquí ilustramos el concepto
        y = self.selective_scan(x_ssm, dt, A, B, C)
        
        # Gating
        y = y * F.silu(z)
        
        return self.out_proj(y)
    
    def selective_scan(self, x: torch.Tensor, dt: torch.Tensor, 
                       A: torch.Tensor, B: torch.Tensor, C: torch.Tensor) -> torch.Tensor:
        """
        Selective scan - el corazón de Mamba.
        Por simplicidad, aquí es una versión ilustrativa.
        La implementación real usa parallel scan algorithm.
        """
        # Esta es una versión simplificada
        # La implementación real usa torch.scan con parallel scan
        batch_size, seq_len, d_inner = x.shape
        d_state = A.shape[0]
        
        h = torch.zeros(batch_size, d_state, d_inner, device=x.device)
        outputs = []
        
        for t in range(seq_len):
            # Selección de parámetros en tiempo t
            B_t = B[:, t, :]  # [batch, d_state]
            C_t = C[:, t, :]  # [batch, d_state]
            dt_t = dt[:, t, None]  # [batch, 1]
            
            # Discretizar
            dA = torch.exp(dt_t * A)  # [d_state, d_inner]
            dB = dt_t * B_t.unsqueeze(-1)  # [batch, d_state, 1]
            
            # Recurrence
            h = dA * h + (dB * x[:, t, :].unsqueeze(1))  # [batch, d_state, d_inner]
            
            # Output
            y_t = (C_t.unsqueeze(-1) * h).sum(dim=1)  # [batch, d_inner]
            outputs.append(y_t)
        
        return torch.stack(outputs, dim=1)

# Ejemplo
block = MambaBlock(d_model=128, d_state=16)
x = torch.randn(2, 50, 128)
y = block(x)
print(f"Input: {x.shape}")
print(f"Output: {y.shape}")

📊 SSM vs Transformer

Complexidad

$$O_{transformer} = O(n^2 \cdot d) \quad \text{(attention)}$$ $$O_{SSM} = O(n \cdot d \cdot d_{state}) \quad \text{(linear scan)}$$

Para secuencias largas (n >> d * d_state), SSM es dramatically más eficiente.

Trade-offs

  • SSM: O(n) en inference, pero no tiene access exacto a tokens anteriores como attention
  • Transformer: O(n²) pero con full attention context
  • SSM + conv: Puede capturar local context via convolutions

🌟 Modelos Conocidos

  • Mamba: SSM selectivo, compite con transformers en language modeling
  • Jamba: Mezcla de Mamba + Attention blocks
  • S4 (Structured State Spaces): El predecesor, muy eficiente para longitud 16K+
  • RWKV: Otro modelo recurrente que compite con transformers

⚠️ Limitaciones Actuales

📝 Copy Task Difficulty

SSMs struggle con tareas que requieren copiar exactamente un token visto hace mucho. Por ejemplo: "记住: ABC... [10K tokens]... 记住: ABC" — el modelo debe copiar ABC exactamente. Attention puede hacer esto trivialmente, SSM tiene dificultad.

🎯 Benchmarks Mixtos

En algunos benchmarks Mamba iguala o supera transformers, pero en otros (especialmente tareas que requieren matching preciso) pierde. La combinación con attention (Jamba-style) parece ser el futuro.

📈 Resumen y Cierre

SSMs representan un paradigma diferente a transformers:

  • Eficiencia linear: O(n) vs O(n²) — game changer para secuencias largas
  • Selección de estado: Mamba aprende qué recordar/olvidar por input
  • Trade-off: Menos flexible que attention pero más eficiente
  • Futuro: Arquitecturas híbridas SSM + Attention

El campo está evolucionando rápido. La pregunta no es "SSM vs Transformer" sino cómo combinar lo mejor de ambos mundos.
