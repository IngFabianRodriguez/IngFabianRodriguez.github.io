LLM Text Matching — El 80% Lo Hace Mal y el 20% Lo Hace Bien

Hagale pues, parcero. Aquí en Colombia tenemos muchas formas de decir lo mismo: "¡Hágale!", "¡Hagámosle!", "¡Vamos pa'!", "¡Dale!". Si un modelo no entiende que todas significan lo mismo, está perdido. Eso es exactamente el problema del text matching: el 80% de las implementaciones usan técnicas que no capturan la semántica real. Hoy Día 306 vamos a cambiar eso — con matemáticas, código y el estilo paisa que no pela.

🎯 Por Que Text Matching Es Crucial?

Text matching es el corazón de muchas aplicaciones:

  • Buscadores semánticos: "bolso de mano" debe encontrar "bolsa de viaje"
  • deduplicación: Detectar textos duplicados aunque usen palabras distintas
  • Respuesta a preguntas: Matchear preguntas de usuarios con respuestas en la base de conocimiento
  • PLagiarism detection: Encontrar textos similares aunque estén parafraseados

El problema: el 80% usa coincidencia léxica (keywords) cuando debería usar similitud semántica.

📐 La Matemática Del Text Matching

Métricas de Similitud

Dados dos vectores de embedding $\mathbf{a}$ y $\mathbf{b}$, hay varias formas de medir similitud:

Cosine Similarity:

$$\text{cos}(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{|\mathbf{a}| \cdot |\mathbf{b}|} = \frac{\sum_{i=1}^{n} a_i b_i}{\sqrt{\sum_{i=1}^{n} a_i^2} \cdot \sqrt{\sum_{i=1}^{n} b_i^2}}$$

Dot Product (cuando los vectores ya están normalizados):

$$\text{dot}(\mathbf{a}, \mathbf{b}) = \mathbf{a} \cdot \mathbf{b}$$

Euclidean Distance:

$$d(\mathbf{a}, \mathbf{b}) = |\mathbf{a} - \mathbf{b}| = \sqrt{\sum_{i=1}^{n} (a_i - b_i)^2}$$

Para embeddings de LLMs, cosine similarity es generalmente la mejor opción porque es invariante a la escala.

Matriz de Similitud

Para matching entre query y múltiples candidates, construimos una matriz:

$$S_{ij} = \text{sim}(\mathbf{q}_i, \mathbf{c}_j)$$

🔬 Approach 1: Embeddings-Based Matching

La aproximación clásica: usar sentence embeddings y medir similitud coseno.

from sentence_transformers import SentenceTransformer
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

class EmbeddingMatcher:
    """
    Text matching basado en sentence embeddings.
    Usa sentence-transformers para generar embeddings densos.
    """
    
    def __init__(self, model_name: str = "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"):
        self.model = SentenceTransformer(model_name)
    
    def encode(self, texts: list[str]) -> np.ndarray:
        """Genera embeddings para una lista de textos."""
        return self.model.encode(texts, convert_to_tensor=True).cpu().numpy()
    
    def compute_similarity(self, query: str, candidates: list[str]) -> list[dict]:
        """
        Calcula similitud entre query y candidates.
        Retorna lista ordenada por similitud.
        """
        # Encode
        query_emb = self.encode([query])
        candidate_emb = self.encode(candidates)
        
        # Cosine similarity
        similarities = cosine_similarity(query_emb, candidate_emb)[0]
        
        # Ordenar por similitud
        results = sorted(
            zip(candidates, similarities),
            key=lambda x: x[1],
            reverse=True
        )
        
        return [
            {"text": text, "similarity": float(sim)} 
            for text, sim in results
        ]
    
    def compute_similarity_matrix(self, texts_a: list[str], texts_b: list[str]) -> np.ndarray:
        """
        Computa matriz de similitud entre dos listas de textos.
        Útil para retrieval y deduplicación.
        """
        emb_a = self.encode(texts_a)
        emb_b = self.encode(texts_b)
        return cosine_similarity(emb_a, emb_b)

# Ejemplo
matcher = EmbeddingMatcher()

query = "¿Cómo hago para devolver un producto?"
candidates = [
    "Proceso de devolución de artículos",
    "Quiero cambiar mi pedido",
    "El clima hoy en Bogotá",
    "Política de reembolso y cambios",
    "Cómo cancelar una orden"
]

results = matcher.compute_similarity(query, candidates)
print(f"Query: {query}\n")
for r in results:
    print(f"Similitud: {r['similarity']:.3f} | {r['text']}")

🔬 Approach 2: LLM-Based Matching (Cross-Encoder)

Para mayor precisión, cross-encoders consideran la interacción entre query y documento jointly.

from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch
import torch.nn.functional as F

class CrossEncoderMatcher:
    """
    Text matching usando Cross-Encoder.
    Considera query y documento jointly para mayor precisión.
    """
    
    def __init__(self, model_name: str = "cross-encoder/ms-marco-MiniLM-L-12-v2"):
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModelForSequenceClassification.from_pretrained(model_name)
        self.model.eval()
    
    def predict(self, query: str, documents: list[str]) -> list[dict]:
        """
        Predice scores de relevancia entre query y documentos.
        """
        # Preparar pares [query, doc]
        pairs = [[query, doc] for doc in documents]
        
        # Tokenizar
        inputs = self.tokenizer(
            pairs,
            padding=True,
            truncation=True,
            max_length=512,
            return_tensors="pt"
        )
        
        # Predicción
        with torch.no_grad():
            outputs = self.model(**inputs)
            scores = outputs.logits.squeeze(-1)
            probs = torch.sigmoid(scores)
        
        # Ordenar por score
        results = sorted(
            zip(documents, probs.numpy(), scores.numpy()),
            key=lambda x: x[1],
            reverse=True
        )
        
        return [
            {
                "text": doc,
                "relevance_score": float(prob),
                "raw_score": float(score)
            }
            for doc, prob, score in results
        ]

class LLMPoweredMatcher:
    """
    Combinación de embeddings + LLM para text matching.
    1. Retrieval inicial con embeddings (rápido)
    2. Re-ranking con cross-encoder (preciso)
    3. Verificación opcional con LLM
    """
    
    def __init__(self):
        self.embedding_matcher = EmbeddingMatcher()
        self.cross_encoder = CrossEncoderMatcher()
    
    def match(self, query: str, candidates: list[str], top_k: int = 5, use_llm_verification: bool = False) -> list[dict]:
        """
        Pipeline completo de matching.
        """
        # Paso 1: Retrieval rápido con embeddings
        initial_results = self.embedding_matcher.compute_similarity(query, candidates)
        top_candidates = [r["text"] for r in initial_results[:top_k * 2]]
        
        # Paso 2: Re-ranking con cross-encoder
        reranked = self.cross_encoder.predict(query, top_candidates)
        
        # Paso 3: Verificación opcional con LLM
        if use_llm_verification:
            reranked = self._llm_verify(query, reranked)
        
        return reranked[:top_k]
    
    def _llm_verify(self, query: str, results: list[dict]) -> list[dict]:
        """
        Usa LLM para verificar si el matching tiene sentido.
        """
        from transformers import pipeline
        
        verifier = pipeline(
            "text-generation",
            model="google/flan-t5-small",
            max_length=100
        )
        
        verified = []
        for r in results:
            prompt = f"Is '{r['text']}' relevant to '{query}'? Answer yes or no."
            answer = verifier(prompt)[0]["generated_text"].lower()
            
            if "yes" in answer or "relevant" in answer:
                r["llm_verified"] = True
                verified.append(r)
            else:
                r["llm_verified"] = False
        
        return verified

# Ejemplo completo
matcher = LLMPoweredMatcher()
query = "cómo reclamar un reembolso"
documents = [
    "Para devolver un producto, visite nuestra tienda con el recibo",
    "Reembolso en 5-7 días hábiles",
    "El presidente anunció nuevas medidas económicas",
    "Pasos para procesar una devolución",
    "Cambios y devoluciones tienen costo de envío",
    "Mi pedido llegó dañado qué hago"
]

results = matcher.match(query, documents, top_k=3)
print(f"Query: {query}\n")
for r in results:
    print(f"Score: {r['relevance_score']:.3f} | {r['text']}")

🔄 Re-Ranking Strategies

El re-ranking es crucial porque los embeddings tienen limitaciones. Aquí las estrategias principales:

import numpy as np
from typing import Callable

class Reranker:
    """
    Framework para diferentes estrategias de re-ranking.
    """
    
    @staticmethod
    def reciprocal_rank(candidate_scores: list[float], k: int = 60) -> float:
        """
        Reciprocal Rank Fusion (RRF).
        Combina múltiples rankings en uno solo.
        
        Formula: RRF(score) = Σ 1/(k + rank_i)
        """
        return sum(1.0 / (k + rank) for rank, _ in enumerate(candidate_scores, 1))
    
    @staticmethod
    def weighted_rrf(
        candidate_scores: list[tuple[str, float]], 
        weights: list[float],
        k: int = 60
    ) -> float:
        """
        RRF ponderado — combina scores de múltiples retrievers.
        """
        return sum(
            w * (1.0 / (k + rank)) 
            for w, (_, score) in zip(weights, candidate_scores)
        )
    
    @staticmethod
    def score_normalization(scores: list[float], method: str = "min-max") -> list[float]:
        """
        Normaliza scores a [0, 1].
        """
        if method == "min-max":
            min_s, max_s = min(scores), max(scores)
            if max_s == min_s:
                return [0.5] * len(scores)
            return [(s - min_s) / (max_s - min_s) for s in scores]
        elif method == "z-score":
            mean = np.mean(scores)
            std = np.std(scores)
            if std == 0:
                return [0.0] * len(scores)
            return [(s - mean) / std for s in scores]
        elif method == "sigmoid":
            return [1.0 / (1.0 + np.exp(-s)) for s in scores]
        
        return scores

class HybridReranker:
    """
    Combina múltiples estrategias de retrieval con ponderación.
    """
    
    def __init__(self):
        self.embedding_matcher = EmbeddingMatcher()
        self.cross_encoder = CrossEncoderMatcher()
    
    def hybrid_search(
        self, 
        query: str, 
        candidates: list[str],
        weights: dict = {"embedding": 0.3, "cross_encoder": 0.7}
    ) -> list[dict]:
        """
        Búsqueda híbrida: combina embedding + cross-encoder.
        """
        # Embedding scores
        emb_results = self.embedding_matcher.compute_similarity(query, candidates)
        emb_scores = {r["text"]: r["similarity"] for r in emb_results}
        
        # Cross-encoder scores
        ce_results = self.cross_encoder.predict(query, candidates)
        ce_scores = {r["text"]: r["relevance_score"] for r in ce_results}
        
        # Normalizar scores
        emb_vals = list(emb_scores.values())
        ce_vals = list(ce_scores.values())
        
        emb_norm = Reranker.score_normalization(emb_vals, "min-max")
        ce_norm = Reranker.score_normalization(ce_vals, "min-max")
        
        emb_scores_norm = dict(zip(emb_scores.keys(), emb_norm))
        ce_scores_norm = dict(zip(ce_scores.keys(), ce_norm))
        
        # Combinar con pesos
        combined_scores = {}
        for text in emb_scores:
            combined = (
                weights["embedding"] * emb_scores_norm.get(text, 0) +
                weights["cross_encoder"] * ce_scores_norm.get(text, 0)
            )
            combined_scores[text] = combined
        
        # Ordenar
        results = sorted(
            combined_scores.items(),
            key=lambda x: x[1],
            reverse=True
        )
        
        return [
            {"text": text, "combined_score": float(score)}
            for text, score in results
        ]

# Ejemplo
reranker = HybridReranker()
results = reranker.hybrid_search(
    query="cómo hacer un pedido",
    candidates=[
        "Proceso para realizar una compra",
        "El clima",
        "Pasos de checkout",
        "Devoluciones",
        "Crear cuenta nueva"
    ],
    weights={"embedding": 0.4, "cross_encoder": 0.6}
)
print("Hybrid Search Results:")
for r in results:
    print(f"  {r['combined_score']:.3f} | {r['text']}")

📊 Métricas de Evaluación

No basta con decir "funciona bien". Hay que medirlo:

  • MRR (Mean Reciprocal Rank): Posición del primer resultado relevante
  • NDCG (Normalized Discounted Cumulative Gain): Calidad del ranking completo
  • Recall@K: ¿Cuántos relevantes encontré en los top K?
  • Precision@K: De los top K, cuántos son relevantes
  • MAP (Mean Average Precision): Precisión promedia en todos los relevantes
from sklearn.metrics import ndcg_score
import numpy as np

def evaluate_matching(
    query_results: list[list[tuple[str, bool]]],  # [(text, relevant), ...] por query
    k_values: list[int] = [1, 3, 5, 10]
) -> dict:
    """
    Evalúa sistema de matching con múltiples métricas.
    
    Args:
        query_results: Lista de resultados por query
                       Cada resultado es lista de (text, relevant)
        k_values: Valores de K para Precision@K y Recall@K
    """
    metrics = {
        "mrr": [],
        "ndcg": [],
        "precision_at_k": {k: [] for k in k_values},
        "recall_at_k": {k: [] for k in k_values},
    }
    
    for results in query_results:
        # Calcular relevancias
        relevances = [1 if rel else 0 for _, rel in results]
        scores = list(range(len(results), 0, -1))  # Scores decrecientes por posición
        
        # MRR
        first_relevant = next((i+1 for i, (_, rel) in enumerate(results) if rel), None)
        if first_relevant:
            metrics["mrr"].append(1.0 / first_relevant)
        else:
            metrics["mrr"].append(0.0)
        
        # NDCG
        if len(results) > 1:
            ndcg = ndcg_score([relevances], [scores], k=len(results))
            metrics["ndcg"].append(ndcg)
        
        # Precision@K y Recall@K
        relevant_count = sum(relevances)
        for k in k_values:
            top_k_rel = sum(relevances[:k])
            precision = top_k_rel / k if k > 0 else 0
            recall = top_k_rel / relevant_count if relevant_count > 0 else 0
            
            metrics["precision_at_k"][k].append(precision)
            metrics["recall_at_k"][k].append(recall)
    
    # Promediar
    final_metrics = {
        "MRR": np.mean(metrics["mrr"]),
        "NDCG": np.mean(metrics["ndcg"]) if metrics["ndcg"] else 0,
    }
    
    for k in k_values:
        final_metrics[f"Precision@{k}"] = np.mean(metrics["precision_at_k"][k])
        final_metrics[f"Recall@{k}"] = np.mean(metrics["recall_at_k"][k])
    
    return final_metrics

# Ejemplo
sample_results = [
    [("doc1", True), ("doc2", True), ("doc3", False), ("doc4", True), ("doc5", False)],
    [("doc6", False), ("doc7", True), ("doc8", True), ("doc9", True), ("doc10", False)],
]

metrics = evaluate_matching(sample_results)
print("=" * 50)
print("EVALUACIÓN DE TEXT MATCHING")
print("=" * 50)
for metric, value in metrics.items():
    print(f"{metric}: {value:.3f}")

⚠️ Los 3 Errores Más Comunes

❌ Error 1: Usar Matching Léxico Cuando Semantic Es Mejor

El problema: Buscar por palabras exactas. "Solicitar reembolso" no encuentra "pedir devolución" aunque significan lo mismo.

La solución: Usa embeddings semánticos. Palabras distintas, significado similar = alta similitud.

# MAL: TF-IDF o BM25 (matching léxico)
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

def lexical_match(query, documents):
    vectorizer = TfidfVectorizer()
    tfidf = vectorizer.fit_transform([query] + documents)
    return cosine_similarity(tfidf[0:1], tfidf[1:])[0]

# "solicitar reembolso" vs "pedir devolución" = 0 (léxicamente diferentes)

# BIEN: Embeddings semánticos
def semantic_match(query, documents):
    matcher = EmbeddingMatcher()
    return matcher.compute_similarity(query, documents)

# "solicitar reembolso" vs "pedir devolución" = ~0.85 (semánticamente similares)

❌ Error 2: No Usar Re-Ranking

El problema: Los embeddings capturan generalidad pero pierden precisión en detalles. Un buen embedding retrieval tiene recall alto pero precisión media.

La solución: Pipeline de dos etapas — retrieval rápido con embeddings + re-ranking fino con cross-encoder o LLM.

# MAL: Solo embeddings
results = matcher.embedding_matcher.compute_similarity(query, candidates)

# BIEN: Hybrid con re-ranking
results = matcher.hybrid_search(
    query, 
    candidates,
    weights={"embedding": 0.3, "cross_encoder": 0.7}
)
# El re-ranking refina los top-k del embedding matcher

❌ Error 3: No Evaluar Con Métricas Apropiadas

El problema: "El modelo funciona bien" no es una métrica. Accuracy en matching es casi inútil si no mides ranking.

La solución: Usa MRR, NDCG, Precision@K para ranking. Accuracy solo si es clasificación directa.

# MAL: Solo accuracy
from sklearn.metrics import accuracy_score
accuracy_score(labels, predictions)  # Inadecuado para ranking

# BIEN: Métricas de ranking
metrics = evaluate_matching(query_results)
print(f"MRR: {metrics['MRR']:.3f}")  # Mean Reciprocal Rank
print(f"NDCG: {metrics['NDCG']:.3f}")  # Normalized DCG
print(f"Precision@5: {metrics['Precision@5']:.3f}")  # Precisión en top-5

📈 Resumen y Cierre

Hoy aprendimos que el text matching va mucho más allá de buscar palabras. Recapitulemos:

  • Embeddings: Rápidos, buenos para retrieval en escala
  • Cross-encoders: Más precisos, consideran query+document jointly
  • Re-ranking: Combina lo mejor de ambos mundos
  • Métricas: MRR, NDCG, Precision@K para ranking; no accuracy

Los 3 errores a evitar:

  1. No uses matching léxico cuando puedes usar semántico
  2. Siempre incluye re-ranking en tu pipeline
  3. Mide con métricas de ranking, no de clasificación

El 80% lo hace mal, parcero — pero tú ahora estás en el 20% que lo hace bien. Y lo mejor es que estos principios aplican desde chatbots hasta sistemas de búsqueda enterprise.

Algo que siempre olvido: los embeddings no son iguales para todos los dominios. Un embedding entrenado en Wikipedia puede no funcionar bien para texto médico o legal. Siempre haz fine-tuning o usa embeddings específicos del dominio cuando puedas.
