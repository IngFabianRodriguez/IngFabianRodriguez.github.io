Intro

En Medellín, un call center de Bancolombia recibe 10,000 llamadas diarias. El operador promedio tarda 4 minutos en procesar una solicitud de información de cuenta. ¿Y si le dijera que con un voice interface bien implementado ese tiempo se reduce a 45 segundos, con mayor precisión y sinfadiga? La voz es la modality más natural para los humanos — nacemos hablando, no escribiendo prompts. Sin embargo, el 75% de los equipos salta directamente a chatbots de texto cuando diseña interfaces de IA, ignorando que la voz es un canal completamente diferente que requiere思考 distinta. El 25% que sí la implementa bien está diferenciándose con experiencias que se sienten como magia. Hoy desglosamos cómo construir voice interfaces con LLMs que realmente funcionen.

¿Por qué Voice es Diferente?

La voz no es "texto con delay". Es una modality con características únicas:

  • Latencia baja es crítica: 300ms es el umbral para que una conversación se sienta natural.超过1 segundo y se rompe el flujo.
  • Prosodia carries meaning: el tono, ritmo y énfasis изменяют el significado tanto como las palabras
  • Turn-taking es complejo: saber cuándo hablar, cuándo escuchar, cuándo interrumpir
  • Error recovery es diferente: en texto puedes editar; en voz necesitas strategies de confirmación y repair

La fórmula del Round-Trip Time (RTT) en un pipeline de voz:

$$RTT = T_{STT} + T_{LLM} + T_{TTS}$$

Donde cada componente tiene su propia latencia característica. El objetivo es mantener RTT < 300ms para interactividad natural.

Arquitectura de un Voice Interface con LLM

Un pipeline completo de voice interface incluye:


from dataclasses import dataclass
from typing import Optional, Literal
import asyncio

@dataclass
class VoiceMessage:
    audio_bytes: bytes
    transcript: Optional[str] = None
    intent: Optional[str] = None
    entities: Optional[dict] = None
    confidence: float = 0.0

@dataclass  
class VoiceResponse:
    text: str
    audio_bytes: Optional[bytes] = None
    should_speak: bool = True
    interruptible: bool = True

class VoiceInterfacePipeline:
    """
    Pipeline de voice interface con LLM.
    
    Flujo: Audio → STT → LLM → TTS → Audio
    """
    
    def __init__(self, config: VoiceConfig):
        # 1. Speech-to-Text (STT)
        self.stt = WhisperSTT(
            model_size=config.stt_model,  # tiny/base/small/medium/large
            language=config.language,
            timestamp=True
        )
        
        # 2. Intent recognition + NER (lightweight, runs with STT)
        self.intent_parser = IntentParser(
            model=config.intent_model
        )
        
        # 3. LLM para generación de respuestas
        self.llm = LLM(
            model=config.llm_model,
            system_prompt=config.system_prompt,
            temperature=config.temperature
        )
        
        # 4. Text-to-Speech (TTS)
        self.tts = CoquiTTS(
            model=config.tts_model,
            voice=config.voice_clone  # opción de voice cloning
        )
        
        # 5. Audio buffer y turn management
        self.audio_buffer = RingBuffer(size=config.buffer_size)
        self.vad = VoiceActivityDetection()  # detecta cuándo habla el usuario
        self.turn_manager = TurnManager()

    async def process_turn(self, audio_chunk: bytes) -> VoiceResponse:
        """
        Procesa un turno de voz completo.
        """
        # Detectar si hay voz activa
        is_speech = self.vad.is_speech(audio_chunk)
        
        if not is_speech:
            return VoiceResponse(text="", should_speak=False)
        
        # 1. STT: audio → texto
        transcript = await self.stt.transcribe(audio_chunk)
        
        # 2. Parsear intent y entities
        intent_data = self.intent_parser.parse(transcript)
        
        # 3. Verificar que el LLM recebeu tudo corretamente
        if not self.turn_manager.should_respond(intent_data):
            # Interlocutor no terminó, esperar más input
            return VoiceResponse(text="", should_speak=False)
        
        # 4. Generar respuesta con LLM
        llm_response = await self.llm.generate(
            context=self.conversation_history,
            user_input=transcript,
            intent=intent_data
        )
        
        # 5. Actualizar historial
        self.conversation_history.add("user", transcript)
        self.conversation_history.add("assistant", llm_response.text)
        
        # 6. TTS: texto → audio
        if llm_response.should_speak:
            audio_response = await self.tts.synthesize(
                llm_response.text,
                voice=self.voice_config
            )
        else:
            audio_response = None
        
        return VoiceResponse(
            text=llm_response.text,
            audio_bytes=audio_response,
            should_speak=llm_response.should_speak,
            interruptible=llm_response.interruptible
        )

Speech-to-Text (STT) con Whisper

Whisper de OpenAI es el estándar actual para STT en producción. Pero hay que configurarlo bien:


import whisper
import numpy as np
from typing import AsyncGenerator

class WhisperSTT:
    def __init__(self, model_size: str = "medium", language: str = "es"):
        self.model = whisper.load_model(model_size)
        self.language = language
        self.sample_rate = 16000
        
        # Timings para control de flujo
        self.last_transcript_time = 0
        
    async def transcribe(
        self, 
        audio: np.ndarray, 
        partial: bool = False
    ) -> str:
        """
        Transcribe audio a texto.
        
        Args:
            audio: numpy array de audio (16kHz, mono, float32)
            partial: si True, devuelve transcripción parcial (para streaming)
        """
        # Normalizar
        audio = audio.astype(np.float32) / 32768.0
        
        # Opciones de decodificación
        options = {
            "language": self.language,
            "task": "transcribe",
            "beam_size": 5,
            "best_of": 5,
            "temperature": 0.0,  # más determinístico
            "condition_on_previous_text": True,  # coherencia contextual
        }
        
        if partial:
            # Para streaming, usar timestamps
            options["return_segments"] = True
            
        result = self.model.transcribe(audio, **options)
        
        return result["text"].strip()
    
    async def transcribe_streaming(
        self, 
        audio_stream: AsyncGenerator[np.ndarray, None]
    ) -> AsyncGenerator[str, None]:
        """
        Versión streaming para baja latencia.
        Devuelve fragmentos de texto conforme se procesan.
        """
        buffer = np.array([], dtype=np.float32)
        
        async for chunk in audio_stream:
            buffer = np.concatenate([buffer, chunk])
            
            # Procesar cada 5 segundos de audio
            if len(buffer) >= self.sample_rate * 5:
                text = await self.transcribe(buffer, partial=True)
                if text:
                    yield text
                # Mantener últimos 2 seg para continuidad
                buffer = buffer[-self.sample_rate * 2:]

Manejo de Turn-Taking

El turn-taking es lo que hace que una voz interface se sienta natural o robótica. La clave es detectar:

  1. Cuando el usuario terminó de hablar: VAD + silence detection
  2. Cuando el asistente debe empezar: después de generar y pre-roll del TTS
  3. Cuando interrumpir es apropiado: durante pausas naturales del TTS

import torch
from scipy.signal import find_peaks

class VoiceActivityDetection:
    """
    Detecta cuándo hay voz activa vs silencio.
    Usa energía de señal + spectral features.
    """
    
    def __init__(self, energy_threshold: float = 0.02):
        self.energy_threshold = energy_threshold
        self.speech_prob_history = []
        
    def is_speech(self, audio: np.ndarray) -> bool:
        """Detecta si hay voz en el audio."""
        # Calcular energía RMS
        energy = np.sqrt(np.mean(audio ** 2))
        
        # Calcular zero-crossing rate (más alto para voz)
        zcr = np.mean(np.abs(np.diff(np.sign(audio)))) / 2
        
        # Heurística simple
        is_speech = energy > self.energy_threshold and zcr > 0.1
        
        self.speech_prob_history.append(float(is_speech))
        if len(self.speech_prob_history) > 10:
            self.speech_prob_history.pop(0)
            
        return is_speech
    
    def detect_turn_end(self, audio: np.ndarray) -> bool:
        """
        Detecta cuándo terminó un turno de habla.
        Busca silencio prolongado (500ms+).
        """
        # Dividir en frames de 20ms
        frame_size = int(0.02 * 16000)  # 20ms a 16kHz
        n_frames = len(audio) // frame_size
        
        silence_frames = 0
        for i in range(n_frames):
            frame = audio[i * frame_size:(i + 1) * frame_size]
            if np.sqrt(np.mean(frame ** 2)) < self.energy_threshold:
                silence_frames += 1
            else:
                silence_frames = 0
        
        # Si hay 25+ frames consecutivos de silencio (~500ms), fin de turno
        return silence_frames >= 25


class TurnManager:
    """
    Gestiona el turno de palabra en la conversación.
    """
    
    def __init__(self):
        self.user_speaking = False
        self.assistant_speaking = False
        self.last_user_speech_time = 0
        self.interruption_allowed = False
        
    def should_respond(self, intent_data) -> bool:
        """
        Decide si el asistente debe responder.
        """
        # Estrategias de decisión
        if self.assistant_speaking:
            return False  # Ya estamos hablando
        
        if not self.user_speaking:
            return False  # Usuario no está hablando
        
        # Esperar confirmaciones de fim de turno
        turn_ended = self._detect_turn_end()
        
        return turn_ended
    
    def _detect_turn_end(self) -> bool:
        """Detecta si el turno del usuario terminó."""
        import time
        elapsed = time.time() - self.last_user_speech_time
        
        # Más de 1.5 seg de silencio = fin de turno
        return elapsed > 1.5

Los 3 Errores Comunes (y sus Soluciones)

Error 1: No considerar la voz como modality propia

Síntoma: Diseñas un voice bot copiando exactamente tu chatbot de texto. Resultado: delays incómodos, respuestas que no suenan naturales, y usuarios colgando.

Fix: Diseña para voz desde cero. La voz requiere:

Error 2: Tratar la voz como texto con delay

Síntoma: Haces STT → LLM → TTS secuencial, esperando toda la respuesta de texto antes de empezar TTS. Latencia > 3 segundos.

Fix: Implementa streaming y speculative TTS:


class StreamingVoicePipeline:
    """
    Pipeline optimizado para baja latencia.
    """
    
    async def process_streaming(self, audio_stream):
        """
        Procesa audio en streaming mientras genera respuesta.
        """
        # 1. STT streaming con partial results
        transcript_queue = asyncio.Queue()
        
        async def transcribe_task():
            async for partial_text in self.stt.transcribe_streaming(audio_stream):
                await transcript_queue.put(partial_text)
        
        # 2. LLM con streaming output
        async def llm_task():
            full_response = ""
            async for token in self.llm.generate_streaming(
                self.build_prompt(transcript_queue)
            ):
                full_response += token
                # 3. Empezar TTS ANTES de tener toda la respuesta
                await self.tts.add_token(token)  # speculative
                yield token  # yield tokens para logging
        
        # 4. TTS reproduce mientras recibe tokens
        async def tts_task():
            async for audio_chunk in self.tts.stream_synthesize():
                await self.play_audio(audio_chunk)  # play in real-time
        
        # Ejecutar todo en paralelo
        await asyncio.gather(
            transcribe_task(),
            self.consume_and_play(llm_task())
        )

    async def llm_generate_streaming(self, prompt):
        """
        LLM generando tokens uno por uno.
        """
        async for token in self.llm.astream(prompt):
            yield token

Error 3: No manejar errores de STT/TTS graceful

Síntoma: STT devuelve basura o TTS falla, y el usuario queda colgado sin saber qué pasó.

Fix: Implementa graceful degradation:


class ErrorHandlingVoice:
    """
    Manejo robusto de errores en pipeline de voz.
    """
    
    # Códigos de error específicos para voz
    VOICE_ERROR_CODES = {
        "STT_NOISE": "No pude entender bien, ¿me lo repites más claro?",
        "STT_SILENCE": "No te escuché bien, ¿podrías hablar más fuerte?",
        "STT_LATENCY": "Se perdió un poco de tu mensaje, ¿qué decías?",
        "TTS_ERROR": "Tengo problemas con el audio, pero aquí está tu respuesta en texto.",
        "LLM_ERROR": "Tuve un problema procesando tu solicitud, ¿puedes repetir?",
        "NETWORK_TIMEOUT": "Se cayó la conexión, déjame intentarlo de nuevo.",
    }
    
    async def process_with_error_handling(self, audio):
        try:
            # STT con timeout
            transcript = await asyncio.wait_for(
                self.stt.transcribe(audio),
                timeout=5.0
            )
        except asyncio.TimeoutError:
            return self._error_response("STT_LATENCY")
        
        # Verificar calidad de transcript
        if self._low_quality_transcript(transcript):
            return self._error_response("STT_NOISE")
        
        if len(transcript.strip()) == 0:
            return self._error_response("STT_SILENCE")
        
        try:
            response = await self.llm.generate(transcript)
        except Exception as e:
            return self._error_response("LLM_ERROR")
        
        try:
            audio_response = await asyncio.wait_for(
                self.tts.synthesize(response),
                timeout=10.0
            )
        except asyncio.TimeoutError:
            return VoiceResponse(
                text=response,  # Devolver texto si TTS falla
                should_speak=False,
                audio_bytes=None
            )
        
        return VoiceResponse(text=response, audio_bytes=audio_response)
    
    def _low_quality_transcript(self, text: str) -> bool:
        """Detecta transcripciones de baja calidad."""
        # Demasiados caracteres especiales
        special_char_ratio = sum(1 for c in text if not c.isalnum() and not c.isspace()) / max(len(text), 1)
        if special_char_ratio > 0.3:
            return True
        
        # Muy corto o muy largo
        if len(text) < 3 or len(text) > 500:
            return True
        
        return False
    
    def _error_response(self, error_code: str) -> VoiceResponse:
        """Genera respuesta de error friendly."""
        return VoiceResponse(
            text=self.VOICE_ERROR_CODES.get(error_code, "Tuve un problema, ¿me lo repites?"),
            should_speak=True,
            audio_bytes=None
        )

Métricas para Voice Interfaces

No puedes medir un voice bot igual que un chatbot de texto:

  • Latencia percibida: time-to-first-audio (TTFA) — ideally < 500ms
  • Word Error Rate (WER): qué tan preciso es el STT
  • Mean Opinion Score (MOS): rating 1-5 de calidad de voz
  • Turn-Taking Accuracy: % de veces que el bot responde en el momento correcto
  • Completion Rate: % de tareas completadas sin escalar a humano

$$MOS = \frac{1}{N}\sum_{i=1}^{N} \frac{\sum_{j=1}^{M} r_{ij}}{M}$$

Donde $r_{ij}$ es el rating del juez $i$ para el sample $j$.

Resumen

Los voice interfaces con LLMs son un superpower subestimado:

  • STT + LLM + TTS: la tríada fundamental del pipeline de voz
  • Latencia < 300ms: el umbral crítico para naturalidad
  • Streaming: imperative para evitar delays percibidos
  • Turn-taking: gestionar cuando hablar y cuando escuchar es tan importante como qué decir
  • Error recovery diferente a texto: confirmación implícita, nunca dejar al usuario colgado

La voz es el modality más natural para los humanos. Cuando la implementas bien, la IA se siente como un помощник real, no como un robot con el que tienes que hablar lento y claro.
