Clustering para Embeddings — K-means vs DBSCAN

Hagale pues, parcero. Hoy es el Día 197 y vamos a meternos en el mundo del clustering para embeddings. Cuando tienes miles o millones de vectores de palabras, imágenes o cualquier cosa que puedas embeddear, necesitas organizarlos. ¿Cómo agrupas cosas similares sin que un humano tenga que label todo? Eso es lo que vemos hoy, con código PyTorch real y los errores que el 80% de la gente comete. Sirvete un tintico y vamos pa'llá.

🎯 Por Qué Clustering en High-Dimensional Spaces?

Los embeddings viven en espacios de alta dimensionalidad — 768, 1024, 1536 dimensiones no son raros. En estos espacios pasan cosas extrañas:

  • Maldición de la dimensionalidad: La distancia euclidiana pierde смысл cuando hay demasiadas dimensiones
  • Distancia coseno al rescate: El coseno del ángulo entre vectores funciona mejor que la distancia L2
  • Clusters no esféricos: K-means asume clusters esféricos, pero la realidad es más compleja

La métrica que usas importa. En embeddings, casi siempre es mejor usar cosine_similarity o 1 - cosine_distance en vez de distancias euclidianas.

📐 La Matemática del Clustering

K-means: Minimizar Inercia

K-means busca minimizar la suma de distancias cuadráticas intra-cluster:

$$J = \sum_{i=1}^{k} \sum_{x \in C_i} \| x - \mu_i \|^2$$

Donde $\mu_i$ es el centroide del cluster $C_i$. El algoritmo alterna entre asignar puntos al cluster más cercano y recalcular centroides hasta convergencia.

DBSCAN: Densidad de Puntos

DBSCAN define clusters como regiones densas separadas por regiones de baja densidad. Dos parámetros:

  • $\epsilon$ (eps): Radio de vecindad
  • MinPts: Mínimo de puntos para considerar un core point

$$N_\epsilon(p) = \{ q \in D \mid d(p,q) \leq \epsilon \}$$

Un punto es core point si tiene al menos MinPts puntos en su $\epsilon$-vecindad. Puntos que no son core points pero son alcanzables desde uno son border points. El resto son noise.

HDBSCAN: Hierarchical DBSCAN

HDBSCAN construye un dendrograma de densidades y corta en el nivel óptimo automáticamente:

$$\lambda = \frac{1}{d(m_i, m_j)}$$

Donde $d$ es la distancia y $\lambda$ es la "inversa de la distancia" o persistencia del cluster.

🚀 Implementación en PyTorch

K-means para Embeddings

import torch
import torch.nn.functional as F
from sklearn.cluster import KMeans
import numpy as np

def kmeans_clustering(embeddings, n_clusters, device='cuda'):
    """
    K-means clustering para embeddings.
    
    Args:
        embeddings: Tensor de forma (N, D) con N embeddings de D dimensiones
        n_clusters: Número de clusters desired
    Returns:
        labels: Tensor de forma (N,) con el cluster asignado a cada embedding
        centroids: Tensor de forma (n_clusters, D) con los centroides
    """
    # Normalizar embeddings para usar cosine similarity
    embeddings_norm = F.normalize(embeddings, p=2, dim=1)
    
    # Convertir a numpy para sklearn (más eficiente para K-means)
    embeddings_np = embeddings_norm.cpu().numpy()
    
    kmeans = KMeans(n_clusters=n_clusters, random_state=42, n_init=10)
    labels = kmeans.fit_predict(embeddings_np)
    centroids = torch.tensor(kmeans.cluster_centers_, device=device)
    
    return torch.tensor(labels), centroids


# Ejemplo: clusterizar embeddings de palabras
embeddings = torch.randn(10000, 768, device='cuda')  # 10k embeddings, 768 dims
n_clusters = 50

labels, centroids = kmeans_clustering(embeddings, n_clusters)
print(f"Forma de labels: {labels.shape}")
print(f"Forma de centroids: {centroids.shape}")
print(f"Puntos por cluster (primeros 5): {labels[:100].bincount()[:5]}")

DBSCAN para Embeddings

from sklearn.cluster import DBSCAN
from sklearn.metrics.pairwise import cosine_similarity

def dbscan_clustering(embeddings, eps=0.5, min_samples=5, device='cuda'):
    """
    DBSCAN clustering para embeddings.
    Detecta automáticamente outliers (noise points).
    
    Args:
        embeddings: Tensor de forma (N, D)
        eps: Radio máximo para considerar vecinos (para cosine distance, 0.5-0.8 es común)
        min_samples: Puntos mínimos para un cluster
    Returns:
        labels: -1 para noise, 0, 1, 2... para clusters
        n_clusters: Número de clusters descubiertos
    """
    # Normalizar para cosine similarity
    embeddings_norm = F.normalize(embeddings, p=2, dim=1)
    embeddings_np = embeddings_norm.cpu().numpy()
    
    # Para cosine similarity: eps en [0, 2], donde 0 = mismo vector
    # sklearn usa distance, así que convertimos: distance = 1 - cosine_similarity
    # Un eps de 0.5 significa que aceptamos pares con similarity >= 0.5
    cos_eps = 1 - eps  # Convertir de similarity threshold a distance threshold
    
    db = DBSCAN(eps=cos_eps, min_samples=min_samples, metric='cosine', n_jobs=-1)
    labels = db.fit_predict(embeddings_np)
    
    n_clusters = len(set(labels)) - (1 if -1 in labels else 0)
    n_noise = list(labels).count(-1)
    
    return torch.tensor(labels), n_clusters, n_noise


# Ejemplo práctico
embeddings = torch.randn(10000, 768, device='cuda')
labels, n_clusters, n_noise = dbscan_clustering(
    embeddings, 
    eps=0.7,  # Accept vectors with cosine similarity >= 0.7
    min_samples=10
)
print(f"Clusters encontrados: {n_clusters}")
print(f"Puntos de ruido (noise): {n_noise} ({100*n_noise/len(labels):.1f}%)")
print(f"Etiquetas únicas: {torch.unique(labels)}")

HDBSCAN para Mejor Detección de Clusters

import hdbscan

def hdbscan_clustering(embeddings, min_cluster_size=15, device='cuda'):
    """
    HDBSCAN - versión jerárquica de DBSCAN.
    Mejor para datos con clusters de diferentes densidades.
    """
    embeddings_norm = F.normalize(embeddings, p=2, dim=1)
    embeddings_np = embeddings_norm.cpu().numpy()
    
    clusterer = hdbscan.HDBSCAN(
        min_cluster_size=min_cluster_size,
        metric='cosine',  # Importante: cosine para embeddings
        cluster_selection_method='eom'  # Excess of Mass
    )
    labels = clusterer.fit_predict(embeddings_np)
    
    n_clusters = len(set(labels)) - (1 if -1 in labels else 0)
    
    # Persistencia: cuánto tiempo sobrevive cada cluster
    persistences = clusterer.cluster_persistence_
    
    return torch.tensor(labels), n_clusters, persistences


# Ejemplo
labels, n_clusters, persistences = hdbscan_clustering(embeddings, min_cluster_size=20)
print(f"Clusters: {n_clusters}")
print(f"Persistencias por cluster: {persistences}")

Silhouette Analysis para Elegir k

from sklearn.metrics import silhouette_score
import matplotlib.pyplot as plt

def find_optimal_k(embeddings, k_range=range(5, 50, 5), device='cuda'):
    """
    Encuentra el k óptimo usando silhouette score.
    Mayor silhouette = mejores clusters definidos.
    
    Silhouette score: [-1, 1]
    - Cerca de 1: clusters bien separados
    - Cerca de 0: clusters sobrepuestos
    - Cerca de -1: clustering incorrecto
    """
    embeddings_norm = F.normalize(embeddings, p=2, dim=1)
    embeddings_np = embeddings_norm.cpu().numpy()
    
    results = []
    for k in k_range:
        kmeans = KMeans(n_clusters=k, random_state=42, n_init=10)
        labels = kmeans.fit_predict(embeddings_np)
        
        if len(set(labels)) > 1:  # Necesitamos al menos 2 clusters
            score = silhouette_score(embeddings_np, labels, metric='cosine')
        else:
            score = -1
        results.append((k, score))
        print(f"k={k}: silhouette={score:.4f}")
    
    # Mejor k
    best_k, best_score = max(results, key=lambda x: x[1])
    print(f"\nMejor k: {best_k} con silhouette={best_score:.4f}")
    return results


# Uso
embeddings = torch.randn(5000, 768)
results = find_optimal_k(embeddings, k_range=range(10, 100, 10))

⚠️ Errores Comunes (y Sus Soluciones)

Error 1: Usar K-means Cuando DBSCAN Es Mejor para Datos con Noise

El problema: K-means fuerza todos los puntos a algún cluster. Si tienes outliers o ruido, los asigna al cluster más cercano distorsionando los centroides. En datos reales, siempre hay ruido.

# MAL: K-means ignora que hay noise
kmeans = KMeans(n_clusters=10)
labels = kmeans.fit_predict(embeddings)  # Todos los puntos en algún cluster

# BIEN: DBSCAN detecta noise y no lo fuerza
db = DBSCAN(eps=0.7, min_samples=10, metric='cosine')
labels = db.fit_predict(embeddings)  # -1 = noise points
noise_mask = labels == -1
print(f"Tienes {noise_mask.sum()} puntos de ruido")

La solución: Analiza la distribución de labels. Si muchos puntos son ruido esperado, usa DBSCAN o HDBSCAN. Si sabes que no hay ruido y necesitas exactamente k clusters, usa K-means.

Error 2: No Normalizar Embeddings Antes de Clustering

El problema: Embeddings de modelos como BERT o Sentence-BERT tienen información tanto en la dirección como en la magnitud. Sin normalización, puntos con mayor norma dominan las distancias.

# MAL: Sin normalizar
distances = torch.cdist(embeddings, centroids)  # La magnitud afecta

# BIEN: Normalizar L2 primero
embeddings_norm = F.normalize(embeddings, p=2, dim=1)
centroids_norm = F.normalize(centroids, p=2, dim=1)
distances = 1 - torch.mm(embeddings_norm, centroids_norm.T)  # Cosine distance

La solución: Siempre normaliza con F.normalize(x, p=2, dim=1) antes de clustering. Esto convierte la similaridad coseno en la distancia dominante.

Error 3: Elegir Número de Clusters Arbitrariamente sin Silhouette Analysis

El problema: Escoger k=10 porque "se ve bien" o "siempre uso 10" lleva a clusters subóptimos. Puede que tengas 5 o 20 clusters naturales en tus datos.

# MAL: Arbitrario
kmeans = KMeans(n_clusters=10)  # Por qué 10?

# BIEN: Análisis de silueta
silhouette_scores = []
for k in range(5, 50, 5):
    labels = KMeans(n_clusters=k).fit_predict(embeddings_np)
    score = silhouette_score(embeddings_np, labels, metric='cosine')
    silhouette_scores.append((k, score))

best_k = max(silhouette_scores, key=lambda x: x[1])[0]
print(f"k óptimo: {best_k}")

La solución: Usa silhouette analysis, elbow method, o gap statistic para elegir k datadriven. No adivines.

📊 Comparación de Algoritmos

  • K-means: Rápido, escala bien, asume clusters esféricos, sensible a outliers, requiere especificar k
  • DBSCAN: Detecta noise automáticamente, encuentra clusters de forma arbitraria, no requiere k, sensible a eps
  • HDBSCAN: Como DBSCAN pero automático, maneja diferentes densidades, más robusto, más lento

Para embeddings de texto o imágenes, HDBSCAN suele dar los mejores resultados porque no sabes cuántos "temas" o "categorías" tienes realmente.

🎯 Resumen y Cierre

Hoy cubrimos clustering para embeddings: K-means, DBSCAN y HDBSCAN. Remember:

  • Siempre normaliza embeddings antes de clustering
  • Usa cosine similarity como métrica, no euclidiana
  • DBSCAN/HDBSCAN para datos con ruido o cuando no sabes cuántos clusters hay
  • K-means cuando sabes exactamente cuántos grupos buscas y no hay ruido
  • Silhouette analysis para elegir k de forma data-driven

El clustering es la base para unsupervised learning con embeddings. Topic modeling, image clustering, document organization — todo esto usa variaciones de lo que vimos hoy.
