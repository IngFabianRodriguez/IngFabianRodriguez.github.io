Synthetic Data Generation — La técnica que el 80% ignora y que permite trainar modelos sin data privada

02 de octubre de 2026
synthetic-datallmdata-augmentationprivacy

Acá en Medellín, cuando explican machine learning, siempre empieza todo con "consigue más datos". Pero qué pasa cuando los datos son escasos, costosos de etiquetar, o peor aún — cuando son datos sensibles de pacientes, clientes bancarios o información personal? Aquí es donde entra la generación de datos sintéticos, y lo más verraco es que el 80% de los equipos de ML todavía la ignora como si fuera brujería.

Qué es Synthetic Data Generation?

Datos sintéticos son información generada artificialmente que preserva las propiedades estadísticas de los datos reales sin contener ninguna instancia real. Piénsalo así: si tienes 1,000 radiografías de tórax pero necesitas 100,000 para entrenar un modelo robusto, generas 99,000 radiografías sintéticas que mantienen las distribuciones, variaciones patológicas y características anatómicas de las originales.

La magia está en que esos datos sintéticos te permiten:

  • Entrenar sin exponer data sensible (HIPAA, GDPR, cualquier regulación)
  • Balancear clases cuando tienes imbalance severo (clínicas con pocas patologías raras)
  • Aumentar la diversidad de tu dataset sin costo de recolección
  • Crear esquinas casos (corner cases) que en la vida real casi no ocurren

La matemática detrás: cómo保住 distribuciones

El problema central es: cómo garantizo que los datos sintéticos \( \tilde{X} \) preserven las propiedades de \( X_{real} \)?

Enfoque 1: Statistical Generation

Si \( X \sim P_{data}(X) \), queremos generar \( \tilde{X} \sim P_{data}(X) \). La forma más simple es ajustar los parámetros de la distribución:

import numpy as np
from scipy import stats

# Supongamos que tenemos features continuas
real_data = np.random.exponential(scale=2.0, size=1000)

# Ajustar distribución a los datos reales
fitted_dist = stats.exponnorm.fit(real_data)

# Generar datos sintéticos de la misma distribución
synthetic_data = stats.exponnorm.rvs(*fitted_dist, size=10000)

print(f"Real mean: {np.mean(real_data):.4f}")
print(f"Synthetic mean: {np.mean(synthetic_data):.4f}")

Enfoque 2: GANs para datos tabulares

Para datos más complejos, las GANs (Generative Adversarial Networks) son el estándar. La idea es un juego minimax entre un generador \( G \) y un discriminador \( D \):

El generador crea datos sintéticos \( \tilde{X} = G(z) \) donde \( z \sim N(0,1) \). El discriminador intenta distinguir datos reales de sintéticos. El equilibrio de Nash ocurre cuando:

$$ \min_G \max_D \mathbb{E}_{x \sim P_{data}}[\log D(x)] + \mathbb{E}_{z \sim P_z}[\log(1 - D(G(z)))] $$ 
# Usando CTGAN para datos tabulares
from sdv.tabular import CTGAN

# Tu dataset real (solo metadatos, no datos sensibles)
model = CTGAN(epochs=100)
model.fit(real_dataframe)

# Generar datos sintéticos con las mismas propiedades estadísticas

# Validar que las distribuciones coinciden

print(f"Data Quality Score: {quality_score:.2%}")

Enfoque 3: LLMs para generar datos de texto

Para texto, los LLMs son increíbles generando datos sintéticos de entrenamiento:

from openai import OpenAI

client = OpenAI()

def generate_synthetic_examples(
    topic: str,
    template: str,
    n_examples: int,
    temperature: float = 0.8
) -> list[str]:
    """Genera ejemplos sintéticos usando un LLM."""
    examples = []
    for i in range(n_examples):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": f"""Eres un generador de datos sintéticos.
Tu tarea es crear ejemplos realistas de: {topic}
Usa este formato: {template}
Inyerta variación natural: diferentes estructuras, sinónimos, estilos."""},
                {"role": "user", "content": f"Genera el ejemplo #{i+1} de {n_examples}"}
            ],
            temperature=temperature
        )
        examples.append(response.choices[0].message.content)
    return examples

El peligro del Mode Collapse

Aquí es donde muchos se queman. El mode collapse ocurre cuando el generador solo produce un subconjunto limitado de las distribuciones reales — como cuando le pides variaciones de carros y solo te genera pickups Toyota.

Matemáticamente: \( \tilde{X} \sim P_{collapse}(X) \) donde \( P_{collapse} \) tiene menos modos que \( P_{data} \).

# Detectar mode collapse con clustering
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

def detect_mode_collapse(real_X, synthetic_X, n_clusters=10):
    """Detecta si hay mode collapse comparando clusters."""
    combined = np.vstack([real_X, synthetic_X])
    labels = KMeans(n_clusters=n_clusters).fit_predict(combined)
    
    # Silhouette score: bajo = mode collapse
    real_labels = labels[:len(real_X)]
    synth_labels = labels[len(real_X):]
    
    real_score = silhouette_score(real_X, real_labels)
    synth_score = silhouette_score(synthetic_X, synth_labels)
    
    # Si los scores divergen significativamente, hay mode collapse
    score_diff = abs(real_score - synth_score)
    
    if score_diff > 0.2:
        print(f"⚠️ MODE COLLAPSE DETECTED: diff={score_diff:.3f}")
        return True
    else:
        print(f"✅ No mode collapse: diff={score_diff:.3f}")
        return False

# Mitigation con diversity penalty
def diversity_penalty(generated_samples, eps=1e-6):
    """Penaliza muestras muy similares entre sí."""
    sim_matrix = generated_samples @ generated_samples.T
    # Normalize
    norms = np.linalg.norm(generated_samples, axis=1, keepdims=True)
    sim_matrix = sim_matrix / (norms @ norms.T + eps)
    # Penalize high similarity
    np.fill_diagonal(sim_matrix, 0)
    max_sim = sim_matrix.max()
    return max_sim

Validación de Calidad: El paso que el 90% se salta

GIGO — Garbage In, Garbage Out. No sirve generar datos si no validas que son buenos. Las métricas esenciales:

from sdv.evaluation import evaluate
from scipy.stats import ks_2samp, wasserstein_distance

def validate_synthetic_data_quality(real_df, synthetic_df, verbose=True):
    """Valida la calidad de datos sintéticos en múltiples dimensiones."""
    results = {}
    
    # 1. Statistical Similarity (Kolmogorov-Smirnov test)
    for col in real_df.select_dtypes(include=[np.number]).columns:
        stat, pvalue = ks_2samp(real_df[col], synthetic_df[col])
        results[f"ks_{col}"] = {"statistic": stat, "pvalue": pvalue}
        if pvalue < 0.05:
            if verbose: print(f"❌ {col}: KS rejected (p={pvalue:.4f})")
    
    # 2. Privacy metrics (utiliza расстояние Махаланобиса)
    from scipy.spatial.distance import mahalanobis
    real_mean = real_df.mean()
    real_cov = real_df.cov()
    try:
        inv_cov = np.linalg.inv(real_cov.values)
        mahal_distances = [
            mahalanobis(row.values, real_mean.values, inv_cov)
            for _, row in synthetic_df.iterrows()
        ]
        results["privacy_mahal_mean"] = np.mean(mahal_distances)
        if verbose: print(f"📊 Mean Mahalanobis distance: {np.mean(mahal_distances):.2f}")
    except np.linalg.LinAlgError:
        if verbose: print("⚠️ Covariance matrix singular, skipping privacy check")
    
    # 3. Utility: train on synthetic, test on real
    from sklearn.model_selection import train_test_split
    from sklearn.ensemble import RandomForestClassifier
    from sklearn.metrics import accuracy_score
    
    # Split real data
    X_train, X_test, y_train, y_test = train_test_split(
        real_df.drop('target', axis=1), 
        real_df['target'],
        test_size=0.2
    )
    
    # Train on synthetic
    model = RandomForestClassifier()
    model.fit(synthetic_df.drop('target', axis=1), synthetic_df['target'])
    
    # Evaluate on REAL test set
    y_pred = model.predict(X_test)
    results["utility_accuracy"] = accuracy_score(y_test, y_pred)
    
    if verbose: print(f"🎯 Utility (synthetic→real): {results['utility_accuracy']:.2%}")
    
    return results

# Uso
quality_report = validate_synthetic_data_quality(real_dataframe, synthetic_df)

Los 3 errores que mandan tu proyecto al piso

Error 1: No usar datos sintéticos cuando la data es scarce o sensitive

El problema: Te niegas a usar synthetic data por escepticismo, mientras tu competencia está entrenando modelos con 10x más datos sintéticos que tú.

El fix: Implementa synthetic data desde el día 1 cuando:

  • Tienes menos de 10,000 ejemplos etiquetados
  • Estás en healthcare, finance o cualquier dominio regulado
  • Tu dataset tiene classes con menos del 5% de representación

Error 2: Generar datos sin validar calidad (GIGO)

El problema: Lanzas el generador, usas los datos, y tu modelo empeora porque los datos sintéticos tienen distribuciones diferentes a la realidad.

El fix: Siempre ejecuta el pipeline completo de validación antes de usar sintéticos en training:

# Pipeline completo de validación
def safe_synthetic_pipeline(real_data, generator, n_samples):
    # Step 1: Generate
    synthetic = generator.generate(n_samples)
    
    # Step 2: Validate BEFORE using
    quality = validate_synthetic_data_quality(real_data, synthetic)
    
    # Step 3: Only use if quality passes threshold
    if quality["utility_accuracy"] > 0.75:
        print("✅ Synthetic data approved for training")
        return synthetic
    else:
        print("❌ Synthetic data rejected, regenerating with tighter constraints...")
        # Regenerate with different parameters
        return safe_synthetic_pipeline(real_data, generator, n_samples)

Error 3: No balancear sintéticos con datos reales

El problema: Entrenas 100% con sintéticos y tu modelo aprende artefactos del generador, no patrones reales.

El fix: La proporción óptima depende del dominio, pero típicamente:

  • Mínimo 20-30% de datos reales en tu training set
  • Usa datos reales para validación y test (nunca sintéticos ahí)
  • Considera curriculum learning: empieza con 100% real, gradual introduce sintéticos
def mix_real_synthetic(real_df, synthetic_df, real_ratio=0.3):
    """Mezcla datos reales y sintéticos manteniendo distribución."""
    n_real = int(len(real_df) * real_ratio)
    n_synth = len(real_df) - n_real  # Complement to real
    
    # Sample from synthetic
    synth_sample = synthetic_df.sample(n=n_synth)
    
    # Combine
    balanced = pd.concat([real_df, synth_sample], ignore_index=True)
    balanced = balanced.sample(frac=1).reset_index(drop=True)  # Shuffle
    
    return balanced

# En entrenamiento:
train_set = mix_real_synthetic(train_real, train_synthetic, real_ratio=0.3)
model.fit(train_set)  # Tu modelo aprende de verdad + diversidad sintética

Resumen: synthetic data no es magia, es ingeniería

La generación de datos sintéticos es una de las herramientas más poderosas en ML moderno, pero viene con su propia ingeniería. No es "generar datos y listo" — es:

  1. Entender tu distribución real antes de generar nada
  2. Elegir el generador correcto (statistical vs GAN vs LLM según el dominio)
  3. Validar como si fuera sagrado — GIGO destruye proyectos
  4. Mezclar estratégico con datos reales para preservar señal
  5. Monitorear mode collapse constantemente

En el fondo, los datos sintéticos son lo que hacemos en la vida real también: cuando un médico estudia con casos de textbooks, cuando un piloto entrena en simuladores, cuando un ingeniero diseña en CAD antes de construir. Estamos usando representantes sintéticos de la realidad para prepararnos para ella.

Eso sí — nada reemplaza la data real cuando la tienes. Los sintéticos son para cuando no hay de otra, o para cuando necesitas más de la que tienes.
