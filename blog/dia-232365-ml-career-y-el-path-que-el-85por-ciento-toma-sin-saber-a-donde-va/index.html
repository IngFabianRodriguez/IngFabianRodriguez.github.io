ML Career — El Path Que el 85% Toma Sin Saber a Dónde Va

Hagale pues, parcero. En Bogotá uno sabe que en la vida hay dos caminos: el que te toca y el que tú eliges. En ML career pasa igual — el 85% entra a trabajos de ML sin saber qué significa "ser bueno" ni cómo se avanza. Hoy desmalezamos el terreno: skills que necesitas, cómo prepare for interviews, y por qué negotiate salary no es opcional. Café en mano.

🎯 Paths en ML: IC vs Management

Antes de anything, necesitas entender que hay DOS tracks principales y no son ladder — son parallèle roads.

La ecuación de compensación por track:

$$\text{Total Compensation}_{IC} = \text{Base} + \text{Equity}_{IC} + \text{Perks}$$

$$\text{Total Compensation}_{M} = \text{Base} + \text{Equity}_{M} + \text{Perks} + \text{Management Bonus}$$

En early/mid career, ICs pueden ganar más que managers. En late career, management typically supera.

Individual Contributor (IC) Track

  • Junior ML Engineer: Scripts, pipelines, modelo baseline
  • Mid-level ML Engineer: End-to-end ownership, debugging complexo
  • Senior ML Engineer: Architecture decisions, tech debt, mentorship
  • Staff ML Engineer: Multi-team impact, standards, strategy
  • Principal ML Engineer: Org-wide technical vision

Management Track

  • ML Team Lead: 2-5 personas, noch technical contribution
  • ML Manager: 5-10 personas, hiring, performance, roadmap
  • Senior ML Manager: Multi-team, strategy, budget
  • Director/VP: Org-wide ML strategy
La decisión IC vs Management no es "tecnical vs no technical" — es qué tipo de impacto te mueve: código vs personas.

Cómo Preparar ML System Design Interview

# Framework para ML System Design Interview
"""
5 pasos para ML System Design:

1. ACLARAR EL PROBLEMA (5 min)
   - Qué exact we're predicting?
   - Qué business metrics importan?
   - Qué constraints tenemos?

2. ESCALAR EL PROBLEMA (5 min)
   - Cuantos requests/day?
   - Latency requirements?
   - Data size?

3. DATA + FEATURES (10 min)
   - Available data sources?
   - Feature engineering approach?
   - Labeling strategy?

4. MODEL ARCHITECTURE (10 min)
   - Baseline simple primero
   -然后 full architecture
   - Trade-offs (accuracy vs latency vs complexity)

5. SERVING + MONITORING (5 min)
   - Batch vs real-time?
   - How to monitor drift?
   - A/B testing strategy?
"""

# Ejemplo: Design a News Feed Ranking System
ML_SYSTEM_DESIGN_EXAMPLE = """
Problem: Rank Facebook news feed para maximize engagement

Step 1: Clarify
- We're predicting engagement score (likes, shares, time spent)
- Metric: DAU engagement rate
- Constraint: 100ms latency budget

Step 2: Scale
- 1B users, 1000 posts/user/day
- Need candidate retrieval + ranking

Step 3: Data
- User features: past engagement, demographics
- Content features: recency, author quality
- Context: time of day, device

Step 4: Model
- Retrieval: embeddings similarity (Faiss)
- Ranking: LightGBM/wide-and-deep
- Features: 100+ signals

Step 5: Serving
- Two-stage: retrieve top-1000, rank top-100
- Online evaluation: A/B test engagement
- Offline: holdout validation
"""

Cómo Showcase ML Skills a Employers

⚠️ Los 3 Errores Más Comunes

Error 1: Enfoquese Solo en Models Sin System Design

El problema: "Soy data scientist, no necesito saber de sistemas". FALSO. En la industria, 80% del trabajo es hacer que los modelos corran en producción de forma reliable. Si solo sabes hacer Jupyter notebooks, tu ceiling es analyst.

La solución: Aprende MLOps fundamentals:

# MLOps fundamentals que necesitas
MLOPS_CORE = {
    "versioning": ["DVC", "MLflow Tracking"],
    "data_pipeline": ["Airflow", "Prefect", "dbt"],
    "model_serving": ["Ray Serve", "Triton", "TorchServe", "BentoML"],
    "monitoring": ["Prometheus", "Grafana", "Evidently AI"],
    "infrastructure": ["Docker", "Kubernetes basics", "Terraform basics"]
}

Error 2: No Construir Portfolio Projects Que Demuestren Skills

El problema: "Tengo título de la U y eso debe bastar". No. Los hiring managers no confían en transcripciones — quieren ver qué puedes hacer con código real, en problemas reales. Sin portfolio, eres un stranger con un credential.

La solución: 2-3 projects fuertes > 20 proyectos mediocre. Cada proyecto debe tener:

  • README con problem statement y solution
  • Código production-ready (no scripts de Jupyter)
  • Results con metrics reales
  • Demo funcional (Streamlit/Gradio)

Error 3: No Negotiate Salary (Dejando Money on the Table)

El problema: Aceptar la primera oferta "porque ya es buena" o por miedo a perder la oportunidad. Typical mistake: dejas $10k-30k USD anuales sobre la mesa por no negociar.

La solución: Siempre negocia. Passos:

  • Research market rates con levels.fyi, glassdoor
  • Nunca seas el primero en dar un número
  • Ten siempre una otra oferta como leverage
  • Negocia total comp, no solo base
  • Pide tiempo (1 week para decidir es normal)

📊 Resumen y Cierre

ML career es un juego de long-term strategy, no de short-term wins:

  • IC vs Management: Son paths igualmente válidos — elige con honestidad qué te mueve
  • Skills: coding + ml + systems + soft skills = ML engineer completo
  • System Design: Aprende porque en producción no hay Jupyter
  • Portfolio: 2-3 proyectos excelentes > 20 proyectos mediocres
  • Negotiation: Siempre negocia, siempre tiene alternative offer

En Colombia el mercado ML está creciendo: startups en Bogotá, fintechs en Medellín, remote roles hacia empresas de EE.UU. La oportunidad existe — pero solo para quienes se preparan con intención. No improvises tu career como si fuera un paseo por la Plazoleta del Zipa sin saber a dónde vas.
