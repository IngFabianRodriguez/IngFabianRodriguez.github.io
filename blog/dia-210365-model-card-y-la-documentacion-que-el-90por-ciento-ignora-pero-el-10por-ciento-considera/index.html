Model Card y la documentación que el 90% ignora pero el 10% considera

29 de jul de 2026
responsible-ai

Hola, parcero. Día 210 y hoy vamos con algo que me duele cuando veo en producción: modelos de ML deployados sin documentación, sin contexto de entrenamiento, sin información de limitaciones. El 90% de los equipos que veo en Bogotá despliegan modelos como si fueran funciones puras de Python — "funciona, ya está". El 10% que sí documenta se ahorra meses de problemas legales, técnicos y de reputación. Acompañame que esto es más importante de lo que suena.

📐 Fundamentos: Por qué la documentación de ML es diferente

La documentación de software tradicional describe qué hace el código. La documentación de modelos de ML describe decisiones: qué datos se usaron, qué sesgos se conocen, en qué condiciones el modelo falla, cómo se evaluó. Cada decisión de entrenamiento es una decisión ética, no solo técnica.

Elpaper seminal de Mitchell et al. (2019) introdujo las Model Cards como framework para documentar modelos de ML de forma estandarizada. La idea: una tarjeta que cualquier persona pueda leer para entender qué puede y qué no puede hacer el modelo, y bajo qué condiciones.

La matemática de transparencia: Ganancia de información vs. Riesgo

Hay una tensión fundamental en documentación de ML:

\text{Decisión de divulgación} = \arg\max_{d \in D} \underbrace{I(\text{doc}, \text{usuarios})}_{\text{ganancia de transparencia}} - \lambda \cdot \underbrace{R(\text{doc}, \text{adversarios})}_{\text{riesgo de misuse}}

Divulgar demasiado puede ayudar a actores adversarios. Divulgar muy poco impide uso responsable. La Model Card encuentra el balance apropiándose de la sección de limitacionesknown knowns — sesgos medidos, condiciones de validación, y fallos documentados.

💻 Implementación: Model Card Template Completo

Vamos a crear una Model Card completa y funcional. Usamos Python y la estructura de Mitchell et al. adaptada:

"""
Model Card Generator — Día 210
Template completo para documentar modelos de ML de forma responsable.
"""
from dataclasses import dataclass, field, asdict
from typing import List, Optional, Dict, Any
from datetime import datetime
import json

# ─────────────────────────────────────────────────────────────────────────────
# 1. Estructura de datos para la Model Card
# ─────────────────────────────────────────────────────────────────────────────

@dataclass
class ModelDetails:
    """Información básica del modelo."""
    model_name: str
    model_version: str
    model_type: str  # "text-generation", "classification", "embedding", etc.
    model_owner: str
    license: str
    release_date: str
    url: Optional[str] = None
    description: str = ""
   训练日期: Optional[str] = None

@dataclass
class TrainingData:
    """Datos usados para entrenar el modelo."""
    dataset_name: str
    dataset_url: Optional[str] = None
    dataset_size: str = ""  # "1.2M examples"
    dataset_description: str = ""
    data_source: List[str] = field(default_factory=list)
    data_preprocessing: str = ""
    known_limitations: str = ""
    
    # Para compliance con Datasheet (Gebru et al.)
    motivation: str = ""  # ¿Por qué se creó este dataset?
    composition: str = ""  # ¿Qué contiene?
    collection_process: str = ""
    preprocessing: str = ""
    uses: str = ""
    distribution: str = ""
    maintenance: str = ""

@dataclass
class EvaluationResults:
    """Resultados de evaluación, incluyendo métricas y benchmarks."""
    benchmark_name: str
    metric_name: str
    metric_value: float
    test_set_size: int = 0
    confidence_interval: Optional[str] = None
    slice_name: Optional[str] = None  # Ej: "female", "latino", "urban"
    notes: str = ""

@dataclass
class EthicalConsiderations:
    """Consideraciones éticas documentadas."""
    bias_known: List[str] = field(default_factory=list)
    bias_mitigation_strategies: List[str] = field(default_factory=list)
    sensitive_data_used: List[str] = field(default_factory=list)
    privacy_compliance: str = ""  # GDPR, CCPA, etc.
    adversarial_testing: str = ""
    human_oversight: str = ""

@dataclass
class Limitations:
    """Limitaciones conocidas del modelo."""
    capability_boundaries: List[str] = field(default_factory=list)
    known_fail_cases: List[str] = field(default_factory=list)
    out_of_distribution_behavior: str = ""
    safety_concerns: List[str] = field(default_factory=list)

@dataclass
class RecommendedUse:
    """Casos de uso recomendados y no recomendados."""
    primary_use: str = ""
    secondary_use: str = ""
    not_recommended_for: List[str] = field(default_factory=list)
    disclaimer: str = ""

@dataclass
class ValidationConditions:
    """Condiciones bajo las cuales el modelo fue validado."""
    validation_context: str = ""  # "¿En qué entorno se probó?"
    validation_demographics: str = ""  # "¿Qué grupos poblacionales?"
    validation_date: str = ""
    validation_performed_by: str = ""
    validation_conditions_notes: str = ""

@dataclass
class ModelCard:
    """Model Card completa."""
    model_details: ModelDetails
    training_data: TrainingData
    evaluation_results: List[EvaluationResults]
    ethical_considerations: EthicalConsiderations
    limitations: Limitations
    recommended_use: RecommendedUse
    validation_conditions: ValidationConditions
    
    def to_markdown(self) -> str:
        """Genera la Model Card en formato Markdown."""
        md = f"""# Model Card: {self.model_details.model_name}

## 1. Detalles del Modelo
- **Nombre**: {self.model_details.model_name}
- **Versión**: {self.model_details.model_version}
- **Tipo**: {self.model_details.model_type}
- **Owner**: {self.model_details.model_owner}
- **Licencia**: {self.model_details.license}
- **Fecha de release**: {self.model_details.release_date}
- **URL**: {self.model_details.url or "N/A"}
- **Descripción**: {self.model_details.description}

## 2. Datos de Entrenamiento
- **Dataset**: {self.training_data.dataset_name}
- **Tamaño**: {self.training_data.dataset_size}
- **Fuentes**: {", ".join(self.training_data.data_source)}
- **Preprocesamiento**: {self.training_data.data_preprocessing}
- **Limitaciones conocidas**: {self.training_data.known_limitations}

## 3. Resultados de Evaluación

| Benchmark | Métrica | Valor | IC (95%) | Slice |
|-----------|---------|-------|-----------|-------|
"""
        for r in self.evaluation_results:
            md += f"| {r.benchmark_name} | {r.metric_name} | {r.metric_value} | {r.confidence_interval or 'N/A'} | {r.slice_name or 'N/A'} |\n"

        md += f"""
## 4. Consideraciones Éticas
**Sesgos conocidos**:
"""
        for bias in self.ethical_considerations.bias_known:
            md += f"- {bias}\n"

        md += """
**Estrategias de mitigación**:
"""
        for strategy in self.ethical_considerations.bias_mitigation_strategies:
            md += f"- {strategy}\n"

        md += f"""
**Datos sensibles usados**: {", ".join(self.ethical_considerations.sensitive_data_used) or "Ninguno"}
**Compliance**: {self.ethical_considerations.privacy_compliance}

## 5. Limitaciones
**Capacidades conocidas**:
"""
        for cap in self.limitations.capability_boundaries:
            md += f"- {cap}\n"

        md += """
**Casos de fallo conocido**:
"""
        for fail in self.limitations.known_fail_cases:
            md += f"- {fail}\n"

        md += f"""
**Comportamiento OOD**: {self.limitations.out_of_distribution_behavior}

## 6. Uso Recomendado
- **Uso primario**: {self.recommended_use.primary_use}
- **Uso secundario**: {self.recommended_use.secondary_use}
- **No recomendado para**:
"""
        for nr in self.recommended_use.not_recommended_for:
            md += f"- {nr}\n"

        md += f"""
**Disclaimer**: {self.recommended_use.disclaimer}

## 7. Condiciones de Validación
- **Contexto**: {self.validation_conditions.validation_context}
- **Demográficos**: {self.validation_conditions.validation_demographics}
- **Fecha**: {self.validation_conditions.validation_date}
- **Validado por**: {self.validation_conditions.validation_performed_by}
- **Notas**: {self.validation_conditions.validation_conditions_notes}

---
*Generada automáticamente el {datetime.now().strftime('%Y-%m-%d')}*
"""
        return md

# ─────────────────────────────────────────────────────────────────────────────

def create_sentiment_model_card() -> ModelCard:

    details = ModelDetails(

        license="CC BY-NC 4.0",
        release_date="2026-06-15",

        description="Clasificador de sentimiento para texto en español. "

    )
    
    training = TrainingData(
        dataset_name="SentimentES-2024",
        dataset_url="https://huggingface.co/datasets/xyz/sentiment-es",
        dataset_size="850,000 ejemplos",
        dataset_description="Reviews de productos, tweets, y comentarios de redes sociales en español.",
        data_source=["Amazon Reviews ES", "Twitter/X API", "Google Play Reviews"],
        data_preprocessing="Lowercasing, eliminación de URLs y emails, "
                          "tokenización con sentencepiece",
        known_limitations="Subrepresentación de dialectos andinos y caribeños. "
                         "Sesgo hacia español neutro (méxico-español).",
    )
    
    evaluations = [
        EvaluationResults(
            benchmark_name="SentimentES-Test",
            metric_name="accuracy",
            metric_value=0.873,
            test_set_size=10000,
            confidence_interval="[0.865, 0.881]",
        ),
        EvaluationResults(
            benchmark_name="SentimentES-Test",
            metric_name="macro_f1",
            metric_value=0.851,
            test_set_size=10000,
            confidence_interval="[0.842, 0.860]",
        ),
        EvaluationResults(
            benchmark_name="SentimentES-Test",
            metric_name="accuracy",
            metric_value=0.823,

        ),

        model_details=details,

if __name__ == "__main__":
    card = create_sentiment_model_card()
    
    # Generar Markdown
    markdown = card.to_markdown()
    print(markdown)
    
    # Guardar como JSON para machine-readable
    card_dict = {
        "model_details": asdict(card.model_details),
        "training_data": asdict(card.training_data),
        "evaluation_results": [asdict(r) for r in card.evaluation_results],
        "ethical_considerations": asdict(card.ethical_considerations),
        "limitations": asdict(card.limitations),
        "recommended_use": asdict(card.recommended_use),
        "validation_conditions": asdict(card.validation_conditions),
    }
    
    with open("model_card_sentiment_es.json", "w") as f:
        json.dump(card_dict, f, indent=2, ensure_ascii=False)
    
    print("\n✅ Model Card guardada en model_card_sentiment_es.json")

🚨 Los 3 Errores Que Van a Causarte Problemas Legales y Técnicos

Error 1: No documentar biases conocidos — y después te demandan

El problema: Tu modelo de hiring screening tiene 15% menor accuracy para candidaturas afrodescendientes. No lo documentaste. La empresa lo deploya masivamente. Después un estudio académicolo detecta y lo publica. Crisis de PR, demanda colectiva, y tu nombre como "el ingeniero que construyó el sistema discriminatorio".

Por qué pasa: "No quería asumir que tenía sesgo", "los números se veían bien en el aggregate", "documentar sesgos = admitir culpa". Falsa lógica: documentar sesgos es precisamente lo que te protege legalmente porque demuestras awareness y mitigación.

La matemática: El riesgo esperado de no documentar vs. documentar:

\mathbb{E}[\text{riesgo}_{\text{no doc}}] = P(\text{detección}) \cdot (\text{costo legal} + \text{costo reputacional})
\mathbb{E}[\text{riesgo}_{\text{doc}}] = P(\text{detección}) \cdot \text{costo marginal} + C_{\text{documentación}}

Documentar típicamente reduce el factor legal por 3-5x porque demuestras good faith.

La solución: 항상 documenta los sesgos que encuentres, incluso los que no puedas mitigar completamente:

"""
Documentación obligatoria de sesgos — no es opcional.
"""
BIASES_DOCUMENTED = [
    {
        "bias_type": "demographic_disparity",
        "affected_group": "afrodescendientes",
        "metric": "accuracy",
        "gap": -0.15,  # 15% menor
        "p_value": 0.002,
        "mitigation": "Data augmentation + weighted sampling",
        "residual_risk": "Aún puede haber gaps residuales de ~5%",
        "monitoring_plan": "Monthly fairness audit",
        "approval": "Legal + Ethics board approved deployment 2026-07-01",
    },
]

Error 2: No especificar condiciones de validación — y el modelo falla en producción

El problema: Tu modelo de triage médico fue validado solo con datos de clínicas urbanas de Bogotá. Se deploya en zona rural del Chocó y那里的基础设施es muy diferente. El modelo empieza a dar diagnósticos incorrectos porque las condiciones de validación no reflejan el contexto real de uso.

Por qué pasa: Validar es caro y lento. "Si funciona en Bogotá, funciona en todas partes" — lógica que no resiste 5 minutos de pensamiento estadístico.

La matemática: El covariate shift entre validación y producción:

\Delta_{\text{covariate}} = \mathbb{E}_{x \sim P_{\text{validación}}}[\log \frac{P_{\text{producción}}(x)}{P_{\text{validación}}(x)}]

Si $\Delta_{\text{covariate}}$ es grande, tu modelo probablemente fallará.

La solución: Documenta las condiciones exactas de validación y exige que cualquier deployment fuera de esas condiciones sea re-validado:

"""
Validación: documentación obligatoria de TODAS las condiciones.
"""
VALIDATION_CONDITIONS = {
    "geographic_scope": ["Bogotá D.C.", "Medellín", "Cali"],
    "facility_types": ["Clínica nivel 3", "Hospital universitario"],
    "population_characteristics": {
        "age_range": "18-65",
        "socioeconomic": ["estrato 3", "estrato 4", "estrato 5"],
        "urban_rural": "100% urbano",
    },
    "hardware": ["GPU NVIDIA A100", "32GB RAM"],
    "deployment_context": "Clinical decision support (no autonomía)",
    
    "OUT_OF_SCOPE": [
        "Rural areas",
        "Population < 18 or > 65",
        "Emergency triage (validado solo para no-emergency)",
        "Facilities without proper hardware",
    ],
    
    "required_revalidation": [
        "New geographic region",
        "New facility type",
        "Age groups outside validation range",
    ],
}

Error 3: Model Card genérica sin detalles específicos — y nadie sabe cómo usarla

El problema: Tu Model Card dice "Este modelo tiene accuracy 87%". Eso es todo. Un equipo de producto quiere usarlo para klasificar reviews médicos. Otro quiere usarlo para analizar tweets de política. Ninguno sabe que el modelo no fue entrenado para esos casos y va a dar resultados malos con alta confianza.

Por qué pasa: La pereza. Llenar una Model Card detallada toma tiempo. "Ya tenemos el modelo, para qué tantas preguntas". Spoiler: para que no te culpen cuando alguien misuse el modelo.

La solución: Cada Model Card DEBE incluir:

"""
Checklist de Model Card mínima requerida.
Si falta algo de esto, NO se hace deploy.
"""
MINIMUM_MODEL_CARD_FIELDS = {
    # 1. Identificación
    "model_name": "str — único y versionado",
    "model_type": "str — específico, no 'AI'",
    
    # 2. Capacidades y limitaciones (NO genéricas)
    "what_it_does": "str — específico al dominio",
    "what_it_does_NOT_do": ["list — específico"],
    "known_fail_cases": ["list — con ejemplos si es posible"],
    
    # 3. Evaluación
    "benchmark_results": [{"benchmark": str, "metric": str, "value": float}],
    "evaluation_demographics": "str — quién fue evaluado",
    "evaluation_conditions": "str — cómo se evaluó",
    
    # 4. Datos
    "training_data_source": "str — específico",
    "training_data_limitations": "str — qué NO contiene",
    
    # 5. Ethical
    "known_biases": ["list — aunque no puedas mitigarlos todos"],
    "safety_concerns": ["list — aunque sean obvios"],
    "disclaimer": "str — uso inappropriate cubierto",
}

def validate_model_card(card: dict) -> list:
    """
    Valida que la model card tenga los campos mínimos.
    Retorna lista de campos faltantes.
    """
    missing = []
    for field, desc in MINIMUM_MODEL_CARD_FIELDS.items():
        if field not in card or not card[field]:
            missing.append(f"{field}: {desc}")
    return missing

✅ Resumen y Cierre

Parcero, lo que aprendimos hoy:

  • Model Cards son el estándar de facto para documentar modelos de ML — empezaron en Google y ahora son adoptadas por Hugging Face, major labs, y reguladores.
  • Una Model Card debe incluir: detalles del modelo, datos de entrenamiento, resultados de evaluación (con slices), consideraciones éticas (sesgos conocidos), limitaciones, uso recomendado, y condiciones de validación.
  • Documentar sesgos NO es admitir culpa — es precisamente lo que te protege legalmente porque demuestras awareness.
  • Las condiciones de validación son críticas: si deployas fuera de esas condiciones sin re-validar, estás asumiendo un riesgo que no has medido.
  • Una Model Card genérica ("accuracy 87%") es inútil. La especificidad es lo que hace la documentación valiosa.

La próxima vez que tu manager te diga "para qué tanto papeleo, el modelo funciona", explícale que la Model Card es tu registro de auditoría, tu protección legal, y tu forma de asegurar que el modelo se use responsablemente. En Bogotá decimos que "el que documenta, se protege".
