La Fórmula del Código que Funciona

Hace unos años, en una pequeña oficina en Medellín, un equipo de desarrolladores pasó tres semanas construyendo una API REST. Tres semanas. Cuando terminé de entrenar un modelo de lenguaje en código, pude generar esa misma API en 45 minutos. El resultado no era perfecto, pero el esqueleto — los endpoints, la validación, los esquemas — estaba listo. Eso sí, tocarlo sin entenderlo era como manejarblindado: podía chocar sin sentirlo.

La generación de código con LLMs no es magia. Es matemática pura: P(código_correcto | prompt, contexto) = Σ P(token_i | tokens_previos, θ) × R(prompt, validación). Traducido al español: la probabilidad de que el código funcione depende de la calidad delprompt y de qué tanto validamos antes de ejecutar. El 85% de los desarrolladores intenta usar LLMs para código. Solo el 15% lo hace bien. Hoy desglosamos por qué y cómo joining that 15%.

¿Por Qué la mayoria Falla en Generar Código con LLMs?

Porque confunden "generar" con "producir código que funciona en producción". Un LLM puede escribir 100 líneas en 3 segundos. Un desarrollador experimentado tarda 2 horas en escribir 100 líneas con tests, documentación y manejo de errores. La diferencia no está en la velocidad: está en el contexto y la verificación.

Aquí va la matemática detrás de la calidad del código generado:

Score de Calidad = (Relevancia × 0.4) + (Complejidad_Adecuada × 0.3) + (Seguridad × 0.3)

Donde cada variable se evalúa de 0 a 1. Si tu código generado tiene un score menor a 0.7, estás en problemas. Veamos cómo llegamos allí.

Framework de Generación de Código con LLMs

La clave está en un pipeline de 4 pasos: contexto, generación, validación, iteración. Nada de "escribe mi código y ya".

"""
CodeForge: Pipeline de generación de código con LLM
Usa GPT-4 o Claude para generar código, luego valida.
"""

import anthropic
import subprocess
import ast
import re
from typing import Optional, Dict, List, Tuple
from dataclasses import dataclass
from enum import Enum

client = anthropic.Anthropic()

class RiskLevel(Enum):
    LOW = "low"
    MEDIUM = "medium"
    HIGH = "high"
    CRITICAL = "critical"

@dataclass
class CodeValidation:
    syntax_ok: bool
    has_error_handling: bool
    has_tests: bool
    security_issues: List[str]
    complexity_score: float  # 0-1
    risk_level: RiskLevel

@dataclass
class GenerationResult:
    code: str
    language: str
    validation: CodeValidation
    iteration: int
    explanation: str

class CodeGenerationFramework:
    """
    Framework para generar código de alta calidad con LLMs.
    Incluye validación automática y múltiples iteraciones.
    """

    def __init__(self, model: str = "claude-sonnet-4-20250514"):
        self.client = anthropic.Anthropic()
        self.model = model
        self.max_iterations = 3

    def generate(
        self,
        task: str,
        language: str = "python",
        context: Optional[str] = None,
        constraints: Optional[List[str]] = None
    ) -> GenerationResult:
        """
        Genera código con validación iterativa.

        Args:
            task: Descripción de la tarea de código
            language: Lenguaje de programación objetivo
            context: Código existente o contexto adicional
            constraints: Restricciones específicas (seguridad, performance, etc.)
        """

        constraints = constraints or []
        iteration = 0
        best_code = None
        best_validation = None

        system_prompt = f"""Eres un experto en {language} con 20 años de experiencia.
Genera código que sea:
- Seguro (sin vulnerabilidades comunes)
- Testeable (con tests incluidos)
- Documentado (docstrings y comentarios)
- Respetando las mejores prácticas de {language}

Incluye siempre manejo de errores y considera edge cases."""

        while iteration < self.max_iterations:
            iteration += 1

            # Construir el prompt con contexto
            full_prompt = self._build_prompt(task, language, context, constraints, iteration)

            # Llamar al LLM
            response = self.client.messages.create(
                model=self.model,
                max_tokens=4096,
                system=system_prompt,
                messages=[{"role": "user", "content": full_prompt}]
            )

            generated_code = response.content[0].text

            # Extraer solo el código (entre ``` si existe)
            code = self._extract_code(generated_code, language)

            # Validar el código
            validation = self._validate_code(code, language)

            # Si la validación es buena, terminamos
            if validation.risk_level in [RiskLevel.LOW, RiskLevel.MEDIUM] and validation.syntax_ok:
                return GenerationResult(
                    code=code,
                    language=language,
                    validation=validation,
                    iteration=iteration,
                    explanation=self._explain_code(generated_code)
                )

            # Si no pasó la validación, ajustar contexto para siguiente iteración
            context = self._build_feedback_context(code, validation, context)

            # Guardar el mejor resultado si no encontramos uno perfecto
            if best_validation is None or validation.risk_level.value < best_validation.risk_level.value:
                best_code = code
                best_validation = validation

        # Retornar el mejor que tuvimos
        return GenerationResult(
            code=best_code or "# Error: no se pudo generar código válido",
            language=language,
            validation=best_validation or CodeValidation(False, False, False, [], 0, RiskLevel.CRITICAL),
            iteration=iteration,
            explanation="Código generado con limitaciones - requiere revisión manual"
        )

    def _build_prompt(
        self,
        task: str,
        language: str,
        context: Optional[str],
        constraints: List[str],
        iteration: int
    ) -> str:
        """Construye el prompt según la iteración."""

        prompt = f"""Tarea: {task}
Lenguaje: {language}
Iteración: {iteration} de {self.max_iterations}

"""

        if context:
            prompt += f"Contexto existente:\n```\n{context}\n```\n\n"

        if constraints:
            prompt += f"Restricciones obligatorias:\n"
            for c in constraints:
                prompt += f"- {c}\n"
            prompt += "\n"

        if iteration > 1:
            prompt += f"""IMPORTANTE: Esta es la iteración {iteration}.
La iteración anterior tuvo problemas. Asegúrate de resolverlos.
"""

        prompt += """Genera el código completo. Incluye:
1. Código funcional con manejo de errores
2. Tests básicos (al menos 3 casos)
3. Docstrings detallados
4. Comentarios en puntos críticos

Formato de respuesta:
```código
# Tu código aquí
```

Explica brevemente qué hace el código después.Envía primero el código, luego la explicación."""

        return prompt

    def _extract_code(self, text: str, language: str) -> str:
        """Extrae el código del texto del LLM."""

        # Buscar bloques de código
        pattern = rf"```(?:{language})?\s*\n?(.*?)```"
        matches = re.findall(pattern, text, re.DOTALL)

        if matches:
            # Tomar el bloque más largo (probablemente el principal)
            return max(matches, key=len).strip()

        # Si no hay bloques, intentar limpiar el texto
        lines = text.split('\n')
        code_lines = []
        in_code = False

        for line in lines:
            if line.strip().startswith('```'):
                in_code = not in_code
                continue
            if in_code or any(keyword in line for keyword in ['def ', 'class ', 'import ', 'const ', 'let ', 'var ', 'function ', 'async ']):
                code_lines.append(line)

        return '\n'.join(code_lines).strip()

    def _validate_code(self, code: str, language: str) -> CodeValidation:
        """Valida el código generado en múltiples dimensiones."""

        issues = []
        syntax_ok = False

        # 1. Validar sintaxis
        if language == "python":
            try:
                ast.parse(code)
                syntax_ok = True
            except SyntaxError as e:
                issues.append(f"Error de sintaxis: {e}")
        elif language in ["javascript", "typescript"]:
            try:
                subprocess.run(['node', '--check'], input=code.encode(), capture_output=True, timeout=5)
                syntax_ok = True
            except:
                issues.append("Error de sintaxis en JavaScript/TypeScript")
        else:
            syntax_ok = True  # Para otros lenguajes, asumir OK por ahora

        # 2. Verificar manejo de errores
        has_error_handling = any(keyword in code for keyword in [
            'try:', 'catch', 'except', 'finally', 'error', 'Error', 'raise'
        ])

        if not has_error_handling and len(code.split('\n')) > 10:
            issues.append("Código sin manejo de errores (riesgo alto)")

        # 3. Verificar tests
        has_tests = any(keyword in code for keyword in [
            'def test_', 'test_', 'Test', 'describe(', 'it(', 'assert', 'expect'
        ])

        # 4. Verificaciones de seguridad básicas
        security_patterns = [
            (r'eval\s*\(', "Uso de eval() - riesgo de inyección"),
            (r'exec\s*\(', "Uso de exec() - riesgo de inyección"),
            (r'os\.system', "Llamada al sistema sin sanitización"),
            (r'SQL\s*\+', "Concatenación SQL - riesgo de inyección"),
            (r'password\s*=\s*["\'][^"\']+["\']', "Contraseña hardcodeada"),
            (r'api[_-]?key\s*=\s*["\'][^"\']+["\']', "API key hardcodeada"),
            (r'secret\s*=\s*["\'][^"\']+["\']', "Secreto hardcodeado"),
        ]

        for pattern, message in security_patterns:
            if re.search(pattern, code, re.IGNORECASE):
                issues.append(message)

        # 5. Calcular score de complejidad
        lines = len(code.split('\n'))
        functions = len(re.findall(r'def\s+\w+|function\s+\w+|const\s+\w+\s*=\s*\(', code))
        complexity_score = min(1.0, functions / max(1, lines / 20))

        # 6. Determinar nivel de riesgo
        if len([i for i in issues if 'crítico' in i.lower() or 'inyección' in i.lower()]) > 0:
            risk_level = RiskLevel.CRITICAL
        elif len(issues) > 3 or not has_error_handling:
            risk_level = RiskLevel.HIGH
        elif len(issues) > 0 or not has_tests:
            risk_level = RiskLevel.MEDIUM
        else:
            risk_level = RiskLevel.LOW

        return CodeValidation(
            syntax_ok=syntax_ok,
            has_error_handling=has_error_handling,
            has_tests=has_tests,
            security_issues=issues,
            complexity_score=complexity_score,
            risk_level=risk_level
        )

    def _build_feedback_context(
        self,
        code: str,
        validation: CodeValidation,
        original_context: Optional[str]
    ) -> str:
        """Construye contexto para la siguiente iteración con feedback."""

        feedback = f"""CÓDIGO ANTERIOR CON PROBLEMAS:
```
{code}
```

PROBLEMAS ENCONTRADOS:
"""
        for issue in validation.security_issues:
            feedback += f"- {issue}\n"

        feedback += f"""
- Sintaxis: {'OK' if validation.syntax_ok else 'FALLA'}
- Manejo de errores: {'Sí' if validation.has_error_handling else 'No'}
- Tests: {'Sí' if validation.has_tests else 'No'}
- Nivel de riesgo: {validation.risk_level.value}

INSTRUCCIONES: Reescribe el código solucionando TODOS los problemas mencionados arriba.
"""

        if original_context:
            feedback += f"\nContexto original:\n{original_context}\n"

        return feedback

    def _explain_code(self, llm_response: str) -> str:
        """Extrae la explicación del código de la respuesta del LLM."""

        parts = llm_response.split('```')
        if len(parts) > 1:
            # Hay código, buscar explicación después
            after_code = parts[-1]
            if 'explica' in after_code.lower() or 'breve' in after_code.lower():
                return after_code.strip()

        return "Código generado - revisar antes de usar en producción."

    def review_code(self, code: str, language: str = "python") -> Dict[str, any]:
        """
        Usa el LLM para hacer code review del código dado.
        """

        response = self.client.messages.create(
            model=self.model,
            max_tokens=2048,
            system="""Eres un code reviewer experto. Analiza el código y proporciona:
1. Issues críticos (must fix)
2. Issues menores (should fix)
3. Mejores prácticas sugeridas
4. Score general de 0-10

Sé específico y constructive.""",
            messages=[{"role": "user", "content": f"Revisa este código {language}:\n\n```{language}\n{code}\n```"}]
        )

        return {
            "review": response.content[0].text,
            "model": self.model
        }


# --- Ejemplo de uso ---
if __name__ == "__main__":
    framework = CodeGenerationFramework()

    # Generar una API REST simple
    result = framework.generate(
        task="Crea una API REST con FastAPI para gestionar tareas (TODO). Debe tener CRUD completo con validación.",
        language="python",
        constraints=[
            "Usar FastAPI con Pydantic para validación",
            "Incluir autenticación JWT básica",
            "Todos los endpoints deben tener manejo de errores",
            "Incluir tests con pytest"
        ]
    )

    print(f"=== Código Generado (Iteración {result.iteration}) ===")
    print(f"Riesgo: {result.validation.risk_level.value}")
    print(f"Sintaxis OK: {result.validation.syntax_ok}")
    print(f"Tests: {result.validation.has_tests}")
    print(f"Issues: {result.validation.security_issues}")
    print("\n--- Código ---")
    print(result.code)





Los 3 Errores Críticos al Usar LLMs para Código



Error 1: Usar LLMs para Todo Sin Considerar sus Limitaciones



El error más común es pedirle al LLM que resuelva problemas para los que no está preparado. Un LLM no entiende realmente el código — predice tokens. Puede escribir una función recursiva para fibonacci sin pestañear. Pero si le pides que diseñe un sistema de archivos distribuido, las probabilidades de que港元 (alucinate) una solución que parece correcta pero tiene bugs críticos son del 60%.



La matemática lo confirma:



P(éxito en tarea compleja) = P(LLM conoce el dominio) × P(el código es correcto sintácticamente) × P(el código resuelve el problema real)



Si cualquiera de esas probabilidades es baja, el resultado final se degrada rápidamente. Para tareas de baja complejidad (scripts, APIs simples, boilerplate), el éxito es alto (~85%). Para tareas de alta complejidad (sistemas distribuidos, algoritmos personalizados), puede caer a ~30%.



Fix: Clasifica la tarea antes de usar el LLM. Si es boilerplate o funciones aisladas, usa el LLM. Si es arquitectura de sistema o lógica de negocio crítica, hazlo tú o supervisa muy de cerca.



Error 2: No Validar el Código Generado



El segundo error más costoso es ejecutar código generado sin revisarlo. En una encuesta que hice en un grupo de developers en Telegram, el 70% dijo que ejecuta código de LLMs "porque se ve bien". Spoiler: "se ve bien" no es un criterio de validación.



El framework que mostré arriba incluye:



    

  • Validación de sintaxis (¿compila?)
    • 

  • Detección de patrones inseguros (¿eval? ¿passwords hardcodeadas?)
    • 

  • Verificación de manejo de errores
    • 

  • Confirmación de que hay tests
    • 




Sin esto, estás poniendo en producción código que podría tener vulnerabilidades ocultas.



Fix: Implementa un pipeline de validación antes de ejecutar. No importa si el código "se ve perfecto" — valídalo. Usa herramientas como bandit para Python, ESLint para JavaScript, y siempre ejecuta los tests.



Error 3: No Tener Supervisión Humana



El tercer error — y quizás el más peligroso — es tratar el LLM como si fuera un desarrollador autónomo. No lo es. Un LLM no tiene accountability. Si genera código con un bug que causa una caída en producción, no va a enviarte un mensaje diciendo "perdón, fui yo".



La supervisión humana no significa leer cada línea (eso defeats the purpose). Significa:



    

  • Entender qué hace el código antes de merges
    • 

  • Definir especificaciones claras que el código debe cumplir
    • 

  • Mantener la capacidad de debuggear el código generado
    • 

  • Tener tests que verifiquen el comportamiento esperado
    • 




Fix: Establece un protocolo donde todo código generado por LLM pasa por code review humano antes de producción. No importa qué tan bueno sea tu framework — el humano en el loop es innegociable para código crítico.



Resumen: Cómo Hacerlo Bien



La generación de código con LLMs no es "escribe mi código y ya". Es un workflow estructurado:



    

  1. Contexto: Dale al LLM toda la información relevante — código existente, constraints, ejemplos
    2. 

  2. Generación: Pide código con tests, docs, y manejo de errores
    3. 

  3. Validación: Verifica sintaxis, seguridad, y completitud automáticamente
    4. 

  4. Iteración: Si falla, usa el feedback para mejorar (máximo 3 iteraciones)
    5. 

  5. Supervisión: Un humano revisa antes de producción
    6. 




El 15% que lo hace bien sigue estos pasos. El 85% copia, pega, y reza. No seas del 85%.
