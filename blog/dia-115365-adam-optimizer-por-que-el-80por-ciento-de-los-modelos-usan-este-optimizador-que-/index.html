26 de march de 2026
sklearn

Hola, parcero. Llegamos al Día 115 y hoy vamos con Adam. Este tema es criticalísimo en producción: el 80% de los modelos en producción usan Adam, pero la mayoría lo implementa con errores que cuestan puntos valiosos de accuracy. Yo mismo me quemé con esto en varios proyectos en Medellín. Vamos a dejarlo claro de una vez por todas.

📐 Adam: Adaptive Moment Estimation

Adam combina las ideas de RMSProp (media móvil exponencial del gradiente normalizado) con el momentum (media móvil exponencial de los gradientes). La fórmula central usa dos estimadores:

m_t = β₁ · m_{t-1} + (1 - β₁) · g_t (primer momento)
v_t = β₂ · v_{t-1} + (1 - β₂) · g_t² (segundo momento)

Pero aquí viene el detalle que casi nadie menciona: ambos estimadores comienzan en cero. En las primeras iteraciones esto causa que tanto m_t como v_t estén sesgados hacia cero. Por eso Adam aplica biased correction:

m̂_t = m_t / (1 - β₁^t)
v̂_t = v_t / (1 - β₂^t)

Con esto, el update finalmente es:

θ_t = θ_{t-1} - α · m̂_t / (√v̂_t + ε)

Los valores típicos: β₁ = 0.9, β₂ = 0.999, ε = 10⁻⁸.

En Colombia dicen "el que no conoce la mata, pasa por圣人". Pues aquí aplica: si no entiendes el biased correction, vas a tener problemas de convergencia en las primeras epochs y no sabrás por qué.

💻 Adam Desde Cero con Biased Correction

"""
Adam optimizer desde cero en PyTorch.
Demuestra el biased correction y la actualización real de parámetros.
"""
import torch
import torch.nn as nn
import matplotlib.pyplot as plt
from torch.utils.data import DataLoader, TensorDataset

# ─────────────────────────────────────────────
# 1. Adam nativo (sin torch.optim)
# ─────────────────────────────────────────────
class AdamNative:
    """Adam directo con biased correction explícito."""

    def __init__(self, params, lr=1e-3, beta1=0.9, beta2=0.999, eps=1e-8):
        self.params = list(params)
        self.lr = lr
        self.beta1 = beta1
        self.beta2 = beta2
        self.eps = eps
        self.t = 0  # timestep
        # Estados por parámetro
        self.m = {id(p): torch.zeros_like(p) for p in self.params}
        self.v = {id(p): torch.zeros_like(p) for p in self.params}

    def step(self):
        self.t += 1
        for p in self.params:
            if p.grad is None:
                continue
            g = p.grad.data
            pid = id(p)

            # biased correction
            self.m[pid] = self.beta1 * self.m[pid] + (1 - self.beta1) * g
            self.v[pid] = self.beta2 * self.v[pid] + (1 - self.beta2) * g * g

            m_hat = self.m[pid] / (1 - self.beta1 ** self.t)
            v_hat = self.v[pid] / (1 - self.beta2 ** self.t)

            p.data -= self.lr * m_hat / (torch.sqrt(v_hat) + self.eps)

    def zero_grad(self):
        for p in self.params:
            if p.grad is not None:
                p.grad.zero_()

# 3. Adam vs AdamW: weight decay correcto
# ─────────────────────────────────────────────
def adam_vs_adamw_demo():
    """
    AdamW = Adam + weight decay DECOUPLED (no es L2 regularización).
    En Adam, weight decay modifica el gradiente: g' = g + λθ
    En AdamW, se resta λθ DEL UPDATE directamente, sin afectar m̂/v̂.
    """
    torch.manual_seed(42)

    model = nn.Sequential(
        nn.Linear(10, 64),
        nn.ReLU(),
        nn.Linear(64, 1)
    )

    # Adam con weight decay (INCORRECTO si se quiere AdamW real)
    adam_with_l2 = torch.optim.Adam(
        model.parameters(), lr=1e-3, weight_decay=0.01
    )

    # AdamW (decoupled weight decay)
    adamw = torch.optim.AdamW(
        model.parameters(), lr=1e-3, weight_decay=0.01
    )

    # Verificar que el update es diferente
    x = torch.randn(4, 10)
    target = torch.randn(4, 1)

    for name, opt in [("Adam+L2", adam_with_l2), ("AdamW", adamw)]:
        model.zero_grad()
        loss = nn.MSELoss()(model(x), target)
        loss.backward()

        # Capturar update
        grads_before = {n: p.grad.clone() for n, p in model.named_parameters() if p.grad is not None}
        opt.step()

        print(f"{name}: loss={loss.item():.4f}")

    # La diferencia está en cómo se aplica el weight decay al update.
    # En Adam (weight_decay): el decay modifica el gradiente → afecta m̂/v̂
    # En AdamW: el decay se aplica en el paso final, independiente de m̂/v̂
    return adam_with_l2, adamw


# ─────────────────────────────────────────────
# 4. AMSGrad: la variante que corrige la convergencia
# ─────────────────────────────────────────────
class AMSGradNative:
    """AMSGrad: usa max(v̂_t) en lugar de v̂_t para garantizar convergencia en convex."""

    def __init__(self, params, lr=1e-3, beta1=0.9, beta2=0.999, eps=1e-8):
        self.params = list(params)
        self.lr = lr
        self.beta1 = beta1
        self.beta2 = beta2
        self.eps = eps
        self.t = 0
        self.m = {id(p): torch.zeros_like(p) for p in self.params}
        self.v = {id(p): torch.zeros_like(p) for p in self.params}
        self.v_hat_max = {id(p): torch.zeros_like(p) for p in self.params}

    def step(self):
        self.t += 1
        for p in self.params:
            if p.grad is None:
                continue
            g = p.grad.data
            pid = id(p)

            self.m[pid] = self.beta1 * self.m[pid] + (1 - self.beta1) * g
            self.v[pid] = self.beta2 * self.v[pid] + (1 - self.beta2) * g * g

            m_hat = self.m[pid] / (1 - self.beta1 ** self.t)
            v_hat = self.v[pid] / (1 - self.beta2 ** self.t)

            # CLAVE AMSGrad: usar el máximo histórico de v_hat
            self.v_hat_max[pid] = torch.maximum(self.v_hat_max[pid], v_hat)

            p.data -= self.lr * m_hat / (torch.sqrt(self.v_hat_max[pid]) + self.eps)

    def zero_grad(self):
        for p in self.params:
            if p.grad is not None:
                p.grad.zero_()


# ─────────────────────────────────────────────
# 5. Lion optimizer: la nueva alternativa (EvoLved Sign Momentum)
# ─────────────────────────────────────────────
class LionNative:
    """
    Lion optimizer: m = β1*m + (1-β1)*sign(g); θ = θ - lr*m
    Más simple que Adam (solo un momento), pero requiere lr más grande.
    Paper: "Symbolic Discovery of Optimization Algorithms" (Chen & Ritter, 2023)
    """

    def __init__(self, params, lr=1e-3, beta1=0.9, beta2=0.99):
        self.params = list(params)
        self.lr = lr
        self.beta1 = beta1
        self.beta2 = beta2
        self.m = {id(p): torch.zeros_like(p) for p in self.params}

    def step(self):
        for p in self.params:
            if p.grad is None:
                continue
            g = p.grad.data
            pid = id(p)

            self.m[pid] = self.beta1 * self.m[pid] + (1 - self.beta1) * g
            # Sign operation es el truco central de Lion
            p.data -= self.lr * torch.sign(self.m[pid])

    def zero_grad(self):
        for p in self.params:
            if p.grad is not None:
                p.grad.zero_()


def lion_comparison():
    """Compara Lion vs Adam en una tarea de clasificación."""
    torch.manual_seed(42)

    # Datos simples
    X = torch.randn(200, 20)
    y = (X @ torch.randn(20, 1) > 0).float()

    model = nn.Sequential(
        nn.Linear(20, 64),
        nn.ReLU(),
        nn.Linear(64, 1),
        nn.Sigmoid()
    )

    loss_fn = nn.BCELoss()

    results = {}
    for name, opt_fn, lr in [
        ("Adam", lambda p: torch.optim.Adam(p, lr=1e-3), 1e-3),
        ("Lion", lambda p: LionNative(p, lr=1e-3), 1e-3),
        ("Lion(lr=1e-2)", lambda p: LionNative(p, lr=1e-2), 1e-2),
    ]:
        torch.manual_seed(42)
        model = nn.Sequential(
            nn.Linear(20, 64), nn.ReLU(),
            nn.Linear(64, 1), nn.Sigmoid()
        )
        opt = opt_fn(model.parameters())
        losses = []
        for epoch in range(100):
            pred = model(X)
            loss = loss_fn(pred, y)
            opt.zero_grad()
            loss.backward()
            opt.step()
            losses.append(loss.item())
        results[name] = losses

    print("Lion vs Adam convergencia:")
    for name, losses in results.items():
        print(f"  {name}: final_loss={losses[-1]:.4f}")
    return results

🚨 Los 3 Errores Más Frecuentes con Adam

Error 1: Usar Adam en problemas convexos donde SGD converge mejor

Este es el error que más me ha costado en producción. En problemas estrictamente convexos (como regresión lineal con loss MSE), SGD con momentum converge a la solución óptima global, mientras que Adam puede quedarse atascado en mínimos locales por su adaptive learning rate.

# ❌ ERROR: Usar Adam en un problema convexo simple
model = nn.Linear(10, 1)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
# En convex: SGD general converge más rápido y de forma más estable.

# ✅ FIX: Para convexos, usa SGD
optimizer = torch.optim.SGD(model.parameters(), lr=0.01, momentum=0.9)
# O mejor aún: prueba ambos y compara.

Error 2: No separar weight decay de L2 regularization (debería ser AdamW)

En PyTorch, torch.optim.Adam(weight_decay=λ) aplica L2 regularization por defecto (modifica el gradiente). Pero esto interfiere con el adaptive learning rate porque afecta el cálculo de m̂ y v̂. La solución correcta es usar AdamW:

# ❌ ERROR: Adam con weight_decay aplica L2 que interactúa mal con adaptive lr
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=0.01)

# ✅ FIX: Usar AdamW — decoupled weight decay
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)
# El weight decay se aplica directamente al update, sin tocar m̂ ni v̂.

Error 3: Learning rate global demasiado alto que causa divergencia

Adam es sensible al learning rate. Un lr de 0.1 o mayor típicamente causa divergencia en redes profundas. Lo he visto pasar en modelos de NLP con transformers:

# ❌ ERROR: lr demasiado alto para Adam
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)  # muy alto

# ❌ ERROR: lr por defecto de algunos tutorials (1.0) es catastrophico
optimizer = torch.optim.Adam(model.parameters(), lr=1.0)

# ✅ FIX: lr típicos para Adam en deep learning
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)   # default seguro
optimizer = torch.optim.Adam(model.parameters(), lr=3e-4)   # para transformers
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)

# Si necesitas lr alto, usa AdamW con weight decay fuerte para compensar.

✅ Resumen y Cierre

Adam es el optimizador más usado por una razón: funciona bien en la mayoría de casos sin mucha tuneoría. Pero entender las matemáticas — biased correction, la diferencia entre Adam y AdamW, y cuándo AMSGrad o Lion son mejores alternativas — es lo que te separa de los que solo copian código de internet.

  • Usa Adam para redes profundas, transformers, y problemas no-convexos.
  • Usa AdamW cuando necesitas weight decay (casi siempre en deep learning).
  • Usa AMSGrad si tienes problemas de convergencia en convex settings.
  • Considera Lion para tareas de ML moderno (según papers recientes tiene mejor generalización en algunos casos).
  • Para convexos puros: SGD con momentum es tu mejor opción.

Eso sí, parcero: nunca copies un learning rate de un tutorial sin entender por qué funciona ahí. Cada modelo y dataset es un mundo. Afina con experiments, no con fe.
