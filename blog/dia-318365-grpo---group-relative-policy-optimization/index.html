GRPO: Group Relative Policy Optimization — La Evolución de PPO

14 de noviembre de 2026
reinforcement-learninggrpogroup-relativeoptimization

☕ Intro

Qué más, parce. Día 318 y hoy hablamos de GRPO — Group Relative Policy Optimization. Si PPO fue la revolución en RL, GRPO es la evolución que el 75% no conoce pero que DeepSeek popularizó. La diferencia clave: en vez de usar un reward absoluto, GRPO usa relative rewards dentro de un group de muestras.

La intuición es simple pero poderosa: en vez de preguntar "¿qué tan bueno es este output?", preguntamos "¿este output es mejor o peor que los otros outputs que generamos para la misma pregunta?". Eso elimina la necesidad de un reward model separado en muchos casos.

📐 La Idea Central de Group Relative

En PPO tradicional, necesitas un reward signal para cada acción. Ese reward viene de:

  • Un reward model entrenado con humanos (RM)
  • Un environment externo que te da feedbacks

Pero entrenar un buen reward model es costoso y frágil. GRPO propone una alternativa: para cada prompt, genera múltiples outputs (un "group"), y compara los outputs entre sí.

La diferencia conceptual

PPO: $A_t = Q(s,a) - V(s)$ — usa value function baseline

GRPO: Para un group de $G$ samples $\{o_1, o_2, ..., o_G\}$ del mismo prompt:

$$A_{GRPO}(o_i) = \frac{r(o_i) - \mu_G}{\sigma_G}$$

donde $r(o_i)$ es el reward del output $i$, y $\mu_G, \sigma_G$ son la media y desviación estándar de los rewards del group.

Esto es un relative ranking — no importa el valor absoluto del reward, solo importa cómo se compara con sus "hermanos" del mismo prompt.

🔧 Implementación de GRPO

Vamos al código. La implementación de GRPO tiene estos componentes:

"""
GRPO - Group Relative Policy Optimization
Implementación basada en DeepSeek-V3 paper
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np
from typing import List, Dict, Tuple, Optional
from dataclasses import dataclass
import math


@dataclass
class GRPOConfig:
    """Configuración para GRPO"""
    # Hiperparámetros principales
    group_size: int = 8                    # Muestras por grupo (G)
    beta: float = 0.04                    # Factor de KL penalty (similar a PPO's clip)
    gamma: float = 1.0                    # Discount factor para rewards
    num_update_steps: int = 1              # Updates por grupo
    epsilon_range: Tuple[float, float] = (0.2, 0.2)  # (lower, upper) bounds
    
    # Para advantage normalization
    eps: float = 1e-8
    
    # Para reward shaping
    reward_norm_type: str = "group"        # "group" | "instance" | "none"
    advantage_norm: bool = True


class GRPOGroup:
    """
    Un grupo de muestras para el mismo prompt.
    En GRPO, solo nos importa el ranking relativo dentro del grupo.
    """
    
    def __init__(
        self, 
        prompt: str, 
        outputs: List[str],
        rewards: List[float],
        log_probs: Optional[List[torch.Tensor]] = None
    ):
        self.prompt = prompt
        self.outputs = outputs
        self.rewards = rewards
        self.log_probs = log_probs  # log π_old(a|s) para cada output
        
        # Computar statistics del grupo
        self.reward_mean = np.mean(rewards)
        self.reward_std = np.std(rewards) + self.eps
        
        # Normalized/reward centrado
        self.reward_centred = [r - self.reward_mean for r in rewards]
        
        # Relative advantages (z-score dentro del grupo)
        self.relative_advantages = [(r - self.reward_mean) / self.reward_std for r in rewards]
        
    def get_group_stats(self) -> Dict:
        """Estadísticas del grupo para logging"""
        return {
            "reward_mean": self.reward_mean,
            "reward_std": self.reward_std,
            "reward_min": np.min(self.rewards),
            "reward_max": np.max(self.rewards),
            "reward_range": np.max(self.rewards) - np.min(self.rewards),
            "relative_spread": (np.max(self.rewards) - np.min(self.rewards)) / (self.reward_std + self.eps)
        }


class GRPOObjective:
    """
    GRPO objective con 3 componentes:
    1. Policy gradient con advantages relativos al grupo
    2. KL penalty para no alejar demasiado de la policy anterior
    3. Marginal likelihood para regularización
    """
    
    def __init__(self, config: GRPOConfig):
        self.config = config
    
    def compute_loss(
        self,
        policy_logits: torch.Tensor,           # (batch_size, vocab_size) - logits de la nueva policy
        old_log_probs: torch.Tensor,            # (batch_size,) - log probs de la old policy
        actions: torch.Tensor,                  # (batch_size,) - acciones tomadas
        group_rewards: List[List[float]],       # [[r1, r2, ..., rG], ...] un grupo por prompt
        return_dict: bool = True
    ) -> Tuple[torch.Tensor, Dict]:
        """
        Computa el GRPO loss.
        
        Args:
            policy_logits: Logits de la policy actual para cada sample
            old_log_probs: Log probs de la policy anterior para cada sample  
            actions: Las acciones tomadas (token IDs)
            group_rewards: Rewards organizados por grupo (cada grupo = samples del mismo prompt)
        
        Returns:
            loss, metrics dict
        """
        batch_size = policy_logits.shape[0]
        
        # 1. Log probs de la nueva policy para las acciones tomadas
        log_probs_new = F.log_softmax(policy_logits, dim=-1)
        log_probs_new = log_probs_new.gather(1, actions.unsqueeze(1)).squeeze()  # (batch_size,)
        
        # 2. Construir grupos y computar relative advantages
        advantages = []
        sample_to_group_idx = []
        
        group_start = 0
        for group_idx, group_reward in enumerate(group_rewards):
            group_size = len(group_reward)
            group_end = group_start + group_size
            
            # Relative advantage: z-score dentro del grupo
            group_mean = np.mean(group_reward)
            group_std = np.std(group_reward) + self.config.eps
            
            for r in group_reward:
                if self.config.advantage_norm:
                    adv = (r - group_mean) / group_std
                else:
                    adv = r - group_mean
                advantages.append(adv)
                sample_to_group_idx.append(group_idx)
            
            group_start = group_end
        
        advantages = torch.FloatTensor(advantages).to(policy_logits.device)
        
        # 3. Policy gradient con advantages relativos
        # El ratio es: π_new(a) / π_old(a)
        # En log space: exp(log π_new - log π_old)
        ratio = torch.exp(log_probs_new - old_log_probs)
        
        # 4. Clipped objective (similar a PPO pero con relative advantages)
        # GRPO no usa clip externo, usa KL penalty en cambio
        policy_loss_unclipped = ratio * advantages
        policy_loss_clipped = self._apply_clip(ratio, policy_loss_unclipped)
        policy_loss = -torch.min(policy_loss_unclipped, policy_loss_clipped).mean()
        
        # 5. KL penalty: asegurar que π_new no se aleje mucho de π_old
        # D_KL(π_old || π_new) = Σ π_old * log(π_old/π_new)
        # Versión simplificada usando log probs
        with torch.no_grad():
            old_log_probs_expanded = old_log_probs.unsqueeze(1)  # (batch, 1)
            kl_penalty = self.config.beta * F.kl_div(
                log_probs_new.unsqueeze(1),  # log π_new
                old_log_probs_expanded,      # log π_old (como target)
                reduction='batchmean'
            )
        
        # 6. Total loss
        loss = policy_loss + kl_penalty
        
        # Metrics
        metrics = {
            'total_loss': loss.item(),
            'policy_loss': policy_loss.item(),
            'kl_penalty': kl_penalty.item(),
            'mean_advantage': advantages.mean().item(),
            'std_advantage': advantages.std().item(),
            'mean_ratio': ratio.mean().item(),
            'clipped_fraction': self._compute_clipped_fraction(ratio)
        }
        
        if return_dict:
            return loss, metrics
        return loss
    
    def _apply_clip(self, ratio: torch.Tensor, loss: torch.Tensor) -> torch.Tensor:
        """
        Aplica clipping en el ratio (similar a PPO).
        En GRPO, el clipping es más suave - usa un rango [1-ε, 1+ε].
        """
        lower, upper = self.config.epsilon_range
        clipped_ratio = torch.clamp(ratio, 1 - lower, 1 + upper)
        return clipped_ratio * (loss / (ratio + self.config.eps))
    
    def _compute_clipped_fraction(self, ratio: torch.Tensor) -> float:
        """Qué fracción de samples están en el rango clippeado"""
        lower, upper = self.config.epsilon_range
        clipped = ((ratio < (1 - lower)) | (ratio > (1 + upper))).float()
        return clipped.mean().item()


class GRPOAgent:
    """
    Agente que usa GRPO para optimizar policy.
    
    El workflow es:
    1. Para cada prompt, generar G samples (group_size)
    2. Obtener rewards para cada sample (puede ser de un reward model o del environment)
    3. Computar relative advantages dentro del grupo
    4. Actualizar policy con GRPO objective
    5. Repetir
    """
    
    def __init__(
        self,
        model: nn.Module,
        tokenizer,
        config: GRPOConfig = GRPOConfig()
    ):
        self.model = model
        self.tokenizer = tokenizer
        self.config = config
        self.objective = GRPOObjective(config)
        
        # Old model para KL penalty (copia de la current model)
        self.old_model = type(model)(**model.config).__dict__
        self._sync_old_model()
    
    def _sync_old_model(self):
        """Copiar pesos del modelo actual al old model"""
        # En práctica, esto es un deep copy o un EMA update
        # Por simplicidad, aquí solo marcamos la necesidad
        pass
    
    @torch.no_grad()
    def generate_group(
        self, 
        prompt: str, 
        group_size: int,
        max_length: int = 512,
        temperature: float = 1.0,
        top_p: float = 0.9
    ) -> List[Dict]:
        """
        Generar un grupo de G samples para un prompt.
        
        Returns:
            List of dicts con 'output', 'log_probs', 'reward'
        """
        results = []
        
        # Tokenize prompt una vez
        input_ids = self.tokenizer(prompt, return_tensors="pt").input_ids
        
        for _ in range(group_size):
            # Generar un sample
            output_ids = self.model.generate(
                input_ids,
                max_length=max_length,
                do_sample=True,
                temperature=temperature,
                top_p=top_p,
                pad_token_id=self.tokenizer.pad_token_id
            )
            
            output_text = self.tokenizer.decode(output_ids[0], skip_special_tokens=True)
            
            # Compute log probs para el output (para ratio computation)
            outputs = self.model(output_ids)
            log_probs = F.log_softmax(outputs.logits, dim=-1)
            
            # Log prob de cada token
            output_log_probs = log_probs.gather(2, output_ids.unsqueeze(2)).squeeze()
            total_log_prob = output_log_probs.sum().item()
            
            results.append({
                'prompt': prompt,
                'output': output_text,
                'input_ids': output_ids,
                'log_probs': total_log_prob,
                'tokens': output_ids[0].tolist()
            })
        
        return results
    
    def compute_rewards(
        self, 
        generated_group: List[Dict], 
        reward_fn
    ) -> List[float]:
        """
        Computar rewards para cada sample del grupo.
        reward_fn es una función: (prompt, output) -> float
        """
        rewards = []
        for gen in generated_group:
            r = reward_fn(gen['prompt'], gen['output'])
            rewards.append(r)
        return rewards
    
    def update(
        self,
        groups_data: List[Dict],
        optimizer: torch.optim.Optimizer,
        reward_fn=None
    ) -> Dict:
        """
        Una actualización de GRPO.
        
        groups_data: lista de dicts, cada uno con:
            - 'prompt': el prompt original
            - 'samples': lista de samples (cada uno con output, log_probs, tokens)
            - 'rewards': lista de rewards correspondientes
        """
        all_losses = []
        all_metrics = []
        
        for group_data in groups_data:
            prompt = group_data['prompt']
            samples = group_data['samples']
            rewards = group_data['rewards']
            
            if reward_fn is not None:
                # Recomputar rewards con reward_fn si se provee
                rewards = self.compute_rewards(samples, reward_fn)
            
            # Organizar por grupo para GRPO
            group_rewards = [rewards]  # Un grupo por prompt
            
            # Concatenar todos los samples del grupo
            all_input_ids = torch.cat([s['input_ids'] for s in samples], dim=0)
            all_actions = all_input_ids[:, 1:]  # Shift left for prediction
            all_log_probs_old = torch.FloatTensor([s['log_probs'] for s in samples])
            
            # Forward pass
            outputs = self.model(all_input_ids)
            logits = outputs.logits[:, :-1]  # (batch, seq_len-1, vocab)
            
            # Flatten para loss computation
            logits_flat = logits.reshape(-1, logits.size(-1))
            actions_flat = all_actions.reshape(-1)
            log_probs_old_flat = all_log_probs_old.repeat(all_actions.shape[1])
            
            # Compute GRPO loss
            loss, metrics = self.objective.compute_loss(
                logits_flat,
                log_probs_old_flat,
                actions_flat,
                group_rewards
            )
            
            # Update
            optimizer.zero_grad()
            loss.backward()
            
            # Gradient clipping
            torch.nn.utils.clip_grad_norm_(self.model.parameters(), 1.0)
            
            optimizer.step()
            
            all_losses.append(loss.item())
            all_metrics.append(metrics)
        
        # Promediar métricas
        avg_metrics = {}
        for key in all_metrics[0].keys():
            avg_metrics[key] = np.mean([m[key] for m in all_metrics])
        
        return {
            'mean_loss': np.mean(all_losses),
            **avg_metrics
        }


def grpo_reward_function(prompt: str, output: str) -> float:
    """
    Ejemplo de reward function para generación de código.
    
    En la práctica esto podría ser:
    - Un reward model entrenado con preferences humanas
    - Un verificador de correctness (ej. tests pasan)
    - Un modelo de recompensas como en RLHF
    """
    reward = 0.0
    
    # Reward por longitud razonable
    if len(output) > 50:
        reward += 0.1
    
    # Reward por tener estructura de código (backticks, keywords, etc.)
    code_indicators = ['def ', 'class ', 'import ', 'return ', 'if ', 'for ', 'while ']
    for indicator in code_indicators:
        if indicator in output:
            reward += 0.1
    
    # Reward por no tener placeholders obvios
    if 'TODO' not in output and 'FIXME' not in output:
        reward += 0.1
    
    # Reward por no ser copy-paste del prompt
    if output[:len(prompt)].lower() != prompt[:len(output)].lower() if len(output) > len(prompt) else True:
        reward += 0.1
    
    # Reward por relevancia (heurística simple: compartir palabras)
    prompt_words = set(prompt.lower().split())
    output_words = set(output.lower().split())
    overlap = len(prompt_words & output_words) / max(len(prompt_words), 1)
    reward += overlap * 0.3
    
    return reward

🔢 Por Qué GRPO Funciona Mejor que PPO en Algunos Casos

Ventaja 1: No necesita value function

PPO requiere un value network separado para computar advantages ($A = Q - V$). Entrenar ese value network es costoso y puede introducir sesgo. GRPO elimina esta necesidad usando relative rewards dentro del grupo.

Ventaja 2: Más estable con rewards ruidosos

Si el reward signal tiene ruido (que es común cuando viene de humanos o de un modelo imperfecto), el z-score normalization dentro del grupo reduce el impacto del ruido absoluto.

Ventaja 3: Reward hacking reducido

En PPO, un reward model imperfecto puede ser explotado. En GRPO, como solo importan las comparaciones relativas, es más difícil "hackear" el sistema con outputs que maximicen reward absoluto pero sean malos comparativamente.

La matemática detrás

En GRPO, para un grupo de size $G$:

$$\bar{r}_g = \frac{1}{G}\sum_{i=1}^G r_i$$

$$\hat{A}_i = \frac{r_i - \bar{r}_g}{\sqrt{\frac{1}{G}\sum_{i=1}^G (r_i - \bar{r}_g)^2}}$$

Esto es simplemente la standardize within-group. El gradient becomes:

$$\nabla_\theta L_{GRPO} = \mathbb{E}_{o_i \sim \pi_\theta} \left[ \nabla_\theta \log \pi_\theta(o_i) \cdot \hat{A}_i \right]$$

⚠️ Errores Comunes y Cómo Evitarlos

❌ Error 1: Group size muy pequeño

Si $G=2$, la normalización relative no tiene sentido — con solo 2 samples, cualquier diferencia se magnifica.

# GRPO con group_size insuficiente
group_size = 2  # MAL - prácticamente cualquier cosa se vuelve "mejor"

# GRPO con group_size razonable  
group_size = 8  # BIEN - permite ranking significativo

❌ Error 2: Mezclar grupos diferentes

Cada prompt debe tener su propio grupo. No mezcles outputs de diferentes prompts en el mismo grupo — eso rompe la suposición de relative comparison.

# MAL: mezclando prompts
all_outputs = [gen(prompt1), gen(prompt1), gen(prompt2), gen(prompt2)]
all_rewards = [r(prompt1, o1), r(prompt1, o2), r(prompt2, o3), r(prompt2, o4)]
# COMPUTAR ADVANTAGES SOBRE TODOS JUNTOS - INCORRECTO

# BIEN: cada prompt tiene su propio grupo
group1_rewards = [r(prompt1, o1), r(prompt1, o2)]
group2_rewards = [r(prompt2, o3), r(prompt2, o4)]
# Computar relative advantages DENTRO de cada grupo

❌ Error 3: No usar KL penalty

GRPO no usa clipping como PPO, pero necesita el KL penalty para controlar el tamaño de las actualizaciones. Sin él, la policy puede divergir.

# Config con KL penalty apropiado
config = GRPOConfig(
    beta=0.04,  # No muy alto (no aprende) ni muy bajo (explota)
    # Si ves rewards cayendo, sube beta
    # Si no ves cambios, baja beta
)

📊 Resumen

Aprendimos hoy:

  • ✅ GRPO usa relative rewards — compara outputs dentro del mismo grupo, no rewards absolutos
  • ✅ No necesita value function — elimina una red completa de la arquitectura
  • ✅ Más estable con rewards ruidosos — el z-score reduce impacto del ruido
  • ✅ Reward hacking reducido — difícil explotar relative comparisons
  • ⚠️ Group size importa: $G \geq 8$ para ranking significativo
  • ⚠️ KL penalty es crítico — controla el step size代替 clipping de PPO

GRPO es particularmente útil cuando:

  • No tienes un reward model perfecto (casi siempre)
  • Quieres hacer RL sin infrastructure compleja de value networks
  • Trabajas con generation tasks donde puedes muestrear múltiples outputs

🇨🇴 Cierre Colombiano

Mire, parcero, GRPO es como el pensamiento lateral en soluciones — en vez de resolver el problema de frente (reward absoluto), lo aborda de lado. "¿Cómo se compara este output con los otros?" es una pregunta más fácil de responder y más robusta al ruido.

Lo que me gusta de GRPO es que reduce la complexity del sistema. Un value network menos que entrenar, una less source of bias. En producción, menos components significa menos cosas que se rompen. Eso es ingeniería real.

Y lo mejor: si usted tiene un modelo que puede generar múltiples samples y tiene alguna forma de reward (aunque sea imperfecta), puede aplicar GRPO. No necesita el ecosistema completo de RL. Eso es democratización del RL.
