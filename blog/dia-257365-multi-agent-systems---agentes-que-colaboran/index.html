Por Qué los Sistemas Multi-Agente

Hagale pues, parcero. Llegamos al Día 257 y hoy vamos a hablar de algo que el 75% ignora pero que está redefiniendo cómo construimos sistemas de IA complejos: Multi-Agent Systems. Cuando un solo agente no puede hacerlo todo, múltiples agentes especializados colaboran, negocian y resuelven problemas que ningún LLM individual podría abordar. Esto es lo que separa los sistemas de IA toy de los que de verdad funcionan en producción. Póngase cómodo.

Arquitectura Básica de Agentes Múltiples

Un sistema multi-agente no es solo múltiples LLMs llamados en secuencia. Es una arquitectura donde agentes especializados tienen roles definidos, pueden comunicarse entre sí, y trabajan hacia un objetivo común:

class Agent:
    def __init__(self, name, role, model):
        self.name = name
        self.role = role
        self.model = model
    
    def think(self, task, context=None):
        prompt = f"""
        Rol: {self.role}
        Tarea: {task}
        Contexto: {context or 'Sin contexto adicional'}
        """
        return self.model.generate(prompt)
    
    def communicate(self, message, recipient):
        return f"[{self.name} -> {recipient}]: {message}"

class MultiAgentSystem:
    def __init__(self):
        self.agents = {}
    
    def add_agent(self, agent):
        self.agents[agent.name] = agent
    
    def run(self, task, orchestrator='orchestrator'):
        # El orquestador divide y distribuye
        orch = self.agents[orchestrator]
        subtasks = orch.think(task)
        
        results = {}
        for subtask in subtasks:
            agent_name = subtask['agent']
            result = self.agents[agent_name].think(subtask['task'], subtask.get('context'))
            results[agent_name] = result
        
        # El orquestador sintetiza
        return orch.think(f"Sintetiza: {results}")

Patrones de Colaboración

Existen tres patrones principales para hacer que agentes colaboren:

1. Patrón de Orquestación

Un agente central (orquestador) coordina el trabajo de los demás. Decide qué agente hace qué y cuándo. Es simple pero el orquestador puede convertirse en bottleneck.

def orchestration_pattern(task, agents):
    orchestrator = agents['orchestrator']
    
    # Paso 1: Planificar
    plan = orchestrator.think(f"Planifica: {task}")
    
    # Paso 2: Asignar y ejecutar en paralelo
    futures = []
    for subtask in plan['subtasks']:
        agent = agents[subtask['assigned_agent']]
        futures.append(agent.think_async(subtask['task']))
    
    # Paso 3: Recolectar resultados
    results = [f.result() for f in futures]
    
    # Paso 4: Sintetizar
    return orchestrator.think(f"Sintetiza estos resultados: {results}")

2. Patrón de Debates

Múltiples agentes discuten y debaten una pregunta, cada uno aportando su perspectiva. El resultado emerge de la síntesis de viewpoints en conflicto.

def debate_pattern(question, agents, rounds=3):
    # Cada agente tiene立场 diferente
    positions = {name: None for name in agents}
    
    for round_num in range(rounds):
        for name, agent in agents.items():
            # El agente ve las posiciones de los demás
            other_positions = {k: v for k, v in positions.items() if k != name}
            agent_position = agent.think(
                f"Pregunta: {question}\n"
                f"Posiciones actuales: {other_positions}\n"
                f"Redefiende tu posición o modifícala según los argumentos."
            )
            positions[name] = agent_position
    
    # Síntesis final
    synthesizer = agents['synthesizer']
    return synthesizer.think(f"Sintetiza el debate: {positions}")

3. Patrón de Especialistas Cooperativos

Cada agente es un especialista en un dominio. Se pasan información y colaboran secuencialmente o en pipeline:

def specialist_coop_pattern(task, specialist_pipeline):
    context = task
    
    for specialist in specialist_pipeline:
        result = specialist.think(context)
        context = {
            'task': result['conclusion'],
            'evidence': result['evidence'],
            'history': context.get('history', []) + [result]
        }
    
    return context['task']

# Ejemplo de pipeline
researcher = Agent('researcher', 'Investiga y recopila información', research_llm)
analyst = Agent('analyst', 'Analiza datos y encuentra patrones', analysis_llm)
writer = Agent('writer', 'Redacta informe final', writing_llm)

result = specialist_coop_pattern(
    "Análisis de tendencias del mercado de café colombiano",
    [researcher, analyst, writer]
)

Comunicación Entre Agentes

La comunicación es el corazón de cualquier sistema multi-agente. Hay dos modelos principales:

  • Mensajes directos: Un agente envía un mensaje específico a otro agente
  • Pizarra compartida: Todos los agentes escriben y leen de un espacio común de conocimiento
  • Habilidades especiales: Herramientas que un agente puede invocar en otros agentes
# Ejemplo de comunicación por pizarra compartida
class SharedBlackboard:
    def __init__(self):
        self.data = {}
        self.lock = threading.Lock()
    
    def write(self, agent_name, key, value):
        with self.lock:
            if agent_name not in self.data:
                self.data[agent_name] = {}
            self.data[agent_name][key] = {
                'value': value,
                'timestamp': time.time()
            }
    
    def read_all(self, key):
        with self.lock:
            return {
                agent: info[key]['value']
                for agent, info in self.data.items()
                if key in info
            }
    
    def read_from(self, agent_name):
        with self.lock:
            return self.data.get(agent_name, {})

# Agente usando la pizarra
class BlackboardAgent(Agent):
    def __init__(self, name, role, model, blackboard):
        super().__init__(name, role, model)
        self.blackboard = blackboard
    
    def think(self, task):
        # Lee información relevante de otros agentes
        context = self.blackboard.read_all('insights')
        
        # Genera su propia contribución
        result = self.model.generate(f"Rol: {self.role}\nTarea: {task}\nContexto: {context}")
        
        # Escribe su resultado
        self.blackboard.write(self.name, 'insights', result)
        
        return result

Auto-Crítica y Mejora Colectiva

Uno de los beneficios más poderosos de los sistemas multi-agente es la capacidad de auto-critica. Un agente puede revisar el trabajo de otro:

def agentic_critique(original_agent, critic_agent, task):
    # Generar respuesta inicial
    initial_response = original_agent.think(task)
    
    # El crítico evalúa
    critique = critic_agent.think(
        f"Evalúa esta respuesta:\n{initial_response}\n\n"
        f"¿Hay errores? ¿Mejoras posibles? Sé específico."
    )
    
    # Si hay mejoras, iterar
    if critique['needs_revision']:
        improved = original_agent.think(
            f"Mejora tu respuesta anterior según esta crítica:\n{critique['issues']}"
        )
        return improved
    
    return initial_response

# Uso
writer = Agent('writer', 'Redactor técnico', gpt4)
reviewer = Agent('reviewer', 'Crítico técnico', gpt4)

final_doc = agentic_critique(writer, reviewer, "Explica blockchain a un niño de 10 años")

Framework: CrewAI

CrewAI es el framework más popular para construir sistemas multi-agente en Python:

from crewai import Agent, Task, Crew, Process

# Definir agentes
researcher = Agent(
    role="Investigador de Mercado",
    goal="Encontrar las últimas tendencias en IA generativa",
    backstory="Experto en investigación de tendencias tecnológicas con 15 años de experiencia"
)

analyst = Agent(
    role="Analista de Datos",
    goal="Analizar datos de mercado y extraer insights accionables",
    backstory="PhD en Data Science, especialista en análisis predictivo"
)

writer = Agent(
    role="Redactor de Reportes",
    goal="Crear reportes claros y actionable based en el análisis",
    backstory="Ex editor en MIT Technology Review, especialista en comunicación técnica"
)

# Definir tareas
research_task = Task(
    description="Investigar tendencias de IA generativa 2024-2025",
    agent=researcher
)

analysis_task = Task(
    description="Analizar datos de adopción y predicciones de mercado",
    agent=analyst,
    context=[research_task]  # Depende del resultado del researcher
)

write_task = Task(
    description="Escribir reporte ejecutivo de 5 páginas",
    agent=writer,
    context=[research_task, analysis_task]
)

# Crear crew con proceso hierarchical
crew = Crew(
    agents=[researcher, analyst, writer],
    tasks=[research_task, analysis_task, write_task],
    process=Process.hierarchical,  # Un managerOrchestrator coordina
    manager_agent=Agent(role="Manager", goal="Coordinar el workflow", backstory="...")
)

# Ejecutar
result = crew.kickoff()
print(result)

Herramienta: LangGraph para Multi-Agente

from langgraph.graph import StateGraph, END
from typing import TypedDict, List

class AgentState(TypedDict):
    messages: List[str]
    current_agent: str
    task: str
    results: dict

def create_multi_agent_graph():
    workflow = StateGraph(AgentState)
    
    # Nodos
    workflow.add_node("orchestrator", orchestrator_node)
    workflow.add_node("researcher", researcher_node)
    workflow.add_node("analyst", analyst_node)
    workflow.add_node("writer", writer_node)
    workflow.add_node("critic", critic_node)
    
    # Aristas condicionales
    workflow.add_edge("orchestrator", "researcher")
    workflow.add_edge("researcher", "analyst")
    workflow.add_edge("analyst", "writer")
    workflow.add_edge("writer", "critic")
    
    # Decisión: ¿Necesita revisión?
    workflow.add_conditional_edges(
        "critic",
        needs_revision,
        {
            "revise": "writer",  # Volver a escribir
            "done": END  # Terminar
        }
    )
    
    return workflow.compile()

# Ejecutar
graph = create_multi_agent_graph()
result = graph.invoke({
    "messages": ["Análisis de adopción de LLMs en empresas LATAM"],
    "current_agent": "orchestrator",
    "task": "Análisis completo",
    "results": {}
})

Casos de Uso en Producción

  • Código autonomous: Un agente escribe, otro revisa, otro testa. Iteran hasta que todo pasa.
  • Research agents: Múltiples agentes buscan en fuentes diferentes (web, papers, internal docs) y un sintetizador combina.
  • Customer support: Un agente clasifica, otro accede base de conocimiento, otro redacta respuesta.
  • Legal document review: Especialistas en diferentes áreas del derecho revisan secciones distintas.

Errores Comunes

Error 1: Demasiados Agentes sin Rol Claro

El problema: Pones 10 agentes y cada uno hace un poco de todo. No hay especialización real y el sistema es lento.

La solución: Máximo 3-5 agentes especializados. Cada uno debe tener un rol muy específico y diferenciable.

Error 2: Comunicación Caótica

El problema: Los agentes se mandan mensajes en loops infinitos o se contradicen sin resolución.

La solución: Define estructura de comunicación clara. Quién habla con quién, en qué orden, y cómo se resuelve conflicto.

Error 3: No Tener Crítica Externa

El problema: Los agentes validan su propio trabajo. Los errores se propagan sin corrección.

La solución: Siempre incluir un agente crítico o revisor independiente que no esté involucrado en la generación.
