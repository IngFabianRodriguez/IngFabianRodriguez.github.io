Multimodal Learning — Fusionar Visión, Texto y Audio En Un Solo Modelo

26 de julio de 2026
multimodalclipflamingoblip-2

Hagale pues, parcero. Aquí en Bogotá un café es sagrado, y así como combinamos sabores en una aguapanela con queso, la inteligencia artificial está aprendiendo a mezclar imágenes, texto y sonido en un solo modelo. Eso es Multimodal Learning, y hoy lo destripamos.

🎯 Qué Es Multimodal Learning?

Los humanos percibimos el mundo por múltiples canales: vista, oído, tacto. Un modelo multimodal hace lo mismo — aprende representaciones jointas de diferentes modalidades (modalidades) y puede razonar entre ellas.

La clave está en proyectar todo a un espacio vectorial compartido. Así, una imagen de un gato y la palabra "gato" terminan siendo vectores cercanos en ese espacio.

Arquitectura General

Dado un modelo con encoder separado por modalidad:

# Proyectar cada modalidad al espacio compartido
image_embedding = image_encoder(image)      # E_img
text_embedding  = text_encoder(text)         # E_txt
audio_embedding = audio_encoder(audio)      # E_audio

# Todos viven en R^d (ej: d=768 para CLIP)
# Similitud se mide con coseno:
# similarity(i, t) = cos(E_img[i], E_txt[t])

La función de pérdida de contraste (contrastive loss) empuja pares positivos juntos y negativos aparte:

$$\mathcal{L} = -\log \frac{\exp(\text{sim}(i, t^+) / \tau)}{\sum_{j=0}^{N} \exp(\text{sim}(i, t_j) / \tau)}$$

Donde $\tau$ es la temperatura que controla qué tan peaked es la distribución.

📐 Modelos Multimodales Famosos

CLIP (OpenAI)

Entrenado con 400M de pares imagen-texto de internet. Aprende a predecir qué texto corresponde a qué imagen. Usa:

from PIL import Image
import torch
from transformers import CLIPProcessor, CLIPModel

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

image = Image.open("gato.jpg")
text = ["a cat", "a dog", "a car"]

inputs = processor(text=text, images=image, return_tensors="pt", padding=True)
outputs = model(**inputs)
logits_per_image = outputs.logits_per_image  # shape: [1, 3]

probs = logits_per_image.softmax(dim=1)
print(f"Probabilidades: {probs}")  # P(text|image)

Flamingo (DeepMind)

Modelo de lenguaje multimodal que ingiere interleaved image-text sequences. Usa un Perceiver Resampler para comprimir muchos frames visuales a pocos tokens antes del LM:

# Flamingo recibe secuencias como:
# [texto] <image> [texto] <image> [texto]
# El Perceiver extrae features visuales y el LM genera texto

BLIP-2 (Salesforce)

Usa un Querying Transformer (Q-Former) entre el encoder visual y el LLM. Aprende a extraer features relevantes para el LLM sin entrenar el visual encoder:

from transformers import Blip2Processor, Blip2ForConditionalGeneration

processor = Blip2Processor.from_pretrained("Salesforce/blip2-opt-2.7b")
model = Blip2ForConditionalGeneration.from_pretrained("Salesforce/blip2-opt-2.7b")

# Imagen + texto opcional → respuesta
inputs = processor(images=image, text="Describe esta imagen", return_tensors="pt")
out = model.generate(**inputs)
print(processor.decode(out[0], skip_special_tokens=True))

📊 Comparación de Arquitecturas

# CLIP: Alignment puro imagen-texto
# Architecture: ViT + Transformer Text, contrastive training
# Uso: zero-shot image classification, image search

# Flamingo: LLM multimodal con few-shot
# Architecture: Visual encoder + Perceiver + LLM (MPT, Chinchilla)
# Uso: razón multimodal abierta, few-shot learning

# BLIP-2: Bridge visual-LLM eficiente
# Architecture: ViT + Q-Former + frozen LLM (OPT, FlanT5)
# Uso: VQA, image captioning, visual dialogue

🚀 Construyendo Un Pipeline Multimodal

import torch
from transformers import CLIPProcessor, CLIPModel
import numpy as np

class MultimodalPipeline:
    def __init__(self, model_name="openai/clip-vit-base-patch32"):
        self.model = CLIPModel.from_pretrained(model_name)
        self.processor = CLIPProcessor.from_pretrained(model_name)
        self.device = "cuda" if torch.cuda.is_available() else "cpu"
        self.model.to(self.device)

    def encode_image(self, image):
        inputs = self.processor(images=image, return_tensors="pt").to(self.device)
        return self.model.get_image_features(**inputs)

    def encode_text(self, text):
        inputs = self.processor(text=[text], return_tensors="pt", padding=True).to(self.device)
        return self.model.get_text_features(**inputs)

    def compute_similarity(self, image, text):
        img_emb = self.encode_image(image)
        txt_emb = self.encode_text(text)
        # Normalizar
        img_emb = img_emb / img_emb.norm(dim=-1, keepdim=True)
        txt_emb = txt_emb / txt_emb.norm(dim=-1, keepdim=True)
        return (img_emb @ txt_emb.T).item()

    def find_best_match(self, image, candidates):
        img_emb = self.encode_image(image)
        txt_embs = self.encode_text(candidates)
        # Normalizar
        img_emb = img_emb / img_emb.norm(dim=-1, keepdim=True)
        txt_embs = txt_embs / txt_embs.norm(dim=-1, keepdim=True)
        scores = (img_emb @ txt_embs.T).squeeze()
        best_idx = scores.argmax().item()
        return candidates[best_idx], scores[best_idx].item()

# Uso
pipe = MultimodalPipeline()
best, score = pipe.find_best_match(
    image=Image.open("foto.jpg"),
    candidates=["una playa", "una montaña", "un estadio de fútbol"]
)
print(f"Mejor match: {best} (score: {score:.3f})")

⚠️ Errores Comunes y Cómo Evitarlos

Error 1: No Alinear Embeddings de Diferentes Modalidades

El problema: Proyectar cada modalidad a su propio espacio sin alinear produce vectores que no son comparables cross-modalidad.

La solución: Usa un proyector compartido y entrena con contrastive loss sobre pares positivos de diferentes modalidades. Asegúrate de normalizar los embeddings antes de compararlos:

# MAL: comparar sin normalizar
score = img_emb @ txt_emb.T  # Escala variable

# BIEN: normalizar primero
img_emb = img_emb / img_emb.norm(dim=-1, keepdim=True)
txt_emb = txt_emb / txt_emb.norm(dim=-1, keepdim=True)
score = img_emb @ txt_emb.T  # Ahora es coseno, rango [-1, 1]

Error 2: Fine-Tuning Multimodal Sin Suficiente Data de Cada Modalidad

El problema: Hacer fine-tuning con muy pocos ejemplos por modalidad causa modality imbalance — el modelo empieza a ignorar la modalidad con menos data.

La solución: Usa balanced sampling o-weighted losses. Si tu dataset tiene 10K imágenes pero solo 1K textos, muestrea ambos por igual:

from torch.utils.data import WeightedRandomSampler

# Ponderar para balancear modalidades
weights = []
for sample in dataset:
    if sample["modality"] == "image":
        weights.append(1.0)
    else:  # text, audio
        weights.append(10.0)  # Más peso a modalidad con menos samples

sampler = WeightedRandomSampler(weights, len(weights))
dataloader = DataLoader(dataset, sampler=sampler)

Error 3: No Usar Modelos Pre-entrenados Específicos Para Tu Combinación de Modalidades

El problema: Usar un modelo entrenado solo con imagen-texto (como CLIP) para tareas que también requieren audio produce malas results porque audio no fue visto durante entrenamiento.

La solución: Usa modelos diseñados para tu combinación exacta:

# COMBINACIÓN INCORRECTA:
# CLIP no sabe nada de audio
model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
# → para imagen+texto+solo → busca AudioCLIP, LAION-HEAVY, etc.

# COMBINACIÓN CORRECTA para imagen+texto:
from transformers import CLIPModel

# Para imagen+texto+audio → usa modelos como:
# - ImageBind (Meta): unifica imagen, texto, audio, depth, IMU
# - ULIP: imagen, texto, audio (3D point clouds)
# - MetaCLIP: variants con más datos

# Ejemplo con sentence-transformers multmodal:
from sentence_transformers import SentenceTransformer
model = SentenceTransformer('clip-ViT-B-32-multilingual')
# Soporta 50+ idiomas para texto, e imágenes

📝 Resumen y Cierre

Aprendimos que Multimodal Learning proyecta diferentes modalidades a un espacio compartido donde pueden compararse. CLIP pioneer el contraste imagen-texto a escala, Flamingo añade capacidades few-shot con LMs, y BLIP-2 usa Q-Former para bridge eficiente visual-to-LLM. El error más grave es no normalizar embeddings o usar modelos no diseñados para tu combinación de modalities.

En Colombia decimos que "cada machete tiene su machetillo" — cada combinación de modalidades necesita su modelo específico. No intentes usar CLIP para audio, y si necesitas español, asegurate de usar variantes multilingües como CLIP multilingual.
