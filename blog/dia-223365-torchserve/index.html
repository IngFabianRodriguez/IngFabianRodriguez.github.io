Introduccion

Hagale pues, parcero. Hoy es el Dia 223 y vamos a hablar de algo que el 90% de los desarrolladores de ML ignora: como proteger la privacidad de los datos cuando entrenamos modelos. En Colombia, donde la Ley 1581 de 2012 regula el tratamiento de datos personales, esto no es opcional — es obligatorio. Cafe en mano, veamos.

Por Que Proteger Privacidad en ML?

Cada vez que entrenamos un modelo con datos de usuarios, estamos potencialmente exponiendo informacion sensible. Los modelos pueden:

  • Memorizar datos de entrenamiento: Un estudio de 2019 mostro que GPT-2 podia regurgitar texto de entrenamiento verbatim.
  • Ffiltrar informacion de personas: En 2023, investigadores de Apple demostraron como modelos de salud podrian revelar diagnosticos.
  • Ser vulnerable a ataques de inferencia: Queries especificas pueden revelar si un individuo esta o no en el dataset.

La regulacion global exige proteccion real:

  • GDPR (Union Europea): Articulo 89 — garantias apropiadas para procesamiento de datos para investigacion.
  • CCPA (California): Derecho aopt-out y eliminacion de datos personales.
  • Ley 1581 (Colombia): Autorizacion previa, finalidad del tratamiento, y derechos del titular.

Differential Privacy — La Matematica de la Privacidad

Differential privacy (DP) es el gold standard para proteger privacidad en ML. La idea central es simple pero poderosa:

Un algoritmo es diferencialmente privado si la probabilidad de cualquier output es aproximadamente la misma, independentementede si un individuo especifico esta o no en el dataset de entrada.

La definicion formal:

Un mecanismo $\mathcal{M}$ es $(\epsilon, \delta)$-differentially private si para todo parejobs de datasets $D, D'$ que difieren en exactamente un elemento, y para todo conjuntos de outputs $S$:

$$P[\mathcal{M}(D) \in S] \leq e^\epsilon \cdot P[\mathcal{M}(D') \in S] + \delta$$

Donde:

  • $\epsilon$ es el privacy budget oparamtro de privacidad (epsilon > 0, mientras mas pequeno, mayor proteccion)
  • $\delta$ es la probability of failure (generalmente muy pequena, ej. $10^{-5}$)

Intuicion:

Piensa en una encuesta sensible. Si le preguntas a alguien si voto por Petro o por Hernandez, la respuesta puede depender de si su vecino voto o no. Con DP, anadimos ruido estadistico de manera que la presencia o ausencia de cualquier individuo no cambie significativamente el resultado final.

Implementando Differential Privacy con Opacus

Opacus es la libreria de Meta para entrenamiento de modelos con DP en PyTorch. Vamos a ver como implementarlo:

import torch
import torch.nn as nn
from opacus import PrivacyEngine
from opacus.validators import ModuleValidator

# Definir el modelo
class SimpleNN(nn.Module):
    def __init__(self, input_dim=784, hidden_dim=256, num_classes=10):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Dropout(0.5),
            nn.Linear(hidden_dim, num_classes)
        )
    
    def forward(self, x):
        return self.net(x.view(x.size(0), -1))

K-Anonymity — Una Tecnica Clasica Pero Efectiva

K-anonymity es una tecnica mas simple donde cada registro en el dataset es indistinguible de al menos $k-1$ otros registros respecto a quasi-identifiers.

Definicion formal:

Un dataset $T$ satisface $k$-anonymity si cada conjunto de valores de quasi-identifiers aparece al menos $k$ veces.

Implementacion:

import pandas as pd
import numpy as np

def k_anonymize(df, quasi_identifiers, k=5):
    """
    Implementacion de k-anonymity via generalizacion y supresion.
    
    Args:
        df: DataFrame con datos sensibles
        quasi_identifiers: columnas que identifican indirectamente (edad, genero, etc.)
        k: umbral de k-anonymity
    """
    df_anonymized = df.copy()
    
    # 1. Supresion: eliminar filas que no pueden ser anonimizadas
    # Contar frecuencia de cada combinacion de quasi-identifiers
    group_sizes = df_anonymized.groupby(quasi_identifiers).size()
    rows_to_keep = group_sizes[group_sizes >= k].index
    
    df_anonymized = df_anonymized[
        df_anonymized.set_index(quasi_identifiers).index.isin(rows_to_keep)
    ]
    
    # 2. Generalizacion: reemplazar valores especificos por rangos
    def generalize_age(age):
        if age < 18: return "0-17"
        elif age < 30: return "18-29"
        elif age < 45: return "30-44"
        elif age < 60: return "45-59"
        else: return "60+"
    
    if 'age' in quasi_identifiers:
        df_anonymized['age'] = df_anonymized['age'].apply(generalize_age)
    
    # 3. Aggregation: agrupar datos sensibles
    if 'salary' in df_anonymized.columns:
        salary_agg = df_anonymized.groupby(quasi_identifiers)['salary'].agg(['mean', 'median', 'count'])
        # Reemplazar salario individual con estadisticos de grupo
        df_anonymized = df_anonymized.drop('salary', axis=1).join(
            salary_agg, on=quasi_identifiers
        ).rename(columns={'mean': 'salary_estimated'})
    
    return df_anonymized.reset_index(drop=True)

# Ejemplo de uso
data = pd.DataFrame({
    'age': [25, 30, 35, 40, 45, 50, 28, 32, 38, 42],
    'gender': ['M', 'F', 'M', 'F', 'M', 'F', 'M', 'F', 'M', 'F'],
    'zip_code': ['11001', '11001', '11002', '11002', '11003', '11003', '11001', '11002', '11003', '11001'],
    'salary': [2500000, 3500000, 4000000, 4500000, 5000000, 5500000, 2800000, 3800000, 4200000, 4800000],
    'diagnosis': ['flu', 'cancer', 'diabetes', 'hypertension', 'cancer', 'diabetes', 'flu', 'cancer', 'hypertension', 'diabetes']
})

anonymized = k_anonymize(data, quasi_identifiers=['age', 'gender', 'zip_code'], k=2)
print(anonymized)

Errores Graves que el 90% Comete

Error 1: Pensar que "Anonimizado" Significa Realmente Anonymous

El problema: Muchas empresas creen que si quitan el nombre y cedula, los datos son seguros. Error. En 2006, Netflix publibaco un dataset "anonimizado" para una competencia. Investigadores de UT Austin pudieron re-identificar usuarios combinando con reseñas de IMDB. Peor aun: en 2013, investigadores re-identificaron a 87% de los participantes de un estudio medico "anonimizado" usando solo fecha de nacimiento, genero, y codigo postal.

La realidad matematica: Con solo 3 quasi-identifiers (edad, genero, codigo postal), la mayoria de personas en USA son unicas. La unica forma real de proteccion es usar differential privacy o k-anonymity con $k$ suficientemente grande y auditando la capacidad de re-identificacion.

El fix:

  • Implementar $k$-anonymity con $k \geq 10$ para quasi-identifiers
  • Usar differential privacy con $\epsilon \leq 1$ para datos agregados
  • Hacer audits de re-identificacion antes de compartir cualquier dataset
  • Nunca confiar en "solo quito el nombre" como tecnica de privacidad

Error 2: Usar Differential Privacy Sin Calcular Epsilon Apropiadamente

El problema: Muchos desarrolladores copian codigo de internet con $\epsilon=10$ o valores arbitrarios. Esto es peligroso porque:

  • $\epsilon$ pequeno (ej. 0.1): Alta privacidad, baja utilidad
  • $\epsilon$ grande (ej. 10): Baja privacidad, alta utilidad
  • Sin calculo apropiado, no sabes que nivel de privacidad tienes realmente

El fix: Calcular epsilon usando la composicion de mecanismos. Para $T$ epochs de entrenamiento con noise multiplier $\sigma$:

# Formula aproximada para RDP (Renyi Differential Privacy)
# Usando la composicion de momentos accountants

def compute_epsilon(noise_multiplier, sample_rate, epochs, delta=1e-5, alpha=2.0):
    """
    Aproximacion de epsilon para SGD con clipping.
    
    noise_multiplier: ratio entre std del ruido y max_grad_norm
    sample_rate: fraccion de datos por batch
    epochs: numero de pasadas sobre datos
    delta: probabilidad de falla
    """
    # Para mecanismo Gaussian con clipping
    # RDP order alpha, sensitivity = max_grad_norm
    c = noise_multiplier
    r = sample_rate
    
    # Funcion generadora de momentos para Gaussian
    def moment_generate(order, c):
        return 0.5 * order * c**2
    
    # Composicion de momentos
    total_moments = epochs * r * moment_generate(alpha, c)
    
    # Convertir a (epsilon, delta)
    epsilon = (total_moments + np.log(1/delta)) / (alpha - 1)
    return epsilon

# Ejemplo: 100 epochs, batch_size=256, dataset=60000, noise=1.1
epsilon = compute_epsilon(
    noise_multiplier=1.1,
    sample_rate=256/60000,
    epochs=100,
    delta=1e-5
)
print(f"EPSILON TOTAL: {epsilon:.2f}")

Error 3: No Tener un Data Governance Framework

El problema: Sin un framework de gobernanza, la proteccion de datos es inconsistente y no auditable. Cada equipo decide por su cuenta que es "privado" y que no.

El fix: Implementar un framework de gobernanza con:

"""
Data Governance Framework para ML

1. INVENTARIO DE DATOS
   - Que datos recolectamos?
   - Cual es su clasificacion de sensibilidad?
   - Quienes tienen acceso?

2. CONSENTIMIENTO
   - Tenemos autorizacion explícita para cada uso?
   - El consentimiento es granular (diferentes usos = diferentes permisos)?
   - Hay mecanismo de opt-out efectivo?

3. MINIMIZACION
   - Recolectamos SOLO lo necesario?
   - Podemos lograr el objetivo con datos menos sensibles?
   - Estamos borrando datos que ya no necesitamos?

4. CONTROL DE ACCESO
   - Principio de menor privilegio
   - Audit logs de quien accede a que
   - Autenticacion multifactor para datos sensibles

5. RETENCION
   - Politica de retencion definida
   - Eliminacion segura cuando expira
   -Backups: como se manejan?

6. RESPUESTA A INCIDENTES
   - Que hacemos si hay una brecha?
   - Notificacion a afectados segun regulacion aplicable
   - Plan de contencion y remediacin
"""

class DataGovernancePolicy:
    def __init__(self):
        self.min_privacy_budget = 1.0  # epsilon minimo para publicaciones
        self.max_k_anonymity = 5       # k minimo para anonimizacion
        self.data_retention_days = 90  # Retention policy
        self.audit_enabled = True
        self.require_consent = True
    
    def check_privacy_requirements(self, dataset, model_output):
        """Valida que un pipeline de ML cumpla con la politica."""
        issues = []
        
        # Check 1: K-anonymity
        if self.check_k_anonymity(dataset) < self.max_k_anonymity:
            issues.append(f"K-anonymity bajo: {self.max_k_anonymity}")
        
        # Check 2: Consentimiento
        if self.require_consent and not dataset.has_consent:
            issues.append("Dataset sin consentimiento documentado")
        
        # Check 3: Retention
        if dataset.age_days > self.data_retention_days:
            issues.append(f"Datos exceden retention policy: {dataset.age_days} dias")
        
        return issues
    
    def check_k_anonymity(self, dataset, quasi_ids):
        import pandas as pd
        groups = dataset.groupby(quasi_ids).size()
        return groups.min() if len(groups) > 0 else 0

Resumen y Cierre Colombiano

Hoy cubrimos las tecnicas fundamentales para proteger privacidad en ML:

  • Differential Privacy: El gold standard matematico. Opacus hace que implementar DP sea accesible — usa $\epsilon$ pequeno para mayor proteccion.
  • K-Anonymity: Tecnica clasica pero efectiva si se implementa con $k \geq 10$ y se audit la re-identificabilidad.
  • Homomorphic Encryption: Futuro de la privacidad — calculos sobre datos cifrados, pero aun computationally costoso.

Los tres errores que mais duelen:

  1. Confiar en "anonimizado" sin analisis real de re-identificacion — peligroso y posiblemente ilegal bajo GDPR/Ley 1581.
  2. Usar epsilon arbitrario en DP — calcula el budget real y documentalo.
  3. No tener data governance — sin framework, la privacidad es inconsistente y no auditable.
