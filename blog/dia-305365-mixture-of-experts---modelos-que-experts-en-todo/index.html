LLM Sentiment Analysis — El 75% Lo Hace Mal y el 25% Lo Hace Bien

Hagale pues, parcero. Aquí en Bogotá, cuando alguien te dice "está bueno eso", depende del contexto si es bueno o si está siendo sarcasmo puro. Eso mismo pasa con los modelos de sentiment analysis: el 75% de las implementaciones no capturan la riqueza real del lenguaje humano. Hoy en el Día 305 vamos a arreglar eso — con matemáticas, código y el estilo colombiano que nos caracteriza.

🎯 Por Que Sentiment Analysis Con LLMs?

El sentiment analysis tradicional usaba bag-of-words + SVM y funcionaba "aceptable" para reviews de películas con dos categorías: positivo o negativo. Pero el lenguaje real es más complejo. Cuando alguien escribe "no está mal", ¿es positivo o negativo? Cuando dice "el servicio fue lento, pero la comida salvó la noche", ¿qué demonios es eso?

Los LLMs resuelven esto porque:

  • Entienden contexto: Pueden capturar negaciones, sarcasmo, y frases complejas
  • Manejan multi-clase: Van más allá de positivo/negativo binario
  • Zero-shot capability: Pueden clasificar categorías que nunca vieron en entrenamiento

📐 La Matemática Del Sentiment

Matemáticamente, el sentiment analysis es un problema de clasificación. Dado un texto $x$, queremos predecir una distribución de probabilidad sobre $k$ categorías de sentimiento:

$$P(y | x) = \text{softmax}(W \cdot h_\theta(x) + b)_y$$

Donde:

  • $h_\theta(x)$ es la representación del LLM para el texto de entrada
  • $W \in \mathbb{R}^{k \times d}$ mapea el embedding a las $k$ clases
  • $\text{softmax}(z)_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$

Para情感的 finas, usamos una función de pérdida cross-entropy:

$$\mathcal{L} = -\sum_{i=1}^{N} \sum_{c=1}^{k} y_{i,c} \log(\hat{y}_{i,c})$$

🔬 Approccio 1: Zero-Shot Sentiment

El approccio zero-shot usa el LLM directamente sin fine-tuning. Le pedimos que clasifique dado un schema de categorías.

from transformers import pipeline
import torch

# Zero-shot con modelo pre-entrenado
classifier = pipeline(
    "zero-shot-classification",
    model="facebook/bart-large-mnli",
    device=0 if torch.cuda.is_available() else -1
)

candidate_labels = ["positive", "negative", "neutral", "ironic", "mixed"]

def analyze_sentiment_zero_shot(text: str) -> dict:
    """
    Zero-shot sentiment analysis.
    El modelo clasifica sin haber visto ejemplos específicos.
    """
    result = classifier(
        text,
        candidate_labels=candidate_labels,
        multi_label=False  # una sola clase
    )
    
    return {
        "text": text,
        "dominant_sentiment": result["labels"][0],
        "confidence": result["scores"][0],
        "all_scores": dict(zip(result["labels"], result["scores"]))
    }

# Ejemplo
text = "El servicio fue lento, pero la comida salvó la noche"
result = analyze_sentiment_zero_shot(text)
print(f"Sentimiento: {result['dominant_sentiment']}")
print(f"Confianza: {result['confidence']:.2%}")
print(f"Todos los scores: {result['all_scores']}")

Pros: No necesita datos etiquetados, fácil de implementar.

Cons: Puede ser inconsistente, necesita prompt engineering cuidadoso.

🔬 Approccio 2: Fine-Tuned Sentiment Analysis

Para mayor precisión, hacemos fine-tuning de un modelo pre-entrenado con datos etiquetados.

from transformers import (
    AutoModelForSequenceClassification,
    AutoTokenizer,
    TrainingArguments,
    Trainer
)
from datasets import Dataset
import torch

# Cargar modelo pre-entrenado
model_name = "distilbert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForSequenceClassification.from_pretrained(
    model_name,
    num_labels=5,  # positive, negative, neutral, ironic, mixed
    id2label={0: "negative", 1: "mixed", 2: "neutral", 3: "positive", 4: "ironic"},
    label2id={"negative": 0, "mixed": 1, "neutral": 2, "positive": 3, "ironic": 4}
)

def tokenize_function(examples):
    return tokenizer(
        examples["text"],
        padding="max_length",
        truncation=True,
        max_length=512
    )

def fine_tune_sentiment(train_dataset, eval_dataset, output_dir="./sentiment_model"):
    """
    Fine-tuning de modelo para sentiment analysis.
    """
    # Tokenizar datasets
    train_tokenized = train_dataset.map(tokenize_function, batched=True)
    eval_tokenized = eval_dataset.map(tokenize_function, batched=True)
    
    # Training arguments
    training_args = TrainingArguments(
        output_dir=output_dir,
        num_train_epochs=3,
        per_device_train_batch_size=16,
        per_device_eval_batch_size=64,
        warmup_steps=500,
        weight_decay=0.01,
        learning_rate=2e-5,
        eval_strategy="epoch",
        save_strategy="epoch",
        load_best_model_at_end=True,
        metric_for_best_model="accuracy",
        logging_dir="./logs",
        logging_steps=100,
    )
    
    # Métricas
    def compute_metrics(eval_pred):
        logits, labels = eval_pred
        predictions = logits.argmax(axis=-1)
        accuracy = (predictions == labels).mean()
        return {"accuracy": accuracy}
    
    # Trainer
    trainer = Trainer(
        model=model,
        args=training_args,
        train_dataset=train_tokenized,
        eval_dataset=eval_tokenized,
        compute_metrics=compute_metrics,
    )
    
    trainer.train()
    return model, tokenizer

# Inferencia
def predict_sentiment(texts, model, tokenizer):
    """
    Predice sentiment para una lista de textos.
    """
    model.eval()
    inputs = tokenizer(
        texts,
        padding=True,
        truncation=True,
        max_length=512,
        return_tensors="pt"
    )
    
    with torch.no_grad():
        outputs = model(**inputs)
        probs = torch.softmax(outputs.logits, dim=-1)
        preds = outputs.logits.argmax(dim=-1)
    
    return {
        "predictions": [model.config.id2label[p.item()] for p in preds],
        "probabilities": probs.numpy()
    }

🎯 Aspect-Based Sentiment Analysis (ABSA)

El aspect-based sentiment va más allá: no solo dice "positivo", dice "+La comida+ fue excelente" y "-El servicio+ fue lento". Esto es crucial para análisis de reseñas.

from transformers import pipeline
import re

class AspectBasedSentimentAnalyzer:
    """
    Análisis de sentimiento basado en aspectos.
    Identifica diferentes aspectos y el sentimiento asociado a cada uno.
    """
    
    def __init__(self):
        self.aspect_classifier = pipeline(
            "text-classification",
            model="nlptown/bert-base-multilingual-uncased-sentiment"
        )
        # Aspectos comunes para reviews
        self.aspects = [
            "comida", "servicio", "precio", "ambiente", 
            "ubicación", "limpieza", "relación calidad-precio"
        ]
    
    def extract_aspect_sentiment(self, text: str) -> list:
        """
        Extrae aspectos mencionados y su sentimiento.
        """
        results = []
        
        # Dividir por aspectos potenciales (oraciones)
        sentences = re.split(r'[.,;!?]', text)
        
        for sentence in sentences:
            sentence = sentence.strip()
            if not sentence:
                continue
                
            # Clasificar cada oración
            sentiment = self.aspect_classifier(sentence)[0]
            
            # Detectar aspectos mencionados
            mentioned_aspects = [
                aspect for aspect in self.aspects 
                if aspect.lower() in sentence.lower()
            ]
            
            if mentioned_aspects or len(sentences) == 1:
                results.append({
                    "sentence": sentence,
                    "sentiment": sentiment["label"],
                    "score": sentiment["score"],
                    "aspects": mentioned_aspects if mentioned_aspects else ["general"]
                })
        
        return results

# Ejemplo
analyzer = AspectBasedSentimentAnalyzer()
review = "La comida estuvo deliciosa, pero el servicio fue muy lento y el precio es excesivo."
results = analyzer.extract_aspect_sentiment(review)

for r in results:
    print(f"Oración: {r['sentence']}")
    print(f"  Sentimiento: {r['sentiment']}")
    print(f"  Aspectos: {r['aspects']}")

📊 Métricas de Evaluación

No todas las métricas sirven para todos los casos. Aquí va la guía:

  • Accuracy: Solo si las clases están balanceadas
  • F1-Score (macro): Para clases desbalanceadas — promedio del F1 de cada clase
  • F1-Score (weighted): Ponderado por la frecuencia de cada clase
  • Confusion Matrix: Para ver qué clases se confunden más
  • Cross-Entropy Loss: Para monitorear entrenamiento, no para comparar modelos
from sklearn.metrics import (
    accuracy_score, f1_score, classification_report, 
    confusion_matrix
)
import numpy as np

def evaluate_sentiment(y_true, y_pred, class_names):
    """
    Evalúa modelo de sentiment con métricas apropiadas.
    """
    print("=" * 60)
    print("EVALUACIÓN DE SENTIMENT ANALYSIS")
    print("=" * 60)
    
    # Accuracy general
    acc = accuracy_score(y_true, y_pred)
    print(f"\nAccuracy: {acc:.2%}")
    
    # F1 Scores
    f1_macro = f1_score(y_true, y_pred, average='macro')
    f1_weighted = f1_score(y_true, y_pred, average='weighted')
    
    print(f"F1 (macro): {f1_macro:.2%}")
    print(f"F1 (weighted): {f1_weighted:.2%}")
    
    # Reporte detallado por clase
    print("\n" + "-" * 60)
    print("REPORTE POR CLASE:")
    print("-" * 60)
    print(classification_report(y_true, y_pred, target_names=class_names))
    
    # Matriz de confusión
    print("\n" + "-" * 60)
    print("MATRIZ DE CONFUSIÓN:")
    print("-" * 60)
    cm = confusion_matrix(y_true, y_pred)
    print(f"Clases: {class_names}")
    print(cm)
    
    return {
        "accuracy": acc,
        "f1_macro": f1_macro,
        "f1_weighted": f1_weighted,
        "confusion_matrix": cm
    }

⚠️ Los 3 Errores Más Comunes

❌ Error 1: Usar Sentiment Binario Cuando Es Multi-Clase

El problema: Muchas implementaciones forzan's todo a "positivo" o "negativo". Pero el mundo real tiene más matices: "neutral", "mixto", "irónico".

La solución: Usa un schema de 4-5 clases mínimo. Si solo tienes 2, estás perdiendo información.

# MAL: Solo binario
def sentiment_binary(text):
    result = classifier(text, labels=["positive", "negative"])
    return "positive" if result[0]["score"] > 0.5 else "negative"

# BIEN: Multi-clase
SENTIMENT_LABELS = ["negative", "neutral", "positive", "ironic", "mixed"]
def sentiment_multiclass(text):
    result = classifier(text, labels=SENTIMENT_LABELS)
    return result[0]["label"]

❌ Error 2: No Considerar Aspect-Based Sentiment

El problema: "La comida estuvo increíble, pero el servicio fue horrible." Un clasificador binario o multi-clase normal te da UNA etiqueta. ¿Pero cuálaspecto es positivo y cuál negativo?

La solución: Implementa ABSA para capturar la riqueza del texto.

# MAL: Una etiqueta para todo el texto
result = classifier("La comida incredible, servicio horrible")
# Devuelve: {"label": "mixed"} — pero no sabes qué es mixto

# BIEN: Aspect-based
analyzer = AspectBasedSentimentAnalyzer()
results = analyzer.extract_aspect_sentiment("La comida incredible, servicio horrible")
# Devuelve: [
#   {"sentence": "La comida incredible", "sentiment": "positive", "aspects": ["comida"]},
#   {"sentence": "servicio horrible", "sentiment": "negative", "aspects": ["servicio"]}
# ]

❌ Error 3: No Manejar Negaciones

El problema: "No está mal" es POSITIVO, no negativo. "Nunca estuvo bueno" es NEGATIVO. Los modelos simples no capturan esto.

La solución: Usa prompts estructurados o modelos entrenados específicamente para manejar negaciones.

import re

def handle_negation(text: str) -> str:
    """
    Pre-procesa negaciones para mejorar clasificación.
    """
    negation_patterns = [
        (r'\bno\b', 'NO_'),
        (r'\bnunca\b', 'NUNCA_'),
        (r'\bjamás\b', 'JAMAS_'),
        (r'\btampoco\b', 'TAMPOCO_'),
    ]
    
    result = text
    for pattern, replacement in negation_patterns:
        result = re.sub(pattern, replacement, result, flags=re.IGNORECASE)
    
    return result

def analyze_with_negation_handling(text: str, classifier):
    """
    Analiza sentiment manejando negaciones.
    """
    # Pre-procesar
    processed = handle_negation(text)
    
    # Clasificar texto procesada
    result = classifier(processed, labels=SENTIMENT_LABELS)
    
    return {
        "original": text,
        "processed": processed,
        "sentiment": result[0]["label"],
        "score": result[0]["score"]
    }

# Ejemplo
text = "Nunca estuvo tan malo el restaurante"
result = analyze_with_negation_handling(text, classifier)
print(f"Original: {result['original']}")
print(f"Procesado: {result['processed']}")
print(f"Sentimiento: {result['sentiment']}")  # Ahora captura "nunca" correctamente

📈 Resumen y Cierre

Hoy aprendimos que el sentiment analysis con LLMs es poderoso pero tiene trampas. Recapitulemos:

  • Zero-shot: Rápido, no necesita datos, pero inconsistente
  • Fine-tuned: Más preciso, requiere datos y compute
  • Aspect-based: Captura la riqueza de textos complejos
  • Métricas: F1 macro para desbalance, confusion matrix para debugging

Los 3 errores a evitar:

  1. No uses binario cuando es multi-clase
  2. No ignores los aspectos — usa ABSA
  3. Maneja las negaciones explícitamente

Parece complicado, pero con estos fundamentos ya tienes un framework robusto para sentiment analysis en producción. El 75% lo hace mal, parcero — pero tú ahora estás en el 25% que lo hace bien.

Ah, y algo importante: siempre valida con datos reales de tu dominio. Un modelo entrenado en tweets no funciona igual para reseñas de restaurantes. El contexto es rey.

Nos vemos en el Día 306 cuando hablemos de text matching — cómo medir similitud entre textos con LLMs. Va a estar bueno.
