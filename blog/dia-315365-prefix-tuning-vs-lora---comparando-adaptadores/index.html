LLM Math Reasoning — El 85% Lo Hace Mal y el 15% Lo Hace Bien

Hagale pues, parcero. Hoy es el Día 315 y vamos a hablar de algo que me tiene loco hace rato: cómo usar LLMs para hacer matemáticas. Sí, sé que muchos confían ciegamente en que un LLM les resuelva ecuaciones diferenciales, pero la realidad es que el 85% de la gente lo hace mal. Hoy les voy a mostrar cómo ser del 15% que lo hace bien. Póngale café a esa tasa porque esto va largo.

🤔 El Problema: Por Qué los LLMs No Son Calculadoras

Aquí va la verdad incómoda: los Large Language Models son modelos de lenguaje, no motores de computación. Cuando le pedís a un LLM que calcule 47 × 193, no está haciendo aritmética — está prediciendo tokens basado en patrones textuales. Esto significa que para operaciones simples puede fallar más que un estudiante de primaria con sueño.

Qué Puede Hacer un LLM Con Math:

  • Razonamiento paso a paso: Explicar el proceso matemático
  • Verificación de resultados: Comprobar si un resultado es correcto
  • Formulación de problemas: Traducir word problems a expresiones
  • Selección de estrategia: Decidir qué método usar

Qué NO Debe Hacer un LLM Solo:

  • Cálculos numéricos directos: Sumas, restas, multiplicaciones de números grandes
  • Operaciones con decimales precisos:π × e, raíces exactas
  • Cálculos iterativos: loops que requieren precisión numérica

⚠️ Error 1: No Usar Herramientas Externas para Cálculos

El primer error que veo todos los días es pedirle al LLM que haga cálculos directos. "Cuánto es 2^16 dividido por 3.14159"? El LLM te va a dar un número inventado con la confianza de un doctorando.

El Fix: Tool Use con Python/Calculator

import math
from typing import Union

class MathReasoningFramework:
    """Framework de razonamiento matemático con tool use."""
    
    def __init__(self, llm_client):
        self.llm = llm_client
        self.tools = {
            "python_calculator": self._python_eval,
            "exact_math": self._exact_math,
            "numerical_verify": self._verify_result
        }
    
    def _python_eval(self, expression: str) -> float:
        """Evalúa expresiones matemáticas con Python."""
        # SOLO para operaciones que no requieren precisión infinita
        allowed = {"sin", "cos", "tan", "sqrt", "log", "exp", 
                  "pi", "e", "pow", "abs", "round"}
        # Safelist de funciones permitidas
        try:
            return eval(expression, {"__builtins__": {}}, 
                       {k: getattr(math, k) for k in dir(math) if k in allowed})
        except Exception as e:
            return f"Error: {e}"
    
    def _exact_math(self, a: Union[int, float], b: Union[int, float], op: str):
        """Matemáticas exactas con verificación."""
        operations = {
            "+": lambda x, y: x + y,
            "-": lambda x, y: x - y,
            "*": lambda x, y: x * y,
            "/": lambda x, y: x / y if y != 0 else "Undefined",
            "**": lambda x, y: pow(x, y)
        }
        return operations.get(op, lambda x, y: "Unknown op")(a, b)
    
    def solve(self, problem: str) -> dict:
        """Resolver problema matemático con verificación."""
        # Paso 1: El LLM propone el enfoque
        plan = self.llm.think(f"¿Cómo resolverías: {problem}?")
        
        # Paso 2: Identificar cálculos que requieren tools
        calc_needed = self.llm.extract_calculations(problem)
        
        results = {}

            # Delegar a Python, no al LLM
            results[calc] = self._python_eval(calc)
        
        # Paso 3: Verificar con método alternativo
        verification = self._verify_result(results)
        
        return {
            "plan": plan,
            "calculations": results,

⚠️ Error 2: No Verificar las Salidas Matemáticas

El segundo error mortal es confiar ciegamente en el resultado de un LLM sin verificarlo. Uno de mis profesores en la Nacional siempre decía: "El que no verifica, no sabe". Y tiene razón.

El Fix: Double-Check con Métodos Alternativos

class MathVerifier:
    """Verificador de resultados matemáticos."""
    
    def verify_arithmetic(self, result: float, a: float, b: float, op: str) -> dict:
        """Verificar operación aritmética."""
        # Método 1: Operador nativo de Python
        operations = {"+": lambda x, y: x + y, "-": lambda x, y: x - y,
                      "*": lambda x, y: x * y, "/": lambda x, y: x / y}
        native_result = operations[op](a, b)
        
        # Método 2: Implementación manual (para verificar sumas)
        manual_result = self._manual_add(a, b) if op == "+" else native_result
        
        # Método 3: Verificación por inversos
        inverse_ops = {"+": "-", "-": "+", "*": "/", "/": "*"}
        inverse = inverse_ops[op]
        if op in ["+", "-"]:
            check = operations[inverse](native_result, a)
        else:
            check = operations[inverse](native_result, a) if a != 0 else None
        
        return {
            "native": native_result,
            "manual": manual_result,
            "inverse_check": check,
            "consistent": abs(native_result - manual_result) < 1e-10
        }
    
    def _manual_add(self, a: float, b: float) -> float:
        """Suma manual dígito por dígito para verificación."""
        # Conversión a string para manejo preciso
        return float(str(a)) + float(str(b))  # Simplificado, pero ilustra el concepto

La regla de oro: Si el resultado es crítico (ingeniería, finanzas, ciencia), verifica con al menos 2 métodos independientes. Nunca confíes en un solo resultado de LLM para decisiones importantes.

⚠️ Error 3: Asumir Que el LLM Es Bueno en Matemáticas Sin Verificar

El tercer error es el más peligroso: pensar que porque un LLM es "inteligente" o "avanzado", es bueno en matemáticas. Falso. Los LLMs son modelos de lenguaje. Pueden explicarte el teorema de Bayes perfectamente pero fallar en multiplicar 23 × 47.

El Fix: Benchmarking y Conocimiento de Limitaciones

class LLMMathBenchmark:
    """Benchmark de capacidades matemáticas del LLM."""
    
    def __init__(self, llm):
        self.llm = llm
        self.known_weaknesses = [
            "multiplicación de números > 4 dígitos",
            "operaciones con decimales precisos (π, e)",
            "cálculos iterativos largos",
            "operaciones modulares complejas",
            "manipulación de números muy grandes o muy pequeños"
        ]
    
    def diagnose_problem(self, math_problem: str) -> dict:
        """Diagnosticar si el problema es problemático para el LLM."""
        # Patrones que indican problemas
        problem_indicators = {
            "large_numbers": any(char.isdigit() and len(word) > 4 
                                 for word in math_problem.split() 
                                 for char in word if char.isdigit()),
            "precise_decimals": any(s in math_problem.lower() 
                                     for s in ["π", "pi", "euler", "sqrt(2)"]),
            "iterative": "sum" in math_problem.lower() or "loop" in math_problem.lower(),
            "modular": "%" in math_problem or "mod" in math_problem.lower()
        }
        
        needs_tool = any(problem_indicators.values())
        
        return {
            "problem_indicators": problem_indicators,
            "needs_external_tool": needs_tool,
            "recommendation": "Usar Python" if needs_tool else "LLM puede manejar",
            "weaknesses_to_watch": [k for k, v in problem_indicators.items() if v]
        }

📐 Math Reasoning Framework Completo

class CompleteMathReasoningFramework:
    """
    Framework completo para razonamiento matemático con LLMs.
    Diseñado para ser correcto, no solo rápido.
    """
    
    def __init__(self, llm):
        self.llm = llm
        self.python = MathReasoningFramework(llm)
        self.verifier = MathVerifier()
        self.benchmark = LLMMathBenchmark(llm)
    
    def solve(self, problem: str, require_verification: bool = True) -> str:
        # Paso 1: Diagnosticar
        diagnosis = self.benchmark.diagnose_problem(problem)
        
        if diagnosis["needs_external_tool"]:
            # Extraer cálculos y delegar a Python
            calculations = self.llm.extract_math_expressions(problem)
            results = {}
            for calc in calculations:
                results[calc] = self.python._python_eval(calc)
            
            if require_verification:
                # Verificar cada resultado
                for expr, result in results.items():
                    verified = self.verifier.verify_arithmetic(
                        result, 
                        *self._extract_operands(expr),
                        self._extract_operator(expr)
                    )
                    if not verified["consistent"]:
                        return f"Error: Resultado inconsistente para {expr}"
            
            # Reconstruir solución con resultados verificados
            return self.llm.format_solution(problem, results)
        else:
            # Para problemas simples, el LLM puede manejarlos
            return self.llm.solve_simple(problem)

📊 Resumen: Las 3 Reglas de Oro

  • Usa herramientas externas: Python, calculadoras, Wolfram Alpha para cualquier cálculo numérico real. El LLM solo debe decidir qué calcular, no calcularlo.
  • Siempre verifica: Doble-check con métodos independientes para resultados críticos. El LLM puede inventar números con total confianza.
  • Conoce las limitaciones: No todos los LLMs son iguales en matemáticas. Benchmarkea tu modelo específico y conoce sus puntos débiles.
