Cost Optimization - LLM Barato y Eficiente

11 de septiembre de 2026

Por Que El Costo De LLMs Es Un Problema

GPT-4 cuesta $0.03 por 1000 tokens de input y $0.06 por 1000 tokens de output. Eso suena poco hasta que haces las matematicas:

  • 1000 chats diarios con 500 tokens input + 300 tokens output
  • = 500,000 input tokens + 300,000 output tokens
  • = $15 + $18 = $33/dia
  • = $990/mes
  • = $11,880/año

Y eso es solo UN chatbot con volumen bajo. Si tienes 10,000 usuarios activos? $120,000/año. Esto no escala.

Strategias De Cost Optimization

1. Eleccion De Modelo Appropriate

No todo necesita GPT-4. Para muchas tareas, modelos mas pequenos funcionan igual de bien:

  • GPT-4: $0.03/1K input — tareas complejas de razonamiento
  • GPT-3.5: $0.0015/1K input — 20x mas barato, okay para tareas simples
  • Claude Haiku: $0.00025/1K input — 120x mas barato, rapido y efectivo

La regla: usa el modelo mas barato que cumpla con tus requisitos de calidad.

2. Prompt Compression

Si reduces tu prompt de 1000 tokens a 500, reduces tu costo en 50%. Teknik:

3. Caching De Respuestas

Requests identicos o similares no necesitan inference repetida. Cachea:

import hashlib
from functools import lru_cache

class ResponseCache:
    def __init__(self, max_size=10000):
        self.cache = {}
        self.max_size = max_size
    
    def get_key(self, prompt, model="gpt-4"):
        # Hash del prompt para key
        return hashlib.sha256(f"{model}:{prompt}".encode()).hexdigest()
    
    def get(self, prompt, model="gpt-4"):
        key = self.get_key(prompt, model)
        return self.cache.get(key)
    
    def set(self, prompt, response, model="gpt-4"):
        if len(self.cache) >= self.max_size:
            # Evict oldest
            oldest = next(iter(self.cache))
            del self.cache[oldest]
        
        key = self.get_key(prompt, model)
        self.cache[key] = response

# Hit rate del 30% = 30% menos inference = 30% menos costo

4. Semantic Caching

Caching exacto tiene bajo hit rate. Semantic caching encuentra requests similares:

from sentence_transformers import SentenceTransformer
import numpy as np

class SemanticCache:
    def __init__(self, threshold=0.95):
        self.embedder = SentenceTransformer('all-MiniLM-L6-v2')
        self.cache = {}  # embedding -> response
        self.threshold = threshold
    
    def find_similar(self, prompt):
        embedding = self.embedder.encode(prompt)
        
        for cached_emb, (response, cached_prompt) in self.cache.items():
            similarity = np.dot(embedding, cached_emb)
            if similarity > self.threshold:
                return response, cached_prompt
        
        return None, None
    
    def get_or_compute(self, prompt, llm_fn):
        response, cached_prompt = self.find_similar(prompt)
        
        if response:
            # Cache hit!
            return response, True
        
        # Cache miss - compute
        response = llm_fn(prompt)
        embedding = self.embedder.encode(prompt)
        self.cache[embedding.tobytes()] = (response, prompt)
        
        return response, False

# Semantic cache puede alcanzar 60-70% hit rate
# vs 10-15% de exact matching

5. Model Routing

Enruta requests al modelo apropiado basado en complejidad:

class ModelRouter:
    def __init__(self):
        self.simple_keywords = ['hola', 'gracias', 'ayuda', 'info']
        self.complex_keywords = ['analiza', 'compara', 'explica por que', 'razona']
    
    def route(self, prompt):
        prompt_lower = prompt.lower()
        
        # Contar complexity indicators
        simple_score = sum(1 for kw in self.simple_keywords if kw in prompt_lower)
        complex_score = sum(1 for kw in self.complex_keywords if kw in prompt_lower)
        
        # Routing logic
        if complex_score > simple_score:
            return "gpt-4"  # Modelo caro para tareas complejas
        elif simple_score > 0:
            return "claude-haiku"  # Modelo barato para tareas simples
        else:
            return "gpt-3.5"  # Default al balanceado
        
        # Bonus: ML-based router entrenado con labeled data
        # Para casos donde keywords no son suficientes

# Ahorro: 70% de requests van a modelos baratos

Optimizacion De Inference

Quantization Para Costos

Modelos quantizados son mas baratos de inference porque:

  • Menos memoria = batch size mas grande = mas throughput
  • Menos compute = latency menor = menos GPU time
  • INT8 vs FP32 = 4x menos memoria, 2-4x speedup
# Cuantizacion con bitsandbytes
from transformers import AutoModelForCausalLM, BitsAndBytesConfig

quantization_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype="float16",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4"
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-70b",
    quantization_config=quantization_config
)

# 70B params: 35GB FP16 -> 10GB INT4
# Inference cost: ~3.5x menos GPU hours

class OptimizedBatcher:

Cost Monitoring

No puedes optimizar lo que no mides. Implementa tracking desde el primer dia:

class CostTracker:
    def __init__(self):
        self.total_input_tokens = 0
        self.total_output_tokens = 0
        self.costs = defaultdict(float)
        self.model_prices = {
            "gpt-4": {"input": 0.03, "output": 0.06},
            "gpt-3.5": {"input": 0.0015, "output": 0.002},
            "claude-haiku": {"input": 0.00025, "output": 0.00125},
        }
    
    def log_request(self, model, input_tokens, output_tokens):
        self.total_input_tokens += input_tokens
        self.total_output_tokens += output_tokens
        
        price = self.model_prices[model]
        cost = (input_tokens / 1000 * price["input"] + 
                output_tokens / 1000 * price["output"])
        
        self.costs[model] += cost
    
    def get_total_cost(self):
        return sum(self.costs.values())
    
    def get_cost_by_model(self):
        return dict(self.costs)
    
    def report(self):
        print(f"Total Cost: ${self.get_total_cost():.2f}")
        print(f"Input Tokens: {self.total_input_tokens:,}")
        print(f"Output Tokens: {self.total_output_tokens:,}")
        print("\nCost by Model:")
        for model, cost in self.get_cost_by_model().items():
            print(f"  {model}: ${cost:.2f}")

Resumen Y Cierre

Cost optimization para LLMs no es magia — es ingenieria aplicada:

  • Model selection: Usa el mas barato que cumpla requisitos
  • Prompt compression: Menos tokens = menos dinero
  • Caching: No repitas inference para requests similares
  • Semantic caching: 60-70% hit rate con embedding similarity
  • Model routing: 70% de requests a modelos baratos
  • Quantization: 3-4x menos GPU hours
  • Batching: 32x mas throughput
  • Monitoring: Mide todo para optimizar todo

Una startup bien optimizada puede reducir sus costos de LLM en 80-90% sin sacrificar calidad. Eso es la diferencia entre un modelo de negocio viable y uno que se quema cash.
