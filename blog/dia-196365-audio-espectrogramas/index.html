Dia 196/365: Audio Espectrogramas — la cascada verde del ingeniero de radio revelando lo que tu oido no puede

15 de julio de 2026
librosa.display.specshow

Introduccion: Cuando el oido te esta mintiendo

Te llega un audio de tres segundos a produccion. Un pitido seco, intermitente, que tu cliente jura que suena a "algo electrico fallando". Tu modelo de clasificacion dice "normal". Le das play, y suena identico al audio de referencia. Pero la tasa de falsos negativos se disparo un 12%. Algun defecto hay, y no esta en el dominio del tiempo.

Esto me paso en 2023 con un sistema de monitoreo de lineas de ensamblaje. Teniamos 200 horas de audio rotuladas como "anomalia mecanica" y "operacion normal". El clasificador daba 0.94 de accuracy en validacion; en produccion se desplomo a 0.71. La causa: los audios de falla tenian un componente a 7.2 kHz de muy baja energia, indistinguible del ruido de fondo para el oido humano, pero que cualquier modelo en frecuencia cazaba. No se trata de si "suena raro"; se trata de donde vive la energia en el espectro.

El espectrograma es la cascada de agua verde de un analizador de espectro de los 80s: una grilla bidimensional donde el eje horizontal es tiempo, el vertical es frecuencia, y la intensidad del color es la magnitud de la energia en esa celda. Si lo sabes leer, te dice cosas que el oido no puede separar del contexto. Cuando montas un pipeline de ML sobre audio — clasificacion, deteccion de eventos — necesitas esa cascada renderizada correctamente para debugging.

1. Que es un Espectrograma? (Y por que deberia importarte)

1.1 La analogia cotidiana

Imagina el frente de un analizador de espectro Hewlett-Packard de 1986, de los que tenian los ingenieros de RF en sus laboratorios. Una pantalla CRT verde con 60 filas horizontales (cada fila es una banda de frecuencia entre 0 y 20 kHz) que se actualiza de izquierda a derecha, columna por columna, a velocidad lenta. Cuando no hay nada, ves una linea casi plana con ruido disperso. Cuando un violin toca una nota, ves una linea brillante horizontal en la frecuencia fundamental, acompanada de lineas mas debiles por encima (los armonicos). Cuando hay un golpe de tambor, ves una explosion vertical que decae rapidamente.

Esa cascada, hecha con persistencia fosforica, ES un espectrograma. Cada columna es un instante en el tiempo, cada fila es una frecuencia, y el brillo del pixel es cuanta energia acustica vive ahi en ese instante. Tu clasificador de audio no escucha formas de onda; mira esa grilla. Si no sabes como se ve tu data antes de meterla al modelo, no sabes que problema le estas pidiendo resolver.

1.2 La matematica formal

Partimos de una senal discreta $x[n]$ con $n \in \mathbb{Z}$, muestreada a una frecuencia $f_s$ (tipicamente 22050 Hz o 44100 Hz). La Transformada de Fourier de Tiempo Corto (STFT) se define como:

$$ X[m, k] = \sum_{n=0}^{N-1} x[n + mH] \cdot w[n] \cdot e^{-j 2\pi k n / N} $$

Donde cada simbolo significa exactamente lo que parece:

  • $X[m, k]$ es la matriz compleja de salida: la fila $k$ corresponde a la frecuencia $f_k = k \cdot f_s / N$, y la columna $m$ al tiempo $t_m = m \cdot H / f_s$.
  • $w[n]$ es la ventana de analisis (Hann, Hamming, Blackman). Multiplica a la senal para que la STFT sea localizada en el tiempo: sin ventana, una discontinuidad contamina el espectro entero.
  • $N$ es el tamano de la FFT (potencia de 2, tipicamente 1024 o 2048).
  • $H$ es el hop length, el numero de muestras que la ventana avanza entre frames. Si $H = N$, no hay solapamiento; si $H = N/4$, hay 75% de solapamiento, que es el default en librosa.
  • $e^{-j 2\pi k n / N}$ es la base compleja de Fourier: separa la senal en sus componentes sinusoidales.

Del STFT complejo, el espectrograma de potencia es:

$$ S[m, k] = |X[m, k]|^2 $$

Que es solo el cuadrado de la magnitud — esto da unidades de energia (amplitud al cuadrado). Para visualizar y entrenar modelos, casi siempre lo convertimos a decibelios con:

$$ S_{dB}[m, k] = 10 \cdot \log_{10}\left(\frac{S[m, k]}{S_{ref}}\right) $$

Donde $S_{ref}$ es una potencia de referencia. Librosa usa ref=np.max por defecto, lo que significa que el pico maximo del espectrograma queda en 0 dB y el resto es negativo (entre 0 y -80 dB tipicamente). El parametro top_db=80.0 recorta todo lo que este 80 dB por debajo del maximo, porque ese ruido de fondo no aporta senal.

2. Como librosa.display.specshow resuelve esto por vos

specshow no calcula el espectrograma — eso lo hace librosa.stft o librosa.feature.melspectrogram. Lo que hace specshow es tomar una matriz 2D de magnitudes y pintarla en un eje de matplotlib con las unidades correctas. El truco que la hace indispensable es la conversion automatica de indices de frame a tiempo y de bins de FFT a frecuencia, respetando el sr y hop_length.

  +-------------------------------------------------------------+
  | specshow() internals                                         |
  +-------------------------------------------------------------+
  |                                                             |
  |  data: np.ndarray shape (n_freqs, n_frames)                 |
  |     |                                                       |
  |     v                                                       |
  |  +-------------------+     +---------------------------+    |
  |  | Build time axis   |     | Build frequency axis      |    |
  |  | times = m*H/sr    |     | freqs = k * sr / N        |    |
  |  +-------------------+     +---------------------------+    |
  |     |                          |                           |
  |     v                          v                           |
  |  +-------------------+     +---------------------------+    |
  |  | x_axis='time'     |     | y_axis in {linear, log,   |    |
  |  |   -> sec          |     |   mel, logmel, chroma,    |    |
  |  | x_axis='s'        |     |   fft_note, fft_semi...}  |    |
  |  |   -> samples      |     +---------------------------+    |
  |  +-------------------+              |                      |
  |                                     v                      |
  |                          Apply nonlinear mapping            |
  |                          (e.g. mel: bin -> Hz -> mel)       |
  |                                     |                      |
  |                                     v                      |
  |                          ax.imshow(data, extent=...,        |
  |                                    aspect='auto',           |
  |                                    origin='lower')          |
  +-------------------------------------------------------------+

Lo importante: specshow no invierte los ejes. Por convencion, librosa.feature.* devuelve matrices con shape (features, frames) — filas son frecuencias y columnas son tiempo. specshow asume eso y coloca el frame 0 a la izquierda y la frecuencia mas baja abajo. Si tu data viene al reves, te queda el tiempo corriendo de derecha a izquierda y la frecuencia creciendo hacia abajo: clasico bug que explico en la seccion 6.

3. librosa.display.specshow: Uso Directo y Casos de Control Fino

El caso directo, copiar y pegar, ya lo conoces. Lo que importa aqui son los parametros que controlan como se lee:

import librosa
import librosa.display
import matplotlib.pyplot as plt
import numpy as np

y, sr = librosa.load("audio.wav", sr=22050, mono=True)

# STFT crudo -> magnitud -> dB
S = np.abs(librosa.stft(y, n_fft=2048, hop_length=512))
S_db = librosa.amplitude_to_db(S, ref=np.max, top_db=80.0)

fig, ax = plt.subplots(figsize=(12, 4))
img = librosa.display.specshow(
    S_db,
    sr=sr,
    hop_length=512,
    x_axis="time",          # 'time' | 's' | 'ms' | 'frames' | None
    y_axis="log",           # 'linear' | 'log' | 'mel' | 'logmel'
    cmap="magma",           # cualquier colormap perceptualmente uniforme
    ax=ax,
    vmin=-80.0,             # piso explicito para reproducibilidad
    vmax=0.0,               # techo alineado con ref=np.max
)
ax.set_title("Espectrograma de potencia (log scale)")
ax.set_xlabel("Tiempo (s)")
ax.set_ylabel("Frecuencia (Hz)")
fig.colorbar(img, ax=ax, format="%+2.0f dB")
plt.tight_layout()

Tres controles finos que vale la pena marcar:

  • vmin y vmax explicitos. Si no los pones, matplotlib los infiere del min/max del array. Eso hace que dos audios distintos con distinta energia tengan rangos visuales distintos y rompe la comparacion entre batches. Para visualizacion reproducible, fijalos siempre en -80.0 y 0.0.
  • cmap="magma" o "viridis". Son perceptualmente uniformes, a diferencia de jet que es el default historico pero distorsiona la percepcion del dato.
  • y_axis="mel" o "logmel". Si vas a meter el espectrograma a un modelo de deep learning, lo que va a ver la red es el espectrograma Mel. Renderizar en esa misma escala en el plot de debugging hace que lo que vos ves sea lo que ve el modelo.

4. Implementacion Production-Ready: SpectroCache

Cuando estas sirviendo un pipeline de audio y necesitas producir visualizaciones reproducibles para auditoria y debugging, lo que NO queres es que cada llamada recalcule el STFT y reescale el plot. Esto es SpectroCache: una clase que precomputa el espectrograma una vez, lo cachea, y expone metodos de visualizacion y verificacion.

4.1 Tipos y protocolos

# spectro_types.py
from __future__ import annotations

from dataclasses import dataclass
from typing import Literal, NewType

import numpy as np
from numpy.typing import NDArray

# Tipos de dominio
AudioArray = NewType("AudioArray", NDArray[np.float32])
SampleRate = NewType("SampleRate", int)
Spectrogram = NewType("Spectrogram", NDArray[np.float32])  # ya en dB

# Ejes soportados por specshow
XAxis = Literal["time", "s", "ms", "frames"]
YAxis = Literal["linear", "log", "mel", "logmel"]

# Configuracion inmutable del pipeline
@dataclass(frozen=True, slots=True)
class SpectroConfig:
    n_fft: int = 2048
    hop_length: int = 512
    n_mels: int = 128
    fmin: float = 20.0
    fmax: float = 8000.0
    top_db: float = 80.0
    ref_db: float = 0.0     # ref=np.max -> 0 dB

    def __post_init__(self) -> None:
        if self.n_fft & (self.n_fft - 1) != 0:
            raise ValueError(f"n_fft debe ser potencia de 2, recibio {self.n_fft}")
        if not 0 < self.hop_length <= self.n_fft:
            raise ValueError(
                f"hop_length fuera de rango: {self.hop_length} (n_fft={self.n_fft})"
            )

4.2 El motor principal

# spectro_engine.py
from __future__ import annotations

import hashlib
from pathlib import Path

import librosa
import numpy as np

from spectro_types import AudioArray, SampleRate, SpectroConfig, Spectrogram


class SpectroCache:
    """Pipeline deterministico de espectrogramas con cache en disco."""

    def __init__(
        self,
        config: SpectroConfig,
        sr: SampleRate = SampleRate(22050),
        cache_dir: Path | None = None,
    ) -> None:
        self._config = config
        self._sr = int(sr)
        self._cache_dir = cache_dir
        if cache_dir is not None:
            cache_dir.mkdir(parents=True, exist_ok=True)

    @property
    def config(self) -> SpectroConfig:
        return self._config

    def _cache_key(self, audio: AudioArray) -> str:
        digest = hashlib.sha256(audio.tobytes()).hexdigest()[:16]
        cfg = self._config
        return (
            f"n{cfg.n_fft}_h{cfg.hop_length}_m{cfg.n_mels}"
            f"_sr{self._sr}_d{digest}.npy"
        )

    def compute_power(self, audio: AudioArray) -> Spectrogram:
        """STFT en dB. Shape: (n_freqs, n_frames)."""
        S = np.abs(
            librosa.stft(audio, n_fft=self._config.n_fft, hop_length=self._config.hop_length)
        )
        return Spectrogram(
            librosa.amplitude_to_db(S, ref=np.max, top_db=self._config.top_db)
        )

    def compute_mel(self, audio: AudioArray) -> Spectrogram:
        """Mel-espectrograma en dB. Shape: (n_mels, n_frames)."""
        M = librosa.feature.melspectrogram(
            y=audio,
            sr=self._sr,
            n_fft=self._config.n_fft,
            hop_length=self._config.hop_length,
            n_mels=self._config.n_mels,
            fmin=self._config.fmin,
            fmax=self._config.fmax,
        )
        return Spectrogram(librosa.power_to_db(M, ref=np.max, top_db=self._config.top_db))

    def get_or_compute(
        self, audio: AudioArray, kind: str = "mel"
    ) -> Spectrogram:
        if self._cache_dir is None:
            return self.compute_mel(audio) if kind == "mel" else self.compute_power(audio)

        key = self._cache_key(audio)
        cache_path = self._cache_dir / f"{kind}_{key}"
        if cache_path.exists():
            return Spectrogram(np.load(cache_path).astype(np.float32))

        spec = self.compute_mel(audio) if kind == "mel" else self.compute_power(audio)
        np.save(cache_path, spec)
        return spec

4.3 Utilidades de analisis y verificacion

# spectro_verify.py
from __future__ import annotations

import librosa.display
import matplotlib.pyplot as plt
import numpy as np

from spectro_types import SampleRate, Spectrogram, SpectroConfig


def verify_spec(
    spec: Spectrogram,
    cfg: SpectroConfig,
    sr: SampleRate,
    expected_frames: int,
) -> dict[str, float]:
    """Validaciones numericas que siempre corren antes de graficar."""
    checks: dict[str, float] = {}

    # 1) Rango dinamico: debe estar entre -top_db y 0
    checks["max_db"] = float(spec.max())
    checks["min_db"] = float(spec.min())
    checks["dynamic_range_ok"] = float(
        checks["max_db"] <= 0.5 and checks["min_db"] >= -cfg.top_db - 0.5
    )

    # 2) Sin NaN/Inf (log(0) cuando no se aplica amin)
    checks["has_nan"] = float(np.isnan(spec).any())
    checks["has_inf"] = float(np.isinf(spec).any())

    # 3) Shape: numero de frames esperado segun hop_length
    expected = int(np.ceil(expected_frames / cfg.hop_length))
    checks["actual_frames"] = float(spec.shape[1])
    checks["expected_frames"] = float(expected)
    checks["frames_ok"] = float(abs(spec.shape[1] - expected) <= 1)

    # 4) Frecuencia maxima segun Nyquist
    n_freqs = spec.shape[0]
    if cfg.n_mels > 0 and n_freqs == cfg.n_mels:
        checks["y_axis_kind"] = 1.0  # mel
    else:
        max_freq_hz = (n_freqs - 1) * sr / cfg.n_fft
        checks["max_freq_hz"] = float(max_freq_hz)
        checks["nyquist_ok"] = float(max_freq_hz <= sr / 2 + 1.0)

    return checks


def render(
    spec: Spectrogram,
    cfg: SpectroConfig,
    sr: SampleRate,
    title: str,
    ax,
) -> None:
    """Render consistente y reproducible. vmin/vmax fijos."""
    y_axis = "mel" if spec.shape[0] == cfg.n_mels else "log"
    img = librosa.display.specshow(
        spec,
        sr=int(sr),
        hop_length=cfg.hop_length,
        x_axis="time",
        y_axis=y_axis,
        cmap="magma",
        vmin=-cfg.top_db,
        vmax=cfg.ref_db,
        ax=ax,
    )
    ax.set_title(title)
    ax.set_xlabel("Tiempo (s)")
    ax.set_ylabel("Frecuencia (Hz)" if y_axis != "mel" else "Frecuencia (Mel)")
    plt.colorbar(img, ax=ax, format="%+2.0f dB")

Verificacion manual: para sr=22050, n_fft=2048, hop_length=512, 5 segundos de audio = 110250 muestras. Frames esperados = ceil(110250/512) = 216. Frecuencia maxima resoluble = 22050/2 = 11025 Hz. Si la verificacion reporta dynamic_range_ok=0 o frames_ok=0, NO graficar — el plot va a mentir.

5. Ejemplos de Uso en Casos Reales

Caso 1: Validacion visual antes de entrenar un clasificador. Esto es lo que SIEMPRE deberias correr antes de meterle 200 horas de audio a una red. Generas un mosaico de 16 espectrogramas aleatorios de tu dataset, lo guardas como PNG, y lo revisas visualmente.

import librosa
import matplotlib.pyplot as plt

cfg = SpectroConfig(n_fft=2048, hop_length=512, n_mels=128)
engine = SpectroCache(cfg, sr=SampleRate(22050))

fig, axes = plt.subplots(4, 4, figsize=(16, 12), sharex=True, sharey=True)
for ax, audio_path in zip(axes.flat, sample_paths):
    y, _ = librosa.load(audio_path, sr=22050, mono=True)
    y = y.astype(np.float32)
    spec = engine.compute_mel(y)
    checks = verify_spec(spec, cfg, SampleRate(22050), expected_frames=len(y))
    assert checks["frames_ok"] == 1.0, f"Frames inconsistentes en {audio_path}"
    render(spec, cfg, SampleRate(22050), title=audio_path.stem, ax=ax)

fig.suptitle("Muestreo de espectrogramas Mel — dataset de entrenamiento")
plt.tight_layout()
plt.savefig("dataset_audit.png", dpi=120)

Caso 2: Deteccion de anomalias en audio industrial. Para el caso del pitido de 7.2 kHz que mencione al principio, el pipeline es: calcular espectrograma, calcular la energia media por banda, comparar contra un baseline, y marcar como anomalia cualquier banda cuya energia supere 3 sigmas del baseline.

import numpy as np
import librosa

def detect_spectral_anomaly(
    audio_path: str,
    baseline_path: str,
    sr: int = 22050,
    threshold_sigma: float = 3.0,
) -> list[tuple[float, float, float]]:
    cfg = SpectroConfig(n_fft=4096, hop_length=1024, n_mels=256)
    engine = SpectroCache(cfg, sr=SampleRate(sr))

    y_test, _ = librosa.load(audio_path, sr=sr, mono=True)
    y_base, _ = librosa.load(baseline_path, sr=sr, mono=True)

    S_test = engine.compute_power(y_test.astype(np.float32))
    S_base = engine.compute_power(y_base.astype(np.float32))

    e_test = S_test.mean(axis=1)
    e_base = S_base.mean(axis=1)
    sigma = e_base.std(axis=0) + 1e-9

    z = (e_test - e_base) / sigma
    anomaly_bins = np.where(z > threshold_sigma)[0]
    freqs = np.arange(len(z)) * sr / cfg.n_fft

    return [(float(freqs[i]), float(e_test[i]), float(z[i])) for i in anomaly_bins]

# Verificacion: para sr=22050, n_fft=4096, un bin = 22050/4096 ~= 5.38 Hz
# Si devuelve [(7200.0, -25.3, 4.2)], sabes que la anomalia esta en 7.2 kHz con
# magnitud -25 dB y 4.2 sigmas por encima del baseline. Eso es accionable.

6. Debugging: Cuando Todo se Va a la Mierda

Problema 1: NaN en el espectrograma. Si calculas 20 * log10(np.abs(stft)) a mano en vez de usar librosa.amplitude_to_db o librosa.power_to_db, y hay un frame completamente silencioso (energia 0), el log10(0) te devuelve -inf, que matplotlib renderiza como blanco sin avisarte. Deteccion numerica: assert not np.isnan(spec).any() and not np.isinf(spec).any(). Soluciones: (a) usar siempre librosa.amplitude_to_db(S, ref=np.max, top_db=80.0) que internamente hace np.maximum(amin, magnitude) con amin=1e-10 por defecto; (b) si necesitas control total, pre-clampa con S = np.maximum(S, 1e-10) antes del log; (c) verifica que ref=np.max no sea 0 (audio totalmente silencioso) y rechaza el archivo.

Problema 2: Eje Y invertido (frecuencias altas abajo). Causa: pasaste una transpuesta del espectrograma, o tu data viene como (n_frames, n_freqs) por error. specshow no la transpone automaticamente. Deteccion: assert spec.shape[0] < spec.shape[1], porque la convencion de librosa es filas=frecuencias, columnas=tiempo, y casi siempre n_freqs < n_frames. Si no se cumple, transpone: spec = spec.T.

Problema 3: Eje X en frames en vez de segundos. Causa: olvidaste pasar sr=sr o pasaste x_axis="frames" por accidente. specshow sin sr no puede convertir frame index a tiempo. Deteccion: los ticks del eje X son enteros 0, 50, 100, 150... en vez de 0.0, 1.0, 2.0. Solucion: pasa sr=sr, hop_length=hop_length y x_axis="time".

Problema 4: Comparaciones entre archivos imposibles por rangos distintos. Esto es sutil y me ha mordido mas de una vez. Si generas espectrogramas con vmin/vmax automaticos, dos audios de distinta energia tienen rangos visuales distintos y la comparacion visual engana. Solucion: fija siempre vmin=-cfg.top_db y vmax=cfg.ref_db en TODA llamada a specshow. Es el bug que mas facil se cuela en code review.

7. Optimizaciones de Produccion

Cache en disco con clave por contenido. Si tu pipeline re-procesa los mismos audios en multiples entrenamientos, precomputar el espectrograma una sola vez y cachearlo por hash del audio ahorra el 80% del tiempo. La clase SpectroCache lo implementa. Trade-off: espacio en disco. Para 200h a sr=22050 con n_mels=128, son ~10 GB. Comprimilo con np.savez_compressed si te duele el SSD.

Precomputar y serializar a Parquet en vez de recalcular online. El bottleneck nunca es la red neuronal — es el preprocesamiento. Calcula todos los espectrogramas offline, serializalos en Parquet con compresion snappy, y en entrenamiento lees directamente el tensor precomputado. Trade-off: pierdes augmentations en dominio del audio crudo. Si tus augmentations son post-STFT (masking tiempo/frecuencia), esta optimizacion es gratis.

8. Conclusion: Por Que Esto te Salva el Pellejo en Produccion

  • librosa.display.specshow no calcula el espectrograma — lo renderiza. El STFT lo hace librosa.stft; el Mel-spec lo hace librosa.feature.melspectrogram. specshow te ahorra la conversion de indices a unidades fisicas en los ejes.
  • Tres controles no negociables para visualizacion reproducible: vmin=-80, vmax=0, cmap="magma" (o cualquier perceptualmente uniforme). Sin ellos, los plots mienten.
  • Siempre verifica antes de graficar: dynamic_range_ok, frames_ok, ausencia de NaN/Inf, Nyquist respetado. El assert cuesta 5 microsegundos y te ahorra horas de debugging.
  • El espectrograma ES la entrada del modelo. Si lo que ve el modelo no es lo que ves vos en el plot, tu interpretabilidad es teatro. Renderiza siempre en la misma escala que la red consume.

Mini-checklist antes de production:

def preflight(audio_path: str) -> bool:
    y, sr = librosa.load(audio_path, sr=22050, mono=True)
    assert y.dtype == np.float32, f"dtype={y.dtype}, esperaba float32"
    assert sr == 22050, f"sr={sr}, esperaba 22050"
    assert np.abs(y).max() <= 1.0, "Audio clipeado"
    assert not np.isnan(y).any(), "Audio con NaN"
    cfg = SpectroConfig()
    engine = SpectroCache(cfg, sr=SampleRate(sr))
    spec = engine.compute_mel(y.astype(np.float32))
    checks = verify_spec(spec, cfg, SampleRate(sr), expected_frames=len(y))
    return all(v == 1.0 for k, v in checks.items() if k.endswith("_ok"))

Renderiza primero, entrena despues. Si tu pipeline no tiene un preflight asi, no tenes pipeline — tenes una ruleta. Al toque lo notas cuando el primer batch explota en produccion.
